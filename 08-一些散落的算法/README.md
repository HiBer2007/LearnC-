# 一些散落的算法

配置解析器要剥掉 JSON 里的注释，一遍读过去、边走边判断当前走到哪一步；
日志里要找出一段模式出现的每一个位置，逐字符比对的代价会随文本长度平方增长；
从十万条候选里抽两百条做抽查，随手写成 `rand() % n`，靠前的候选会更容易被抽中；
目录树要遍历到底，写成递归最直接，深度一大栈就顶穿了。

这四件事分属四个方向：扫描、匹配、采样、递归。它们既不归某一个容器管，
也不属于某一个头文件，却在真实代码里反复出现。**这个板块收的就是它们。**

**这个板块不是算法竞赛教程**：不推证明，不追复杂度最优。它是一层索引——
遇到这类问题，先想到有哪个解法可用，再看那个解法在什么前提下成立、代价落在哪。
推进路线与 `09` 一致：**问题 → 模型 → 解法 → 实现 → 代价**，
每一章都从一个真实的问题起步，而不是从一个算法的名字起步。

这些算法之所以散落，是因为它们不属于任何一件现成的工具：
标准库给了容器与迭代器，却没有给「怎么找」「怎么排」「怎么在状态空间里走」的统一答案；
语言给了递归与模板，却没有规定拿它们去解哪一类问题。
**它们共同的一点是「一类问题对应一类解法」**，
因此按问题归类、拆成十几章分散着放，比硬凑成一门课更清楚。

> [!IMPORTANT]
> **本板块的目标是给出「遇到这类问题先想到这个解法」的一层索引。**
> 前面七个板块把语言、工具链、语法、类与面向对象、底层、标准库、数据结构都铺完了，
> 这个板块收的是**没有别处安放、但相当重要**的那些算法：递归、查找与排序的策略、
> 分治、贪心与动态规划、字符串匹配、扫描与状态机、随机与采样。
> **每条解法都要落到能跑的代码与实测上**：它解决什么问题、在什么前提下成立、
> 代价测出来是多少，三件事缺一不可。证明与复杂度最优不是这里的目标。

## 一、本板块覆盖的核心问题

按「要解决的问题」排，不按算法的名气排。**左边那一列才是起点**——
先有问题，再有解法；同一个问题换一个前提，解法就换一种。

| 要解决的问题 | 引出的解法 | 在哪一章 |
|---|---|---|
| 算法散在各个角落，不知道该从哪一本找起 | 一张按问题查的索引 | `00` |
| 一件大事能拆成形式相同、规模更小的小事 | 递归：基线、推进、合并 | `01` |
| 同一个子问题被反复算很多遍，或者要把所有摆法都试一遍 | 记忆化、分治与回溯 | `02` |
| 要调用的函数参数个数不定，类型也不定 | 不定参数：`va_list` 与可变参数模板 | `03` |
| 十万条记录里反复问「这一条在不在」「这一段里有哪些」 | 线性查找、二分与索引 | `04` |
| 一批数据要按大小排好，还要知道哪种排法在什么数据上撑得住 | 比较排序的三种策略与内省排序 | `05` |
| 数据的取值范围或位数有界，比较不是唯一的路 | 计数排序、基数排序与桶排序 | `06` |
| 从起点出发找一条路，还要考虑代价、方向与「看起来往哪走更近」 | 深搜、广搜、Dijkstra 与 A* | `07` |
| 关系网本身有结构：谁必须先做、哪里有咽喉、至少要修多长的路 | 拓扑排序、强连通分量、割点与桥、最小生成树 | `08` |
| 每一步都能选当前最优，或者状态太多只能一层层推表 | 贪心与动态规划 | `09` |
| 长文本里找一段模式出现的全部位置，逐字符比太慢 | 朴素匹配、KMP 与 Rabin–Karp | `10` |
| 输入只能读一遍，边读边判断当前处在哪一步 | 状态机：`switch`、表驱动与状态转移表 | `11` |
| 要公平地抽、要不重复地洗、要同一个种子跑出同一个结果 | 伪随机与采样 | `12` |
| 遇到一个没见过的问题，不知道从哪里下手 | 先分类、再降规模、再找相似结构 | `END` |

**这张表里没有「KMP」「动态规划」这样的起点。** 它们都出现在中间那一列；
左边那一列才是起点——先有问题，再有解法。

同一行里的解法不是唯一答案。**换一个前提，解法就换一种**：
「这条记录在不在」在数据有序时是二分，在无序但内存装得下时是哈希，
在数据只落在磁盘上时是索引加分块；三者没有谁绝对更好，只有谁更配当前的前提。
这也是每一章都要交代「这个解法在什么前提下成立」的原因。

- `01` 到 `03`：递归是共同的底子。`01` 讲递归本身，`02` 把递归用在重复子问题与枚举上，
  `03` 是「个数不定」的接口怎么写——C 的 `va_list` 与 C++ 的可变参数模板。
- `04` 到 `08`：都在处理一批数据或一张关系网。`04` 找、`05` 与 `06` 排、
  `07` 在状态空间里走、`08` 看关系网本身的结构。
- `09` 到 `11`：一遍一遍往后推。`09` 推最优值，`10` 推失配位置，`11` 推当前状态。

## 三、与 `09`、`10` 的边界

这个板块最容易和相邻板块重叠，因此先把边界划清。
**划界的原则只有一条**：结构自带的算法与结构的接口留在 `09`，
与结构无关、跨结构通用的事情留在本板块。

| 数据结构自己的算法：树的遍历、堆的上浮与下沉、图的遍历、并查集 | **`09-高阶数据结构`** | 用结构与用它的算法强关联，拆到两处讲会重复；见《09-高阶数据结构/README.md》章节 |

| 并发、并行、线程池、数据竞争 | **`10-并发与并行`**（尚未编写） | 独立一层；写好后见该板块 |
| `<numeric>`：`accumulate`、`reduce`、`iota` | **`07-标准库`** | 已登记在那边；见《07-标准库/README.md》章节 |

| lambda 与模板机制本身 | **`05-类与面向对象`** | 见《05-类与面向对象/10-lambda 与函数对象.md》章节与《05-类与面向对象/11-模板.md》章节；本板块只讲「把它放进算法怎么用」 |
| 缓存、对齐、伪共享，以及代价到底从哪来 | **`06-更底层`** | 见《06-更底层/02-对齐、填充与缓存.md》章节；本板块讲代价时只**指路**，不重讲 |

一句便于记住的分界：**`09` 讲「数据怎么摆」，本板块讲「事情怎么做」。**
同一个「找出最小的 k 个数」，换一种摆法就换一种做法（`09` 的 `A-05` 给的是摆法与接口），
而「先排序再取」「用堆维护」「快选分区」这三种做法各自的取舍，在本板块讲。

还有一条：**本板块不重复 `09` 已经给出的数字。** 引用那边的代价时写明出处，
需要新的数字就在本板块自己测一次——两处数字由不同的程序产生，不混着比。

## 五、本板块的约定

本板块的每条结论都对应一次真跑，或者一次回原文核对。

- **结论必标依据**：`` `实测数据` ``（本机真跑，输出可复现）、`` `文档` ``（引标准草案或官方资料并给章节号）、`` `待确认` ``（合理推断但未验证）；随环境而变的写明**存疑**，并说清变的是什么。
- **数据一律来自实测**：每一处实测都注明当次版本——本机 `g++` 是 **16.2.0**（MinGW-w64）。教材里还留着 15.2.0 时期的旧数字，**两组数字不放进同一张表**，需要对照就重测一次。
- **代码块上方标语言**（`` `C++` ``／`` `C` ``／`` `Text` ``／`` `Bash` ``／`` `Mermaid` ``）；凡出现代码的块，要么是完整单文件，要么明确标「（下面是节选）」。
- **不写本机路径**，用 `<MinGW>`、`<工作区>` 这类占位符；编译命令写在程序首行注释里，读者按自己的环境替换路径。

**另外三条是本板块独有的实测纪律**，排序、查找、随机三章的实测最容易撞上：

1. **优化器会删掉「没人读」的容器**：`-O2` 下只往容器里放、从不读结果，整段循环会消失，
   分配计数变成 0。要么加 `asm volatile("" : : "r"(&c) : "memory")` 屏障，
   要么把结果真读出来打印。
2. **循环不变的东西会被提出循环**：`std::distance(...)` 写在循环条件里会被换成 `size()`，
   测到的代价就不是它的。要测它的代价，就写三种写法互相对照。
3. **小规模的计时按规模反比设轮数**，让各档的总工作量大致相当；
   贴着时钟分辨率的行**不进 `实测数据` 块**。
