# 并发与并行

**同一个程序里同时推进两件事，这叫并发；两件事在同一时刻各占一个核，这叫并行。**
前者是结构，后者是执行结果——**并发的写法不保证真的并行，而并行一定先要并发**。

本板块讲 C++ 在这一层给的东西：`std::thread` 的创建与收尾、锁与条件变量、
原子类型与内存序、`future` 与 `async`、线程池、并行算法，
以及**怎么用工具把写错的并发代码抓出来**。
C 侧对应的是 C11 起的 `<threads.h>` 与 `<stdatomic.h>`，
本板块在需要对照的地方点出差别，不展开 C 的写法。

> [!IMPORTANT]
> **并发是唯一一类「写错了也照样能跑对」的编程。**
> 少加一把锁、内存序写错一个取值，程序可能连续跑一万次都给出正确答案，
> 然后在换一台机器、换一个优化等级、换一次负载之后给出错误的答案。
> **因此本板块每一章都要给出可以复现的失败现场**——
> 丢掉的更新、崩掉的内存、挂住的程序、以及工具打出来的报告原文。
> 只讲结论的并发教材没有用，因为读者无法用它判断自己的代码属于哪一类。

## 四、建议阅读顺序

`Text`

```text
   弄清两个词与失败的样子        00        ← 必读
      ↓
   怎么开一条线程、怎么收尾        01        ← 一切的地基
      ↓
   为什么会错：数据竞争            02        ← 本板块的重心
      ↓
   一组数据要一起改怎么办          03
      ↓
   等一个条件成立怎么办            04
      ↓
   不加锁的共享变量与顺序保证      05        ← 最难的一章
      ↓
   只要一个结果，不要管线程        06
      ↓
   线程的数量要管起来              07
      ↓
   标准库里已经写好的并行          08
      ↓
   写错了怎么抓出来                09
      ↓
   收尾：判断顺序与清单            10        ← 最后读
```

**02 与 05 是两根柱子**：02 讲「不加保护的访问会怎样」，
05 讲「加了保护之后，顺序还由谁说了算」。
其余各章是这两件事在具体设施上的展开，遇到不懂的地方回到这两章。

## 五、怎么用这个板块

| 你的处境 | 从哪开始 |
|---|---|
| 刚开始学，按顺序读 | `00` → `10` |
| 手上有一段多线程代码要改 | 先读 `02`，再跳到与症状相符的那一章（挂住看 `03`、`04`，结果不对看 `02`、`05`） |
| 只想知道该不该开线程 | `00` 的第 3 节、`01` 的第 5 节、`10` 的判断顺序 |
| 要用标准库现成的并行 | `08`，读完再回来看 `07` |
| 程序偶尔出错，抓不到 | `09`，先让工具说话 |
| 在做嵌入式，只有中断没有线程 | `06-更底层` 第 10 节，本板块的 `05` 可作为内存序的补充 |

## 七、本板块的约定

- **每个代码块上方标语言**（`` `C++` `` / `` `C` `` / `` `Text` `` / `` `Assembly` `` / `` `Bash` `` …）；
- **数据**：跑出来的数字都用 `` `实测数据` `` 独立成行标出，**每一个都是真跑出来的**；
- **标准条文**用 `` `文档` `` 引英文原文并给出草案章节号（C++ 用 N4659，C 用 N3220）；
- **不写本机路径**，用 `<工作区>`、`<MinGW>`、`<发行版名>` 这类占位符；
- **示例以 C++ 为主**：线程、锁、原子量这些设施在 C 里是函数加结构体，
  只在能说清差别的地方给一小段 C 对照，不展开实现。

**本板块的实测环境**（复现任何一条数字都需要，因此写在正文之前）：

`实测数据`

| 侧 | 环境 | 说明 |
|---|---|---|
| Linux | WSL 的 Ubuntu 24.04.5，g++ 13.3.0 | 24 个逻辑核；线程、`ThreadSanitizer`、`Helgrind` 的实测都在这一侧 |
