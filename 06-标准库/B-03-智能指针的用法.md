《05-类与面向对象/06-RAII 与资源管理.md》第 5 节已经把这两样东西交代清楚：

循环引用会把两个对象钉死在堆上，以及什么时候该选哪一个。

剩下的问题都落在接口与类型上**：某个动作的语义是什么，某种写法会让类型变成什么样，

# 第 1 节 `unique_ptr`：独占所有权

`unique_ptr` 管的是「一份资源一个主人」这一种情形。**它的接口小到可以一次列完**，
难的地方不在接口，而在「所有权什么时候离开这个变量」，
也就是函数签名怎么写、写漏了会得到什么。

## 1.1 创建、判空、取用、转移

`unique_ptr` 常见的名字只有十来个：

| 写法 | 作用 |
|---|---|
| `std::unique_ptr<T> p(new T(...))` | 从一个裸指针接管所有权 |
| `std::unique_ptr<T> p = std::make_unique<T>(...)` | 同上，C++14 起，推荐写法 |
| `if (p)`、`p ? a : b` | 判空：能隐式转成 `bool` |
| `p->member`、`*p` | 像裸指针一样取用 |
| `p.get()` | 取出裸指针，**所有权不动** |
| `std::move(p)` | 转移所有权，转移之后 `p` 变空 |
| `p.release()` | 交出裸指针，自己变空，**不释放资源** |
| `p.reset(q)` / `p.reset()` | 释放当前资源，改成接管 `q` / 变成空 |
| `p.swap(q)`、`std::swap(p, q)` | 两边对调 |
| `p = nullptr` | 等价于 `p.reset()` |

拷贝构造与拷贝赋值是 `= delete` 的（《05-类与面向对象/06-RAII 与资源管理.md》第 4.2 小节），
因此**能编译的只有移动**。

`C++`

```cpp
/* b03_uptr_basic.cpp    编译：g++ -std=c++17 b03_uptr_basic.cpp -o b03_uptr_basic */
#include <cstdio>
#include <memory>
#include <utility>

class Widget {
public:
    explicit Widget(const char *name) : name_(name) { std::printf("  构造 %s\n", name_); }
    ~Widget() { std::printf("  析构 %s\n", name_); }
    const char *name() const { return name_; }

private:
    const char *name_;
};

int main() {
    std::printf("1. 创建：裸 new 与 make_unique\n");
    std::unique_ptr<Widget> a(new Widget("a"));
    std::unique_ptr<Widget> b = std::make_unique<Widget>("b");
    std::printf("  a 非空 = %d，b 非空 = %d\n", a ? 1 : 0, b ? 1 : 0);
    std::printf("  sizeof(unique_ptr<Widget>) = %zu，sizeof(Widget *) = %zu\n",
                sizeof(a), sizeof(Widget *));

    std::printf("2. 拷贝被删掉，只能 move\n");
    std::unique_ptr<Widget> c = std::move(a);
    std::printf("  move 之后 a 非空 = %d，c 指向 %s\n", a ? 1 : 0, c->name());

    std::printf("3. release：交出裸指针，自己变空，不释放\n");
    Widget *raw = c.release();
    std::printf("  release 之后 c 非空 = %d，raw 指向 %s\n", c ? 1 : 0, raw->name());
    delete raw;                                     /* 从这里起又归手工管 */

    std::printf("4. reset：先释放旧的，再接管新的\n");
    std::unique_ptr<Widget> d(new Widget("d1"));
    d.reset(new Widget("d2"));
    std::printf("  reset 之后 d 指向 %s\n", d->name());
    d.reset();
    std::printf("  reset() 之后 d 非空 = %d\n", d ? 1 : 0);

    std::printf("5. swap：两边对调\n");
    std::unique_ptr<Widget> e(new Widget("e"));
    std::unique_ptr<Widget> f(new Widget("f"));
    e.swap(f);                                      /* 与 f.swap(e)、std::swap(e, f) 等价 */
    std::printf("  swap 之后 e 指向 %s，f 指向 %s\n", e->name(), f->name());

    std::printf("6. 离开作用域，剩下的自己释放\n");
    return 0;
}
```

三行输出值得对照：

| 输出 | 说明 |
|---|---|
| `析构 a` 出现在 `reset 之后` 之前 | `release` 交出去之后是那行 `delete raw` 释放的，不是 `c` |
| `析构 d1` 出现在 `构造 d2` 之后 | `reset(new Widget("d2"))` 先把新对象造出来，再释放旧的 |
| 最后析构的是 `e`、`f`、`b` | 析构顺序与构造顺序相反（《04-语法/11-作用域、生存期与链接.md》第 3 节） |

> [!IMPORTANT]
> **`release` 与 `reset` 只差一个动作：`release` 什么都不释放。**
> 它的用途是「把这个所有权交给别的接口」——比如一个只认裸指针的 C 函数。
> 交出去之后必须在某处 `delete`，否则这份资源就没人管了。

## 1.2 忘了 `move` 会怎样

拷贝被 `= delete` 掉了，因此写漏 `std::move` 的代码根本编不过。

`C++`

```cpp

    std::unique_ptr<int> a(new int(1));

    std::unique_ptr<int> c(a);              /* 直接初始化也一样 */
    return *b + *c;
}
```

## 1.3 工厂函数：把所有权给出去

`unique_ptr` 不能拷贝，因此它出现在哪里，哪里的写法就必须随之调整。
一份所有权在函数之间走动只有三种走法——借用、交出、转交再收回，
三种写法对应三种签名，汇总在第 4 节。

「可能造不出来」的对象要交给工厂函数（构造函数没有返回值可以报告失败，
《05-类与面向对象/04-构造与析构.md》第 1.5 小节）。**返回类型写成 `unique_ptr`，
调用方一眼就知道拿到的是所有权。** 下面这个工厂失败时返回空指针，
不需要错误码。

`C++`

```cpp
/* b03_uptr_factory.cpp    编译：g++ -std=c++17 b03_uptr_factory.cpp -o b03_uptr_factory */
#include <cstdio>
#include <memory>
#include <string>
#include <utility>
#include <vector>

class Connection {

public:
    Connection(int id, std::string host) : id_(id), host_(std::move(host)) {
        std::printf("  连接 %d 建立（%s）\n", id_, host_.c_str());
    }
    ~Connection() { std::printf("  连接 %d 关闭\n", id_); }

    Connection(const Connection &) = delete;             /* 连接不能复制 */
    Connection &operator=(const Connection &) = delete;

    int id() const { return id_; }

private:
    int         id_;
    std::string host_;
};

/* 工厂函数：失败返回空指针，成功返回独占所有权 */
std::unique_ptr<Connection> connect_to(const std::string &host, int id, bool ok) {
    if (!ok) return nullptr;                             /* 这里返回的是空 unique_ptr */
    return std::make_unique<Connection>(id, host);        /* 返回值直接构造 */
}

int main() {
    std::printf("工厂返回 unique_ptr：\n");
    std::unique_ptr<Connection> c = connect_to("db-1", 1, true);
    std::printf("  拿到连接 %d\n", c->id());

    std::unique_ptr<Connection> bad = connect_to("db-2", 2, false);
    std::printf("  失败时返回的指针非空 = %d\n\n", bad ? 1 : 0);

    std::printf("把所有权交给容器（容器只要求元素可移动）：\n");
    std::vector<std::unique_ptr<Connection>> pool;
    pool.push_back(std::move(c));                        /* 收下之后 c 变空 */
    std::printf("  池里有 %zu 条连接，c 非空 = %d\n", pool.size(), c ? 1 : 0);
    return 0;
}
```

`实测数据`
`Text`

```text
工厂返回 unique_ptr：
  连接 1 建立（db-1）
  拿到连接 1
  失败时返回的指针非空 = 0

把所有权交给容器（容器只要求元素可移动）：
```

两点：**失败路径上返回 `nullptr` 就够**，不需要错误码；
**容器只要求元素可移动**，把 `Connection` 的拷贝删掉不影响它进容器。

> [!TIP]
> **看到 `unique_ptr` 出现在参数表里，先问一句「这个函数是要拿走它，还是只用一下」。**
> 只用一下就写 `const T &`；写成按值会让每次调用都要求 `std::move`。

## 1.4 数组特化 `unique_ptr<T[]>`

`new T[n]` 配 `delete[]`，`new T` 配 `delete`。这两组配对错了是未定义行为，
而且**编译器不会拦着**——`T *` 就是 `T *`。`unique_ptr<T[]>` 存在的意义就是把配对写进类型。

| 写法 | 析构时调用 | 能用 `p[i]` 吗 | 能 `*p` 吗 |
|---|---|---|---|
| `unique_ptr<T>` | `delete p` | 不能 | 能 |
| `unique_ptr<T[]>` | `delete[] p` | 能 | 不能 |

`C++`

```cpp
/* b03_uptr_array.cpp    编译：g++ -std=c++17 b03_uptr_array.cpp -o b03_uptr_array */
#include <cstdio>
#include <memory>

static int g_dtor = 0;                              /* 记下析构函数被调用了几次 */

class Counter {
public:
    Counter() { std::printf("  构造第 %d 个\n", ++g_dtor); }
    ~Counter() { std::printf("  析构一个\n"); }
};

int main() {
    std::setvbuf(stdout, nullptr, _IONBF, 0);       /* 本程序后面会崩，让输出立刻落盘 */

    std::printf("unique_ptr<Counter[]>：数组特化，用 delete[] 释放\n");
    {
        std::unique_ptr<Counter[]> arr(new Counter[3]);
        std::printf("  arr[1] 可以下标访问：%p\n", (void *)&arr[1]);
        std::printf("  sizeof(unique_ptr<Counter[]>) = %zu\n", sizeof(arr));
    }
    std::printf("  三个元素全部析构，析构行数 = %d\n\n", g_dtor);

    g_dtor = 0;
    std::printf("用错特化：拿 unique_ptr<Counter> 去接 new Counter[3] 的返回值\n");
    {
        std::unique_ptr<Counter> bad(new Counter[3]);
        std::printf("  语句本身能编译通过，指针类型都是 Counter *\n");
    }                                               /* 这里调用的是 delete，不是 delete[] */
    std::printf("  析构行数 = %d，数组里另外两个元素没有被析构\n", g_dtor);
    return 0;
}
```

> [!CAUTION]
> **`new T[n]` 一律配 `unique_ptr<T[]>`，不要靠记性去配对 `delete` 与 `delete[]`。**
> 配对错了至少要执行到析构才看得出来，而且它的后果是堆损坏，
> 不一定在出错的那一行崩，可能崩在很久之后的另一次分配上。

需要「一串数量在运行期才知道的对象」时，`std::vector<T>` 通常比 `unique_ptr<T[]>` 合适得多。
`unique_ptr<T[]>` 的合适场合是「这块缓冲区要交给一个只认裸数组的接口」。

## 1.5 自定义删除器：三种写法与各自的代价

默认删除器 `std::default_delete<T>` 只做一件事：`delete p`。
资源不是 `new` 出来的时候（`malloc` 的内存、`fopen` 的文件、系统句柄），
就要把「怎么释放」也交给类型记着。

**删除器的类型是 `unique_ptr` 的第二个模板参数**，因此它写在类型里。

`C++`

```cpp
/* b03_uptr_deleter.cpp    编译：g++ -std=c++17 b03_uptr_deleter.cpp -o b03_uptr_deleter */
#include <cstdio>
#include <cstdlib>
#include <memory>

/* 一个不是用 new 拿到的资源：C 的 malloc 配 free */
struct Payload {
    int value;
};

/* 1. 无状态仿函数：空类，不占空间 */
struct FreeDeleter {
    void operator()(Payload *p) const {
        std::printf("  FreeDeleter：free(%p)\n", (void *)p);
        std::free(p);
    }
};

/* 2. 有状态仿函数：带一个成员，要占空间 */
struct TaggedDeleter {
    const char *tag;
    void operator()(Payload *p) const {
        std::printf("  TaggedDeleter[%s]：free(%p)\n", tag, (void *)p);
        std::free(p);
    }
};

/* 3. 函数指针：也是 8 字节，但要走一次间接调用 */
static void free_payload(Payload *p) {
    std::printf("  函数指针：free(%p)\n", (void *)p);
    std::free(p);
}

static Payload *make_payload(int v) {
    Payload *p = (Payload *)std::malloc(sizeof(Payload));
    p->value = v;
    return p;
}

int main() {
    std::printf("同一个资源，四种删除器的写法：\n\n");

    {
        std::printf("默认删除器 std::default_delete：\n");
        std::unique_ptr<Payload> p(new Payload{7});
        std::printf("  sizeof = %zu\n\n", sizeof(p));
    }
    {
        std::printf("无状态仿函数：\n");
        std::unique_ptr<Payload, FreeDeleter> p(make_payload(7));
        std::printf("  sizeof = %zu（空类被优化掉，与裸指针相同）\n\n", sizeof(p));
    }
    {
        std::printf("有状态仿函数：\n");
        std::unique_ptr<Payload, TaggedDeleter> p(make_payload(7), TaggedDeleter{"带标签"});
        std::printf("  sizeof = %zu（多出来的 8 字节就是那个 tag 指针）\n\n", sizeof(p));
    }
    {
        std::printf("函数指针（无捕获的 lambda 也会转成它）：\n");
        std::unique_ptr<Payload, void (*)(Payload *)> p(make_payload(7), free_payload);
        std::printf("  sizeof = %zu（存的是函数地址本身），值 = %d\n\n", sizeof(p), p->value);
    }
    return 0;
}
```

`实测数据`
`Text`

```text
同一个资源，四种删除器的写法：

默认删除器 std::default_delete：
  sizeof = 8

无状态仿函数：
  sizeof = 8（空类被优化掉，与裸指针相同）

  FreeDeleter：free(000001e7dc402660)
有状态仿函数：
  sizeof = 16（多出来的 8 字节就是那个 tag 指针）

  TaggedDeleter[带标签]：free(000001e7dc402660)
函数指针（无捕获的 lambda 也会转成它）：
  sizeof = 16（存的是函数地址本身），值 = 7

  函数指针：free(00000290739e2660)
```

| 删除器写法 | `sizeof(unique_ptr<T, D>)` | 说明 |
|---|---|---|
| 默认（`default_delete`） | **8** | 空类，不占存储 |
| 无状态仿函数 | **8** | 空类同样被优化掉 |
| 有状态仿函数（带一个指针） | **16** | 状态存进 `unique_ptr` 自己 |
| 函数指针、无捕获的 lambda | **16** | 一个地址（lambda 隐式转成函数指针，《05-类与面向对象/10-lambda 与函数对象.md》第 2.3 小节） |

**这份开销只落在 `unique_ptr` 自己身上，不会转嫁到对象上**，
而且删除器的状态只有一份，不随对象数量增加。

> [!TIP]
> **删除器优先选无状态仿函数。** 它不占空间，调用点还能内联；
> 函数指针写法短，但要多一次间接调用，还多占 8 字节。
> 需要携带状态时（比如要往日志里写资源名字）才用有状态仿函数。

需要管 C 库资源时，删除器常写成 `decltype(&std::fclose)` 这样的函数指针，
把清理函数直接接进来。

---

# 第 2 节 `shared_ptr`：控制块与引用计数

`shared_ptr` 多出来的那 8 字节指向一块单独分配的内存——控制块。
**控制块里装着计数、删除器与分配器**，这一节讨论的正是它怎样决定写法：
删除器为什么不再影响指针大小，计数什么时候变，两参数构造多花的那一次分配花在哪。

## 2.1 控制块里有什么

`shared_ptr` 是 16 字节，其中 8 字节是对象指针，另外 8 字节指向**控制块**。

`Text`

```text
std::shared_ptr<T>（16 字节）
├─ 对象指针 ──► T 的实例          （强计数归零时析构）
└─ 控制块指针 ──► 控制块           （强计数与弱计数都归零时析构）
                 ├─ 强计数 use_count
                 ├─ 弱计数 weak count
                 ├─ 删除器
                 ├─ 分配器
                 └─ 被管理对象的指针
```

控制块里的三样东西都能直接观察到：计数随拷贝增加，删除器可以按类型取回来，
而 `shared_ptr` 自己的大小与 `T`、与删除器都无关。

`C++`

```cpp
/* b03_control_block.cpp    编译：g++ -std=c++17 b03_control_block.cpp -o b03_control_block */
#include <cstdio>
#include <memory>

/* 一个占 32 字节的删除器：它要住进控制块里 */
struct TaggedDeleter {
    char        pad[24];
    const char *tag;
    void operator()(int *p) const {
        std::printf("  TaggedDeleter[%s] 释放 %d\n", tag, *p);
        delete p;
    }
};

struct Big {
    char data[1024];
};

int main() {
    std::printf("1. 那 16 个字节与 T 无关\n");
    std::printf("  sizeof(shared_ptr<char>) = %zu\n", sizeof(std::shared_ptr<char>));
    std::printf("  sizeof(shared_ptr<Big>)  = %zu，而 sizeof(Big) = %zu\n\n",
                sizeof(std::shared_ptr<Big>), sizeof(Big));

    std::printf("2. 拷贝出来的一群 shared_ptr 共用一个控制块\n");
    std::shared_ptr<int> a(new int(5));
    std::printf("  刚造出来：use_count = %ld，a.get() = %p\n", a.use_count(), (void *)a.get());
    {
        std::shared_ptr<int> b = a;
        std::shared_ptr<int> c = b;
        std::printf("  再拷贝两份：use_count = %ld\n", a.use_count());
        std::printf("  三份的对象指针相同吗 = %d\n",
                    (a.get() == b.get()) && (b.get() == c.get()) ? 1 : 0);
    }
    std::printf("  两份析构之后：use_count = %ld\n\n", a.use_count());

    std::printf("3. 删除器也在控制块里\n");
    {
        std::shared_ptr<int> t(new int(9), TaggedDeleter{{}, "带标签"});
        std::printf("  sizeof(shared_ptr<int>) = %zu，sizeof(TaggedDeleter) = %zu\n",
                    sizeof(t), sizeof(TaggedDeleter));
        TaggedDeleter *d = std::get_deleter<TaggedDeleter>(t);
        std::printf("  按类型取回来：tag = %s\n", d ? d->tag : "(取不到)");
        std::printf("  类型写错时取到空指针 = %d\n",
                    std::get_deleter<int>(t) == nullptr ? 1 : 0);
        std::printf("  离开作用域：\n");
    }
    std::printf("  到这一步 a 还活着，use_count = %ld\n", a.use_count());
    return 0;
}
```

`实测数据`
`Text`

```text
1. 那 16 个字节与 T 无关
  sizeof(shared_ptr<char>) = 16
  sizeof(shared_ptr<Big>)  = 16，而 sizeof(Big) = 1024

2. 拷贝出来的一群 shared_ptr 共用一个控制块
  刚造出来：use_count = 1，a.get() = 0000029a166d2660
  再拷贝两份：use_count = 3
  三份的对象指针相同吗 = 1
  两份析构之后：use_count = 1

3. 删除器也在控制块里
  sizeof(shared_ptr<int>) = 16，sizeof(TaggedDeleter) = 32
  按类型取回来：tag = 带标签
  类型写错时取到空指针 = 1
  离开作用域：
  TaggedDeleter[带标签] 释放 9
  到这一步 a 还活着，use_count = 1
```

**删除器住在控制块里，所以删除器多大都不影响 `shared_ptr` 的大小。**
这一点与 `unique_ptr` 正好相反。

`实测数据`

| 类型 | `sizeof` |
|---|---|
| `Tracked *` | 8 |
| `unique_ptr<Tracked>` | 8 |
| `unique_ptr<Tracked, BigDeleter>`，删除器 32 字节 | **40** |
| `shared_ptr<Tracked>` | **16** |
| `weak_ptr<Tracked>` | 16 |

同一个 32 字节的删除器：`unique_ptr` 配上它从 8 涨到 40（第 2.2 小节），
`shared_ptr` 配上它仍是 16——删除器被搬进控制块，还能用 `std::get_deleter` 取回来。

> [!IMPORTANT]
> **`shared_ptr` 的 16 字节是固定的，与删除器无关；`unique_ptr` 的大小随删除器变。**
> 代价换了个地方付：`shared_ptr` 一定会多一次控制块分配（第 2.3 小节），
> 而 `unique_ptr` 什么都不多分。

## 2.2 `use_count` 的增减

`use_count()` 返回的是控制块里的强计数。它的变化只有三个来源：
**拷贝构造或拷贝赋值加一，析构减一，`reset` 先减一再换成新的。**

`C++`

```cpp
/* b03_shptr_count.cpp    编译：g++ -std=c++17 b03_shptr_count.cpp -o b03_shptr_count */
#include <cstdio>
#include <memory>

class Tracked {
public:
    explicit Tracked(const char *name) : name_(name) { std::printf("  Tracked(%s) 构造\n", name_); }
    ~Tracked() { std::printf("  Tracked(%s) 析构\n", name_); }

private:
    const char *name_;
};

/* 一个占 32 字节的删除器，用来观察它被放在哪里 */
struct BigDeleter {
    char pad[32];
    void operator()(Tracked *p) const { delete p; }
};

int main() {
    std::printf("1. 大小对比\n");
    std::printf("  sizeof(Tracked *)                       = %zu\n", sizeof(Tracked *));
    std::printf("  sizeof(unique_ptr<Tracked>)             = %zu\n", sizeof(std::unique_ptr<Tracked>));
    std::printf("  sizeof(unique_ptr<Tracked, BigDeleter>) = %zu\n",
                sizeof(std::unique_ptr<Tracked, BigDeleter>));
    std::printf("  sizeof(shared_ptr<Tracked>)             = %zu\n", sizeof(std::shared_ptr<Tracked>));
    std::printf("  sizeof(weak_ptr<Tracked>)               = %zu\n", sizeof(std::weak_ptr<Tracked>));
    std::printf("  删除器本身的大小                          = %zu\n\n", sizeof(BigDeleter));

    std::printf("2. 计数随拷贝与析构变化\n");
    {
        std::shared_ptr<Tracked> a = std::make_shared<Tracked>("a");
        std::printf("  make_shared 之后：use_count = %ld\n", a.use_count());
        {
            std::shared_ptr<Tracked> b = a;                 /* 拷贝：计数 +1 */
            std::printf("  拷贝给 b 之后：use_count = %ld\n", a.use_count());
            std::shared_ptr<Tracked> c = b;                 /* 再拷贝：计数再 +1 */
            std::printf("  再拷贝给 c 之后：use_count = %ld\n", a.use_count());
        }                                                    /* b、c 析构：计数 -2 */
        std::printf("  b、c 离开作用域之后：use_count = %ld\n", a.use_count());
        std::printf("  a 离开作用域：\n");
    }

    std::printf("\n3. 弱引用不加强计数，但控制块要等它一起走\n");
    {
        std::weak_ptr<Tracked> w;
        {
            std::shared_ptr<Tracked> a = std::make_shared<Tracked>("b");
            w = a;                                          /* weak 指向同一个控制块 */
            std::printf("  a 与 w 都在：use_count = %ld，w.expired() = %d\n",
                        a.use_count(), w.expired() ? 1 : 0);
        }                                                    /* 强计数归零，对象在这里析构 */
        std::printf("  a 没了：w.expired() = %d，w.use_count() = %ld\n",
                    w.expired() ? 1 : 0, w.use_count());
        std::printf("  控制块仍然活着（w 还占着），直到 w 也析构\n");
    }
    return 0;
}
```

`实测数据`
`Text`

```text
1. 大小对比
  sizeof(Tracked *)                       = 8
  sizeof(unique_ptr<Tracked>)             = 8
  sizeof(unique_ptr<Tracked, BigDeleter>) = 40
  sizeof(shared_ptr<Tracked>)             = 16
  sizeof(weak_ptr<Tracked>)               = 16
  删除器本身的大小                          = 32

2. 计数随拷贝与析构变化
  Tracked(a) 构造
  make_shared 之后：use_count = 1
  拷贝给 b 之后：use_count = 2
  再拷贝给 c 之后：use_count = 3
  b、c 离开作用域之后：use_count = 1
  a 离开作用域：
  Tracked(a) 析构

3. 弱引用不加强计数，但控制块要等它一起走
  Tracked(b) 构造
  a 与 w 都在：use_count = 1，w.expired() = 0
  Tracked(b) 析构
  a 没了：w.expired() = 1，w.use_count() = 0
  控制块仍然活着（w 还占着），直到 w 也析构
```

第 3 段拆开了两件事：

| 时刻 | 强计数 | 对象 | 控制块 |
|---|---|---|---|
| 只有 `a` 时 | 1 | 活着 | 活着 |
| `w = a` 之后 | **仍是 1** | 活着 | 活着 |
| `a` 析构之后 | 0 | **析构** | **仍然活着** |
| `w` 析构之后 | 0 | 已析构 | 释放 |

**对象由强计数管，控制块由强计数加弱计数一起管。**
因此 `weak_ptr` 不会拖住对象，但会在对象消失之后继续占着一小块控制块。

## 2.3 `make_shared` 与 `shared_ptr(new T)`：分配次数与异常安全

两行代码看起来只差一层括号，向堆要内存的次数差一倍。

`C++`

```cpp
/* b03_shptr_alloc.cpp    编译：g++ -std=c++17 b03_shptr_alloc.cpp -o b03_shptr_alloc */
#include <cstdio>
#include <cstdlib>
#include <memory>
#include <new>

/* 接管全局分配，数一数每段代码向堆要了几次 */
static long g_allocs = 0;                            /* 累计分配次数 */
static long g_frees  = 0;                            /* 累计释放次数 */
static long g_bytes  = 0;                            /* 累计分配字节数 */

void *operator new(std::size_t n) {
    ++g_allocs;
    g_bytes += (long)n;
    void *p = std::malloc(n ? n : 1);
    if (!p) throw std::bad_alloc();
    return p;
}
void operator delete(void *p) noexcept { if (p) { ++g_frees; std::free(p); } }
void operator delete(void *p, std::size_t) noexcept { operator delete(p); }

void *operator new[](std::size_t n) { return operator new(n); }
void operator delete[](void *p) noexcept { operator delete(p); }
void operator delete[](void *p, std::size_t) noexcept { operator delete(p); }

/* 被管理的对象：64 字节，足够大，不落进任何小对象缓存 */
struct Payload {
    char data[64];
    Payload() { data[0] = 1; }
};

static void report(const char *what) {
    std::printf("%-34s 分配 %2ld 次，释放 %2ld 次，向堆要了 %3ld 字节\n",
                what, g_allocs, g_frees, g_bytes);
    g_allocs = g_frees = g_bytes = 0;
}

int main() {
    std::printf("sizeof(Payload) = %zu，sizeof(shared_ptr<Payload>) = %zu\n\n",
                sizeof(Payload), sizeof(std::shared_ptr<Payload>));

    {
        std::shared_ptr<Payload> p = std::make_shared<Payload>();
        report("make_shared<Payload>()");
        std::printf("  use_count = %ld\n\n", p.use_count());
    }
    report("  （离开作用域，全部释放）");

    {
        std::shared_ptr<Payload> p(new Payload());
        report("shared_ptr<Payload>(new Payload())");
        std::printf("  use_count = %ld\n\n", p.use_count());
    }
    report("  （离开作用域，全部释放）");

    {
        std::shared_ptr<Payload> p = std::make_shared<Payload>();
        std::weak_ptr<Payload>   w = p;
        report("make_shared + weak_ptr");
        std::printf("  use_count = %ld\n\n", p.use_count());
    }
    report("  （弱引用也走完，控制块才释放）");
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(Payload) = 64，sizeof(shared_ptr<Payload>) = 16

make_shared<Payload>()             分配  1 次，释放  0 次，向堆要了  80 字节
  use_count = 1

  （离开作用域，全部释放） 分配  0 次，释放  1 次，向堆要了   0 字节
shared_ptr<Payload>(new Payload()) 分配  2 次，释放  0 次，向堆要了  88 字节
  use_count = 1

  （离开作用域，全部释放） 分配  0 次，释放  2 次，向堆要了   0 字节
make_shared + weak_ptr             分配  1 次，释放  0 次，向堆要了  80 字节
  use_count = 1

  （弱引用也走完，控制块才释放） 分配  0 次，释放  1 次，向堆要了   0 字节
```

`实测数据`

| 写法 | 分配次数 | 总字节数 | 拆分 |
|---|---|---|---|
| `make_shared<Payload>()` | **1** | **80** | 对象 64 + 控制块 16，一次要够 |
| `shared_ptr<Payload>(new Payload())` | **2** | **88** | 对象 64（`new` 那次）+ 控制块 24（构造 `shared_ptr` 那次） |
| `std::allocate_shared<Payload>(alloc)` | 1 | 80 | 与 `make_shared` 相同，只是走分配器 |

**这就是 `make_shared` 的全部好处：一次分配。**

还有第二条差别，与异常有关。`shared_ptr<T>(new T)` 这句表达式里有两件事：
`new T` 先发生，随后才轮到 `shared_ptr` 的构造函数申请控制块。
如果**申请控制块那一步抛出 `std::bad_alloc`**，对象指针还没有交到任何 `shared_ptr` 手里，
那块内存就丢了。

> [!CAUTION]
> **不要写 `f(std::shared_ptr<T>(new T), g())` 这种一个表达式里塞两次分配的形式。**
> 参数求值顺序在 C++17 之前没有规定，`g()` 先跑、抛异常时那个裸 `new` 出来的对象就泄漏了。
> `make_shared` 把对象与控制块合成一次分配，这个漏洞不存在。

`make_shared` 有三处不如两参数构造：

| 情形 | 说明 |
|---|---|
| 想接管一个已经拿到的裸指针 | `make_shared` 不接裸指针，只能两参数构造 |
| 想自定义删除器 | 同上 |
| 对象很大、`weak_ptr` 活得很久 | 合在一起的那块内存要等弱计数也归零才还回去 |

最后一条的含义是：对象析构了，**`make_shared` 那块内存也不会还**，
要等到最后一个 `weak_ptr` 消失；两参数构造则分成两块，对象那一块在强计数归零时立刻还。

## 2.4 从 `this` 造 `shared_ptr`：`enable_shared_from_this` 为什么存在

一个成员函数想把「管着我的那个 `shared_ptr`」交出去时，手上只有 `this`。
直接拿 `this` 现造一个是不行的：

`C++`

```cpp
/* b03_sft_wrong.cpp    编译：g++ -std=c++17 b03_sft_wrong.cpp -o b03_sft_wrong */
#include <cstdio>
#include <memory>
#include <vector>

static std::vector<std::shared_ptr<class Session>> g_registry;

class Session {                                          /* 没有继承 enable_shared_from_this */
public:
    explicit Session(int id) : id_(id) { std::printf("  会话 %d 建立\n", id_); }
    ~Session() { std::printf("  会话 %d 结束\n", id_); }

    void start() {
        /* 想表达「管着我的那个 shared_ptr」，于是从 this 现造一个 */
        g_registry.push_back(std::shared_ptr<Session>(this));
        std::printf("  注册表里的 use_count = %ld\n", g_registry.back().use_count());
    }

private:
    int id_;
};

int main() {
    std::setvbuf(stdout, nullptr, _IONBF, 0);            /* 后面会崩，让输出立刻落盘 */
    std::printf("从一个裸 this 造出第二个 shared_ptr：\n");
    {
        std::shared_ptr<Session> s = std::make_shared<Session>(1);
        std::printf("  main 里的 use_count = %ld\n", s.use_count());
        s->start();
        std::printf("  两个 shared_ptr 各自的 use_count 都是 1\n");
    }
    std::printf("  局部引用消失，它会删一次对象\n");
    std::printf("清空注册表：\n");
    g_registry.clear();                                  /* 另一个控制块也删一次 */
    std::printf("  这一步不会执行到\n");
    return 0;
}
```

`实测数据`
`Text`

```text
从一个裸 this 造出第二个 shared_ptr：
  会话 1 建立
  main 里的 use_count = 1
  注册表里的 use_count = 1
  两个 shared_ptr 各自的 use_count 都是 1
  会话 1 结束
  局部引用消失，它会删一次对象
清空注册表：
  会话 1 结束
```

**`会话 1 结束` 打印了两次，然后程序终止**：

`实测数据`
`Text`

```text
退出码 -1073740940，即 0xC0000374（堆损坏）
```

原因在计数上：`std::shared_ptr<Session>(this)` **新建了一个控制块**，
两个控制块各自以为自己是唯一的主人，各自的 `use_count` 都是 1，
于是各自删了一次同一个对象。

`enable_shared_from_this` 做的事就是**把那个已经存在的控制块记在对象里**。

`C++`

```cpp
/* b03_enable_sft.cpp    编译：g++ -std=c++17 b03_enable_sft.cpp -o b03_enable_sft */
#include <cstdio>
#include <memory>
#include <vector>

/* 注册表持有会话，因此会话的寿命由注册表与调用方共同决定 */
static std::vector<std::shared_ptr<class Session>> g_registry;

class Session : public std::enable_shared_from_this<Session> {
public:
    explicit Session(int id) : id_(id) { std::printf("  会话 %d 建立\n", id_); }
    ~Session() { std::printf("  会话 %d 结束\n", id_); }

    void start() {
        /* 成员函数里只有裸 this。make_shared 造出来的那个控制块，
           只有 enable_shared_from_this 记着，因此只能向它要。 */
        g_registry.push_back(shared_from_this());
    }

private:
    int id_;
};

int main() {
    std::printf("从成员函数里把 this 交出去：\n");
    {
        std::shared_ptr<Session> s = std::make_shared<Session>(1);
        std::printf("  外部只有一个引用：use_count = %ld\n", s.use_count());
        s->start();
        std::printf("  start() 之后：use_count = %ld\n", s.use_count());
    }
    std::printf("  局部引用消失，注册表还持有它\n");
    std::printf("  注册表里 %zu 项，use_count = %ld\n",
                g_registry.size(), g_registry[0].use_count());

    std::printf("清空注册表：\n");
    g_registry.clear();
    std::printf("  会话这才结束\n");
    return 0;
}
```

`实测数据`
`Text`

```text
从成员函数里把 this 交出去：
  会话 1 建立
  外部只有一个引用：use_count = 1
  start() 之后：use_count = 2
  局部引用消失，注册表还持有它
```

计数从 1 变成 2，**没有出现第二个控制块**，因此对象只析构一次。

`文档`

> "A class `T` can inherit from `enable_shared_from_this<T>` to inherit the
> `shared_from_this` member functions that obtain a `shared_ptr` instance
> pointing to `*this`."
>
> —— N4659 §23.11.2.5/1

两条使用限制：

| 限制 | 后果 |
|---|---|
| 对象必须已经由某个 `shared_ptr` 管着 | 构造函数里调用 `shared_from_this()` 会抛 `std::bad_weak_ptr` |
| 不能拿 `shared_ptr<T>(this)` 与它混用 | 那等于又造一个控制块，回到上面那个双重析构 |

> [!IMPORTANT]
> **`enable_shared_from_this` 解决的问题是「只有一个控制块」。**
> 成员函数里需要交出所有权时写 `shared_from_this()`；
> 任何时候都不要写 `std::shared_ptr<T>(this)`。

# 第 3 节 循环引用与 `weak_ptr`

引用计数有一个管不了的情形：**两个对象互相指着，谁也不肯先撒手**。
本节先构造出那个环并测出代价，再给出断环的写法。

## 3.1 不释放的环：计数与进程内存

《05-类与面向对象/06-RAII 与资源管理.md》第 5.4 小节已经给出两个节点的结论，
下面的实测把规模放大到 2000 个节点，同时给出未释放的块数与进程的工作集。

`C++`

```cpp
/* b03_shptr_cycle.cpp    编译：g++ -std=c++17 b03_shptr_cycle.cpp -o b03_shptr_cycle
   用法：b03_shptr_cycle strong   闭合边用 shared_ptr，建一条 2000 节点的环
         b03_shptr_cycle weak     闭合边用 weak_ptr，结构相同但不闭合强引用环 */
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <memory>
#include <new>

#ifdef _WIN32
#include <windows.h>
#include <psapi.h>
#endif

static long g_live = 0;                              /* 尚未释放的分配块数 */

void *operator new(std::size_t n) {
    void *p = std::malloc(n ? n : 1);
    if (!p) throw std::bad_alloc();
    ++g_live;
    return p;
}
void operator delete(void *p) noexcept { if (p) { --g_live; std::free(p); } }
void operator delete(void *p, std::size_t) noexcept { operator delete(p); }
void *operator new[](std::size_t n) { return operator new(n); }
void operator delete[](void *p) noexcept { operator delete(p); }
void operator delete[](void *p, std::size_t) noexcept { operator delete(p); }

static long long working_set() {
#ifdef _WIN32
    PROCESS_MEMORY_COUNTERS pmc;
    if (GetProcessMemoryInfo(GetCurrentProcess(), &pmc, sizeof(pmc))) {
        return (long long)pmc.WorkingSetSize;
    }
    return -1;
    /* 换到 Linux：读 /proc/self/statm 的第二个字段（常驻页数）再乘页大小即可 */
#endif
}

static void report(const char *what) {
    std::printf("%-12s 未释放 %5ld 块   工作集 %9lld 字节\n", what, g_live, working_set());
}

/* 链表节点：正向边强引用，反向边弱引用 */
struct Node {
    std::shared_ptr<Node> strong;
    std::weak_ptr<Node>   weak;
    char                  pad[4096];
};

/* 建一条 n 个节点的链；closing_strong 决定末端那条边是强还是弱 */
static void build_ring(int n, bool closing_strong) {
    std::shared_ptr<Node> first = std::make_shared<Node>();
    std::memset(first->pad, 1, sizeof(first->pad));   /* 把页真正碰一遍 */
    std::shared_ptr<Node> cur = first;
    for (int i = 1; i < n; ++i) {
        std::shared_ptr<Node> nxt = std::make_shared<Node>();
        std::memset(nxt->pad, 1, sizeof(nxt->pad));
        cur->strong = nxt;
        nxt->weak   = cur;
        cur         = nxt;
    }
    if (closing_strong) {
        cur->strong = first;                          /* 首尾相接：强引用成环 */
    } else {
        cur->weak = first;                            /* 末端的边不断所有权 */
    }
    report("建完之后");                                /* 此时 n 个节点全在内存里 */
}

int main(int argc, char **argv) {
    bool        closing_strong = (argc > 1) && (std::strcmp(argv[1], "strong") == 0);
    const int   n              = 2000;                /* 每节点 4 KB 出头，共约 8 MB */

    std::printf("sizeof(Node) = %zu\n", sizeof(Node));
    std::printf("闭合边是 %s，节点数 %d\n", closing_strong ? "shared_ptr" : "weak_ptr", n);
    report("建环之前");
    build_ring(n, closing_strong);
    report("函数返回后");
    std::printf("  未释放块数 %ld\n", g_live);
    return 0;
}
```

两个节点互相指着时，`use_count` 会停在 2；把外部那两个引用都清掉之后它归零，
**对象却还在**——计数归零只说明「外部引用没了」，
而环内部那两条强引用互相撑着对方，**谁也不会先放手**
（《05-类与面向对象/06-RAII 与资源管理.md》第 5.4 小节）。

放大到 2000 个节点，两种闭合方式的对照：

`实测数据`
`Text`

```text

闭合边是 shared_ptr，节点数 2000
建环之前     未释放     0 块   工作集   4431872 字节
建完之后     未释放  2000 块   工作集  13479936 字节
函数返回后   未释放  2000 块   工作集  13479936 字节
  未释放块数 2000

$ b03_shptr_cycle weak
sizeof(Node) = 4128
闭合边是 weak_ptr，节点数 2000
建环之前     未释放     0 块   工作集   4423680 字节
建完之后     未释放  2000 块   工作集  13471744 字节
```

`实测数据`

| 闭合边 | 建完之后未释放 | 函数返回后未释放 | 函数返回后工作集 |
|---|---|---|---|
| `shared_ptr` | 2000 块 | **2000 块** | **13,479,936 字节** |
| `weak_ptr` | 2000 块 | **0 块** | **5,840,896 字节** |

两边的结构、节点数、建完之后占的内存完全一样；
**差别只在最后那条边是强引用还是弱引用**，一边全部还回去，一边全部留着。
`sizeof(Node)` 是 4128，`make_shared` 一次分配 4128 + 16 = 4144 字节，
2000 个正好 8,288,000 字节，与工作集涨的那 9 MB 对得上。

> [!CAUTION]
> **用 `shared_ptr` 表达「两个对象互相关联」时，边必须有方向。**
> 表示「我拥有它」的边用 `shared_ptr`，表示「我只是知道它、不决定它的生死」的边用 `weak_ptr`。
> 全部用 `shared_ptr` 就是循环引用，也就是一块谁也收不回来的内存。

还有一条与环无关的事实：**链式结构的析构是递归的**。
同样的结构去掉闭合边、只留一条 20000 个节点的单向链，释放头节点时以 `0xC00000FD`
（栈溢出）终止；降到 2000 个节点则正常结束。

## 3.2 `weak_ptr` 的 `lock` 与 `expired`

`weak_ptr` 只有四个动作：

| 写法 | 作用 |
|---|---|
| `w.expired()` | 对象是否已经析构 |
| `w.use_count()` | 看一眼当前的强计数 |
| `w.lock()` | 升级成 `shared_ptr`；对象已析构时返回空的 |
| `w = sp`、`w.reset()` | 指向或放弃 |

**升级必须用 `lock()`，不能先 `expired()` 再访问**：两步之间对象可能就没了。
`lock()` 要么给出一个能用的 `shared_ptr`，要么给出空的，中间没有缝。

`C++`

```cpp
/* b03_weak_ptr.cpp    编译：g++ -std=c++17 b03_weak_ptr.cpp -o b03_weak_ptr */
#include <cstdio>
#include <memory>
#include <string>
#include <utility>
#include <vector>

class Texture {
public:
    explicit Texture(std::string name) : name_(std::move(name)) {
        std::printf("  载入贴图 %s\n", name_.c_str());
    }
    ~Texture() { std::printf("  卸载贴图 %s\n", name_.c_str()); }

private:
    std::string name_;
};

/* 一个不持有所有权的缓存：弱引用指向贴图，谁都不用了就自己消失 */
class TextureCache {
public:
    std::shared_ptr<Texture> get(const std::string &name) {
        for (auto &entry : entries_) {
            if (entry.first == name) {
                std::shared_ptr<Texture> hit = entry.second.lock();   /* 还活着就升级 */
                if (hit) {
                    std::printf("  缓存命中 %s，use_count = %ld\n", name.c_str(), hit.use_count());
                    return hit;                                   /* 计数 +1，寿命被延长 */
                }
                std::printf("  缓存里的 %s 已经没了，重新载入\n", name.c_str());
            }
        }
        std::shared_ptr<Texture> fresh = std::make_shared<Texture>(name);
        entries_.emplace_back(name, fresh);                          /* 存进去的是弱引用 */
        return fresh;
    }

    void dump() const {
        std::printf("  缓存里有 %zu 条记录，第一条 expired = %d\n",
                    entries_.size(), entries_[0].second.expired() ? 1 : 0);
    }

private:
    std::vector<std::pair<std::string, std::weak_ptr<Texture>>> entries_;
};

int main() {
    std::printf("1. expired 与 lock 的三种状态\n");
    std::weak_ptr<Texture> w;                        /* 默认：不指向任何控制块 */
    std::printf("  默认构造：expired = %d，lock() 非空 = %d\n",
                w.expired() ? 1 : 0, w.lock() ? 1 : 0);
    {
        std::shared_ptr<Texture> s = std::make_shared<Texture>("石头");
        w = s;
        std::printf("  指着一个活对象：expired = %d，lock() 非空 = %d\n",
                    w.expired() ? 1 : 0, w.lock() ? 1 : 0);
    }                                                /* 强引用归零，对象析构 */
    std::printf("  对象析构之后：expired = %d，lock() 非空 = %d\n\n",
                w.expired() ? 1 : 0, w.lock() ? 1 : 0);

    std::printf("2. 缓存：弱引用不阻止对象回收\n");
    TextureCache cache;
    {
        std::shared_ptr<Texture> a = cache.get("草地");
        std::shared_ptr<Texture> b = cache.get("草地");     /* 第二次：命中 */
        std::printf("  a 与 b 指着同一张：%d\n", (a == b) ? 1 : 0);
    }
    std::printf("  外部引用全部消失：\n");
    cache.dump();
    {
        std::shared_ptr<Texture> c = cache.get("草地");     /* 重新载入 */
    }
    cache.dump();
    return 0;
}
```

`实测数据`
`Text`

```text
1. expired 与 lock 的三种状态
  默认构造：expired = 1，lock() 非空 = 0
  载入贴图 石头
  指着一个活对象：expired = 0，lock() 非空 = 1
  卸载贴图 石头
  对象析构之后：expired = 1，lock() 非空 = 0

2. 缓存：弱引用不阻止对象回收
  载入贴图 草地
  缓存命中 草地，use_count = 2
  a 与 b 指着同一张：1
  卸载贴图 草地
  外部引用全部消失：
  缓存里有 1 条记录，第一条 expired = 1
  缓存里的 草地 已经没了，重新载入
  载入贴图 草地
  卸载贴图 草地
  缓存里有 2 条记录，第一条 expired = 1
```

几处对照：

| 观察 | 说明 |
|---|---|
| 默认构造的 `weak_ptr`，`expired()` 返回**真** | 不指向任何控制块，等同于「已经没了」 |
| 缓存命中时 `use_count = 2` | `lock()` 返回的那个 `shared_ptr` 也占一个强引用 |
| `卸载贴图 草地` 出现在 `外部引用全部消失` 之前 | 缓存里存的是弱引用，拦不住对象析构 |

**缓存是这个机制最典型的用途**：表里记着「有这个东西」，但不阻止它被回收；
下次要用时先 `lock()`，拿到就复用，拿不到就重建。

# 第 4 节 怎么选

三种所有权的选择标准只有一条：**这份资源由几个使用者共同决定寿命**。
拿不准时，应当从最简单的那一种开始。

| 情形 | 选什么 | 理由 |
|---|---|---|
| 一份资源一个主人 | `unique_ptr` | 零额外开销，所有权最清楚 |
| 函数内部临时造的对象 | `unique_ptr` | 与裸指针同样大小 |
| 释放动作不是 `delete` | `unique_ptr` + 自定义删除器 | 删除器写在类型里；无状态时不占对象空间 |
| 函数只接收、不持有 | `const T &` 或 `T *` | 借用不涉及所有权 |
| 对象要交给别人，自己不再管 | `unique_ptr<T>` 按值参数 + `std::move` | 调用处一眼看出所有权走了 |
| 数量在运行期决定的一串对象 | `std::vector<T>` | 比 `unique_ptr<T[]>` 好用 |
| 只认裸数组的接口需要一块缓冲区 | `unique_ptr<T[]>` | 数组特化保证 `delete[]` |
| 生命周期由多个使用者共同决定 | `shared_ptr` | 最后一份引用消失时析构 |
| 需要共享，而且多数时候是同一个对象 | `shared_ptr` + `make_shared` | 一次分配 |
| 只是观察，不决定生死 | `weak_ptr` | 不加强计数，能断环 |
| 双向关联里的反向边 | `weak_ptr` | 边必须有方向 |
| 成员函数里要把 `this` 交出去 | `enable_shared_from_this` | 保证只有一个控制块 |

一条总的倾向，与《05-类与面向对象/06-RAII 与资源管理.md》第 5.5 小节一致：

> [!IMPORTANT]
> **能用栈上的对象就不用指针，能用引用就不用智能指针，
> 能用 `unique_ptr` 就不用 `shared_ptr`。**
> `shared_ptr` 多出来的控制块、原子计数与「谁都可能是最后一个」这层不确定性，
> 只在真的需要共享所有权时才值得付。

三种所有权在签名上的形态完全不同，**读签名就能知道调用方要不要交出东西**：

| 形态 | 签名 | 调用处 |
|---|---|---|
| 借用，不动所有权 | `void f(const T &)` 或 `void f(const T *)` | `f(x)`、`f(p.get())` |
| 交出所有权 | `void f(std::unique_ptr<T>)` | `f(std::move(p))` |
| 转交再收回 | `std::unique_ptr<T> f(std::unique_ptr<T>)` | `p = f(std::move(p))` |
| 共享 | `void f(const std::shared_ptr<T> &)` | `f(sp)` |

四种签名各自对应一段可以直接跑的代码：

`C++`

```cpp
/* b03_ownership.cpp    编译：g++ -std=c++17 b03_ownership.cpp -o b03_ownership */
#include <cstdio>
#include <memory>
#include <utility>

struct Buffer {
    int id;
    explicit Buffer(int i) : id(i) { std::printf("  Buffer(%d) 建立\n", id); }
    ~Buffer() { std::printf("  Buffer(%d) 销毁\n", id); }
};

/* 借用：只看一眼，不动所有权 */
static void use(const Buffer &b) { std::printf("  借用 %d\n", b.id); }

/* 交出：按值收，调用处必须写 std::move */
static void take(std::unique_ptr<Buffer> b) { std::printf("  收下 %d\n", b->id); }

/* 转交再收回：所有权出去转一圈又回来 */
static std::unique_ptr<Buffer> reconfigure(std::unique_ptr<Buffer> b) {
    std::printf("  改配 %d\n", b->id);
    return b;                                        /* 返回时又是一次移动 */
}

/* 共享：按 const 引用收，不加计数 */
static void share(const std::shared_ptr<Buffer> &b) {
    std::printf("  共享 %d，use_count = %ld\n", b->id, b.use_count());
}

int main() {
    std::printf("1. 借用：void f(const T &)\n");
    {
        std::unique_ptr<Buffer> p = std::make_unique<Buffer>(1);
        use(*p);
        std::printf("  调用之后 p 非空 = %d\n", p ? 1 : 0);
    }

    std::printf("2. 交出：void f(std::unique_ptr<T>)\n");
    {
        std::unique_ptr<Buffer> p = std::make_unique<Buffer>(2);
        take(std::move(p));
        std::printf("  交出之后 p 非空 = %d\n", p ? 1 : 0);
    }

    std::printf("3. 转交再收回：std::unique_ptr<T> f(std::unique_ptr<T>)\n");
    {
        std::unique_ptr<Buffer> p = std::make_unique<Buffer>(3);
        p = reconfigure(std::move(p));               /* 不收回返回值，这份资源就丢了 */
        std::printf("  收回来之后 p 非空 = %d\n", p ? 1 : 0);
    }

    std::printf("4. 共享：void f(const std::shared_ptr<T> &)\n");
    {
        std::shared_ptr<Buffer> sp = std::make_shared<Buffer>(4);
        share(sp);
        std::printf("  调用之后 use_count = %ld（按引用传，计数没变）\n", sp.use_count());
    }
    return 0;
}
```

`Text`

```text

  Buffer(1) 建立
  借用 1
  调用之后 p 非空 = 1
  Buffer(1) 销毁
2. 交出：void f(std::unique_ptr<T>)
  Buffer(2) 建立
  收下 2
  Buffer(2) 销毁
  交出之后 p 非空 = 0
3. 转交再收回：std::unique_ptr<T> f(std::unique_ptr<T>)
  Buffer(3) 建立
```

# 第 5 节 代价

前面各节反复说「`shared_ptr` 有代价」。**代价具体是多少要测出来才作数**，
这一节把它拆成三块：大小、引用计数、一次拷贝的时间。

## 5.1 大小

`实测数据`

| 类型 | `sizeof`（64 位，`g++` 15.2.0 MinGW-w64） |
|---|---|
| `T *` | 8 |
| `std::unique_ptr<T>` | 8 |
| `std::unique_ptr<T>` + 无状态删除器 | 8 |
| `std::unique_ptr<T>` + 32 字节有状态删除器 | 40 |
| `std::unique_ptr<T[]>` | 8 |
| `std::shared_ptr<T>` | 16 |
| `std::weak_ptr<T>` | 16 |

打印这份表只需要一个程序：

`C++`

```cpp
/* b03_sizes.cpp    编译：g++ -std=c++17 b03_sizes.cpp -o b03_sizes */
#include <cstdio>
#include <memory>

struct Empty {                                       /* 无状态删除器：空类 */
    void operator()(int *) const {}
};

struct Fat {                                         /* 有状态删除器：32 字节 */
    char pad[32];
    void operator()(int *) const {}
};

int main() {
    std::printf("T *                            %2zu\n", sizeof(int *));
    std::printf("unique_ptr<int>                %2zu\n", sizeof(std::unique_ptr<int>));
    std::printf("unique_ptr<int, Empty>         %2zu   （空删除器被优化掉）\n",
                sizeof(std::unique_ptr<int, Empty>));
    std::printf("unique_ptr<int, Fat>           %2zu   （32 字节删除器）\n\n",
                sizeof(std::unique_ptr<int, Fat>));

    std::printf("unique_ptr<int[]>              %2zu   （数组特化也是 8）\n",
                sizeof(std::unique_ptr<int[]>));
    std::printf("unique_ptr<int[], Fat>         %2zu\n\n", sizeof(std::unique_ptr<int[], Fat>));

    std::printf("shared_ptr<int>                %2zu\n", sizeof(std::shared_ptr<int>));
    std::shared_ptr<int> sp(new int(1), Fat{});
    std::printf("shared_ptr 配同一个 Fat 删除器  %2zu   （删除器进了控制块，不占这份空间）\n",
                sizeof(sp));
    std::printf("weak_ptr<int>                  %2zu\n", sizeof(std::weak_ptr<int>));
    return 0;
}
```

`实测数据`
`Text`

```text
T *                             8
unique_ptr<int>                 8
unique_ptr<int, Empty>          8   （空删除器被优化掉）
unique_ptr<int, Fat>           40   （32 字节删除器）

unique_ptr<int[]>               8   （数组特化也是 8）
unique_ptr<int[], Fat>         40

shared_ptr<int>                16
shared_ptr 配同一个 Fat 删除器  16   （删除器进了控制块，不占这份空间）
weak_ptr<int>                  16
```

规则很简单：

| 类型 | 大小 |
|---|---|
| `unique_ptr<T, D>` | `sizeof(T *)` + `sizeof(D)`（空删除器被优化掉） |
| `shared_ptr<T>` | `2 × sizeof(void *)`，与 `T` 和删除器都无关 |

**把裸指针换成 `unique_ptr` 不会让对象变大**；换 `shared_ptr` 要付 8 字节，
另外还要付一次控制块分配（第 2.3 小节）。

## 5.2 引用计数是原子操作

`shared_ptr` 的计数可以在多个线程里同时加减，因此用的必须是原子操作。
「一次赋值」编成汇编后的结果如下：

`C++`

```cpp
/* b03_refcount_asm.cpp    编译：g++ -std=c++17 -O2 -S b03_refcount_asm.cpp -o b03_refcount_asm.s */
#include <memory>

/* 一次 shared_ptr 赋值：析构旧的、拷贝新的，各涉及一次引用计数改动 */
void assign_shared(std::shared_ptr<int> &dst, const std::shared_ptr<int> &src) {
    dst = src;
}

/* 对照：裸指针赋值只有一条存储指令 */
void assign_raw(int *&dst, int *src) {
    dst = src;
}
```

`实测数据`
`Assembly`

```asm
# MinGW-w64 g++ 15.2.0，-O2 -S。只摘出与计数有关的部分，注释是后加的
_Z10assign_rawRPiS_:
    movq    %rdx, (%rcx)                 # 裸指针：一条存储指令，就这一条
    ret

_Z13assign_sharedRSt10shared_ptrIiERKS0_:
    ...
    cmpq    %rcx, %rdx
    je      .L13                         # 两边控制块相同：什么都不用做
    testq   %rdx, %rdx
    je      .L16
    ...
.L17:
    lock addl   $1, 8(%rdx)              # 新的一份：强计数加一（带 lock）
    ...
.L24:
    movl    $-1, %r8d
    lock xaddl  %r8d, (%r10)             # 旧的一份：强计数减一（带 lock）
```

**两条 `lock` 前缀指令就是引用计数的代价。**
`lock` 让这一条指令独占缓存行，即使单线程跑也一样要走总线仲裁；
它与普通 `add` 不是一回事。

同一份汇编里还有 `.L16` 到 `.L17` 之间的一个分支：
libstdc++ 会先看一个内部标志（`_CRT_MT`，表示程序里有没有线程），
单线程时走不带 `lock` 的那条。本机上这个标志的值是 2，
因此走的是带 `lock` 的那条——这也与下面测出来的量级对得上。

## 5.3 拷贝的开销

`C++`

```cpp
/* b03_cost.cpp    编译：g++ -std=c++17 -O2 b03_cost.cpp -o b03_cost */
#include <atomic>
#include <chrono>
#include <cstdio>
#include <memory>
#include <vector>

static long long g_sum = 0;                          /* 结果落到全局，编译器就不能删掉循环 */

static double ms_since(std::chrono::steady_clock::time_point t0) {
    return std::chrono::duration<double, std::milli>(
               std::chrono::steady_clock::now() - t0).count();
}

int main() {
    const int       n      = 100000;                 /* 表长 */
    const int       rounds = 1000;                   /* 合计 1 亿次 */
    const long long total  = (long long)n * rounds;

    std::vector<int *>                raw(n, nullptr);
    std::vector<std::shared_ptr<int>> shr;
    shr.reserve(n);
    for (int i = 0; i < n; ++i) {
        raw[i] = new int(i);
        shr.push_back(std::make_shared<int>(i));
    }

    std::printf("一、%lld 次引用计数自增（只做原子加，不碰对象）\n", total);
    std::atomic<long long> cnt{0};
    auto t_a0 = std::chrono::steady_clock::now();
    for (int r = 0; r < rounds; ++r) {
        for (int i = 0; i < n; ++i) {
            cnt.fetch_add(1, std::memory_order_relaxed);
        }
    }
    double t_atomic = ms_since(t_a0);
    std::printf("  atomic fetch_add(relaxed)  %8.1f 毫秒   即 %.2f 纳秒一次\n",
                t_atomic, t_atomic * 1e6 / (double)total);
    g_sum += cnt.load();

    std::printf("二、%lld 次拷贝一个指针（含取对象求和）\n", total);
    auto t0 = std::chrono::steady_clock::now();
    long long s1 = 0;
    for (int r = 0; r < rounds; ++r) {
        for (int i = 0; i < n; ++i) {
            int *q = raw[i];                         /* 只是复制一个地址 */
            s1 += *q;
        }
    }
    double t_raw = ms_since(t0);
    g_sum += s1;

    auto t1 = std::chrono::steady_clock::now();
    long long s2 = 0;
    for (int r = 0; r < rounds; ++r) {
        for (int i = 0; i < n; ++i) {
            std::shared_ptr<int> q = shr[i];         /* 复制地址 + 一次原子加 + 一次原子减 */
            s2 += *q;
        }
    }
    double t_shr = ms_since(t1);
    g_sum += s2;

    std::printf("  裸指针                     %8.1f 毫秒   即 %.2f 纳秒一次\n",
                t_raw, t_raw * 1e6 / (double)total);
    std::printf("  shared_ptr                 %8.1f 毫秒   即 %.2f 纳秒一次\n",
                t_shr, t_shr * 1e6 / (double)total);
    std::printf("  两者加数一致 = %d\n", s1 == s2);
    std::printf("  shared_ptr 的一次拷贝 ÷ 一次原子加 = %.1f\n", t_shr / t_atomic);

    for (int i = 0; i < n; ++i) delete raw[i];
    return g_sum == 0 ? 1 : 0;
}
```

`实测数据`
`Text`

```text
一、100000000 次引用计数自增（只做原子加，不碰对象）
  atomic fetch_add(relaxed)     363.0 毫秒   即 3.63 纳秒一次
二、100000000 次拷贝一个指针（含取对象求和）
  裸指针                         39.4 毫秒   即 0.39 纳秒一次
  shared_ptr                   1037.9 毫秒   即 10.38 纳秒一次
  两者加数一致 = 1
  shared_ptr 的一次拷贝 ÷ 一次原子加 = 2.9
```

`实测数据`

| 操作 | 每次耗时 | 说明 |
|---|---|---|
| 一次 `atomic fetch_add(relaxed)` | **3.63 纳秒** | 一次带 `lock` 的加法 |
| 裸指针拷贝 | 0.39 纳秒 | 一条存储指令 |
| `shared_ptr` 拷贝 | **10.38 纳秒** | 一加一减两次原子操作 |
| `shared_ptr` 拷贝 ÷ 一次原子加 | **2.9** | 与「两次原子操作」对得上 |

**`shared_ptr` 的一次拷贝就是两次原子操作**，实测比值 2.9 与这个结论一致。
裸指针那一列只有 0.39 纳秒，因为那个循环能被向量化，`shared_ptr` 那一版不行——
**这个差距里既有原子操作，也有「优化不掉」。**

> [!IMPORTANT]
> **这些开销只在「拷贝得很频繁」或「数量很大」时才看得出来。**
> 一次拷贝约 10 纳秒，绝大多数代码里它的影响远小于一次文件读写或一次字符串拼接。
> 该用 `shared_ptr` 的地方不要因为这点开销就不用，
> 但也不要为了少写一个 `unique_ptr` 就换成它。

# 第 6 节 检查清单与速查表

代码写完之后应当逐条核对一遍，这能挡掉本章绝大多数问题。

## 6.1 速查表

| 名字 | 一句话用途 | 典型坑 |
|---|---|---|
| `std::unique_ptr<T>` | 独占所有权，析构时 `delete` | 忘了 `std::move`（编译错误）；两个 `unique_ptr` 接同一个裸指针 |
| `std::make_unique<T>(...)` | 推荐的创建方式 | C++14 起才有 |
| `p.get()` | 取裸指针，不动所有权 | 拿它去 `delete`，或又造一个智能指针 |
| `p.release()` / `p.reset(q)` | 交出裸指针 / 释放旧的再接管新的 | 交出去之后忘了谁负责释放 |
| `std::unique_ptr<T[]>` | 数组，析构时 `delete[]` | 与 `unique_ptr<T>` 用混；在 `unique_ptr<T>` 上写 `p[i]` |
| 自定义删除器 | 把「怎么释放」写进类型 | 有状态删除器会让 `unique_ptr` 变大 |
| `std::shared_ptr<T>` | 共享所有权，最后一份引用析构 | 从同一个裸指针造两个 |
| `std::make_shared<T>(...)` | 一次分配同时得到对象与控制块 | 对象很大且 `weak_ptr` 存在时间长时内存不提前归还 |
| `p.use_count()` | 看一眼强计数 | 多线程里这个值随时会变，不能拿它做判断 |
| `std::weak_ptr<T>` | 不持有所有权的观察者 | 先 `expired()` 再解引用（要用 `lock()`） |
| `w.lock()` | 升级成 `shared_ptr` | 忘了判空 |
| `std::enable_shared_from_this<T>` | 让成员函数交出唯一的控制块 | 构造函数里调用；与 `shared_ptr<T>(this)` 混用 |
| `std::get_deleter<D>(sp)` | 从控制块里取出删除器 | 类型不匹配时返回空指针 |
| `std::allocate_shared<T>(a, ...)` | 用自定义分配器一次分配 | 分配器要能分配控制块 |

## 6.2 检查清单

| 检查 | 为什么 |
|---|---|
| 业务代码里还有裸的 `new`、`delete`、`fopen` 吗 | 它们应当只出现在 RAII 包装的构造函数里 |
| 每个 `unique_ptr` 的所有权来路清楚吗 | 两个 `unique_ptr` 接同一个裸指针就是双重释放 |
| `new T[n]` 配的是 `unique_ptr<T[]>` 吗 | 配错了要等到析构才看得出来，后果是堆损坏（第 1.4 小节） |
| `shared_ptr` 是从裸指针造的吗 | 同一个裸指针造两个就是两个控制块（第 2.4 小节） |
| 有没有成员函数写 `std::shared_ptr<T>(this)` | 改成 `shared_from_this()` + `enable_shared_from_this` |
| 两个对象互相关联时，边都有方向吗 | 全用 `shared_ptr` 就是循环引用（第 3.1 小节） |
| 缓存、观察者、索引用的是 `weak_ptr` 吗 | 用 `shared_ptr` 会让被引用者永远不释放 |
| 长链表的析构会不会递归太深 | 两万个 `shared_ptr` 节点会栈溢出（第 3.1 小节） |
| 能写成 `const T &` 的参数写成智能指针了吗；能用 `unique_ptr` 的地方用成 `shared_ptr` 了吗 | 借用不涉及所有权；`shared_ptr` 多 8 字节、多一次分配、多两次原子操作 |

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 所有权 | Ownership | 谁负责释放这份资源；写在类型里比写在注释里可靠 |
| 独占所有权 | Unique ownership | 一份资源一个主人，对应 `unique_ptr` |
| 共享所有权 | Shared ownership | 生命周期由多个使用者共同决定，对应 `shared_ptr` |
| 控制块 | Control block | `shared_ptr` 里存放强计数、弱计数、删除器与分配器的那块内存 |
| 强计数 | Strong count / `use_count` | 持有对象所有权的 `shared_ptr` 个数；归零时析构对象 |
| 弱计数 | Weak count | 指向同一控制块的 `weak_ptr` 个数；与强计数一起决定控制块何时释放 |
| 删除器 | Deleter | 智能指针析构时调用的释放动作；数组特化 `unique_ptr<T[]>` 用 `delete[]` |
| 循环引用 | Reference cycle | 两个对象互相持有对方的 `shared_ptr`，计数降不到零 |
| `weak_ptr` | — | 不增加强计数的观察者指针，用 `lock()` 升级 |
| `enable_shared_from_this` | — | 让对象记住管着自己的那个控制块 |

# 附录 A 复现本章节实测

## A.1 环境

各程序用 `g++` 15.2.0（MinGW-w64）、`-std=c++17` 编译，平台为 Windows 11 x86-64；
计时与汇编那两组额外加了 `-O2`，其余用默认。

`sizeof` 与耗时都随平台和标准库实现变化。换 32 位目标时所有指针减半；
换 libstdc++ 之外的实现时控制块的大小也可能不同。

## A.2 崩溃那一组的复现命令

两个程序都会以堆损坏结束，Windows 的退出码是 `-1073740940`，即 `0xC0000374`。

`Bash`

```bash

g++ -std=c++17 b03_sft_wrong.cpp  -o b03_sft_wrong  && ./b03_sft_wrong
```

`Text`

```text
两个程序都用 setvbuf(stdout, nullptr, _IONBF, 0) 关掉了标准输出的缓冲，
因此崩溃之前的输出仍然看得到。
```

Linux 侧有 AddressSanitizer 可用，《05-类与面向对象/06-RAII 与资源管理.md》
第 2.2 小节给过复现命令。

## A.3 进程内存那一组怎么读

`b03_shptr_cycle.cpp` 用了 `GetProcessMemoryInfo`（`<psapi.h>`，MinGW-w64 下不需要
额外加 `-lpsapi`），给出的是**工作集**，即当前常驻在物理内存里的字节数。

**释放之后工作集不立刻回落到起点**，因为内存还给了分配器，
而分配器不一定马上还给系统。有意义的是两个模式之间的对照：
「建完之后」两边接近，「函数返回后」相差 7.6 MB。
