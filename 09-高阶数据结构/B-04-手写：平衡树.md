有序插入十万个键，朴素搜索树树高十万层、每次查找 142188 纳秒，
而 AVL 把树高压到 17、查找 40.6 纳秒。这一章讲**怎么写出一棵平衡树**，
以红黑树为主——因为 `std::map` 用的就是它（`A-07` 从实现头文件里核过这一点），

红黑树有两个出名的难处：**插入修复要分情况**，**删除修复更难**。
这一章不背性质表，而是讲清每种情况**在修什么**，
再给两条真正管用的调试手段：**校验不变式**与**把树画出来**。

本章是**指南**：讲要点与陷阱，不贴整份实现。

# 第 1 节 不变式

红黑树给每个节点加一个颜色，要求四条：

| 不变式 | 在修什么 |
|---|---|
| 每个节点是红或黑 | —— |
| 根是黑的 | 排除边界情形，让修复有落脚点 |
| **红节点的孩子必须是黑的** | 同一路径上不能连着两个红节点 |
| **从任一节点到它所有叶子的路径上，黑节点个数相同** | 各条路径的长度被锁在一个范围内 |

前三条加上第四条推出的结论是：**最长路径不超过最短路径的两倍**。
`A-07` 给过对照：AVL 是 `1.44 log₂ n`，红黑树是 `2 log₂(n+1)`，
十万个键时最坏比较次数约 24 对 34——**多十次比较，换掉大量结构调整**。

> [!IMPORTANT]
> **写实现时不要背这四条，而要能回答「我正在恢复哪一条」。**
> 插入修复只可能破坏「红节点的孩子是黑的」这一条
> （新节点是红的，它的父亲可能也是红的）；
> 删除修复破坏的是「黑节点个数相同」这一条。**知道破坏的是哪条，就知道该往哪修。**

# 第 2 节 旋转

`A-07` 用实测演示过：旋转**只改三个指针，中序顺序完全不变**。

`C++`

（下面是节选：左旋；右旋完全对称）

```cpp
void rotate_left(Node* x) {
    Node* y = x->right;
    x->right = y->left;                    // ① 把 y 的左子树过继给 x
    if (y->left) y->left->parent = x;
    y->parent = x->parent;                 // ② y 顶替 x 的位置
    if (!x->parent) root_ = y;
    else if (x == x->parent->left) x->parent->left = y;
    else x->parent->right = y;
    y->left = x;                           // ③ x 变成 y 的左孩子
    x->parent = y;
}
```

**写对旋转的三个要点**：

1. **有没有父指针**：没有父指针就必须在递归里把新的子树根**返回**给调用方；
   有父指针则可以就地改（本机 `std::map` 的实现有父指针，
   这也是 `A-03` 里「迭代器能 `--`」的原因之一）；
2. **别忘更新父指针**：三处链接要成对更新，漏一处就会出现「孩子认父、父不认孩子」；
3. **旋转之后要更新子树信息**：如果节点上记了高度、大小这类东西，旋转完必须重算。

# 第 3 节 插入修复

## 3.1 新节点染红

**新插入的节点一定是红的。** 理由：插入一个黑节点会让那条路径的黑节点数
比别的路径多一个，直接破坏第四条——那是最难修的一条。
染红则最多破坏「红节点的孩子是黑的」这一条，好修。

## 3.2 分情况：看叔叔的颜色

修复时看的是**父亲与叔叔**（祖父的另一个孩子）：

| 情形 | 叔叔的颜色 | 怎么修 | 在修什么 |
|---|---|---|---|
| 1 | 红 | 父亲与叔叔染黑、祖父染红，**把祖父当成新的「当前节点」继续往上修** | 把「双红」往上推 |
| 2 | 黑（且当前节点是内侧孩子） | 先对父亲旋转一次，**变成情形 3** | 把折线拉直 |
| 3 | 黑（且当前节点是外侧孩子） | 祖父染红、父亲染黑，对祖父旋转一次 | 局部重排，修复结束 |

`Text`

```text
   情形 1：叔叔是红的              情形 3：叔叔是黑的（外侧）
        G（黑）                        G（黑）
       /   \                          /   \
    P（红） U（红）      ──►        P（红） U（黑）   ──►   P（黑）
     |                              |                     /   \
    N（红）                         N（红）              N（红） G（红）
                                                                    \
                                                                     U（黑）
   父叔染黑、祖父染红              祖父染红、父亲染黑，对祖父右旋
   双红被推到祖父那一层            这一棵子树修好了
```

> [!TIP]
> **情形 1 是唯一「需要继续往上」的情况**，另两种都在本层结束。
> 写循环时把这一点记住，就不会写出「修完还往上跑」的死循环。

## 3.3 修完之后

**根永远染黑。** 情形 1 可能一路推到根，此时把根染黑即可——
它让所有路径的黑节点数一起加一，不变式仍然成立。

# 第 4 节 删除为什么难

## 4.1 难在两处

| 难点 | 说明 |
|---|---|
| 被删节点有两个孩子 | 要先和后继（右子树里最小的）**交换位置**，转成「删一个最多只有一个孩子的节点」 |
| 删掉的是黑节点 | **那条路径的黑节点数少了一个**，第四条被破坏，要从孩子那一侧往上修 |

**第二处是红黑树最复杂的地方**：修复要分四种情形，
判断依据是**兄弟的颜色**与**兄弟两个孩子的颜色**。

## 4.2 四种情形在修什么

| 情形 | 兄弟的情况 | 怎么修 |
|---|---|---|
| 1 | 兄弟是红的 | 兄弟染黑、父亲染红，对父亲旋转——**转成后三种之一** |
| 2 | 兄弟是黑的，两个孩子都黑 | 兄弟染红，**把「缺一个黑」往上推给父亲** |
| 3 | 兄弟是黑的，远侄子黑、近侄子红 | 近侄子染黑、兄弟染红，对兄弟旋转——**转成情形 4** |
| 4 | 兄弟是黑的，远侄子是红的 | 兄弟继承父亲的颜色、父亲染黑、远侄子染黑，对父亲旋转，**修复结束** |

**与插入修复对照着记**：插入是「双红往上推」，删除是「缺黑往上推」；
两者都有「先转成另一种情形」的中间步骤，也都只有一种情况需要继续往上。

## 4.3 一条实用建议

> [!WARNING]
> **第一次写红黑树，先只写插入，删除用「标记删除」顶着。**
> 这样能先把旋转、颜色、不变式校验这三件事写对；
> 删除那四种情形等插入跑通、校验器也写好之后再补。
> 反过来（先啃删除）会因为一处颜色写错而排查很久，而那时还没有校验手段。

# 第 5 节 调试：两条真正管用的手段

## 5.1 校验不变式

**每次修改之后跑一遍校验器**，比盯着一堆 `if` 猜要快得多。

`C++`

（下面是节选：校验器的骨架）

```cpp
// 返回这棵子树的黑高度；同时校验四条不变式，违反就报错
int check(const Node* p) {
    if (!p) return 1;                                  // 空节点算一个黑
    if (p->color == RED) {                             // 红节点的孩子必须黑
        if ((p->left && p->left->color == RED) ||
            (p->right && p->right->color == RED)) fail("红节点的孩子是红的");
    }
    if (p->left && p->right && !(key(p->left) < key(p) && key(p) < key(p->right)))
        fail("搜索树性质被破坏");
    const int lh = check(p->left), rh = check(p->right);
    if (lh != rh) fail("两条路径的黑节点数不同");       // 第四条
    return lh + (p->color == BLACK ? 1 : 0);
}
```

**校验器要放在两个地方**：单元测试里，以及**调试构建**里每次插入删除之后
（发布构建里关掉）。它把「颜色写错」这类错误从「查半天」变成「当场报出哪一条不变式破了」。

## 5.2 把树画出来

`A-07` 用过按层打印的写法（那个程序的输出就是一棵树的形状）。
红黑树再进一步：**把颜色一起打出来**，一眼就能看出「有没有连着两个红」。

`Text`

```text
        B:30
       /     \
    R:10     B:50          B=黑 R=红
    /  \     /  \
 B:5  B:20 R:40 B:60
                     ← 这里 50 是黑、40 是红，允许；
                       若 50 也是红就违反了「红孩子必须黑」
```

> [!TIP]
> **随机测 + 校验器是最省力的组合**：随机插删几万次，
> 每一步都跑校验器。红黑树的分支很多，手写的用例覆盖不全，
> 而随机序列能在几分钟内把四种删除情形都走一遍。

# 第 6 节 迭代器与「下一个是谁」

树是有序的，因此迭代器必须能按中序走。两种做法：

| 做法 | 优点 | 代价 |
|---|---|---|
| 每个节点存父指针 | `++`／`--` 都是 `O(1)`（本机 `std::map` 的做法） | 每个节点多 8 字节 |
| 用栈模拟 | 节点省 8 字节 | 迭代器变重，`--` 很难做 |

`A-03` 里有一条结论与此相关：**`map` 的迭代器是双向的**，
`--` 也要是常数时间——这也是多数实现选父指针的原因。

**写 `++` 的三步**（有父指针时）：

1. 有右子树 → 右子树里最左的那个；
2. 没有右子树 → 往上走，直到「我是我父亲的左孩子」，那个父亲就是下一个；
3. 走到根还没有 → 到了 `end()`。

**`--` 是镜像**：有左子树就找最右，否则往上找「我是右孩子」的那个父亲。

# 第 7 节 常见陷阱清单

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 新节点染黑 | 直接破坏「黑节点数相同」，极难修 | **新节点染红** |
| 旋转漏更新父指针 | 树从中间断开 | 三处链接成对更新 |
| 修完忘了把根染黑 | 根是红时后续修复出错 | 每次修复结束都染黑根 |
| 情形 1 忘了继续往上 | 双红留在树里 | 把祖父当成新的当前节点 |
| 删除时忘了先与后继交换 | 两个孩子的情形无法处理 | 先交换，转成单孩子情形 |
| 没有校验器 | 颜色错了只能靠肉眼找 | 随机测 + 每步校验 |
| 直接照抄别人的删除代码 | 不理解为哪四种情形，改不动 | 按第 4.2 小节的表逐条对 |
| 节点里存高度却不更新 | 平衡判断失效 | 旋转后重算，或用颜色代替高度 |

> [!NOTE]
> 这一章收成三句话：
> **红黑树要维持的是四条不变式，修复时先问「我破坏了哪一条」；
> 插入只有「双红往上推」这一条主线，删除只有「缺黑往上推」这一条主线，
> 其余都是把情形转成能收尾的那一种；
> 真正省时间的是工具——一个校验不变式的函数加一棵能打印出来的树。**

# 术语表

| 术语 | 含义 |
|---|---|
| **红黑树** | 用节点颜色约束路径长度的搜索树 |
| **黑高度** | 从某节点到叶子路径上的黑节点个数 |
| **旋转** | 改变树的形状但不改变中序顺序的局部调整 |
| **双红** | 父亲与孩子都是红，违反「红孩子的孩子必须黑」 |
| **叔叔** | 父亲的兄弟；插入修复靠它的颜色分情况 |
| **后继** | 中序里紧跟在后面的节点；删除两个孩子的情形要用它 |
| **不变式校验器** | 每次修改后检查结构是否合法的函数 |
| **标记删除** | 不真删、只打标记的做法；先跑通插入时可以用 |
