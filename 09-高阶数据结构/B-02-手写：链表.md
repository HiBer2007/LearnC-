`A-02` 讲了 `list` 与 `forward_list` 的用法与代价。
链表本身比动态数组简单——没有扩容、没有搬迁、没有容量，
但自己写一个仍有三件事必须想清楚：**哨兵节点要不要**、
**节点什么时候被析构**、**`splice` 到底改了哪几个指针**。
这三件事决定了迭代器稳不稳定、代码会不会漏内存、以及「把一段接到另一处」
能不能做到常数时间。

本章讲要点与陷阱，不贴整份实现。
完整的实例与练习模板见 《B-examples/09-data-structures/02-list-mini/》
与 《C-templates/09-data-structures/02-list/》。
正文里的数字全部来自 `A` 段并注明出处。

# 第 1 节 节点的形状与两种链

`A-02` 测过 `sizeof(std::list<int>)` 是 24 字节、`sizeof(std::forward_list<int>)` 是 8 字节——
差的就是「几个指针」。

`C++`

（下面是节选：两种节点的定义）

```cpp
struct ForwardNode {           // forward_list：一个后继指针
    ForwardNode* next;
    T value;
};

struct ListNode {              // list：前后两个指针
    ListNode* prev;
    ListNode* next;
    T value;
};
```

| | 单向链 | 双向链 |
|---|---|---|
| 每个节点的指针开销 | 8 字节 | 16 字节 |
| 能不能 `--` | 不能 | 能 |
| 删除当前节点 | **要先知道前驱**（否则得从头找） | 直接删 |
| 迭代器类别 | 前向 | 双向 |

**`A-02` 的实测里每元素堆字节是 `list` 24、`forward_list` 16**——
差的那 8 字节就是多出来的 `prev`。**双向的代价是每个节点多付一半的链接开销**，
换来的是「能往回走」与「删除不用先找前驱」。

# 第 2 节 哨兵节点

**哨兵是一个不存数据的节点，它的 `next` 指向第一个元素，`prev` 指向最后一个。**
有了它，插入与删除都不必再为「在头部」和「在尾部」写特例。

`Text`

```text
   没有哨兵：head 与 tail 要单独维护，插入到空链、插入到头部、
             插入到尾部、删掉最后一个 —— 四种特例

   有哨兵：  ┌──────────────────────────────┐
             │  ┌───┐   ┌───┐   ┌───┐       │
             └─►│ 1 │──►│ 2 │──►│ 3 │───────┘
                └───┘◄──└───┘◄──┘   │◄──────┘
                                   哨兵：不存数据，
                                   begin() = 哨兵->next
                                   end()   = 哨兵自己
```

| 好处 | 说明 |
|---|---|
| 空链与非空链代码一样 | 哨兵的 `next` 指回自己就是空链 |
| 头插、尾插不用特例 | 在哨兵与第一个元素之间插入，与中间插入同一段代码 |
| `end()` 有实体 | 迭代器可以指向哨兵，`--end()` 就是最后一个元素 |
| 不必维护 `head`／`tail` | 只需要一个哨兵 |

> [!TIP]
> **哨兵那一个节点的开销，换掉的是四段特例代码。**
> 判据很直接：**如果某段逻辑要反复判断「是不是第一个／最后一个」，
> 就该考虑加一个哨兵。**

# 第 3 节 所有权与析构

链表的内存管理比动态数组更简单，也更危险：**每个元素一次分配**，
因此每个节点都要单独释放一次。`A-02` 实测过这件事的代价：
每元素 24 字节、遍历一百万个元素要 38.86 毫秒（连续存储只要 1.30 毫秒）。

## 3.1 析构要顺着链走

`C++`

（下面是节选：析构的骨架）

```cpp
~List() {
    Node* p = sentinel_->next;
    while (p != sentinel_) {
        Node* next = p->next;      // 先记住下一个，再删当前
        destroy_node(p);
        p = next;
    }
    destroy_node(sentinel_);       // 哨兵也要删
}
```

**必须先记住 `next` 再删当前节点**——顺序反了就是「删完之后读已释放的内存」。

## 3.2 三条所有权规则

| 规则 | 说明 |
|---|---|
| 节点归容器所有 | 容器析构时全部删掉，`clear()` 也一样 |
| 元素归节点所有 | 删节点前先析构元素（元素可能是文件、锁、内存） |
| `splice` 是**转移**所有权 | 元素从一条链搬到另一条，**不构造也不析构** |

**第三条是链表独有的**：`splice` 之后，那些节点换了主人，
因此原来那条链的 `size` 要减、目标链要加，但**元素的构造与析构一次都不发生**。

# 第 4 节 插入与删除改哪几个指针

`C++`

（下面是节选：在 `pos` 之前插入）

```cpp
iterator insert(iterator pos, const T& value) {
    Node* cur  = pos.node_;        // pos 指向的节点
    Node* prev = cur->prev;        // 它的前驱
    Node* fresh = create_node(value);
    fresh->prev = prev;            // ① 新节点的两个指针
    fresh->next = cur;
    prev->next = fresh;            // ② 前驱指向新节点
    cur->prev  = fresh;            // ③ 后继指回新节点
    ++size_;
    return iterator(fresh);
}
```

**四个指针、三条赋值**（新节点自己那两个算一条）。
删除就是反过来的三条赋值，最后把节点释放掉。

> [!IMPORTANT]
> **链表的插入删除是常数时间，但前提是「位置已经拿到」。**
> `A-02` 测过：位置已知时插入一百万个元素是 41.435 毫秒，
> 而「先找位置再插入」的代价由查找决定——
> **链表从来不省查找，只省搬移。**

# 第 5 节 `splice`：为什么是常数时间

`splice` 把一条链上的一段（或一个）节点**摘下来接到另一处**，
一个元素都不构造、也不析构。

`Text`

```text
   把 [first, last) 接到 pos 之前，只改四个指针：

        …… ──► A ──► [first …… last) ──► B ──► ……
                       └── 摘下来 ──┘

        …… ──► A ─────────────► B ──► ……        ① A->next = last
                                ② last->prev = A
        …… ──► pos_prev ──► [first …… last) ──► pos ──► ……
                                ③ pos_prev->next = first
                                ④ first->prev = pos_prev
```

`文档`

> "6 Complexity: Constant time."
>
> "10 Complexity: Constant time."
>
> "14 Complexity: Constant time if `&x == this`; otherwise, linear time."
>
> —— N4659 §26.3.10.5 `[list.ops]`（三段分别是整条链、单个元素、按段三个重载）

| 重载 | 标准给的复杂度 | 会不会让迭代器失效 |
|---|---|---|
| `splice(pos, x)`（整条链） | **常数时间** | **不会**：节点没搬家 |
| `splice(pos, x, i)`（一个元素） | **常数时间** | 不会 |
| `splice(pos, x, first, last)`（一段） | **`&x == this` 时是常数时间；否则线性时间** | 不会 |

**按段那个重载为什么可能是线性**：把一段从**另一条**链上摘下来，
要知道它有多少个元素才能把两条链的 `size` 都改对，
而标准要求 `size()` 是常数时间——于是实现只能**数一遍**。
把一段从**自己**身上挪到别处（`&x == this`）时，总数不变，不必数，因此是常数时间。

`实测数据`

| 按段 `splice`（段长 1000，跨链） | 次数 |
|---|---|
| 改指针 | **6（与段长无关）** |
| 数元素（为维护常数时间的 `size()`） | **1000（等于段长）** |

（数字与程序见《B-examples/09-data-structures/02-list-mini/》的 README；项目把这两项分成两列打印。）

**「不会失效」这一点与复杂度是两回事**：按段搬的时候可能要数一遍元素，
但节点地址没变，指向它们的迭代器与引用仍然有效，只是换了所属的容器。

> [!WARNING]
> **`splice` 之后，两个容器的 `size` 都要改**，而且**元素不会重新构造**。
> 如果元素的析构里有副作用（比如计数、写日志），
> `splice` 不会触发它们——这与「删掉再插入」的语义不同。

# 第 6 节 迭代器的稳定性从哪来

`A-02` 与 `A-06` 都说过：**链表的插入与删除不让任何别的迭代器失效**。
原因是节点没有搬家：

| 动作 | 连续存储（`vector`） | 链式存储（`list`） |
|---|---|---|
| 扩容 | 整块搬家，**全部失效** | 没有扩容 |
| 插入 | 插入点之后整体后移 | **只改指针，谁都不动** |
| 删除 | 删除点之后整体前移 | 只有被删的那个失效 |

**手写时保住这一点的关键**：插入删除**只改指针，绝不搬元素**。
一旦写成「把值复制到相邻节点再删」，
迭代器稳定性立刻消失——那已经不是链表了。

# 第 7 节 常见陷阱清单

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 析构时先删当前再取 `next` | 读已释放内存 | 先存 `next` |
| 忘了删哨兵 | 每次构造都漏一个节点 | 析构里连哨兵一起删 |
| `insert` 里先改指针再构造节点 | 构造抛异常时链断成两截 | **先建好节点，再改指针** |
| 删除时不析构元素 | 泄漏元素持有的资源 | 先析构元素，再还内存 |
| `splice` 忘了改两个 `size` | `size()` 与实际不符 | 两边都改 |
| 单向链删除当前节点 | 找不到前驱，只能从头找 | 用「删下一个」的接口，或改双向 |
| 用链表存小对象 | 每元素 24 字节、遍历慢 30 倍 | 见 `A-02` 第 6 节的选择表 |
| 以为链表插入一定快 | 找位置的代价没算进去 | 位置已知才快 |

> [!NOTE]
> 这一章收成三句话：
> **哨兵用「多一个节点」换掉四段特例代码；
> 插入删除只改指针、不搬元素，因此别的迭代器都不失效；
> `splice` 是链表独有的操作——常数时间、不构造不析构、迭代器仍然有效。**

# 术语表

| 术语 | 含义 |
|---|---|
| **哨兵** | 不存数据的节点，串在链的两端，用来消掉边界特例 |
| **节点** | 链表里独立分配的一块内存，存元素与链接 |
| **所有权** | 谁负责释放；链表的节点归容器所有 |
| **`splice`** | 把一段节点从一条链摘下来接到另一处，不构造不析构 |
| **迭代器稳定性** | 插入删除之后，别的迭代器仍然有效 |
| **前向迭代器** | 只能 `++` 的迭代器；`forward_list` 属于这一类 |
