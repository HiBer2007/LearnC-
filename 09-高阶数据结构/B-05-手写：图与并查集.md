`A-10` 讲了图的三种存法与它们的代价，`A-12` 讲了并查集与它的两条优化。
这一章讲**怎么写**：三种存法各自的代码要点、遍历接口怎么设计
（接口决定算法能不能直接套上去）、并查集那两处优化写在哪一行。

**图的结构与遍历是两件事**：
存法只负责「谁能查到谁」，遍历只用到这个接口；
接口设计得不好，算法就得跟着结构改。**并查集只有二十行**，
但那两处优化各只有一行，写漏一行的代价 `A-12` 实测过：
从 2.637 毫秒变成 5385.970 毫秒。

本章是**指南**：讲要点与陷阱，不贴整份实现。
完整的实例与练习模板见 `【待补：B-examples/09-data-structures/】`
与 `【待补：C-templates/09-data-structures/】`。
正文里的数字全部来自 `A` 段并注明出处。

# 第 1 节 邻接表

`A-10` 实测过：稀疏图里邻接表遍历邻居比邻接矩阵快 **1197 倍**，
无向图每边 30.03 字节。

`C++`

（下面是节选：无向图的加边）

```cpp
class AdjList {
    std::vector<std::vector<int>> adj_;
public:
    explicit AdjList(int n) : adj_(static_cast<std::size_t>(n)) {}
    void add_undirected(int a, int b) {
        adj_[a].push_back(b);          // 两个方向各存一次
        adj_[b].push_back(a);
    }
    void add_directed(int from, int to) {
        adj_[from].push_back(to);      // 只存出边
    }
};
```

| 要点 | 说明 |
|---|---|
| 外层用 `vector`、每个点一个内层 `vector` | `A-10` 实测每边 30.03 字节，其中一部分是内层 `vector` 的头部（每点 24 字节） |
| 已知边数时先 `reserve` | 省掉内层 `vector` 的反复扩容——`A-10` 实测稠密档每边 17.37 字节里有一部分就是扩容余量 |
| 有向只存一侧 | `A-10` 实测省下约三分之一（1203268 → 767912 字节） |
| 带权时把邻居换成 `pair<int, 权值>` | `A-10` 实测每边从 30.03 涨到 48.08 字节 |

> [!TIP]
> **稀疏图一律用它。** 判断稀疏与否看平均度数：
> 几十以下都算稀疏，而现实里的图（社交、网页、道路、依赖）几乎都在这个范围。

# 第 2 节 邻接矩阵

## 2.1 无权图：一位一条边

`A-10` 实测：矩阵固定占 `V²/8` 字节，两万个点是 50000008 字节，
与边数无关。

`C++`

（下面是节选：位图矩阵的定位）

```cpp
class BitMatrix {
    int n_;
    std::vector<std::uint64_t> bits_;      // n*n 位
public:
    explicit BitMatrix(int n)
        : n_(n), bits_(static_cast<std::size_t>(n) * n / 64 + 1, 0) {}

    void set(int a, int b) {
        const std::size_t i = static_cast<std::size_t>(a) * n_ + b;
        bits_[i >> 6] |= 1ULL << (i & 63);          // 除以 64 与取余 64 就是移位与掩码
    }
    bool get(int a, int b) const {
        const std::size_t i = static_cast<std::size_t>(a) * n_ + b;
        return (bits_[i >> 6] >> (i & 63)) & 1ULL;
    }
};
```

| 要点 | 说明 |
|---|---|
| 用位图而不是 `bool` 数组 | 位图每格 1 位；`vector<bool>` 也是位图，但下标返回代理对象（见《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 4.5 小节） |
| 无向图两个位置都要置位 | 有向只置一个 |
| 带权要换成一格一个权值 | `A-10` 算过：两万个点的带权矩阵要 1.5 GB |

## 2.2 什么时候用

| 情况 | 用矩阵 |
|---|---|
| 点少（几百个）而边密 | 是：`V²` 小到可以忽略，换来 `O(1)` 查边，这笔取舍划算 |
| 要反复问「这两点相连吗」 | 是：`A-10` 实测查边 9 到 11 纳秒，且不随密度变化 |
| 要反复取一个点的邻居 | **否**：矩阵要扫整行，`A-10` 实测稀疏图上差 1197 倍 |
| 点很多而边稀 | **否**：`V²` 装不下 |

# 第 3 节 边表

边表只有一串 `(u, v)`。`A-10` 实测它加边最快（稀疏档 0.246 毫秒），
但查边与取邻居都要扫全表。

**它在两个场合反而合适**：

| 场合 | 为什么合适 |
|---|---|
| 只需要把所有边读一遍 | 顺序访问最紧凑，没有额外结构 |
| 边的集合要反复重建 | 加边就是一次追加，最便宜 |

`C++`

（下面是节选：带权边表的元素类型）

```cpp
struct WeightedEdge {
    int from, to, weight;
};
std::vector<WeightedEdge> edges;      // 就这么多，没有索引
```

> [!IMPORTANT]
> **边表是「先用它把边收齐，再建别的结构」的中间形态**，
> 很少直接把它当最终结构。它的价值在于：读入与生成边时，它是最直接的形式。

# 第 4 节 遍历接口怎么设计

**接口设计的目标只有一个：让算法不必知道用的是哪种存法。**

## 4.1 三种做法

| 做法 | 形状 | 适用 |
|---|---|---|
| 返回邻居数组的引用 | `const std::vector<int>& neighbors(int v)` | 邻接表——零开销，但矩阵与边表给不出这样的引用 |
| 回调／函数对象 | `template <class F> void for_each_neighbor(int v, F f)` | **三种存法都能实现**，推荐 |
| 迭代器对 | `neighbors_range(v)` 返回一对迭代器 | 最通用，但要写一套迭代器（见 `A-06` 第 6 节） |

`C++`

（下面是节选：回调式接口）

```cpp
template <class F>
void for_each_neighbor(int v, F f) const {
    for (int u : adj_[v]) f(u);        // 邻接表：直接遍历
}
// 邻接矩阵的同一个接口：
//   for (int u = 0; u < n_; ++u) if (get(v, u)) f(u);
// 边表的同一个接口：
//   for (const auto& e : edges_) if (e.from == v) f(e.to);
```

**换一种存法，算法一个字都不用改**——因为算法只依赖这个接口。

## 4.2 遍历算法要自己准备什么

| 算法 | 需要的辅助数据 | 说明 |
|---|---|---|
| 深度优先 | 一个 `visited` 数组 + 显式栈（或递归） | 递归深度可能等于点数，大图上会爆栈 |
| 广度优先 | `visited` + 队列 | —— |
| 拓扑排序 | 入度数组 + 队列 | 只对有向无环图有意义 |
| 最短路 | 距离数组 + 优先队列 | 见 `A-05` 的 `priority_queue` |

> [!WARNING]
> **图的遍历算法本身归 `08` 板块**，本章只讲接口。
> **用递归写深度优先时，链状的图（十万个点连成一条线）
> 会让递归深度等于点数**，本机默认栈大约 1 MB，
> 十万层递归足以把栈耗尽。

# 第 5 节 并查集：两处优化写在哪一行

`A-12` 的实测对照如下：同一串四十万次操作，
**都不做**要走 1649519512 步、耗时 5385.970 毫秒、最大树高 14503；
**两处优化都加上**只要 475230 步、2.637 毫秒、树高 1。

## 5.1 数据结构：一个数组

`C++`

（下面是节选：初始化与两处优化）

```cpp
std::vector<int> parent, size_;
void init(int n) {
    parent.resize(n);
    size_.assign(n, 1);
    for (int i = 0; i < n; ++i) parent[i] = i;   // 每个点自成一集合，根记自己
}

int find(int x) {                     // 优化二：路径压缩（就这几行）
    int r = x;
    while (parent[r] != r) r = parent[r];
    while (parent[x] != r) { const int next = parent[x]; parent[x] = r; x = next; }
    return r;
}

void unite(int a, int b) {            // 优化一：按大小合并（就这几行）
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    if (size_[ra] < size_[rb]) std::swap(ra, rb);   // 让 ra 是大的那棵
    parent[rb] = ra;
    size_[ra] += size_[rb];
}
```

| 优化 | 写在哪 | 作用 | `A-12` 实测（单独用） |
|---|---|---|---|
| 按大小合并 | `unite` 里的 `swap` 那一行 | 限制树高 | 树高 4、平均 2.60 步 |
| 路径压缩 | `find` 里第二个 `while` | 走过的路压平 | 树高 5、平均 6.12 步 |
| 路径减半 | `find` 里 `parent[x] = parent[parent[x]]` | 同上，代码更短 | 树高 6、平均 4.47 步 |
| 两者都用 | —— | —— | **树高 1、平均 2.38 步** |

> [!IMPORTANT]
> **两处优化各只有几行，但漏掉任一处就是几千倍的差距。**
> 工程上还有一个细节：**按大小合并的 `size_` 只在根上有效**，
> 非根节点的 `size_` 是陈旧值——不能把它当作「这个集合有多大」。

## 5.2 秩与大小

`A-12` 里写过：**秩（rank）与大小等价，不必两个都实现。**
秩记的是高度的上界，只在合并时更新根；大小记的是元素个数。
两者给出同样的 `O(log n)` 保证，选一个即可。

# 第 6 节 并查集的常见误用

| 误用 | 为什么不行 | 怎么办 |
|---|---|---|
| 想删边 | 结构里没记「当初是哪条边并起来的」 | 离线倒序处理（《09-高阶数据结构/A-12-不相交集合：只要连通性.md》第 5.3 小节有实测） |
| 想要路径 | 它连边都没存 | 用图的遍历（`08` 板块） |
| 想统计每个集合的大小 | `size_` 只在根上有效 | 求根之后读 `size_[root]` |
| 用 `find` 的返回值当「编号」比较 | 代表是谁由合并顺序决定，**不稳定** | 只用来判断「是否相同」，不要跨运行比较 |
| 在遍历中合并 | 合并会改父指针，可能影响正在走的路径 | 先把要合并的对收齐，再统一合并 |

> [!TIP]
> **代表是谁不重要，重要的是「相同与不同」。**
> 这一点决定了并查集不能用来给连通块编号（编号会随合并顺序变），
> 但很适合回答「这两个是否属于同一个集合」。

# 第 7 节 常见陷阱清单

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 邻接表不 `reserve` | 内层 `vector` 反复扩容，每边字节偏高 | 知道度数就先预留 |
| 无向图只存一侧 | 反向查不到邻居 | 两个方向都存 |
| 矩阵带权仍用位图 | 权值无处可放 | 一格一个权值（内存涨 8 倍） |
| 遍历接口绑死存法 | 换存法要改算法 | 用回调式接口 |
| 深度优先用递归且图是链状 | 栈溢出 | 改显式栈，或限制深度 |
| 并查集漏掉按大小合并 | 树退化成链，实测慢两千倍 | `unite` 里加一行 |
| 并查集漏掉路径压缩 | 同样慢很多 | `find` 里加一个循环 |
| 拿非根节点的 `size_` 当集合大小 | 读到陈旧值 | 先 `find` 再读根 |

> [!NOTE]
> 这一章收成三句话：
> **图的三种存法照 `A-10` 的实测选，写的时候记住「有向只存一侧、带权把邻居加宽」；
> 遍历接口用回调式，算法就不必知道用的是哪种存法；
> 并查集只有二十行，但两处优化各几行不能漏——实测中漏掉的代价是两千倍。**

# 术语表

| 术语 | 含义 |
|---|---|
| **邻接表** | 每个点一个数组，只存它真正的邻居 |
| **邻接矩阵** | 用 `V×V` 的表表示边；无权时一位一条边 |
| **边表** | 只存所有 `(u, v)` 对，不建索引 |
| **回调式接口** | 把「要对每个邻居做的事」当参数传进去，三种存法都能实现 |
| **并查集** | 维护一族互不相交的集合，支持合并与查询同属 |
| **按大小合并** | 合并时把小的树挂到大的下面 |
| **路径压缩／减半** | `find` 时把路径上的点挂到根／祖父上 |
| **离线倒序** | 把所有操作倒过来执行，把「删」变成「加」 |
