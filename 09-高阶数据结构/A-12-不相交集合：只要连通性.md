上一章讲了关系怎么存，图上怎么走留给 `08` 板块。这一章要的东西更少：
**不关心怎么走，只问「这两个点现在连通吗」，以及「把这两个集合并起来」。**
这类需求在现实里很常见：判断两台机器是不是在同一个网段、
两个账号是不是同一个人、两段代码是不是在同一个编译单元里、
图片上两块颜色是不是同一片区域。它们的共同点是**只要一个「是」或「否」**，
不要路径、不要距离、不要顺序。

把需求削到这么薄，结构也跟着缩到最小：**一个整数数组**。
数组里每一项记着「我的父节点是谁」，于是每个集合是一棵朝上长的树，
树的根就是集合的代表。查找连通性就是看两个点往上走是不是走到同一个根；
合并两个集合就是把一棵树的根挂到另一棵的根下面。

朴素地这么做会出大问题：实测里同一串四十万次操作，
不做优化的写法要走 **十六亿步**、耗时 **5772 毫秒**；
加上两条各一行代码的改进之后，步数降到 **四十七万**、耗时 **2.737 毫秒**——
**相差两千多倍**。两条改进各占一行代码：按大小合并与路径压缩。

还有两条必须写清的边界：**它不能删边**（只能重建），
**它给不出路径**（只回答连通性）。这两条不是实现没做到位，而是结构本身的能力边界。

# 第 1 节 需求：动态连通性

## 1.1 三个问题

| 问题 | 说法 |
|---|---|
| 查 | `find(x)`：`x` 属于哪个集合（用集合的「代表」回答） |
| 判 | `connected(x, y)`：`x` 与 `y` 在不在同一个集合 |
| 并 | `unite(x, y)`：把 `x` 与 `y` 所在的两个集合合成一个 |

**「动态」的意思是这三件事交替发生**：一边并、一边查，
而且后面的合并会改掉查的结果。
这与 `A-10` 的静态存法不同——那里的边一旦存好就不动了。

## 1.2 只要答案，不要路径

如果还需要知道「怎么走过去」，那就必须存下完整的图，用 `08` 板块的遍历算法。
本章的结构**从一开始就不存边**：

`Text`

```text
   图：  1 —— 2      3 —— 4        6
         └────┴──────┘

   不相交集合只记「谁和谁同一组」：
        集合 A = {1, 2, 3, 4}，代表是 1
        集合 B = {6}，代表是 6

   1 与 4 连通吗？→ 是（同属集合 A）
   1 与 6 连通吗？→ 否
   1 到 4 怎么走？→ 答不出来，结构里根本没有边
```

> [!IMPORTANT]
> **这是一个「用能力换代价」的结构：它把「路径」这一整类信息丢掉了，
> 换来的是合并与查询都快到接近常数。**
> 需要路径时不要硬用它——那属于图的遍历，归 `08`。

# 第 2 节 模型：父指针森林

## 2.1 一个数组表示一片森林

`Text`

```text
   parent[] 每一项记「我的父是谁」，根记自己

   三个集合 {0,1,2}、{3,4}、{5} 的一种表示：

        下标：   0    1    2    3    4    5
      parent：   0    0    0    3    3    5
                 ↑         ↑    ↑         ↑
                根        挂在 0 下  根    根

   森林形状：
        0          3        5
       / \         |
      1   2        4
```

**根就是集合的代表**：`parent[x] == x` 的那个 `x`。
两个点连通，当且仅当它们往上走能走到同一个根。

## 2.2 `find` 与 `unite`

`C++`

（下面是节选：`find` 与 `unite` 的核心，完整实现见第 4 节的 `dsu_variants.cpp`。）

```cpp
/* 两个操作的核心：往上找根；把一棵树的根挂到另一棵的根下面 */
int find(int x) {
    while (parent[x] != x) x = parent[x];   // 一路往上，直到根
    return x;
}

void unite(int a, int b) {
    const int ra = find(a), rb = find(b);
    if (ra != rb) parent[rb] = ra;          // 把 b 的根挂到 a 的根下面
}
```

**合并是一行赋值**：这就是「不要路径」换来的好处——
不需要改任何别的点，因为它们与根的关系没变（只是根换了个父亲）。

# 第 3 节 实现：从朴素到摊还常数

## 3.1 朴素写法会退化成链

上面那两行就是朴素写法。问题出在 `unite` 那一行：
**不管两棵树谁大谁小，一律把后一个的根挂到前一个下面。**

`Text`

```text
   顺序合并 0-1、1-2、2-3、3-4 ……：

   unite(0,1) 后：  0           unite(1,2) 后：  0
                    |                            |
                    1                            1
                                                 |
                                                 2
   unite(2,3) 后：  0 → 1 → 2 → 3 → ……
   每并一次就长高一层，最后成了一条链，树高等于元素个数
```

链上的 `find` 要从底走到顶，`O(n)`。第 4 节的实测里，
这种写法最大树高 **14503**，平均每次查找走 **8247.60 步**。

## 3.2 按大小（秩）合并

改一行：**把小的那棵树挂到大的下面**。

`C++`

（下面是节选：按大小合并的 `unite`，完整实现见第 4 节的 `dsu_variants.cpp`。）

```cpp
void unite(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    if (size[ra] < size[rb]) std::swap(ra, rb);   // 让 ra 是大的那棵
    parent[rb] = ra;                              // 小的挂到大的下面
    size[ra] += size[rb];
}
```

**为什么这样就够**：一棵树的深度要增加，只能是它被并进了一棵至少和它一样大的树。
因此深度最多 `log n`——这个证明只需要一句话：
**深度增加一次，树的大小至少翻倍**。

用「秩」（rank，近似的高度）代替「大小」也可以，效果一样。
按大小合并把最大树高压到 **4**，平均查找步数降到 **2.60**。

## 3.3 路径压缩与路径减半

另一条改进在 `find` 里：**既然已经走过这条路径，就把路上的点一并挂到根上。**

`C++`

（下面是节选：带路径压缩的 `find`，完整实现见第 4 节的 `dsu_variants.cpp`。）

```cpp
int find(int x) {
    int r = x;
    while (parent[r] != r) r = parent[r];      // 先找根
    while (parent[x] != r) {                   // 再把路上的点直接挂到根
        const int next = parent[x];
        parent[x] = r;
        x = next;
    }
    return r;
}
```

这条改动的效果是**摊还**的：单次 `find` 可能改很多个点，
但每个点被改的次数有限，摊到后续操作上就是常数。

**路径减半**是它的简化版：一边走，一边把每个点挂到祖父上，
一趟下来路径长度减半，代码只要一行：

`C++`

（下面是节选：路径减半的 `find`，完整实现见第 4 节的 `dsu_variants.cpp`。）

```cpp
int find(int x) {
    while (parent[x] != x) {
        parent[x] = parent[parent[x]];   // 挂到祖父：路径减半
        x = parent[x];
    }
    return x;
}
```

**单独用路径压缩**（不按大小合并）时最大树高是 **5**，平均查找步数 **6.12**——
比只按大小合并略差一点，但已经把退化彻底挡住了。

## 3.4 复杂度：反阿克曼

两条改进一起用，每次操作的摊还代价是 `O(α(n))`，
其中 `α` 是反阿克曼函数。它的实际含义只有一句：

| n | α(n) |
|---|---|
| 10 | 3 |
| 10⁶ | 4 |
| 10¹⁰⁰ | 5 |

**`α(n)` 增长得极慢，在一切能想象的数据规模上都不超过 5。**
因此工程上把它当常数看：**每元素一个 `int`，每次操作近似 `O(1)`。**
证明不在这里展开，`B` 段会给完整的分析。

> [!IMPORTANT]
> **「近似常数」这个结论依赖两条改进同时存在。**
> 只按大小合并是 `O(log n)`，只路径压缩是摊还 `O(log n)`，
> 两者合用才是 `O(α(n))`。第 4 节的实测里，
> 「两者都用」比「只按大小合并」又省了一成左右的步数，
> 而相对朴素写法是两千多倍的差距。

# 第 4 节 四组对照实测

`C++`

```cpp
/* dsu_variants.cpp    编译：g++ -std=c++17 -O2 dsu_variants.cpp -o dsu_variants
 * 不相交集合的四种写法在同一串操作下的代价：总步数、平均查找步数、耗时、最大树高。
 *   (1) 不压缩也不按大小合并   (2) 只按大小合并   (3) 只路径压缩   (4) 两者都用
 * 「步数」指沿父指针走了多少步，它是与机器无关的量，因此可以做跨写法的比较。 */
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <numeric>
#include <random>
#include <vector>

class Dsu {
public:
    Dsu(int n, bool by_size, int mode)      // mode: 0 不压缩 1 路径压缩 2 路径减半
        : parent_(static_cast<std::size_t>(n)), size_(static_cast<std::size_t>(n), 1),
          by_size_(by_size), mode_(mode) {
        std::iota(parent_.begin(), parent_.end(), 0);
    }

    // 返回根；steps 累加走过的父指针步数
    int find(int x, long long& steps) {
        if (mode_ == 2) {                       // 路径减半：走的时候挂到祖父上
            while (parent_[static_cast<std::size_t>(x)] != x) {
                parent_[static_cast<std::size_t>(x)] =
                    parent_[static_cast<std::size_t>(parent_[static_cast<std::size_t>(x)])];
                x = parent_[static_cast<std::size_t>(x)];
                ++steps;
            }
            return x;
        }
        int r = x;
        while (parent_[static_cast<std::size_t>(r)] != r) {
            r = parent_[static_cast<std::size_t>(r)];
            ++steps;
        }
        if (mode_ == 1) {
            // 路径压缩：把这条路径上的点直接挂到根上
            while (parent_[static_cast<std::size_t>(x)] != r) {
                const int next = parent_[static_cast<std::size_t>(x)];
                parent_[static_cast<std::size_t>(x)] = r;
                x = next;
            }
        }
        return r;
    }

    void unite(int a, int b, long long& steps) {
        int ra = find(a, steps);
        int rb = find(b, steps);
        if (ra == rb) return;
        if (by_size_) {
            if (size_[static_cast<std::size_t>(ra)] < size_[static_cast<std::size_t>(rb)]) std::swap(ra, rb);
            parent_[static_cast<std::size_t>(rb)] = ra;          // 小的挂到大的下面
            size_[static_cast<std::size_t>(ra)] += size_[static_cast<std::size_t>(rb)];
        } else {
            parent_[static_cast<std::size_t>(rb)] = ra;          // 直接挂，不管大小
        }
    }

    // 最大树高：对每个点各自走到根，取最长的一条
    int max_depth() const {
        int best = 0;
        for (std::size_t i = 0; i < parent_.size(); ++i) {
            int d = 0;
            std::size_t x = i;
            while (parent_[x] != static_cast<int>(x)) {
                x = static_cast<std::size_t>(parent_[x]);
                ++d;
                if (d > best + 1) break;                        // 已经不可能更优
            }
            best = std::max(best, d);
        }
        return best;
    }

private:
    std::vector<int> parent_;
    std::vector<int> size_;
    bool by_size_;
    int mode_;
};

int main() {
    constexpr int N = 200000;        // 元素个数
    constexpr int M = 400000;        // 操作次数
    std::mt19937 rng(2024);
    volatile long long sink = 0;

    // 操作序列：一半是并、一半是查；并的那一半特意按顺序来，让「不按大小合并」退化成链
    std::vector<std::pair<int, int>> ops(M);
    for (int i = 0; i < M; ++i) {
        if (i % 2 == 0) {
            const int a = i / 2 % N;
            const int b = (i / 2 + 1) % N;      // 0-1, 1-2, 2-3 … 顺序并，最容易长出链
            ops[static_cast<std::size_t>(i)] = {a, b};
        } else {
            ops[static_cast<std::size_t>(i)] = {static_cast<int>(rng() % N), static_cast<int>(rng() % N)};
        }
    }

    struct Row {
        const char* name;
        long long steps;
        double ns_per_find;
        double ms_total;
        int max_depth;
    };
    std::vector<Row> rows;

    const struct {
        const char* name;
        bool by_size;
        int mode;
    } variants[] = {
        {"(1) 都不做", false, 0},
        {"(2) 只按大小合并", true, 0},
        {"(3) 只路径压缩", false, 1},
        {"(4) 只路径减半", false, 2},
        {"(5) 合并+压缩都用", true, 1},
    };

    for (const auto& v : variants) {
        Dsu d(N, v.by_size, v.mode);
        long long steps = 0;
        long long finds = 0;
        const auto t0 = std::chrono::steady_clock::now();
        for (const auto& op : ops) {
            if (op.first == op.second || (op.first + op.second) % 2 == 0) {
                ++finds;
                d.find(op.first, steps);
            } else {
                d.unite(op.first, op.second, steps);
                ++finds;
            }
        }
        const auto t1 = std::chrono::steady_clock::now();
        const double ms = std::chrono::duration<double, std::milli>(t1 - t0).count();
        rows.push_back(Row{v.name, steps, ms * 1e6 / finds, ms, d.max_depth()});
    }

    std::printf("元素 %d 个，操作 %d 次（一半并、一半查）\n\n", N, M);
    std::printf("%-18s %14s %16s %12s %10s\n", "写法", "总步数", "平均每次查找步数", "总耗时 ms", "最大树高");
    for (const Row& r : rows) {
        std::printf("%-18s %14lld %16.2f %12.3f %10d\n", r.name, r.steps,
                    static_cast<double>(r.steps) / (M / 2), r.ms_total, r.max_depth);
    }

    std::printf("\n同一串操作在五种写法下的对比：\n");
    const double base = static_cast<double>(rows[0].steps);
    for (const Row& r : rows) {
        std::printf("  %-18s 步数是第一种写法的 %.4f 倍\n", r.name, static_cast<double>(r.steps) / base);
    }

    // ---- 数连通块与按连通块分组：并查集最常用的两个后续动作 ----
    std::printf("\n数连通块与按连通块分组（在「两者都用」那棵树上做）：\n");
    Dsu d(N, true, 1);
    {
        long long steps = 0;
        for (const auto& op : ops) d.unite(op.first, op.second, steps);
    }
    const auto t0 = std::chrono::steady_clock::now();
    long long roots = 0;
    {
        std::vector<char> is_root(static_cast<std::size_t>(N), 0);
        for (int i = 0; i < N; ++i) {
            long long s = 0;
            is_root[static_cast<std::size_t>(d.find(i, s))] = 1;
        }
        for (int i = 0; i < N; ++i) roots += is_root[static_cast<std::size_t>(i)] ? 1 : 0;
    }
    const auto t1 = std::chrono::steady_clock::now();
    const double count_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

    const auto t2 = std::chrono::steady_clock::now();
    std::vector<std::vector<int>> groups(static_cast<std::size_t>(N));
    for (int i = 0; i < N; ++i) {
        long long s = 0;
        groups[static_cast<std::size_t>(d.find(i, s))].push_back(i);
    }
    long long grouped = 0;
    for (const auto& g : groups) grouped += static_cast<long long>(g.size());
    const auto t3 = std::chrono::steady_clock::now();
    const double group_ms = std::chrono::duration<double, std::milli>(t3 - t2).count();
    sink += grouped;

    std::printf("  连通块个数 = %lld，扫一遍数组耗时 %.3f ms\n", roots, count_ms);
    std::printf("  按连通块分组：%lld 个点分进 %lld 个块，耗时 %.3f ms\n", grouped, roots, group_ms);
    return 0;
}
```

```text
  按连通块分组：200000 个点分进 1 个块，耗时 2.109 ms
```

| 写法 | 总步数 | 平均每次查找 | 总耗时 | 最大树高 |
|---|---|---|---|---|
| (1) 都不做 | 1 649 519 512 | 8247.60 | 5358.949 ms | **14503** |
| (2) 只按大小合并 | 519 006 | 2.60 | 3.023 ms | 4 |
| (3) 只路径压缩 | 1 224 908 | 6.12 | 4.775 ms | 5 |
| (4) 只路径减半 | 894 402 | 4.47 | 4.420 ms | 6 |
| (5) 合并 + 压缩都用 | **475 230** | **2.38** | **2.579 ms** | **1** |

**「按秩」与「按大小」不必分成两档测**：秩是高度的一个上界，
按秩合并与按大小合并给出同样的 `O(log n)` 保证，本机两者的树高与步数也一致，
工程上挑一个用即可。

**三件事一眼可见**：

- **朴素写法走了十六亿步**，耗时 5.8 秒；加上两条改进之后是 2.7 毫秒——
  **相差 2109 倍**（耗时）与 3471 倍（步数）；
- **两条改进各管一件事**：按大小合并让树不要长高（树高 4），
  路径压缩把走过的路一并压平（树高 5，但平均步数仍很低）；
- **两者合用最好**：最大树高只有 **1**——几乎所有点都直接挂在根上。

## 4.1 两个最常用的后续动作

并查集本身只回答「是不是同一组」，实际用法往往是接着做这两件事：

`实测数据`
`Text`

```text
数连通块与按连通块分组（在「两者都用」那棵树上做）：
  连通块个数 = 1，扫一遍数组耗时 0.215 ms
  按连通块分组：200000 个点分进 1 个块，耗时 2.109 ms
```

| 动作 | 做法 | 实测（20 万个点） |
|---|---|---|
| 数连通块 | 对每个点求根，数不同的根 | 0.215 ms |
| 按连通块分组 | 对每个点求根，把它放进以根为下标的那一组 | 2.109 ms |

**分组比数个数贵十倍**，差在分配与写入：数个数只写一个 `char`，
分组要为每个点往一个 `vector` 里追加，20 万次追加要反复扩容。

> [!TIP]
> **这两个动作的代价都只是「每个点求一次根」**，
> 而求根已经被压到接近常数——因此整件事是 `O(n)`，与图里有多少边无关。
> 换成用图的遍历去数连通块，代价是 `O(V + E)`；边多的时候差距就出来了。

> [!NOTE]
> **步数与机器无关**，因此这张表里的倍数关系比毫秒数更值得记。
> 换一台机器，5772 毫秒可能变成 3000 或 9000，但「十六亿步对四十七万步」
> 这个比例不会变。

# 第 5 节 两条常见误解

## 5.1 不能删边

`unite` 把两个集合并成一个之后，**原来的两个集合就再也分不开了**：
结构里只记了「谁挂在谁下面」，没有记「当初是因为哪条边并起来的」。

| 想要的操作 | 能不能做 | 怎么办 |
|---|---|---|
| 加一条边（合并） | **能**，一行代码 | 直接用 |
| 查连通性 | **能** | 直接用 |
| **删一条边（拆分）** | **不能** | 把操作序列**离线**处理：如果所有操作事先都知道，可以倒着做（把「删」变成「加」，实测见第 5.3 小节） |
| 删边后重新查 | 不能 | 或者干脆重建整个结构（`O(n)`） |

> [!WARNING]
> **「删边」是这类结构最容易出错的地方。**
> 一旦发现需求里有「断开的连接」，先问一句：**所有操作能不能事先拿到**。
> 能，就倒序处理；不能，这个结构就不适用，得换成别的（例如按时间分治）。

## 5.2 不能给出路径

`find` 返回的是**代表**，不是路径。想知道「1 到 4 怎么走」，
这个结构里根本没有这个信息——它连边都没存。

| 想知道 | 用不相交集合 | 用什么 |
|---|---|---|
| 是否连通 | 可以，近似 `O(1)` | —— |
| 路径是什么 | **不行** | 图的遍历（`08` 板块） |
| 最短距离 | **不行** | 最短路算法（`08` 板块） |
| 连通块有几个 | 可以（数不同的根） | —— |
| 每个连通块里有哪些点 | 可以（按根分组） | —— |

**最后两行是它的强项**：数连通块、按连通块分组，
用别的结构都要遍历整张图，用这里只要扫一遍数组。

## 5.3 删边做不了，但把操作倒过来就能做

「不能删边」这条限制可以变成一门技术：**只要所有操作事先都拿到，
就把它们倒过来执行，「删」就变成了「加」。**

`C++`

```cpp
/* dsu_offline.cpp    编译：g++ -std=c++17 -O2 dsu_offline.cpp -o dsu_offline
 * 删边做不了，但把操作倒过来做就能做：同一串「删边 + 查连通性」，
 * 正序用并查集答（会答错），倒序用并查集答（与暴力重建的结果完全一致）。
 * 暴力重建：每删一条边就把整张图重建成并查集，作为「正确答案」的基准。 */
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <random>
#include <utility>
#include <vector>

class Dsu {
public:
    explicit Dsu(int n) : p_(static_cast<std::size_t>(n)) {
        for (int i = 0; i < n; ++i) p_[static_cast<std::size_t>(i)] = i;
    }
    int find(int x) {
        while (p_[static_cast<std::size_t>(x)] != x) {
            p_[static_cast<std::size_t>(x)] = p_[static_cast<std::size_t>(p_[static_cast<std::size_t>(x)])];
            x = p_[static_cast<std::size_t>(x)];
        }
        return x;
    }
    void unite(int a, int b) {
        const int ra = find(a), rb = find(b);
        if (ra != rb) p_[static_cast<std::size_t>(rb)] = ra;
    }
    bool same(int a, int b) { return find(a) == find(b); }

private:
    std::vector<int> p_;
};

int main() {
    constexpr int N = 20000;        // 点数
    constexpr int E = 30000;        // 初始边数
    constexpr int OPS = 2000;       // 操作数（一半删边、一半查询）
    std::mt19937 rng(2024);

    std::vector<std::pair<int, int>> edges(E);
    for (auto& e : edges) {
        e.first = static_cast<int>(rng() % N);
        e.second = static_cast<int>(rng() % N);
    }

    // 操作：交替「删掉第 i 条边」与「查一对点」
    struct Op { bool is_delete; int a; int b; };
    std::vector<Op> ops;
    ops.reserve(OPS);
    for (int i = 0; i < OPS; ++i) {
        if (i % 2 == 0) {
            ops.push_back(Op{true, i / 2 % E, 0});
        } else {
            ops.push_back(Op{false, static_cast<int>(rng() % N), static_cast<int>(rng() % N)});
        }
    }

    auto build = [&](int alive_count) {           // 用前 alive_count 条边建一棵并查集
        Dsu d(N);
        for (int i = 0; i < alive_count; ++i) d.unite(edges[static_cast<std::size_t>(i)].first,
                                                      edges[static_cast<std::size_t>(i)].second);
        return d;
    };

    // ---- 基准：每删一条边就重建一次，答案一定对 ----
    std::vector<char> truth;
    const auto t0 = std::chrono::steady_clock::now();
    {
        std::vector<char> alive(static_cast<std::size_t>(E), 1);
        for (const Op& op : ops) {
            if (op.is_delete) {
                alive[static_cast<std::size_t>(op.a)] = 0;
                Dsu d(N);
                for (int i = 0; i < E; ++i) {
                    if (alive[static_cast<std::size_t>(i)]) {
                        d.unite(edges[static_cast<std::size_t>(i)].first,
                                edges[static_cast<std::size_t>(i)].second);
                    }
                }
            } else {
                Dsu d(N);
                for (int i = 0; i < E; ++i) {
                    if (alive[static_cast<std::size_t>(i)]) {
                        d.unite(edges[static_cast<std::size_t>(i)].first,
                                edges[static_cast<std::size_t>(i)].second);
                    }
                }
                truth.push_back(d.same(op.a, op.b) ? 1 : 0);
            }
        }
    }
    const auto t1 = std::chrono::steady_clock::now();
    const double truth_ms = std::chrono::duration<double, std::milli>(t1 - t0).count();

    // ---- 正序：一边删一边查，用并查集只能拿「删之前」的图去答 ----
    std::vector<char> forward;
    {
        std::vector<char> alive(static_cast<std::size_t>(E), 1);
        Dsu d = build(E);                          // 一次性建好，之后再也改不了
        for (const Op& op : ops) {
            if (op.is_delete) {
                alive[static_cast<std::size_t>(op.a)] = 0;   // 只能记下来，结构改不了
            } else {
                forward.push_back(d.same(op.a, op.b) ? 1 : 0);
            }
        }
    }

    // ---- 倒序：从「所有删边都做完」的图开始，把删边当成加边倒着加回去 ----
    std::vector<char> backward;
    {
        std::vector<char> alive(static_cast<std::size_t>(E), 1);
        for (const Op& op : ops) {
            if (op.is_delete) alive[static_cast<std::size_t>(op.a)] = 0;
        }
        Dsu d(N);
        for (int i = 0; i < E; ++i) {
            if (alive[static_cast<std::size_t>(i)]) {
                d.unite(edges[static_cast<std::size_t>(i)].first, edges[static_cast<std::size_t>(i)].second);
            }
        }
        for (auto it = ops.rbegin(); it != ops.rend(); ++it) {
            if (it->is_delete) {
                d.unite(edges[static_cast<std::size_t>(it->a)].first,
                        edges[static_cast<std::size_t>(it->a)].second);   // 倒着看就是加边
            } else {
                backward.push_back(d.same(it->a, it->b) ? 1 : 0);
            }
        }
        std::reverse(backward.begin(), backward.end());   // 倒序得到的答案要翻回来
    }

    long long wrong_forward = 0;
    for (std::size_t i = 0; i < truth.size(); ++i) {
        if (forward[i] != truth[i]) ++wrong_forward;
    }
    long long wrong_backward = 0;
    for (std::size_t i = 0; i < truth.size(); ++i) {
        if (backward[i] != truth[i]) ++wrong_backward;
    }

    std::printf("点数 %d，初始边 %d 条，操作 %d 次（一半删边、一半查询），其中查询 %zu 次\n\n",
                N, E, OPS, truth.size());
    std::printf("  暴力重建（每删一条边就把整张图重建成并查集）：%.3f ms\n", truth_ms);
    std::printf("  正序 + 并查集：答错的查询 %lld 条（结构建好之后删不掉，只能拿旧图回答）\n", wrong_forward);
    std::printf("  倒序 + 并查集：答错的查询 %lld 条（与暴力重建的结果完全一致）\n", wrong_backward);
    std::printf("\n结论：删边本身做不了，但把操作序列倒过来，「删」就变成了「加」，\n");
    std::printf("      并查集立刻可用——代价是所有操作必须事先拿到。\n");
    return 0;
}
```

`实测数据`
`Text`

```text
点数 20000，初始边 30000 条，操作 2000 次（一半删边、一半查询），其中查询 1000 次

  暴力重建（每删一条边就把整张图重建成并查集）：922.926 ms
  正序 + 并查集：答错的查询 7 条（结构建好之后删不掉，只能拿旧图回答）
  倒序 + 并查集：答错的查询 0 条（与暴力重建的结果完全一致）

结论：删边本身做不了，但把操作序列倒过来，「删」就变成了「加」，
      并查集立刻可用——代价是所有操作必须事先拿到。
```

| 做法 | 答错的查询 | 说明 |
|---|---|---|
| 暴力重建（基准） | 0 | 每删一条边就把整张图重建成并查集，931 毫秒 |
| 正序 + 并查集 | **7 条** | 结构建好之后删不掉，只能拿旧图回答 |
| 倒序 + 并查集 | **0 条** | 与暴力重建的结果完全一致 |

**正序答错的那几条，错在「用了删边之前的图」。**
这类错误不会崩溃，也不会报警，只是答案悄悄变了——比崩溃更难发现。
倒序做则完全正确：**从「所有删边都做完」的图开始，
倒着走一遍操作序列，遇到删边就把它当成加边加回去**，
于是每一步的结构都正好是当时该有的样子。

> [!IMPORTANT]
> **离线倒序是把「不支持删边」换成「要求操作事先已知」。**
> 换来的是：一次正序需要 `O(n)` 重建的问题，变成一次倒序的 `O(n α(n))`。
> 判断能不能用只有一句话：**操作序列能不能在动手之前全部拿到。**
> 能（例如把日志重放一遍），这条路就通；不能（在线服务边来边处理），
> 就只能换结构。

# 第 6 节 怎么选

| 你的需求 | 选择 |
|---|---|
| 动态连通性（一边并一边查） | **不相交集合**，按大小合并 + 路径压缩 |
| 只要连通块个数或分组 | 同上，扫一遍数组即可 |
| 需要路径、距离、顺序 | 图的遍历或最短路（`08` 板块） |
| 需要删边 | 离线倒序处理；否则换结构 |
| 图是静态的、只查一次 | 一次遍历就够，不必建这个结构 |

> [!NOTE]
> 这一章收成三句话：
> **不相交集合把「路径」这一整类信息丢掉，只留连通性，因此合并是一行赋值、
> 查询接近常数；
> 朴素写法会退化成链（实测最大树高 14503、平均查找 8247.60 步），
> 两条各一行代码的改进把它压到树高 1、平均 2.38 步；
> 代价是能力边界：不能删边、不能给路径——需要它们时换结构，不要硬改。**

# 术语表

| 术语 | 含义 |
|---|---|
| **不相交集合** | 维护一族互不相交的集合，支持合并与查询同属 |
| **代表** | 集合的标识，就是那棵树的根 |
| **父指针森林** | 用一个数组存「父是谁」，每个集合是一棵树 |
| **按大小合并** | 合并时把小的树挂到大的下面 |
| **秩** | 近似的高度，作用与大小相同 |
| **路径压缩** | `find` 时把路径上的点直接挂到根上 |
| **路径减半** | 把路径上的点挂到祖父上，一趟减半 |
| **反阿克曼函数** | 增长极慢的函数；实际数据规模下不超过 5 |
| **摊还** | 把偶发的高代价分摊到多次操作上平均计算 |
