前面几章一直在用迭代器，却没有单独说过它是什么。它承担着一件
别的机制都没承担的事：**让算法不必知道容器**。
`std::sort`、`std::find`、`std::accumulate` 这些算法的参数里从来没有出现过 `vector`、`list` 或 `map`，
它们只认两个东西——一个开始位置、一个结束位置。
换成别的容器，只要这两个位置还符合约定，同一份算法代码一个字都不用改。

这份约定由两部分组成：**迭代器能做什么**（能不能 `++`、能不能 `--`、能不能跳着走），
以及**它承诺了什么**（哪些操作是常数时间，什么时候会失效）。
能做什么由五个类别分层描述，算法在编译期就能问出一个迭代器属于哪一类，
并据此决定用哪种写法——这就是同一个 `std::distance` 在 `vector` 上是常数时间、
在 `list` 上是线性的原因。

而「什么时候失效」是这份约定里最容易被忽略的一半：
容器一改动，手里的迭代器可能已经指向一块被释放的内存。
普通构建、`-D_GLIBCXX_DEBUG` 与 AddressSanitizer 三种查法各自能抓到一部分：
不加开关时什么也查不出，后两者分别盯着容器的不变量与已释放的内存。

# 第 1 节 迭代器是容器与算法之间的契约

## 1.1 算法只认两个位置

`std::find` 的实现里没有「容器」这个概念，它的全部参数是两个位置：

`C++`

```cpp
/* what_algorithm_needs.cpp
 * 编译：g++ -std=c++17 -O2 what_algorithm_needs.cpp -o what_algorithm_needs
 * 算法真正用到迭代器的哪些操作：把 find 与 distance 各手写一遍就看清了 */
#include <cstddef>
#include <cstdio>
#include <iterator>
#include <vector>

// 这就是 std::find 的形状：只用到 !=、* 与 ++
template <class It, class T>
It my_find(It first, It last, const T& value) {
    for (; first != last; ++first) {
        if (*first == value) return first;
    }
    return last;
}

// 标签分派：随机访问迭代器一次减法，其余一步一步数
template <class It>
typename std::iterator_traits<It>::difference_type
my_distance_impl(It first, It last, std::random_access_iterator_tag) {
    return last - first;
}

template <class It>
typename std::iterator_traits<It>::difference_type
my_distance_impl(It first, It last, std::input_iterator_tag) {
    typename std::iterator_traits<It>::difference_type n = 0;
    for (; first != last; ++first) ++n;
    return n;
}

template <class It>
typename std::iterator_traits<It>::difference_type my_distance(It first, It last) {
    using Cat = typename std::iterator_traits<It>::iterator_category;
    return my_distance_impl(first, last, Cat{});
}

int main() {
    std::vector<int> v{10, 20, 30};
    const auto it = my_find(v.begin(), v.end(), 20);
    std::printf("手写 find 找到 %d\n", it != v.end() ? *it : -1);
    std::printf("手写 distance = %td\n", my_distance(v.begin(), v.end()));

    // 同一份实现换到链表上：category 一变，走的就是另一条分支
    std::printf("（同一份 my_distance 用在 list 上会走数数那条分支，见第 3 节）\n");
    return 0;
}
```

`实测数据`
`Text`

```text
手写 find 找到 20
手写 distance = 3
（同一份 my_distance 用在 list 上会走数数那条分支，见第 3 节）
```

上面的 `my_distance` 里出现了 `iterator_traits` 与两个标签类型，
它们是第 1.3 小节的内容；这里先看 `my_find`：
**它只用了 `!=`、`*`、`++` 三个操作。**
这三个操作就是「输入迭代器」这一档的全部要求——
换句话说，只要一个类型能提供这三个操作，`std::find` 就能用在它上面。

## 1.2 五类迭代器：每一类多承诺一件事

标准把迭代器分成五类，**每一类在前一类的基础上多提供一组操作**。

| 类别 | 能做 | 不能做 | 谁提供 |
|---|---|---|---|
| 输入迭代器 | `*`（读一次）、`++`、`==` | 往回走、多次读同一个位置 | `istream_iterator` |
| 输出迭代器 | `*it = v`、`++` | 读 | `ostream_iterator`、`back_inserter` |
| 前向迭代器 | 上面全部，且可反复读写、可多趟遍历 | `--` | `forward_list`、`unordered_map` |
| 双向迭代器 | 再加上 `--` | `+ n`、相减、比较大小 | `list`、`set`、`map` |
| 随机访问迭代器 | 再加上 `+ n`、`- n`、相减、`<`、`[]` | —— | `vector`、`deque`、`int*` |

**类别不是标签，是承诺。** 说一个迭代器是随机访问的，
等于承诺「`it + n` 是常数时间」；算法据此选择写法：
是走一步看一步，还是直接算出中点、一步跳过去。
所以同一个算法在两类迭代器上的实现可能完全不同，而调用方看不出来。

`C++`

```cpp
/* iterator_categories.cpp    编译：g++ -std=c++17 -O2 iterator_categories.cpp -o iterator_categories
 * 各容器的迭代器属于哪一类：把 iterator_category 的标签类型名打出来 */
#include <cstdio>
#include <deque>
#include <forward_list>
#include <iterator>
#include <list>
#include <map>
#include <set>
#include <sstream>
#include <string>
#include <typeinfo>
#include <unordered_map>
#include <vector>

/* 用一个函数重载把标签类型翻译成中文名。
 * 参数类型就是标签本身，因此重载决议就是「这个迭代器属于哪一类」。 */
static const char* name(std::input_iterator_tag) { return "输入迭代器"; }
static const char* name(std::output_iterator_tag) { return "输出迭代器"; }
static const char* name(std::forward_iterator_tag) { return "前向迭代器"; }
static const char* name(std::bidirectional_iterator_tag) { return "双向迭代器"; }
static const char* name(std::random_access_iterator_tag) { return "随机访问迭代器"; }

template <class It>
static void show(const char* what) {
    using Cat = typename std::iterator_traits<It>::iterator_category;
    std::printf("  %-34s %s\n", what, name(Cat{}));
}

int main() {
    std::printf("== 各迭代器的类别（由 iterator_traits 取标签，用重载决议翻译）==\n");
    show<int*>("int*（C 数组的元素指针）");
    show<std::vector<int>::iterator>("vector<int>::iterator");
    show<std::vector<int>::const_iterator>("vector<int>::const_iterator");
    show<std::deque<int>::iterator>("deque<int>::iterator");
    show<std::list<int>::iterator>("list<int>::iterator");
    show<std::forward_list<int>::iterator>("forward_list<int>::iterator");
    show<std::set<int>::iterator>("set<int>::iterator");
    show<std::map<int, int>::iterator>("map<int,int>::iterator");
    show<std::unordered_map<int, int>::iterator>("unordered_map<int,int>::iterator");
    show<std::istream_iterator<int>>("istream_iterator<int>");
    show<std::ostream_iterator<int>>("ostream_iterator<int>");
    show<std::back_insert_iterator<std::vector<int>>>("back_insert_iterator<vector<int>>");

    std::printf("\n== 编译期可判定的部分：用 if constexpr 在编译期分支 ==\n");
    std::printf("  vector 迭代器可做 it += n ? %s\n",
                std::is_same<std::iterator_traits<std::vector<int>::iterator>::iterator_category,
                             std::random_access_iterator_tag>::value ? "是" : "否");
    std::printf("  list   迭代器可做 it += n ? %s\n",
                std::is_same<std::iterator_traits<std::list<int>::iterator>::iterator_category,
                             std::random_access_iterator_tag>::value ? "是" : "否");
    return 0;
}
```

**三点结论**：C 数组的元素指针是随机访问迭代器，
因此裸数组能直接进算法；`unordered_map` 的迭代器只到前向，
因为桶内的链是单向的；插入迭代器是输出迭代器，它只能写、不能读。

## 1.3 `iterator_traits`：算法怎么问出类别

算法需要的信息有五样：类别、元素类型、指针类型、引用类型、距离类型。
C++17 里它们从 `iterator_traits<It>` 取；对自定义迭代器来说，
这五样就是你在迭代器类里写的五个类型别名。

`Text`

```text
   iterator_traits<It>
        │
        ├── iterator_category   →  哪一类（决定算法用哪种写法）
        ├── value_type          →  元素类型（决定临时变量怎么声明）
        ├── difference_type     →  距离类型（决定 distance 返回什么）
        ├── pointer             →  operator-> 返回什么
        └── reference           →  *it 返回什么
```

对指针这类「不是类」的迭代器，`iterator_traits` 由标准库专门特化出来；
对类类型，默认版本直接从类里那五个别名取。第 6 节会自己写一个迭代器，
把五个别名补齐之后，`std::sort` 就能直接用。

# 第 2 节 范围

## 2.1 四种取首尾的写法

| 写法 | 返回 | 什么时候用 |
|---|---|---|
| `v.begin()` / `v.end()` | `iterator` | 要改元素 |
| `v.cbegin()` / `v.cend()` | `const_iterator` | 只读，避免误改元素 |
| `std::begin(v)` / `std::end(v)` | 同上（成员版本的转发） | **写模板**：容器与 C 数组都能用 |
| `v.rbegin()` / `v.rend()` | `reverse_iterator` | 逆序遍历 |

`C++`

```cpp
/* begin_end.cpp    编译：g++ -std=c++17 -O2 begin_end.cpp -o begin_end
 * begin/end 的几种写法：成员、自由函数、cbegin；以及 C 数组也能进算法 */
#include <algorithm>
#include <cstdio>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> v{5, 3, 1, 4, 2};
    int c_array[5] = {5, 3, 1, 4, 2};

    std::printf("== 四种取首尾的写法，结果一样 ==\n");
    std::printf("  v.begin()      -> %d\n", *v.begin());
    std::printf("  std::begin(v)  -> %d\n", *std::begin(v));
    std::printf("  v.cbegin()     -> %d（const_iterator）\n", *v.cbegin());
    std::printf("  std::begin(c_array) -> %d（C 数组在 C++17 里也有 begin/end）\n",
                *std::begin(c_array));

    std::printf("\n== C 数组直接进算法 ==\n");
    std::sort(std::begin(c_array), std::end(c_array));
    std::printf("  sort 之后：");
    for (int x : c_array) std::printf("%d ", x);
    std::printf("\n");
    std::printf("  std::size(c_array) = %zu\n", std::size(c_array));

    std::printf("\n== vector 与数组一样可以排序 ==\n");
    std::sort(v.begin(), v.end());
    std::printf("  sort 之后：");
    for (int x : v) std::printf("%d ", x);
    std::printf("\n");

    std::printf("\n== 空容器的 begin 与 end 相等 ==\n");
    std::vector<int> empty;
    std::printf("  empty.begin() == empty.end() ? %s\n",
                empty.begin() == empty.end() ? "是" : "否");
    std::printf("  对空区间调用 std::sort 是安全的（区间为空，什么都不做）\n");
    std::sort(empty.begin(), empty.end());
    std::printf("  std::sort(empty.begin(), empty.end()) 已执行，没有崩溃\n");
    return 0;
}
```

## 2.2 范围 `for` 展开成什么

范围 `for` 的展开规则有三条，都不复杂。

`文档`

> "The range-based for statement
> `for ( for-range-declaration : for-range-initializer ) statement`
> is equivalent to
> `{`
> `  auto&& __range = for-range-initializer;`
> `  auto __begin = begin-expr;`
> `  auto __end = end-expr;`
> `  for (; __begin != __end; ++__begin) {`
> `    for-range-declaration = *__begin;`
> `    statement`
> `  }`
> `}`
> where — (1.1) if the *for-range-initializer* is an expression, it is regarded as if it were
> surrounded by parentheses (so that a comma operator cannot be reinterpreted as delimiting
> two init-declarators);"
>
> —— N4659 §9.5.4/1（p.164）

三点结论：**它只用 `begin`、`end`、`!=`、`*`、`++`**；
`begin-expr` 优先找成员，找不到就找自由函数——这一步走的是 ADL
（实参依赖查找：到实参所属的命名空间里找同名函数）；
绑定用的是 `auto&&`，因此不会平白多一次拷贝。

`C++`

```cpp
/* range_for.cpp    编译：g++ -std=c++17 -O2 range_for.cpp -o range_for
 * 范围 for 展开成什么；自定义类型怎样才支持范围 for */
#include <cstdio>
#include <iterator>
#include <vector>

/* 一个最小的「范围」：只有 begin/end 成员函数。 */
struct IntRange {
    int lo, hi;
    struct It {
        int cur;
        int operator*() const { return cur; }
        It& operator++() { ++cur; return *this; }
        bool operator!=(const It& o) const { return cur != o.cur; }
    };
    It begin() const { return It{lo}; }
    It end() const { return It{hi}; }
};

/* 只有自由函数 begin/end 的类型：范围 for 通过 ADL 也能找到它们。 */
struct FreeRange {
    int n;
};
static const int* begin(const FreeRange& r) { return &r.n; }
static const int* end(const FreeRange& r) { return &r.n + 1; }

int main() {
    std::printf("== 范围 for 展开后 ==\n");
    std::vector<int> v{10, 20, 30};
    for (int x : v) std::printf("%d ", x);
    std::printf("\n");
    {
        auto __b = v.begin();
        auto __e = v.end();
        for (; __b != __e; ++__b) {
            int x = *__b;                       // 展开后的样子
            std::printf("%d ", x);
        }
        std::printf("（这是上面那个循环的展开写法）\n");
    }

    std::printf("\n== 只有 begin/end 成员的类型 ==\n");
    for (int x : IntRange{1, 6}) std::printf("%d ", x);
    std::printf("\n");

    std::printf("\n== 只有自由 begin/end 的类型（ADL）==\n");
    for (int x : FreeRange{42}) std::printf("%d ", x);
    std::printf("\n");

    std::printf("\n== 用引用避免拷贝 ==\n");
    std::vector<std::pair<int, int>> pairs{{1, 2}, {3, 4}};
    for (auto& p : pairs) p.second += 100;      // 按引用绑定，改的是容器里的对象
    for (const auto& p : pairs) std::printf("(%d,%d) ", p.first, p.second);
    std::printf("\n");
    return 0;
}
```

`Text`

`IntRange` 只提供了 `begin`、`end` 与一个能 `*`、`++`、`!=` 的最小迭代器，
范围 `for` 就用上了。**这反过来说明了范围 `for` 到底要求什么**：
它不要求容器、不要求 `size()`、也不要求元素连续。

> [!WARNING]
> **`for (auto x : v)` 是拷贝，不是引用。**
> 元素是 `std::string` 或结构体时，每一轮都要复制一份；
> 只是读就写 `const auto&`，要改就写 `auto&`。
> 唯一适合按值写的情形是元素很小（`int`、`char`、指针）或者本来就该拿一份副本。

## 2.3 半开区间：为什么是 `[first, last)`

标准算法接受的区间是**左闭右开**的：`first` 指向第一个元素，
`last` 指向最后一个元素的**下一个位置**。

| 好处 | 说明 |
|---|---|
| 空区间能表示 | `first == last` 就是空，不需要额外标志 |
| 循环条件统一 | `it != last` 一种写法，不用区分「是不是最后一个」 |
| 拼接不需要特判 | `[a, b)` 与 `[b, c)` 接起来就是 `[a, c)` |
| `last` 总能取到 | 每个容器都有 `end()`，而它只需表示「末尾之后」，不必真的指向元素 |

`end()` 不是「最后一个元素」，它是**一个可以到达、但不能解引用的位置**。
对 `vector` 它通常就是缓冲区里最后一个元素之后那个地址；
对 `list` 它是哨兵节点。解引用它是未定义行为。

## 2.4 空区间与边界情况

`实测数据`
`Text`

```text
  empty.begin() == empty.end() ? 是
  对空区间调用 std::sort 是安全的（区间为空，什么都不做）
```

**空区间是合法区间**，所有标准算法都必须接受它。
这条性质在写通用代码时很实用：不必为「集合为空」单独写一个分支，
循环自然一次都不执行。

# 第 3 节 四个移动位置的函数

## 3.1 四个函数

| 函数 | 做什么 | 会不会改原迭代器 |
|---|---|---|
| `std::advance(it, n)` | 把 `it` 本身往前移 `n` 步 | **会**（按引用传） |
| `std::next(it, n = 1)` | 返回移动后的副本 | 不会 |
| `std::prev(it, n = 1)` | 返回往回移 `n` 步的副本 | 不会 |
| `std::distance(first, last)` | 返回两个位置之间的距离 | 不会 |

`next` 是 `advance` 的「不动原迭代器」版本，日常写代码几乎只用 `next` 与 `prev`；
`advance` 出现在需要原地移动的循环里。

## 3.2 复杂度由类别决定

`文档`

> "Since only random access iterators provide `+` and `-` operators, the library provides two
> function templates `advance` and `distance`. These function templates use `+` and `-` for
> random access iterators (and are, therefore, constant time for them); for input, forward
> and bidirectional iterators they use `++` to provide linear time implementations."
> "Effects: If `InputIterator` meets the requirements of random access iterator, returns
> `(last - first)`; otherwise, returns the number of increments needed to get from `first`
> to `last`."
>
> —— N4659 §27.4.3/1、§27.4.3/4（p.981）

| 类别 | `advance` / `next` / `prev` | `distance` |
|---|---|---|
| 随机访问 | `O(1)`，一次加法 | `O(1)`，一次减法 |
| 双向 | `O(n)`，一步一步跳 | `O(n)`，一步一步数 |
| 前向 | `O(n)` | `O(n)` |
| 输入 | `O(n)` | `O(n)` |

**同一个函数落在两类迭代器上，代价从常数变成线性**，这一点在第 3.3 小节有实测。

## 3.3 代价实测与一个陷阱

`实测数据`

| 100 万元素，走 999999 步 | 耗时 |
|---|---|
| `list`，10 次 | 45.279 ms（每次 4.528 ms） |
| `vector`，100000 次 | 低于时钟分辨率（每次 0.000000 ms） |

（程序与完整输出见《09-高阶数据结构/A-02-链式存储：list 与 forward_list.md》第 5 节。）

链表上走一百万步要 4.528 ms，连续存储上走一百万步低于时钟分辨率。
**同一个 `std::advance`、同一个目标位置**，一个是一次加法，一个是近百万次内存跳转。

`实测数据`
`Text`

```text
100 万元素
  vector：1000 次 std::distance(begin,end)         0.000 ms
  list  ：100 次  std::distance(begin,end)         0.000 ms
```

**这一组数字是陷阱**：链表上「从头数到尾」一百次本该是几百毫秒量级，
却测到 0.000 ms。原因不是 `std::distance` 在 `list` 上变快了——
`distance` 对双向迭代器就是一步一步数——**而是优化器把整段计算移出了计时区间**：
容器在循环中没变，这次遍历是个不变量，循环里每一轮算出的都是同一个常数。

`实测数据`

| 单独编成最小程序、改用 `-O0` 编译 | 耗时 |
|---|---|
| 单次 `std::distance(list)`（走一百万个节点） | 10.265 ms |
| 循环里 100 次 `std::distance(list)` | 529.406 ms |
| 循环里 1000 次 `std::distance(vector)` | 0.002 ms |

**上面这组数是把那段代码单独编成一份最小程序、改用 `-O0` 编译（关掉优化）得到的**：
连一次调用都藏不住——一百万个节点走一遍就是十毫秒上下，一百次就是半秒，
它本来就是 `O(n)`；`-O2` 下连单次调用都测到 0.000 ms，移走的正是整段计算。
完整的分析与三个纪律见《09-高阶数据结构/A-00-导读：数据结构是问题的形状.md》第 3.3 小节。

> [!IMPORTANT]
> **`O(n)` 与 `O(1)` 的差别只有在「真的执行了」的时候才存在。**
> 写性能代码时，优化器可以把整段计算换掉；测到的数字先要问一句
> 「这段代码真的跑了吗」。用 `volatile` 接收结果、让规模由运行期决定、
> 或者把目标位置做成运行期取值，都是让代码「必须跑」的办法。

# 第 4 节 失效：一张总表与三种查法

## 4.1 失效规则总表

| 容器 | 读取、遍历 | 插入 | 删除 | 扩容／再哈希 |
|---|---|---|---|---|
| `vector` | 不失效 | 扩容则**全部**失效；不扩容则插入点**及之后**失效 | 删除点**及之后**失效 | 全部失效 |
| `deque` | 不失效 | 两端插入只失效迭代器；中间插入全部失效 | 两端删除只失效被删的；中间删除全部失效 | —— |
| `list` / `forward_list` | 不失效 | **全都不失效** | 只有被删的那个失效 | —— |
| `map` / `set` | 不失效 | **全都不失效** | 只有被删的那个失效 | —— |
| `unordered_*` | 不失效 | 不触发再哈希则不失效 | 只有被删的那个失效 | **迭代器全部失效，指针与引用仍有效** |
| 数组 / `std::array` | 不失效 | 不能插入 | 不能删除 | —— |

三条贯穿全表的规律：

- **节点式容器（`list`、`map`、`unordered_*`）插入不动别人**，
  因为它们不搬元素，只改指针；
- **连续存储（`vector`、`deque`）只要发生重新分配，就是一大片一起失效**；
- **哈希表把「迭代器」与「指针」分开对待**：再哈希改的是桶的归属，
  元素本身没搬家，因此指针与引用仍然有效，只有迭代器作废。

下面这份程序用**地址**把前两条规律测出来：地址没变，指向它的迭代器就还有效。

`C++`

```cpp
/* iterator_stability.cpp
 * 编译：g++ -std=c++17 -O2 iterator_stability.cpp -o iterator_stability
 * 插入元素之后，原来那个元素的地址变没变。
 * 地址变了，指向它的迭代器/指针/引用就全失效了。 */
#include <cstdio>
#include <list>
#include <map>
#include <unordered_map>
#include <utility>
#include <vector>

template <class C, class V>
static void probe(const char* name, C& c, const V& extra) {
    auto it = c.begin();
    const void* before = static_cast<const void*>(&*it);
    c.insert(it, extra);                 // 在头部插一个
    auto it2 = c.begin();
    ++it2;                               // 指向插入前那个首元素
    const void* after = static_cast<const void*>(&*it2);
    std::printf("  %-20s 插入前 %p  插入后 %p  %s\n", name, before, after,
                before == after ? "地址不变" : "地址已变");
}

int main() {
    std::printf("== 在头部插入一个元素，看原来首元素的地址 ==\n");
    {
        std::vector<int> v{1, 2, 3, 4, 5};
        v.reserve(64);                   // 先留够容量，让这次插入不触发扩容
        probe("vector(预留了容量)", v, 0);
    }
    {
        std::vector<int> v{1, 2, 3, 4, 5};   // 容量刚好等于 5
        probe("vector(容量刚好满)", v, 0);
    }
    {
        std::list<int> l{1, 2, 3, 4, 5};
        probe("list", l, 0);
    }
    {
        std::map<int, int> m{{1, 1}, {2, 2}, {3, 3}};
        probe("map", m, std::pair<const int, int>{0, 0});
    }
    {
        std::unordered_map<int, int> m{{1, 1}, {2, 2}, {3, 3}};
        probe("unordered_map", m, std::pair<const int, int>{0, 0});
    }

    std::printf("\n== vector 扩容：整块缓冲区换地方 ==\n");
    std::vector<int> v;
    v.reserve(3);                    // 容量刚好等于 3，下一次 push_back 一定扩容
    for (int i = 0; i < 3; ++i) v.push_back(i);
    std::printf("  size=3 capacity=%zu 缓冲区首地址 %p\n", v.capacity(),
                static_cast<const void*>(v.data()));
    v.push_back(3);
    std::printf("  再 push 一个：capacity=%zu 缓冲区首地址 %p\n", v.capacity(),
                static_cast<const void*>(v.data()));
    std::printf("  旧地址上的元素已被搬走并销毁，指向那里的迭代器全部失效\n");
    return 0;
}
```

`实测数据`
`Text`

```text

  vector(预留了容量) 插入前 000002735a512660  插入后 000002735a512664  地址已变
  vector(容量刚好满) 插入前 000002735a512640  插入后 000002735a512664  地址已变
  list                 插入前 000002735a512650  插入后 000002735a512650  地址不变
  map                  插入前 000002735a512660  插入后 000002735a512660  地址不变
```

**`vector` 的两行都是「地址已变」**：即使预留了容量、没有重新分配，
在头部插入也会把后面的元素整体后移一格，那个元素的地址因此变了
（标准对这种情形的说法是「插入点之前的迭代器仍然有效」）。

上面输出的最后一段演示的是**另一种失效**：容量用满以后 `push_back` 触发重新分配——
`capacity` 从 3 变成 6，缓冲区首地址跟着换了一个地方，
旧地址上的元素已经被搬走，指向那里的迭代器与指针全部失效。

## 4.2 三种查法

失效之后继续使用是未定义行为，普通构建下可能什么都不报。
三种查法各自能抓到一部分：

| 查法 | 怎么开 | 能抓到什么 | 代价 |
|---|---|---|---|
| 普通构建 | `g++ -O2` | 什么都不查 | 无 |
| 调试模式 | `g++ -D_GLIBCXX_DEBUG` | libstdc++ 容器的**迭代器越界、失效、区间颠倒** | 运行慢几倍，且与其他库混用会出问题 |
| Sanitizer | `g++ -fsanitize=address,undefined` | **访问已释放内存**、越界、未定义行为 | 慢两三倍，内存占用高 |

不加任何开关时，两份程序都会「正常」跑完——这正是失效最麻烦的地方。

`实测数据`

| 程序（都用普通命令编译运行） | 打印出的值 |
|---|---|
| `debug_iter.cpp` | 再读同一个迭代器：690235008 |
| `asan_iter.cpp` | 通过旧指针读：2081583264 |

**两处读出来的都是垃圾值**：那块内存已经被释放，内容可能被后来的分配覆盖。
程序没有崩溃、没有警告、退出码是 0。**未定义行为最常见的表现不是崩溃，而是这样一份看起来正常的输出。**
（上面两个数字每次运行都可能不同，它们只是「读到了别的数据」的证据。）

# 第 5 节 适配器：改变迭代器的行为

适配器是**包在别的迭代器外面的迭代器**：它自己不指向数据，
把 `*`、`++` 这些操作翻译成另一种动作。
标准库给了四类（插入、流、移动、反向），下面这份程序把四类各演示一次。

`C++`

```cpp
/* iterator_adapters.cpp
 * 编译：g++ -std=c++17 -O2 iterator_adapters.cpp -o iterator_adapters
 * 迭代器适配器：插入迭代器、流迭代器、移动迭代器、反向迭代器 */
#include <algorithm>
#include <cstdio>
#include <iterator>
#include <list>
#include <sstream>
#include <string>
#include <vector>

int main() {
    // 一、插入迭代器：把「赋值」变成「插入」
    std::printf("== 插入迭代器 ==\n");
    std::vector<int> v;
    auto bi = std::back_inserter(v);
    *bi = 1;
    ++bi;
    *bi = 2;
    ++bi;
    *bi = 3;                       // 每一次赋值都对应一次 push_back
    std::printf("  往 back_inserter 赋值三次之后，v 有 %zu 个元素\n", v.size());

    std::list<int> l;
    auto fi = std::front_inserter(l);
    *fi = 1;
    ++fi;
    *fi = 2;
    ++fi;
    *fi = 3;                       // 每一次赋值都对应一次 push_front
    std::printf("  往 front_inserter 赋值 1、2、3 之后，l 的内容：");
    for (int x : l) std::printf(" %d", x);
    std::printf("（顺序反了，因为它每次都插在头部）\n");

    const std::vector<int> src{7, 8, 9};
    std::copy(src.begin(), src.end(), std::back_inserter(v));
    std::printf("  用 copy 追加三个元素后，v 的内容：");
    for (int x : v) std::printf(" %d", x);
    std::printf("\n");

    // 二、流迭代器：把输入输出流当成区间
    std::printf("\n== 流迭代器 ==\n");
    std::istringstream in("10 20 30 40");
    std::istream_iterator<int> it(in);
    const std::istream_iterator<int> last;          // 默认构造的就是「流末尾」
    int sum = 0;
    for (; it != last; ++it) sum += *it;
    std::printf("  从字符串流里读四个整数，求和 = %d\n", sum);

    std::ostringstream out;
    std::ostream_iterator<int> oi(out, ",");
    for (int x : src) *oi++ = x;                    // 每次赋值往流里写一个值加一个分隔符
    std::printf("  写进另一个字符串流的结果 = %s\n", out.str().c_str());
    std::printf("  流迭代器很少直接用，常见的是配 copy：\n");
    std::ostringstream out2;
    std::copy(src.begin(), src.end(), std::ostream_iterator<int>(out2, " "));
    std::printf("    copy 到输出流迭代器 = %s\n", out2.str().c_str());

    // 三、移动迭代器：把元素搬过去而不是复制
    std::printf("\n== 移动迭代器 ==\n");
    std::vector<std::string> a{"alpha", "beta", "gamma"};
    std::vector<std::string> b(std::make_move_iterator(a.begin()),
                               std::make_move_iterator(a.end()));
    std::printf("  移动之后 b 有 %zu 个，第一个是 %s\n", b.size(), b[0].c_str());
    std::printf("  源里的字符串被搬空：a[0].size() = %zu，a[1].size() = %zu\n",
                a[0].size(), a[1].size());
    std::printf("  （搬走之后源对象处于有效但未指定的状态，本机实现留空串）\n");

    // 四、反向迭代器：直接当区间用
    std::printf("\n== 反向迭代器 ==\n");
    std::vector<int> w{1, 2, 3, 4, 5};
    std::sort(w.rbegin(), w.rend());                // 用反向区间排序 = 从大到小
    std::printf("  sort(w.rbegin(), w.rend()) 之后：");
    for (int x : w) std::printf(" %d", x);
    std::printf("\n");
    std::printf("  find(w.rbegin(), w.rend(), 3) 找到的位置，转成正向是第 %td 个\n",
                std::distance(w.begin(), std::find(w.rbegin(), w.rend(), 3).base()) - 1);
    return 0;
}
```

## 5.1 插入迭代器

`back_insert_iterator` 把「赋值」变成「`push_back`」，
`front_insert_iterator` 变成「`push_front`」，`insert_iterator` 变成「`insert`」。
它们的作用是**让「往容器里加元素」这件事看起来像「往一个位置上写」**，
于是 `std::copy` 这类算法可以直接用来追加数据。

**输出里 `front_inserter` 那一段的顺序是反的**：赋值顺序是 1、2、3，
插进链表之后读出来是 `3 2 1`——它每次插在头部。
这也是「适配器改的是动作，不是数据」的直接体现。

## 5.2 反向迭代器与 `base()` 的错位

`rbegin()` 指向最后一个元素，而 `rbegin().base()` 等于 `end()`——
两者错开一个位置。这条规则是反向迭代器最容易记错的地方。

`C++`

```cpp
/* reverse_iterator.cpp    编译：g++ -std=c++17 -O2 reverse_iterator.cpp -o reverse_iterator
 * reverse_iterator 的 base() 与它指向的位置差一位；以及删掉最后一个元素的写法 */
#include <cstdio>
#include <iterator>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3, 4, 5};

    std::printf("== 正序与逆序 ==\n  正序：");
    for (int x : v) std::printf("%d ", x);
    std::printf("\n  逆序：");
    for (auto it = v.rbegin(); it != v.rend(); ++it) std::printf("%d ", *it);
    std::printf("\n");

    std::printf("\n== rbegin() 与 base() 的错位 ==\n");
    auto rit = v.rbegin();
    std::printf("  *rbegin()                          = %d\n", *rit);
    std::printf("  rbegin().base() 就是 end()         = %s\n",
                rit.base() == v.end() ? "是" : "否");
    std::printf("  distance(begin, rbegin().base())   = %td（= size，不是最后一个下标）\n",
                std::distance(v.begin(), rit.base()));
    std::printf("  distance(begin, rbegin()) 不可用：反向迭代器不能与正向迭代器相减\n");
    std::printf("  要取回它指的元素，用 *(rbegin().base() - 1) 或直接 *rbegin()\n");

    std::printf("\n== 正向迭代器转反向迭代器 ==\n");
    auto it = v.begin() + 3;                    // 指向 4
    auto back = std::make_reverse_iterator(it);
    std::printf("  正向 it 指向 %d，make_reverse_iterator(it) 指向 %d（它前面那个）\n",
                *it, *back);
    std::printf("  要让它仍指向 4，要写 make_reverse_iterator(it + 1)，得到 %d\n",
                *std::make_reverse_iterator(it + 1));

    std::printf("\n== 删除最后一个元素 ==\n");
    std::vector<int> w{1, 2, 3, 4, 5};
    w.erase(std::prev(w.end()));                // 不能写 erase(w.rbegin())：类型不匹配
    std::printf("  erase(prev(end())) 之后：");
    for (int x : w) std::printf("%d ", x);
    std::printf("\n");
    return 0;
}
```

`Text`

```text

  正序：1 2 3 4 5
  逆序：5 4 3 2 1

== rbegin() 与 base() 的错位 ==
  *rbegin()                          = 5
  rbegin().base() 就是 end()         = 是
  distance(begin, rbegin().base())   = 5（= size，不是最后一个下标）
  distance(begin, rbegin()) 不可用：反向迭代器不能与正向迭代器相减
  要取回它指的元素，用 *(rbegin().base() - 1) 或直接 *rbegin()

  正向 it 指向 4，make_reverse_iterator(it) 指向 3（它前面那个）
```

**反向迭代器的 `base()` 指向它右边那一格。**
用 `base()` 换算位置时要减一；
反过来把正向迭代器转成反向迭代器，要加一。

## 5.3 移动迭代器

`std::make_move_iterator` 把 `*it` 从「返回引用」变成「返回右值引用」，
于是算法搬元素时走的是移动构造而不是拷贝构造。
上面输出里「移动迭代器」那一段就是它的效果：搬完之后源里的字符串长度变成 0。

**搬走之后源对象「有效但内容未指定」**：
本机实现留空串，别的实现可能留别的。**不要读它**，
只能给它赋新值或者销毁它。

## 5.4 流迭代器

`istream_iterator` 把输入流变成一个区间，`ostream_iterator` 把输出流变成一个位置。
它们让「读一列数字」「写一列数字」也能用标准算法。
上面输出里「流迭代器」那一段同时给出了两种用法：
直接循环读、以及用 `copy` 写。

**输出流迭代器构造时给的分隔符会跟在每个值后面**：`ostream_iterator<int>(out, ",")`
每写一个值就补一个 `,`，因此最后一个值后面也留了一个分隔符。

> [!WARNING]
> **流迭代器没有「回头」的能力**（它是输入／输出迭代器），
> 因此不能用于需要多趟遍历或多重扫描的算法。
> 另外 `istream_iterator` 在构造时就会读第一个值，用完整个区间后流处于失败状态，
> 想复用同一个流要先 `clear()`。

# 第 6 节 写一个能进算法的迭代器

## 6.1 五个类型别名

自定义迭代器要进标准算法，最少要做两件事：**写五个类型别名**、**重载必要运算符**。
别名决定算法能用哪些写法，运算符决定这些写法真的能编译过。

| 别名 | 作用 |
|---|---|
| `iterator_category` | 告诉算法「我是哪一类」，从而选择写法 |
| `value_type` | 元素类型 |
| `difference_type` | 距离类型，通常是 `std::ptrdiff_t` |
| `pointer` | `operator->` 的返回类型 |
| `reference` | `*it` 的返回类型 |

## 6.2 一个完整的例子

下面这个容器只有一个定长数组，但它的迭代器把自己声明成随机访问迭代器，
并且把该类要求的运算符全部补齐，于是标准算法可以直接用。

`C++`

```cpp
/* custom_iterator.cpp
 * 编译：g++ -std=c++17 -O2 custom_iterator.cpp -o custom_iterator
 * 写一个能直接进标准算法的迭代器：五个类型别名加必要的运算符 */
#include <algorithm>
#include <cstddef>
#include <cstdio>
#include <iterator>
#include <numeric>

class IntBuffer {
public:
    static constexpr std::size_t kCap = 8;

    class iterator {
    public:
        // 算法要从这五个别名里取它需要的信息
        using iterator_category = std::random_access_iterator_tag;
        using value_type = int;
        using difference_type = std::ptrdiff_t;
        using pointer = int*;
        using reference = int&;

        explicit iterator(int* p = nullptr) : p_(p) {}

        reference operator*() const { return *p_; }
        pointer operator->() const { return p_; }
        reference operator[](difference_type n) const { return p_[n]; }

        iterator& operator++() { ++p_; return *this; }
        iterator operator++(int) { iterator t(*this); ++p_; return t; }
        iterator& operator--() { --p_; return *this; }
        iterator operator--(int) { iterator t(*this); --p_; return t; }
        iterator& operator+=(difference_type n) { p_ += n; return *this; }
        iterator& operator-=(difference_type n) { p_ -= n; return *this; }

        friend iterator operator+(iterator it, difference_type n) { return iterator(it.p_ + n); }
        friend iterator operator+(difference_type n, iterator it) { return iterator(it.p_ + n); }
        friend iterator operator-(iterator it, difference_type n) { return iterator(it.p_ - n); }
        friend difference_type operator-(const iterator& a, const iterator& b) { return a.p_ - b.p_; }
        friend bool operator==(const iterator& a, const iterator& b) { return a.p_ == b.p_; }
        friend bool operator!=(const iterator& a, const iterator& b) { return a.p_ != b.p_; }
        friend bool operator<(const iterator& a, const iterator& b) { return a.p_ < b.p_; }
        friend bool operator>(const iterator& a, const iterator& b) { return a.p_ > b.p_; }
        friend bool operator<=(const iterator& a, const iterator& b) { return a.p_ <= b.p_; }
        friend bool operator>=(const iterator& a, const iterator& b) { return a.p_ >= b.p_; }

    private:
        int* p_;
    };

    iterator begin() { return iterator(buf_); }
    iterator end() { return iterator(buf_ + n_); }
    void push_back(int x) { buf_[n_++] = x; }
    std::size_t size() const { return n_; }

private:
    int buf_[kCap]{};
    std::size_t n_ = 0;
};

int main() {
    IntBuffer b;
    for (int x : {5, 3, 1, 4, 2}) b.push_back(x);

    std::printf("范围 for 能直接用（它只用 !=、* 与 ++）：");
    for (int x : b) std::printf(" %d", x);
    std::printf("\n");

    std::sort(b.begin(), b.end());                  // 需要随机访问迭代器
    std::printf("std::sort 之后：");
    for (int x : b) std::printf(" %d", x);
    std::printf("\n");

    std::printf("std::find(4) 命中=%d\n", std::find(b.begin(), b.end(), 4) != b.end());
    std::printf("std::distance = %td\n", std::distance(b.begin(), b.end()));
    std::printf("std::accumulate = %d\n", std::accumulate(b.begin(), b.end(), 0));
    std::printf("std::lower_bound(3) 指向 %d\n", *std::lower_bound(b.begin(), b.end(), 3));
    std::printf("std::reverse 之后：");
    std::reverse(b.begin(), b.end());
    for (int x : b) std::printf(" %d", x);
    std::printf("\n");
    std::printf("迭代器相减 end() - begin() = %td\n", b.end() - b.begin());
    return 0;
}
```

`实测数据`
`Text`

```text

std::sort 之后： 1 2 3 4 5
std::find(4) 命中=1
std::distance = 5
std::accumulate = 15
std::lower_bound(3) 指向 3
std::reverse 之后： 5 4 3 2 1
```

**八行输出、六个标准算法，全部直接可用**，代价是六十行的迭代器类。
这就是「接口」这个词的实际含义：**容器付出实现成本，换取算法的全部能力。**

## 6.3 类别是承诺，不是标签

把上面那个 `iterator_category` 改成 `std::forward_iterator_tag`（其余不动），
`std::sort` 立刻编不过——因为 `sort` 要用 `last - first` 算中点，
而前向迭代器没有减法。

| 你声明的类别 | 算法会用它做什么 | 你必须提供 |
|---|---|---|
| 输入 | 只往前走一遍 | `*`、`++`、`==`、`!=` |
| 前向 | 允许走多遍 | 上一行加默认构造 |
| 双向 | 允许往回走 | 上一行加 `--` |
| 随机访问 | 允许算距离、跳步、比较大小 | 上一行加 `+`、`-`、`[]`、`<` |

> [!CAUTION]
> **声明了随机访问却把 `operator+` 写成线性遍历，是比不做更糟的错。**
> 算法会根据类别选写法：它以为 `it + n` 是常数时间，就可能在一个循环里反复调用它，
> 于是复杂度从 `O(n)` 变成 `O(n²)`，而且**编译器不会报错，运行时也没有任何提示**。
> **类别是一个约定：声明了就要兑现。**

# 第 7 节 判据

| 你的情况 | 做法 |
|---|---|
| 只需要遍历一个已有容器 | 用容器自己的迭代器或范围 `for` |
| 要让算法支持 C 数组与容器两种实参 | 模板里写 `std::begin` / `std::end` |
| 想往容器里追加数据 | `back_inserter` / `front_inserter` / `inserter` |
| 想逆序遍历或反向排序 | `rbegin` / `rend`；要换算位置时记住 `base()` 减一 |
| 想把元素搬走而不是复制 | `make_move_iterator` |
| 想从流里读一列值 | `istream_iterator`（只能遍历一次） |
| 自己写的类型想进算法 | 补齐五个别名与必要运算符，类别按真实能力声明 |
| 需要用旧迭代器排查 bug | 加 `-D_GLIBCXX_DEBUG` 重编一遍；内存问题用 ASan |

> [!NOTE]
> 迭代器这一章的结论归纳成三句话：
> **它是容器与算法之间的契约——类别说明「能做什么」，失效规则说明「什么时候不能再用」；
> 算法只依赖这两件事，因此换容器不必换算法，换算法也不必换容器；
> 契约里的每一句都要兑现，声明了随机访问就要真的常数时间，声明了有效期就要真的管用。**

# 术语表

| 术语 | 含义 |
|---|---|
| **迭代器** | 指向容器中某个位置的通用接口，算法通过它访问数据 |
| **类别** | 迭代器能力的分层：输入、输出、前向、双向、随机访问 |
| **`iterator_traits`** | 从迭代器类型里取出五样信息的统一入口 |
| **范围** | 一对「开始位置、结束位置」，约定为左闭右开 |
| **半开区间** | `[first, last)`，`last` 指向最后一个元素的下一个位置 |
| **`past-the-end`** | `end()` 那个位置：可以到达、可以比较，但不能解引用 |
| **失效** | 容器结构变化后，原先的迭代器不再可用 |
| **适配器** | 包在别的迭代器外面、改变其行为的迭代器 |
| **`base()`** | 反向迭代器转回正向迭代器的入口，与它本身错开一个位置 |
| **单数迭代器** | 不与任何容器关联的迭代器（默认构造或被失效之后），不能解引用 |
