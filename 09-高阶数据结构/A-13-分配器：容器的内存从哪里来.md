**前面各章讲的都是容器怎么摆数据，它们站在同一个假设上：内存总有人给。**
`vector` 扩容时要换一块更大的缓冲区，`list` 每插一个元素要多一个节点，
`map` 每插一个键值对要多一个树节点——这些内存从哪来、谁在管、什么时候还，
前面各章都用「向系统要一块内存」一句话带过。

**这一章把这句话拆开。** 容器并不直接向系统要内存，它向一个叫分配器的东西要，
而且只要两样东西：一块能放下若干个元素的原始内存，以及把这块内存还回去的办法。
对象什么时候造、什么时候拆，容器自己管。两件事分开之后，内存的来源就能换——
换成池子、换成共享内存、换成一块静态数组，容器一行都不用改。
前面各章凡是提到「分配次数」的地方，测的都是这一层的行为。

容器带一个分配器模板参数，是为了把「要内存」这一步交给调用方决定：
默认分配器走 `operator new`，换成自己的就能接内存池、共享内存或统计器。
本章把这一层拆开看，给出默认分配器与 `malloc`／`free` 的对照、
一个记录型分配器套进三种容器之后的分配曲线、一个固定大小内存池，
以及忽略 `deallocate` 的大小参数会出什么事。

# 第 1 节 需求：内存与对象是两件事

## 1.1 容器只要两样东西

**需求写清楚是这样**：放下一批同类型的元素，个数在运行期才知道；
放下之后还要反复调整这块内存的大小（追加、预留、析构）。
这份需求对内存提出的要求只有两条：

| 要什么 | 什么时候要 |
|---|---|
| 一块能放下 `n` 个元素的原始内存 | 第一次插入、扩容、`reserve` |
| 把这块内存还回去 | 扩容后旧缓冲区不用了、容器析构、`shrink_to_fit` |

**两条里都没有「对象」两个字。** `reserve(1000)` 之后 `size()` 还是 0，
缓冲区里一个对象也没有；反过来，`pop_back()` 与 `clear()` 拆掉的是对象，
缓冲区一个字节都没还。**内存的账与对象的账是两本账，各有各的时点。**

**为什么不能直接用 `new T[n]`。** `new T[n]` 一次做三件事：
算大小、要内存、把 `n` 个对象全构造出来——构造只能是默认构造，没有传参数的余地。
容器要的恰恰是「先有内存、对象以后再逐个造」；而且 `new[]` 要配 `delete[]`，
扩容时想换一块更大的内存就得先把元素搬过去再释放，
做不到「先备好新内存、再决定搬哪些」。C++ 的做法是把 `new` 的两件事拆成两组操作：

| 操作 | 管什么 | 谁做 |
|---|---|---|
| `allocate(n)` / `deallocate(p, n)` | 内存 | 分配器 |
| `construct(p, args...)` / `destroy(p)` | 对象 | 容器发起，转给分配器或由 `allocator_traits` 代劳 |

> [!IMPORTANT]
> **分配器不是「内存的提供者」，而是「内存来源的接口」。**
> 它回答两个问题：从哪拿、怎么还。对象怎么造、什么时候拆，仍由容器决定。

## 1.2 拆开之后的自由

**拆开之后，容器与内存之间多出了四种自由。**

| 拆开带来的自由 | 具体表现 |
|---|---|
| 内存来源可换 | 系统堆、固定大小的池、共享内存、一块静态数组、调试期加了护栏的块——容器一行不用改 |
| 容器不必知道元素怎么构造 | `emplace_back(args...)` 把参数原样转给 `construct`，容器不必为每种元素写一份插入代码 |
| 「只分配、不构造」成为可能 | `reserve` 与 `capacity > size` 的整个机制都建立在这一条上 |
| 分配与构造可以分别计量 | 本章的实测都靠这一条：内存那一侧可以计数、可以替换，元素那一侧不用动 |

## 1.3 容器侧的两本账

下面这份程序用计数型元素把两条账分开：`reserve` 只要内存，
`emplace_back` 才造对象，`pop_back` 与 `clear` 只析构对象。

`C++`

```cpp
/* split_in_container.cpp    编译：g++ -std=c++17 -O2 split_in_container.cpp -o split_in_container
 * 从容器这一侧看「要内存」与「造对象」是两件事：
 * reserve 只要内存，emplace_back 才造对象，pop_back 与 clear 只析构对象、不还内存。 */
#include <cstdio>
#include <string>
#include <vector>

struct Counted {
    static int built;
    static int destroyed;
    std::string payload;
    explicit Counted(const char* s) : payload(s) { ++built; }
    Counted(const Counted& o) : payload(o.payload) { ++built; }   // 搬迁也算构造
    ~Counted() { ++destroyed; }
};
int Counted::built = 0;
int Counted::destroyed = 0;

int main() {
    std::vector<Counted> v;
    v.reserve(4);
    std::printf("reserve(4) 之后：已构造 %d 个，capacity = %zu（内存有了，对象还没有）\n",
                Counted::built, v.capacity());

    v.emplace_back("甲");
    v.emplace_back("乙");
    std::printf("emplace_back 两次之后：已构造 %d 个，size = %zu\n",
                Counted::built, v.size());

    v.pop_back();
    std::printf("pop_back 一次之后：已析构 %d 个，capacity 仍是 %zu（还的是对象，不是内存）\n",
                Counted::destroyed, v.capacity());

    v.clear();
    std::printf("clear() 之后：已析构 %d 个，capacity 仍是 %zu\n",
                Counted::destroyed, v.capacity());
    return 0;
}
```

`实测数据`
`Text`

```text
reserve(4) 之后：已构造 0 个，capacity = 4（内存有了，对象还没有）
emplace_back 两次之后：已构造 2 个，size = 2
pop_back 一次之后：已析构 1 个，capacity 仍是 4（还的是对象，不是内存）
clear() 之后：已析构 2 个，capacity 仍是 4
```

**四行输出把两条账分得很清楚。** `reserve(4)` 要到了 4 个元素的位置，构造计数还是 0；
两次 `emplace_back` 之后才有两个对象；`pop_back` 与 `clear` 让析构计数涨到 2，
而 `capacity` 一直是 4——**对象没了，内存还在**。
容器析构时才会把这块内存还回去，第 2 节数这一步。

## 1.4 容器不直接调分配器：`allocator_traits` 这一层

**容器从不直接调用分配器的成员，而是通过 `std::allocator_traits<A>`。**
这一层是容器与分配器之间的适配器：分配器写了就用，没写就补一个默认的。
因此一个只有 `value_type`、`allocate`、`deallocate` 的分配器就能直接用，第 3 节就是这么写的。

| `allocator_traits<A>` 里的名字 | 从分配器哪里来 | 分配器没写时 |
|---|---|---|
| `allocate(a, n)` / `deallocate(a, p, n)` | `a.allocate(n)` / `a.deallocate(p, n)` | 没有默认，**必须写** |
| `construct(a, p, args...)` | `a.construct(p, args...)` | `::new (p) T(args...)` |
| `destroy(a, p)` | `a.destroy(p)` | `p->~T()` |
| `max_size(a)` | `a.max_size()` | `numeric_limits<size_type>::max() / sizeof(value_type)` |
| `select_on_container_copy_construction(a)` | 同名成员 | 返回 `a`（拷贝时沿用来源的分配器） |
| `rebind_alloc<U>` | `A::rebind<U>::other` 或 `A<U>` | 靠模板参数换类型 |
| `propagate_on_container_copy_assignment` 等三个 | 同名成员 | `false_type` |
| `is_always_equal` | 同名成员 | `is_empty<A>` |

**`rebind_alloc` 是容器真正要的那一步。** `vector<int, Alloc>` 拿到的分配器是 `Alloc<int>`，
但 `list<int, Alloc>` 要分配的不是 `int`，而是「前驱指针 + 后继指针 + 数据」的节点；
`map` 要分配的是树节点。容器于是向 traits 要一个「把元素类型换成节点类型」的分配器。
**这也是分配器必须有一个模板转换构造函数的原因**：要从 `Alloc<int>` 造出 `Alloc<节点>`。

**C++17 把 `std::allocator<T>` 的 `construct`／`destroy` 移进了弃用附录。**
附录 D 是兼容性附录，里面的内容都属于弃用项：

`文档`

> "This Clause describes features of the C++ Standard that are specified for compatibility with
> existing implementations."
>
> "The following members and explicit class template specialization are defined in addition to those
> specified in 23.10.9:"
>
> —— N4659 §D/1、§D.9/1

**§D.9 后面列出的成员里有 `construct` 与 `destroy`**，还有 `address` 与带 `hint` 的 `allocate`。
它们仍然有效，但已经被列为将来可能移除的候选，新的代码不该再调它们。接手的是 `allocator_traits`：

`文档`

> "Effects: Calls a.construct(p, std::forward<Args>(args)...) if that call is well-formed; otherwise,
> invokes ::new (static_cast<void*>(p)) T(std::forward<Args>(args)...)."
>
> —— N4659 §23.10.8.2/5

**这一句就是「有就用、没有就补」的原文**：分配器自带 `construct` 时交给它，
可以在构造前后加日志、加护栏；没写时 traits 用 placement new 顶上。
第 3 节的记录型分配器没有写 `construct`，照样能用在三个容器上。

## 1.5 最小分配器要写什么

**能直接用在标准容器上的最小分配器，要写的成员只有五样。**

| 成员 | 必须吗 | 作用 |
|---|---|---|
| `value_type` | 必须 | traits 靠它推 `size_type`、`pointer` 等一串类型 |
| `allocate(n)` | 必须 | 拿 `n * sizeof(T)` 字节原始内存 |
| `deallocate(p, n)` | 必须 | 还内存；`n` 要与 `allocate` 一致（第 5.1 小节） |
| `template <class U> A(const A<U>&)` | 必须 | `rebind` 时要从别的特化造出来 |
| `operator==` / `operator!=` | 必须 | 回答「一个分配器释放的内存另一个能不能释放」（第 5.2 小节） |
| `propagate_on_container_*`、`is_always_equal` | 可选 | 不写取默认值 |
| `construct`、`destroy`、`max_size`、`select_on_container_copy_construction` | 可选 | 不写由 traits 补 |

> [!NOTE]
> **容器与内存之间隔着一层接口，而不是一层实现。**
> 接口只有四个动作：要内存、还内存、造对象、拆对象。
> 前两个由分配器实现，后两个由容器发起，可以转给分配器，也可以由 `allocator_traits` 顶替。

# 第 2 节 默认分配器：`std::allocator<T>` 与 `operator new`

## 2.1 默认参数就是它

**`std::vector<int>` 是 `std::vector<int, std::allocator<int>>` 的简写**——
每个容器模板的最后一个参数都有默认值，那个默认值就是 `std::allocator<T>`。

**它是一个空类型**：`sizeof(std::allocator<int>)` 是 1，`is_empty` 是 1，
第 1 节的程序最后一行打的就是这两个数。空类型意味着容器不必为它留空间：
`sizeof(std::vector<int>)` 是 24，与「容器里只有三个指针」完全一致，第 7.1 小节给出对照表。

`std::allocator<T>` 把内存的获取交给全局的 `operator new`：

`文档`

> "Remarks: the storage is obtained by calling ::operator new (21.6.2), but it is unspecified when or
> how often this function is called."
>
> "Remarks: Uses ::operator delete (21.6.2), but it is unspecified when this function is called."
>
> —— N4659 §23.10.9.1/3、§23.10.9.1/7

**「unspecified when or how often」有两层意思。** 第一层：标准不规定扩容几次、
每次要多少字节，那是实现的自由，《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 3.3 小节
比较过两套标准库的增长倍数。第二层：**次数只能测，不能推**。
同一份代码换一套标准库，数字就变。

**`operator new` 与 `malloc` 是什么关系**：标准把这件事留给实现——

`文档`

> "Replaceable: A C++ program may define functions with either of these function signatures, and
> thereby displace the default versions defined by the C++ standard library."
>
> "Required behavior: Return a non-null pointer to suitably aligned storage (6.7.4), or else throw a
> bad_alloc exception. This requirement is binding on any replacement versions of these functions."
>
> "Whether the attempt involves a call to the C standard library functions malloc or aligned_alloc is
> unspecified."
>
> —— N4659 §21.6.2.1/2、/3、/4.1

**三段话合起来给出本章全部实测的入口**：全局 `operator new`／`operator delete` 可以被替换，
替换版本必须返回对齐的存储或者抛 `bad_alloc`，而它内部是不是调 `malloc` 由实现决定。
本节与后面各节的程序都自己调 `malloc`，因此行为可控；替换之后，
**所有走默认分配器的容器都会经过这一层**。

## 2.2 一次扩容的真实账

下面这份程序把全局 `operator new` 与 `operator delete` 换掉，
在里面对次数与字节计数，容器的用法一个字都不改。

`C++`

```cpp
/* new_counter.cpp    编译：g++ -std=c++17 -O2 new_counter.cpp -o new_counter
 * 把全局 operator new / delete 换掉，数一数 vector 扩容到底调用了几次、
 * 每次要多少字节、什么时候还回去。 */
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <new>
#include <vector>

static long long g_new_calls = 0;      // operator new 调用次数
static long long g_new_bytes = 0;      // 累计要到的字节
static long long g_delete_calls = 0;   // operator delete 调用次数
static long long g_sizes[64];          // 每次要的字节，按顺序记下来
static int g_size_n = 0;

void* operator new(std::size_t n) {
    ++g_new_calls;
    g_new_bytes += static_cast<long long>(n);
    if (g_size_n < 64) g_sizes[g_size_n++] = static_cast<long long>(n);
    void* p = std::malloc(n ? n : 1);
    if (!p) throw std::bad_alloc();
    return p;
}
void operator delete(void* p) noexcept { ++g_delete_calls; std::free(p); }
void operator delete(void* p, std::size_t) noexcept { ++g_delete_calls; std::free(p); }
void* operator new[](std::size_t n) { return operator new(n); }
void operator delete[](void* p) noexcept { operator delete(p); }
void operator delete[](void* p, std::size_t) noexcept { operator delete(p); }

static void reset() {
    g_new_calls = g_new_bytes = g_delete_calls = 0;
    g_size_n = 0;
}

int main() {
    std::printf("== 默认分配器：vector<int> 的扩容账 ==\n");   // 预热，printf 自己的缓冲区先要下来

    reset();
    {
        std::vector<int> v;
        for (int i = 0; i < 1000; ++i) v.push_back(i);
        asm volatile("" : : : "memory");          // 屏障：这段有真实副作用，不许被优化掉

        // 先快照，再打印——printf 自己也可能要内存，会把计数搅进来
        const long long new_calls = g_new_calls;
        const long long new_bytes = g_new_bytes;
        const long long del_calls = g_delete_calls;
        const int size_n = g_size_n;
        long long sizes[64];
        std::memcpy(sizes, g_sizes, sizeof(long long) * static_cast<std::size_t>(size_n));

        std::printf("push_back 1000 个 int：operator new 调用 %lld 次，累计 %lld 字节\n",
                    new_calls, new_bytes);
        std::printf("每次要的字节：");
        for (int i = 0; i < size_n; ++i) std::printf("%lld ", sizes[i]);
        std::printf("\n");
        std::printf("循环结束时 size = %zu，capacity = %zu\n", v.size(), v.capacity());
        std::printf("循环结束时 operator delete 调用 %lld 次（扩容时还掉旧缓冲区）\n", del_calls);
    }
    std::printf("容器析构后 operator delete 调用 %lld 次（最后一块也还了）\n", g_delete_calls);

    reset();
    {
        std::vector<int> v;
        v.reserve(1000);
        for (int i = 0; i < 1000; ++i) v.push_back(i);
        asm volatile("" : : : "memory");
        std::printf("先 reserve(1000) 再 push_back：operator new 调用 %lld 次，累计 %lld 字节\n",
                    g_new_calls, g_new_bytes);
    }

    reset();
    {
        std::vector<int> v(1000, 7);
        asm volatile("" : : : "memory");
        std::printf("直接构造 vector<int> v(1000)：operator new 调用 %lld 次，累计 %lld 字节\n",
                    g_new_calls, g_new_bytes);
    }

    reset();
    {
        std::vector<int> v;
        for (int i = 0; i < 1000; ++i) v.push_back(i);
        const long long before = g_delete_calls;
        v.clear();
        asm volatile("" : : : "memory");
        std::printf("clear() 前后：size 从 1000 变成 %zu，operator delete 多调用 %lld 次\n",
                    v.size(), g_delete_calls - before);
        std::printf("clear() 之后 capacity 仍是 %zu\n", v.capacity());
    }
    return 0;
}
```

`实测数据`
`Text`

```text
== 默认分配器：vector<int> 的扩容账 ==
push_back 1000 个 int：operator new 调用 11 次，累计 8188 字节
每次要的字节：4 8 16 32 64 128 256 512 1024 2048 4096
循环结束时 size = 1000，capacity = 1024
循环结束时 operator delete 调用 10 次（扩容时还掉旧缓冲区）
容器析构后 operator delete 调用 11 次（最后一块也还了）
先 reserve(1000) 再 push_back：operator new 调用 1 次，累计 4000 字节
直接构造 vector<int> v(1000)：operator new 调用 1 次，累计 4000 字节
clear() 前后：size 从 1000 变成 0，operator delete 多调用 0 次
clear() 之后 capacity 仍是 1024
```

## 2.3 读这本账

**11 次分配对应容量序列 1、2、4、…、1024。** 容量不够就翻倍，
第 11 次拿到 1024 个元素的位置，`push_back` 一千次正好用得上。
《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 3.2 小节讲过为什么翻倍、
第 3.4 小节算过摊还代价，这里给的是次数与字节的原始记录。

**累计 8188 字节，最终留在手里的是 4096 字节。** 多出来的那 4092 字节是增长的代价：
每扩容一次，旧缓冲区立刻还掉，循环结束时 `operator delete` 已经调用 10 次；
最后一块在容器析构时才还，那是第 11 次。

**`reserve` 把 11 次压成 1 次。** 提前说清要放多少个元素，次数与字节都降到最低；
直接构造 `vector<int> v(1000)` 也是一次分配。
《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 3.5 小节给过这条建议，这里给出它的计数证据。

**`clear()` 不还内存**：`operator delete` 调用 0 次，`capacity` 仍是 1024。
要还就得 `shrink_to_fit`（那是请求，不是保证）或者与一个空容器交换，
《09-高阶数据结构/B-01-手写：动态数组.md》第 8 节的陷阱清单里列过这一条。

> [!WARNING]
> **测这类账时最容易出错的不是程序，是优化器。**
> `-O2` 下如果容器的结果没有人读，整段 `push_back` 循环可以被删掉，
> 于是计数全是 0，看上去像「分配被优化掉了」。两个办法：把结果读出来打印
> （本节的程序打印 `size` 与 `capacity`），或者加一条 `asm volatile("" : : : "memory")` 屏障，
> 让编译器不敢跨越它重排内存操作。

**本节所有数字来自 g++ 16.2.0（MinGW-w64）**。同一台机器上换一套标准库，
增长倍数与节点布局都会变，因此这些数字要连同工具链一起引用。

# 第 3 节 一个有记录的分配器

## 3.1 为什么要自己写一个

第 2 节的办法有一个限制：**计数是全局的**。同时用三个容器，数出来的是三者之和，
分不清谁要了多少。要按容器分开数，就得让容器用「自己的」分配器——
分配器的类型是容器的模板参数，因此计数可以挂在类型上，也可以挂在实例上。

《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 4.2 小节已经用全局计数
给过一张十万元素的表，那一组数字来自 g++ 15.2.0，不与本章的数字混排。
这一节换一个办法：让分配器自己记账。这样既能按容器分开数，
还能看到**每次分配的大小**——那个数直接暴露节点的大小。

## 3.2 一个最小分配器

下面这份程序里的分配器只写了五样东西，直接套在三个容器上。

`C++`

```cpp
/* logging_alloc.cpp    编译：g++ -std=c++17 -O2 logging_alloc.cpp -o logging_alloc
 * 一个有记录的分配器：把每次分配的次数、字节、单次大小都记下来，
 * 套到 vector / list / map 上，看三者的分配账差在哪。 */
#include <cstddef>
#include <cstdio>
#include <list>
#include <map>
#include <new>
#include <vector>

struct MemLog {
    static long long calls;      // 分配次数
    static long long bytes;      // 累计字节
    static long long frees;      // 释放次数
    static long long max_one;    // 单次最大
    static long long min_one;    // 单次最小
    static void reset() { calls = bytes = frees = max_one = min_one = 0; }
};
long long MemLog::calls = 0;
long long MemLog::bytes = 0;
long long MemLog::frees = 0;
long long MemLog::max_one = 0;
long long MemLog::min_one = 0;

template <class T>
struct LoggingAlloc {
    using value_type = T;

    LoggingAlloc() noexcept = default;
    template <class U>
    LoggingAlloc(const LoggingAlloc<U>&) noexcept {}     // 无状态，换类型等于复制

    T* allocate(std::size_t n) {
        const long long got = static_cast<long long>(n * sizeof(T));
        ++MemLog::calls;
        MemLog::bytes += got;
        if (got > MemLog::max_one) MemLog::max_one = got;
        if (MemLog::min_one == 0 || got < MemLog::min_one) MemLog::min_one = got;
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }
    void deallocate(T* p, std::size_t) noexcept {
        ++MemLog::frees;
        ::operator delete(p);
    }

    template <class U> bool operator==(const LoggingAlloc<U>&) const noexcept { return true; }
    template <class U> bool operator!=(const LoggingAlloc<U>&) const noexcept { return false; }
};

static void report(const char* name) {
    std::printf("%-14s %8lld %10lld %10lld %10lld %8lld\n", name,
                MemLog::calls, MemLog::bytes, MemLog::max_one, MemLog::min_one,
                MemLog::frees);
}

int main() {
    constexpr int N = 1000;
    std::printf("容器             分配次数     累计字节     单次最大     单次最小   释放次数\n");

    MemLog::reset();
    {
        std::vector<int, LoggingAlloc<int>> v;
        for (int i = 0; i < N; ++i) v.push_back(i);
        asm volatile("" : : : "memory");
    }
    report("vector<int>");

    MemLog::reset();
    {
        std::list<int, LoggingAlloc<int>> l;
        for (int i = 0; i < N; ++i) l.push_back(i);
        asm volatile("" : : : "memory");
    }
    report("list<int>");

    MemLog::reset();
    {
        std::map<int, int, std::less<int>, LoggingAlloc<std::pair<const int, int>>> m;
        for (int i = 0; i < N; ++i) m.emplace(i, i);
        asm volatile("" : : : "memory");
    }
    report("map<int,int>");

    std::printf("三个容器都插入 %d 个元素，计数在容器析构之后读出\n", N);
    return 0;
}
```

**这个分配器一共写了五样东西**：`value_type`、模板转换构造、`allocate`、`deallocate`、
`operator==` 与 `operator!=`。`construct` 与 `destroy` 没有写——`allocator_traits`
会用 placement new 与直接析构顶上，第 1.4 小节引过那段原文。
三个容器用同一个分配器模板，各自的节点类型由 `rebind_alloc` 换出来。

## 3.3 三本账

**同一个分配器套到三个容器上，三本账的差别一目了然。**

`实测数据`
`Text`

```text
容器             分配次数     累计字节     单次最大     单次最小   释放次数
vector<int>          11       8188       4096          4       11
list<int>          1000      24000         24         24     1000
map<int,int>       1000      40000         40         40     1000
三个容器都插入 1000 个元素，计数在容器析构之后读出
```

## 3.4 差在哪

**三本账放在一起，差别出在「一次分配服务几个元素」上。**

| 容器 | 分配次数 | 累计字节 | 每次分配多大 | 为什么 |
|---|---|---|---|---|
| `vector<int>` | 11 | 8188 | 4、8、…、4096 | 一次分配换一整块缓冲区；累计字节是最终容量的约 2 倍 |
| `list<int>` | 1000 | 24000 | 24 | 每插一个元素一次分配：两个指针 + `int` + 填充 |
| `map<int,int>` | 1000 | 40000 | 40 | 每插一个键值对一次分配：颜色 + 三个指针 + 键值对 |

**三者的差别不在「每元素多少字节」，而在「一次分配服务几个元素」。**
`vector` 最后一次分配服务了 1024 个元素，`list` 与 `map` 一次永远只服务一个。
这正是《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 4.2 小节那句
「分配次数比字节数更值钱」的来源：次数决定了要进出分配器多少趟，
而每一趟都有成本——找块、切分、记账、合并。

**节点大小是结构量，逐位可复现**：`list<int>` 的节点 24 字节、`map<int,int>` 的节点 40 字节，
同一套标准库上重跑多少次都一样；换成 MSVC 的标准库，`map` 的节点布局不同，数字会变。
《09-高阶数据结构/A-02-链式存储：list 与 forward_list.md》第 2.2 小节算过链表节点的组成，
这里的 24 就是那个算式的答案。

> [!TIP]
> **分配器能改的是常数与内存开销，改不了复杂度。**
> 把 `list` 的分配器换成池子，插入仍然是 `O(1)`、按位置查找仍然是 `O(n)`；
> 想让查找变快只能换结构（见《09-高阶数据结构/A-03-索引存储：map、set 与有序.md》章节、
> 《09-高阶数据结构/A-04-按哈希定位：unordered_map.md》章节），换分配器没有用。

# 第 4 节 固定大小的内存池

## 4.1 需求：同一尺寸反复申请释放

第 3 节的表里，`list` 与 `map` 的分配次数与元素个数是一比一。
每次分配都要走一趟通用分配器：在空闲表里找一块合适的、可能要切分、要更新记账，
释放时还要看能不能与相邻的空闲块合并（《09-高阶数据结构/A-02-链式存储：list 与 forward_list.md》第 5.3 小节）。而这些块的**大小完全相同**——
`list<int>` 的节点永远是 24 字节。通用分配器要应付尺寸混杂的一般情形，
固定尺寸这种特殊情形它没有理由做得更快。

## 4.2 模型：一次要一大块，自己切

`Text`

```text
   向系统要一块（chunk），每块切成 4096 份：
   ┌────┬────┬────┬────┬────┬────┬────┬────┐
   │ 块 │ 块 │ 块 │ 块 │ 块 │ 块 │ 块 │ 块 │   每块 24 字节
   └────┴────┴────┴────┴────┴────┴────┴────┘
     ▲
     └── 切分位置：下一块从这里取

   还回来的块挂成空闲链表（空闲块自己的前 8 字节存下一个空闲块的地址）：
   free ──►┌──────┐   ┌──────┐   ┌──────┐
           │ 下一个├──►│ 下一个├──►│ null │
           └──────┘   └──────┘   └──────┘
```

**池子只有三个动作**：`accepts(尺寸)`（服务不服务这个尺寸）、`take()`（给一块）、
`give(p)`（还一块）。架在池子上的分配器把 `allocate` 与 `deallocate` 转给池子；
尺寸不符时退回系统分配，这就是「尺寸单一」这条限制的落地方式。

## 4.3 分配次数降到了多少

下面这份程序把默认分配器与池放在同一个工作量下对照，
系统分配次数由替换过的全局 `operator new` 数出来。

`C++`

```cpp
/* pool_alloc.cpp    编译：g++ -std=c++17 -O2 pool_alloc.cpp -o pool_alloc
 * 固定大小的内存池：同一尺寸反复申请释放时，把系统分配次数从十万级压到几十次；
 * 同一个池子遇到别的尺寸（map 的节点）会拒收，那一部分退回系统分配。 */
#include <chrono>
#include <cstddef>
#include <cstdio>
#include <cstdlib>
#include <list>
#include <map>
#include <new>

// ---- 全局 operator new / delete 计数：池子自己向系统要的块也会被数进来 ----
static long long g_new_calls = 0;
static long long g_new_bytes = 0;
static long long g_delete_calls = 0;

void* operator new(std::size_t n) {
    ++g_new_calls;
    g_new_bytes += static_cast<long long>(n);
    void* p = std::malloc(n ? n : 1);
    if (!p) throw std::bad_alloc();
    return p;
}
void operator delete(void* p) noexcept { ++g_delete_calls; std::free(p); }
void operator delete(void* p, std::size_t) noexcept { ++g_delete_calls; std::free(p); }
void* operator new[](std::size_t n) { return operator new(n); }
void operator delete[](void* p) noexcept { operator delete(p); }
void operator delete[](void* p, std::size_t) noexcept { operator delete(p); }

static void reset() { g_new_calls = g_new_bytes = g_delete_calls = 0; }

// ---- 固定块大小的池：一次向系统要一大块，切给很多次小请求 ----
class FixedPool {
public:
    static const std::size_t kMaxChunks = 512;

    explicit FixedPool(std::size_t blocks_per_chunk) : per_chunk_(blocks_per_chunk) {}
    ~FixedPool() {
        for (std::size_t i = 0; i < chunks_; ++i) ::operator delete(chunk_[i]);
    }

    // 池子只服务一种尺寸：第一个请求把它定下来，之后不符的请求一律拒收
    bool accepts(std::size_t want) const { return block_size_ == 0 || block_size_ == want; }

    void* take(std::size_t want) {
        if (block_size_ == 0)
            block_size_ = want < sizeof(void*) ? sizeof(void*) : want;
        if (block_size_ != want) return nullptr;      // 尺寸不符：池子不收

        ++live_;
        if (live_ > peak_) peak_ = live_;
        if (free_) {                              // 空闲链表里有现成的块
            void* p = free_;
            free_ = *static_cast<void**>(p);
            return p;
        }
        if (left_ == 0) new_chunk();              // 上一块用完了，向系统再要一块
        void* p = bump_;
        bump_ = static_cast<char*>(bump_) + block_size_;
        --left_;
        ++carved_;
        return p;
    }

    void give(void* p) {
        --live_;
        *static_cast<void**>(p) = free_;          // 空闲块自己存下一个空闲块的地址
        free_ = p;
    }

    std::size_t block_size() const { return block_size_; }
    std::size_t chunks() const { return chunks_; }
    std::size_t carved() const { return carved_; }
    std::size_t peak() const { return peak_; }

private:
    void new_chunk() {
        if (chunks_ >= kMaxChunks) {
            std::fprintf(stderr, "池子的块表满了\n");
            std::abort();
        }
        void* c = ::operator new(block_size_ * per_chunk_);
        chunk_[chunks_++] = c;
        bump_ = c;
        left_ = per_chunk_;
    }

    std::size_t per_chunk_;
    std::size_t block_size_ = 0;                  // 0 表示还没定型
    std::size_t left_ = 0;                        // 当前块还能切出几个
    void* free_ = nullptr;                        // 空闲链表头
    void* bump_ = nullptr;                        // 当前块的切分位置
    void* chunk_[kMaxChunks] = {};
    std::size_t chunks_ = 0;
    std::size_t carved_ = 0;
    std::size_t peak_ = 0;
    std::size_t live_ = 0;
};

// ---- 架在池子上的分配器：尺寸不符时退回 ::operator new ----
static long long g_fallback = 0;

template <class T>
struct PoolAlloc {
    using value_type = T;
    FixedPool* pool = nullptr;

    PoolAlloc() noexcept = default;
    explicit PoolAlloc(FixedPool* p) noexcept : pool(p) {}
    template <class U>
    PoolAlloc(const PoolAlloc<U>& o) noexcept : pool(o.pool) {}

    T* allocate(std::size_t n) {
        if (n == 1 && pool->accepts(sizeof(T))) return static_cast<T*>(pool->take(sizeof(T)));
        if (n == 1) ++g_fallback;                 // 尺寸不符：池子不收，退回系统
        return static_cast<T*>(::operator new(n * sizeof(T)));
    }
    void deallocate(T* p, std::size_t n) noexcept {
        if (n == 1 && pool->accepts(sizeof(T))) { pool->give(p); return; }
        ::operator delete(p);
    }

    template <class U> bool operator==(const PoolAlloc<U>& o) const noexcept { return pool == o.pool; }
    template <class U> bool operator!=(const PoolAlloc<U>& o) const noexcept { return pool != o.pool; }
};

int main() {
    constexpr int N = 100000;          // 节点数
    constexpr int CHUNK = 4096;        // 池子每块切多少个
    volatile long long sink = 0;

    std::printf("== 一、默认分配器：十万个节点两轮 ==\n");
    reset();
    {
        std::list<int> l;
        for (int r = 0; r < 2; ++r) {
            for (int i = 0; i < N; ++i) l.push_back(i);
            sink += static_cast<long long>(l.size());
            l.clear();
        }
        asm volatile("" : : : "memory");
        std::printf("两轮各插入 %d 个节点：operator new 调用 %lld 次，累计 %lld 字节\n",
                    N, g_new_calls, g_new_bytes);
    }

    std::printf("== 二、固定大小的池：同一工作量 ==\n");
    reset();
    FixedPool pool(CHUNK);
    {
        PoolAlloc<int> pa{&pool};
        std::list<int, PoolAlloc<int>> l(pa);
        for (int r = 0; r < 2; ++r) {
            for (int i = 0; i < N; ++i) l.push_back(i);
            sink += static_cast<long long>(l.size());
            l.clear();
        }
        asm volatile("" : : : "memory");
        std::printf("两轮各插入 %d 个节点：operator new 调用 %lld 次，累计 %lld 字节\n",
                    N, g_new_calls, g_new_bytes);
        std::printf("池子定型的块大小 = %zu 字节，每块切 %d 个，向系统要了 %zu 块\n",
                    pool.block_size(), CHUNK, pool.chunks());
        std::printf("池子一共切出 %zu 个块，峰值同时在用 %zu 个\n", pool.carved(), pool.peak());
    }

    std::printf("== 三、同一个池子换成 map 的节点（尺寸不同）==\n");
    reset();
    g_fallback = 0;
    {
        using MapAlloc = PoolAlloc<std::pair<const int, int>>;
        MapAlloc ma{&pool};
        std::map<int, int, std::less<int>, MapAlloc> m(ma);
        for (int i = 0; i < 1000; ++i) m.emplace(i, i);
        asm volatile("" : : : "memory");
        std::printf("插入 1000 个 map 节点：operator new 调用 %lld 次，累计 %lld 字节\n",
                    g_new_calls, g_new_bytes);
        std::printf("分配器发现尺寸不符、退回系统分配 %lld 次（池子定型的 24 字节用不上）\n",
                    g_fallback);
        std::printf("池子定型的块大小仍是 %zu 字节，池内切出的块仍是 %zu 个\n",
                    pool.block_size(), pool.carved());
    }

    std::printf("== 四、耗时对照（同一次运行内）==\n");
    constexpr int ROUNDS = 20;
    double ms_default = 0.0, ms_pool = 0.0;
    {
        std::list<int> l;
        const auto t0 = std::chrono::steady_clock::now();
        for (int r = 0; r < ROUNDS; ++r) {
            for (int i = 0; i < N; ++i) l.push_back(i);
            sink += static_cast<long long>(l.size());
            l.clear();
        }
        const auto t1 = std::chrono::steady_clock::now();
        ms_default = std::chrono::duration<double, std::milli>(t1 - t0).count();
    }
    {
        FixedPool pool2(CHUNK);
        PoolAlloc<int> pa{&pool2};
        std::list<int, PoolAlloc<int>> l(pa);
        const auto t0 = std::chrono::steady_clock::now();
        for (int r = 0; r < ROUNDS; ++r) {
            for (int i = 0; i < N; ++i) l.push_back(i);
            sink += static_cast<long long>(l.size());
            l.clear();
        }
        const auto t1 = std::chrono::steady_clock::now();
        ms_pool = std::chrono::duration<double, std::milli>(t1 - t0).count();
    }
    std::printf("%d 个节点 × %d 轮（插满再清空）总耗时：默认分配器 %.1f ms\n",
                N, ROUNDS, ms_default);
    std::printf("%d 个节点 × %d 轮（插满再清空）总耗时：池 %.1f ms\n",
                N, ROUNDS, ms_pool);
    std::printf("同一工作量下池比默认分配器快 %.1f 倍（默认 %.1f ms，池 %.1f ms）\n",
                ms_default / ms_pool, ms_default, ms_pool);
    return 0;
}
```

`实测数据`
`Text`

```text
== 一、默认分配器：十万个节点两轮 ==
两轮各插入 100000 个节点：operator new 调用 200000 次，累计 4800000 字节
== 二、固定大小的池：同一工作量 ==
两轮各插入 100000 个节点：operator new 调用 25 次，累计 2457600 字节
池子定型的块大小 = 24 字节，每块切 4096 个，向系统要了 25 块
池子一共切出 100000 个块，峰值同时在用 100000 个
== 三、同一个池子换成 map 的节点（尺寸不同）==
插入 1000 个 map 节点：operator new 调用 1000 次，累计 40000 字节
分配器发现尺寸不符、退回系统分配 1000 次（池子定型的 24 字节用不上）
池子定型的块大小仍是 24 字节，池内切出的块仍是 100000 个
== 四、耗时对照（同一次运行内）==
100000 个节点 × 20 轮（插满再清空）总耗时：默认分配器 85.1 ms
100000 个节点 × 20 轮（插满再清空）总耗时：池 6.1 ms
同一工作量下池比默认分配器快 13.9 倍（默认 85.1 ms，池 6.1 ms）
```

**同一份工作量，系统分配从 200000 次降到 25 次。**
第一轮插入十万个节点，池子向系统要 25 块，每块切 4096 份，一共切出 100000 块；
清空时节点没有还给系统，而是挂回池子的空闲链表，第二轮再插十万个，**一次系统分配都没要**。

**累计字节从 4800000 降到 2457600。** 少的那一半不是元素本身，
是通用分配器给每一块配的记账信息——池子只需要给整块记账，块与块之间不需要额外开销。

**峰值 100000 块**：池子的占用看的是峰值，不是累计。这条性质是双刃的：
省下了反复进出的成本，代价是这些内存不还给系统，除非把整块还掉。

**耗时那一栏差了一个数量级。** 它是计时量，随机器负载变化，
本教材的自检脚本按比值判，超过 5 倍才算不一致；而且优势全部来自「第二轮开始复用」，
第一轮池子也要向系统要 25 块，那一轮它与默认分配器做的事差不多。

## 4.4 池子适合什么、不适合什么

**池子的收益与风险来自同一件事：内存的所有权被它握住了。**

| 适合 | 为什么 | 不适合 | 为什么 |
|---|---|---|---|
| 尺寸单一 | 池子只服务一种块大小，`take` 是几步指针操作 | 尺寸混杂 | 每个尺寸要一套池子，等于自己写一个通用分配器；本节实测里 `map` 的 40 字节节点就被这个池子退回系统分配 1000 次 |
| 分配次数远大于块种类 | 收益随分配次数增长 | 分配次数本来就不多 | 复杂度与风险照付，收益接近于零 |
| 生命周期整齐（一起要一起还，或反复申请释放同一批） | 空闲块能循环利用 | 长短命混在一起 | 池子只能整块还给系统，一块长期活着就压住整块 |
| 要可预测的延迟 | 没有查找、没有切分、没有合并 | 要把内存及时还给系统 | 池子默认不还，还就是整块还 |

**还有一条最容易漏的：池子默认不是线程安全的。**
空闲链表是一个共享的指针，两个线程同时 `take` 就会撞车。
多线程场景要么给池子加锁，那会把池子的一部分优势还回去；要么给每个线程一个池子。
数据竞争是未定义行为这一条，见【待补：10-并发与并行/】，那个板块讲线程与原子量。

## 4.5 标准库里的池

**池子不是标准库之外的土办法。** C++17 的 `std::pmr` 里就有现成的资源类型：
`unsynchronized_pool_resource` 与 `synchronized_pool_resource` 是按尺寸分档的池，
`monotonic_buffer_resource` 是另一种用途的资源，标准里各有一节
（N4659 §23.12.5、§23.12.6）。自己写池子的场合通常是：要接一块固定地址（嵌入式）、
要跨进程共享，或者要一份自己能完全控制的记账，第 3 节那种。

# 第 5 节 两处容易踩的地方

## 5.1 `deallocate` 的大小参数是一份契约

**`allocate(n)` 与 `deallocate(p, n)` 里的 `n` 必须一致**，标准把它写成对调用方的要求：

`文档`

> "Requires: p shall be a pointer value obtained from allocate(). n shall equal the value passed as
> the first argument to the invocation of allocate which returned p."
>
> —— N4659 §23.10.9.1/5

下面这份程序把两种分配器放在一起对照：一种忽略 `n`，自己记着每块的账；
一种拿 `n` 归档，按尺寸分档。然后故意把 `n` 写错。

`C++`

```cpp
/* dealloc_size.cpp    编译：g++ -std=c++17 -O2 dealloc_size.cpp -o dealloc_size
 * 两件事：deallocate 的大小参数被写错会怎样；分配器的 == 与容器的 == 不是一回事。 */
#include <cstddef>
#include <cstdio>
#include <new>
#include <vector>

// ---- 一、忽略 n 的分配器：自己记一份「指针 → 字节」的账 ----
struct Ledger {
    static const int kMax = 4096;
    void* p[kMax];
    std::size_t b[kMax];
    int n = 0;

    void add(void* q, std::size_t bytes) { p[n] = q; b[n] = bytes; ++n; }
    std::size_t remove(void* q) {                 // 返回当初记下的字节，找不到返回 0
        for (int i = 0; i < n; ++i) {
            if (p[i] == q) {
                const std::size_t got = b[i];
                p[i] = p[n - 1];
                b[i] = b[n - 1];
                --n;
                return got;
            }
        }
        return 0;
    }
    long long live_bytes() const {
        long long s = 0;
        for (int i = 0; i < n; ++i) s += static_cast<long long>(b[i]);
        return s;
    }
};
static Ledger g_ledger;
static long long g_mismatch = 0;

template <class T>
struct MallocAlloc {
    using value_type = T;
    T* allocate(std::size_t n) {
        void* q = ::operator new(n * sizeof(T));
        g_ledger.add(q, n * sizeof(T));
        return static_cast<T*>(q);
    }
    void deallocate(T* p, std::size_t n) noexcept {
        const std::size_t real = g_ledger.remove(p);      // 释放路径只查自己的账，不看 n
        if (real != n * sizeof(T)) ++g_mismatch;
        ::operator delete(p);
    }
    template <class U> bool operator==(const MallocAlloc<U>&) const noexcept { return true; }
    template <class U> bool operator!=(const MallocAlloc<U>&) const noexcept { return false; }
};

// ---- 二、按 n 归档的池子：档位 16 / 32 / 64 字节 ----
class SizeClassArena {
public:
    static const int kClasses = 3;
    static std::size_t size_of(int c) { return static_cast<std::size_t>(16) << c; }
    static int class_of(std::size_t bytes) {
        for (int c = 0; c < kClasses; ++c)
            if (bytes <= size_of(c)) return c;
        return kClasses - 1;
    }

    ~SizeClassArena() {
        for (int i = 0; i < carved_n_; ++i) ::operator delete(carved_[i]);
    }

    void* allocate(std::size_t bytes) {
        const int c = class_of(bytes);
        void* p;
        if (free_[c]) {                                   // 从这一档的空闲链表里取
            p = free_[c];
            free_[c] = *static_cast<void**>(p);
        } else {
            p = ::operator new(size_of(c));
            carved_[carved_n_++] = p;
        }
        if (true_class(p, c) != c) ++wrong_handouts_;     // 取到的块比请求的档小
        return p;
    }

    void deallocate(void* p, std::size_t bytes) {
        const int c = class_of(bytes);                    // 按调用方给的 n 归档
        if (true_class(p, c) != c) ++misrouted_;          // 与实际档位不符
        *static_cast<void**>(p) = free_[c];
        free_[c] = p;
    }

    std::size_t true_bytes(void* p) const {               // 这块内存当初是按哪一档要来的
        for (int i = 0; i < seen_n_; ++i)
            if (seen_ptr_[i] == p) return size_of(seen_class_[i]);
        return 0;
    }
    long long misrouted() const { return misrouted_; }
    long long wrong_handouts() const { return wrong_handouts_; }

private:
    int true_class(void* p, int c) {                      // 第一次见到就记下真实档位
        for (int i = 0; i < seen_n_; ++i)
            if (seen_ptr_[i] == p) return seen_class_[i];
        seen_ptr_[seen_n_] = p;
        seen_class_[seen_n_] = c;
        ++seen_n_;
        return c;
    }

    void* free_[kClasses] = {};
    void* carved_[512] = {};
    int carved_n_ = 0;
    void* seen_ptr_[1024] = {};
    int seen_class_[1024] = {};
    int seen_n_ = 0;
    long long misrouted_ = 0;
    long long wrong_handouts_ = 0;
};

// ---- 三、分配器相等不参与对象相等 ----
template <class T>
struct ArenaAlloc {
    using value_type = T;
    int arena = 0;
    ArenaAlloc() = default;
    explicit ArenaAlloc(int a) : arena(a) {}
    template <class U> ArenaAlloc(const ArenaAlloc<U>& o) : arena(o.arena) {}
    T* allocate(std::size_t n) { return static_cast<T*>(::operator new(n * sizeof(T))); }
    void deallocate(T* p, std::size_t) { ::operator delete(p); }
    template <class U> bool operator==(const ArenaAlloc<U>& o) const { return arena == o.arena; }
    template <class U> bool operator!=(const ArenaAlloc<U>& o) const { return arena != o.arena; }
    template <class> friend struct ArenaAlloc;
};

int main() {
    std::printf("== 一、忽略 n 的分配器 ==\n");
    {
        MallocAlloc<int> alloc;
        int* p = alloc.allocate(10);                       // 40 字节
        std::printf("allocate(10) 之后：账面活着 %d 块、%lld 字节\n",
                    g_ledger.n, g_ledger.live_bytes());
        alloc.deallocate(p, 3);                            // 故意把 n 写成 3（当初是 10）
        std::printf("按错误的 n=3 归还（当初是 10）：账面活着 %d 块、%lld 字节\n",
                    g_ledger.n, g_ledger.live_bytes());
        std::printf("分配器发现 n 与实际不符 %lld 次；没有崩，账面也归零\n", g_mismatch);
    }

    std::printf("== 二、按 n 归档的池子 ==\n");
    {
        SizeClassArena arena;
        void* a = arena.allocate(24);                      // 进 32 字节档
        arena.deallocate(a, 24);                           // 按 24 归还：一致
        std::printf("正确路径：allocate(24) 拿 %zu 字节档的块，按 n=24 归还\n",
                    arena.true_bytes(a));

        void* b = arena.allocate(8);                       // 进 16 字节档
        arena.deallocate(b, 24);                           // 按 24 归还：归进了 32 字节档
        std::printf("错误路径：allocate(8) 拿 %zu 字节档的块，按 n=24 归还\n",
                    arena.true_bytes(b));

        void* c = arena.allocate(24);                      // 从 32 档取，取到的却是 16 字节那块
        const std::size_t got = arena.true_bytes(c);
        std::printf("之后 allocate(24)：拿到的块真实大小 %zu 字节，比请求的 24 字节少 %zu 字节\n",
                    got, 24 - got);
        std::printf("池子记录：归错档 %lld 次，发出偏小的块 %lld 次\n",
                    arena.misrouted(), arena.wrong_handouts());
        (void)c;
    }

    std::printf("== 三、分配器的 == 与容器的 == ==\n");
    {
        ArenaAlloc<int> a1{1}, a2{2}, a3{1};
        std::vector<int, ArenaAlloc<int>> v1(a1), v2(a2), v3(a3);
        for (int i = 0; i < 3; ++i) {
            v1.push_back(i);
            v2.push_back(i);
            v3.push_back(i);
        }
        std::printf("内容相同的两个 vector：v1 == v2 → %d\n", static_cast<int>(v1 == v2));
        std::printf("两个分配器本身：a1 == a2 → %d，a1 == a3 → %d\n",
                    static_cast<int>(a1 == a2), static_cast<int>(a1 == a3));
        std::vector<int, ArenaAlloc<int>> v4 = v1;         // 拷贝构造：分配器跟着来源走
        std::printf("从 v1 拷贝出的 v4：arena = %d（默认取来源那一份）\n",
                    v4.get_allocator().arena);
    }
    return 0;
}
```

`实测数据`
`Text`

```text
== 一、忽略 n 的分配器 ==
allocate(10) 之后：账面活着 1 块、40 字节
按错误的 n=3 归还（当初是 10）：账面活着 0 块、0 字节
分配器发现 n 与实际不符 1 次；没有崩，账面也归零
== 二、按 n 归档的池子 ==
正确路径：allocate(24) 拿 32 字节档的块，按 n=24 归还
错误路径：allocate(8) 拿 16 字节档的块，按 n=24 归还
之后 allocate(24)：拿到的块真实大小 16 字节，比请求的 24 字节少 8 字节
池子记录：归错档 1 次，发出偏小的块 1 次
== 三、分配器的 == 与容器的 == ==
内容相同的两个 vector：v1 == v2 → 1
两个分配器本身：a1 == a2 → 0，a1 == a3 → 1
从 v1 拷贝出的 v4：arena = 1（默认取来源那一份）
```

**第一种分配器对错的 `n` 免疫。** 它自己记着「指针 → 字节」的账，
释放路径只查自己的表，`n` 只当参考；因此账目照样归零，没有崩，也没有泄漏。
`malloc` 一类的实现就是这种形状，`free` 不需要大小。

**第二种分配器把正确性押在了调用方身上。** 它按 `n` 算出该还给哪一档：
16 字节的块被按 24 字节归还，于是进了 32 字节档；下一次 `allocate(24)` 从 32 字节档取块，
取到的却是那块 16 字节的内存，**比请求少 8 字节**。
池子自己记录了这个错位：归错档 1 次、发出偏小的块 1 次。

> [!CAUTION]
> **归错档不会立刻报错，这才是它危险的地方。**
> 上面那个程序没有崩，只是池子发出了一块偏小的内存；
> 真往那块内存里写 24 字节才是堆越界，那是未定义行为。
> 这类错误在测试里常常表现为「偶发崩溃」，因为要等到那块内存被重新发出去、
> 并且被写满才发作。

**两边各有各的教训**：

| 站在哪一边 | 教训 |
|---|---|
| 写分配器 | 可以完全忽略 `n`；但只要实现要用 `n`，就等于把正确性押在调用方守约上 |
| 写容器 | 必须把 `allocate` 的 `n` 原样存下来，`deallocate` 时原样传回去。`vector` 记的是 `capacity`，`list` 与 `map` 每次只要一个节点，传的永远是 1 |

标准库容器自己守约，因此这条契约在「只用标准容器」时看不见；
一旦自己写容器或写包装层，它就是第一个会露头的地方。
《09-高阶数据结构/B-01-手写：动态数组.md》第 7 节把这条写成了「`deallocate` 的 `n` 不能省」，
这里给出的是它背后的现场。

## 5.2 分配器的 `==` 不参与容器的 `==`

**`a1 == a2` 只回答一件事：`a1` 释放的内存，`a2` 能不能释放。**
它不是「两个分配器长得一样」，也不是「两块内存的内容一样」。
第 5.1 小节的程序最后一段把这件事打了出来：内容相同的两个 `vector` 相等，
而它们背后的两个分配器不相等；同一个 arena 的两个分配器对象才相等。

**容器的相等是值语义**：比的是元素与顺序，内存从哪个 arena 来与「值」无关。
分配器的相等是另一件事：它决定内存的所有权能不能转移。

**分配器的 `==` 决定了这几件事**：

| 场合 | 分配器相等 | 分配器不相等 |
|---|---|---|
| 移动赋值 | 缓冲区直接换手（第 7.2 小节实测：0 次元素移动） | 只能逐个搬（1000 次元素移动） |
| `swap` | 可以互换内容 | **行为未定义**，除非 `propagate_on_container_swap` 为真 |
| 拷贝构造 | 沿用来源那一份（`select_on_container_copy_construction`） | 同上，默认也是沿用来源那一份 |

`文档`

> "Otherwise, the allocators shall not be swapped, and the behavior is undefined unless
> a.get_allocator() == b.get_allocator()."
>
> —— N4659 §26.2.1/9

> [!WARNING]
> **`swap` 这一条是「看起来能用、标准却没有保证」的典型。**
> 两个分配器不相等的容器互换内容，标准库通常不会崩，元素看起来也换过来了，
> 但两块内存的所有权已经错位，容器析构时可能把它不该释放的内存还回去。
> 无状态分配器永远相等，默认分配器就是这样，因此这条只有自定义分配器时才露头。

# 第 6 节 `std::pmr` 一句话指路

**C++17 给了另一条路：把分配器的类型从编译期参数换成运行期指针。**
`std::pmr::polymorphic_allocator<T>` 里存一个 `memory_resource*`，
因此两个 `std::pmr::vector<int>` 是同一个类型，却可以一个用普通堆、一个用栈上的缓冲区。

`文档`

> "Constructed with different memory resources, different instances of the same specialization of
> pmr::polymorphic_allocator can exhibit entirely different allocation behavior. This runtime
> polymorphism allows objects that use polymorphic_allocator to behave as if they used different
> allocator types at run time even though they use the same static allocator type."
>
> —— N4659 §23.12.3/1

**什么时候值得用**：同一份代码要在几种内存来源之间切换（普通堆、栈上缓冲区、池），
又不想让分配器类型渗进每一个函数签名与每一个容器类型时。
**代价是多一个指针与一次间接调用**：`sizeof(std::pmr::vector<int>)` 是 32 字节，
比普通的 `vector<int>` 多 8 字节，第 7.1 小节的表里有这一行。

**本章不展开这一套。** 分配器接口与对齐的用法见
《07-标准库/B-10-内存与并发的基础设施.md》第 1 节；
多态内存资源的几个资源类（`synchronized_pool_resource`、`unsynchronized_pool_resource`、
`monotonic_buffer_resource` 与全局资源）在本教材里还没有对应的章节，
需要时按 N4659 §23.12.4 到 §23.12.6 查。

# 第 7 节 代价与选择

## 7.1 容器对象的大小

下面这份程序把几种分配器下的容器对象大小逐个打出来。

`C++`

```cpp
/* alloc_cost.cpp    编译：g++ -std=c++17 -O2 alloc_cost.cpp -o alloc_cost
 * 带分配器的两笔代价：容器的对象大小，以及分配器不相等时移动赋值退化成逐元素搬。 */
#include <cstddef>
#include <cstdio>
#include <list>
#include <map>
#include <memory_resource>
#include <new>
#include <string>
#include <vector>

template <class T>
struct EmptyAlloc {                                   // 无状态、空类型：可以被优化掉
    using value_type = T;
    T* allocate(std::size_t n) { return static_cast<T*>(::operator new(n * sizeof(T))); }
    void deallocate(T* p, std::size_t) { ::operator delete(p); }
    template <class U> bool operator==(const EmptyAlloc<U>&) const noexcept { return true; }
    template <class U> bool operator!=(const EmptyAlloc<U>&) const noexcept { return false; }
};

template <class T>
struct ArenaAlloc {                                   // 有状态：记着自己属于哪个内存区
    using value_type = T;
    int arena = 0;
    ArenaAlloc() = default;
    explicit ArenaAlloc(int a) : arena(a) {}
    template <class U> ArenaAlloc(const ArenaAlloc<U>& o) : arena(o.arena) {}
    T* allocate(std::size_t n) { return static_cast<T*>(::operator new(n * sizeof(T))); }
    void deallocate(T* p, std::size_t) { ::operator delete(p); }
    template <class U> bool operator==(const ArenaAlloc<U>& o) const { return arena == o.arena; }
    template <class U> bool operator!=(const ArenaAlloc<U>& o) const { return arena != o.arena; }
    template <class> friend struct ArenaAlloc;
};

struct Counted {                                      // 数一数元素被搬了几次
    static long long moves;
    static long long copies;
    int v;
    explicit Counted(int x = 0) : v(x) {}
    Counted(const Counted& o) : v(o.v) { ++copies; }
    Counted(Counted&& o) noexcept : v(o.v) { ++moves; }
    Counted& operator=(const Counted& o) { v = o.v; ++copies; return *this; }
    Counted& operator=(Counted&& o) noexcept { v = o.v; ++moves; return *this; }
};
long long Counted::moves = 0;
long long Counted::copies = 0;

int main() {
    std::printf("对象                                             字节\n");
    std::printf("%-44s %4zu\n", "std::vector<int>", sizeof(std::vector<int>));
    std::printf("%-44s %4zu\n", "std::vector<int, EmptyAlloc<int>>",
                sizeof(std::vector<int, EmptyAlloc<int>>));
    std::printf("%-44s %4zu\n", "std::vector<int, ArenaAlloc<int>>",
                sizeof(std::vector<int, ArenaAlloc<int>>));
    std::printf("%-44s %4zu\n", "std::list<int>", sizeof(std::list<int>));
    std::printf("%-44s %4zu\n", "std::list<int, ArenaAlloc<int>>",
                sizeof(std::list<int, ArenaAlloc<int>>));
    std::printf("%-44s %4zu\n", "std::map<int,int>", sizeof(std::map<int, int>));
    std::printf("%-44s %4zu\n", "std::map<int,int, ArenaAlloc<pair<const int,int>>>",
                sizeof(std::map<int, int, std::less<int>,
                                ArenaAlloc<std::pair<const int, int>>>));
    std::printf("%-44s %4zu\n", "std::pmr::vector<int>", sizeof(std::pmr::vector<int>));
    std::printf("%-44s %4zu\n", "std::pmr::string", sizeof(std::pmr::string));
    std::printf("ArenaAlloc<int> 自己只有 %zu 字节（一个 int），对齐到 %zu 字节\n",
                sizeof(ArenaAlloc<int>), alignof(ArenaAlloc<int>));

    constexpr int N = 1000;
    {
        ArenaAlloc<Counted> a1{1}, a2{2};
        std::vector<Counted, ArenaAlloc<Counted>> x(a1), y(a2);
        x.reserve(N);
        y.reserve(N);
        for (int i = 0; i < N; ++i) {
            x.emplace_back(i);
            y.emplace_back(i);
        }
        Counted::moves = Counted::copies = 0;
        x = std::move(y);                             // 分配器不相等：缓冲区不能接管
        std::printf("分配器不相等时的移动赋值：元素移动 %lld 次，拷贝 %lld 次\n",
                    Counted::moves, Counted::copies);
    }
    {
        ArenaAlloc<Counted> a1{1};
        std::vector<Counted, ArenaAlloc<Counted>> x(a1), y(a1);
        x.reserve(N);
        y.reserve(N);
        for (int i = 0; i < N; ++i) {
            x.emplace_back(i);
            y.emplace_back(i);
        }
        Counted::moves = Counted::copies = 0;
        x = std::move(y);                             // 分配器相等：整块缓冲区直接换手
        std::printf("分配器相等时的移动赋值：元素移动 %lld 次，拷贝 %lld 次\n",
                    Counted::moves, Counted::copies);
    }
    return 0;
}
```

`Text`

```text
对象                                             字节
std::vector<int>                               24
std::vector<int, EmptyAlloc<int>>              24
std::vector<int, ArenaAlloc<int>>              32
std::list<int>                                 24
std::list<int, ArenaAlloc<int>>                32
std::map<int,int>                              48
std::map<int,int, ArenaAlloc<pair<const int,int>>>   48
std::pmr::vector<int>                          32
std::pmr::string                               40
ArenaAlloc<int> 自己只有 4 字节（一个 int），对齐到 4 字节
分配器不相等时的移动赋值：元素移动 1000 次，拷贝 0 次
分配器相等时的移动赋值：元素移动 0 次，拷贝 0 次
```

**无状态分配器一个字节都不多花。** `EmptyAlloc` 没有数据成员，
容器用空基类优化把它塞进原有的填充里：`vector` 24 对 24。

**有状态分配器让 `vector` 与 `list` 各多 8 字节**：24 变成 32。
多出来的不是 4 字节而是 8，分配器要按指针宽度对齐，而 `ArenaAlloc<int>` 自己只有 4 字节。
一个容器多 8 字节，一万个容器就是 80 KB。

**`map` 没有变大：48 对 48。** 树容器的成员里本来就有对齐留下的空隙，
那 4 字节塞得进去，这一点与 `vector`、`list` 不同。
**分配器的状态不是免费的，但也不是每个容器都收这笔钱**，取决于容器里原本有没有空隙。

**`std::pmr` 的容器多一个指针**：`pmr::vector<int>` 是 32 字节，
比普通 `vector<int>` 多 8 字节，这是第 6 节那句「代价是多一个指针」的实测。

## 7.2 拷贝与移动语义

最后两行输出是同一件事的两种结果：**分配器相等时，移动赋值把整块缓冲区换手，
一个元素都不用搬；分配器不相等时，只能把 1000 个元素逐个搬过去。**

**原因是 `propagate_on_container_move_assignment` 默认为 `false_type`**：
移动赋值不能改变目标容器的分配器。两个分配器不相等时，目标容器的内存不能接管来源的缓冲区，
接管了也没法释放——释放必须用当初分配它的那个分配器。因此只能把元素搬进自己的内存，
搬完以后来源的缓冲区照旧由来源释放。

**这条与「无状态分配器永远相等」连起来看**：默认分配器与一切空类型分配器都不会付这笔钱，
自定义的有状态分配器才会。这也是「能无状态就无状态」的一条实际理由。

## 7.3 什么时候该自己写分配器

**该不该写，取决于内存的来源与分配的次数，不取决于分配器的写法。**

| 该写 | 不该写 |
|---|---|
| 要把某类容器的内存集中管起来（池、固定地址、共享内存） | 只是「觉得 `malloc` 慢」——先按第 3 节的办法数一遍次数与字节 |
| 要统计与限额（内存预算、调试期护栏、泄漏检测） | 为了「减少碎片」而写一个通用分配器：通用分配器已经做了几十年这件事 |
| 要在没有系统堆的环境里给容器一块静态内存（嵌入式） | 分配次数本来就不多：复杂度照付，收益接近于零 |
| 要可预测的延迟（实时系统不能接受一次不确定的查找） | 需要线程安全又没打算写锁：池子默认不是线程安全的 |

**一条判断顺序**：先数（第 3 节），再算（第 4 节：池子能省多少），最后才写。
数出来「次数不多、字节不大」，就到此为止——**换分配器不会让算法变快，只会让常数变小。**

**与 B 段的分工**：自己写容器时怎么把分配器接进去（`rebind`、`n` 要存、异常安全），
见《09-高阶数据结构/B-01-手写：动态数组.md》第 7 节；
这一层是标准库给的分配器：默认分配器是谁、traits 补了什么、容器怎么用它。

# 术语表

| 术语 | 含义 |
|---|---|
| 分配器（allocator） | 容器用来要内存、还内存的接口；对象生命周期仍由容器管 |
| `allocator_traits` | 容器与分配器之间的适配层：分配器写了就用，没写就补默认 |
| `rebind` | 把 `A<T>` 换成 `A<U>`；容器用它拿到节点类型的分配器 |
| 原始内存 | 只分配、未构造对象的一块内存 |
| 空类型分配器 | 没有数据成员的分配器；容器不为它留空间，而且永远相等 |
| 有状态分配器 | 带数据的分配器，例如记着自己属于哪个池子；容器对象会变大，相等性要看数据 |
| 内存池 | 一次向系统要大块、自己切成固定大小块的分配方式 |
| `std::pmr` | C++17 的多态内存资源：分配器类型在编译期固定，资源在运行期可换 |
