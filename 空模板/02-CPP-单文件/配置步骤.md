## 唯一的实质区别：GDB 路线需要使用 `g++`

建议先通过实验观察该现象，这比直接记忆结论更为有效：

```powershell
# 使用 gcc 编译 C++ 会失败
gcc -g -O0 main.cpp -o main_gcc.exe
```

将出现以下错误信息：

```
undefined reference to `std::cout'
undefined reference to `operator new(unsigned long long)'
...
```

**原因**：`gcc` 能够识别 `.cpp` 并按 C++ 语法编译，但**不会自动链接 `libstdc++`**。

```powershell
# 改用 g++ 可以成功
g++ -g -O0 main.cpp -o main_gpp.exe
```

- [ ] 复现一次上述报错（以便识别该错误的形式）

> **说明**：MSVC 的 `cl.exe` 不存在该问题，它按文件扩展名判断语言，参数均相同。

## 其他注意点

| 项 | C | C++ |
|---|---|---|
| 编译器 | `gcc` | **`g++`** |
| 标准参数 | `-std=gnu17` | `-std=gnu++17` |
| 智能感知 | `C_Cpp.default.cStandard` | `C_Cpp.default.cppStandard` |
| 智能感知编译器 | `gcc.exe` | **`g++.exe`** |

`launch.json` **完全相同**：调试器不区分所编写的是 C 还是 C++。
