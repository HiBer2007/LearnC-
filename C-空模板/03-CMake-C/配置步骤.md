# 配置步骤 · 空模板 03（CMake 工程，C）

目标：使本文件夹中按 **F5** 即可自动依次完成 CMake 配置、编译与调试，两条路线各配置一套。

与单文件模板相比，本模板增加两项操作：**编写 CMake 预设** 与 **使 F5 自动执行 CMake 的两个步骤**。

---

## 第 0 步 · 先确认工程本身能够编译

在不启动 VS Code 的情况下，使用命令行验证：

```powershell
cmake -S . -B build -G Ninja -DCMAKE_C_COMPILER=gcc -DCMAKE_BUILD_TYPE=Debug
cmake --build build
build\bin\app.exe
```

- [ ] 命令行能够配置、能够编译、能够运行

> **说明**：本步骤较为重要。**CMake 报错与 VS Code 报错是两类不同的问题**，
> 应先排除 CMake 层面的问题，再检查 VS Code 配置。

---

## 第 1 步 · 编写 `CMakePresets.json`

将上述命令固化到预设中，避免每次手动输入。需要编写：

- [ ] 一个 `configurePresets` 条目（Ninja + gcc + Debug）
- [ ] 一个 `configurePresets` 条目（Visual Studio 17 2022 + x64）
- [ ] 对应的 `buildPresets` 条目

**关键点：**

| 项 | 说明 |
|---|---|
| `binaryDir` | 两个预设必须使用**不同的目录**（如 `build/mingw` / `build/msvc`），否则会互相覆盖 |
| MSVC 使用 VS 生成器 | 该方式**不需要 vcvars**，CMake 会自动定位 Visual Studio |
| **不能写注释** | 它是严格 JSON。CMake 底层容忍注释，但 CMake Tools 扩展可能不容忍 |
| `CMAKE_EXPORT_COMPILE_COMMANDS` | Ninja 生成器会产出 `compile_commands.json`，供智能感知使用 |

- [ ] `cmake --list-presets` 能够看到所编写的预设

---

## 第 1.5 步 · `CMakeLists.txt`：设置字符集

**该步骤容易被忽略，但缺少时程序的中文输出会显示为 `涓枃` 一类的乱码。**

gcc 与 MSVC 默认都把字符串常量按 UTF-8 写入 exe，而中文 Windows 的控制台
按 CP936（GBK）解释字节流。需要在 `CMakeLists.txt` 中显式指定：

- [ ] MSVC 分支使用 `/source-charset:utf-8 /execution-charset:gbk`
      （**不能使用 `/utf-8`**，它会把执行字符集也设为 UTF-8）
- [ ] 非 MSVC 分支使用 `-finput-charset=UTF-8 -fexec-charset=GBK`

```cmake
if(MSVC)
    target_compile_options(app PRIVATE /source-charset:utf-8 /execution-charset:gbk /W4)
else()
    target_compile_options(app PRIVATE -g -Wall -Wextra
                                -finput-charset=UTF-8 -fexec-charset=GBK)
endif()
```

> **说明**：完整的字节级实测对照见《01-编译器/02-环境配置.md》第 9 章第 6 节。

- [ ] 编译后运行程序，确认中文显示正常

## 第 2 步 · `tasks.json`：将 CMake 的两个步骤串联起来

CMake 需要**先配置再编译**，是两个命令。使用 `dependsOn` 与 `dependsOrder: "sequence"` 串联为一个任务：

- [ ] 一个「配置」任务（`cmake --preset xxx`）
- [ ] 一个「编译」任务（`cmake --build --preset xxx`）
- [ ] 一个组合任务，`dependsOrder: "sequence"`，`dependsOn` 上述两个任务

这样 `launch.json` 中只需要引用**一个**名称。

> **说明**：在 CMake 任务的 `options.env.PATH` 中加入 `<CMake>\bin`，
> 可以避免「刚安装完 CMake 但尚未重启 VS Code」所导致的问题。

- [ ] 组合任务能通过 `Tasks: Run Task` 手动运行成功

---

## 第 3 步 · `launch.json`

- [ ] GDB 路线：`type: cppdbg`，`program` 指向 `build/mingw/bin/app.exe`
- [ ] VS2022 路线：`type: cppvsdbg`，`program` 指向 `build/msvc/bin/Debug/app.exe`
- [ ] `preLaunchTask` 指向第 2 步的**组合任务名**

### 易错点：产物路径不同

```
Ninja（单配置）        → build/mingw/bin/app.exe
Visual Studio（多配置） → build/msvc/bin/Debug/app.exe
                                             ↑ 多出来的这层是生成器自动加的
```

若遗漏 `Debug/`，将出现「找不到 exe」的错误。

- [ ] 两个 `program` 路径均编写正确

## 第 4 步 · 验证

- [ ] 在 `src/util.c` 的 `int result = x * x;` 处设置断点
- [ ] 按 F5 选择 GDB 路线，应停在断点处
- [ ] 在 `src/main.c` 的 `square(i)` 所在行设置断点，按 **F11**，执行点将**跳转到 `util.c`**
      （这是多文件调试的核心体验）
- [ ] 在 `factorial(6)` 所在行反复按 F11 进入，观察「调用堆栈」逐层增高
- [ ] 切换到 VS2022 路线，重复上述验证

## 第 5 步（选做）· 使用 CMake Tools 扩展的图形界面

- [ ] 在命令面板中执行 `CMake: Select Configure Preset`，并选择一个预设
- [ ] 在命令面板中执行 `CMake: Configure`
- [ ] 状态栏出现「构建」按钮

> **说明**：另有更为简便的方式。在状态栏点击 **Set Launch/Debug Target** 选择目标，
> 再点击 **Debug**，CMake Tools 会**自动生成调试配置，无需编写 `launch.json`**。
> 如需自定义，可将 `cmake.debugConfig` 写入 `settings.json`。
