# 配置步骤 · 空模板 08（模板与泛型）

本模板是**分阶段的整体演练**：成品是一个小型的泛型库——一个算法头文件、
一个定长栈的类模板，外加一个显式实例化单元，由命令行程序 `app_cli.exe` 驱动。
本模板是纯命令行工程，没有界面版。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../README.md`](../README.md)，本文件不重复。

---

## 成品形态

做完 4 个阶段之后，这套泛型库具备：

| 能力 | 由哪一阶段提供 |
|---|---|
| `max_of` 对任意可比较类型求较大者，实参类型由编译器推导 | 阶段 1 |
| `sum_of` 用非类型模板参数接收任意长度的数组 | 阶段 1 |
| `max_of` 对 `const char *` 有专门实现，按字典序而不是按地址比较 | 阶段 2 |
| `Stack<T, N>` 定长栈：入栈、出栈、取栈顶、判空、取大小、容量 | 阶段 3 |
| 成员模板 `push_all` 把另一种类型的数组压进栈 | 阶段 3 |
| 显式实例化：把常用类型组合的代码提前生成好 | 阶段 4 |

## 阶段 1 · 函数模板与非类型模板参数

**要做什么**（在 `include/algo.hpp`）

- 1-1 `max_of` 主模板：返回较大者
- 1-2 `sum_of`：用非类型模板参数 `N` 接收数组长度并求和

**验收标准**

`Text`

```text
=== 阶段 1：函数模板 ===
  max_of(3, 5)         = 5
  max_of(2.5, 1.5)     = 2.5
  max_of<double>(3, 5) = 5
  sum_of(values)       = 15
  count_of(values)     = 5
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `max_of(3, 5) = 3` | 主模板还是占位版本 |
| `sum_of(values) = 0` | 求和循环没写，或者初值写成了 `0` 而不是 `T{}`（对 `double` 数组会丢小数） |
| 编译报 `no matching function for call to 'max_of(int, double)'` | 这是**预期现象**：两个实参类型不同，`T` 推导不出来。解决办法是显式指定 `max_of<double>(3, 5.0)`，或先把其中一个转成相同类型 |
| `max_of<double>(3, 5)` 打印 `5` | 正确。两个 `int` 被转成 `double` 后走同一份模板代码 |

## 阶段 2 · 函数模板的全特化

**要做什么**

- 2-1 在 `include/algo.hpp` 里为 `max_of` 写一份针对 `const char *` 的全特化，用 `std::strcmp` 比较

**验收标准**

`Text`

```text
=== 阶段 2：全特化 ===
  max_of(a, b)                     = cd
  max_of<const char *>(a, b)       = cd
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 两行都是 `ab`（或其他非 `cd` 的值） | 全特化还没写，主模板在比较两个指针的地址。地址大小与字面量在内存里的排布有关，因此骨架这一行的结果不保证是哪一个 |
| 编译报 `error: template-id 'max_of<const char*>' for 'const char* max_of(const char*, const char*)' does not match any template declaration` | 返回类型或参数类型与主模板不一致。主模板是 `T max_of(T, T)`，`T` 填成 `const char *` 之后就是 `const char *max_of(const char *, const char *)`，必须逐字对上 |
| 编译报 `specialization of 'max_of' after instantiation` | 特化写在了某个用到它的函数后面。全特化必须写在第一次使用之前，本模板里就是写在头文件的主模板之后 |

**选做实验（本章节第 6.1 小节的现象）**：在头文件里再加一个**非模板**重载

`C++`

```cpp
const char *max_of(const char *a, const char *b)   /* 非模板：重载决议里排在模板之前 */
{
    std::printf("  走非模板重载：");
    return std::strcmp(a, b) > 0 ? a : b;
}
```

加上之后重新运行，`max_of(a, b)` 会走非模板那一份并打印标记，而
`max_of<const char *>(a, b)` 仍然走全特化。实验完把这段删掉。

## 阶段 3 · 类模板与成员模板

**要做什么**（在 `include/stack.hpp`）

- 3-1 `push`：满则返回 `false`
- 3-2 `pop`：空则返回 `false`
- 3-3 `top`：空则抛 `std::out_of_range`
- 3-4 成员模板 `push_all`：把另一种类型的数组压进栈
- 3-5 `size` 与 `empty`

**验收标准**

`Text`

```text
=== 阶段 3：类模板 Stack ===
  压入 1 2 3 后 size = 3，capacity = 8
  top = 3
  弹出顺序： 3 2 1
  空栈再 pop：false
  容量 3 的栈压第 4 个：false
  push_all 压入 3 个，size = 3
  字符串栈：size = 2, top = beta
  空栈取 top：捕获到 std::out_of_range
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `size = 0` | `push` 里忘了让 `size_` 自增，或者根本没写入 `items_` |
| `top = 0` 或 `top =`（空） | `top` 还是占位版本，应当返回 `items_[size_ - 1]` |
| 弹出顺序是 `1 2 3` | 出栈取的是 `items_[0]`，那是队列不是栈 |
| `空栈再 pop：true` | `pop` 没有判空 |
| `容量 3 的栈压第 4 个：true` | `push` 没有判满，此时会写到数组外面（越界写） |
| `空栈取 top：没有抛异常` | `top` 没有判空，或者抛的不是 `std::out_of_range` |

## 阶段 4 · 显式实例化

**要做什么**

- 4-1 在 `src/instantiations.cpp` 里为 `Stack<std::string, 4>` 补一行显式实例化

**验收标准**

- 程序仍能编过、能运行，输出与阶段 3 完全一致（显式实例化不改变行为）
- 文件里出现两行显式实例化

`Text`

```text
template class Stack<int, 8>;
template class Stack<std::string, 4>;
```

**怎么自查**

| 现象 | 说明 |
|---|---|
| 编译报 `explicit instantiation of 'Stack<...>' that does not name a defined type` | 头文件没包含进来，或类型写错了 |
| 链接报 `undefined reference to 'bool Stack<int, 8ul>::push(int const&)'` | 你把 `Stack::push` 的**定义**从头文件挪进了 `.cpp`。模板的定义必须能被调用点看到，这正是本阶段要验证的一条 |
| 程序输出与阶段 3 不同 | 显式实例化只影响代码生成，不该改变行为，检查是不是同时改动了别的代码 |

> [!IMPORTANT]
> 模板的声明与定义要放在同一个头文件里，因为编译器在**看到调用点**时才知道用什么类型
> 实例化。显式实例化不能替代这一点：它只让某几个类型组合提前生成代码，
> 定义本身仍然必须在头文件里可见。
