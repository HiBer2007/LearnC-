# 配置步骤 · 空模板 05（`const` 与初始化）

本模板是**分阶段的整体演练**：成品是一个「单位换算小工具」（单文件、命令行版，没有界面版），分 4 个阶段做完，
每个阶段结束时程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../README.md`](../README.md)，本文件不重复。

---

## 成品形态

做完这 4 个阶段之后，`unit_tool.exe` 具备下面这些能力：

| 能力 | 由哪一阶段提供 |
|---|---|
| 打印内置的换算表（7 个单位，含相对基准单位的倍数） | 阶段 1 |
| 按名字查找单位，找不到时返回空结果 | 阶段 2 |
| 在两个单位之间换算并控制小数位 | 阶段 2、阶段 3 |
| 用一个类把「名字 + 倍数 + 打印精度」封装起来，并能统计存活对象数 | 阶段 3 |
| 换算常量在编译期就算出来，并在编译期做断言 | 阶段 4 |

## 阶段 1 · 换算表（`const` 与 `constexpr` 常量）

**要做什么**

- 1-1 把 `kUnitCount` 写成正确的常量表达式（表里有几个单位）
- 1-2 实现 `print_table`，按 `  名字   x 倍数` 的格式逐行打印

**验收标准**

- 表头打印出 `count = 7`
- 表格部分逐行打印 7 个单位，对齐整齐，倍数用 `%g` 的形式

**怎么自查**

`Text`

```text
count = 7
  mm     x 0.001
  cm     x 0.01
  m      x 1
  km     x 1000
  inch   x 0.0254
  ft     x 0.3048
  mile   x 1609.34
```

| 你看到的 | 说明 |
|---|---|
| `count = 28` 或别的整数 | 你写成了 `sizeof(kUnits)`，得到的是整个数组的字节数，还要除以 `sizeof(kUnits[0])` |
| 表格只有几行或一行都没有 | 循环的上界写成了常数，或者循环变量类型写成了 `int` 与 `std::size_t` 比较时出现符号问题 |
| 把 `print_table` 的形参改成 `Unit *units` 后编译失败 | 这是预期现象：`kUnits` 是 `constexpr` 对象，本身隐含 `const`，不能交给「可写」的指针。试完改回来 |

## 阶段 2 · 查找与换算（`const` 在指针与引用上）

**要做什么**

- 2-1 实现 `find_unit`：按名字查找，找不到返回 `nullptr`（记得在文件顶部补 `#include <cstring>`）
- 2-2 实现 `convert`：两个形参都用 `const Unit &`

**验收标准**

- `find km` 与 `find mile` 打印出名字，`find kg` 打印 `(nullptr)`
- `3 km = 1.86411 mile`（保留 5 位小数）
- `3 km = 3000.0 m`

**怎么自查**

`Text`

```text
=== 阶段 2：查找与换算 ===
  find km   -> km
  find mile -> mile
  find kg   -> (nullptr)
  3 km = 1.86411 mile
  3 km = 3000.0 m
```

| 你看到的 | 说明 |
|---|---|
| 三行全是 `(nullptr)` | 比较字符串用了 `==`。C 与 C++ 里比较的是指针，不是内容，要用 `std::strcmp` |
| `find kg` 也打印出名字 | 循环缺少「找不到返回 `nullptr`」，或者返回了最后一个元素 |
| `3 km = 1.86411 m` 一类的数量级错误 | 乘除方向反了，检查 `v * from.factor / to.factor` |
| 把 `convert` 的形参改成 `Unit &` 后编译失败 | 这是预期现象：`constexpr` 表的元素是 `const` 对象，绑不到非 `const` 引用上。试完改回来 |

## 阶段 3 · `Converter` 类（初始化列表、类内初始化、`const` 成员函数）

**要做什么**

- 3-1 用成员初始化列表初始化 `name_` 与 `factor_`
- 3-2 让 `alive_` 在析构函数里自减
- 3-3 实现 `to_base`
- 3-4 用类内初始化把 `precision_` 的默认值改成 3

**验收标准**

- `name = mile, factor = 1609.34`
- `1 mile = 1609.344 base`（三位小数）
- 作用域内 `alive = 1`，出作用域后 `alive = 0`

**怎么自查**

`Text`

```text
=== 阶段 3：Converter 类 ===
  name = mile, factor = 1609.34
  1 mile = 1609.344 base
  alive = 1
  alive = 0
```

| 你看到的 | 说明 |
|---|---|
| `name = ?` | 构造函数体里没有赋值，初始化列表也没写 |
| `1 mile = 1609 base` | `precision_` 还是类内初始化的 0，没有改成 3 |
| 两行 `alive` 都是 0 | 构造函数里漏了自增（骨架已给出）或析构函数里漏了自减 |
| 编译出现 `will be initialized after` 警告 | 初始化列表里的书写顺序与成员声明顺序相反。成员的初始化顺序**只看声明顺序**，列表顺序不影响，改成同序即可消除警告 |

实验：把构造函数里的初始化列表删掉，只留函数体，观察 `name = ?`、`factor = 0`——
这说明「初始化」与「赋值」是两件事，见《04-语法/05-初始化.md》第 1 节。

## 阶段 4 · 编译期求值（`constexpr`、`static_assert`、`if constexpr`）

**要做什么**

- 4-1 把 `to_base_ct` 声明成 `constexpr`
- 4-2 把文件里那两行 `static_assert` 取消注释
- 4-3（进阶）用 `if constexpr` 让整数与浮点走不同分支

**验收标准**

- 取消注释后仍能编译通过（条件成立）
- `to_base_ct(1.0, 1000.0) = 1000`
- `print_number(5)` 打印 `5`，`print_number(1.5)` 打印 `1.500`

**怎么自查**

`Text`

```text
=== 阶段 4：编译期求值 ===
  to_base_ct(1.0, 1000.0) = 1000
  5
  1.500
```

| 你看到的 | 说明 |
|---|---|
| `error: non-constant condition for static assertion` | `to_base_ct` 还没加 `constexpr`，或 `kUnitCount` 还不是常量表达式 |
| `static assertion failed: 换算表应当有 7 个单位` | 阶段 1-1 没做对，回到阶段 1 |
| 第二行是 `1.5` 而不是 `1.500` | 阶段 4-3 的分支没写：现在两个类型都走同一个 `%g` 分支 |
