**这个问题有两种答案，取决于变量在哪**——

# 第 1 节 初始化不是赋值

## 1.1 两者的区别

**这两句话看着像，做的却是两件事。**

`C`

```c
int a = 5;      /* 初始化：a 从「没有值」变成 5 */
int b;          /* b 此时还没有值 */
b = 5;          /* 赋值：把 5 写进已经存在的 b */
```

| | 初始化 | 赋值 |
|---|---|---|
| 什么时候发生 | 变量**诞生**时 | 变量**已经存在**之后 |
| 之前那块内存 | 没有意义 | 有旧值 |
| 能不能被跳过 | **不能**——每个变量诞生时都要处理 | 可以，想赋几次赋几次 |
| 有没有「先清空」 | 直接写成目标值 | 覆盖旧值 |

**关键差别在最后一行**：**赋值要先把旧值读出来（或至少覆盖掉），初始化不用。**

## 1.2 为什么这个区别重要

**三条后果。**

**第一，`const` 只能靠初始化。**

`C`

```c
const int a = 5;        /* 合法：初始化时给值 */
const int b;            /* C 里合法但没用；C++ 里直接编译失败 */
b = 5;                  /* 不合法：const 不能赋值 */
```

**第二，有些类型没有默认状态，必须初始化。**
引用就是这样：它必须绑定到一个已有对象，**没有「空引用」这回事**
（见《04-语法/08-数组、指针与引用.md》第 3.2 小节）。

**第三，赋值的开销可能更大。**
对一个类对象来说，赋值意味着「先构造一个空对象，再把它覆盖掉」，
而初始化可以直接构造出目标状态。

> [!IMPORTANT]
> **初始化发生在变量诞生时，赋值发生在变量已存在之后。**
> 一条声明里带 `=`，**大多数情况下是初始化，不是赋值**——
> 尽管它长得像赋值。

**「大多数情况下」这个限定有原因**：C++ 里有一种写法确实是「先默认构造、再赋值」。
它属于进阶内容，本章不展开。

# 第 2 节 四种写法

## 2.1 一览

**同一个值，有四种写法。**

`C++`

```cpp
// four_forms.cpp    编译：g++ -std=c++17 four_forms.cpp -o four_forms
#include <cstdio>

struct Point { int x; int y; };

int main() {
    int a = 5;              // ① 复制初始化
    int b(5);               // ② 直接初始化
    int c{5};               // ③ 列表初始化
    int d = {5};            // ④ 复制列表初始化

    Point p1 = {1, 2};      // 聚合：复制列表初始化
    Point p2{1, 2};         // 聚合：列表初始化

    std::printf("%d %d %d %d\n", a, b, c, d);   // 5 5 5 5
    std::printf("%d %d / %d %d\n", p1.x, p1.y, p2.x, p2.y);
    return 0;
}
```

**四者对 `int` 的效果完全一样。** 区别在**编译器检查的严格程度**上，
下一节会看到。

## 2.2 三种写法怎么读

**上表的四种写法归成三类**：

| 写法 | 读作 | 特点 |
|---|---|---|
| `T a = v;` | 「a **等于** v」 | 最宽松，窄化不报错 |
| `T a(v);` | 「用 v **构造** a」 | 宽松，但受「最令人烦恼的解析」影响 |
| `T a{v};` | 「a 由 v **组成**」 | **最严格**，窄化报错 |

**第四种 `T a = {v};` 是「等于」与「组成」的合写**，
检查的严格程度与第三种相同。

**三类写法里只有两类用括号**——圆括号与花括号。
第一种用的是等号，它是复制初始化的写法，与括号无关。

**圆括号的麻烦在于它同时是函数调用的符号**：

`C++`

```cpp
// vexing.cpp
int a();            // 这不是「把 a 初始化成空」，
                    // 而是「声明一个返回 int 的函数 a」
```

上面这行单独写在函数体里，链接时会报
`undefined reference to 'a()'`——因为编译器把它当成了函数声明。

> [!WARNING]
> **`T a();` 声明的是函数，不是变量。**
> 想要「初始化为默认值」，写 `T a{};` 或 `T a = T();`。

**这是「最令人烦恼的解析」的雏形**：C++ 里凡是能用两种方式解释的写法，
编译器优先当声明。

## 2.3 C 与 C++ 的分界：不带 `=` 的大括号

**这是本章最容易出错混淆的一处。**

`C`

```c
/* c_braces.c    编译：gcc -std=c23 c_braces.c -o c_braces */
int a = { 5 };      /* 合法：带等号 */
int b = { };        /* 合法：空大括号，等价于 int b = 0 */
int c { 5 };        /* 编译失败：C 没有这种写法 */
```

`实测数据`
`Text`

```text
int a = {};        C23 通过，输出 0
int a{};           C23 失败：expected '=', ',', ';', 'asm' or '__attribute__' before '{' token
int a{0};          C23 失败（同一处报错）
int a[3]{1,2};     C23 失败（同一处报错）
struct S s{};      C23 失败（同一处报错）
```

> [!IMPORTANT]
> **C 里的大括号初始化必须带 `=`。**
> `int a{};`、`int a{0};`、`struct S s{1};` 这些**全是 C++ 独有的写法**，
> C 编译器会报语法错误。

**同一批写法在 C++17 下全部通过**，包括 `int a[]{};`、`int a[3]{1,2};`。

# 第 3 节 大括号拦住了什么

## 3.1 窄化

**窄化**指把一个宽类型的值塞进窄类型，可能丢掉信息。

`C++`

```cpp
// narrow.cpp    编译：g++ -std=c++17 narrow.cpp -o narrow
#include <cstdio>

int main() {
    int a = 3.7;        // 圆括号/等号：允许，a 变成 3
    std::printf("%d\n", a);

    int b(3.7);         // 直接初始化：也允许
    std::printf("%d\n", b);

    // int c{3.7};      // 列表初始化：编译失败
    return 0;
}
```

**去掉注释后编译器给出的原文**：

`实测数据`
`Text`

```text
narrow.cpp:11:19: error: narrowing conversion of '3.7000000000000002e+0'
                  from 'double' to 'int' [-Wnarrowing]
```

**注意报错里的数字**：编译器把它展开成了 `3.7000000000000002e+0`，
因为它要强调「这不是 3.7，而是 3.7 在 `double` 里最接近的那个值」。

## 3.2 哪些算窄化

`实测数据`

| 写法 | C23 | C++17 |
|---|---|---|
| `int a = 3.7;` | 通过 | 通过 |
| `int a = 5000000000LL;` | 通过 | 通过 |
| `char c = 300;` | 通过 | 通过 |
| `int a{3.7};` | **语法错误** | **窄化错误** |
| `int a{5000000000LL};` | **语法错误** | **窄化错误** |
| `char c{300};` | **语法错误** | **窄化错误** |
| `double d{1};` | **语法错误** | **通过**（加宽不算窄化） |

**C 那一列的「语法错误」不是因为它拦窄化**，而是因为 C 根本没有这种写法。

> [!TIP]
> **C++ 里优先用 `{}` 初始化。**
> 它把「我不小心丢精度了」这类错误从运行期提到了编译期，
> 而写成 `=` 或 `()` 时编译器不会提醒。

**C 没有这层保护**，因此 C 代码里 `char c = 300;` 这类写法要自己留神
（越界后的行为见《04-语法/02-数据类型与类型系统.md》第 2.6 小节）。

# 第 4 节 不初始化会怎样

## 4.1 全局与静态：自动清零

`C`

```c
/* zeroed.c    编译：gcc -std=c23 zeroed.c -o zeroed */
#include <stdio.h>

int g;                  /* 全局，未显式初始化 */
static int s;           /* 静态，未显式初始化 */

int main(void) {
    int loc;            /* 局部，未初始化 */
    printf("全局 g = %d, 静态 s = %d\n", g, s);
    printf("局部 loc = %d\n", loc);      /* 读它是未定义行为 */
    return 0;
}
```

`实测数据`
`Text`

```text
全局 g = 0, 静态 s = 0
局部 loc = 32759
```

**全局与静态变量被自动清零**，这一条标准有保证：
它们在程序启动前由运行环境统一填 0。

## 4.2 局部：不确定的值

**局部变量不会被清零。** 它落在栈上，而栈是复用的。

`C`

```c
/* uninit.c    编译：gcc -std=c23 -O0 uninit.c -o uninit */
#include <stdio.h>

int main(void) {
    int a;              /* 未初始化 */
    int b[4];           /* 数组未初始化 */
    printf("%d %d %d %d %d\n", a, b[0], b[1], b[2], b[3]);
    return 0;
}
```

**同一份程序连跑三次，输出完全相同**：

`实测数据`
`Text`

```text
第 1 次: 32758 -1409232832 32758 -1409232824 32758
第 2 次: 32758 -1409232832 32758 -1409232824 32758
第 3 次: 32758 -1409232832 32758 -1409232824 32758
```

> [!CAUTION]
> **「三次结果一样」不等于「值是确定的」。**
> 它只是说明这三次的栈布局恰好相同——那是上一个函数留下的残留数据。
> **换一台机器、换一个编译选项、在前后多写几行代码，值就会变。**
> 读未初始化的变量是未定义行为，标准对它不作任何保证。

**这正是未初始化变量难查的原因**：它常常「看起来能用」，
直到某次改动之后突然变了。

## 4.3 为什么局部变量不清零

**因为清零要花时间，而大部分局部变量马上就会被写入。**

`Text`

```
   全局变量    在程序启动时清一次，只花一次时间   → 清零划算
   局部变量    每次进函数都要清，而多数马上被覆盖 → 清零不划算
```

**这是「性能优先」的选择**，代价是把责任交给了写代码的人。

> [!TIP]
> **养成习惯：声明时就给初值。**
> `int a = 0;` 与 `int a;` 的成本差别在编译后通常为零
> （编译器会把 `int a = 0;` 优化成同样高效的代码），
> 但前者不会让你在半夜查一个「有时对有时错」的 bug。

# 第 5 节 聚合初始化

## 5.1 部分初始化时，剩下的填什么

**数组与结构体可以只给一部分值，其余部分按规则补齐。**

`C`

```c
/* partial.c    编译：gcc -std=c23 partial.c -o partial */
#include <stdio.h>

int main(void) {
    int a[5] = { 1, 2 };        /* 只给前两个 */
    int b[5] = { 0 };           /* 常见的清零写法 */
    int c[5] = { [3] = 9 };     /* 指定下标 */
    printf("a: %d %d %d %d %d\n", a[0], a[1], a[2], a[3], a[4]);
    printf("b: %d %d %d %d %d\n", b[0], b[1], b[2], b[3], b[4]);
    printf("c: %d %d %d %d %d\n", c[0], c[1], c[2], c[3], c[4]);
    return 0;
}
```

`实测数据`
`Text`

```text
a: 1 2 0 0 0
b: 0 0 0 0 0
c: 0 0 0 9 0
```

**只要写了 `=` 加大括号，没提到的成员一律补 0。**

> [!IMPORTANT]
> **`int a[5] = { 0 };` 是「全部清零」的惯用写法。**
> 它只显式给了第一个元素，其余四个由规则补 0。
> **写成 `int a[5] = { 1 };` 只会得到 `1 0 0 0 0`，不是全部为 1。**

## 5.2 指定初始化器

**可以按名字给结构体成员赋值，不必按顺序。**

`实测数据`
`C`

```c
/* designated.c    编译：gcc -std=c23 designated.c -o designated */
#include <stdio.h>

struct S { int a; int b; int c; };

int main(void) {
    struct S s = { .b = 2, .a = 1 };    /* 乱序，且省略 c */
    printf("a=%d b=%d c=%d\n", s.a, s.b, s.c);
    return 0;
}
```

**输出是 `a=1 b=2 c=0`**：乱序可以，省略的补 0。

**C++ 的情况不同**：

`实测数据`

| 写法 | C23 | C++17 | C++20 |
|---|---|---|---|
| `{ .a = 1, .b = 2 }`（顺序正确） | 通过 | 通过 | 通过 |
| `{ .b = 2, .a = 1 }`（**乱序**） | **通过** | **失败** | **失败** |
| `{ .a = 1, .c = 3 }`（跳过中间） | 通过 | 通过 | 通过 |
| `{ .p = { .x = 1 } }`（嵌套） | 通过 | 通过 | 通过 |

**C++ 的报错原文**：

`Text`

```text
error: designator order for field 'S::a' does not match declaration order in 'S'
```

> [!WARNING]
> **C++ 的指定初始化器必须按声明顺序写，不能乱序。**
> 这一点与 C 不同——**C 允许乱序，C++ 不允许**。
> 从 C 转过来的代码里若用了乱序的指定初始化器，编译会直接失败。

**还有一个容易误判的地方**：g++ 在 `-std=c++17` 下**默认接受**指定初始化器，
不报错也不警告。但加上 `-pedantic` 就会警告：

`实测数据`
`Text`

```text
-std=c++17                      通过（无警告）
-std=c++17 -pedantic            warning: C++ designated initializers only available
                                with '-std=c++20' or '-std=gnu++20'
-std=c++17 -pedantic-errors     编译失败
-std=c++20                      通过
-std=c++20 -pedantic-errors     通过
```

**也就是说**：指定初始化器在 C++ 里**到 C++20 才进标准**，
C++17 下能用是编译器的扩展。**本教材的基准是 C++17**，
因此正文里遇到它时会注明。

# 第 6 节 动态分配的内存

**`malloc` 拿到的那块内存也不会被清零。**

`实测数据`
`C`

```c
/* malloc_init.c    编译：gcc -std=c23 malloc_init.c -o malloc_init */
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *p = malloc(4 * sizeof(int));       /* 只分配，不清零 */
    if (!p) return 1;

    /* 此时 p[0..3] 是垃圾值，读它们是未定义行为 */

    int *q = calloc(4, sizeof(int));        /* 分配并清零 */
    if (!q) { free(p); return 1; }

    printf("calloc 之后: %d %d %d %d\n", q[0], q[1], q[2], q[3]);
    free(p);
    free(q);
    return 0;
}
```

**输出是 `calloc 之后: 0 0 0 0`。**

**两个函数的区别就在这一步**：

| 函数 | 分配 | 清零 |
|---|---|---|
| `malloc` | 是 | **否** |
| `calloc` | 是 | **是** |

> [!CAUTION]
> **`malloc` 返回的内存里是上一个使用者留下的数据。**
> 直接读它不仅是未定义行为，还可能读到别人的敏感信息——
> 这是真实的安全漏洞来源之一。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 初始化 | Initialization | 变量诞生时获得初值 |
| 赋值 | Assignment | 给已存在的变量写入新值 |
| 复制初始化 | Copy-initialization | 用 `=` 的初始化 |
| 直接初始化 | Direct-initialization | 用 `()` 的初始化 |
| 列表初始化 | List-initialization | 用 `{}` 的初始化 |
| 窄化 | Narrowing | 宽类型转窄类型时可能丢信息 |
| 聚合 | Aggregate | 数组、或没有自定义构造与私有成员的结构体 |
| 指定初始化器 | Designated initializer | 用 `.成员名 = 值` 指定初始化哪个成员 |
| 值初始化 | Value-initialization | 用 `{}` 或 `T()` 把对象置为「零状态」 |
