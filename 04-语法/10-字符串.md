**C 与 C++ 里都没有「字符串」这个类型。**

**字符串是一个约定**：一串字符，最后跟一个值为 0 的字节。
**这个约定有个固定名字，叫「C 风格字符串」（第 1.2 小节）。**
**所有的字符串函数都靠这个 0 来判断「到哪结束」。**

**理解了这一点，`strlen` 为什么不算结尾、`strcpy` 为什么会越界，
都不用背。**

# 第 1 节 字符串是一个约定

## 1.1 结尾的 0

`C`

```c
/* str_basic.c    编译：gcc -std=c23 str_basic.c -o str_basic */
#include <stdio.h>
#include <string.h>

int main(void) {
    char s[] = "abc";

    printf("sizeof(s) = %zu   （含结尾的 0）\n", sizeof(s));
    printf("strlen(s) = %zu   （不含结尾的 0）\n", strlen(s));
    printf("sizeof(\"abc\") = %zu\n", sizeof("abc"));
    printf("s 的字节: %d %d %d %d\n", s[0], s[1], s[2], s[3]);
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(s) = 4   （含结尾的 0）
strlen(s) = 3   （不含结尾的 0）
sizeof("abc") = 4
s 的字节: 97 98 99 0
```

**`"abc"` 在内存里是四个字节**：

`Text`

```
   ┌────┬────┬────┬────┐
   │ 97 │ 98 │ 99 │  0 │     'a'  'b'  'c'  结尾
   └────┴────┴────┴────┘
     s[0] s[1] s[2] s[3]
```

> [!IMPORTANT]
> **`sizeof` 是「这块内存多大」，`strlen` 是「数到 0 之前有几个字符」。**
> 对字符串字面量来说，两者永远差 1——**差的就是那个结尾的 0**。

**为什么要这个 0**：函数拿到一个 `char *` 时，
**只知道起点，不知道长度**（见《04-语法/08-数组、指针与引用.md》第 2.5 小节）。
于是约定「遇到 0 就停」。

**代价是每个字符串函数都必须逐个字节扫描**——
`strlen` 不是「读一个长度字段」，而是真的数一遍。

## 1.2 这个约定叫「C 风格字符串」

**以 0 结尾的字符序列，在文档与别的语言里有一个固定名字：C 风格字符串**
（C-style string、C string，也叫 null-terminated string，
中文常说「以空字符结尾的字符串」）。

**这个名字指的是约定，不是类型。** 这一点最容易混：

`实测数据`

| 说法 | 对不对 |
|---|---|
| 「`char *` 就是字符串」 | **不准确**：`char *` 只是一个地址，它指向的东西是不是字符串，要看那里有没有结尾的 0 |
| 「`char[10]` 就是字符串」 | **不准确**：数组里可以放任意字节，只有内容以 0 结尾时它才是一个字符串 |
| 「C 风格字符串就是一段以 0 结尾的字符序列」 | 准确 |

**判断一个东西是不是 C 风格字符串，看的是内容，不是类型。**
**因此下面这种事随时会发生**：

`实测数据`
`C`

```c
/* no_terminator.c    编译：gcc -std=c23 -w no_terminator.c -o no_terminator */
#include <stdio.h>
#include <string.h>

int main(void) {
    char s[3] = {'a', 'b', 'c'};        /* 没有结尾的 0 */

    printf("sizeof(s) = %zu\n", sizeof(s));
    printf("把它当字符串用：%s\n", s);
    printf("strlen(s) = %zu\n", strlen(s));
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(s) = 3
把它当字符串用：abc 后面跟着一串乱码
strlen(s) = 9
```

**`strlen` 给出 9，而数组只有 3 字节**——它一路读到内存里碰巧出现的 0 才停下。
**这是未定义行为**，这次的 9 只是恰好如此，
与越界同源（见《04-语法/08-数组、指针与引用.md》第 5 节）。

**初始化时，那个 0 是编译器替你补的**：

`实测数据`
`C`

```c
/* terminator_matters.c    编译：gcc -std=c23 -w terminator_matters.c -o terminator_matters */
#include <stdio.h>
#include <string.h>

int main(void) {
    char a[] = "abc";               /* 编译器自动补结尾的 0 */
    char b[4] = "abc";              /* 显式给足空间，补 0 */
    char c[3] = "abc";              /* 空间刚好，没有位置放 0 */
    char d[8] = "abc";              /* 后面全是 0 */

    printf("a: sizeof=%zu strlen=%zu\n", sizeof(a), strlen(a));
    printf("b: sizeof=%zu strlen=%zu\n", sizeof(b), strlen(b));
    printf("c: sizeof=%zu strlen=%zu\n", sizeof(c), strlen(c));
    printf("d: sizeof=%zu strlen=%zu\n", sizeof(d), strlen(d));
    printf("d 的字节: %d %d %d %d %d %d %d %d\n",
           d[0], d[1], d[2], d[3], d[4], d[5], d[6], d[7]);
    return 0;
}
```

`实测数据`
`Text`

```text
a: sizeof=4 strlen=3
b: sizeof=4 strlen=3
c: sizeof=3 strlen=6     ← 这个 strlen 已经在读数组外面了
d: sizeof=8 strlen=3
d 的字节: 97 98 99 0 0 0 0 0
```

**`char c[3] = "abc";` 这一行，C 与 C++ 的处理不同**：

`实测数据`
`Text`

```text
C  ：通过，sizeof(c) = 3，结尾的 0 被丢掉
C++：error: initializer-string for 'char [3]' is too long
```

**C 允许「刚好装下、丢掉 0」，C++ 直接拒绝**——**C++ 的做法更安全**：
一个不带结尾 0 的字符数组，本来就不该被当成字符串用。

**别的语言用别的约定**，对照着看更清楚：

`实测数据`

| 约定 | 长度放在哪 | 取长度要花多久 |
|---|---|---|
| **C 风格**（C 与 C++ 沿用） | **末尾一个 0** | **O(n)**：要一路扫到 0 |
| Pascal 风格（早期 Pascal、部分 Delphi 字符串） | **开头一个字节** | O(1)：读第一个字节 |
| `std::string`（C++ 的库类型） | 对象里存着（见第 5 节） | O(1) |

**Pascal 风格可以手工造出来看**：

`实测数据`
`C`

```c
/* pascal_style.c    编译：gcc -std=c23 pascal_style.c -o pascal_style */
#include <stdio.h>

int main(void) {
    /* 第一个字节是长度，后面是内容，末尾再放一个 0 便于对照 */
    unsigned char p[5] = {3, 'a', 'b', 'c', 0};

    printf("按 Pascal 风格读：长度 = %u，内容 = %c%c%c\n", p[0], p[1], p[2], p[3]);
    printf("把内容那一段按 C 风格读：\"%s\"\n", p + 1);
    printf("整个数组按 C 风格读：\"%s\"\n", p);
    return 0;
}
```

`实测数据`
`Text`

```text
按 Pascal 风格读：长度 = 3，内容 = abc
把内容那一段按 C 风格读："abc"
整个数组按 C 风格读："abc"      ← 开头那个长度字节 0x03 不可打印，看着像空的
```

**同一个数组，两套约定读出来的东西完全不同。**
**约定不同，「按 C 风格读」的 `printf("%s")` 自然读不对。**

> [!IMPORTANT]
> **C 风格字符串是一套约定：内容以 0 结尾，长度靠扫到 0 才知道。**
> 它不是一种类型——`char *` 与 `char[]` 都可能承载它，也都可能不是它。
> **`strlen` 的 O(n)、忘记结尾 0 的越界、`strcpy` 的坑，都是这套约定的直接后果。**

## 1.3 中文字符串占几个字节

`C`

```c
/* zh_bytes.c    编译：gcc -std=c23 zh_bytes.c -o zh_bytes */
#include <stdio.h>
#include <string.h>

int main(void) {
    const char *s = "中文";
    printf("strlen = %zu\n", strlen(s));
    printf("sizeof = %zu\n", sizeof("中文"));
    printf("逐字节: ");
    for (size_t i = 0; i < strlen(s); i++) printf("%02X ", (unsigned char)s[i]);
    printf("\n");
    return 0;
}
```

`实测数据`
`Text`

```text
strlen = 6
sizeof = 7
逐字节: E4 B8 AD E6 96 87
```

**两个汉字占 6 个字节**，因为源码是 UTF-8 编码，一个汉字 3 字节。

> [!WARNING]
> **`strlen` 数的是字节，不是字符。**
> `strlen("中文")` 是 6，不是 2。
> **要数「多少个字」，得按编码规则解析**——
> 这属于字符编码问题，不属于语法。

**这也解释了为什么 `char s[10]` 装不下 4 个汉字**：
需要 12 字节，加结尾 0 是 13。

# 第 2 节 两种写法，两种命运

## 2.1 数组与指针

`C`

```c
/* arr_vs_ptr.c    编译：gcc -std=c23 arr_vs_ptr.c -o arr_vs_ptr */
#include <stdio.h>

int main(void) {
    char  arr[] = "abc";        /* 数组：字面量被复制进数组 */
    char *ptr   = "abc";        /* 指针：指向只读区里的字面量 */

    printf("sizeof(arr) = %zu   （数组，整块）\n", sizeof(arr));
    printf("sizeof(ptr) = %zu   （指针）\n", sizeof(ptr));

    arr[0] = 'X';               /* 合法：改的是自己的副本 */
    printf("改 arr 之后: %s\n", arr);

    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(arr) = 4   （数组，整块）
sizeof(ptr) = 8   （指针）
改 arr 之后: Xbc
```

**两种写法在内存里完全不同**：

`Text`

```
   char arr[] = "abc";           char *ptr = "abc";

   栈上（可读可写）               只读区        栈上
   ┌────┬────┬────┬────┐         ┌────┬────┬────┬────┐   ┌───────┐
   │ a  │ b  │ c  │ \0 │         │ a  │ b  │ c  │ \0 │ ← │  ptr  │
   └────┴────┴────┴────┘         └────┴────┴────┴────┘   └───────┘
     ↑ 数组自己有一份               ↑ 字面量在这里          ↑ 只是存了个地址
```

**`sizeof` 的差别就是证据**：4 是整块，8 是一个指针。

## 2.2 改字面量会崩溃

`C`

```c
/* modify_literal.c    编译：gcc -std=c23 modify_literal.c -o modify_literal */
#include <stdio.h>

int main(void) {
    char *ptr = "abc";
    ptr[0] = 'X';               /* 写只读内存 */
    printf("%s\n", ptr);
    return 0;
}
```

**编译通过且没有任何警告，运行时直接崩溃。**

`实测数据`
`Text`

```text
编译: 通过（无警告）
运行: 崩溃，退出码 3221225477（0xC0000005，访问冲突）
```

> [!CAUTION]
> **字符串字面量在只读区，改它是未定义行为。**
> 它可能崩溃，也可能「看起来改了」——
> 后者更糟，因为字面量可能被多个地方共用。
>
> **写 `char *p = "abc";` 时，本教材一律写成 `const char *p = "abc";`**——
> 加上 `const` 之后，任何试图修改的代码都会在编译期被拦住。

**正确写法**：

`C`

```c
const char *p = "abc";      /* 想改也改不了，编译器帮你拦住 */
char arr[] = "abc";         /* 确实需要改，用数组 */
```

# 第 3 节 常用函数与它们的坑

## 3.1 四个最常用的

| 函数 | 做什么 | 在哪 |
|---|---|---|
| `strlen(s)` | 数到 0 之前的字节数 | `<string.h>` |
| `strcpy(dst, src)` | 复制，**不检查 `dst` 够不够大** | `<string.h>` |
| `strncpy(dst, src, n)` | 最多复制 `n` 字节 | `<string.h>` |
| `strcmp(a, b)` | 比较内容，返回负数/0/正数 | `<string.h>` |

## 3.2 `strcpy` 越界：编译过，运行崩

`C`

```c
/* overflow.c    编译：gcc -std=c23 overflow.c -o overflow */
#include <stdio.h>
#include <string.h>

int main(void) {
    char buf[4];
    strcpy(buf, "这是一个很长的字符串");    /* 远超 4 字节 */
    printf("%s\n", buf);
    return 0;
}
```

**编译只有一个警告，运行时崩溃。**

`实测数据`
`Text`

```text
编译警告: '__builtin_memcpy' writing 31 bytes into a region of size 4
运行结果: 崩溃，退出码 3221225477（0xC0000005）
```

> [!CAUTION]
> **`strcpy` 不知道目标有多大，它只认源字符串的结尾 0。**
> 这是缓冲区溢出漏洞最常见的来源。
>
> **用 `strncpy` 或 `snprintf` 代替**，并且**记得自己补结尾 0**——
> `strncpy` 在源字符串比 `n` 长时**不会**补 0。

**更安全的做法**：

`C`

```c
char buf[4];
snprintf(buf, sizeof(buf), "%s", src);      /* 一定会补 0，且不越界 */
```

## 3.3 `==` 比的是地址

`C`

```c
/* str_cmp.c    编译：gcc -std=c23 str_cmp.c -o str_cmp */
#include <stdio.h>
#include <string.h>

int main(void) {
    char a[] = "abc";
    char b[] = "abc";
    const char *p = "abc";
    const char *q = "abc";

    printf("a == b           : %d   （比地址，两个不同数组）\n", a == b);
    printf("strcmp(a,b) == 0 : %d   （比内容）\n", strcmp(a, b) == 0);
    printf("p == q           : %d   （同一字面量，可能被合并）\n", p == q);
    return 0;
}
```

`实测数据`
`Text`

```text
a == b           : 0   （比地址，两个不同数组）
strcmp(a,b) == 0 : 1   （比内容）
p == q           : 1   （同一字面量，可能被合并）
```

> [!WARNING]
> **`a == b` 比的是两个地址，不是两串字符。**
> 第三行 `p == q` 得到 1，是因为编译器把相同的字面量合并了——
> **这是实现自由，不保证一定发生。**
> **比较字符串内容一律用 `strcmp`，不要用 `==`。**

**`strcmp` 的返回值不是「相不相等」**：

| 返回值 | 含义 |
|---|---|
| 负数 | `a` 排在 `b` 前面 |
| 0 | 相同 |
| 正数 | `a` 排在 `b` 后面 |

**所以判断相等要写 `strcmp(a, b) == 0`**，
不能写 `if (strcmp(a, b))`——那恰好是「不相等」的意思。

# 第 4 节 字符串数组

**两种常见结构，占的空间差很多。**

`C`

```c
/* str_table.c    编译：gcc -std=c23 str_table.c -o str_table */
#include <stdio.h>

int main(void) {
    char        arr[3][6] = { "one", "two", "three" };   /* 二维数组 */
    const char *ptr[3]    = { "one", "two", "three" };   /* 指针数组 */

    printf("sizeof(arr) = %zu   （3 行 × 6 字节）\n", sizeof(arr));
    printf("sizeof(ptr) = %zu   （3 个指针）\n", sizeof(ptr));
    for (int i = 0; i < 3; i++) printf("%s %s | ", arr[i], ptr[i]);
    printf("\n");
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(arr) = 18   （3 行 × 6 字节）
sizeof(ptr) = 24   （3 个指针）
one one | two two | three three |
```

**两者的区别**：

| | `char arr[3][6]` | `const char *ptr[3]` |
|---|---|---|
| 存什么 | **字符本身** | **地址** |
| 能不能改内容 | 能 | **不能**（字面量只读） |
| 每行长度 | **固定**，短的浪费 | 按实际长度 |
| 大小 | 行数 × 每行长度 | 指针数 × 指针宽度 |

> [!TIP]
> **字符串长度差不多、需要修改时用二维数组；
> 长度差很多、只读时用指针数组。**
> 上例里 `"one"` 与 `"three"` 长度差一倍，
> 二维数组写法让每行都占 6 字节，短的那个浪费了 3 字节。

# 第 5 节 C++ 的 `std::string`

**C++ 标准库提供了一个会自己管内存的字符串类型。**

`C++`

```cpp
// std_string.cpp    编译：g++ -std=c++17 std_string.cpp -o std_string
#include <cstdio>
#include <string>

int main() {
    std::string s = "abc";
    s += "def";                     // 自动扩容，不用管缓冲区多大
    std::printf("内容 = %s\n", s.c_str());
    std::printf("size() = %zu   （不含结尾 0）\n", s.size());
    std::printf("sizeof(s) = %zu （对象本身，不是字符数）\n", sizeof(s));
    return 0;
}
```

`实测数据`
`Text`

```text
内容 = abcdef
size() = 6   （不含结尾 0）
sizeof(s) = 32 （对象本身，不是字符数）
```

**`sizeof(s)` 是 32**——它不是一个 `char` 数组，
而是一个**对象**：内部通常有「指向堆内存的指针、长度、容量」三样东西
（本机实现占 32 字节）。

## 5.1 与 C 字符串的对照

| | C 字符串 | `std::string` |
|---|---|---|
| 是什么 | `char` 数组 + 结尾 0 的约定 | 一个类对象 |
| 长度 | `strlen` 每次数一遍 | `size()` 直接读字段 |
| 拼接 | `strcat`，要自己保证够大 | `+=`，自动扩容 |
| 比较 | `strcmp(a, b) == 0` | `a == b` |
| 内存 | 自己管 | 自己管（RAII） |
| 传给 C 函数 | 直接传 | `s.c_str()` |

> [!IMPORTANT]
> **`std::string` 把「缓冲区多大」这件事从写代码的人手里拿走了。**
> 这是它最大的价值——**C 字符串的绝大多数 bug 都出在长度上**。

**`c_str()` 返回一个 C 字符串**，用来传给只认 `const char *` 的函数。
**注意它返回的指针在 `string` 被修改或销毁后就失效了。**

## 5.2 什么时候用哪个

| 场合 | 用什么 |
|---|---|
| C 代码、嵌入式、需要精细控制内存 | **C 字符串** |
| C++ 里的一般字符串处理 | **`std::string`** |
| 与 C 库交互 | `std::string` + `c_str()` |

**本教材的 `06` 与 `07` 里演示指针与数组时用的是 C 字符串**，
因为那正是要讲清「结尾 0」与「退化」的地方。

> [!NOTE]
> **字符串的完整讲解（编码、宽字符、`std::string_view`、
> 正则与格式化）属于更后面的内容**，

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| C 风格字符串 | C-style string | **一套约定**：字符序列以值为 0 的字节结尾；它不是类型，`char *` 与 `char[]` 都可能承载它 |
| 结尾 0 | Null terminator | 那个值为 0 的字节 |
| 缓冲区溢出 | Buffer overflow | 写入超出目标容量的数据 |
| 字面量 | String literal | 源码里写死的 `"..."` |
| 只读区 | Read-only section | 字面量所在的内存段 |

# 附录 A 复现本章节实测

**环境**：`gcc` / `g++` 15.2.0（MinGW-w64），Windows x64。

## A.1 `sizeof` 与 `strlen`

`C`

```c
/* str_size.c */
#include <stdio.h>
#include <string.h>
int main(void) {
    char s[] = "abc";
    printf("sizeof=%zu strlen=%zu\n", sizeof(s), strlen(s));
    printf("字节: %d %d %d %d\n", s[0], s[1], s[2], s[3]);
    return 0;
}
```

`Bash`

```bash
gcc -std=c23 str_size.c -o s && ./s
# sizeof=4 strlen=3
# 字节: 97 98 99 0
```

## A.2 中文字符串的字节数

`C`

```c
/* zh.c */
#include <stdio.h>
#include <string.h>
int main(void) {
    const char *s = "中文";
    printf("%zu\n", strlen(s));
    for (size_t i = 0; i < strlen(s); i++) printf("%02X ", (unsigned char)s[i]);
    printf("\n");
    return 0;
}
```

`Bash`

```bash
gcc -std=c23 zh.c -o zh && ./zh
# 6
# E4 B8 AD E6 96 87
```

## A.7 C 风格字符串：没有结尾 0 会怎样

`C`

```c
/* no_terminator.c */
#include <stdio.h>
#include <string.h>

int main(void) {
    char s[3] = {'a', 'b', 'c'};        /* 没有结尾的 0 */

    printf("sizeof(s) = %zu\n", sizeof(s));
    printf("把它当字符串用：%s\n", s);
    printf("strlen(s) = %zu\n", strlen(s));
    return 0;
}
```

`C`

```c
/* terminator_matters.c */
#include <stdio.h>
#include <string.h>

int main(void) {
    char a[] = "abc";               /* 编译器自动补结尾的 0 */
    char b[4] = "abc";              /* 显式给足空间，补 0 */
    char c[3] = "abc";              /* 空间刚好，没有位置放 0 */
    char d[8] = "abc";              /* 后面全是 0 */

    printf("a: sizeof=%zu strlen=%zu\n", sizeof(a), strlen(a));
    printf("b: sizeof=%zu strlen=%zu\n", sizeof(b), strlen(b));
    printf("c: sizeof=%zu strlen=%zu\n", sizeof(c), strlen(c));
    printf("d: sizeof=%zu strlen=%zu\n", sizeof(d), strlen(d));
    printf("d 的字节: %d %d %d %d %d %d %d %d\n",
           d[0], d[1], d[2], d[3], d[4], d[5], d[6], d[7]);
    return 0;
}
```

`C`

```c
/* pascal_style.c */
#include <stdio.h>

int main(void) {
    unsigned char p[5] = {3, 'a', 'b', 'c', 0};

    printf("按 Pascal 风格读：长度 = %u，内容 = %c%c%c\n", p[0], p[1], p[2], p[3]);
    printf("把内容那一段按 C 风格读：\"%s\"\n", p + 1);
    printf("整个数组按 C 风格读：\"%s\"\n", p);
    return 0;
}
```

`C++`

```cpp
// tight.cpp    编译：g++ -std=c++17 tight.cpp （失败）
#include <cstdio>

int main() {
    char c[3] = "abc";      // 空间刚好：C++ 直接拒绝
    std::printf("sizeof(c) = %zu\n", sizeof(c));
    return 0;
}
```

`Bash`

```bash
gcc -std=c23 -w no_terminator.c      -o no_terminator      && ./no_terminator
gcc -std=c23 -w terminator_matters.c -o terminator_matters && ./terminator_matters
gcc -std=c23    pascal_style.c       -o pascal_style       && ./pascal_style
g++ -std=c++17  tight.cpp            -o tight              # 失败
```

**`no_terminator.c` 与 `terminator_matters.c` 里的 `strlen` 都在读数组外面**，
输出（`9` 与 `6`）只是这次运行恰好如此，属于未定义行为。
