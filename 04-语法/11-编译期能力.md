**有些事情不必等到程序跑起来才知道。**

**一个数是不是 4 字节、一个结构体的成员排在哪、
一段计算的结果是多少——这些在编译时就能确定。**

**把它们放到编译期做，好处有三个**：
**错误提前暴露**、**运行期少算一次**、**结果不进二进制**。

# 第 1 节 哪些东西在编译期就能确定

**先列出清单。**

| 东西 | 什么时候确定 |
|---|---|
| `sizeof(T)` | **编译期** |
| `offsetof(S, m)` | **编译期** |
| `constexpr` 变量 | **编译期** |
| 数组长度（常量表达式） | **编译期** |
| `static_assert` 的条件 | **编译期** |
| 模板参数 | **编译期** |
| 枚举值 | **编译期** |
| 字符串字面量的长度 | **编译期** |

**「编译期」意味着**：这个值在生成机器码之前就已知，
编译器可以直接把它填进去。

<small style="color:gray">cpp</small>

```cpp
// compile_time.cpp    编译：g++ -std=c++17 compile_time.cpp -o compile_time
#include <cstdio>
#include <cstddef>

struct S { char c; int i; };

int main() {
    std::printf("sizeof(S) = %zu\n", sizeof(S));
    std::printf("offsetof(S, i) = %zu\n", offsetof(S, i));

    int arr[sizeof(S)];         // 能当数组长度用，说明它是常量
    std::printf("sizeof(arr) = %zu\n", sizeof(arr));
    return 0;
}
```

**实测输出**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
sizeof(S) = 8
offsetof(S, i) = 4
sizeof(arr) = 32
```

**`int arr[sizeof(S)]` 这一行是关键**：数组长度必须是编译期常量，
能这么写就证明了 `sizeof` 不是运行期函数。

# 第 2 节 `const` 不等于「编译期常量」

## 2.1 一个常见的误解

**`const` 的意思是「不能改」，不是「编译期就知道」。**

<small style="color:gray">cpp</small>

```cpp
int get() { return 5; }

const int a = 5;            // 常量初始化 → 可以当常量表达式用
const int b = get();        // 运行期初始化 → 不是常量表达式
```

**实测**：

<small style="color:gray">实测数据</small>

| 写法 | 能否当数组长度 |
|---|---|
| `const int a = 5;` | **能** |
| `const int b = get();` | **不能**，报 `ISO C++ forbids variable length array` |

**两者都叫 `const`，但只有第一个是常量表达式。**

> [!IMPORTANT]
> **`const` 只保证「你不改它」，不保证「它的值在编译期已知」。**
> 一个用函数返回值初始化的 `const` 变量，
> 它的值要到运行期才知道——**它仍然是只读的，但不是常量**。

## 2.2 `constexpr` 补上了这个保证

**`constexpr` 的意思是「这确实是一个编译期常量」。**

<small style="color:gray">cpp</small>

```cpp
constexpr int n = 5;        // 编译器保证：值在编译期已知
```

**它的约束比 `const` 强**：

| | `const` | `constexpr` |
|---|---|---|
| 不能改 | 是 | 是 |
| 值必须在编译期已知 | **不一定** | **是** |
| 能否当数组长度 | 看初始化方式 | **一定能** |
| 能否当模板参数 | 看初始化方式 | **一定能** |

> [!TIP]
> **需要「编译期常量」时一律用 `constexpr`。**
> 它把「这是常量」这件事写进了类型系统，
> 编译器会替你检查，而不是等某个地方用不了才发现。

## 2.3 强行改 `const` 会怎样

**可以用强制转换绕过 `const`，但结果往往不是你想的那样。**

<small style="color:gray">cpp</small>

```cpp
// castaway.cpp    编译：g++ -std=c++17 castaway.cpp -o castaway
#include <cstdio>

int main() {
    const int n = 5;
    int *p = (int *)&n;         // 强行去掉 const
    *p = 6;
    std::printf("n = %d, *p = %d\n", n, *p);
    return 0;
}
```

**实测输出**：`n = 5, *p = 6`

**同一块内存，两种读法得到不同的值。**

**原因**：编译器知道 `n` 是 `const`，
凡是读到 `n` 的地方**直接把 5 填了进去**（这叫常量折叠），
根本没去内存里读。

> [!CAUTION]
> **修改 `const` 对象是未定义行为。**
> 上例里 `n` 打印出 5 不是「没改成功」，而是
> **编译器压根没打算去读那块内存**。
> 这个程序在别的编译器上可能打印 6，也可能崩溃。

# 第 3 节 `constexpr` 函数

## 3.1 它是什么

**一个「既能编译期算、也能运行期算」的函数。**

<small style="color:gray">cpp</small>

```cpp
// constexpr_fn.cpp    编译：g++ -std=c++17 constexpr_fn.cpp -o constexpr_fn
#include <cstdio>

constexpr int square(int x) { return x * x; }

int main() {
    constexpr int a = square(5);        // 编译期算
    int b = square(5);                  // 也可能在运行期算
    int arr[square(3)];                 // 数组长度必须是常量

    std::printf("a = %d, b = %d, sizeof(arr) = %zu\n", a, b, sizeof(arr));
    return 0;
}
```

**实测输出**：`a = 25, b = 25, sizeof(arr) = 36`

**`int arr[square(3)]` 能编过，说明 `square(3)` 在编译期就被算成了 9。**

## 3.2 它真的省掉了运行期的计算

**看汇编最直接。**

<small style="color:gray">cpp</small>

```cpp
// fold.cpp    编译：g++ -std=c++17 -O0 -S fold.cpp -o fold.s
int use_constexpr() {
    constexpr int n = 5;
    return n * n;
}
int use_variable() {
    int n = 5;
    return n * n;
}
```

**实测：两个函数的汇编**

<small style="color:gray">asm</small>

```asm
_Z13use_constexprv:              _Z12use_variablev:
    pushq   %rbp                     pushq   %rbp
    movq    %rsp, %rbp               movq    %rsp, %rbp
    subq    $16, %rsp                subq    $16, %rsp
    movl    $5, -4(%rbp)             movl    $5, -4(%rbp)
    movl    $25, %eax                movl    -4(%rbp), %eax
    addq    $16, %rsp                imull   %eax, %eax
    popq    %rbp                     addq    $16, %rsp
    ret                              popq    %rbp
                                     ret
```

**右边有一条 `imull`（乘法指令），左边没有。**

**左边直接把 25 填进了寄存器**——乘法在编译期就算完了。

> [!IMPORTANT]
> **`constexpr` 的计算不进入运行期。**
> 上例是在 `-O0`（不优化）下测的，
> 也就是说**这不是优化器的功劳，而是 `constexpr` 本身的效果**。

## 3.3 函数体里能写什么

**C++14 起放宽了很多。**

<small style="color:gray">实测数据</small>

| 函数体里用了什么 | C++17 |
|---|---|
| 直接返回常量 | 通过 |
| 局部变量 | **通过** |
| `if` | **通过** |
| `for` / `while` | **通过** |
| `static` 局部变量 | **失败**：`'x' defined 'static' in 'constexpr' function only available with -std=c++23` |
| `goto` | 失败 |
| 调用非 `constexpr` 函数 | 失败（除非该分支不在编译期求值时执行） |

**实测：`if`、`for`、局部变量都能用**，输出 `1 6 6`。

> [!NOTE]
> **C++11 时 `constexpr` 函数体只能有一条 `return` 语句**，
> 所以那时的写法要写成递归。**C++14 起放宽成普通函数体**，
> 本教材的基准 C++17 因此可以直接写循环。

# 第 4 节 `static_assert`

## 4.1 编译期断言

**如果条件不成立，编译直接失败。**

<small style="color:gray">cpp</small>

```cpp
// static_assert.cpp    编译：g++ -std=c++17 static_assert.cpp -o static_assert
#include <cstdio>

static_assert(sizeof(int) == 4, "int 不是 4 字节");

int main() {
    std::printf("int 是 %zu 字节\n", sizeof(int));
    return 0;
}
```

**条件成立时编译通过。把 `4` 改成 `8`，编译报错**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
error: static assertion failed: int 不是 4 字节
```

**C++17 起消息可以省略**：

<small style="color:gray">cpp</small>

```cpp
static_assert(sizeof(int) == 4);        // 不写消息也合法
```

## 4.2 C 里也有

**C11 起有了 `static_assert`**，但需要包含 `<assert.h>`。
**C23 起它成了关键字，不需要包含任何头文件**。

<small style="color:gray">实测数据</small>

| 写法 | C23 |
|---|---|
| `#include <assert.h>` 后用 `static_assert` | 通过 |
| **不包含任何头文件**直接用 | **通过** |

> [!TIP]
> **`static_assert` 是「把假设写进代码」的手段。**
> 比如「这个结构体必须是 8 字节」「这个类型必须是无符号的」——
> 写下来之后，换平台、换编译器时会立刻暴露，
> 而不是等到运行期发现数据不对。

## 4.3 它和 `assert` 的区别

| | `static_assert` | `assert` |
|---|---|---|
| 什么时候检查 | **编译期** | 运行期 |
| 失败会怎样 | **编译不过** | 程序中止 |
| 有没有运行期开销 | **没有** | 有（判断一次） |
| 能不能检查变量 | **不能**（只认常量表达式） | 能 |
| 发布版里还在吗 | 在 | 通常被 `NDEBUG` 去掉 |

> [!IMPORTANT]
> **凡是编译期能查的，就不要留到运行期。**
> `static_assert` 的检查是零成本的——它在生成的代码里
> 什么也不留。

# 第 5 节 `if constexpr`

**C++17 起，`if` 的条件可以是编译期常量。**

<small style="color:gray">cpp</small>

```cpp
// if_constexpr.cpp    编译：g++ -std=c++17 if_constexpr.cpp -o if_constexpr
#include <cstdio>

template <typename T>
void show(T v) {
    if constexpr (sizeof(T) <= 4) {
        std::printf("小类型，%zu 字节\n", sizeof(T));
    } else {
        std::printf("大类型，%zu 字节\n", sizeof(T));
    }
}

int main() {
    show(1);            // int，4 字节
    show(1.0);          // double，8 字节
    return 0;
}
```

**实测输出**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
小类型，4 字节
大类型，8 字节
```

## 5.1 它与普通 `if` 的区别

**普通 `if` 的两个分支都要能编过。`if constexpr` 只编被选中的那个。**

| | `if` | `if constexpr` |
|---|---|---|
| 条件 | 运行期值 | **编译期常量** |
| 两个分支 | **都要合法** | **只编选中的那个** |
| 没选中的分支 | 仍然生成代码 | **完全不生成** |
| 能不能写「只对某类型成立」的代码 | 不能 | **能** |

**这一点在模板里非常有用**：可以针对不同类型的参数写完全不同的实现，
而不要求所有实现都对所有类型成立。

> [!NOTE]
> **`if constexpr` 属于模板编程的入门工具**，
> 完整的模板讲解不在本章范围。
> 本章只说明「编译期的分支选择」这件事存在。

# 第 6 节 C 里的编译期手段

**C 没有 `constexpr`，也没有 `if constexpr`。**

**它能用的手段有限**：

| 手段 | 说明 |
|---|---|
| `sizeof`、`offsetof` | 编译期常量 |
| 枚举值 | 编译期常量 |
| `static_assert`（C11 起） | 编译期断言 |
| `#define` | 文本替换，见 `13-预处理器` |
| 数组长度 | 必须是常量表达式（C99 起可以是变量，即变长数组） |

**C 里想表达「编译期常量」，通常用宏或枚举**：

<small style="color:gray">c</small>

```c
#define MAX_LEN 128                 /* 宏：文本替换，没有类型 */
enum { MAX_LEN_E = 128 };           /* 枚举：有类型，可以调试 */
static const int MAX_LEN_C = 128;   /* const：是变量，不是常量表达式 */
```

> [!WARNING]
> **C 里的 `static const int` 不能当数组长度**——
> 它是只读变量，不是常量表达式。
> **想要编译期常量，用 `#define` 或 `enum`。**

**C23 里 `constexpr` 已经加入**（语法与 C++ 不同），
但它还太新，本教材的实测环境虽支持，正文暂不依赖它。

> [!TIP]
> **C 与 C++ 在这一块的差距是两种语言设计取向的体现**：
> C++ 把「编译期计算」做进了语言（模板、`constexpr`、`consteval`），
> C 则主要靠预处理器。
> 这一区别的讨论见《04-语法/02-数据类型与类型系统.md》第 7 节。

# 附录 A 复现本章节实测

**环境**：`gcc` / `g++` 15.2.0（MinGW-w64），Windows x64。

## A.1 `sizeof` 是编译期常量

<small style="color:gray">cpp</small>

```cpp
// compile_time.cpp
#include <cstdio>
#include <cstddef>
struct S { char c; int i; };
int main() {
    std::printf("%zu %zu\n", sizeof(S), offsetof(S, i));
    int arr[sizeof(S)];
    std::printf("%zu\n", sizeof(arr));
    return 0;
}
```

<small style="color:gray">bash</small>

```bash
g++ -std=c++17 compile_time.cpp -o c && ./c
# 8 4
# 32
```

## A.2 `const` 与 `constexpr` 的区别

<small style="color:gray">cpp</small>

```cpp
// const_vs_constexpr.cpp
int get() { return 5; }
int main() {
    const int a = 5;
    int x[a];               // 通过
    const int b = get();
    // int y[b];            // 失败：ISO C++ forbids variable length array
    return sizeof(x);
}
```

<small style="color:gray">bash</small>

```bash
g++ -std=c++17 -pedantic-errors -c const_vs_constexpr.cpp -o c.o
```

## A.3 `constexpr` 省掉运行期计算

<small style="color:gray">cpp</small>

```cpp
// fold.cpp
int use_constexpr() { constexpr int n = 5; return n * n; }
int use_variable()  { int n = 5; return n * n; }
```

<small style="color:gray">bash</small>

```bash
g++ -std=c++17 -O0 -S fold.cpp -o fold.s
```

## A.4 `static_assert`

<small style="color:gray">cpp</small>

```cpp
static_assert(sizeof(int) == 4, "int 不是 4 字节");
```

## A.6 `if constexpr`

<small style="color:gray">cpp</small>

```cpp
// if_constexpr.cpp

void show(T v) {
    if constexpr (sizeof(T) <= 4) std::printf("小\n");
    else                          std::printf("大\n");
}
int main() { show(1); show(1.0); return 0; }
```

<small style="color:gray">bash</small>

```bash
g++ -std=c++17 if_constexpr.cpp -o i && ./i
```
