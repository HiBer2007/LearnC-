# 第 1 节 类型解决什么问题

## 1.1 类型不是「标签」

**一份常见的说法**：

`C`

```c
int a = 5;
```

> 「`a` 是 `int` 类型，`int` 表示整数。」

**这句话没错，但它只描述了结果，没说明类型在做什么。**

**换成机器视角看**：变量在内存里就是一块空间加上一个地址。

`Text`

```text
   地址 0x7ffd1234 处有 4 个字节： 05 00 00 00
```

**问题来了**：

| 问题 | 不回答它就不知道 |
|---|---|
| 这块空间有几个字节 | 读几个字节才算一个值 |
| 这串字节怎么解释 | `05 00 00 00` 是整数 5，还是别的东西 |
| 能对它做什么 | 能不能做除法，能不能取地址，能不能赋值 |

**类型同时回答这三个问题。**

> [!IMPORTANT]
> 类型 ＝ 大小 ＋ 解释方式 ＋ 允许的操作

## 1.2 一个例子：同样的字节，不同的类型

**同样一串字节，按不同类型解释，结果完全不同。**

`实测数据`
`C`

```c
int  i = 65;      /* 4 字节：41 00 00 00 */
char c = 65;      /* 1 字节：41          */
float f = 65.0f;  /* 4 字节：00 00 82 42 */
```

**其中 `int` 与 `float` 的字节数相同，内容却毫不相干。**
**如果不知道类型，那块内存就是四个无法解释的字节。**

## 1.3 类型在什么时候发挥作用

**大部分时候，类型是编译器「记账」用的**——
它记住每个名字对应什么类型，然后检查你的用法是否合法。

**发挥作用有三个时机**：

| 时机 | 做什么 | 例子 |
|---|---|---|
| **编译时检查** | 拦住类型不匹配的操作 | `int *p = "abc";` 报错 |
| **生成代码时** | 决定用哪条指令 | `float` 加法用浮点指令，`int` 加法用整数指令 |
| **运算时转换** | 按规则把类型统一起来 | `1 + 2.0` 中的 `1` 先变成 `1.0` |

**第一种是学习者感受最深的**，因为它会直接报错。
**第二种决定了程序对不对**。**第三种最容易被忽略，也最容易出错**——第 5 节专门讲。

## 1.4 一个反例：汇编里没有类型

**对照《01-编译器/01-编译与链接.md》第 1.4 小节那段汇编就清楚了。**

`实测数据`
`Assembly`

```asm
add    %edx,%eax        /* 把两个寄存器的内容相加 */
```

这条指令不知道加的是整数还是浮点数，也不检查。
**它是「加法」这个动作本身，没有类型的概念。**

**类型是高级语言加在机器之上的一层约束**：

`Text`

```text
   高级语言：  int a;  a + b      ← 有类型，编译器检查
        ↓ 编译
   机器码：    add %edx,%eax       ← 没有类型，直接算
```

> [!IMPORTANT]
> **类型是编译期的东西，运行期只剩下字节和指令。**
> **理解了这一点，就能理解为什么类型错误是编译错误，而不是运行错误。**

# 第 2 节 基本类型

## 2.1 整数类型家族

**C 与 C++ 的整数类型是同一套**：

`Text`

```text
   字符型      char    signed char    unsigned char

   整型        short   int   long   long long
               （每一种都有对应的 unsigned 版本）

   布尔型      bool（C23 起为关键字；C++ 一直有）
```

**「整数类型」是一个家族，不是几个孤立的类型**——
标准规定了它们的**相对大小关系**：

`Text`

```text
   sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)
      1              2               4            4 或 8            8
```

**注意 `long` 那一格写了两个值**，原因见下节。

**C++ 与 C 对这条的规定方式不同**：C++ 明文要求列表里后一项的存储
不小于前一项；C 只规定取值范围被包含，存储顺序是推出来的。

`文档`

> "In this list, each type provides at least as much storage
> as those preceding it in the list."
>
> —— N4659 §6.9.1/2
>
> "the range of values of the type with smaller integer conversion
> rank is a subrange of the values of the other type."
>
> —— N3220 §6.2.5/10

**结论两者相同**：C 是由「取值范围被包含」推出「存储不会更小」的。

## 2.2 字符类型家族

**表示「字符」的类型不止一个，而是一个家族**：
它们大小不同、用途不同，混用会出问题。

`实测数据`

| 类型 | 字节 | 有符号 | 用途 |
|---|---|---|---|
| `char` | 1 | **实现定义** | **窄字符**，日常用的那个 |
| `signed char` | 1 | 是 | 单字节的**有符号**整数语义 |
| `unsigned char` | 1 | 否 | 单字节的**无符号**整数语义 |
| **`wchar_t`** | **2** | 实现定义 | **宽字符** |
| `char16_t` | 2 | 否 | UTF-16 码元 |
| `char32_t` | 4 | 否 | UTF-32 码元 |

`C`

```c
/* wchar_size.c    编译：gcc -std=c17 wchar_size.c -o wchar_size */
#include <stdio.h>
#include <wchar.h>

int main(void) {
    /* sizeof 的结果是 size_t，转 int 只是为了让 printf 好写 */
    printf("char=%d wchar_t=%d\n", (int)sizeof(char), (int)sizeof(wchar_t));
    printf("short=%d int=%d long=%d ptr=%d\n",
           (int)sizeof(short), (int)sizeof(int),
           (int)sizeof(long), (int)sizeof(void *));
    /* WCHAR_MIN / WCHAR_MAX 在 <wchar.h> 里，能看出符号性 */
    printf("WCHAR_MIN=%d WCHAR_MAX=%d\n", (int)WCHAR_MIN, (int)WCHAR_MAX);
    return 0;
}
```

`C++`

```cpp
// wchar_size.cpp    编译：g++ -std=c++17 wchar_size.cpp -o wchar_size
#include <cstdio>
#include <cwchar>

int main() {
    // char16_t 与 char32_t 是 C++11 起的内建类型，C 里没有
    std::printf("char=%d wchar_t=%d char16_t=%d char32_t=%d\n",
                (int)sizeof(char), (int)sizeof(wchar_t),
                (int)sizeof(char16_t), (int)sizeof(char32_t));
    return 0;
}
```

**`char` 家族是语言里唯一宽度为 1 字节的整数类型**，
因此处理单字节数据时只能用它们。

**上表的 `wchar_t` 一行是 Windows 的取值。** 它的宽度与符号性
都由实现决定，换个平台就不同。

`实测数据`

| 平台 | `sizeof(wchar_t)` | 符号性 |
|---|---|---|
| Windows（`gcc` 15.2.0） | 2 | **无符号** |
| Linux（`gcc` 13.3.0） | **4** | **有符号** |

**同一个程序在两个平台上跑，结果不同。**

> [!CAUTION]
> 标准没有为 `wchar_t` 规定统一的宽度与符号性。
> 同一个变量在两个平台上能存的字符范围不同，参与数值运算的行为也不同。
> **用 `wchar_t` 做数值运算的代码不可移植。**

### 它们不是同一种类型的别名

**大小相同不代表类型相同。**

`实测数据`
`C++`

```cpp
std::is_same<char, signed char>::value        /* 否 */
std::is_same<char, unsigned char>::value      /* 否 */
std::is_same<char16_t, unsigned short>::value /* 否，即使都是 2 字节 */
```

**这个区分有实际用处的场合只有一处**：
存**原始字节**（内存内容、二进制协议）时必须用 **`unsigned char`**，
否则会引入「`char` 到底有没有符号」这个不确定性。

**至于「用单字节类型装普通的整数」**：那是另一类考虑，
见《04-语法/14-奇技淫巧与优化.md》第 3 节。

**「三种不同类型」这条规定的实际影响集中在两处**：
函数重载时 `f(char)` 与 `f(signed char)` 是两个不同的函数；
以及 `char` 的符号性未定，拿它参与数值运算的结果可能随平台变化。
展开见第 2.5 小节。

## 2.3 浮点类型

**浮点数与整数是两类东西，存储方式也自成一套。**
下面的字段划分来自 IEEE 754：

`Text`

```text
   float （32 位）：  1 位符号 + 8 位指数 + 23 位尾数
   double（64 位）：  1 位符号 + 11 位指数 + 52 位尾数
```

**「符号」是单独一位，与整数的做法完全不同。**
整数用补码把正负编进同一串比特里（见第 2.7 小节），浮点数则把
符号、指数、尾数分开存。

> [!IMPORTANT]
> **浮点数没有「无符号」版本。**
> 加不加 `unsigned` 对它没有意义。

**标准只规定了精度的下限，不规定宽度。**

`文档`

> "The value representation of floating-point types is
> implementation-defined."
>
> —— N4659 §6.9.1/8

`实测数据`

| 宏 | 标准要求 | `gcc` | `MSVC` |
|---|---|---|---|
| `FLT_DIG`（`float` 的有效十进制位数） | **至少 6** | 6 | 6 |
| `DBL_DIG`（`double`） | **至少 10** | 15 | 15 |
| `LDBL_DIG`（`long double`） | **至少 10** | **18** | **15** |
| **`sizeof(long double)`** | **不规定** | **16** | **8** |

> [!IMPORTANT]
> 同一个 Windows 平台上的两个编译器，`long double` 的宽度
> 一个是 16、一个是 8。**标准不规定、由实现决定，这就是后果。**

**`float` 大约在第 7 位开始不准，`double` 大约在第 16 位。**
完整的浮点宏清单与精度打印见附录 A.5。

**浮点数有两条必须记住的性质**：

| 性质 | 后果 |
|---|---|
| **不能精确表示所有十进制小数** | `0.1 + 0.2` 不等于 `0.3` |
| **相等比较不可靠** | 应当比较差的绝对值是否小于某个容差 |

**第一条的后果可以直接看到。**

`实测数据`
`C`

```c
/* fp_eq.c    编译：gcc -std=c23 fp_eq.c -o fp_eq */
#include <stdio.h>

int main(void) {
    double a = 0.1, b = 0.2;
    /* 打印 20 位小数，看真实存下来的值 */
    printf("%.20f\n", a + b);                       /* 0.30000000000000004441 */
    printf("%.20f\n", 0.3);                         /* 0.29999999999999998890 */
    /* 直接比较相等，结果是假 */
    printf("%s\n", (a + b == 0.3) ? "真" : "假");
    return 0;
}
```

`C++`

```cpp
// fp_eq.cpp    编译：g++ -std=c++17 fp_eq.cpp -o fp_eq
#include <cstdio>

int main() {
    // 与 C 版逐行等价
    double a = 0.1, b = 0.2;
    std::printf("%.20f\n", a + b);
    std::printf("%.20f\n", 0.3);
    std::printf("%s\n", (a + b == 0.3) ? "真" : "假");
    return 0;
}
```

**两个值确实不一样**，差的不是显示精度，是存储下来的数本身就不同。

**原因不在语言，在二进制**：`0.1` 与 `0.3` 在二进制里都是无限循环小数，
`double` 存不下，只能存最接近的那个值。
两个「最接近的值」相加，结果不会自动变成另一个最接近的值。

> [!CAUTION]
> 浮点数不能用 `==` 比较相等。需要精确十进制的场合
> （如金额）要用定点数或专门的库，不能用 `float` 与 `double`。

## 2.4 `void`

**`void` 表示「没有」**，用在三个位置：

| 位置 | 含义 |
|---|---|
| `void f(void)` | 函数不接收参数 |
| `void f()` | 函数不返回值 |
| `void *p` | 指向「不知道什么类型」的指针 |

**第三种的用途见第 6.2 小节**——那是 C 与 C++ 的一处分歧。

## 2.5 有符号与无符号标记

**`signed` 与 `unsigned` 是加在整数类型前面的标记，用来指定「要不要负数」。**

### 能加在哪些类型上

`实测数据`

| 声明 | C23 |
|---|---|
| `signed a;` / `unsigned a;` | 通过（等价于带 `int`） |
| `signed char a;` / `unsigned char a;` | 通过 |
| `unsigned float a;` / `unsigned double a;` | **失败** |
| `signed wchar_t a;` | **失败** |

**只能加在整数类型上**：浮点类型没有有符号与无符号之分，它们天然带符号。
**可以省略 `int`**：`unsigned a;` 就是 `unsigned int a;`。
**`wchar_t` 上不能加**：它是独立类型，不是某个整数类型的别名。

**这些声明的逐条结果见附录 A.14。**

### 三种 `char` 的实质区别

**这三种类型的区别只在一件事上：`char` 的符号性没有保证。**

| 类型 | 符号性 | 能不能确定 |
|---|---|---|
| `signed char` | **一定是有符号** | 能 |
| `unsigned char` | **一定是无符号** | 能 |
| **`char`** | **由实现决定** | **不能** |

`实测数据`
`Text`

```text
CHAR_MIN = -128, CHAR_MAX = 127
char 是有符号的吗: 是
```

**这不保证别的平台也一样**——标准把它留给实现，就意味着可以不同。

`C`

```c
char c = 200;              /* 若 char 无符号，c 是 200 */
                           /* 若有符号，200 超出范围，行为由实现决定 */
if (c > 100) { ... }       /* 结果取决于 char 的符号性 */
```

**同样的代码，在不同平台上走不同的分支。**

**对策**：

| 想做什么 | 用什么 |
|---|---|
| 处理字符 | `char`，**不要拿它跟数值比较大小** |
| 处理原始字节 | **`unsigned char`** |
| 需要确定的符号性 | 显式写 `signed char` 或 `unsigned char` |

### 一条容易被忽略的规则

**`signed` 单独出现时表示 `int`，`unsigned` 单独出现时表示 `unsigned int`。**
这两条在 C 与 C++ 里都成立，是早期的简写。

**建议一律写全**：

`C`

```c
unsigned a;             /* 合法，但读者要停一下才能确定它是 unsigned int */
unsigned int a;         /* 一眼就清楚 */
```

> [!TIP]
> `unsigned` 究竟修饰哪个类型，需要读者回忆规则。
> 写全不花成本，省下的是别人的阅读时间。

## 2.6 宽度决定了什么

**「宽度」指一个类型占几个字节。它决定三件具体的事。**

### 一、宽度决定取值范围

`实测数据`

| 类型 | 字节 | 最小值 | 最大值 |
|---|---|---|---|
| `signed char` | 1 | -128 | 127 |
| `unsigned char` | 1 | 0 | 255 |
| `short` | 2 | -32768 | 32767 |
| `unsigned short` | 2 | 0 | 65535 |
| `int` | 4 | -2147483648 | 2147483647 |
| `unsigned int` | 4 | 0 | 4294967295 |

**规律很直接**：

`Text`

```text
   n 字节的有符号整数    范围是  -2^(8n-1)  到  2^(8n-1) - 1
   n 字节的无符号整数    范围是       0     到  2^(8n)   - 1
```

**以 1 字节为例**：

`Text`

```text
   signed char    2^7 = 128      →  -128 ~ 127
   unsigned char  2^8 = 256      →     0 ~ 255
```

**有符号与无符号的总个数相同（都是 256 个），
只是有符号类型把一半分给了负数。**

> [!IMPORTANT]
> 要装一个数之前，先想它最大能到多少。
> 装不下就换更宽的类型，不要指望它「差不多能用」。

### 二、宽度不够时会怎样

**超出的部分不会凭空消失，处理方式取决于有没有符号位。**

`实测数据`
`C`

```c
signed char   sc = 127;   sc + 1;   /* = -128      有符号溢出 */
unsigned char uc = 255;   uc + 1;   /* = 0         无符号回绕 */

int   big   = 100000;
short small = (short)big;           /* = -31072    截断 */
```

**无符号的超出是回绕**：从最大值跳回 0，按模 2^n 计算，定义明确。
**有符号的超出是未定义行为**，标准对它不作要求——
本机显示为 `-128`，但那只是这台机器的表现。

**截断是同一件事的另一面**：`100000` 装不进 2 字节的 `short`（最大 32767），
高位被截掉，剩下的部分按 2^n 取模解释。

`Text`

```text
   100000 mod 65536 = 34464
   34464 超过 short 的正数上限 32767
   34464 - 65536 = -31072        ← 对上了
```

**回绕与截断都是「按 2^n 取模」。**
两种越界在高位上的差别见第 2.7 小节，完整的回绕演示见附录 A.5。

### 三、浮点的宽度决定精度

**整数类型的宽度决定「能装多大的数」，
浮点类型的宽度决定的是「能精确到第几位」。**

`实测数据`

| 类型 | 字节 | 尾数位数 | 十进制有效位 |
|---|---|---|---|
| `float` | 4 | 24 | **6** |
| `double` | 8 | 53 | **15** |

**宽度一定时，指数位与尾数位此消彼长**：
指数位越多，能表示的数值范围越大；尾数位越多，精度越高。
`double` 用多出来的 32 位同时扩了这两者。

`实测数据`
`C`

```c
float  f = 16777216.0f;         /* 2^24 */
f + 1.0f;                       /* = 16777216.0，没有变化 */

double d = 9007199254740992.0;  /* 2^53 */
d + 1.0;                        /* = 9007199254740992.0，没有变化 */
```

**加一之后值没变——因为 1 落在了精度之外，被丢掉了。**

**`2^24` 是 `float` 能连续表示整数的上限，`2^53` 是 `double` 的。**
超过这个界限，相邻两个可表示的数之间就有间隔，**中间的数一律表示不了**。

**累积误差更惊人**：把 `0.1` 累加一百万次。

`实测数据`
`C`

```c
/* fp_sum.c    编译：gcc -std=c23 fp_sum.c -o fp_sum */
#include <stdio.h>

int main(void) {
    /* 同样的加法，分别用两种精度做一百万次 */
    float  sf = 0.0f;
    double sd = 0.0;
    for (int i = 0; i < 1000000; i++) {
        sf += 0.1f;         /* float 每次都会丢一点 */
        sd += 0.1;          /* double 的精度足够 */
    }
    printf("float  = %.6f\n", (double)sf);   /* 100958.343750 */
    printf("double = %.6f\n", sd);           /* 100000.000001 */
    return 0;
}
```

**误差分别是 958 与 0.000001，相差约一亿倍。**

**百万次加法里，每次 `float` 都丢一点点，累积起来就成了 958。**
`double` 的精度足够，几乎不丢。

**因此该怎么选**：

| 场合 | 选择 |
|---|---|
| **默认选择** | **`double`** |
| 内存紧张、精度要求低（如图形、嵌入式） | `float` |
| 需要大量累加或精密计算 | **`double` 或更高** |
| 需要精确十进制（如金额） | **都不用**，改用定点数或专门的库 |

> [!CAUTION]
> `float` 不是「精度差一点的 `double`」。
> 在大量累加的场景下它可能差得离谱，而且不会报错。

### 四、宽度由标准与平台共同决定

**标准没有规定 `int` 一定是 4 字节**，只规定了相对关系与最小值：

| 类型 | 标准规定的最小位数 |
|---|---|
| `char` | 至少 8 位 |
| `short` | 至少 16 位 |
| `int` | 至少 16 位 |
| `long` | 至少 32 位 |
| `long long` | 至少 64 位 |

**实际宽度由「数据模型」决定，而数据模型由平台决定。**

`实测数据`
`C`

```c
/* width.c    编译：gcc -std=c23 width.c -o width */
#include <stdio.h>

int main(void) {
    /* sizeof 的结果是 size_t，转 int 只是为了让 printf 好写 */
    printf("char=%d short=%d int=%d long=%d long long=%d ptr=%d\n",
           (int)sizeof(char), (int)sizeof(short), (int)sizeof(int),
           (int)sizeof(long), (int)sizeof(long long), (int)sizeof(void *));
    return 0;
}
```

`C++`

```cpp
// width.cpp    编译：g++ -std=c++17 width.cpp -o width
#include <cstdio>

int main() {
    // 与 C 版逐行等价，只是头文件与 printf 的写法不同
    std::printf("char=%d short=%d int=%d long=%d long long=%d ptr=%d\n",
                (int)sizeof(char), (int)sizeof(short), (int)sizeof(int),
                (int)sizeof(long), (int)sizeof(long long), (int)sizeof(void *));
    return 0;
}
```

| 类型 | Windows x64（MinGW 与 MSVC 一致） | Linux x86-64 |
|---|---|---|
| `char` | 1 | 1 |
| `short` | 2 | 2 |
| `int` | 4 | 4 |
| **`long`** | **4** | **8** |
| `long long` | 8 | 8 |
| 指针 | 8 | 8 |

**只有 `long` 一列不同**（`wchar_t` 也在此列，见第 2.2 小节）。
数据模型的名字怎么读、LLP64 与 LP64 的差别，
见《01-编译器/00-语言的实现.md》第 5.3 小节。

**实用结论**：

| 需要 | 写法 |
|---|---|
| 不关心宽度 | `int` |
| **需要确定宽度** | `int32_t` / `int64_t`（`<stdint.h>`） |
| 表示大小、长度、下标 | `size_t` |
| 跨平台传数据 | 用固定宽度类型与明确的字节序 |

## 2.7 整数在内存里怎么存

**第 2.6 小节讲「能装多大的数」，本小节讲「装进去的到底是什么」。**

**宽度决定有几个字节，编码方式决定这串字节怎么解释成正负数。**
这两件事必须分开看。

### 一个字节，两种读数

`实测数据`
`C`

```c
/* two_readings.c    编译：gcc -std=c23 two_readings.c -o two_readings */
#include <stdio.h>
#include <string.h>

int main(void) {
    for (int i = 0; i < 3; i++) {
        /* 造出一个字节，从 FF 往下取 */
        unsigned char u = (unsigned char)(255 - i);
        signed char   s;
        /* 用 memcpy 把同样的字节拷进有符号变量，避免转换规则干扰 */
        memcpy(&s, &u, 1);
        printf("字节 %02X  ->  无符号 %3u   有符号 %4d\n", u, u, s);
    }
    return 0;
}
```

**输出**：

`Text`

```text
字节 FF  ->  无符号 255   有符号   -1
字节 FE  ->  无符号 254   有符号   -2
字节 FD  ->  无符号 253   有符号   -3
```

**同一串比特，按有符号读是负数，按无符号读是一半以上的正数。**

**这不是两种不同的存储方式，而是同一份数据的两种解释。**
**类型的作用正在于此——它告诉编译器该按哪种方式解释。**

### 三种表示法

**历史上出现过三种用二进制表示带符号整数的方案。**

**以 4 位为例**：

| 真值 | 原码 | 反码 | 补码 |
|---|---|---|---|
| 0 | 0000 | 0000 | **0000** |
| 1 | 0001 | 0001 | 0001 |
| 2 | 0010 | 0010 | 0010 |
| 3 | 0011 | 0011 | 0011 |
| -1 | 1001 | 1110 | **1111** |
| -2 | 1010 | 1101 | **1110** |
| -3 | 1011 | 1100 | **1101** |
| -4 | 1100 | 1011 | **1100** |
| -0 | 1000 | 1111 | **不存在** |

**三种方案的构造规则**：

| 方案 | 正数 | 负数 |
|---|---|---|
| **原码** | 最高位 0，其余放绝对值 | 最高位 1，其余放绝对值 |
| **反码** | 与原码相同 | 符号位不变，**其余按位取反** |
| **补码** | 与原码相同 | **反码加一** |

**读法**：**原码最直观，反码是原码到补码的中间步骤，补码是现在唯一在用的。**

### 为什么补码胜出

**看那张表的最后一行**——

**原码与反码都有两个零**（`0000` 与 `1000`／`1111`），
**而补码只有一个**。这带来两个后果：**多表示一个数**——
4 位补码能表示 -8 ~ 7，原码与反码只能表示 -7 ~ 7；
**不必特判零**——原码要判断「这是 +0 还是 -0」。

**但这还不是补码最重要的优点。**
**补码最重要的优点是减法可以用加法做。**

`实测数据`
`C`

```c
/* twos_complement.c    编译：gcc -std=c23 twos_complement.c -o twos_complement */
#include <stdio.h>

int main(void) {
    int a = 10, b = 3;

    /* -b 的补码：按位取反再加一 */
    unsigned char neg3 = (unsigned char)(~b + 1);   /* = 0xFD */

    printf("10 - 3        = %u\n", (unsigned)(a - b));
    /* 加上补码，再截到 8 位（丢掉最高位的进位） */
    printf("10 + (-3补码) = %u\n", (unsigned)((a + neg3) & 0xFF));
    printf("-3 的补码字节 : %02X\n", neg3);
    return 0;
}
```

**验算**：

`Text`

```text
   0000 1010     (10)
 + 1111 1101     (-3 的补码)
 ───────────
 1 0000 0111     最高位的 1 溢出丢掉，剩下 0111 = 7
```

**结果正确。**

> [!IMPORTANT]
> **CPU 不需要为减法单独做一套电路。**
> 它只要一个加法器，加一个「取补码」的操作，就能同时做加减法。

**这是硬件层面的收益，也是补码成为唯一标准的原因。**

### 怎么求一个数的补码

**两条等价的公式**：

`Text`

```text
   -x  ==  ~x + 1
   ~x  ==  -x - 1
```

**以 `x = 5` 为例。**

`实测数据`
`C`

```c
/* twos.c    编译：gcc -std=c23 twos.c -o twos */
#include <stdio.h>

/* 把低 8 位按二进制打印出来，看清每一位 */
static void show(const char *label, int v) {
    printf("%-16s: ", label);
    for (int i = 7; i >= 0; i--) printf("%d", (v >> i) & 1);
    printf("\n");
}

int main(void) {
    int x = 5;
    show("x", x);                 /* 00000101 */
    show("~x", ~x);               /* 11111010  按位取反 */
    show("~x + 1", ~x + 1);       /* 11111011  加一 */
    printf("~x + 1 = %d, -x = %d\n", ~x + 1, -x);
    return 0;
}
```

**`~x + 1` 与 `-x` 得到同一个值。**
记住其中一条就够，另一条可以推出来。
第二条（`~x == -x - 1`）的逐个取值对照见附录 A.6。

### 补码的一个后果：负数比正数多一个

`实测数据`
`C`

```c
/* range.c    编译：gcc -std=c23 range.c -o range */
#include <stdio.h>
#include <limits.h>

int main(void) {
    /* SCHAR_MIN / SCHAR_MAX 在 <limits.h> 里 */
    printf("signed char 的范围: %d ~ %d\n", SCHAR_MIN, SCHAR_MAX);
    printf("正数个数: %d\n", SCHAR_MAX);
    printf("负数个数: %d\n", -(int)SCHAR_MIN);
    return 0;
}
```

**输出**：

`Text`

```text
signed char 的范围: -128 ~ 127
正数个数: 127
负数个数: 128
```

**为什么负数多一个？**

**因为零占掉了一个位置。** 1 字节有 256 种比特组合，分成两半：

`Text`

```text
   0 ~ 127      128 个        正数与零
   -1 ~ -128    128 个        负数
```

**零不能算进正数里，所以正数只剩 127 个。**

`实测数据`
`C`

```c
/* negate_min.c    编译：gcc -std=c23 negate_min.c -o negate_min */
#include <stdio.h>
#include <limits.h>

int main(void) {
    signed char m = SCHAR_MIN;          /* 最小值 -128 */
    /* 对最小值取负，结果仍是它自己 */
    printf("-SCHAR_MIN = %d\n", (signed char)(-m));
    printf("它的字节     = %02X\n", (unsigned char)m);
    return 0;
}
```

**对一个最小值取负，得到的还是它自己。**

**原因很直接**：`-128` 的对应正数是 `+128`，
**而 `+128` 超出了 `signed char` 的范围（最大 127），装不下。**

**它的字节是 `80`**——最高位是 1，其余全 0，取反加一之后又回到自己。

**这类问题属于有符号溢出，标准把它归入未定义行为**
（见《04-语法/03-表达式与运算符.md》第 3.3 小节）。
本次实测得到了 `-128`，但那只是本机的表现。

### 扩宽时的两种填法

**把一个窄的有符号数扩成宽类型时，高位补什么？**

`实测数据`
`C`

```c
/* widen.c    编译：gcc -std=c23 widen.c -o widen */
#include <stdio.h>

int main(void) {
    signed char   sc = -1;      /* 字节 FF */
    unsigned char uc = 255;     /* 字节 FF —— 与上面完全相同的字节 */

    int a = sc;                 /* 符号扩展 */
    int b = uc;                 /* 零扩展 */

    printf("signed char   -1 的字节  : %02X\n", (unsigned char)sc);
    printf("  扩成 int              : %08X  （值 %d）\n", (unsigned)a, a);
    printf("unsigned char 255 的字节 : %02X\n", uc);
    printf("  扩成 int              : %08X  （值 %d）\n", (unsigned)b, b);
    return 0;
}
```

**同样是 `FF` 这一个字节，扩宽之后一个补 1、一个补 0。**

| 类型 | 扩宽时高位补什么 | 名字 |
|---|---|---|
| 有符号 | **补符号位**（负数补 1，正数补 0） | **符号扩展** |
| 无符号 | **补 0** | **零扩展** |

**这就解释了那两种不同的越界行为**：

| 情形 | 高位的变化 | 结果 |
|---|---|---|
| 无符号回绕 | 只保留低 8 位 | **定义明确**：255 + 1 = 0 |
| 有符号溢出 | 符号位本身被改掉 | **未定义行为** |

**无符号数的每一位都是数值位**，进位溢出丢掉即可，规则清楚。
**有符号数的最高位是符号位**，它被改掉之后，
「这个数是正是负」就不再有意义——**标准因此不作要求。**

> [!NOTE]
> 补码不是「一种约定」，而是「让加法器同时能算减法」这个目标
> 推出来的结果。理解了这个目标，`-128` 为什么没有正数对应、
> 扩宽为什么补符号位，都不必单独记。

# 第 3 节 类型限定符

## 3.1 `const`

**`const` 表示「不应被修改」，并且由编译器保证。**

`实测数据`
`C`

```c
/* const_assign.c    编译：gcc -std=c23 const_assign.c —— 应当失败 */
int main(void) {
    const int n = 10;
    n = 20;              /* error: assignment of read-only variable 'n' */
    return 0;
}
```

**C 与 C++ 的写法相同**：把命令换成 `g++ -std=c++17`，得到的是同一条错误。

> [!IMPORTANT]
> 上面这个错误是**编译期**发生的，不是运行期检查。
> 不需要任何运行时开销，就能获得保证。

**这正是 `const` 的价值所在**：

| 做法 | 保证来自 | 代价 |
|---|---|---|
| 写注释「这个值不要改」 | **人的自觉** | 改错了没人拦 |
| **用 `const`** | **编译器** | 零运行时开销 |

**`const` 的位置有讲究**：

`C`

```c
const int *p;         /* p 指向的东西不能改，p 本身可以改 */
int * const q = &x;   /* q 本身不能改，它指向的东西可以改 */
const int * const r;  /* 两者都不能改 */
```

**读法**：**从变量名出发，先看右边，再看左边。**
这一规则同样适用于指针与数组的复杂声明，见
《04-语法/07-数组、指针与引用.md》第 4.1 小节。

> [!IMPORTANT]
> **`const` 还有一层与链接属性有关的行为，C 与 C++ 在这里不一致**，
> 见《01-编译器/00-语言的实现.md》第 6.4 小节。

## 3.2 `volatile`

**`volatile` 表示「这个值可能在意料之外被改变」，因此编译器不许优化对它的读写。**

**它解决的问题**：

`C`

```c
/* 假设 0x40021000 是某个硬件寄存器 */
#define GPIOA_ODR  (*(volatile uint32_t *)0x40021000)

GPIOA_ODR = 0x01;      /* 没有 volatile 时，这两次写可能被合并成一次 */
GPIOA_ODR = 0x02;
```

**没有 `volatile` 时**，编译器看到「连续两次写同一个地址、
中间没有读」，会认为第一次写没有意义，**直接删掉**。
**对普通内存这是正确的优化，对硬件寄存器这是灾难。**

**完整实测见《01-编译器/03-嵌入式与交叉编译.md》第 4.5 小节**，
那里给出了带与不带 `volatile` 的汇编对照。

**两个常见误解**：

| 误解 | 实际 |
|---|---|
| `volatile` 能保证线程安全 | **不能**。它只管编译器不优化，不管 CPU 乱序与缓存一致性 |
| `volatile` 能保证原子性 | **不能**。多字节读写仍可能被打断 |

## 3.3 C 独有的 `restrict`

**`restrict` 是 C 的限定符，C++ 标准里没有。**

**「C++ 没有」这一半可以直接核实**：N4659 全文检索不到 `restrict` 这个关键字，
关键词表（§5.11 Table 5）里也没有它。
**C23 则把它列在类型限定符里。**

`文档`

> ```text
> type-qualifier:  const   restrict   volatile   _Atomic
> ```
>
> —— N3220 §6.7.4.1

`待确认`

**「`restrict` 由 C99 引入」这一说法尚未核实。** 两份草案都只记载当前规则，
不记载条款的版本沿革，因此无法从它们确认它是哪一版加入的。
要落实这一条需要查 C99 的标准原文。

**它向编译器承诺**：这块内存只通过这一个指针访问。

`C`

```c
void copy(int * restrict dst, const int * restrict src, size_t n);
```

**有了这个承诺，编译器可以放心地向量化循环**——
它知道两个指针不会指向同一块内存。

**这条属于 C 与 C++ 的差异之一**，归入第 6 节的模式。

## 3.4 `register`

**`register` 是另一个 C 遗留的限定符**，
它建议编译器把这个变量放进寄存器
（现代编译器自己会判断，不理会这个建议）。
**它在两种语言里的地位完全不同。**

`文档`

> "The export and register keywords are unused but are reserved
> for future use."
>
> —— N4659 §5.11 Table 5

**C23 里它仍是存储类说明符**（N3220 §6.7.2/1）；
**C++17 里它已经不是存储类说明符**（N4659 §10.1.1/1），
存储类说明符只剩 `static`、`thread_local`、`extern`、`mutable` 四个。
**也就是说，在 C++17 里写 `register` 并不符合标准**——
它不是「不推荐」，而是**标准里已经没有这个功能**。

**编译器的实际表现如下。**

`实测数据`

| 命令 | 结果 |
|---|---|
| `gcc -std=c17 -Wall` | 通过，无警告 |
| `gcc -std=c23 -Wall` | 通过，无警告 |
| `g++ -std=c++17 -Wall` | **通过，但有警告**：`ISO C++17 does not allow 'register' storage class specifier [-Wregister]` |

> [!WARNING]
> 最后一行里 GCC 只给警告、不报错，这是编译器的宽松行为，不代表合法。
> 这正是第 6.6 小节那条：能编过不等于合法。

**结论：现代代码里两边都不要再用。**

# 第 4 节 类型别名

## 4.1 `typedef`：把变量名换成类型名

**写 `typedef` 有一个固定的机械步骤，先看一个普通变量声明**：

`C`

```c
unsigned long long counter;         /* 声明一个变量 counter */
```

**三步就能得到别名**：

`Text`

```text
   第一步  写一个普通的变量声明
           unsigned long long counter;

   第二步  把变量名替换成你想要的类型名
           unsigned long long u64;

   第三步  在最前面加上 typedef
           typedef unsigned long long u64;
```

**至此 `u64` 就是 `unsigned long long` 的别名。**

**复杂类型也一样，因为变量声明怎么写，别名就怎么写**：

`C`

```c
int (*handler)(int, void *);            /* 变量 handler：指向函数的指针 */

typedef int (*callback_t)(int, void *); /* 把 handler 换成 callback_t，再加 typedef */
```

> [!IMPORTANT]
> **`typedef` 不引入新语法。**
> **它就是「变量声明 + 把变量名换成类型名 + 前面加 `typedef`」，
> 三步而已。**

**这也解释了为什么 `typedef` 的名字总在声明中间**——
它占的正是变量名的位置。

## 4.2 `using`：给类型名赋值

**`using` 是 C++11 引入的另一种写法，读法完全不同。**

`Text`

```text
   using   u64        =   unsigned long long;
           └┬─┘           └───────┬───────┘
        目标类型名          类型表达式
```

**把 `using` 当成一个类型关键字，整句读作**：

> [!IMPORTANT]
> **把类型表达式「赋值」给目标类型名。**

**类型表达式怎么写？把变量声明里的变量名挖掉即可**：

`Text`

```text
   int (*handler)(int, void *);
                 └──┬───┘
              把 handler 挖掉

   剩下  int (*)(int, void *)
   这就是类型表达式
```

**代入 `using`**：

`C++`

```cpp
int (*handler)(int, void *);            /* 变量声明 */
using callback_t = int (*)(int, void *);/* 挖掉 handler，填进 using */
```

**与 `typedef` 的写法对照**：

| | 写法 | 读法 |
|---|---|---|
| `typedef` | `typedef int (*callback_t)(int, void *);` | 名字**占变量名的位置**，藏在中间 |
| `using` | `using callback_t = int (*)(int, void *);` | 名字在**等号左边**，一眼可见 |

> [!TIP]
> **`using` 更容易读**，因为名字总在最前面。
> **C++ 代码里优先用 `using`**，只有在需要与 C 共用头文件时才用 `typedef`。

**两种写法的完整可编译示例见附录 A.11。**

## 4.3 一个 `using` 能做而 `typedef` 做不到的事

**模板别名。**

`C++`

```cpp
using Vec = std::vector<int>;         /* 这个 typedef 也能做 */

template <typename T>
using VecT = std::vector<T>;          /* 这个 typedef 做不到 */
```

**`typedef` 无法定义带参数的别名**，
因为它的机制是「替换变量名」，而模板参数没有对应的变量名可替换。

**这是 `using` 存在的真正理由**：
C++ 没有去扩展 `typedef`，而是加了一套新写法。
**代价是同一个功能有了两种写法**，读别人的代码时两种都会遇到。

## 4.4 别名是语法糖

**「语法糖」的意思是：同一件事的另一种写法，底层机制完全相同。**

**别名正是如此——它只存在于源码里，编译之后什么都不剩。**

`Text`

```text
   源码                      编译之后
   typedef int myint;        （没留下任何东西）
   myint a = 1;      ───►    int a = 1;
```

**编译器在读源码时就把 `myint` 换成了 `int`**，
**生成的机器码与直接写 `int` 完全一样**。

`实测数据`
`C`

```c
/* alias_sugar.c    编译：gcc -std=c23 -S alias_sugar.c -o alias_sugar.s */
#include <stdio.h>

typedef int myint;

int with_typedef(void) {
    myint a = 1;            /* 用别名 */
    return a + 1;
}

int without_typedef(void) {
    int a = 1;              /* 不用别名 */
    return a + 1;
}

int main(void) {
    printf("%d %d\n", with_typedef(), without_typedef());
    return 0;
}
```

**把生成的汇编里两个函数对照一下，指令序列完全相同**——
别名没有带来任何运行期差别。

> [!IMPORTANT]
> **别名是语法糖：它是写给人和编译器看的名字，不是新的类型。**
> **它不占内存、没有运行期开销、也不提供任何类型安全。**

**三条推论**：

| 推论 | 说明 |
|---|---|
| 别名**不影响性能** | 编译后不存在 |
| 别名**不是类型** | `myint` 与 `int` 是同一个 |
| 别名**不自带检查** | 编译器只看底层类型，不看名字 |

**最后一条最容易被误用**：

`实测数据`
`C`

```c
/* alias_not_type.c    编译：gcc -std=c23 alias_not_type.c -o alias_not_type */
#include <stdio.h>

typedef int UserId;
typedef int OrderId;

/* 参数类型写成 UserId，但传 OrderId 一样能编过 */
static void print_user(UserId id) { printf("id = %d\n", id); }

int main(void) {
    OrderId o = 7;
    print_user(o);          /* 合法，编译器不拦 */
    return 0;
}
```

> [!WARNING]
> **别名不提供任何类型安全。**
> `UserId` 与 `OrderId` 都是 `int`，编译器不会拦住你把其中一个
> 传给需要另一个的函数。
> 要真正的新类型，需要结构体包装或 C++ 的 `enum class`。

**别名的三个用途**：

| 用途 | 例子 |
|---|---|
| **简化复杂类型** | 函数指针 |
| **表达意图** | `typedef int UserId;` 比 `int` 更说明问题 |
| **便于修改** | 宽度需要变时只改一处 |

> [!IMPORTANT]
> 语法糖不等于「没用」。别名省下的是**阅读与维护的成本**，
> 而不是运行期的成本。这类收益在工程规模变大时才显现出来。

# 第 5 节 类型转换

## 5.1 为什么会有转换

**运算要求两边类型一致**，但实际代码里常常不一致：

`C`

```c
int    i = 1;
double d = 2.0;
i + d            /* 类型不同，怎么加 */
```

**C 与 C++ 的处理方式是：按一套固定规则，把其中一个转成另一个。**

**这套规则分两步**：

`Text`

```text
   第一步：整型提升        把小类型提升到 int
   第二步：常用算术转换     把两边统一到同一个类型
```

**这两步是隐式发生的，代码里看不到**，因此最容易出错。

## 5.2 第一步：整型提升

**规则**：**凡是比 `int` 窄的整数类型，参与运算前先提升为 `int`。**

**这条规则有两个具体后果**：

| 场景 | 结果 |
|---|---|
| `unsigned char` 的加法不会在 255 处回绕 | 提升到 `int` 后空间足够 |
| `char` 的位运算结果可能与预期不同 | 提升时带上了符号 |

**下面这段程序把两件事一起演示出来。**

`实测数据`
`C`

```c
/* promote.c    编译：gcc -std=c23 promote.c -o promote */
#include <stdio.h>

int main(void) {
    /* 两个比 int 窄的类型相加 */
    unsigned char a = 200, b = 100;
    printf("%d\n", a + b);                /* 300：没有在 255 处回绕 */
    printf("%d\n", (int)sizeof(a + b));   /* 4：整个表达式已经是 int */

    /* 位运算同样先提升：x 先变成 int 的 255，再移位 */
    unsigned char x = 0xFF;
    printf("%d\n", x >> 4);               /* 15 */
    return 0;
}
```

**先看前两行**：结果是 **300**，超出了 `unsigned char` 的范围（最大 255），
**却没有回绕**；而 `sizeof(a + b)` 是 **4**——表达式的类型已经不是
`unsigned char`，而是 `int`。`a` 与 `b` 都是 1 字节，它们的和却是 4 字节，
**说明运算确实在 `int` 上进行，两个操作数都被提升过了。**

**第三行是同一件事的另一种表现**：`x >> 4` 得到 15，因为 `x` 先被提升成
`int` 的 255 再移位。多数情况下这与「在 1 字节上直接移位」的结果相同，
但在涉及符号的运算里就会分岔。

**C 与 C++ 的写法相同。**

## 5.3 第二步：常用算术转换

**两个不同类型相遇时，按下面的顺序统一**（下图是简化表述）：

`Text`

```text
   long double
       ↑
    double
       ↑
     float
       ↑
   unsigned long long
       ↑
   long long
       ↑
   unsigned long / long（按宽度）
       ↑
   unsigned int 与 int       ← 同一层
       ↑
   （比 int 窄的都已提升到 int）
```

**规则是：等级低的一方转成等级高的一方。**

**`unsigned int` 与 `int` 在图上处于同一层**——
**它们是有符号与无符号的对应类型，标准规定两者等级相等。**

`文档`

> "The rank of any unsigned integer type shall equal the rank
> of the corresponding signed integer type."
>
> —— N4659 §7.15/1.4、N3220 §6.3.1.1

**等级相等时，规则是另一条**（N4659 §8[expr]/11.5.3）：
若一方是无符号类型，且它的等级**大于或等于**另一方的等级，
则有符号的一方转成无符号的一方。

**这一条才是下一节所有问题的来源**——
不是「`unsigned int` 更高级」，而是**「等级相同时，有符号的让位给无符号的」**。

**两者的区别很实在**：

| 说法 | 对不对 |
|---|---|
| 「`unsigned int` 等级比 `int` 高」 | **不对**，两者等级相等 |
| 「等级相等时，有符号的转成无符号的」 | **对** |

**这不是文字游戏**——按第一种理解，
`unsigned short` 与 `int` 相遇时（`short` 等级低于 `int`），
就会推不出正确答案。**实际规则是 `int` 胜出**，因为无符号方等级更低。

## 5.4 有符号与无符号混用

**这是 C 与 C++ 里最经典的一类错误。**

`实测数据`
`C`

```c
/* sign_mix.c    编译：gcc -std=c23 sign_mix.c -o sign_mix */
#include <stdio.h>

int main(void) {
    /* 有符号与无符号比较：i 先被转成 unsigned int */
    int          i = -1;
    unsigned int u = 1;
    printf("(-1 < 1u) = %s\n", (i < u) ? "真" : "假");    /* 假 */
    printf("-1 转成 unsigned int = %u\n", (unsigned)i);   /* 4294967295 */

    /* sizeof 的结果是 size_t，两个无符号数相减会下溢 */
    printf("sizeof(short) - 5 = %zu\n", sizeof(short) - 5);
    /* 18446744073709551613 */
    return 0;
}
```

**C 与 C++ 的写法相同。**

**`-1` 怎么会不小于 `1`？**

**因为按第 5.3 小节的规则，`i` 被转成了 `unsigned int`**：

`Text`

```text
   -1 转成 unsigned int  =  4294967295
   4294967295 < 1         →  假
```

**这条规则的意图是「保证结果的范围最大」，代价是负数的语义被丢掉了。**

**第二处更隐蔽**：`sizeof(short) - 5` 本应是 `-3`，
实际是一个接近 2^64 的大数。

**原因是 `sizeof` 的结果类型是 `size_t`，而 `size_t` 是无符号的**：
本教材环境下 `sizeof(size_t)` 为 8，且 `size_t` 就是 `unsigned long long`。

`Text`

```text
   sizeof(short) - 5
   = 2 - 5                 两个无符号数相减
   = 2^64 - 3              下溢，回绕到最大值附近
```

**典型触发场景**：

`C`

```c
for (size_t i = n - 1; i >= 0; i--)   /* 死循环：i 永远不小于 0 */
```

**这条循环写法的错误在于**：`size_t` 是无符号的，`i >= 0` 永远成立。

**怎么避免**：

| 做法 | 说明 |
|---|---|
| 编译时打开 `-Wsign-compare` | GCC 默认可检出一部分 |
| 有符号与无符号**不要混用** | 最根本的办法 |
| 用 `size_t` 时**避免反向遍历** | 或改用「大于 0」而不是「不小于 0」 |
| 明确需要负数时用有符号类型 | 不要靠转换 |

**编译器能拦住一部分，但拦不住全部**：有符号与无符号的比较会触发
`-Wsign-compare`，而 `sizeof(short) - 5` 这样的纯计算不会。
**两种写法的对照复现见附录 A.12。**

> [!WARNING]
> 第二种写法即使加了 `-Wall -Wextra` 也不会报。
> 这条规则的代价必须由写代码的人自己承担。

## 5.5 显式转换

**需要明确转换时，有几种写法**：

| 写法 | 可用 | 说明 |
|---|---|---|
| `(int)x` | C 与 C++ | **C 风格**，什么都能转，检查最少 |
| `static_cast<int>(x)` | C++ | 编译期检查 |
| `const_cast<T>(x)` | C++ | 去掉 `const` |
| `reinterpret_cast<T>(x)` | C++ | 重新解释字节 |
| `dynamic_cast<T>(x)` | C++ | 运行期检查（多态类型） |

**C++ 引入四种具名转换的意图**：

> [!IMPORTANT]
> **把「我想做什么」写出来，而不是笼统地说「转一下」。**

**C 风格的 `(int)x` 一个问题在于它什么都干**——
去 `const`、改类型、重新解释字节，全靠一个括号。
**读代码的人无法从写法上判断意图，编译器也一样。**

**因此 C++ 代码里应当优先用具名转换。**

## 5.6 窄化

**把一个宽类型转成窄类型，会丢数据**：

`C`

```c
int   big = 1000;
char  small = big;         /* 丢了高字节 */
```

**C 里这只是一个警告，C++ 里在列表初始化中是错误**：

`C++`

```cpp
char small{1000};          /* error: narrowing conversion */
char small2 = 1000;        /* 通过，但同样丢数据 */
```

**这是「初始化」与「转换」两条规则配合的结果**，
完整说明见《04-语法/04-初始化.md》第 3 节。

**为什么列表初始化要严**：

> [!IMPORTANT]
> **花括号的写法是「我知道这里可能有坑，所以用更严的写法」。
> 既然你主动选了严的，编译器就按严的来。**

# 第 6 节 C 与 C++ 的类型系统差异

## 6.1 差异一：字符字面量的类型

**为什么会分岔，以及它牵出了什么**，
《04-语法/00-导读：从记住规则到理解意图.md》第 4.4 小节已经完整走过一遍，
**此处不重复，只补一条：C 从头到尾没有改过这一点。**

`实测数据`

| 命令 | `sizeof('a')` | 字面量的类型 |
|---|---|---|
| `gcc -std=c17` | 4 | `int` |
| `gcc -std=c23` | 4 | `int` |
| `g++ -std=c++17` | **1** | **`char`** |

**C 的两个版本给出同一个值**，改动全部来自 C++ 那一侧。
**这正是「差异」而不是「C 落后」的原因。**

## 6.2 差异二：`void *` 的隐式转换

`实测数据`
`C`

```c
/* void_ptr.c    编译：gcc -std=c23 void_ptr.c -o void_ptr */
#include <stdlib.h>

int main(void) {
    void *v = malloc(sizeof(int) * 10);
    int  *p = v;     /* C：通过；C++：invalid conversion from 'void*' to 'int*' [-fpermissive] */
    free(p);
    return 0;
}
```

**同一份源码交给 `g++ -std=c++17`，`int *p = v;` 这一行就编不过。**

**为什么要分岔？因为 `void *` 是所有对象指针的「通用容器」**：

`C`

```c
/* C 的典型写法 */
int *p = malloc(sizeof(int) * 10);      /* malloc 返回 void* */
```

**C 允许这种写法，代价是它无法检查你写的目标类型对不对**：

`C`

```c
/* 写错了，C 不会报错 */
double *p = malloc(sizeof(int) * 10);   /* 分配了 int 的大小，当 double 用 */
```

**C++ 不允许，于是必须显式写出来**：

`C++`

```cpp
int *p = static_cast<int *>(malloc(sizeof(int) * 10));
/* 或者更好的写法 */
int *p = new int[10];
```

**因此该怎么理解**：

> [!IMPORTANT]
> **这是「类型安全」与「书写方便」之间的一次取舍。**
> **C 选了方便，C++ 选了安全。**
> **C++ 的意图是：宁可让你多打几个字，也要拦住类型写错。**

**代价也要说清**：C++ 里 `malloc` 用起来明显更啰嗦，
因此 C++ 代码通常直接用 `new`，或者用容器。

**`malloc` 与 `new` 的完整对照**见《04-语法/07-数组、指针与引用.md》第 1.4 小节。

## 6.3 差异三：整数不能隐式转成枚举

`实测数据`
`C`

```c
/* enum_int.c    编译：gcc -std=c23 enum_int.c -o enum_int */
#include <stdio.h>

enum E { A, B };

int main(void) {
    enum E e  = 5;    /* C：通过；C++：invalid conversion from 'int' to 'E' [-fpermissive] */
    enum E e2 = A;
    int x = e2;       /* 反方向：C 与 C++ 都通过 */
    printf("%d %d\n", (int)e, x);
    return 0;
}
```

**同一份源码交给 `g++ -std=c++17`，`enum E e = 5;` 这一行编不过。**

**反方向是两者都允许的**，这个不对称值得琢磨：

| 方向 | C | C++ | 为什么 |
|---|---|---|---|
| `int` → `enum` | 允许 | **禁止** | 任意整数都能转，等于枚举失去了约束力 |
| `enum` → `int` | 允许 | 允许 | 枚举本身就是一个整数，转出去无损 |

**因此该怎么理解**：

> [!IMPORTANT]
> **枚举的价值在于「这个变量的取值只有这几个」。**
> **如果随便一个整数都能塞进去，这个价值就没有了。**

**C++11 的 `enum class` 把两个方向都收紧，并且不再与 `int` 互相隐式转换**，
完整对照见《04-语法/08-结构体、联合体与 enum.md》第 3.3 小节。

## 6.4 差异四：`struct` 的名字是不是类型名

`实测数据`
`C`

```c
/* struct_tag.c    编译：gcc -std=c23 struct_tag.c -o struct_tag */
#include <stdio.h>

struct S { int a; };

int main(void) {
    struct S s1 = { 1 };   /* C 与 C++ 都通过 */
    S s2 = { 2 };          /* C：unknown type name 'S'; use 'struct' keyword ...；C++：通过 */
    printf("%d %d\n", s1.a, s2.a);
    return 0;
}
```

**为什么 C 要这样？**

**因为 C 里「标签」与「普通标识符」在两个独立的命名空间**：

`C`

```c
struct stat { int a; };    /* 标签命名空间里有个 stat */
int stat(const char *);    /* 普通命名空间里也可以有个 stat */
```

**两者同名而不冲突**，这在 C 里是合法的，而且 POSIX 里真实存在这样的代码。

**C++ 为什么合并了？**

**因为它要把 `struct` 升级成类**：

`C++`

```cpp
struct Point { int x, y; };
Point p;                   /* 类型名是一等公民，不该还要写 struct */
```

**若维持 C 的规则，每次用自定义类型都要写 `struct`，
与「类是一等公民」的设计冲突。**

**代价**：C++ 里不能再有「标签与函数同名」的写法。
**这是「为 OOP 让路」付出的一点兼容性代价。**

## 6.5 差异五：空参数列表（C23 起消失了）

**这是一处「差异刚刚被消除」的例子。**

**先看两个标准的差别**：

| 写法 | C17 及以前 | C23 起 | C++ |
|---|---|---|---|
| `int f();` | **参数不限**（旧式） | **无参** | 无参 |
| `int f(void);` | 无参 | 无参 | 无参 |

`实测数据`
`C`

```c
/* oldstyle.c    编译：gcc -std=c17 oldstyle.c -o oldstyle */
int f();
int main(void) { return f(1, 2, 3); }
int f(int a, int b, int c) { return a + b + c; }
```

| 命令 | 结果 |
|---|---|
| `gcc -std=c17` | **通过** |
| `gcc -std=c23` | **失败**：`too many arguments to function 'f'; expected 0, have 3` |

**C23 让 `int f();` 的含义与 C++ 一致了。**

**因此该怎么理解**：

> [!IMPORTANT]
> **旧式空参数列表是 C 早期的历史包袱，
> 它让编译器无法检查调用时的参数个数。**
> **C23 把这个包袱卸掉了——这是 C 向 C++ 靠拢的一个实例。**

**实用建议**：**函数不接收参数时写 `void`**，这样在 C17 与 C23 下含义一致。

`C`

```c
int f(void);        /* 两种标准下都是「无参」 */
```

## 6.6 一处反直觉的实测：隐式 `int`

**这是一处「C 比 C++ 更严」的例子。**

`实测数据`
`C`

```c
/* implicit_int.c    编译：gcc -std=c17 implicit_int.c -o implicit_int */
#include <stdio.h>

f() { return 7; }        /* 没写返回类型 */

int main(void) {
    printf("f() 返回 %d\n", f());
    printf("sizeof(f()) = %d\n", (int)sizeof(f()));
    return 0;
}
```

| 命令 | 结果 |
|---|---|
| `gcc -std=c17` | **失败**：`return type defaults to 'int' [-Wimplicit-int]` |
| `gcc -std=c23` | **失败**：同上 |
| `g++ -std=c++17` | **通过**，退出码 0，**连 `-Wall -Wextra` 都不报** |

**在 C++ 模式下它确实能用，程序会打印出**：

`Text`

```text
f() 返回 7
sizeof(f()) = 4
```

**编译器自己承认把它当成了 `int f()`**——从另一处故意写错的报错里
可以看到 `error: assignment of function 'int f()'`。完整输出见附录 A.13。

`文档`

> "The "implicit int" rule of C is no longer supported."
>
> —— N4659 §10/12 脚注 93

**C++17 不允许这样写**：只有构造函数、析构函数与转换函数可以省略
声明说明符序列，且只能在模板声明、显式实例化或显式特化里。

**C23 在语法上也不允许**（N3220 §6.9.2/1）：函数定义的语法里，
`declaration-specifiers` 不可省略。标准里已经没有「默认 `int`」这条规则了。

**因此整件事是这样**：

| 层面 | 结论 |
|---|---|
| **标准** | **C 与 C++ 都不允许**（C 从 C99 起已移除，C++ 从未支持） |
| **GCC 实测** | C 模式下拒绝并报错；**C++ 模式下静默接受** |
| **该怎么理解** | **GCC 在 C++ 模式下比标准宽松** |

> [!IMPORTANT]
> **「能编过」不等于「合法」。**
> GCC 放行或只给警告，是编译器的宽松行为，不代表这种写法符合标准。

**该怎么理解这件事**：

| 结论 | 说明 |
|---|---|
| **不要写这种代码** | 它在 C 里直接报错，在 C++ 里的行为也不该依赖 |
| **「能编过」不等于「合法」** | 这是本教材反复强调的一点 |
| **两个语言的严格程度不是单向的** | C++ 在多数地方更严，但不是处处如此 |

> [!TIP]
> 遇到能编过但不确定的写法，先查它属于哪个版本、是否合法。
> 这与《04-语法/00-导读：从记住规则到理解意图.md》第 3.4 小节的建议一致。

# 第 7 节 两种类型系统的设计取向

## 7.1 差异背后的共同点

**回头看这五处差异**：

| 差异 | C 的选择 | C++ 的选择 |
|---|---|---|
| `void *` 隐式转换 | 允许，写起来短 | **禁止，类型安全** |
| `int` → `enum` | 允许 | **禁止，保住枚举的约束** |
| `struct` 标签 | 独立命名空间 | **合并，类型名是一等公民** |
| `int f();` | 参数不限 | **无参**（C23 跟随） |
| `'a'` 的类型 | `int` | **`char`**（为了重载） |

**规律很清楚**：

> [!IMPORTANT]
> **C 的取向是「信任程序员，少设障碍」。**
> **C++ 的取向是「宁可麻烦一点，也要在编译期拦住错误」。**

## 7.2 但这不是「谁更好」

**两种取向各有代价，也各有适用场合。**

| 取向 | 好处 | 代价 |
|---|---|---|
| **宽松（C）** | 代码短、写起来快、与硬件打交道方便 | 错误要到运行期才暴露 |
| **严格（C++）** | 大量错误在编译期就被拦住 | 写法更啰嗦、需要更多类型知识 |

**为什么 C 选择宽松，是有历史原因的**：
它诞生于 1972 年，要替代汇编来写操作系统，
**当时的目标是「比汇编好用的系统编程语言」**，
因此保留了大量贴近机器的自由度。

**C++ 选择严格，也有它的理由**：
它要支持大型程序与抽象机制，
**函数重载、类、模板这些东西都依赖精确的类型信息**——
**类型不明确，重载就无从决议。**

## 7.3 因此该怎么用

**这不是一道选择题，因为两者你都会遇到。** 实用的态度是：

| 场合 | 建议 |
|---|---|
| 写新代码 | 按 C++ 的严格方式写，**即使编译器不拦，也自己写清楚** |
| 读 C 的老代码 | 知道那些宽松写法为什么存在，**不要以为它们更优雅** |
| 需要与硬件打交道 | `void *`、位运算这些**该用就用**，严格不等于处处绕路 |
| 跨语言接口 | 用固定宽度类型与 `extern "C"`，见《01-编译器/00-语言的实现.md》第 6.5 小节 |

> [!IMPORTANT]
> **类型系统是工具，不是教条。**
> **理解它为什么这样设计，才能在「该严的地方严、该松的地方松」。**

#include <limits.h>

## A.11 别名的两种写法

**`typedef`**：

`C`

```c
/* typedef_demo.c    编译：gcc -std=c23 typedef_demo.c -o typedef_demo */
#include <stdio.h>

/* 用「变量声明 + 换名字 + 加 typedef」三步得到的两个别名 */
typedef unsigned long long u64;
typedef int (*callback_t)(int, void *);

/* 一个符合 callback_t 形状的函数 */
static int on_event(int code, void *ctx) {
    (void)ctx;                      /* 本例不用上下文 */
    return code * 2;
}

int main(void) {
    u64 n = 42;                     /* u64 就是 unsigned long long */
    callback_t cb = on_event;       /* callback_t 就是那个函数指针类型 */

    printf("n  = %llu\n", n);
    printf("cb = %d\n", cb(21, NULL));
    return 0;
}
```

**`using`**（C++11 起）：

`C++`

```cpp
/* using_demo.cpp    编译：g++ -std=c++17 using_demo.cpp -o using_demo */
#include <cstdio>

using u64 = unsigned long long;
using callback_t = int (*)(int, void *);

static int on_event(int code, void *ctx) {
    (void)ctx;
    return code * 2;
}

int main() {
    u64 n = 42;
    callback_t cb = on_event;
    std::printf("n  = %llu\n", n);
    std::printf("cb = %d\n", cb(21, nullptr));
    return 0;
}
```

**两个程序除别名的写法外完全相同，输出也相同。**
