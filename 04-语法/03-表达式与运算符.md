# 第 1 节 一切皆表达式

## 1.1 一个被忽略的事实

`C`

```c
int a = 1;
int b = 2;
a = b = 3;
if (a = 5) { }
while (--b) { }
int c = (a > 0) ? a : -a;
```

**逐行的构成**：

| 代码 | 它的构成 |
|---|---|
| `a = b = 3;` | 一个**赋值表达式**加一个分号 |
| `if (a = 5) { }` | `if` 后面括号里是一个**赋值表达式** |
| `while (--b) { }` | 括号里是一个**自减表达式** |
| `int c = ...;` | 后面是一个**条件表达式** |

**除了少数几个独立的控制语句**，其余全是「表达式加分号」，
或者「控制符加表达式」。

**`=` 是一个运算符，因此 `a = 5` 是一个表达式，它本身有一个值——
就是被赋进去的那个 5。**

`实测数据`
`C`

```c
/* assign_value.c    编译：gcc -std=c23 assign_value.c -o assign_value */
#include <stdio.h>

int main(void) {
    int a, b;
    a = b = 5;                          /* 赋值表达式的值就是 5，可以接着赋给 a */
    printf("a = %d, b = %d\n", a, b);   /* 输出 a = 5, b = 5 */
    return 0;
}
```

**`a = b = 5` 为什么合法，而且两个都变成 5？**

**因为 `b = 5` 本身是一个表达式，它的值是 5**，
于是 `a = (b = 5)` 就是把 5 赋给 `a`。

`Text`

```text
   a = b = 5
       └─┬─┘
     这一步的值是 5
   所以等价于
   a = 5
```

**如果赋值不是表达式而只是一个动作，`a = b = c` 这种写法就无从解释。**

## 1.2 语句与表达式的分工

**一句话区分**：

| | 表达式 | 语句 |
|---|---|---|
| **做什么** | **计算出一个值** | **控制执行流程** |
| **有没有值** | **有**（可能是 `void`） | 通常没有 |
| **能不能嵌套** | **能**，表达式里放表达式 | 一般不能 |
| **例子** | `a + b`、`f(x)`、`a = 1` | `if`、`for`、`return`、`{}` |

**C 与 C++ 里的语句种类很少**：

`Text`

```text
   表达式语句         expr ;
   复合语句           { ... }
   选择语句           if / switch
   循环语句           for / while / do
   跳转语句           break / continue / return / goto
   声明语句           定义变量、类型
   （C++ 另有 try 块、throw 等）
```

**六类。** 其余全是表达式。

**几个「看起来像语句」的东西，本身就是表达式**：

`实测数据`

| 写法 | 是表达式吗 | 值是什么 |
|---|---|---|
| `a = 1` | **是** | 赋进去的值 1 |
| `++a` | **是** | 自增之后的值 |
| `a++` | **是** | **自增之前**的值 |
| `f()` | **是** | 函数的返回值 |
| `(1, 2, 3)` | **是** | **最右边那个**，即 3 |
| `x > 0 ? x : -x` | **是** | 选中那一支的值 |
| `sizeof(x)` | **是** | 大小，类型是 `size_t` |

**逗号运算符取最右边的值**，`(1, 2, 3)` 的值就是 `3`——
这也解释了为什么 `for (i = 0, j = n; ...)` 里能用逗号：
它在做多件事，同时交出一个值。完整程序见附录 A.2。

## 1.3 函数调用是表达式

**函数调用有返回值，因此它是一个表达式，可以出现在任何需要值的地方。**

`C`

```c
int a = f();                /* 出现在初始化里 */
int b = f() + g();          /* 出现在加法里 */
if (f()) { }                /* 出现在条件里 */
printf("%d", f());          /* 当作参数传给另一个函数 */
```

**如果函数调用不是表达式**，上面这些写法都要另立语法规则。

> [!IMPORTANT]
> **函数调用可以嵌套，因为它是表达式。**

`C`

```c
printf("%d\n", add(mul(1, 2), div(3, 4)));
```

**这一条看着平常，但它是「函数式写法」在 C 与 C++ 里可行的基础。**

## 1.4 这个视角能解释什么

**把「一切皆表达式」立起来之后，下面这些原本零散的点就连成了一条线**：

| 现象 | 为什么 |
|---|---|
| `a = b = c` 合法 | 赋值是表达式，它本身有值，可以接着赋给别人 |
| `if (x = 1)` 能编过 | 赋值是表达式，有值，可以当条件 |
| `while (--n)` 常见 | 前置自减是表达式，它的值是**自减之后**的值，可以直接当条件 |
| `while (n--)` 也常见 | 后置自减同样是表达式，但它的值是**自减之前**的值 |
| 三目能嵌套 | 它是表达式，能出现在任何表达式位置 |
| `f(g())` 合法 | 调用是表达式 |
| `printf` 能返回字符数 | 调用有值 |
| `for` 的三个部分都能放表达式 | 它本来就是三个表达式槽位 |

**`while (--n)` 与 `while (n--)` 的差别同样由这条推出**：
前置版本交出减完的值，后置版本交出减之前的值，**两者差一次循环**。
完整的说明与数据见第 2.3 小节。

# 第 2 节 表达式的构成

## 2.1 操作数与运算符

**一个表达式由操作数与运算符组成**：

`Text`

```text
   1 + 2 * 3
   │   │ │ └─ 操作数
   │   │ └─── 运算符
   │   └───── 运算符
   └───────── 操作数
```

**运算符按操作数个数分**：

| 类别 | 例子 |
|---|---|
| 一元 | `-a`、`!a`、`*p`、`&a`、`++a`、`sizeof` |
| 二元 | `a + b`、`a = b`、`a[i]` |
| 三元 | **只有一个**：`a ? b : c` |

**二元运算符占绝大多数，三元只有条件运算符一个。**

## 2.2 左值与右值

**这是理解表达式的一条主线。**

**粗略的说法**：

| | 左值（lvalue） | 右值（rvalue） |
|---|---|---|
| **是什么** | 有**确定位置**的东西 | 只是一个**值** |
| **能否取地址** | **能**，`&x` 合法 | **不能** |
| **能否赋值** | **能**（若可写） | **不能** |
| **例子** | 变量、`*p`、`a[i]` | `1`、`a + b`、`f()` |

**「能不能取地址」是最实用的判据。**

**C 与 C++ 在这里有一处差异**：`++a = 5` 与 `&(a = 1)`
在 C 里失败、在 C++ 里通过，`a++ = 5` 则两边都失败。
**完整源码与报错原文见第 7.1 小节。**

**`a++` 给出的是「自增之前那个值」的副本，
没有可以赋值的位置**——因此两边都不允许。

**这条对照正好说明左值与右值的区别**：

| 写法 | 给出什么 | 能否赋值 |
|---|---|---|
| `++a` | `a` **本身**（已自增） | C++ 里能 |
| `a++` | `a` **旧值的副本** | 都不能 |

## 2.3 自增与自减：取值时机

**`++` 与 `--` 各有两个版本，区别只在一件事上：取值在自增之前还是之后。**

`Text`

```text
   ++a   先加，再把加完的值交出来
   a++   先把当前的值交出来，再加
```

`实测数据`
`C`

```c
/* inc_value.c    编译：gcc -std=c23 inc_value.c -o inc_value */
#include <stdio.h>

int main(void) {
    int a = 5;
    int r1 = ++a;      /* r1 = 6, a = 6    取的是「加完之后」 */
    int b = 5;
    int r2 = b++;      /* r2 = 5, b = 6    取的是「加之前」 */
    int c = 5;
    int r3 = --c;      /* r3 = 4, c = 4 */
    int d = 5;
    int r4 = d--;      /* r4 = 5, d = 4 */
    printf("%d %d %d %d\n", r1, r2, r3, r4);   /* 输出 6 5 4 5 */
    return 0;
}
```

**四个版本的区别只在表达式的取值上**：

| 写法 | 变量最终值 | 表达式的值 |
|---|---|---|
| `++a` | `a + 1` | **`a + 1`**（加完的值） |
| `a++` | `a + 1` | **`a`**（原来的值） |
| `--a` | `a - 1` | **`a - 1`** |
| `a--` | `a - 1` | **`a`** |

**四个版本的「变量最终值」都一样，不同的只有「表达式的值」。**

**这也解释了 `++a = 5` 与 `a++ = 5` 为什么一个能过一个不能**：
前者指代 `a` 本身，后者交出的是临时副本。

### 底层代价：后置要多留一份旧值

**后置版本更贵，因为它必须先把旧值留下来。**

`实测数据`
`C`

```c
/* inc_cost.c    编译：gcc -std=c23 -O0 -S inc_cost.c -o inc_cost.s */
int pre_inc(int a)  { return ++a; }
int post_inc(int a) { return a++; }
```

**`-O0` 下两个函数的汇编**：

`Assembly`

```asm
pre_inc:                        post_inc:
    movl  %ecx, 16(%rbp)            movl  %ecx, 16(%rbp)
    addl  $1, 16(%rbp)      ←就地加  movl  16(%rbp), %eax    ←先留旧值
    movl  16(%rbp), %eax    ←读回    leal  1(%rax), %edx     ←算新值
                                    movl  %edx, 16(%rbp)    ←写回
```

| 版本 | 指令数 | 关键差别 |
|---|---|---|
| `++a` | 3 条 | 就地加，然后读回结果 |
| `a++` | **4 条** | **先把旧值取到寄存器**，再算新值写回 |

**多出来的那一条 `movl 16(%rbp), %eax` 就是「保留旧值」的代价。**

### 循环里差一次

**这个差别在循环条件里会被放大。**

`实测数据`
`C`

```c
/* loop_once.c    编译：gcc -std=c23 loop_once.c -o loop_once */
#include <stdio.h>

int main(void) {
    int n1 = 3, c1 = 0;
    while (--n1) { c1++; }      /* 先减再判断：循环体执行 2 次 */

    int n2 = 3, c2 = 0;
    while (n2--) { c2++; }      /* 先判断再减：循环体执行 3 次 */

    printf("c1 = %d, c2 = %d\n", c1, c2);   /* 输出 c1 = 2, c2 = 3 */
    return 0;
}
```

**两者差的这一次循环，来自判断时用的是哪一个值**：

| 写法 | 判断时用哪个值 |
|---|---|
| `while (--n)` | **先减**，用减完的值判断 → `n` 变 0 时立即退出 |
| `while (n--)` | 用**当前值**判断，判断完才减 → `n` 为 0 的那一轮仍会进入 |

**因此两者不可互换。要判断「还剩几个」用前置，要「先把当前这个用掉」用后置。**

### 什么时候非用后置不可

**三处典型场合**：

`C`

```c
/* 一、要把旧值当索引用掉 */
arr[i++] = value;            /* 写入 arr[i]，然后 i 加一 */

/* 二、判断完再减 */
do { ... } while (j++ < 2);

/* 三、遍历到 0 为止，但循环体要处理 0 那一轮 */
while (n--) { process(n); }
```

**这三处的共同点是**：**当前这一轮要用「自增前」的值**。
**换成前置就会少处理一次。**

### 一条实用建议

> [!TIP]
> **不在意取值时机时，一律用前置版本（`++i`）。**
> 一是**少一条指令**；二是**对类类型，后置版本还要多一次对象的拷贝**，
> 这一类开销在循环里会累积。

**前置与后置的自增运算符，对类类型的重载写法不同**，
见【待补：05-类与面向对象/】。

# 第 3 节 运算符

**运算符决定表达式「做什么」，操作数决定「对谁做」。**

**同一个符号写在不同位置，可能是两个不同的运算符**：

| 符号 | 一元用法 | 二元用法 |
|---|---|---|
| `-` | `-a`：对 `a` 取负 | `a - b`：相减 |
| `+` | `+a`：对 `a` 做整型提升 | `a + b`：相加 |
| `*` | `*p`：解引用 | `a * b`：相乘 |
| `&` | `&a`：取地址 | `a & b`：按位与 |

**判断依据是操作数的个数**，不是符号本身。

## 3.1 分类

**C 与 C++ 共有的运算符**（按用途分组）：

| 组 | 运算符 | 结果类型 |
|---|---|---|
| 算术 | `+` `-` `*` `/` `%` | 两个操作数统一后的算术类型 |
| 自增自减 | `++` `--` | 操作数本身的类型 |
| 关系 | `==` `!=` `<` `>` `<=` `>=` | C：`int`　C++：`bool` |
| 逻辑 | `&&` `\|\|` `!` | C：`int`　C++：`bool` |
| 位运算 | `&` `\|` `^` `~` `<<` `>>` | 提升后左操作数的整型 |
| 赋值 | `=` 与十个复合赋值 | 左操作数的类型 |
| 取址与解引用 | `&` `*` | 指针 / 左值 |
| 成员访问 | `.` `->` `[]` | 成员类型 / 元素类型 |
| 其他 | `?:` `,` `sizeof` `(类型)` 转换 | 见各小节 |

**C++ 另有一批**：`::`、`new`、`delete`、`.*`、`->*`、`typeid`、
四种具名转换，以及 `noexcept`、`alignof`、`sizeof...`。

**C++ 的运算符还可以重载**：同一个符号在类类型上变成一次函数调用，
见第 6.2 小节；重载的写法归【待补：05-类与面向对象/】。

> [!IMPORTANT]
> **关系与逻辑运算符的结果类型，C 与 C++ 不同**：
> C 给出 `int`，C++ 给出 `bool`。
> 这是两者表达式规则里最容易忽略的一处差异，实测见第 3.3.1 与 3.4.2 小节。

## 3.2 算术运算符

**五个二元运算符与两个一元运算符**：

| 写法 | 名称 | 操作数要求 |
|---|---|---|
| `a + b` | 加法 | 算术类型；指针加整数另算 |
| `a - b` | 减法 | 算术类型；指针相减另算 |
| `a * b` | 乘法 | 算术类型 |
| `a / b` | 除法 | 算术类型 |
| `a % b` | 取模 | **只能是整型** |
| `+a` | 一元加 | 算术类型 |
| `-a` | 一元减 | 算术类型 |

**两个操作数类型不同时，先按《04-语法/02-数据类型与类型系统.md》第 5.3 小节统一**，
结果是统一之后的类型。**整型参与时还要先做整型提升**（同章节第 5.2 小节）。

**`%` 不接受浮点**，这是它在类型上唯一的特殊要求：

`实测数据`
`C`

```c
/* float_mod.c    编译：gcc -std=c23 float_mod.c -o float_mod （失败）
 * gcc 报错：error: invalid operands to binary % (have 'double' and 'double')
 */
#include <stdio.h>

int main(void) {
    double d = 5.0 % 2.0;       /* 浮点不能取模 */
    printf("%f\n", d);
    return 0;
}
```

**要对浮点取余，用数学库的 `fmod`**：

`实测数据`
`C`

```c
/* float_fmod.c    编译：gcc -std=c23 float_fmod.c -o float_fmod -lm */
#include <stdio.h>
#include <math.h>

int main(void) {
    printf("5.0 / 2.0       = %f\n", 5.0 / 2.0);           /* 2.500000 */
    printf("fmod(5.0, 2.0)  = %f\n", fmod(5.0, 2.0));      /* 1.000000 */
    printf("fmod(-5.0, 2.0) = %f\n", fmod(-5.0, 2.0));     /* -1.000000 */
    return 0;
}
```

### 3.2.1 整数除法向零截断

**整数除法不是「向下取整」，是「向零截断」——小数部分直接丢掉，不管正负。**

`文档`

> "When integers are divided, the result of the / operator is the algebraic quotient
> with any fractional part discarded. If the quotient a/b is representable, the
> expression (a/b)*b + a%b shall equal a; otherwise, the behavior of both a/b and
> a%b is undefined."
>
> —— N3220 §6.5.6

`文档`

> "For integral operands the / operator yields the algebraic quotient with any
> fractional part discarded; if the quotient a/b is representable in the type of
> the result, (a/b)*b + a%b is equal to a; otherwise, the behavior of both a/b
> and a%b is undefined."
>
> —— N4659 §8.6/4

**两份标准都用了 "discarded"（丢弃）这个词**，
N3220 的脚注把它说得更直白：**truncation toward zero**（向零截断）。

`实测数据`
`C`

```c
/* arith_sign.c    编译：gcc -std=c23 arith_sign.c -o arith_sign */
#include <stdio.h>

int main(void) {
    printf(" 7 /  2 = %d\n",  7 /  2);
    printf("-7 /  2 = %d\n", -7 /  2);
    printf(" 7 / -2 = %d\n",  7 / -2);
    printf("-7 / -2 = %d\n", -7 / -2);
    return 0;
}
```

| 写法 | 数学上的商 | 结果 | 说明 |
|---|---|---|---|
| `7 / 2` | 3.5 | **3** | 丢掉 0.5 |
| `-7 / 2` | -3.5 | **-3** | 丢掉 -0.5，**不是 -4** |
| `7 / -2` | -3.5 | **-3** | 商的符号由两数符号决定 |
| `-7 / -2` | 3.5 | **3** | |

**「向零」与「向下」在负数上分道扬镳**：`-7 / 2` 向零截断得 `-3`，
向下取整（`floor`）则应得 `-4`。**C 与 C++ 取的是前者。**

> [!WARNING]
> **想要向下取整，除法给不了。**
> `-7 / 2` 得 `-3`，要对负数向下取整需要另行处理。

### 3.2.2 取模的符号跟着被除数

**`%` 的结果与 `a - (a/b)*b` 相等**，这是由上一小节那条
`(a/b)*b + a%b == a` 的等式推出来的，也是标准对 `%` 唯一的约束。

`实测数据`
`C`

```c
/* arith_mod.c    编译：gcc -std=c23 arith_mod.c -o arith_mod */
#include <stdio.h>

int main(void) {
    printf(" 7 %%  2 = %d\n",  7 %  2);
    printf("-7 %%  2 = %d\n", -7 %  2);
    printf(" 7 %% -2 = %d\n",  7 % -2);
    printf("-7 %% -2 = %d\n", -7 % -2);
    printf("(-7/2)*2 + (-7%%2) = %d\n", (-7 / 2) * 2 + (-7 % 2));
    return 0;
}
```

| 写法 | 结果 | 符号 |
|---|---|---|
| `7 % 2` | **1** | 正 |
| `-7 % 2` | **-1** | **负** |
| `7 % -2` | **1** | 正 |
| `-7 % -2` | **-1** | 负 |

**结果的符号跟着左操作数（被除数），与右操作数无关。**

**最后一行 `(-7/2)*2 + (-7%2)` 的输出是 `-7`**，与标准要求的一致。

> [!TIP]
> **判断整除用 `a % b == 0`，这在四种符号组合下都成立**；
> 但**直接把 `%` 的结果当「余数」参与后续计算时要留意符号**：
> `-7 % 2` 是 `-1` 而不是 `1`。
> **要得到非负的余数，先转成无符号数，或写成 `(a % b + b) % b`。**

### 3.2.3 除以零

`文档`

> "The result of the / operator is the quotient from the division of the
> first operand by the second; the result of the % operator is the remainder.
> In both operations, if the value of the second operand is zero,
> the behavior is undefined."
>
> —— N3220 §6.5.6/6

`文档`

> "The binary / operator yields the quotient, and the binary % operator yields
> the remainder from the division of the first expression by the second.
> If the second operand of / or % is zero the behavior is undefined."
>
> —— N4659 §8.6/4

**整数除零是未定义行为。编译器给出的只是警告，编译仍然通过；
除数是变量时连警告都没有。**

`实测数据`
`C`

```c
/* div_zero.c    编译：gcc -std=c23 -Wall div_zero.c -o div_zero
 * gcc 输出：warning: division by zero [-Wdiv-by-zero]
 * 加 -Werror 后该警告才变成错误。
 */
#include <stdio.h>

int main(void) {
    int a = 1 / 0;              /* 除数是编译期常量 0：给警告 */
    int one = 1;
    int z = 0;
    int r = one / z;            /* 除数是变量：不产生任何警告 */
    double d = 1.0 / 0.0;       /* 浮点除零不是未定义行为，结果是 inf */
    printf("%d %d %f\n", a, r, d);
    return 0;
}
```

**警告只在编译期能看出除数是 0 时才给**：
除数是变量时编译器不知道它的值，一声不响。

**把除数是变量的那一行单独拿出来运行，进程不会输出结果，而是直接结束**：

`实测数据`
`C`

```c
/* div_zero_run.c    编译：gcc -std=c23 div_zero_run.c -o div_zero_run
 * 运行结果：先打印「开始计算」，随后进程以 0xC0000094 结束
 *          （0xC0000094 是 Windows 的整数除零异常）。
 */
#include <stdio.h>

int main(void) {
    int z = 0;
    printf("开始计算 1 / z\n");
    fflush(stdout);             /* 先冲掉缓冲区，否则看不到这一行 */
    int r = 1 / z;
    printf("r = %d\n", r);
    return 0;
}
```

**「未定义行为」在这里的具体表现是硬件异常**，程序被系统终止，
不是「算出一个奇怪的数」。**其余平台的异常编号不同。**

**同一份源码换一套环境，表现可能完全不同**：

`实测数据`

| 环境 | 运行结果 |
|---|---|
| Windows，`gcc` 15.2.0 | 打印「开始计算 1 / z」后进程以 **`0xC0000094`** 结束 |
| Linux，`gcc` 13.3.0 | 打印「开始计算 1 / z」与 **`r = 0`**，退出码 **0** |

**第二行连异常都没有，直接算出了 `0`。**
两份源码逐字相同，差别只在编译器——这正是「未定义」的含义：
**标准对结果不作任何要求，两种表现都不算错。**

**浮点除零不是未定义行为**，结果是无穷大或 `NaN`——
它与整数除零是两回事，不能互相类推。

> [!CAUTION]
> **除数是变量时，编译器不会替你检查。**
> 整数除法与取模之前，必须自己确认除数不为 0。

### 3.2.4 商装不下的时候

**`INT_MIN / -1` 的数学结果是 2147483648，装不进 `int`。**
标准对这种情形的规定是「未定义」：

`文档`

> "If an exceptional condition occurs during the evaluation of an expression
> (that is, if the result is not mathematically defined or not in the range of
> representable values for its type), the behavior is undefined."
>
> —— N3220 §6.5.1/5

**编译器只在两个操作数都是编译期常量时才提示**：

`实测数据`
`C`

```c
/* div_min.c    编译：gcc -std=c23 -Wall div_min.c -o div_min
 * gcc 输出：warning: integer overflow in expression of type 'int'
 *           results in '-2147483648' [-Woverflow]
 */
#include <stdio.h>
#include <limits.h>

int main(void) {
    int q = INT_MIN / -1;       /* 两个都是常量：给 -Woverflow 警告 */
    printf("%d\n", q);
    return 0;
}
```

**把这两个数换成变量，警告就消失了**：
`int a = INT_MIN, b = -1;` 之后再写 `a / b`，编译期没有任何输出。

### 3.2.5 溢出与回绕

**超出现有类型能表示的范围时，处理方式取决于有没有符号位。**

| 类型 | 行为 | 依据 |
|---|---|---|
| 无符号 | **回绕**（按 2^N 取模） | 定义明确 |
| 有符号 | **未定义行为** | N3220 §6.5.1/5 |

`文档`

> "The range of representable values for the unsigned type is 0 to 2^N − 1
> (inclusive). A computation involving unsigned operands can never produce an
> overflow, because arithmetic for the unsigned type is performed modulo 2^N."
>
> —— N3220 §6.2.5/11

`文档`

> "Unsigned integers shall obey the laws of arithmetic modulo 2^n where n is the
> number of bits in the value representation of that particular size of integer."
>
> —— N4659 §6.9.1/4

`实测数据`
`C`

```c
/* overflow.c    编译：gcc -std=c23 overflow.c -o overflow */
#include <stdio.h>
#include <limits.h>

int main(void) {
    unsigned u = UINT_MAX;
    u = u + 1;                  /* 无符号回绕：标准规定为模 2^N */
    printf("UINT_MAX + 1 = %u\n", u);       /* 0 */

    int i = INT_MAX;
    i = i + 1;                  /* 有符号溢出：未定义行为 */
    printf("INT_MAX + 1  = %d\n", i);       /* 本机为 -2147483648 */
    return 0;
}
```

**第二行的 `-2147483648` 只是本机的表现**，标准对它不作要求。

**同样的道理，编译期能算出来的溢出会得到一个警告**：

`实测数据`
`C`

```c
/* overflow_const.c    编译：gcc -std=c23 -Wall overflow_const.c -o overflow_const
 * gcc 输出：warning: integer overflow in expression of type 'int'
 *           results in '-2147483648' [-Woverflow]
 */
#include <stdio.h>
#include <limits.h>

int main(void) {
    int k = INT_MAX + 1;        /* 编译期能看出溢出 */
    printf("%d\n", k);
    return 0;
}
```

**无符号的回绕与截断是同一件事**，完整的推导见
《04-语法/02-数据类型与类型系统.md》第 2.6 小节；
三类行为自由度的划分见《01-编译器/00-语言的实现.md》第 3 节。

> [!CAUTION]
> **有符号溢出是未定义行为，不是「变成负数」。**
> 优化器有权假设它不会发生，据此删掉判断、改变循环次数。
> 上述 `-2147483648` 只是本机在 `-O0` 下的表现。

### 3.2.6 一元 `+` 与 `-`

**这两个运算符做的事比看上去多一些：它们先对操作数做整型提升，再取正负**，
结果的类型是**提升之后**的类型。

`文档`

> "The result of the unary + operator is the value of its (promoted) operand.
> The integer promotions are performed on the operand, and the result has the
> promoted type."
>
> —— N3220 §6.5.4.3/2

**这一条在窄类型上会带来意外**：

`实测数据`
`C`

```c
/* unary_promote.c    编译：gcc -std=c23 unary_promote.c -o unary_promote */
#include <stdio.h>

int main(void) {
    unsigned char c = 200;
    printf("c                 = %u\n", (unsigned)c);  /* 200 */
    printf("+c                = %d\n", +c);           /* 200  */
    printf("-c                = %d\n", -c);           /* -200，不是 56 */
    printf("sizeof(+c)        = %zu\n", sizeof(+c));  /* 4：已经是 int */
    printf("(unsigned char)-c = %u\n", (unsigned char)-c);  /* 56 */
    return 0;
}
```

**`-c` 得到 `-200`，而不是「在 1 字节上取负」的 `56`**：
`c` 先被提升成 `int` 的 200，再取负得到 -200，这个值装得下。
**只有再转回 `unsigned char`，才会截出 `56`。**

**`+a` 不改变值，只做提升**，因此它常被用来「把窄类型显式提到 `int`」。

## 3.3 关系运算符

**这一组运算符问的是「两个值之间是什么关系」，答案只有「是」与「否」。**
六种运算符里，`==` 与 `!=` 管相等，其余四种管大小。

### 3.3.1 六种与结果类型

**`==` `!=` `<` `>` `<=` `>=`** 六种，操作数可以是算术类型、枚举、指针。
**两个操作数类型不同时先做常用算术转换。**

`文档`

> "Each of the operators < (less than), > (greater than), <= (less than or equal
> to), and >= (greater than or equal to) shall yield 1 if the specified relation
> is true and 0 if it is false. The result has type int."
>
> —— N3220 §6.5.9/7

`文档`

> "The operators < (less than), > (greater than), <= (less than or equal to),
> and >= (greater than or equal to) all yield false or true.
> The type of the result is bool."
>
> —— N4659 §8.9/1

**同一份程序分别用 `gcc` 与 `g++` 编译，结果类型就现出差别**：

`实测数据`
`C`

```c
/* logical_result.c    编译：gcc -std=c23 logical_result.c -o logical_result */
#include <stdio.h>

int main(void) {
    printf("sizeof(1 < 2)  = %zu\n", sizeof(1 < 2));    /* 4：int */
    printf("sizeof(1 == 1) = %zu\n", sizeof(1 == 1));   /* 4 */
    printf("sizeof(!1)     = %zu\n", sizeof(!1));       /* 4 */
    printf("sizeof(1 && 2) = %zu\n", sizeof(1 && 2));   /* 4 */
    printf("sizeof(1 & 2)  = %zu\n", sizeof(1 & 2));    /* 4：按位与也是 int */
    return 0;
}
```

**同一份源码直接交给 `g++ -std=c++17` 编译，前四行都变成 1**，
第五行仍是 4（按位与与逻辑运算无关，两边的类型都由操作数决定）。

> [!IMPORTANT]
> **C 里比较的结果是 `int`，所以它是「一个数」；**
> **C++ 里比较的结果是 `bool`，所以它是「一个逻辑值」。**
> 这一处差异会在重载、模板与 `sizeof` 上显出后果。

**有符号与无符号混用是这一组运算符最经典的坑**：
`-1 < 1u` 的结果是**假**，因为 `-1` 先被转成了无符号数。
完整规则与实测见《04-语法/02-数据类型与类型系统.md》第 5.4 小节。

### 3.3.2 结果只能当 0 与 1 用

**在 C 里比较的结果是整数，因此可以直接参与运算**；
在 C++ 里它是 `bool`，参与运算时会先提升成 `int`。

`实测数据`
`C`

```c
/* rel_int.c    编译：gcc -std=c23 rel_int.c -o rel_int */
#include <stdio.h>

int main(void) {
    int a = 3, b = 5;
    int cnt = (a < b) + (a == b) + (a > b);     /* 三个结果相加 */
    printf("cnt = %d\n", cnt);                  /* 1：只有一个是真 */
    printf("(a < b) * 100 = %d\n", (a < b) * 100);   /* 100 */
    return 0;
}
```

**这与「三个条件里成立几个」是同一个意思**，
它的写法依赖「真就是 1、假就是 0」这条规定。

### 3.3.3 链式比较不成立

**数学里的 `a < b < c` 在 C 与 C++ 里不成立**，因为 `<` 是左结合的二元运算符：

`文档`

> "The relational operators group left-to-right. [Example: a<b<c means (a<b)<c
> and not (a<b)&&(b<c). —end example]"
>
> —— N4659 §8.9/1

`实测数据`
`C`

```c
/* chained.c    编译：gcc -std=c23 -Wall chained.c -o chained
 * gcc 输出：warning: comparisons like 'X<=Y<=Z' do not have their
 *           mathematical meaning [-Wparentheses]
 */
#include <stdio.h>

int main(void) {
    int a = 3, b = 2, c = 1;
    printf("a > b > c = %d\n", a > b > c);                    /* 0：假 */
    printf("(a > b) && (b > c) = %d\n", (a > b) && (b > c));  /* 1：真 */
    return 0;
}
```

**`3 > 2 > 1` 在数学上成立，在 C 与 C++ 里却是假**：
先算 `3 > 2` 得 `1`，再算 `1 > 1` 得 `0`。

**`gcc` 与 `g++` 在 `-Wall` 下都会给出 `-Wparentheses` 警告**。

### 3.3.4 浮点不要用 `==`

**二进制浮点表示不了 `0.1` 与 `0.2` 这样的十进制小数**，
它们的和与 `0.3` 不是同一个数。

`实测数据`
`C`

```c
/* float_eq.c    编译：gcc -std=c23 float_eq.c -o float_eq -lm */
#include <stdio.h>
#include <math.h>

int main(void) {
    double x = 0.1 + 0.2;
    printf("0.1 + 0.2 = %.20f\n", x);                       /* 0.30000000000000004441 */
    printf("x == 0.3  = %d\n", x == 0.3);                   /* 0：不相等 */
    printf("x <  0.3  = %d\n", x <  0.3);                   /* 0：它比 0.3 大 */
    printf("fabs(x - 0.3) < 1e-9 = %d\n", fabs(x - 0.3) < 1e-9);   /* 1 */
    return 0;
}
```

**`<` 与 `>` 可以放心用，`==` 与 `!=` 不行**——
前者问的是大小关系，后者要求两个数逐位相等。

> [!TIP]
> **比较两个浮点数是否「相等」，改成比较它们的差是否小于一个容差。**
> 容差取多少取决于问题本身，`1e-9` 只是一个常见起点。

### 3.3.5 指针比较

**`==` 与 `!=` 可以比较任意两个指针**，包括与 `NULL` 比较。
**`<` `>` 这一组只对指向同一个数组（或同一聚合体的成员）的指针有意义。**
**两份标准对「其余情形」的规定并不相同**：

`文档`

> "In all other cases, the behavior is undefined."
>
> —— N3220 §6.5.9/6

`文档`

> "Otherwise, neither pointer compares greater than the other. ... Otherwise,
> the result of each of the operators is unspecified."
>
> —— N4659 §8.9/3.3、§8.9/4

**C 把与数组无关的指针大小比较归入未定义行为，C++ 归入未指定。**
两者都不能依赖，但性质不同：前者编译器可以任意处置，后者只是不规定用哪一种结果。

**相等比较没有这条限制**，两份标准都给出了完整刻画：

`文档`

> "Two pointers compare equal if and only if both are null pointers, both are
> pointers to the same object ... or function, both are pointers to one past the
> last element of the same array object, ..."
>
> —— N3220 §6.5.10/7

`实测数据`
`C`

```c
/* ptr_cmp.c    编译：gcc -std=c23 ptr_cmp.c -o ptr_cmp */
#include <stdio.h>

int main(void) {
    int a[4] = {0};
    int *p = &a[1], *q = &a[3];
    printf("p < q      = %d\n", p < q);          /* 1 */
    printf("q - p      = %td\n", q - p);         /* 2：元素个数，不是字节数 */
    int *n = NULL;
    printf("n == NULL  = %d\n", n == NULL);      /* 1 */
    return 0;
}
```

**`q - p` 得到的是元素个数**：两个指针相减先按元素大小缩放，
这一条属于指针运算，完整讲解见《04-语法/07-数组、指针与引用.md》第 2 节。

## 3.4 逻辑运算符

**这一组运算符把任意值折成「真」或「假」，并且可能不去算右边那一半。**
两条性质各自带来一串用法与陷阱。

### 3.4.1 三种与「真」的判据

**`!` 是一元，`&&` 与 `||` 是二元。**
它们的操作数不限于比较式，**任何标量（算术类型或指针）都可以**：
**非 0 为真，0 为假。**

`实测数据`
`C`

```c
/* logical_scalar.c    编译：gcc -std=c23 logical_scalar.c -o logical_scalar */
#include <stdio.h>

int main(void) {
    int v = 7;
    int *p = &v;
    printf("p && *p == 7 = %d\n", p && *p == 7);   /* 1 */
    printf("NULL || 1    = %d\n", NULL || 1);      /* 1 */
    printf("0.0 为真吗   = %d\n", 0.0 ? 1 : 0);    /* 0 */
    printf("0.5 为真吗   = %d\n", 0.5 ? 1 : 0);    /* 1 */
    return 0;
}
```

**`if (p)`、`while (n)` 这些写法都建立在这条规定上**，
不需要写成 `if (p != NULL)` 或 `while (n != 0)`。

`文档`

> "The && operator shall yield 1 if both of its operands compare unequal to 0;
> otherwise, it yields 0. The result has type int."
>
> —— N3220 §6.5.14

### 3.4.2 结果只有 0 与 1

**`&&` 与 `||` 交出的不是操作数的值，只是「真或假」**，
这一点与某些语言不同，与按位运算符也不同。

`实测数据`
`C`

```c
/* logical_value.c    编译：gcc -std=c23 logical_value.c -o logical_value */
#include <stdio.h>

int main(void) {
    printf("!5     = %d\n", !5);        /* 0 */
    printf("2 && 3 = %d\n", 2 && 3);    /* 1，不是 3 */
    printf("0 || 7 = %d\n", 0 || 7);    /* 1，不是 7 */
    printf("2 & 3  = %d\n", 2 & 3);     /* 2：按位与，按位算 */
    printf("!!42   = %d\n", !!42);      /* 1 */
    printf("!!0    = %d\n", !!0);       /* 0 */
    return 0;
}
```

**`2 && 3` 得 1，而 `2 & 3` 得 2**，
这一行对照把两类运算符的分工摆在了一起。

**`!!x` 是把任意标量归一化成 0 或 1 的固定写法**：
第一个 `!` 判「是否为零」，第二个 `!` 再取反回来。
在 C++ 里 `(bool)x` 更直接，在 C 里 `!!x` 是最短的写法。

**结果类型同样分岔**：C 里是 `int`，C++ 里是 `bool`（第 3.3.1 小节的程序已一并测出）。

### 3.4.3 短路求值

**`&&` 的左边为假时，右边不求值；`||` 的左边为真时，右边不求值。**

`文档`

> "Unlike the bitwise binary & operator, the && operator guarantees left-to-right
> evaluation; ... If the first operand compares equal to 0, the second operand
> is not evaluated."
>
> —— N3220 §6.5.14

**这条规定的实测、两个用途与三个容易混淆之处，见第 4.2 小节。**

## 3.5 位运算符

### 3.5.1 四个位逻辑运算符

**`~` 是一元取反，`&` `|` `^` 是二元**，它们**按位独立计算，位与位之间没有进位**：

| 写法 | 名称 | 逐位规则 |
|---|---|---|
| `~a` | 按位取反 | 0 变 1，1 变 0 |
| `a & b` | 按位与 | 两位都是 1 才得 1 |
| `a \| b` | 按位或 | 有一位是 1 就得 1 |
| `a ^ b` | 按位异或 | 两位不同得 1，相同得 0 |

**结果类型是提升之后左操作数的类型。**
三个二元运算符都**没有短路性质**，两边一律求值，
这一点与 `&&`、`||` 的区别见第 4.2 小节。

`实测数据`
`C`

```c
/* bitwise.c    编译：gcc -std=c23 bitwise.c -o bitwise */
#include <stdio.h>

int main(void) {
    printf("0x0F & 0x35 = 0x%02X\n", 0x0F & 0x35);   /* 0x05 */
    printf("0x0F | 0x35 = 0x%02X\n", 0x0F | 0x35);   /* 0x3F */
    printf("0x0F ^ 0x35 = 0x%02X\n", 0x0F ^ 0x35);   /* 0x3A */
    printf("~0          = %d\n", ~0);                /* -1 */
    printf("~0u         = 0x%08X\n", ~0u);           /* 0xFFFFFFFF */
    return 0;
}
```

**最后两行是同一件事的两种类型**：`~0` 在 `int` 上是 `-1`，
`~0u` 在 `unsigned int` 上是 `0xFFFFFFFF`。**位模式相同，读出来的值不同。**

### 3.5.2 整型提升先发生

**对窄类型取反时，先提升再取反**，这会让结果比预期「宽」：

`实测数据`
`C`

```c
/* bitwise_promote.c    编译：gcc -std=c23 bitwise_promote.c -o bitwise_promote */
#include <stdio.h>

int main(void) {
    unsigned char b = 0x0F;
    printf("b                 = 0x%02X\n", b);                   /* 0x0F */
    printf("~b                = 0x%08X\n", ~b);                  /* 0xFFFFFFF0 */
    printf("(unsigned char)~b = 0x%02X\n", (unsigned char)~b);   /* 0xF0 */
    return 0;
}
```

**`~b` 不是 `0xF0`，而是 `0xFFFFFFF0`**：
`b` 先被提升成 `int` 的 `0x0000000F`，取反后高 28 位全变成 1。
**把结果截回一个字节才是 `0xF0`。**

**整型提升的完整规则见《04-语法/02-数据类型与类型系统.md》第 5.2 小节。**

### 3.5.3 移位

**`a << n` 左移，`a >> n` 右移**，移位的方向与「位往哪边挪」一致。
**左移空出的低位补 0；右移空出的高位补什么，取决于类型**（见下一小节）。

**两个操作数都先做整型提升，结果的类型是提升后左操作数的类型。**

**左移在不出界时等于乘 2 的幂**：

`实测数据`
`C`

```c
/* shift_mul.c    编译：gcc -std=c23 shift_mul.c -o shift_mul */
#include <stdio.h>

int main(void) {
    int x = 5;
    printf("x * 2  = %d, x << 1 = %d\n", x * 2, x << 1);   /* 10, 10 */
    printf("x * 4  = %d, x << 2 = %d\n", x * 4, x << 2);   /* 20, 20 */
    return 0;
}
```

**「不出界」是这句话的前提**，一旦左移把有效位移出类型范围，行为就是未定义（第 3.5.5 小节）。
**右移则不能这样类推**，原因是补位规则：

`实测数据`
`C`

```c
/* shift_vs_div.c    编译：gcc -std=c23 shift_vs_div.c -o shift_vs_div */
#include <stdio.h>

int main(void) {
    printf("-7 / 2  = %d\n", -7 / 2);     /* -3：除法向零截断 */
    printf("-7 >> 1 = %d\n", -7 >> 1);    /* -4：算术右移向下取整 */
    printf(" 7 / 2  = %d\n",  7 / 2);     /* 3 */
    printf(" 7 >> 1 = %d\n",  7 >> 1);    /* 3 */
    return 0;
}
```

**正数上两者一致，负数上不一致**：除法向零截断，算术右移向下取整。

### 3.5.4 右移补什么

**左移补 0 没有争议，右移补什么取决于类型与实现。**

`实测数据`
`C`

```c
/* shift_fill.c    编译：gcc -std=c23 shift_fill.c -o shift_fill */
#include <stdio.h>

int main(void) {
    printf("-8 >> 1 = %d\n", -8 >> 1);              /* -4：符号位被保留 */
    printf("-1 >> 1 = %d\n", -1 >> 1);              /* -1：补进来的是 1 */
    printf(" 8 >> 1 = %d\n", 8 >> 1);               /*  4：正数正常 */
    unsigned u = 0x80000000u;
    printf("0x80000000u >> 1 = 0x%X\n", u >> 1);    /* 0x40000000：补 0 */
    return 0;
}
```

**规则**：

| 类型 | 右移时补什么 |
|---|---|
| 无符号 | **一定补 0**，规则明确 |
| 有符号且非负 | 补 0，等价于除以 2 的幂后向下取整 |
| 有符号且为负 | **由实现决定**：算术右移补符号位，逻辑右移补 0 |

`文档`

> "The result of E1 >> E2 is E1 right-shifted E2 bit positions. ... If E1 has a
> signed type and a negative value, the resulting value is implementation-defined."
>
> —— N3220 §6.5.8

**本教材用的三个环境都是算术右移**（补符号位），
但这属于「实现定义行为」，不能跨平台依赖。

> [!TIP]
> **要对一个数做位运算时，先用 `unsigned`。**
> 这样补位规则明确，不会有意外。

### 3.5.5 移位量越界与负数左移

**移位量不能是负数，也不能大于等于左操作数提升后的位宽**，
否则是未定义行为：

`文档`

> "If the value of the right operand is negative or is greater than or equal to
> the width of the promoted left operand, the behavior is undefined."
>
> —— N3220 §6.5.8

`实测数据`
`C`

```c
/* shift_count.c    编译：gcc -std=c23 -Wall shift_count.c -o shift_count
 * gcc 输出：warning: left shift count >= width of type [-Wshift-count-overflow]
 *           warning: left shift count is negative   [-Wshift-count-negative]
 *           warning: right shift count >= width of type [-Wshift-count-overflow]
 */
#include <stdio.h>

int main(void) {
    int c = 32;
    unsigned u = 1u;
    printf("1 << 32        = %d\n", 1 << 32);   /* 编译期常量：给警告，本机 0 */
    printf("1u << c（c=32）= %u\n", u << c);     /* 变量：无警告，本机 1 */
    printf("1 << -1        = %d\n", 1 << -1);   /* 负数移位量：给警告，本机 -2147483648 */
    printf("1u >> 32       = %u\n", u >> 32);   /* 给警告，本机 0 */
    return 0;
}
```

**同一件事的两种写法给出了不同的结果**：常量 `1 << 32` 由编译器折叠成 0，
变量 `u << c` 交给机器指令执行，而机器把移位量按 32 取模，于是结果成了 1。
**两个结果都不作数，因为整段代码是未定义行为。**

**负数左移同样越界**：

`实测数据`
`C`

```c
/* shift_ub.c    编译：gcc -std=c23 -Wall -Wextra shift_ub.c -o shift_ub
 * gcc 输出：warning: left shift of negative value [-Wshift-negative-value]
 */
#include <stdio.h>

int main(void) {
    printf("-1 << 1  = %d\n", -1 << 1);     /* 本机 -2：未定义行为 */
    printf("1 << 31  = %d\n", 1 << 31);     /* 本机 -2147483648：未定义行为，无警告 */
    printf("1u << 31 = %u\n", 1u << 31);    /* 2147483648：无符号，定义明确 */
    return 0;
}
```

`文档`

> "If E1 has a signed type and nonnegative value, and E1×2^E2 is representable in
> the result type, then that is the resulting value; otherwise, the behavior is
> undefined."
>
> —— N3220 §6.5.8

**`1 << 31` 把 1 移进了符号位，`-1 << 1` 的左操作数是负数，两者都是未定义行为**，
`-Wall -Wextra` 只对后者给出警告。**第三行的 `1u << 31` 是无符号运算，结果明确。**

> [!CAUTION]
> **没有警告不等于合法。**
> `1 << 31` 编译时一声不响，运行时得到的却是未定义行为的结果。

### 3.5.6 位运算的固定写法

**位运算最常见的用途是管理一组标志位**，做法固定：

`实测数据`
`C`

```c
/* bitmask.c    编译：gcc -std=c23 bitmask.c -o bitmask */
#include <stdio.h>

int main(void) {
    unsigned flags = 0;

    flags |= (1u << 3);                     /* 置位：第 3 位置 1 */
    printf("置位后    flags = 0x%08X\n", flags);      /* 0x00000008 */

    int on = (flags >> 3) & 1u;             /* 取位：取出第 3 位 */
    printf("第 3 位         = %d\n", on);              /* 1 */

    flags ^= (1u << 3);                     /* 翻转：第 3 位取反 */
    printf("翻转后    flags = 0x%08X\n", flags);      /* 0x00000000 */

    flags |= 0xFFu;
    flags &= ~0xFFu;                        /* 清位：低 8 位清零 */
    printf("清位后    flags = 0x%08X\n", flags);      /* 0x00000000 */

    unsigned v = 0xABCD1234u;
    printf("取低 8 位       = 0x%02X\n", v & 0xFFu);            /* 0x34 */
    printf("取高 8 位       = 0x%02X\n", (v >> 24) & 0xFFu);    /* 0xAB */
    return 0;
}
```

**四条固定写法**：

| 目的 | 写法 |
|---|---|
| 置第 n 位 | `x \|= (1u << n)` |
| 清第 n 位 | `x &= ~(1u << n)` |
| 翻转第 n 位 | `x ^= (1u << n)` |
| 取第 n 位 | `(x >> n) & 1u` |

**其中「清位」必须用 `~`**：`x & (1u << n)` 是取位，不是清位。

**哪些位运算属于技巧、哪些属于本意，见
《04-语法/14-奇技淫巧与优化.md》第 6.3 小节；
寄存器上的置位与清位套路见《01-编译器/03-嵌入式与交叉编译.md》第 4.4 小节。**

### 3.5.7 `&` 与 `%` 的关系

**对 2 的幂取模，可以用按位与代替——但只限非负数。**

`实测数据`
`C`

```c
/* mod_pow2.c    编译：gcc -std=c23 mod_pow2.c -o mod_pow2 */
#include <stdio.h>

int main(void) {
    int x = 13;
    printf(" 13 %% 8 = %d,  13 & 7 = %d\n", x % 8, x & 7);   /* 5, 5 */
    x = -7;
    printf(" -7 %% 8 = %d,  -7 & 7 = %d\n", x % 8, x & 7);   /* -7, 1 */
    return 0;
}
```

**`-7 % 8` 是 `-7`（符号跟着被除数），`-7 & 7` 是 `1`**，
两者在负数上不同。**`&` 拿到的是低三位的位模式，`%` 拿到的是带符号的余数。**

## 3.6 赋值运算符

### 3.6.1 简单赋值

**`=` 把右操作数转成左操作数的类型后存进去，整个表达式的值是「赋值之后左操作数的值」。**

`文档`

> "An assignment operator stores a value in the object designated by the left
> operand. An assignment expression has the value of the left operand after the
> assignment, but is not an lvalue."
>
> —— N3220 §6.5.17.1

`文档`

> "All require a modifiable lvalue as their left operand and return an lvalue
> referring to the left operand. ... The right operand is sequenced before the
> left operand."
>
> —— N4659 §8.18/1

**两句话只差一处：C 里赋值的结果不是左值，C++ 里是。**
这一处分岔的完整展开见第 7.1 小节。

**赋值右结合，因此可以连写**：

`实测数据`
`C`

```c
/* assign_chain.c    编译：gcc -std=c23 assign_chain.c -o assign_chain */
#include <stdio.h>

int main(void) {
    int a, b, c;
    a = b = c = 3;                  /* 右结合：a = (b = (c = 3)) */
    printf("a = %d, b = %d, c = %d\n", a, b, c);    /* 3, 3, 3 */

    double d;
    int n;
    n = d = 1.5;                    /* 先算 d = 1.5，值 1.5 再转成 int 赋给 n */
    printf("d = %f, n = %d\n", d, n);               /* 1.500000, 1 */
    return 0;
}
```

**`n = d = 1.5` 里发生了一次转换**：
`d = 1.5` 的值是 `1.5`（`double`），赋给 `n` 时截断成 `1`。

### 3.6.2 复合赋值的等价规则

**十个复合赋值运算符都可以展开成「算一次再把结果存回去」**：

`文档`

> "A compound assignment of the form E1 op= E2 is equivalent to the simple
> assignment expression E1 = E1 op (E2), except that the lvalue E1 is evaluated
> only once."
>
> —— N3220 §6.5.17.3/4

**`except` 之后那半句是关键**：左操作数**只求值一次**，而不是两次。

`实测数据`
`C`

```c
/* assign_once.c    编译：gcc -std=c23 assign_once.c -o assign_once */
#include <stdio.h>

int calls = 0;
int next(void) { calls++; return 0; }       /* 每次求值都记一次数 */

int main(void) {
    int a[2] = {0, 0};

    a[next()] += 5;                          /* 复合赋值：下标只求值一次 */
    printf("a[0] = %d, 下标被求值 %d 次\n", a[0], calls);

    a[0] = 0; calls = 0;                     /* 复位，两次从同一状态出发 */
    a[next()] = a[next()] + 5;               /* 展开写法：下标求值两次 */
    printf("a[0] = %d, 下标被求值 %d 次\n", a[0], calls);
    return 0;
}
```

| 写法 | 下标被求值的次数 | `a[0]` |
|---|---|---|
| `a[next()] += 5` | **1** | 5 |
| `a[next()] = a[next()] + 5` | **2** | 5 |

**两次的最终结果相同，代价却不同**：展开写法里那个下标表达式被写了两遍，
于是也算了两遍。**如果下标里带 `i++` 这类副作用，两遍就会出错。**

> [!CAUTION]
> **不要照着等价规则做文本替换。**
> 规则里的 `E1` 是同一段代码，把它抄两遍会让副作用发生两次；
> 若两次修改同一个变量，行为还是未定义的。

**括号也在规则里**：`a *= b + 1` 等价于 `a = a * (b + 1)`，
右边的 `+1` 先算，实测得到 `2 * 4 = 8`。

### 3.6.3 两侧的求值顺序：C 与 C++ 相反

**C++17 起明确规定：赋值先算右边，再算左边。**
C 则明确规定：**两边谁先算，不作规定。**

`文档`

> "The side effect of updating the stored value of the left operand is sequenced
> after the value computations of the left and right operands.
> The evaluations of the operands are unsequenced."
>
> —— N3220 §6.5.17.1/3

`文档`

> "In all cases, the assignment is sequenced after the value computation of the
> right and left operands, and before the value computation of the assignment
> expression. The right operand is sequenced before the left operand."
>
> —— N4659 §8.18/1

`实测数据`
`C`

```c
/* assign_order.c    编译：gcc -std=c23 assign_order.c -o assign_order
 *                   编译：g++ -std=c++17 assign_order.c -o assign_order_cpp
 */
#include <stdio.h>

int lhs(void) { printf("  先算左边\n"); return 0; }
int rhs(void) { printf("  先算右边\n"); return 1; }

int a[2];

int main(void) {
    a[lhs()] = rhs();
    printf("a[0] = %d\n", a[0]);
    return 0;
}
```

| 编译器 | `-O0` 下的顺序 |
|---|---|
| `gcc -std=c23` | **先算左边**，再算右边 |
| `g++ -std=c++17` | **先算右边**，再算左边 |

**同一个程序，同一份源码，换一个编译器顺序就反过来了。**
`g++` 在 `-O2` 下依然是先右后左，与标准的要求一致。

**C 侧的顺序属于「未指定」**，完整的规则与实测见第 4.1 小节。

### 3.6.4 十个复合赋值运算符

`实测数据`

| 运算符 | 等价于 | 结果 |
|---|---|---|
| `+=` | `a = a + b` | 100 `+=` 5 → **105** |
| `-=` | `a = a - b` | 105 `-=` 5 → **100** |
| `*=` | `a = a * b` | 100 `*=` 2 → **200** |
| `/=` | `a = a / b` | 200 `/=` 4 → **50** |
| `%=` | `a = a % b` | 50 `%=` 7 → **1** |
| `&=` | `a = a & b` | `0b1100 &= 0b1010` → **8** |
| `\|=` | `a = a \| b` | 8 `\|=` 1 → **9** |
| `^=` | `a = a ^ b` | 9 `^=` 15 → **6** |
| `<<=` | `a = a << b` | 6 `<<=` 2 → **24** |
| `>>=` | `a = a >> b` | 24 `>>=` 1 → **12** |

**`>>=` 对负数同样受实现定义影响**，
规则与第 3.5.4 小节的右移一致。

**复合赋值里含有一次到左操作数类型的转换**：

`实测数据`
`C`

```c
/* compound_char.c    编译：gcc -std=c23 -Wall -Wextra -Wconversion compound_char.c -o compound_char */
#include <stdio.h>

int main(void) {
    char c = 120;
    c += 20;                /* 等价于 c = (char)(c + 20)：回绕 */
    printf("c += 20 之后 c = %d\n", c);          /* -116 */

    char d = 120;
    d = d + 20;             /* 展开写法同样会转回 char */
    printf("d = d + 20 之后 d = %d\n", d);       /* -116 */
    return 0;
}
```

**两种写法都得到 `-116`**，因为 `char` 装不下 140。
**它们的差别只在求值次数**，不在转换上。

## 3.7 取址、解引用与成员访问

### 3.7.1 一元 `&` 与 `*`

**`&a` 得到 `a` 的地址，`*p` 得到 `p` 指向的对象。**
两个运算符互为逆运算，但**方向不同**：

| 写法 | 结果 | 是不是左值 |
|---|---|---|
| `&a` | 指向 `a` 的指针 | 不是（是指针值） |
| `*p` | `p` 指向的那个对象 | **是** |

`文档`

> "The unary * operator denotes indirection. ... if it points to an object, the
> result is an lvalue designating the object."
>
> —— N3220 §6.5.4.2

**`*p` 是左值，这就是它能被赋值的原因**，也是第 2.2 小节说的「能不能取地址」判据的另一面。

`实测数据`
`C`

```c
/* addr_deref.c    编译：gcc -std=c23 addr_deref.c -o addr_deref */
#include <stdio.h>

int main(void) {
    int x = 5;
    int *p = &x;
    *p = 7;                                  /* 通过指针改 x */
    printf("x            = %d\n", x);        /* 7 */
    printf("*&x          = %d\n", *&x);      /* 7：先取地址再解引用，回到原对象 */
    printf("&*p 与 p 相同 = %d\n", &*p == p); /* 1 */
    printf("sizeof(&x)   = %zu\n", sizeof(&x));   /* 8：指针的宽度 */
    return 0;
}
```

> [!CAUTION]
> **`&` 不能作用于位域，`*` 不能作用于无效指针。**
> 对空指针或已释放的内存解引用是未定义行为，
> 完整讲解见《04-语法/07-数组、指针与引用.md》。

### 3.7.2 `.` 与 `->`

**`.` 用于对象，`->` 用于指针，`q->x` 就是 `(*q).x`。**

`实测数据`
`C`

```c
/* member_access.c    编译：gcc -std=c23 member_access.c -o member_access */
#include <stdio.h>

struct Point { int x; int y; };

int main(void) {
    struct Point p = {1, 2};
    struct Point *q = &p;

    printf("p.x     = %d\n", p.x);       /* 1 */
    printf("q->x    = %d\n", q->x);      /* 1 */
    printf("(*q).x  = %d\n", (*q).x);    /* 1 */
    return 0;
}
```

**`->` 存在的唯一理由就是省掉那对括号**：
`*q.x` 会先算 `.`，得到 `*(q.x)` 而不是 `(*q).x`，
而 `q.x` 本身就是错的（`q` 是指针，没有成员）。

**两种写法的编译结果完全相同**，完整实测（含两条报错原文）见
《04-语法/08-结构体、联合体与 enum.md》第 1.4 小节。

### 3.7.3 `[]` 是二元运算符

**`a[i]` 的定义就是 `*(a + i)`**，两边对称，因此交换也成立：

`实测数据`
`C`

```c
/* subscript.c    编译：gcc -std=c23 subscript.c -o subscript */
#include <stdio.h>

int main(void) {
    int a[3] = {10, 20, 30};
    printf("a[1]     = %d\n", a[1]);       /* 20 */
    printf("*(a + 1) = %d\n", *(a + 1));   /* 20 */
    printf("1[a]     = %d\n", 1[a]);       /* 20：下标是运算符，不是语法 */
    return 0;
}
```

**`1[a]` 能编过不是玩笑，它是「`a[i]` 就是 `*(a + i)`」的直接证据**，
语法糖的识别方法见《04-语法/01-一些基础概念.md》第 1.5 小节。

**后缀 `++` 与 `[]`、`*` 叠在一起时也按优先级拆开**：

`实测数据`
`C`

```c
/* deref_inc.c    编译：gcc -std=c23 deref_inc.c -o deref_inc */
#include <stdio.h>

int main(void) {
    int a[3] = {10, 20, 30};
    int *p = a;

    printf("*p++ = %d\n", *p++);    /* 10：等价于 *(p++)，先用后移 */
    printf("*++p = %d\n", *++p);    /* 30：等价于 *(++p)，先移后用 */
    printf("++*p = %d\n", ++*p);    /* 31：等价于 ++(*p)，改的是元素本身 */
    return 0;
}
```

**三行的差别全在 `++` 与 `*` 的结合顺序上**：
后缀 `++` 优先级最高，前缀 `++` 与 `*` 同级且从右往左结合。

> [!CAUTION]
> **`[]` 不做边界检查。**
> `a[3]` 在长度为 3 的数组上是未定义行为，越界读写不会报错。

## 3.8 条件运算符

### 3.8.1 只求值一支

**`a ? b : c` 先算 `a`，再按结果只算 `b` 或 `c` 中的一个。**

`文档`

> "The first operand is evaluated; there is a sequence point between its
> evaluation and the evaluation of the second or third operand (whichever is
> evaluated). The second operand is evaluated only if the first compares unequal
> to 0; the third operand is evaluated only if the first compares equal to 0."
>
> —— N3220 §6.5.16/5

`实测数据`
`C`

```c
/* ternary_eval.c    编译：gcc -std=c23 ternary_eval.c -o ternary_eval */
#include <stdio.h>

int side(const char *who) { printf("  [%s被求值]\n", who); return 1; }

int main(void) {
    printf("条件为真：\n");
    (void)(1 ? side("真分支") : side("假分支"));
    printf("条件为假：\n");
    (void)(0 ? side("真分支") : side("假分支"));
    return 0;
}
```

**每次只有一支被求值。**
这与 `&&`、`||` 的短路是同一类规定，理由也相同：没被选中的那支不必算。

### 3.8.2 结果类型由两支共同决定

**这是条件运算符最容易误解的地方：结果类型与实际走哪一支无关。**

`实测数据`
`C++`

```cpp
/* cond_type.cpp    编译：g++ -std=c++17 cond_type.cpp -o cond_type */
#include <cstdio>

int main() {
    int    i = 1;
    double d = 2.5;

    auto r1 = (i > 0) ? i : d;      /* 条件为真，选中的是 int 那一支 */
    printf("sizeof = %d\n", (int)sizeof(r1));     /* 8：结果类型是 double */
    printf("值 = %f\n", (double)r1);              /* 1.000000 */
    return 0;
}
```

**条件为真、选中的是 `int`，结果类型却是 `double`（8 字节）。**
**两支先按《04-语法/02-数据类型与类型系统.md》第 5.3 小节的规则统一，
整个表达式再取统一后的类型。** 完整说明见第 5.2 小节。

### 3.8.3 结合方向

**条件运算符右结合**，因此嵌套时从右往左归组：

`实测数据`
`C`

```c
/* ternary_nested.c    编译：gcc -std=c23 ternary_nested.c -o ternary_nested */
#include <stdio.h>

int main(void) {
    int s = -3;
    /* 从右往左结合：s > 0 ? "正" : ((s < 0) ? "负" : "零") */
    const char *t = (s > 0) ? "正" : (s < 0) ? "负" : "零";
    printf("%s\n", t);          /* 负 */
    return 0;
}
```

**多层嵌套的三目可读性差**，超过两层就应当改用 `if` 或抽成函数。

### 3.8.4 结果是不是左值

**这是 C 与 C++ 在运算符上的又一处分岔**：

`实测数据`
`C`

```c
/* cond_lvalue.c    编译：gcc -std=c23 cond_lvalue.c -o cond_lvalue （失败）
 * gcc 报错：error: lvalue required as left operand of assignment
 */
int main(void) {
    int a = 1, b = 2;
    (1 ? a : b) = 5;        /* C 里条件表达式不是左值 */
    return a + b;
}
```

**同一个文件用 `g++ -std=c++17` 编译则通过**，赋值之后 `a` 变成 5。

`文档`

> "If the second and third operands are glvalues of the same value category and
> have the same type, the result is of that type and value category."
>
> —— N4659 §8.16/5

**两支都是同一类型的左值时，C++ 把结果也当作左值**，
C 则一律只把它当作一个值。这与第 7.1 小节是同一类差异。

## 3.9 逗号运算符

**逗号有两个身份**：分隔符与运算符。**只有在表达式位置出现的那个才是运算符。**

| 场合 | 逗号的身份 |
|---|---|
| `f(a, b)` 的实参之间 | **分隔符** |
| `int a = 1, b = 2;` 的声明符之间 | **分隔符** |
| `(a, b)`、`for (i = 0, j = n; ...)` | **运算符** |

`文档`

> "The left operand of a comma operator is evaluated as a void expression; there
> is a sequence point between its evaluation and that of the right operand.
> Then the right operand is evaluated; the result has its type and value."
>
> —— N3220 §6.5.18/2

**左操作数先算，整个表达式的值取右操作数。**

`实测数据`
`C`

```c
/* comma_lab.c    编译：gcc -std=c23 comma_lab.c -o comma_lab */
#include <stdio.h>

int main(void) {
    int x = (1, 2, 3);              /* 值是最右边那个 */
    printf("x = %d\n", x);          /* 3 */

    int i, j;
    for (i = 0, j = 10; i < j; i++, j--) { }    /* for 的三个槽位都能用逗号 */
    printf("i = %d, j = %d\n", i, j);           /* 5, 5 */

    int a = 0;
    int y = (a = 5, a + 10);        /* 左边先算，右边给值 */
    printf("y = %d, a = %d\n", y, a);           /* 15, 5 */
    return 0;
}
```

**两个身份的区别很实际**：

`实测数据`
`C`

```c
/* comma_sep.c    编译：gcc -std=c23 comma_sep.c -o comma_sep
 *                编译：gcc -std=c23 -c comma_sep.c （把 f(a, b) 那行放出来则失败）
 */
#include <stdio.h>

static int f(int x) { return x + 100; }

int main(void) {
    int a = 1, b = 2;
    printf("f((a, b)) = %d\n", f((a, b)));   /* 102：先算 (a, b)，值是 b，一个实参 */
    printf("a = %d, b = %d\n", a, b);        /* 1, 2 */
    /* printf("%d\n", f(a, b)); */           /* 放开这行：error: too many arguments to function 'f' */
    return 0;
}
```

**`f((a, b))` 传进去的是一个实参**，值是 `b`；
**`f(a, b)` 传进去的是两个实参**，编译器会报实参个数不符。

> [!TIP]
> **逗号运算符只适合放在 `for` 的初始化与步进里。**
> 放在别处会让「一个表达式做几件事」变得难读，写成分号隔开的语句更清楚。

## 3.10 `sizeof` 与类型转换

### 3.10.1 `sizeof` 的两种形式

**`sizeof` 是一元运算符，操作数可以是表达式，也可以是加了括号的类型名**：

| 形式 | 例子 | 说明 |
|---|---|---|
| `sizeof 一元表达式` | `sizeof x`、`sizeof a[0]` | 不用括号 |
| `sizeof(类型名)` | `sizeof(int)`、`sizeof(struct Point)` | **括号是类型名的一部分** |

**第二种形式里的括号不是函数调用的括号**，
所以 `sizeof(int)` 并不是「把 `int` 传进一个函数」。

**结果类型是 `size_t`**，一个无符号整型：

`文档`

> "The value of the result of both operators is implementation-defined, and its
> type (an unsigned integer type) is size_t"
>
> —— N3220 §6.5.4.4

`实测数据`
`C`

```c
/* sizeof_form.c    编译：gcc -std=c23 sizeof_form.c -o sizeof_form */
#include <stdio.h>

int main(void) {
    int x = 0;
    printf("sizeof x            = %zu\n", sizeof x);            /* 4 */
    printf("sizeof(x)           = %zu\n", sizeof(x));           /* 4 */
    printf("sizeof(int)         = %zu\n", sizeof(int));         /* 4 */
    printf("sizeof(sizeof(int)) = %zu\n", sizeof(sizeof(int))); /* 8：结果是 size_t */
    return 0;
}
```

**最后一行把结果类型暴露出来**：`sizeof(int)` 的值是 4，
但「`sizeof(int)` 这个表达式的类型」是 `size_t`，在本机占 8 字节。

**`sizeof` 不求值**（变长数组除外），实测与推导见第 4.3 小节。
**变长数组是 C 专有的**：

`实测数据`
`C`

```c
/* sizeof_vla.c    编译：gcc -std=c23 sizeof_vla.c -o sizeof_vla */
#include <stdio.h>

int main(void) {
    int n = 5;
    printf("sizeof(int[n++]) = %zu\n", sizeof(int[n++]));   /* 20 */
    printf("执行之后 n = %d\n", n);                          /* 6：操作数被求值了 */
    return 0;
}
```

**`n` 从 5 变成 6，说明这一次操作数确实被求值了**——
这是「不求值」规则唯一的例外。**同一个程序用 `g++ -std=c++17 -pedantic-errors`
编译会失败：`error: ISO C++ forbids variable length array`**，
变长数组不是 C++ 的一部分。

**`sizeof('a')` 是这一处的经典对照：C 里是 4，C++ 里是 1**，
原因与重载上的后果见《04-语法/00-导读：从记住规则到理解意图.md》第 4.5 小节。

### 3.10.2 类型转换 `(T)x`

**转换运算符是一元的，把操作数转成指定类型**，
它改变的是「这个值按哪种类型参与后面的运算」。

`实测数据`
`C`

```c
/* cast_two.c    编译：gcc -std=c23 cast_two.c -o cast_two */
#include <stdio.h>

int main(void) {
    double d = 3.7;
    printf("(int)d        = %d\n", (int)d);          /* 3：截断，不是四舍五入 */
    printf("(double)3 / 2 = %f\n", (double)3 / 2);   /* 1.500000：先转再除 */
    printf("3 / 2         = %d\n", 3 / 2);           /* 1：整数除法 */
    return 0;
}
```

**第二行与第三行只差一个转换，结果从 1 变成 1.5**：
转换发生在除法之前，于是除法变成了浮点除法。

**C++ 里的 `int(d)` 写法与 `(int)d` 等价**，
两者的读法差别、以及四种具名转换，见第 6.1 小节与
《04-语法/02-数据类型与类型系统.md》第 5.5 小节。
**对类类型，`T(x)` 会调用构造函数**，这一层归【待补：05-类与面向对象/】。

## 3.12 优先级与结合性

**优先级决定「先算谁」，结合性决定「同优先级时从哪边算」。**

**不需要背整张表**，只需要记住三条：

| 规则 | 说明 |
|---|---|
| **算术 > 关系 > 逻辑** | `a + b > c && d` 先加、再比、最后与 |
| **赋值右结合** | `a = b = c` 是 `a = (b = c)` |
| **一元 > 二元 > 三元 > 赋值 > 逗号** | 大体顺序 |

**同级运算符的结合方向只有两处例外**：

| 方向 | 运算符 |
|---|---|
| **左结合**（多数） | 算术、关系、相等、位运算、逻辑、逗号 |
| **右结合** | **赋值**（含复合赋值）、**条件运算符** |

**后缀运算符的优先级最高**：`p++`、`a[i]`、`f()`、`p->x` 都先于它们左边的一元运算符。
`*p++` 因此是 `*(p++)` 而不是 `(*p)++`，两者的结果见第 3.7.3 小节。

**三处最容易写错的**：

`实测数据`
`C`

```c
/* precedence.c    编译：gcc -std=c23 precedence.c -o precedence
 * gcc 输出：warning: result of '2^3' is 1; did you mean '1 << 3' (8)? [-Wxor-used-as-pow]
 *           （该警告默认开启，用来提醒 ^ 是异或，不是幂运算）
 */
#include <stdio.h>

int main(void) {
    printf("%d\n", 1 << 2 + 3);   /* 32：加法先算，不是 20 */
    printf("%d\n", 1 & 2 == 2);   /* 1：== 先算，不是 0 */
    printf("%d\n", 1 | 2 ^ 3);    /* 1：^ 先算 */
    return 0;
}
```

**三行的实际结合方式**：

| 写法 | 实际结合方式 | 原因 |
|---|---|---|
| `1 << 2 + 3` | `1 << (2 + 3)` = `1 << 5` = **32** | **加法优先级高于移位** |
| `1 & 2 == 2` | `1 & (2 == 2)` = `1 & 1` = **1** | **`==` 优先级高于 `&`** |
| `1 \| 2 ^ 3` | `1 \| (2 ^ 3)` = `1 \| 1` = **1** | **`^` 优先级高于 `\|`** |

**前两条最容易写错**：
`1 << 2 + 3` 看着像「先移位」，`1 & 2 == 2` 看着像「先按位与」，
**两者都相反。**

**第三行还会引出一个默认开启的警告**：
`warning: result of '2^3' is 1; did you mean '1 << 3' (8)? [-Wxor-used-as-pow]`。
**编译器在提醒 `^` 是异或，不是幂运算**，`2 ^ 3` 得到的是 `1`。

> [!TIP]
> **优先级不确定时就加括号。**
> **括号不花钱，猜错要花时间调试。**

**完整的优先级与结合性表见附录 B**，其中也写明了标准为什么没有给出这样一张表。

# 第 4 节 求值

**一个表达式里常常有好几个部分**：两个操作数、几个函数实参、下标的两个半边。
**它们「什么时候算」，标准给出的答案只有三种。**

| 情形 | 顺序 | 能不能依赖 |
|---|---|---|
| 多数二元运算符的两个操作数、函数实参 | **不确定** | **不能** |
| `&&`、`\|\|`、`?:`、逗号 | **有保证**，而且可能有一边根本不求值 | 能 |
| `sizeof` 的操作数 | **根本不求值** | —— |

> [!IMPORTANT]
> **前两行说的是「顺序」，第三行说的是「连算都不算」。**
> 这是两件不同的事，混在一起看就会觉得这一节没有头绪。

## 4.1 多数场合：顺序不确定

**同一份代码、同一台机器上，两种写法的求值顺序不同**：

`实测数据`
`C`

```c
/* order.c    编译：gcc -std=c23 order.c -o order */
#include <stdio.h>

int f(void) { printf("  f 先算\n"); return 1; }
int g(void) { printf("  g 先算\n"); return 2; }
void h(int a, int b) { (void)a; (void)b; }

int main(void) {
    printf("f() + g()：\n");
    (void)(f() + g());      /* 输出顺序：f → g */
    printf("h(f(), g())：\n");
    h(f(), g());            /* 输出顺序：g → f */
    return 0;
}
```

**同一份代码里，`+` 的两边从左到右算，函数实参却从右到左算。**
四个优化等级下的结果都一样，数据见附录 A.22。

> [!IMPORTANT]
> **标准没有规定这两个函数谁先被调用。编译器自己选，
> 而且对不同的场合选了不同的顺序。**

**这类行为在标准里叫「未指定行为」（unspecified behavior）**——
标准给出若干种可能，不规定用哪一种。
**完整的三类行为自由度见《01-编译器/00-语言的实现.md》第 3 节。**

**没有确定顺序的场合**：

| 场合 | 例子 |
|---|---|
| 二元运算符的两个操作数 | `f() + g()` |
| 函数实参的求值 | `h(f(), g())` |
| 数组下标的两个部分 | 极少需要关心 |

**「不确定」的后果仅仅是「不能依赖」**——程序的行为仍然是确定的，
只是这个行为由编译器决定，不由标准决定。

**一旦同一个对象既被读又被改，性质就变了**，见第 4.4 小节。

## 4.2 少数场合：顺序有保证

**`&&`、`||`、`?:`、逗号运算符是四个例外**，它们的顺序由标准保证。

### 一、短路：`&&` 与 `||`

**`&&` 与 `||` 有保证的求值顺序**，这是它们与 `&`、`|` 的重要区别。

`实测数据`
`C`

```c
/* short_circuit.c    编译：gcc -std=c23 short_circuit.c -o short_circuit */
#include <stdio.h>

int side(const char *who) { printf("  [%s 被调用]\n", who); return 1; }

int main(void) {
    printf("0 && side(...) = %d\n", 0 && side("与的右边"));     /* 右边不求值 */
    printf("1 || side(...) = %d\n", 1 || side("或的右边"));     /* 右边不求值 */
    printf("1 && side(...) = %d\n", 1 && side("与的右边"));     /* 右边求值 */
    printf("0 &  side(...) = %d\n", 0 &  side("按位与的右边")); /* 右边照样求值 */
    return 0;
}
```

**前两行没有打印「被调用」，后两行打印了。**

**规则**：

| 写法 | 左边是 | 右边 |
|---|---|---|
| `a && b` | 假 | **不求值** |
| `a \|\| b` | 真 | **不求值** |
| 其余 | — | 求值 |

**这条规则的两个用途**：

| 用途 | 写法 |
|---|---|
| **保护空指针** | `if (p && p->x > 0)` |
| **避免无谓计算** | `if (n != 0 && 100 / n > 5)` |

> [!WARNING]
> **位运算符 `&` 与 `|` 没有短路性质**，两边一律求值。
> **它们只是按位算，不控制流程。**

### 二、条件运算符只算一支

**`a ? b : c` 先算 `a`，再按结果只算 `b` 或 `c` 中的一个。**
实测与规则见第 3.8.1 小节。

### 三、逗号：左边先于右边

**逗号运算符的两边有确定的先后**：左边先算完，再算右边，
整个表达式的值取右边。见第 3.9 小节。

**有确定顺序的场合汇总**：

| 场合 | 说明 |
|---|---|
| `&&`、`\|\|` 的两边 | 短路求值要求先算左边 |
| `?:` 的条件与选中分支 | 没被选中的分支不求值 |
| 逗号运算符的两边 | 左边先于右边 |
| 完整表达式之间 | 前一条语句整体先于后一条 |

## 4.3 有些操作数根本不被求值

**`sizeof` 的操作数是这一类：它只问类型，不问值。**

`实测数据`
`C`

```c
/* sizeof_no_eval.c    编译：gcc -std=c23 sizeof_no_eval.c -o sizeof_no_eval */
#include <stdio.h>

int main(void) {
    int i = 0;
    size_t n = sizeof(i++);             /* 操作数不被求值 */
    printf("sizeof(i++) = %zu\n", n);   /* 4 */
    printf("执行之后 i = %d\n", i);      /* 0 */

    int j = 0;
    int k = (j++, j + 1);               /* 逗号运算符：两个操作数都求值 */
    printf("j = %d, k = %d\n", j, k);   /* 1, 2 */

    int arr[sizeof(int) == 4 ? 1 : -1]; /* 能当数组长度：结果是编译期常量 */
    printf("sizeof(arr) = %zu\n", sizeof(arr));   /* 4 */
    return 0;
}
```

**`i++` 没有执行，`i` 仍是 0**；而 `j++` 执行了，`j` 变成 1。

**原因**：求值是为了拿到值，而 `sizeof` 只要类型，
**因此整个操作数根本不被求值**。

| 写法 | 操作数会被求值吗 |
|---|---|
| `sizeof(i++)` | **不会** |
| `(j++, j+1)` | **会** |

**`sizeof` 是编译期就完成的运算**，这也解释了另外两件事：

| 现象 | 原因 |
|---|---|
| 它能当数组长度 | 编译期常量 |
| 它没有运行期开销 | 编译期就算完了 |

**变长数组是唯一的例外**：那时 `sizeof` 的操作数会被求值，
实测见第 3.10.1 小节。

## 4.4 顺序不确定的后果：未定义行为

**顺序不确定只是「不规定」；对同一个对象既读又改，性质就变成未定义行为。**

`C`

```c
int i = 0;
printf("%d %d\n", i++, i++);       /* 未定义行为 */
```

**它对同一个对象做了两次没有顺序关系的修改**，
因此标准不再给出「若干种可能」，而是完全不作要求。

**描述这件事的术语是「先序于」（sequenced before）**：
C++11 起用它，C11 起也引入了同一套说法。
**两次修改之间如果没有「先序」关系，程序就是未定义的。**

`文档`

> "Except as specified later, side effects and value computations of
> subexpressions are unsequenced."
>
> —— N3220 §6.5.1/3

**这句话的意思是**：除了标准点名保证顺序的那几处（第 4.2 小节列的四种），
其余子表达式的求值之间**没有先后关系**。没有先后关系，就谈不上「谁先谁后」，
而「先改再读」还是「先读再改」正是这类代码的成败所在。

> [!CAUTION]
> **不要在同一个表达式里对同一个对象既读又改，或者改两次。**
> **也不要依赖函数实参的求值顺序。**

# 第 5 节 类型转换在表达式里发生

**转换的规则见《04-语法/02-数据类型与类型系统.md》第 5 节。
在表达式里，转换发生的时机如下。**

## 5.1 转换的时机

**隐式转换几乎都发生在表达式求值的过程中**：

| 时机 | 例子 |
|---|---|
| 两个操作数类型不同 | `1 + 2.0` |
| 赋值时 | `int i = 1.5;` |
| 传参与返回 | `void f(double); f(1);` |
| 条件判断 | `if (p)` —— 指针转 `bool` |
| 初始化 | `double d = 1;` |

**转换不是一条独立规则，它是表达式求值的一部分。**

## 5.2 条件运算符的结果类型

**三目运算符有一处最容易误解的地方。**

`实测数据`
`C++`

```cpp
/* cond_type.cpp    编译：g++ -std=c++17 cond_type.cpp -o cond_type */
#include <cstdio>

int main() {
    int    i = 1;
    double d = 2.5;

    auto r1 = (i > 0) ? i : d;      /* 条件为真，选中的是 int 那一支 */
    printf("sizeof = %d\n", (int)sizeof(r1));     /* 8：结果类型是 double */
    printf("值 = %f\n", (double)r1);              /* 1.000000 */

    char c = 'A';
    auto r3 = (i > 0) ? c : i;      /* 一支是 char，一支是 int */
    printf("sizeof(r3) = %d\n", (int)sizeof(r3)); /* 4：char 被提升成 int */
    return 0;
}
```

**条件为真、选中的是 `int` 那一支，结果类型却是 `double`（8 字节）；
`char` 与 `int` 两支的结果是 `int`。**

> [!IMPORTANT]
> **条件运算符的结果类型由两支共同决定，与实际走哪一支无关。**

**两支先按《04-语法/02-数据类型与类型系统.md》第 5.3 小节的规则统一，
整个表达式再取统一后的类型。**

**若两支里有浮点数，整个表达式就是浮点**，哪怕另一支是整型、而且被选中；
**两支都是整型时结果就是整型**，赋给 `double` 时才发生转换。

# 第 6 节 运算符与函数的界限

**运算符与函数之间有一条模糊的界线。**

## 6.1 长得像函数的运算符

**`sizeof(int)`、`int(d)`、`double(x)` 这些写法看起来都像函数调用。**

**其中两种转换写法生成的代码完全一致，读起来的意味却不同**：

| 写法 | 读作 | 像什么 |
|---|---|---|
| **`(int)d`** | 「给 `d` **加一个标记**，说它是 `int`」 | **标记** |
| **`int(d)`** | 「**调用一下**，把 `d` 变成 `int`」 | **函数调用** |

**这个区别不是形式上的，它影响这行代码的读法。**

**`(int)d` 的读法**：类型名在括号里，像一张贴上去的标签。
它不暗示任何动作，**读起来像「什么都没发生，只是换个看法」**。

**`int(d)` 的读法**：`int` 在前，括号在后，与 `f(x)` 的构词完全相同。
**它暗示这是一次「操作」，有输入有输出。**

**两种读法各有适用场合**：

| 场合 | 更合适的写法 | 理由 |
|---|---|---|
| 只是换个看法、没有实际转换 | `(int)d` | 标记式读法更贴切 |
| **确实产生了新值** | `int(d)` | 调用式读法提示了「这里有动作」 |
| 需要说明转换的种类 | `static_cast<int>(d)` | 见下 |

**C++ 后来加的 `static_cast<int>(d)` 解决了这一点**：
它把「函数调用」的形式保留下来，同时把「这是哪种转换」写进了名字里——
`(int)d` 与 `int(d)` 只说结果类型，**不说怎么转的**。

**这也是《04-语法/02-数据类型与类型系统.md》第 5.5 小节说的那件事**：
**把「我想做什么」写出来，而不是笼统地说「转一下」。**

**`sizeof(int)` 也是同样的道理**：
`sizeof` 是运算符，但写成 `sizeof(类型)` 或 `sizeof(表达式)` 时，
**它长得与函数调用一模一样**。

**三者在底层的表现相同**：

`实测数据`

| 写法 | `call` 指令数 |
|---|---|
| `sizeof(int)` | **0** |
| `(int)d` | **0** |
| `int(d)` | **0** |

**一条 `call` 都没有**，说明它们都不是函数调用。

## 6.2 底层区别：有没有 `call`

**把几种写法各自编译出来，数汇编里的 `call` 指令**：

`实测数据`
`C++`

```cpp
/* ops.cpp    编译：g++ -std=c++17 -O0 -S ops.cpp -o ops.s */
struct V { int x; };
V operator+(V a, V b) { V r; r.x = a.x + b.x; return r; }

int add_fn(int a, int b) { return a + b; }

int use_builtin_operator(int a, int b) { return a + b; }         /* 内置类型的 + */
int use_function(int a, int b)   { return add_fn(a, b); }        /* 真正的函数调用 */
int use_sizeof(void)        { return (int)sizeof(int); }
int use_cast_c(double d)    { return (int)d; }
int use_cast_func(double d) { return int(d); }
int use_class_operator(V a, V b) { V c = a + b; return c.x; }    /* 类类型的 + */
```

| 写法 | `call` 指令数 | 说明 |
|---|---|---|
| `a + b`（内置类型） | **0** | 就是一条 `add` 指令 |
| `add_fn(a, b)` | **1** | 真正的函数调用 |
| `sizeof(int)` | **0** | 编译期常量 |
| `(int)d` | **0** | 转换指令 |
| `int(d)` | **0** | 与上一条相同 |
| **`a + b`（类类型）** | **1** | **调用了 `_Zpl1VS_`** |

**为什么同一个 `+`，对 `int` 是零条调用，对类类型是一条调用？**

**因为 C++ 允许重载运算符**——对类类型，
`a + b` 会被翻译成一次函数调用，函数名是**修饰过的 `operator+`**：

`Text`

```text
_Zpl1VS_
```

**拆开读**：

`Text`

```text
   _Z   pl   1V    S_
   │    │    │     └── 第二个参数类型 V
   │    │    └──────── 第一个参数类型 V
   │    └───────────── operator+（pl = plus）
   └────────────────── 修饰前缀
```

**它就是一个普通函数的名字**，与 `add_fn` 修饰成 `_Z6add_fnii` 是同一回事。

## 6.3 因此，界限在哪里

> [!IMPORTANT]
> **运算符与函数的界限，在于底层有没有函数调用、有没有跳转指令。**

| | 内置类型的运算符 | 类类型的运算符 |
|---|---|---|
| 底层 | **一条机器指令** | **一次函数调用** |
| 有没有 `call` | 没有 | **有** |
| 在 C 里 | 只有这种 | **不存在**（C 不支持重载） |
| 在 C++ 里 | 有 | **有** |

**这条界限解释了三个现象**：

| 现象 | 为什么 |
|---|---|
| **`sizeof` 不是函数** | 它没有调用，编译期就算完了 |
| **`int(x)` 不是函数** | 它没有调用，只是转换指令 |
| **C++ 的运算符可以「像函数一样」被重载** | 因为**对类类型它本来就是函数** |

**也解释了为什么 C 里不可能有运算符重载**：
**C 的运算符一律是机器指令，没有「换成一次函数调用」这个机制。**

## 6.4 这条界限的实用意义

**知道 `int(x)` 与 `(int)x` 完全等价，有一个实际好处**：

**不必因为「它看起来像构造函数」就以为它在构造对象。**

`C++`

```cpp
int a = int(3.7);      /* 就是一次转换，得到 3 */
int b = (int)3.7;      /* 同上 */
```

**但对类类型，`T(x)` 确实会调用构造函数**：

`C++`

```cpp
std::string s = std::string("abc");    /* 这里真的会构造对象 */
```

**同一个写法，对内置类型是转换，对类类型是构造。**

**这不是矛盾，而是因为对类类型，它底层真的是一次函数调用。**

**`T(x)` 在类类型上就是构造函数调用**，
这一层的展开见【待补：05-类与面向对象/】。

# 第 7 节 C 与 C++ 的差异

**表达式上的差异一共七处，前面各节都已展开，这里汇总，并补上一条贯穿三处的解释。**

| 差异 | C | C++ | 详细位置 |
|---|---|---|---|
| 关系、相等与逻辑运算的结果类型 | `int` | `bool` | 第 3.3.1、3.4.2 小节 |
| 自增与赋值的结果是不是左值 | 不是 | 是 | 第 7.1 小节 |
| 条件运算符的结果是不是左值 | 不是 | 两支同类型左值时是 | 第 3.8.4 小节 |
| 赋值两侧的求值顺序 | **不规定** | **先右后左** | 第 3.6.3 小节 |
| 与数组无关的指针比大小 | 未定义行为 | 未指定 | 第 3.3.5 小节 |
| 字符字面量的类型 | `int`，`sizeof('a')` 是 4 | `char`，是 1 | 《04-语法/00-导读：从记住规则到理解意图.md》第 4.5 小节 |
| 运算符重载 | 不存在 | 有 | 第 7.2 小节 |

## 7.1 差异背后的两种取向：值语义与对象语义

**自增、赋值与条件运算符这三处差异出自同一个原因**：
**C 关心表达式「算出什么值」，C++ 关心表达式「指代哪个对象」。**

`实测数据`
`C`

```c
/* lvalue.c    编译：gcc -std=c23 -c lvalue.c -o lvalue_c.o（失败）
 *             编译：g++ -std=c++17 -c lvalue.c -o lvalue_cpp.o（通过）
 * gcc 报错：error: lvalue required as left operand of assignment
 *           error: lvalue required as unary '&' operand
 */
int main(void) {
    int a = 1;
    ++a = 5;                /* C：失败     C++：通过 */
    int *p = &(a = 1);      /* C：失败     C++：通过 */
    return 0;
}
```

**条件运算符是同一处的第三个例子**（实测见第 3.8.4 小节）：
C 里 `(1 ? a : b) = 5;` 报
`error: lvalue required as left operand of assignment`，C++ 里通过。

**`a++ = 5` 在两边都失败**——它交出的是旧值的副本，没有可赋值的位置。

| 表达式 | 在 C 里 | 在 C++ 里 |
|---|---|---|
| `++a` | 右值 | **左值**（它就是 `a` 本身） |
| `a = 1` | 右值 | **左值**（就是被赋的那个对象） |
| `1 ? a : b` | 右值 | **左值**（两支是同类型左值时） |

> [!IMPORTANT]
> **C 关心的是「算出什么值」**——`++a` 算出一个数，就到此为止。
> **C++ 关心的是「是哪个对象」**——`++a` 之后 `a` 还在，
> 那么 `++a` 指代的就是 `a` 这个对象本身。

**C++ 需要支持「返回引用的函数」与链式写法**：

`C++`

```cpp
std::cout << a << b << c;      /* 每个 << 都返回流对象的引用 */
```

**若赋值的结果是右值，这一类链式写法就无法成立。**

> [!TIP]
> **`++a = 5` 虽然合法，但没有人会这样写。**
> 这条差异的价值在于：它揭示了 C++ 的表达式比 C 更强调「对象」。

## 7.2 差异二：运算符重载

**这是运算符上最大的一处差异，它需要类类型。**

| | C | C++ |
|---|---|---|
| 运算符 | **一律是机器指令** | 对**类类型**可以重载 |
| 底层 | 没有函数调用 | **一次函数调用** |

**详细对照见第 6.2 小节。**

**运算符重载的写法、规则与陷阱**，见【待补：05-类与面向对象/】。

## 7.3 五处「看起来是差异，实际一致」的地方

### 一、赋值可以作为条件

**`if (a = 1)` 在 C 与 C++ 里都能编过**，因为赋值是表达式、有值。

`实测数据`
`C`

```c
/* assign_cond.c    编译：gcc -std=c23 -Wall assign_cond.c -o assign_cond
 * 不加 -Wall 时没有任何提示；加 -Wall 输出：
 * warning: suggest parentheses around assignment used as truth value [-Wparentheses]
 */
#include <stdio.h>

int main(void) {
    int a = 0;
    if (a = 1) { }          /* 赋值当条件：能编过，但可能是把 == 写成了 = */
    printf("%d\n", a);      /* 1 */
    return 0;
}
```

**默认选项下编译器不会提示，加上 `-Wall` 或 `-Wall -Wextra` 才给出
`-Wparentheses` 警告。**

> [!TIP]
> **编译时加 `-Wall -Wextra` 应当成为习惯。**
> 这不是编译器不帮忙，而是默认没打开开关。

> [!TIP]
> **现代编译器的智能程度很高。**
> 本章里出现过的可疑写法，它大多主动提示过：
> 把 `=` 写进条件、`X <= Y <= Z` 这种没有数学含义的连比、
> 把 `^` 当成幂运算、常量表达式里的整数溢出、常量除零、移位量越界。
> **默认选项下它一声不响，不代表代码没有问题。**
> **这份智能也用在优化上**：常量折叠、强度削减，
> 以及在断定某段代码必然触发未定义行为之后，把那段代码整个删掉。

`实测数据`

| 什么时候出现 | 本章遇到的提示 |
|---|---|
| **默认就开** | 常量溢出（`-Woverflow`）、常量除零（`-Wdiv-by-zero`）、移位量越界（`-Wshift-count-overflow`）、把 `^` 当幂运算（`-Wxor-used-as-pow`） |
| **要 `-Wall` 才开** | 把 `=` 写进条件、没有数学含义的连比（都是 `-Wparentheses`） |

**除零在各个环境下的不同表现，就是这种自由的实例**（见第 3.2.3 小节）；
**优化会改变哪些可观察行为，见《03-构建工具链/05-优化等级.md》第 5 节。**

**老办法「把常量写在左边」（`if (1 == a)`）**：
它确实能让写错的 `=` 变成编译错误，**但现在有了更直接的办法**——
打开警告选项即可，不必为此扭曲写法。

### 二、短路求值

**`&&` 与 `||` 的短路性质在 C 与 C++ 里完全一致**，
写法与行为都没有差别。**第 4.2 小节的数据同时适用于两者。**

### 三、条件运算符的类型规则

**两支类型统一之后取统一类型的规则，两者一致**（见第 5.2 小节）。
**C++ 的类型更多，实际遇到的场合比 C 多。**

### 四、`sizeof` 不求值

**两边都不求值**，写法与结果一致，实测见第 4.3 小节。
C++ 的依据是「不求值操作数」这一条：`An unevaluated operand is not evaluated`（N4659 §8/8）。

### 五、复合赋值的求值次数

**`E1 op= E2` 里左操作数只求值一次**，两份标准的规定相同
（N3220 §6.5.17.3/4、N4659 §8.18/7），实测见第 3.6.2 小节。

| 结合性 | Associativity | 同优先级运算符的结合方向 |
| 求值顺序 | Evaluation order | 子表达式谁先算 |
| 未指定行为 | Unspecified behavior | 标准给出若干可能，不规定用哪个 |
| 实现定义行为 | Implementation-defined behavior | 标准给出若干可能，由实现选定并写出文档 |
| 短路求值 | Short-circuit evaluation | `&&` 与 `\|\|` 在结果已定时不计算右边 |
| 先序于 | Sequenced before | C++11 起描述求值先后关系的说法 |
| 向零截断 | Truncation toward zero | 整数除法丢弃小数部分的方式，在负数上不等于向下取整 |
| 回绕 | Wraparound | 无符号数超出范围后按 2^N 取模的结果 |
| 掩码 | Mask | 用来选中、清除或翻转某些位的位模式 |
| 复合赋值 | Compound assignment | `+=` 这类「算一次再存回去」的写法，左操作数只求值一次 |
| 运算符重载 | Operator overloading | 对类类型赋予运算符新含义，底层是函数调用 |

# 附录 B 优先级与结合性总表

**标准没有给出这样一张表，优先级是由文法（grammar）体现的**：

`文档`

> "The syntax specifies the precedence of operators in the evaluation of an
> expression, which is the same as the order of the major subclauses of this
> subclause, highest precedence first."
>
> —— N3220 §6.5.1 脚注 82

`文档`

> "The precedence of operators is not directly specified, but it can be derived
> from the syntax."
>
> —— N4659 §8 脚注 62

**下表按文法的层级整理，同一行内优先级相同，行号越小绑得越紧。**

| | 运算符 | 结合方向 | 备注 |
|---|---|---|---|
| 1 | `::` | 左 | C++ 专有 |
| 2 | `a++` `a--`、`f()`、`a[]`、`.`、`->`、`typeid` | 左 | **后缀**，绑得最紧 |
| 3 | `++a` `--a`、`+a` `-a`、`!` `~`、`*p`、`&a`、`sizeof`、`(T)x`、`new`、`delete`、`alignof` | 右 | **一元前缀** |
| 4 | `.*`、`->*` | 左 | C++ 专有，成员指针 |
| 5 | `*` `/` `%` | 左 | 乘除 |
| 6 | `+` `-` | 左 | 加减 |
| 7 | `<<` `>>` | 左 | 移位 |
| 8 | `<` `<=` `>` `>=` | 左 | 关系 |
| 9 | `==` `!=` | 左 | 相等 |
| 10 | `&` | 左 | 按位与 |
| 11 | `^` | 左 | 按位异或 |
| 12 | `\|` | 左 | 按位或 |
| 13 | `&&` | 左 | 逻辑与 |
| 14 | `\|\|` | 左 | 逻辑或 |
| 15 | `?:` | **右** | 条件 |
| 16 | `=` 与十个复合赋值 | **右** | 赋值 |
| 17 | `,` | 左 | 逗号，绑得最松 |

**两处容易记错的地方**：

| 现象 | 原因 |
|---|---|
| `1 << 2 + 3` 先算加法 | 第 6 行（加减）在第 7 行（移位）之上 |
| `1 & 2 == 2` 先算相等 | 第 9 行（相等）在第 10 行（按位与）之上 |

**表里第 3 行的 `(T)x` 与第 5 行的 `*` 之间还夹着一层类型转换**，
因此 `(int)a * b` 是 `((int)a) * b`；
完整的层级以两份标准的文法为准（N3220 §6.5、N4659 §8 与附录 A 的文法汇总）。
