**它们由另一个程序处理，叫预处理器。**
**它不懂 C，也不懂 C++**——它只做文本替换。

**这一点决定了它的全部优点与全部缺点。**

# 第 1 节 预处理器做了什么

**预处理器是编译的第一个阶段。**

`Text`

```
   源文件 .c
      │
      ├─ ① 预处理   切出记号、执行 # 指令、展开宏、接进头文件    ← 本章
      │               产物：一个翻译单元（通常存成 .i 文件）
      │
      ├─ ② 编译     变成汇编
      ├─ ③ 汇编     变成目标文件 .o
      └─ ④ 链接     接成可执行文件
```


> [!IMPORTANT]
> **预处理器工作在记号层面，不是在做字符串替换。**
> 它先把源码切成记号，再在记号序列上做替换、拼接与丢弃。
> **因此它不懂类型、不管作用域、不知道运算符优先级。**

## 1.1 把源码切成记号

**预处理器拿到的不是一串字符，而是一串记号。**
标识符、数字、字符串字面量、运算符、标点各自是一个记号，
空白与注释只起分隔作用。

**宏替换的单位就是记号**：

`C`

```c
/* tok.c    编译：gcc -std=c23 -c tok.c -o tok.o */
#define MAX 100
int MAXIMUM = MAX;      /* MAXIMUM 是一个完整的记号，里面的 MAX 不替换 */
```

`实测数据`
`Bash`

```bash
gcc -std=c23 -E -P tok.c
# int MAXIMUM = 100;
```

**`MAXIMUM` 里的 `MAX` 没有被替换**，因为预处理器认的是整个记号，
不是记号里的字符。

**记号之间的关系它也不知道**：`MAX` 是常量还是函数名、
两个记号之间该不该有空白、`1 + 2` 是不是一个整体，它一律不管。
**宏的括号问题与重复求值问题都从这一条来**，见第 2.2 小节。

## 1.2 注释在指令之前就被删掉了

**翻译是分步做的。** 注释在第 3 步被替换成**一个空格**，
`#` 指令到第 4 步才执行。
**因此预处理器看到的东西里已经没有注释了**，只留下一个空格。

`文档`

> "Each comment is replaced by one space character. New-line characters
> are retained."
>
> —— N3220 §5.1.1.2 第 3 步；N4659 §5.2 第 3 步同文

**证据**：`gcc -E` 的输出里没有注释，加 `-C` 才保留。

`C`

```c
/* show_comments.c    编译：gcc -std=c23 -c show_comments.c -o show_comments.o */
int x = 1;      /* 块注释 */
// 行注释
```

`实测数据`
`Text`

```text
gcc -E -P show_comments.c       →  int x = 1;
gcc -E -P -C show_comments.c    →  int x = 1; /* 块注释 */
                                   // 行注释
```

**`-C` 保留全部注释**，连首行那句编译命令也一起留下，因为它同样是注释。

**留下的那个空格有时有用，有时是灾难**：

`实测数据`

| 写法 | 结果 |
|---|---|
| `int/**/x = 1;` | 合法，等价于 `int x = 1;` |
| `int a/**/b = 2;` | `error: expected '=', ',', ';', 'asm' or '__attribute__' before 'b'` |
| `printf("/* 不是注释 */");` | 原样输出 |
| `/* 外层 /* 内层 */ 后面这些 */` | `error: unknown type name ...` |

**`int/**/x` 里的空格补上了两个记号之间必需的空白**，因此合法；
**`int a/**/b` 里的两个记号本来要用逗号或分号分开**，塞一个空格进去就是错的。
**注释不能嵌套**——第一个 `*/` 就把注释结束了，
最后一行剩下的部分于是被当成代码。
**字符串字面量里的 `/*` 不是注释**，因为记号化时整个字符串是一个记号。

**宏定义里的注释同样换成一个空格**：

`C`

```c
/* macro_comment.c    编译：gcc -std=c23 macro_comment.c -o macro_comment */
#include <stdio.h>

#define SUM 1 /* 中间这句注释会被换成空格 */ + 2

int main(void) {
    printf("SUM = %d\n", SUM);
    return 0;
}
```

`实测数据`
`Text`

```text
SUM = 3
```

**`SUM` 展开后是 `1 + 2`**，三个记号之间的空白由那个空格补上。

**不能用注释「注释掉」含 `*/` 的代码**：注释在第一个 `*/` 处就结束，
后面剩下的部分会当成代码。

`C`

```c
/* comment_out_bad.c    编译：gcc -std=c23 comment_out_bad.c （失败） */
#include <stdio.h>

int main(void) {
    /* 下面这行暂时不想要，于是用块注释包起来：
    char *sep = "*/";
    */
    printf("done\n");
    return 0;
}
```

`实测数据`
`Text`

```text
error: missing terminating " character        ← 注释在 "*/" 那里就结束了
error: expected expression before '/' token   ← 剩下的 */ 变成了代码
```

**要停掉一段代码，用 `#if 0`**：里面的内容在预处理阶段整段丢掉，
**不参与词法分析**，有 `*/` 也不影响。

`C`

```c
/* if0_stop.c    编译：gcc -std=c23 if0_stop.c -o if0_stop */
#include <stdio.h>

int main(void) {
#if 0
    char *sep = "*/";
    printf("%s\n", sep);
#endif
    printf("done\n");
    return 0;
}
```

`实测数据`
`Text`

```text
done
```

> [!TIP]
> **临时停掉一段代码用 `#if 0`，不要用块注释。**
> 块注释里不能再出现 `*/`，`#if 0` 里什么都能出现。

**`//` 注释末尾若有反斜杠，会把下一行也拉进注释**，
因为续行发生在删注释之前：

`文档`

> "Each instance of a backslash character (\) immediately followed by a
> new-line character is deleted, splicing physical source lines to form
> logical source lines."
>
> —— N3220 §5.1.1.2 第 2 步

`C`

```c
/* comment_splice.c    编译：gcc -std=c23 -Wall comment_splice.c （失败） */
#include <stdio.h>

int main(void) {
    int x = 1;      // 注释末尾有一个反斜杠，下一行也被吞掉 \
    int y = 2;
    printf("x = %d, y = %d\n", x, y);
    return 0;
}
```

`实测数据`
`Text`

```text
warning: multi-line comment [-Wcomment]
error: 'y' undeclared (first use in this function)
```

**注释本身的写法与边界**见《04-语法/01-一些基础概念.md》第 2.3 小节。

## 1.3 执行 `#` 开头的指令

**`#` 开头的行叫预处理指令，到行尾结束**，行尾不写分号。

`文档`

> "Preprocessing directives are executed, macro invocations are expanded,
> and _Pragma unary operator expressions are executed. ... All preprocessing
> directives are then deleted."
>
> —— N3220 §5.1.1.2 第 4 步

常用的指令：

| 指令 | 作用 |
|---|---|
| `#include` | 把另一个文件的内容接进来 |
| `#define` / `#undef` | 登记、注销一个宏 |
| `#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif` | 按条件保留或丢掉整段文本 |
| `#error` / `#warning` | 主动报错、报警告 |
| `#pragma` / `#line` | 调整编译器的设置、调整行号与文件名 |

`文档`

> 指令的完整清单见 N3220 §6.10.1 的文法，
> 其中 `#elifdef` / `#elifndef`、`#warning`、`__has_include` 与 `#embed` 是 C23 新增的，
> 见第 4.4 小节。

**`#line` 改的是报错信息里的文件名与行号**：

`C`

```c
#line 100 "换了个名字.c"
int y = ;       /* 故意写错，看报错指到哪里 */
```

`实测数据`
`Text`

```text
换了个名字.c:100:9: error: expected expression before ';' token

#error 这个平台还没有适配   →   error: #error 这个平台还没有适配
```

## 1.4 展开宏、接进头文件，得到一个翻译单元

第 4 步里真正发生的三件事：

| 做什么 | 在哪讲 |
|---|---|
| 展开宏调用 | 第 2 节、第 5 节 |
| 把 `#include` 指定的文件读进来 | 第 3 节 |
| 按 `#if` 的结果保留或丢掉整段文本 | 第 4 节 |

**做完之后所有 `#` 行都被删掉**，宏也全部展开完了。
**产物叫翻译单元**，通常存成一个 `.i` 文件：没有 `#` 行，也没有注释。

`C`

```c
/* unit.c    编译：gcc -std=c23 -c unit.c -o unit.o */
#define MAX 100
int x = MAX;      /* 注释 */
```

`实测数据`
`Bash`

```bash
gcc -std=c23 -E -P unit.c -o unit.i
cat unit.i
# int x = 100;
```

**源文件里的三行变成了输出里的一行**：`#define` 不见了，注释不见了，
`MAX` 换成了 `100`。

## 1.5 它不做的事

| 不做 | 结果 |
|---|---|
| 类型检查 | 类型错要到编译阶段才发现 |
| 作用域管理 | 宏不受 `{ }` 限制，从定义处管到文件末尾 |
| 语法检查 | 展开出来的东西合不合法，它不管 |
| 优先级处理 | `#define SQ(x) x * x` 会算错 |

> [!IMPORTANT]
> **预处理器只做记号层面的替换、拼接与丢弃。**
> **后面所有的坑都从这几条推出来**：括号要自己加、参数会被求值多次、
> 宏没有类型、报错信息指向展开后的代码。

# 第 2 节 `#define`

## 2.1 对象式宏与函数式宏

`C`

```c
#define MAX 100             /* 对象式：替换一个记号 */
#define SQ(x) ((x) * (x))   /* 函数式：带参数 */
```

**两者都只是文本替换。**

## 2.2 三个必须知道的坑

### 坑一：参数没有括号

`C`

```c
/* macro_paren.c    编译：gcc -std=c23 macro_paren.c -o macro_paren */
#include <stdio.h>

#define SQ_BAD(x)  x * x
#define SQ_OK(x)   ((x) * (x))

int main(void) {
    printf("SQ_BAD(1+2) = %d   期望 9\n", SQ_BAD(1 + 2));
    printf("SQ_OK(1+2)  = %d   期望 9\n", SQ_OK(1 + 2));
    return 0;
}
```

`实测数据`
`Text`

```text
SQ_BAD(1+2) = 5   期望 9
SQ_OK(1+2)  = 9   期望 9
```

**`SQ_BAD(1+2)` 展开成 `1 + 2 * 1 + 2`**，按优先级算是 `1 + 2 + 2 = 5`。

**展开结果可以直接看**：

`实测数据`
`Bash`

```bash
gcc -std=c23 -E -P macro_paren.c | grep SQ_BAD
# printf("SQ_BAD(1+2) = %d   期望 9\n", 1 + 2 * 1 + 2);
```

**`x` 出现的地方被原样换成了 `1 + 2`**，一个字符不多、一个字符不少。
**宏只认记号，不认语法**，因此它不知道这里应该先算加法（第 1.1 小节）。

> [!WARNING]
> **宏的参数与整体都要加括号。**
> 正确写法是 `#define SQ(x) ((x) * (x))`——
> **每个参数一层括号，整体再一层**。

### 坑二：参数被求值多次

`C`

```c
/* macro_twice.c    编译：gcc -std=c23 macro_twice.c -o macro_twice */
#include <stdio.h>

#define SQUARE(x) ((x) * (x))

int main(void) {
    int i = 3;
    printf("SQUARE(i++) = %d\n", SQUARE(i++));
    printf("i 现在 = %d\n", i);
    return 0;
}
```

`实测数据`
`Text`

```text
SQUARE(i++) = 12
i 现在 = 5
```

**`i` 从 3 变成了 5，被加了两次。**

**看展开结果就明白了**：

`实测数据`
`Text`

```text
((i++) * (i++))
```

**`i++` 出现了两次，因此自增了两次。**

> [!CAUTION]
> **带副作用的参数传给宏会出问题。**
> 因为宏是文本替换，**参数在宏体里出现几次就被求值几次**。
> **传 `i++`、`f()`、`*p++` 这类有副作用的表达式时尤其危险。**

**这也是宏与函数的根本区别**：函数调用只求值一次。

### 坑三：不能放进 `if` 而不加大括号

`C`

```c
#define BAD(x)   printf("bad %d\n", x); printf("done\n")
#define GOOD(x)  do { printf("good %d\n", x); printf("done\n"); } while (0)

if (c)
    BAD(1);             /* 展开后第二个 printf 不受 if 控制 */
else
    printf("else 分支\n");
```

**`BAD` 版本编译失败。**

`实测数据`
`Text`

```text
error: 'else' without a previous 'if'
```

**原因**：展开后变成

`C`

```c
if (c)
    printf("bad %d\n", x); printf("done\n");    /* 这里已经结束了 if */
else
    printf("else 分支\n");                      /* else 找不到 if */
```

**换成 `do { ... } while (0)` 之后编译通过，输出 `good 1 | done`。**

> [!TIP]
> **多语句的宏一律用 `do { ... } while (0)` 包裹。**
> 它看起来像循环，但 `while (0)` 保证只执行一次，
> 而整个结构在语法上是**一条语句**，因此能安全地放进 `if` / `else`。

## 2.3 宏没有类型，也没有作用域

`C`

```c
#define MAX 100
```

**`MAX` 不是一个变量，它没有类型、没有地址、没有作用域。**

**`nm` 看符号表**

`实测数据`
`Text`

```text
#define MAX_A 100         →  符号表里找不到 MAX_A
constexpr int MAX_B = 100 →  0000000000000000 r MAX_B
```

> [!IMPORTANT]
> **宏在预处理阶段就消失了，因此它不进符号表、不能被调试器看到。**
> 用 `constexpr` 或 `const` 定义的常量会出现在调试信息里，
> 调试时能看到它的值；宏不能。
>
> **这就是 C++ 里推荐用 `constexpr` 代替宏的主要原因之一。**

**宏的作用域是「从定义处到文件末尾」**，可以用 `#undef` 取消：

`C`

```c
#define MAX 100
/* ... 使用 MAX ... */
#undef MAX
```

**但它不受 `{ }` 限制**——块里定义的宏在块外仍然有效。

## 2.4 可变参数宏

**宏的参数表末尾也可以写 `...`**，替换列表里用 `__VA_ARGS__` 取用：

`C`

```c
/* pp_vamacro.c    编译：gcc -std=c23 pp_vamacro.c -o pp_vamacro */
#include <stdio.h>

#define LOG(fmt, ...) printf("[log] " fmt "\n", __VA_ARGS__)

int main(void) {
    LOG("打开了 %s，共 %d 字节", "a.txt", 1024);
    LOG("三个数：%d %d %d", 1, 2, 3);
    return 0;
}
```

`实测数据`
`Text`

```text
[log] 打开了 a.txt，共 1024 字节
[log] 三个数：1 2 3
```

**这里的「可变」是文本层面的**：预处理阶段把调用处那一串记号原样搬进替换列表，
没有类型、没有个数、也不生成任何运行期结构。
运行期的可变参数是另一套——收 `...` 的函数与 `<stdarg.h>`，见《04-语法/07-函数.md》第 6 节。

**可变部分一个实参都没有时，替换列表里会留下一个多余的逗号**：

`C`

```c
/* pp_vamacro_zero.c    编译：gcc -std=c23 pp_vamacro_zero.c -o pp_vamacro_zero（失败） */
#include <stdio.h>

#define LOG(fmt, ...) printf("[log] " fmt "\n", __VA_ARGS__)

int main(void) {
    LOG("没有参数");        /* 展开成 printf("[log] " "没有参数" "\n", ) */
    return 0;
}
```

`实测数据`
`Text`

```text
error: expected expression before ')' token
```

C23 之前还有第二道拦阻：这种调用至少要给一个可变实参，
`-pedantic` 下会多一条 `ISO C99 requires at least one argument for the '...' in a variadic macro`；
**C23 起这条限制去掉了**（N3220 §6.10.5/4：调用里的实参个数不少于具名参数的个数即可）。

**两种解法**（`##` 本身见第 5 节）：

`C`

```c
/* pp_vaopt.c    编译：gcc -std=c23 pp_vaopt.c -o pp_vaopt */
#include <stdio.h>

/* 扩展写法：可变部分为空时，## 把前面那个逗号一起删掉 */
#define LOG_GNU(fmt, ...) printf("[GNU] " fmt "\n", ##__VA_ARGS__)

/* C23 的标准写法：__VA_OPT__(,) 只在可变部分非空时展开出逗号 */
#define LOG_C23(fmt, ...) printf("[C23] " fmt "\n" __VA_OPT__(,) __VA_ARGS__)

int main(void) {
    LOG_GNU("没有参数");
    LOG_C23("没有参数");
    LOG_C23("一个数：%d", 7);
    return 0;
}
```

`实测数据`
`Text`

```text
[GNU] 没有参数
[C23] 没有参数
[C23] 一个数：7
```

`实测数据`

| 写法 | `-std=c23` | `-std=c17 -pedantic` |
|---|---|---|
| `, __VA_ARGS__` 加零个可变实参 | 失败：`expected expression before ')' token` | 同样失败，另有「至少一个实参」警告 |
| `, ##__VA_ARGS__` | 通过 | 通过，另有「至少一个实参」警告 |
| `__VA_OPT__(,) __VA_ARGS__` | 通过 | 通过，警告 `'__VA_OPT__' is not available until C23` |

**`##__VA_ARGS__` 是 GCC 的扩展**，不属于标准，别的编译器不一定认；
**`__VA_OPT__` 进了 C23 与 C++20**（N3220 §6.10.5/5 规定这两个名字只能出现在用了 `...`
的函数式宏的替换列表里），新代码用它。

**宏只做文本转发，解析格式串的仍然是函数。** 日志这类接口常拆成三层，
运行期那两层见《04-语法/07-函数.md》第 6.6 小节：

`C`

```c
/* pp_logmacro.c    编译：gcc -std=c23 pp_logmacro.c -o pp_logmacro */
#include <stdio.h>
#include <stdarg.h>

static void log_v(const char *fmt, va_list ap) {    /* 解析格式串 */
    fputs("[log] ", stdout);
    vprintf(fmt, ap);
    putchar('\n');
}

static void log_f(const char *fmt, ...) {           /* 取可变参数 */
    va_list ap;
    va_start(ap, fmt);
    log_v(fmt, ap);
    va_end(ap);
}

#define LOG(...) log_f(__VA_ARGS__)                 /* 只转发 */

int main(void) {
    LOG("打开了 %s，共 %d 字节", "a.txt", 1024);
    LOG("没有参数");
    return 0;
}
```

`实测数据`
`Text`

```text
[log] 打开了 a.txt，共 1024 字节
[log] 没有参数
```

## 2.5 X 宏

**同一份清单要生成好几样东西时，用 X 宏。** 最常见的场合是枚举与名字表：
两处分开手写，漏改一处编译器不报错，运行起来才发现对不上。

`C`

```c
/* xmacro.c    编译：gcc -std=c23 xmacro.c -o xmacro */
#include <stdio.h>

/* 一份清单：每个颜色只在这里写一次 */
#define COLOR_LIST(X)   \
    X(Red)              \
    X(Green)            \
    X(Blue)

/* 第一次展开：生成枚举，名字带 Color_ 前缀 */
#define AS_ENUM(name) Color_##name,
enum Color { COLOR_LIST(AS_ENUM) };

/* 第二次展开：生成名字表，顺序与枚举一致 */
#define AS_NAME(name) #name,
const char *color_name[] = { COLOR_LIST(AS_NAME) };

int main(void) {
    /* 名字表与枚举来自同一份清单，个数不会对不上 */
    printf("%s %s %s\n",
           color_name[Color_Red], color_name[Color_Green], color_name[Color_Blue]);
    printf("%d %d %d\n", Color_Red, Color_Green, Color_Blue);
    printf("共 %zu 个\n", sizeof color_name / sizeof color_name[0]);
    return 0;
}
```

`实测数据`
`Text`

```text
Red Green Blue
0 1 2
共 3 个
```

**`COLOR_LIST` 自己不生成任何东西，它只负责把清单交给参数 `X`**：
`X` 传 `AS_ENUM` 就得到枚举，传 `AS_NAME` 就得到名字表。
`X` 在这里是一个宏参数，替换进去之后再展开，因此两次展开互不影响。

| 不用 X 宏 | 用 X 宏 |
|---|---|
| 枚举写一遍，名字表再抄一遍 | 清单只有一份 |
| 加一个颜色时忘了改名字表，编译不报错 | 加一行 `X(Yellow)`，两处一起变 |
| 两处的顺序错了也看不出来 | 顺序由清单决定 |

**代价也要说清**：

| 代价 | 说明 |
|---|---|
| 可读性 | 展开成什么要跟着 `X` 传进去的那个宏走一遍 |
| 调试 | 调试器里看不到展开后的结果，报错行号常指向清单那一行 |
| 名字占用 | `X` 是宏参数名，同一段里再用 `X` 做别的会混淆 |

> [!TIP]
> **X 宏适合「一份清单要生成好几样东西」的场合**：枚举与名字表、命令表与处理函数、
> 结构体成员与序列化代码。**只生成一样东西时，直接写出来更清楚。**

# 第 3 节 `#include`

## 3.1 两种写法

| 写法 | 到哪找 |
|---|---|
| `#include <stdio.h>` | **系统头文件目录** |
| `#include "myheader.h"` | **当前文件所在目录**，找不到再去系统目录 |

**同一个头文件放在当前目录。**

`实测数据`
`Text`

```text
#include "myheader.h"   → 通过
#include <myheader.h>   → 失败：myheader.h: No such file or directory
```

> [!TIP]
> **自己写的头文件用 `""`，标准库与第三方库用 `<>`。**
> 这既是约定，也影响查找速度——
> `<>` 直接去系统目录，`""` 要先看当前目录。

## 3.2 包含保护

**同一个头文件被包含两次，里面的定义就会重复。**

`C`

```c
/* h1.h    编译：gcc -std=c23 -c h1.h -o h1.h.gch */
int g_counter = 0;
```

`C`

```c
/* t1.c    编译：gcc -std=c23 t1.c -o t1 （失败） */
#include "h1.h"
#include "h1.h"         /* 又来一次 */
int main(void) { return g_counter; }
```

`实测数据`
`Text`

```text
h1.h:1:5: error: redefinition of 'g_counter'
```

**两种保护写法**：

`C`

```c
/* 写法一：包含卫士 */
#ifndef H2_H
#define H2_H

int g_counter = 0;

#endif
```

`C`

```c
/* 写法二：非标准但通用 */
#pragma once

int g_counter = 0;
```

**两种都能让「包含两次」编译通过。**

`实测数据`

| 头文件写法 | 包含两次的结果 |
|---|---|
| 无保护 | **失败**：`redefinition of 'g_counter'` |
| `#ifndef` 卫士 | 通过 |
| `#pragma once` | 通过 |

> [!IMPORTANT]
> **每个头文件都要有包含保护。**
> 有没有它，取决于**别的文件怎么包含**——
> 你可能只包含一次，但你包含的头文件之间可能互相包含。
> **`#pragma once` 更简短，但它不在标准里**；
> `#ifndef` 卫士到处都能用。

**为什么 `#ifndef` 有效**：第一次包含时 `H2_H` 未定义，
于是定义它并读入内容；第二次包含时 `H2_H` 已定义，
整个文件体被跳过。

## 3.3 头文件里该放什么

| 放 | 不放 |
|---|---|
| 函数声明 | **函数定义**（会造成重复定义） |
| 类型定义、`struct` | 变量定义（同上） |
| 宏 | 会分配空间的 `static` 变量 |
| `extern` 声明 | |
| `inline` 函数（C++） | |

**一个反直觉之处**：**完全相同的 `struct` 定义写两次，gcc 允许**：

`实测数据`
`Text`

```text
struct S { int x; };
struct S { int x; };        → 通过
struct S { int y; };        → 失败：redefinition of struct or union 'struct S'
```

> [!WARNING]
> **不要依赖「重复的结构体定义能编过」这件事。**
> 它只是实现宽容，换个编译器就可能报错。
> **包含保护仍然是必需的。**

# 第 4 节 条件编译

## 4.1 三个指令

`C`

```c
/* conditional.c    编译：gcc -std=c23 conditional.c -o conditional */
#include <stdio.h>

#define VERSION 2

int main(void) {
#if VERSION >= 2
    printf("走新版分支\n");
#else
    printf("走旧版分支\n");
#endif

#ifdef NEVER_DEFINED
    printf("这行不会编进去\n");
#endif

#if defined(VERSION) && VERSION == 2
    printf("VERSION 已定义且为 2\n");
#endif
    return 0;
}
```

`实测数据`
`Text`

```text
走新版分支
VERSION 已定义且为 2
```

| 指令 | 判断什么 |
|---|---|
| `#if` / `#elif` / `#else` / `#endif` | 常量表达式 |
| `#ifdef` / `#ifndef` | 某个宏**是否定义** |
| `#if defined(X)` | 同上，可与其他条件组合 |

**`#ifdef X` 等价于 `#if defined(X)`**，
但后者能写进更复杂的表达式里。

## 4.2 条件必须是常量，而且未定义的名字当 0

`C`

```c
int n = 5;
#if n > 0
    printf("走这里\n");
#endif
```

**编译通过，但那一行没有输出。**

`实测数据`
`Text`

```text
编译: 通过
输出: （空）
```

> [!CAUTION]
> **`#if` 里的标识符在预处理阶段都是 0**（未定义时）。
> 上例里的 `n` 是 C 与 C++ 的变量，但预处理器不认识它——
> 它把 `n` 当成一个未定义的宏，于是取 0，条件不成立。
> **编译不报错，只是分支被静默地去掉了。**
>
> **想用运行期的值做判断，必须写 `if` 而不是 `#if`。**

**这也是条件编译最容易出错的地方**：写错了不会报错，
只会让某段代码悄悄消失。

## 4.3 用在哪

| 用途 | 例子 |
|---|---|
| **跨平台** | `#ifdef _WIN32` 走 Windows 分支 |
| **调试开关** | `#ifdef DEBUG` 打印日志 |
| **头文件保护** | 见 3.2 节 |
| **编译期配置** | `#if VERSION >= 2` |
| **防止重复包含 C 与 C++** | `#ifdef __cplusplus` 加 `extern "C"` |

**跨平台的典型写法**：

`C`

```c
#ifdef _WIN32
    #include <windows.h>
    #define PATH_SEP '\\'
#else
    #include <unistd.h>
    #define PATH_SEP '/'
#endif
```

> [!NOTE]
> **平台宏由编译器预定义**，不需要自己写。
> 常用的有 `_WIN32`、`__linux__`、`__APPLE__`、`__x86_64__`。
> 完整清单见编译器的文档。

## 4.4 C23 新增的预处理能力

**C23 给预处理器添了四样东西**：两条条件编译指令（`#elifdef` / `#elifndef`）、
一条诊断指令（`#warning`）、一个条件包含用的算子（`__has_include`），
以及把文件读成数组的 `#embed`。

### `#elifdef` 与 `#elifndef`

**`#elifdef X` 等价于 `#elif defined(X)`**，`#elifndef X` 等价于 `#elif !defined(X)`。
单独给两条指令，是为了省掉 `defined` 那一层括号——条件一长，括号最容易写错。

`C`

```c
/* c23_elifdef.c    编译：gcc -std=c23 c23_elifdef.c -o c23_elifdef */
#include <stdio.h>

#define PLATFORM_B 1        /* 只定义 B，A 没有定义 */

#if defined(PLATFORM_A)
#  define MODE "走 A 分支"
#elifdef PLATFORM_B         /* 等价于 #elif defined(PLATFORM_B) */
#  define MODE "走 B 分支"
#elifndef PLATFORM_C        /* 等价于 #elif !defined(PLATFORM_C) */
#  define MODE "两者都没有定义"
#else
#  define MODE "兜底"
#endif

int main(void) {
    printf("%s\n", MODE);
    return 0;
}
```

`实测数据`
`Text`

```text
走 B 分支
```

`实测数据`

| 编译方式 | 结果 |
|---|---|
| `gcc -std=c23` | 通过，输出 `走 B 分支` |
| `gcc -std=c17`，指令落在**被跳过**的分组里 | 失败：`error: invalid preprocessing directive #elifdef` |
| `gcc -std=c17`，指令落在**被求值**的分组里 | 编译通过，但那一支不生效：条件为真却没有定义宏，报 `'M' undeclared` |

**C23 之前没有这两条指令**，C++ 侧在 C++17 的草案里也查不到。
后面两行的表现都来自同一件事：**旧标准下编译器不认这条指令**，
认不出时它既可能直接报错，也可能把那一支当成假、什么也不说。

### `#warning`

**`#warning` 与 `#error` 是一对**：`#error` 让编译停下来，`#warning` 只提示一句，编译继续。
C23 之前它是各家编译器的扩展，**C23 起进了标准**（N3220 §6.10.1 的指令文法里有它）。

`C`

```c
/* c23_warning.c    编译：gcc -std=c23 c23_warning.c -o c23_warning */
#include <stdio.h>

#ifndef ENABLE_FAST_PATH
#warning ENABLE_FAST_PATH is not defined, using the slow path
#endif

#warning 非 ASCII 字符会被转义

int main(void) {
    printf("这一行出现在运行输出里\n");
    return 0;
}
```

`实测数据`
`Text`

```text
c23_warning.c:5:2: warning: #warning ENABLE_FAST_PATH is not defined, using the slow path [-Wcpp]
c23_warning.c:8:2: warning: #warning \U0000975e ASCII \U00005b57\U00007b26\U00004f1a\U000088ab\U00008f6c\U00004e49 [-Wcpp]
这一行出现在运行输出里
```

**它是给编译的人看的**：产物照常生成，运行时看不到任何痕迹。
第三条提示来自程序里的第二条 `#warning`：**消息里出现非 ASCII 字符时，
GCC 会把它们转义成 `\U0000xxxx` 再显示**，消息本身没有变。

### `__has_include`

**先问一句「这个头文件在不在」，再决定包不包含它**：

`C`

```c
/* c23_has_include.c    编译：gcc -std=c23 c23_has_include.c -o c23_has_include */
#include <stdio.h>

/* __has_include 只能用在 #if 与 #elif 里 */
#if __has_include(<stdio.h>)
#  define HAS_STDIO 1
#else
#  define HAS_STDIO 0
#endif

#if __has_include(<no_such_header_xyz.h>)
#  define HAS_NOPE 1
#else
#  define HAS_NOPE 0
#endif

int main(void) {
    printf("有 stdio.h：%d，有一个不存在的头：%d\n", HAS_STDIO, HAS_NOPE);
    printf("__STDC_VERSION__ = %ldL\n", (long)__STDC_VERSION__);
    return 0;
}
```

`实测数据`
`Text`

```text
有 stdio.h：1，有一个不存在的头：0
__STDC_VERSION__ = 202311L
```

**`__has_include` 只能用在 `#if` 与 `#elif` 里**。不确定编译器认不认它时，先问一句：

`C`

```c
#if defined(__has_include)
#  if __has_include(<stdatomic.h>)
#    include <stdatomic.h>
#  endif
#endif
```

**版本**：C++17 起就有，C 侧是 C23 才有。

`实测数据`

| 编译方式 | 结果 |
|---|---|
| `gcc -std=c23` | 通过，`__STDC_VERSION__` 是 `202311L` |
| `gcc -std=c17` | 通过（当扩展支持），打印的两行相同，`__STDC_VERSION__` 是 `201710L` |

有了它，「有这个头就走快路径，没有就走备用实现」不必再靠构建系统去探测。

### `#embed`

**把一个文件的内容读成一串整数**，用来嵌二进制资源：

`C`

```c
/* 下面这段把同目录的 data.bin 嵌进数组 */
#include <stdio.h>

static const unsigned char data[] = {
#embed "data.bin"
};

int main(void) {
    printf("字节数 %zu，第一个 %d\n", sizeof data, data[0]);
    return 0;
}
```

`实测数据`
`Text`

```text
字节数 3，第一个 65
```

**展开之后就是一个初始化列表**：

`Bash`

```bash
printf 'ABC' > data.bin
gcc -std=c23 c23_embed.c -o c23_embed && ./c23_embed
gcc -std=c23 -E c23_embed.c | grep -A1 'unsigned char data'
```

`实测数据`
`Text`

```text
static const unsigned char data[] = {
       65,66,67
```

**它替代的是「先跑一个脚本把文件转成 `0x41, 0x42, ...` 再生成头文件」那套流程**
（`xxd -i`、`bin2c` 之类）。**C23 新增，GCC 15 起支持**；
旧标准下 GCC 也认，只是 `-pedantic` 会提示 `'#embed' before C23 is a GCC extension`。
它后面还能跟参数，例如 `#embed "data.bin" limit(2)` 只读前两个字节
（实测取到 `2 65 66`）。

> [!TIP]
> **这四样都要看编译器与标准版本。**
> `#elifdef`、`#warning`、`#embed` 是 C23 才进标准，`__has_include` 在 C++17 就有了；
> GCC 常在旧标准下也支持（当扩展），换个编译器就可能不认。
> **写之前先查目标工具链支持到哪一版**；要兼容旧版本，就用 `#if defined(...)` 与包含保护兜底。

# 第 5 节 `#` 与 `##`

**两个只在宏里能用的运算符。**

`C`

```c
/* stringize.c    编译：gcc -std=c23 stringize.c -o stringize */
#include <stdio.h>

#define STR(x)      #x                  /* # 把参数变成字符串 */
#define CAT(a, b)   a##b                /* ## 把两个记号粘起来 */
#define SHOW(expr)  printf(#expr " = %d\n", (expr))

int main(void) {
    printf("STR(hello) = %s\n", STR(hello));
    printf("STR(1 + 2) = %s\n", STR(1 + 2));

    int xy = 42;
    printf("CAT(x, y)  = %d\n", CAT(x, y));

    SHOW(3 * 4 + 1);
    return 0;
}
```

`实测数据`
`Text`

```text
STR(hello) = hello
STR(1 + 2) = 1 + 2
CAT(x, y)  = 42
3 * 4 + 1 = 13
```

| 运算符 | 作用 |
|---|---|
| `#x` | 把参数 `x` 的**原文**变成字符串字面量 |
| `a##b` | 把 `a` 与 `b` **拼成一个记号** |

**`SHOW` 那个宏值得注意**：它把表达式**同时**当字符串打印和当值计算，
因此输出 `3 * 4 + 1 = 13`——左边是原文，右边是结果。

> [!TIP]
> **`#` 的典型用途是写调试宏**：
> 打印出「哪个表达式」得到了「什么值」，
> 而不必手写两遍表达式。

# 第 6 节 预定义宏

**编译器自带一批宏。**

`C`

```c
/* predefined.c    编译：gcc -std=c23 predefined.c -o predefined */
#include <stdio.h>

int main(void) {
    printf("__FILE__         = %s\n", __FILE__);
    printf("__LINE__         = %d\n", __LINE__);
    printf("__DATE__         = %s\n", __DATE__);
    printf("__STDC_VERSION__ = %ld\n", __STDC_VERSION__);
    return 0;
}
```

`实测数据`
`Text`

```text
__FILE__         = predefined.c
__LINE__         = 6
__DATE__         = Sep 30 2026
__STDC_VERSION__ = 202311
```

**C++ 版把 `__STDC_VERSION__` 换成 `__cplusplus`**，输出 `201703`。

| 宏 | 内容 |
|---|---|
| `__FILE__` | 当前文件名 |
| `__LINE__` | 当前行号 |
| `__DATE__` / `__TIME__` | 编译时刻 |
| `__STDC_VERSION__` | C 标准版本（C23 是 `202311`） |
| `__cplusplus` | C++ 标准版本（C++17 是 `201703`） |

> [!TIP]
> **判断标准版本就用这两个宏**，
> 例如 `#if __cplusplus >= 201703L` 表示「需要 C++17 或更新」。
> 本教材的基准是 C++17 与 C23，因此这两个值是 `201703` 与 `202311`。

**`__FILE__` 与 `__LINE__` 是写日志与断言的基础**，
`assert` 就是靠它们报出「哪个文件的哪一行失败了」。

# 第 7 节 宏与替代方案

## 7.1 宏的问题清单

| 问题 | 原因 |
|---|---|
| 参数要加括号 | 文本替换，不认优先级 |
| 参数被求值多次 | 同上 |
| 没有类型检查 | 预处理器不懂类型 |
| 不进符号表 | 预处理阶段就消失了 |
| 不能调试 | 调试器看不到它 |
| 作用域不受 `{ }` 限制 | 它的作用域是「文件剩余部分」 |
| 出错信息难懂 | 报的是展开后的代码 |

## 7.2 用什么替代

| 想做什么 | 宏 | 更好的做法 |
|---|---|---|
| 定义常量 | `#define MAX 100` | **`constexpr int MAX = 100;`** |
| 短小的计算 | `#define SQ(x) ...` | **`constexpr` 函数** 或 `inline` 函数 |
| 类型无关的代码 | 宏 | **模板** |
| 条件编译 | `#if` | **没有替代**，只能用它 |
| 包含头文件 | `#include` | **没有替代** |
| 头文件保护 | `#ifndef` | `#pragma once`（非标准） |

**右列里的 `constexpr` 函数与模板是 C++ 的。**
C 里没有模板，也没有 `constexpr` 函数（C23 有 `constexpr` 对象，见第 7.4 小节），
**因此 C 代码里宏用得更多。**

**`inline` 函数是例外**：C 与 C++ 都有它，但两门语言里它的链接含义不同，
头文件里要写 `static inline` 才稳妥（见第 7.3 小节）。

**`constexpr` 函数的写法**：

`C++`

```cpp
constexpr int square(int x) { return x * x; }       // 有类型、只求值一次、能调试
```

**对比**：`#define MAX_A 100` 在符号表里找不到，
`constexpr int MAX_B = 100` 能找到（见 2.3 节）。

> [!IMPORTANT]
> **C++ 里宏的用途只剩三件事**：
> **条件编译**、**包含头文件**、**`#` 与 `##` 这类预处理器专属操作**。
> **其余场合都有更好的替代**——`constexpr`、模板、`inline` 函数。
>
> **C 里的选择少一些**：没有 `constexpr`（C23 才加入），
> 因此常量常用 `enum` 或宏。

## 7.3 用 `inline` 替换函数式宏

**7.1 里的前四条可以由 `inline` 函数解决**：

| 宏的问题 | `inline` 函数 |
|---|---|
| 参数要加括号 | 参数有类型，优先级由语言决定 |
| 参数被求值多次 | 实参只求值一次 |
| 没有类型检查 | 编译器按参数类型检查 |
| 不能调试、不进符号表 | 有函数名，能下断点、能出现在调用栈里 |

**先看求值次数**：

`C`

```c
/* macro_vs_inline.c    编译：gcc -std=c23 macro_vs_inline.c -o macro_vs_inline */
#include <stdio.h>

#define SQ_MACRO(x) ((x) * (x))                            /* 参数在宏体里出现两次 */
static inline int sq_inline(int x) { return x * x; }        /* 实参只求值一次 */

int main(void) {
    int i = 3;
    printf("宏   SQ_MACRO(i++) = %d，i = %d\n", SQ_MACRO(i++), i);

    int j = 3;
    printf("函数 sq_inline(j++) = %d，j = %d\n", sq_inline(j++), j);
    return 0;
}
```

`实测数据`
`Text`

```text
宏   SQ_MACRO(i++) = 12，i = 5      ← i 被加了两次
函数 sq_inline(j++) = 9，j = 4      ← j 只加了一次
```

> [!CAUTION]
> **`SQ_MACRO(i++)` 展开成 `((i++) * (i++))`，同一处改了两次 `i`。**
> 按标准这是未定义行为，gcc 给出 12 只是这一次的结果。
> **函数版本没有这个问题**：`j++` 作为实参只求值一次。

`文档`

> "If a side effect on a scalar object is unsequenced relative to either a
> different side effect on the same scalar object or a value computation using
> the value of the same scalar object, the behavior is undefined."
>
> —— N3220 §6.5.1/2

**再看类型检查**：同一个字符串实参，两边报的错完全不同。

`C`

```c
/* macro_bad_type.c    编译：gcc -std=c23 macro_bad_type.c （失败） */
#include <stdio.h>

#define SQ_MACRO(x) ((x) * (x))

int main(void) {
    printf("%d\n", SQ_MACRO("ab"));
    return 0;
}
```

`实测数据`
`Text`

```text
error: invalid operands to binary * (have 'char *' and 'char *')
```

**报错指到宏定义那一行**，因为它报的是展开后的代码。

`C`

```c
/* inline_bad_type.c    编译：gcc -std=c23 inline_bad_type.c （失败） */
#include <stdio.h>

static inline int sq_inline(int x) { return x * x; }

int main(void) {
    printf("%d\n", sq_inline("ab"));
    return 0;
}
```

`实测数据`
`Text`

```text
error: passing argument 1 of 'sq_inline' makes integer from pointer without a cast
```

**报错指到调用处**，说的是第 1 个实参类型不对，清楚得多。

**`inline` 会不会真的内联，由编译器决定**：

`C`

```c
/* inline_cost.c    编译：gcc -std=c23 -O0 -S inline_cost.c -o inline_cost.s */
#define SQ_MACRO(x) ((x) * (x))
static inline int sq_inline(int x) { return x * x; }

int use_macro(int a)  { return SQ_MACRO(a); }
int use_inline(int a) { return sq_inline(a); }
```

`实测数据`

| 优化 | `use_macro` | `use_inline` |
|---|---|---|
| `-O0` | 7 条指令，0 个 `call` | 10 条指令，**1 个 `call`** |
| `-O2` | 3 条指令，0 个 `call` | 3 条指令，0 个 `call` |

**`-O0` 下 `inline` 并没有内联**，函数照常被调用；
**`-O2` 下编译器自己把两边都内联了**。

**符号表里同样能看出来**：

`实测数据`
`Text`

```text
-O0  nm inline_cost.o
     0000000000000000 t sq_inline      ← 内部符号（小写 t）
     000000000000000f T use_macro
     000000000000001e T use_inline
     宏本身不产生任何符号

-O2  nm inline_cost.o
     0000000000000000 T use_macro
     0000000000000010 T use_inline     ← sq_inline 的符号消失了
```

**C 与 C++ 的 `inline` 含义不同，这一点必须写清**：

| | C++ | C（C99 起） |
|---|---|---|
| `inline` 主要是什么 | **链接层面的指示**：允许不同翻译单元里有相同的定义 | 同样与链接有关：不带 `static` 的 `inline` 定义不产生外部定义 |
| 谁决定内联 | 编译器 | 编译器 |
| 头文件里怎么写 | 写 `inline` 即可 | 写 **`static inline`** 才稳妥 |

**证据**：头文件里写不带 `static` 的 `inline`，两个翻译单元都包含它：

`C`

```c
/* add.h    编译：gcc -std=c23 -c add.h -o add.h.gch */
#ifndef ADD_H
#define ADD_H

inline int add_one(int x) { return x + 1; }     /* 注意：没有 static */

#endif
```

`实测数据`
`Bash`

```bash
# tu1.c 与 tu2.c 都 #include "add.h"，都调用 add_one，然后一起链接
gcc -std=c23 tu1.c tu2.c -o c_add
# 失败：undefined reference to `add_one'

g++ -std=c++17 tu1.c tu2.c -o cpp_add
# 通过
```

**同一对文件，换一个编译器就通过了**：C++ 允许相同的 `inline` 定义
出现在多个翻译单元里，C 的 `inline` 定义则需要别处再给出一个外部定义。

> [!IMPORTANT]
> **`inline` 是「允许内联」，不是「保证内联」。**
> `-O0` 下它照常是一次函数调用。
> 要强制内联得用编译器扩展（`__attribute__((always_inline))`、
> MSVC 的 `__forceinline`），见《04-语法/15-奇技淫巧与优化.md》第 7 节与附录 A.9。

**`inline` 换不掉宏的场合**：

| 需要 | 用什么 |
|---|---|
| 类型无关的代码 | 宏、C 的 `_Generic`、C++ 的模板 |
| `#` 字符串化、`##` 记号拼接 | 只能用宏（第 5 节） |
| 编译期常量 | C++ 的 `constexpr`、C 与 C++ 的 `enum` |

## 7.4 C 与 C++ 在这里的差别

| 用途 | C | C++ |
|---|---|---|
| 编译期常量 | `#define`、`enum`，或 `constexpr` 对象（C23 起） | **`constexpr`**（对象与函数） |
| 短函数 | `static inline` 函数 | `constexpr` / `inline` |
| 类型无关代码 | 宏（或 `void *`） | **模板** |
| 条件编译 | `#if` | `#if` |

> [!NOTE]
> **预处理器是两种语言共用的**，因此这一章的内容对 C 与 C++ 都成立。
> 差别只在「有多少替代品可用」——
> C++ 的替代品更多，因此宏用得更少。

# 第 8 节 `#pragma` 与 `_Pragma`

**`#pragma` 是留给实现自己解释的指令。**

`文档`

> "causes the implementation to behave in an implementation-defined manner. The behavior may
> cause translation to fail or cause the translator or the resulting program to behave in a
> non-conforming manner. Any such pragma that is not recognized by the implementation is ignored."
>
> —— N3220 §6.10.8/1

**两件事从这句话里直接读出来**：
同一条 `#pragma` 在不同编译器上可以完全不同；
**不认识的 `#pragma` 会被忽略，不报错**——名字写错了不会有人提醒。

## 8.1 常见的几条

| 写法 | 谁认 | 作用 |
|---|---|---|
| `#pragma once` | 主流编译器 | 头文件只展开一次 |
| `#pragma pack(...)` | 主流编译器 | 改结构体的对齐与填充 |
| `#pragma GCC diagnostic ...` | GCC 与 Clang | 局部开关警告 |
| `#pragma message("...")` | 主流编译器 | 编译期打印一句提示 |
| `#pragma warning(...)` | MSVC | 局部开关警告 |
| `#pragma comment(lib, ...)` | MSVC | 让链接器链上某个库 |

## 8.2 `#pragma once`

第 3.2 小节量过三种写法的结果：

`实测数据`

| 头文件写法 | 包含两次的结果 |
|---|---|
| 无保护 | **失败**：`redefinition of 'g_counter'` |
| `#ifndef` 卫士 | 通过 |
| `#pragma once` | 通过 |

取舍在这里：

| | `#ifndef` 卫士 | `#pragma once` |
|---|---|---|
| 在不在标准里 | 在 | **不在** |
| 写多少 | 三行（`#ifndef`、`#define`、`#endif`） | 一行 |
| 靠什么判断 | 自己起的宏名 | 文件本身 |
| 支持面 | 所有编译器 | 主流编译器都支持 |

> [!TIP]
> **两个都写不冲突**：`#pragma once` 写在最前，`#ifndef` 卫士包在外面。
> 认 `#pragma once` 的编译器少读一次文件，不认它的编译器还有卫士兜着。

## 8.3 `#pragma pack`：改结构体布局

`C`

```c
/* pragma_pack.c    编译：gcc -std=c23 pragma_pack.c -o pragma_pack */
#include <stdio.h>
#include <stdalign.h>

struct Plain { char c; int i; };        /* 自然对齐：c 后面补 3 个字节 */

#pragma pack(push, 1)                   /* 从这里开始按 1 字节对齐 */
struct Packed { char c; int i; };
#pragma pack(pop)                       /* 恢复原来的设置 */

alignas(1) struct Relaxed { char c; int i; };   /* 想在结构体上放松对齐：办不到 */

int main(void) {
    printf("Plain   = %zu，alignof = %zu\n", sizeof(struct Plain), alignof(struct Plain));
    printf("Packed  = %zu，alignof = %zu\n", sizeof(struct Packed), alignof(struct Packed));
    printf("Relaxed = %zu，alignof = %zu\n", sizeof(struct Relaxed), alignof(struct Relaxed));
    return 0;
}
```

`实测数据`
`Text`

```text
Plain   = 8，alignof = 4
Packed  = 5，alignof = 1
Relaxed = 8，alignof = 4
```

三行数字说明三件事：

- `Plain` 是自然布局——`char` 后面补 3 个字节，`int` 才能落在 4 的倍数上；
- `#pragma pack(push, 1)` 之后不再补字节：`char` 加 `int` 一共 5 字节，对齐要求降到 1；
- **`alignas` 办不到这件事**。它只能把对齐要求**加严**（至少按这个值对齐），放松没有效果：
  上面那条 `alignas(1)` 编译时 GCC 直接提示 `warning: useless '_Alignas' in empty declaration`，
  `Relaxed` 的大小与对齐跟 `Plain` 一样。

**`push` 与 `pop` 要配对**：`push` 记住当前设置，`pop` 恢复到它。
只写 `#pragma pack(1)` 而不 `pop`，**后面所有结构体都会跟着变**，这类问题很难查。

> [!CAUTION]
> **紧凑结构体的成员可能落在不对齐的地址上。**
> x64 上取这些成员能正常工作，代价是编译器要生成逐字节拼接的代码；
> **换成对齐要求严格的平台（不少 ARM 配置）会直接出错**。
> 只在嵌二进制格式（文件头、网络包）时用它，算完立刻 `pop`。

## 8.4 局部关掉一条警告

`C`

```c
/* pragma_diag.c    编译：gcc -std=c23 -Wall pragma_diag.c -o pragma_diag */
#include <stdio.h>

static int unused_helper(void) { return 1; }    /* 这一条会被 -Wunused-function 报出来 */

#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wunused-function"
static int unused_quiet(void) { return 2; }     /* 这一段里的同类警告被压掉 */
#pragma GCC diagnostic pop

int main(void) {
    printf("运行时的输出\n");
    return 0;
}
```

`实测数据`
`Text`

```text
pragma_diag.c:4:12: warning: 'unused_helper' defined but not used [-Wunused-function]
运行时的输出
```

**只有第一条被报出来**：第二条落在 `push` 与 `pop` 之间，`ignored` 把它压掉了，
出了这一段警告照旧。`ignored` 后面写的是警告的名字（`-Wunused-function` 去掉 `-W`），
换成 `error` 则会把这一段里的警告升级成错误。

**这是 GCC 与 Clang 的写法**，MSVC 的对应写法见第 8.6 小节。

## 8.5 `#pragma message`

`C`

```c
/* pragma_message.c    编译：gcc -std=c23 pragma_message.c -o pragma_message */
#include <stdio.h>

#pragma message("这一行出现在编译输出里")

int main(void) {
    printf("这一行出现在运行输出里\n");
    return 0;
}
```

`实测数据`
`Text`

```text
pragma_message.c:4:9: note: '#pragma message: 这一行出现在编译输出里'
这一行出现在运行输出里
```

**它是编译期的提示，产物里不占任何位置**：常见用法是提示某段代码依赖哪个可选宏、
哪个分支还没有实现。

## 8.6 MSVC 的两条

`待确认`

| 写法 | 作用 |
|---|---|
| `#pragma warning(disable: 4996)` | 关掉某条警告，编号是 MSVC 自己的体系 |
| `#pragma comment(lib, "ws2_32.lib")` | 让链接器自动链上这个库 |

这两条只有 MSVC 认。本章节的实测都在 `gcc` 上做，没有在 `cl` 上验证过，因此不贴输出。

## 8.7 `_Pragma`：把 pragma 放进宏里

**`#pragma` 是一整行指令，宏体里写不出来**：

`C`

```c
/* do_pragma_bad.c    编译：gcc -std=c23 do_pragma_bad.c -o do_pragma_bad（失败） */
#define NOTE(msg) #pragma message(msg)      /* 宏体里不能出现 #pragma 行 */

int main(void) {
    NOTE("hi")
    return 0;
}
```

`实测数据`
`Text`

```text
error: '#' is not followed by a macro parameter
```

**标准给出的替代品是 `_Pragma`**：它写成函数调用的样子，可以出现在宏体里，
也可以像普通语句一样放在文件里。

`C`

```c
/* do_pragma.c    编译：gcc -std=c23 do_pragma.c -o do_pragma */
#include <stdio.h>

/* 宏体里写不出 #pragma 行，用 _Pragma 代替：它接收一个字符串字面量 */
#define DO_PRAGMA(x) _Pragma(#x)
#define NOTE(msg)    DO_PRAGMA(message(msg))

/* 同一个 _Pragma 也可以改结构体布局，而且能在宏里用 */
#define PACK1 DO_PRAGMA(pack(push, 1))

struct Plain { char c; int i; };

PACK1
struct Packed { char c; int i; };
DO_PRAGMA(pack(pop))

int main(void) {
    NOTE("这条提示来自宏展开")
    printf("Plain = %zu，Packed = %zu\n", sizeof(struct Plain), sizeof(struct Packed));
    return 0;
}
```

`实测数据`
`Text`

```text
do_pragma.c:5:22: note: '#pragma message: 这条提示来自宏展开'
Plain = 8，Packed = 5
```

`文档`

> "A unary operator expression of the form: _Pragma ( string-literal )
> is processed as follows: The string literal is destringized by deleting the L prefix, if present,
> deleting the leading and trailing double-quotes, replacing each escape sequence \" by a
> double-quote, and replacing each escape sequence \\ by a single backslash. ... The resulting
> sequence of characters is processed through translation phase 3 to produce preprocessing tokens
> that are executed as if they were the pp-tokens in a pragma directive."
>
> —— N4659 §19.9/1

**`#define DO_PRAGMA(x) _Pragma(#x)` 就是这个算子最常用的包装**，N4659 §19.9 的示例给的也是它：
`#x` 先把参数变成字符串，`_Pragma` 再把字符串还原成 pragma 的内容。
**`_Pragma` 里的内容仍然交给实现解释**，能不能用还是看编译器。

**跨平台时要把它围起来**：

`C`

```c
#if defined(__GNUC__)
#  pragma GCC diagnostic ignored "-Wunused-function"
#elif defined(_MSC_VER)
#  pragma warning(disable: 4101)
#endif
```

> [!WARNING]
> **用了 `#pragma` 就等于用了某一家编译器的方言。**
> 它在标准里没有确定的含义，不认识的写法还会被静默忽略。
> 跨平台代码要么按上面的写法按编译器分支，要么改用标准手段——
> 对齐用 `alignof` 与显式的填充成员，条件包含用 `__has_include`（第 4.4 小节），
> 开关警告用编译选项。

```c
#define STR(x)      #x
#define CAT(a, b)   a##b
#define SHOW(expr)  printf(#expr " = %d\n", (expr))
int main(void) {
    int xy = 42;
    printf("%s | %s | %d\n", STR(1 + 2), STR(hello), CAT(x, y));
    SHOW(3 * 4 + 1);
    return 0;
}
```

`Bash`

```bash
gcc -std=c23 stringize.c -o s && ./s
# 1 + 2 | hello | 42
# 3 * 4 + 1 = 13
```

## A.9 注释在预处理之前就被删掉

`Bash`

```bash
# 注释 = 一个空格：int/**/x = 1; 合法，int a/**/b = 2; 报错
# 注释不能嵌套：第一个 */ 就把注释结束了
# 字符串里的 /* 不是注释
gcc -std=c23 -E -P show_comments.c        # int x = 1;
gcc -std=c23 -E -P -C show_comments.c     # 注释保留

# 宏定义里的注释也换成空格
gcc -std=c23 macro_comment.c -o macro_comment && ./macro_comment    # SUM = 3

# 注释掉含 */ 的代码，注释会提前结束
gcc -std=c23 comment_out_bad.c -o cob
# error: missing terminating " character
# error: expected expression before '/' token

# 改用 #if 0 则正常
gcc -std=c23 if0_stop.c -o i0 && ./i0     # done

# // 注释末尾的反斜杠把下一行吞掉
gcc -std=c23 -Wall comment_splice.c -o cs
# warning: multi-line comment [-Wcomment]
# error: 'y' undeclared (first use in this function)

# 翻译单元的产物：三行源代码变成一行
gcc -std=c23 -E -P unit.c -o unit.i && cat unit.i    # int x = 100;
```

## A.10 `inline` 函数与函数式宏

`Bash`

```bash
# 求值次数：宏 12，i = 5；函数 9，j = 4
gcc -std=c23 macro_vs_inline.c -o mvi && ./mvi

# 类型检查：宏报 invalid operands，函数报 passing argument 1
gcc -std=c23 macro_bad_type.c -o t1
gcc -std=c23 inline_bad_type.c -o t2

# -O0 / -O2 下 use_macro 与 use_inline 的指令条数与 call
gcc -std=c23 -O0 -S inline_cost.c -o O0.s
gcc -std=c23 -O2 -S inline_cost.c -o O2.s
# -O0：use_macro 7 条指令 0 个 call；use_inline 10 条指令 1 个 call
# -O2：两边都是 3 条指令 0 个 call

# 符号表
gcc -std=c23 -O0 -c inline_cost.c -o O0.o && nm O0.o
# t sq_inline / T use_macro / T use_inline
gcc -std=c23 -O2 -c inline_cost.c -o O2.o && nm O2.o
# 只剩 T use_macro 与 T use_inline

# C 与 C++ 的链接差别：add.h 里是不带 static 的 inline int add_one(int)
printf '#include "add.h"\nint a(void) { return add_one(1); }\n' > tu1.c
printf '#include "add.h"\nint main(void) { return add_one(2); }\n' > tu2.c
gcc -std=c23 tu1.c tu2.c -o c_add          # 失败：undefined reference to `add_one'
g++ -std=c++17 tu1.c tu2.c -o cpp_add      # 通过
```
