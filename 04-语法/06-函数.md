**函数是「一段有名字的代码」。**

**但这只是表面。函数真正做的事是封装**——
**把一段实现包起来，只留一个名字、几个参数、一个返回值作为对外的接口。**
调用方只要知道「给它什么、它给回什么」，不必知道里面怎么算。

**封装划出一条边界**：边界之内是它自己的世界，
边界之外只能通过参数与返回值与它打交道；
**只要接口不变，里面的实现怎么改，调用方都不用动。**
**理解了这条边界，很多「为什么改不动外面的变量」就不用背了。**

**在 C 里，函数是最主要的封装单位**；
`static` 用在函数上时，还能把可见范围再收窄到本文件
（见《04-语法/10-作用域、生存期与链接.md》第 4.3 小节）。

**到了 C++，类把封装又推进了一层**：数据与实现被收进类里，
**而对外露出的接口主要仍由函数承载**——它们成了成员函数
（见【待补：05-类与面向对象/】）。

# 第 1 节 封装与调用

## 1.1 封装：把实现收进一个名字

**封装的意思是：把实现藏起来，只把接口露出来。**

**函数的接口就是三样东西**：

`Text`

```
   名字      调用时写什么
   参数      要给它什么
   返回值    它能给回什么
```

**这三样写在声明里，调用方只看声明。**
函数体里怎么算、用了几个临时变量、先算哪一步，**调用方一律不必知道**。

**封装的价值在于「两边可以分别改」**：
只要接口不变，函数体可以重写、可以换算法，
**所有调用点一行都不用动**；反过来，调用方换个地方调用，函数体也不用改。

> [!IMPORTANT]
> **函数不是「一段可以重复使用的代码」，而是「一份实现加一个承诺」。**
> 承诺就是接口：给它这样的参数，它给回这样的结果。
> **复用它只是封装的副产品**——真正被复用的是那个承诺，不是那几行代码。

**同一个接口可以有几份实现**：`printf`、`malloc` 在不同平台上由不同的代码实现，
调用方的写法完全一样。**这正是封装要达到的效果。**

**C 与 C++ 里还有一层更小的封装**：`static` 函数只在本文件可见，
别的文件连名字都找不到（见《04-语法/10-作用域、生存期与链接.md》第 4.3 小节）。

## 1.2 调用时机器上做了什么

**看一段最简单的函数。**

`C`

```c
/* add.c    编译：gcc -std=c23 add.c -o add */
#include <stdio.h>

int add(int a, int b) {         /* 定义 */
    return a + b;
}

int main(void) {
    int r = add(2, 3);          /* 调用 */
    printf("%d\n", r);
    return 0;
}
```

**输出**：`5`

**调用发生时，机器上做了四件事**：

`Text`

```
   1. 把 2 与 3 放进约定的位置（寄存器或栈）
   2. 把返回地址压栈 —— 记住「回来之后从哪继续」
   3. 跳到 add 的第一条指令
   4. add 执行完，把结果放进约定位置，跳回返回地址
```

**这四步叫「调用约定」**，属于 ABI 的一部分
（见《01-编译器/00-语言的实现.md》第 5.4 小节）。

> [!IMPORTANT]
> **函数调用不是「跳过去再跳回来」这么简单**，
> 它包含一整套参数放哪、返回值放哪、谁负责清理栈的约定。
> **两边的约定不一致时，程序会以难以理解的方式出错**——
> 这是链接不同编译器产物时最常见的坑。

# 第 2 节 声明与定义

## 2.1 两者的区别

`C`

```c
int add(int a, int b);          /* 声明：告诉编译器有这个东西 */
int add(int a, int b) {         /* 定义：给出它的实体 */
    return a + b;
}
```

| | 声明 | 定义 |
|---|---|---|
| 说什么 | 名字、参数类型、返回类型 | 同上，**外加函数体** |
| 可以写几次 | 多次 | **只能一次** |
| 占不占空间 | 不占 | 占 |
| 能不能调用 | 能（但链接时要有定义） | 能 |

**只声明不定义，编译能过，链接会失败**：

`C`

```c
/* nodef.c    编译：gcc -std=c23 nodef.c -o nodef */
#include <stdio.h>

int add(int a, int b);          /* 只有声明 */

int main(void) {
    printf("%d\n", add(1, 2));
    return 0;
}
```

`实测数据`
`Text`

```text
undefined reference to `add'
collect2.exe: error: ld returned 1 exit status
```

**注意报错出现在链接阶段，不是编译阶段**——
编译器只检查「用法对不对」，链接器才检查「东西在不在」。

## 2.2 为什么要分开写

**因为 C 与 C++ 都是「一次读一个文件」的**。

`Text`

```
   a.c 里调用 add()         编译器读到这时，必须已经知道 add 长什么样
        ↓
   所以 a.c 里要先声明
        ↓
   真正的定义在 b.c 里，链接时才接上
```

**这就是头文件的用途**：把声明集中起来，两边都 `#include`
（详见《04-语法/13-预处理器.md》第 3 节）。

# 第 3 节 参数是按值传递的

## 3.1 函数里改不动外面的变量

`实测数据`
`C`

```c
/* pass_by_value.c    编译：gcc -std=c23 pass_by_value.c -o pass_by_value */
#include <stdio.h>

void by_value(int x)   { x = 99; }          /* 改的是副本 */
void by_pointer(int *p) { *p = 99; }        /* 改的是外面那块内存 */

int main(void) {
    int a = 1, b = 1;
    by_value(a);
    by_pointer(&b);
    printf("a = %d, b = %d\n", a, b);
    return 0;
}
```

输出是 `a = 1, b = 99`。

**`by_value` 收到的是一份拷贝。** 它把拷贝改成 99，原件没动。

## 3.2 「按值」这两个字的含义

`Text`

```
   调用 by_value(a) 时：
        a 的值  ──拷贝──►  x
                            ↑ 从此两者无关
```

**不是「传变量」，是「传值」。**

> [!IMPORTANT]
> **C 与 C++ 的参数一律按值传递。**
> 想让函数改外面的东西，**必须把地址传进去**——
> 传 `&b` 而不是 `b`，函数里用 `*p` 写回。
> **指针看起来像「按引用传」，实际是「按值传了一个地址」。**

**这一点在 C++ 里有个例外**：C++ 有真正的引用参数 `T&`，
它在语法上看不出「传了地址」，但底层机制就是指针
（见《04-语法/07-数组、指针与引用.md》第 3.3 小节）。

# 第 4 节 返回值

## 4.1 返回值也是拷贝

**函数返回时，返回值被复制到一个约定的位置。**

**因此返回局部变量的地址是错的**：

`C`

```c
/* dangle.c    编译：gcc -std=c23 dangle.c -o dangle */
#include <stdio.h>

int *bad(void) {
    int local[3] = { 1, 2, 3 };
    return local;               /* 返回局部数组的地址 */
}

int main(void) {
    int *p = bad();
    printf("%d %d %d\n", p[0], p[1], p[2]);
    return 0;
}
```

**编译只有一个警告，运行时直接崩溃。**

`实测数据`
`Text`

```text
编译警告: warning: function returns address of local variable [-Wreturn-local-addr]
运行结果: 程序崩溃，退出码 -1073741819（0xC0000005，访问冲突）
```

**原因**：`local` 是 `bad` 的局部变量，函数一返回它的栈空间就失效了。
`p` 指向的是一块已经不属于自己的内存。

> [!CAUTION]
> **返回局部变量的地址是未定义行为。**
> 它可能崩溃，也可能「看起来能用」——
> 后者更危险，因为问题会在别处爆发。
> **这条警告默认就开着，见到必须处理。**

**正确的做法有三种**：

| 做法 | 说明 |
|---|---|
| 让调用方提供缓冲区 | `void fill(int *out, int n)` |
| 返回 `static` 变量 | 简单但不可重入 |
| 用 `malloc` 分配 | 调用方负责 `free` |

## 4.2 `main` 的返回值

**`main` 的返回值会变成进程的退出码。**

`实测数据`
`C`

```c
int main(void) {
    return 0;       /* 0 表示成功 */
}
```

**`main` 里不写 `return` 也能编过**——
C99 起规定 `main` 执行到末尾等价于 `return 0;`，**C++ 从第一版起就有同一条规定**。

> [!TIP]
> **但显式写 `return 0;` 更好**，因为它让「成功」这件事看得见。
> 非 `main` 的函数**没有这个特权**——不写 `return` 而返回值被用到，
> 是未定义行为。

# 第 5 节 C 与 C++ 的分歧

**这一节集中了函数相关的主要差异。**

## 5.1 `void f()` 的含义：C23 改了

**这是本教材基准里最容易疏忽错误的一处。**

`C`

```c
void f() { }            /* 空参数列表 */
int main(void) {
    f(1, 2, 3);         /* 多传了参数 */
    return 0;
}
```

`实测数据`

| 标准 | `f(1, 2, 3)` 的结果 |
|---|---|
| **C17** | **通过**，运行正常 |
| **C23** | **失败**：`too many arguments to function 'f'; expected 0, have 3` |
| **C++17** | **失败**：`too many arguments to function 'void f()'` |

> [!IMPORTANT]
> **C23 起，`void f()` 与 `void f(void)` 含义相同**——都表示「不接收参数」。
> **C17 及更早，`void f()` 表示「参数表未指定」**，
> 编译器不检查实参个数，因此 `f(1, 2, 3)` 能编过。
>
> **这是一处 C23 的破坏性改动**：
> 老代码里若依赖「空参数列表 = 参数不定」，升级到 C23 后会编译失败。

**同一个变化也影响函数声明**：

`C`

```c
int f();                    /* 空参数列表 */
int main(void) { f(1, 2); } /* C17 通过，C23 失败 */
int f(int a, int b) { return a + b; }
```

**C17 输出 `3`；C23 报 `too many arguments`。**

> [!TIP]
> **写代码时一律写 `void`**：`int f(void)`。
> 这样在 C17 与 C23 下含义一致，也不会有跨版本的意外。

## 5.2 默认参数

**C++ 有，C 没有。**

`实测数据`
`C++`

```cpp
// default_arg.cpp    编译：g++ -std=c++17 default_arg.cpp -o default_arg
#include <cstdio>

int add(int a, int b = 10) { return a + b; }

int main() {
    std::printf("%d %d\n", add(1), add(1, 2));
    return 0;
}
```

输出是 `11 3`——省略第二个参数时用 10。

**C 里同样写法直接失败**：`too few arguments to function 'add'; expected 2, have 1`

## 5.3 函数重载

**C++ 有，C 没有。**

`实测数据`
`C++`

```cpp
// overload.cpp    编译：g++ -std=c++17 overload.cpp -o overload
#include <cstdio>

int    f(int x)    { return x; }
double f(double x) { return x; }

int main() {
    std::printf("%d %.1f\n", f(1), f(2.5));
    return 0;
}
```

输出是 `1 2.5`——编译器按实参类型选了不同的 `f`。

**C 里同样写法失败**：`conflicting types for 'f'; have 'double(double)'`

**原因**：C 的函数名就是符号名，两个 `f` 会撞在一起；
C++ 会把参数类型编进符号名里（叫**名字修饰**），
因此 `_Z1fi` 与 `_Z1fd` 是两个不同的符号
（见《01-编译器/00-语言的实现.md》第 4.2 小节）。

> [!IMPORTANT]
> **重载能成立，靠的是名字修饰，不是「语言更聪明」。**
> 这也解释了为什么 C 与 C++ 混编时必须写 `extern "C"`——
> 它关掉名字修饰，让 C 能找到那个符号。

## 5.4 `main` 的返回类型

`实测数据`

| 写法 | C23 | C++17 |
|---|---|---|
| `int main(void)` | 通过 | 通过 |
| `int main()` | 通过 | 通过 |
| `void main()` | **警告** `return type of 'main' is not 'int'` | **错误** `'::main' must return 'int'` |
| `int main(int argc)` | 警告 `takes only zero or two arguments` | 警告 |
| `int main(int argc, char **argv)` | 通过 | 通过 |

**注意 `void main()` 那一行**：
**C 只给警告（默认还关着，要 `-Wall` 才显示），C++ 直接报错。**

> [!CAUTION]
> **`void main()` 不是合法写法。**
> 它在 C 里可能编过，但退出码会变成随机值——
> 因为运行环境读不到你写的返回值。
> **一律写 `int main(void)` 或 `int main(int argc, char **argv)`。**

# 第 6 节 函数指针：函数也是一种值

**函数有地址，因此可以放进指针。**

`C`

```c
/* funcptr.c    编译：gcc -std=c23 funcptr.c -o funcptr */
#include <stdio.h>

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int main(void) {
    /* 声明一个指向「接收两个 int、返回 int」的函数的指针 */
    int (*op)(int, int) = add;

    printf("%d\n", op(5, 3));       /* 用指针调用 */

    op = sub;                       /* 指向另一个函数 */
    printf("%d\n", op(5, 3));
    return 0;
}
```

**输出**：`8` 与 `2`

**读这个声明的办法**：从变量名出发，先看右边，再看左边。

`Text`

```
   int (*op)(int, int)
         └┬┘
        op 是一个指针
              └───┬───┘
            指向「接收两个 int、返回 int」的函数
```

**这一读法在《04-语法/02-数据类型与类型系统.md》第 4 节
讲 `typedef` 时用过，那里给出了把函数指针类型起名的三步做法。**

> [!TIP]
> **函数指针的完整用法（回调、`qsort`、跳转表）见
> 《04-语法/07-数组、指针与引用.md》第 4 节。**
> 本节只说明「函数有地址」这一件事。

**C++ 里还有更简洁的写法**（`auto`、`std::function`、lambda），
它们分别属于 `03-表达式与运算符`、`08-字符串` 与
【待补：05-类与面向对象/】。

# 第 7 节 调用的代价与内联

**第 1.2 小节列过调用的四步**：放参数、压返回地址、跳过去、跳回来。
**这四步与函数体算了什么无关，是调用本身的固定开销。**

## 7.1 一次调用要花多少

`实测数据`
`C`

```c
/* call_cost.c    编译：gcc -std=c23 -O0 -S call_cost.c -o call_cost_O0.s
 * 完整文件见附录 A.6。
 */
int add(int a, int b) {                 /* 函数体只有一次加法 */
    return a + b;
}

int use_add(int x) { return add(x, 1); }
```

`实测数据`
`Assembly`

```asm
use_add:
    pushq    %rbp
    movq     %rsp, %rbp
    subq     $32, %rsp
    movl     %ecx, 16(%rbp)         /* 存下参数 x */
    movl     16(%rbp), %eax
    movl     $1, %edx               /* 第二个参数放进 edx */
    movl     %eax, %ecx             /* 第一个参数放进 ecx */
    call     add                    /* 跳过去 */
    addq     $32, %rsp
    popq     %rbp
    ret
```

**`add` 只做一次加法，`use_add` 为这次调用花了 11 条指令。**

> [!IMPORTANT]
> **函数体越短，调用开销占比越大。**
> **内联就是把这笔开销省掉**：把函数体直接搬进调用点，
> 参数传递与跳转都不再需要。

## 7.2 编译器自己就会内联

**同一份代码换 `-O2` 编译，`call` 消失了**：

`实测数据`

| 函数 | `-O0` 指令数 | `-O0` 的 `call` | `-O2` 指令数 | `-O2` 的 `call` |
|---|---|---|---|---|
| `add` | 9 | 0 | 2 | 0 |
| `use_add` | 11 | **1** | **2** | **0** |
| `big` | 26 | 0 | 17 | 0 |
| `use_big` | 10 | **1** | **17** | **0** |

**`use_add` 从「11 条指令加一次调用」变成两条指令**：

`实测数据`
`Assembly`

```asm
use_add:
    leal    1(%rcx), %eax       /* 内联之后只剩 x + 1 */
    ret
```

**`big` 也被内联进 `use_big`**（26 条加一次调用，变成 17 条、没有调用）。

> [!IMPORTANT]
> **内联是编译器的决定，不是源码里写出来的。**
> 它按自己的成本模型判断：函数体多大、被调用几次、调用点在不在循环里。
> **同一份源码，`-O0` 下每个调用都是真调用，`-O2` 下小函数全部就地展开。**

## 7.3 有四种情形它内联不了

`实测数据`

| 情形 | 例子 | `-O2` 下的结果 |
|---|---|---|
| **递归** | `fib(n - 1) + fib(n - 2)` | 展开了一部分，**仍有 `call fib`** |
| **只有声明，定义在别的文件** | `int ext(int);` | 变成 `jmp ext`（尾调用），跳转仍在 |
| **通过函数指针调用** | `f(x, 2)` | 变成 `jmp *%rax`（间接跳转） |
| **函数取过地址** | `int (*fp)(int, int) = add;` | `add` 的实体必须保留 |

**前三种是「看不到函数体，或者看到了也展不开」**；
**第四种说明「内联」不等于「函数消失」**——
只要有人能拿到它的地址，就必须留一份实体。

## 7.4 什么时候该考虑内联

**先分清三件事**：

| 想做的事 | 该动什么 |
|---|---|
| 让编译器整体优化得更好 | **编译选项**（`-O2`） |
| 让别的文件也能内联某个函数 | **把定义放进头文件** |
| 强行要求内联 | `__attribute__((always_inline))`、`__forceinline` |

**`inline` 关键字不在这张表里**：C 里它管的是「要不要生成函数体」，
C++ 里它管的是「允许多个翻译单元各有一份定义」，
**两者都不是「请内联」**（见《04-语法/14-奇技淫巧与优化.md》第 7.1 小节）。

**值得内联的场合**：

| 场合 | 理由 |
|---|---|
| 函数体只有一两行（取值、包装、转发） | 调用开销比函数体本身还大 |
| 调用点在热点循环里 | 省下的开销被循环次数放大 |
| 定义在头文件里的短函数 | 每个翻译单元都看得见，编译器自己会判断 |

**不值得的场合**：

| 场合 | 理由 |
|---|---|
| 函数体很大 | 每个调用点展开一份，代码膨胀、指令缓存装不下 |
| 需要下断点调试 | 内联之后断点打不进去 |
| 只是「感觉这里慢」 | 没有测量就没有依据 |

> [!TIP]
> **顺序是：先开 `-O2`，再测量，最后才考虑手工内联。**
> 编译器的成本模型看得见调用点上下文与目标 CPU；
> **手工内联的收益要用实测证明**（强制内联的代价见
> 《04-语法/14-奇技淫巧与优化.md》第 7.2、7.4 小节）。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 声明 | Declaration | 告诉编译器有个东西，不给实体 |
| 定义 | Definition | 给出实体 |
| 调用约定 | Calling convention | 参数放哪、返回值放哪、谁清栈 |
| 按值传递 | Pass by value | 传的是拷贝 |
| 名字修饰 | Name mangling | 把参数类型编进符号名，重载靠它 |
| 函数指针 | Function pointer | 存放函数地址的指针 |
| 悬垂指针 | Dangling pointer | 指向已失效内存的指针 |
| 封装 | Encapsulation | 把实现藏起来，只露出接口 |
| 接口 | Interface | 名字、参数与返回值这三样 |
| 内联 | Inlining | 把函数体搬进调用点，省掉调用开销 |
| 尾调用 | Tail call | 函数末尾的调用，可以变成一次跳转 |

## A.6 调用的代价与内联

`C`

```c
/* call_cost.c */
int add(int a, int b) {                 /* 小函数：编译器愿意内联 */
    return a + b;
}

int big(int x) {                        /* 稍大一点，看编译器还内不内联 */
    int s = 0;
    for (int i = 0; i < 8; i++) {
        s += x * i + (s >> 1) - (x ^ i);
        s ^= (s << 3);
    }
    return s;
}

int fib(int n) {                        /* 双递归：无法化成循环 */
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

int ext(int x);                         /* 只有声明：定义在别的文件里 */

int use_add(int x) { return add(x, 1); }
int use_big(int x) { return big(x); }
int use_fib(int x) { return fib(x); }
int use_ext(int x) { return ext(x); }
int use_indirect(int (*f)(int, int), int x) { return f(x, 2); }

int (*fp)(int, int) = add;              /* 取过地址：add 的实体必须留着 */
```

`Bash`

```bash
gcc -std=c23 -O0 -S call_cost.c -o call_cost_O0.s
gcc -std=c23 -O2 -S call_cost.c -o call_cost_O2.s
```

**数一数每个函数里的指令与 `call`**：

`实测数据`

| 函数（`-O0`） | 指令数 | 其中 `call` |
|---|---|---|
| `add` | 9 | 0 |
| `big` | 26 | 0 |
| `fib` | 23 | **2** |
| `use_add` | 11 | **1** |
| `use_big` | 10 | **1** |
| `use_fib` | 10 | **1** |
| `use_ext` | 10 | **1** |
| `use_indirect` | 13 | **1** |

`实测数据`

| 函数（`-O2`） | 指令数 | 其中 `call` |
|---|---|---|
| `add` | 2 | 0 |
| `big` | 17 | 0 |
| `fib` | 265 | **1** |
| `use_add` | 2 | **0** |
| `use_big` | 17 | **0** |
| `use_fib` | 35 | **1** |
| `use_ext` | 1 | 0 |
| `use_indirect` | 4 | 0 |

**`-O2` 下 `use_ext` 只剩 1 条指令**（`jmp ext`）、
**`use_indirect` 剩 4 条**（`jmp *%rax`）：
它们不再是「调用加返回」，而是把返回地址直接交给对方，
**但跳转本身还在，函数体也没有展开**。
**`fib` 在 `-O2` 下涨到 265 条指令**：编译器展开了几层递归，
**剩下的那次 `call fib` 去不掉**——递归无法完全内联。
