**导读里留了一个问题。**

> `static` 用在**函数内部**的变量上、用在**全局变量**上、
> 用在**类成员函数**上，三者的含义看起来毫不相干。
> **它们为什么共用一个关键字？**

**本章回答这个问题。**

**答案不是「背三条规则」，而是「`static` 同时影响了三件不同的事」**，
而这三件事各自都能被它影响。先把三件事分开讲清，答案自然就出来了。

# 第 1 节 三件不同的事

**先把三个概念分开。**

| 概念 | 回答的问题 | 例子 |
|---|---|---|
| **作用域** | 这个名字**在源码的哪些地方能被看到** | 块作用域、文件作用域 |
| **生存期** | 这个对象**在程序运行的哪段时间里存在** | 自动、静态、动态 |
| **链接** | 这个名字**能不能被别的文件看到** | 外部链接、内部链接、无链接 |

**三者互不相关**——任意组合都可能出现。

`实测数据`

| 例子 | 作用域 | 生存期 | 链接 |
|---|---|---|---|
| 函数里的普通局部变量 | 块 | 自动 | 无 |
| 函数里的 `static` 局部变量 | **块** | **静态** | 无 |
| 文件里的普通全局变量 | 文件 | 静态 | **外部** |
| 文件里的 `static` 全局变量 | 文件 | 静态 | **内部** |

**看第二行与第四行**：
**`static` 在局部变量上改的是「生存期」，在全局变量上改的是「链接」。**
**它改的不是同一件事——这就是「三个 `static`」的根源。**

> [!IMPORTANT]
> **`static` 的含义是「与程序同寿命」还是「只在本文件可见」，
> 取决于它出现在哪。** 它出现在局部变量前时是前者，
> 出现在全局变量或函数前时是后者。
> **两者共用一个关键字，是因为它们都表示「固定下来、不随上下文变化」。**

# 第 2 节 作用域

## 2.1 四种作用域

| 作用域 | 覆盖范围 | 谁有 |
|---|---|---|
| **块作用域** | `{ }` 之内 | 局部变量、函数参数 |
| **文件作用域** | 整个 `.c` / `.cpp` 文件 | 全局变量、函数 |
| **函数作用域** | 整个函数 | 只有语句标签（`goto` 的目标） |
| **函数原型作用域** | 那一行声明 | 参数名（写不写都行） |

**函数作用域只有一种东西**：`goto` 的标签。
**因此 `goto` 的标签可以叫 `end`，而别处也能有叫 `end` 的变量。**

## 2.2 同名时谁遮住谁

`C`

```c
/* shadow.c    编译：gcc -std=c23 shadow.c -o shadow */
#include <stdio.h>

int x = 1;                      /* 文件作用域 */

int main(void) {
    printf("外层 x = %d\n", x);

    int x = 2;                  /* 块作用域，遮住外层 */
    printf("块内 x = %d\n", x);

    {
        int x = 3;              /* 更内层，再遮一次 */
        printf("最内层 x = %d\n", x);
    }

    printf("回到块内 x = %d\n", x);
    return 0;
}
```

`实测数据`
`Text`

```text
外层 x = 1
块内 x = 2
最内层 x = 3
回到块内 x = 2
```

**内层的 `x` 一离开 `{ }` 就消失了**，外层那个又露出来。

> [!WARNING]
> **遮蔽（shadowing）是 bug 的常见来源。**
> 内层变量把外层遮住后，你在内层想改外层那个，改的却是内层的。
> **编译器默认不警告**——gcc 的 `-Wshadow` 才检查。

# 第 3 节 生存期

## 3.1 三种生存期

| 生存期 | 什么时候存在 | 谁有 |
|---|---|---|
| **自动** | 进入块时诞生，离开块时消失 | 普通局部变量 |
| **静态** | **程序启动时诞生，程序结束时消失** | 全局、`static` 局部 |
| **动态** | `malloc` 到 `free` 之间 | 堆上的对象 |

**「生存期」与「作用域」是两件事。**

`C`

```c
void f(void) {
    static int kept = 0;    /* 作用域：这个块；生存期：整个程序 */
    kept++;
}
```

**`kept` 出了这个块就看不见了（作用域结束），但它仍然存在（生存期没结束）。**

## 3.2 `static` 局部变量：只初始化一次

`C`

```c
/* static_local.c    编译：gcc -std=c23 static_local.c -o static_local */
#include <stdio.h>

void counter(void) {
    int        normal = 0;      /* 每次进函数都重新初始化 */
    static int kept   = 0;      /* 只初始化一次 */
    normal++;
    kept++;
    printf("normal = %d, kept = %d\n", normal, kept);
}

int main(void) {
    counter();
    counter();
    counter();
    return 0;
}
```

`实测数据`
`Text`

```text
normal = 1, kept = 1
normal = 1, kept = 2
normal = 1, kept = 3
```

**`normal` 每次都是 1，`kept` 一直累加。**

**原因**：`static int kept = 0;` 的初始化**只在程序启动时做一次**，
不在每次进入函数时做。

> [!IMPORTANT]
> **`static` 局部变量的初始化语句「只执行一次」。**
> 这一点在 C++ 里更明显——如果初值是一个函数调用，
> 那个函数只会被调用一次（C++11 起还保证线程安全）。

**它的地址在函数返回后仍然有效**：

`实测数据`
`Text`

```text
静态局部变量的地址仍然有效: 42
```

**而自动局部变量的地址在函数返回后就失效了**——
返回它会造成悬垂指针，实测后果见《04-语法/07-函数.md》第 4.1 小节。

## 3.3 `static` 局部变量的代价

| 代价 | 说明 |
|---|---|
| **不可重入** | 同一函数被两个线程同时调用会互相干扰 |
| **递归时共享** | 递归的每一层用的是同一个变量 |
| **难测试** | 两次调用之间有隐藏状态 |

> [!CAUTION]
> **`static` 局部变量是「隐藏的全局状态」。**
> 它让函数的行为依赖「之前被调用过几次」，
> 这在多线程与递归场景下会直接出错。
> **只在确实需要「记住上次」时才用**，例如一次性初始化的标志。

# 第 4 节 链接

## 4.1 三种链接属性

**先看「链接」在做什么。** 编译是**一个文件一个文件**做的
（见《01-编译器/01-编译与链接.md》第 2 节），每个 `.c` 单独编成一个目标文件；
**链接器再把它们拼成一个程序**。拼接靠的是**符号**：
谁定义了 `printf`、谁要用它，两边靠名字对上。

**链接属性说的就是一件事：一个名字会不会变成符号，以及变成哪一种。**

`实测数据`

| 链接属性 | 含义 | 别的文件能用吗 | 在目标文件里 |
|---|---|---|---|
| **外部链接** | 名字成为**全局符号** | 能 | 有符号：`nm` 显示大写（`T` `D` `B`），或 `U`（要用但没定义） |
| **内部链接** | 名字成为**本文件的符号** | 不能 | 有符号：`nm` 显示小写（`t` `d` `b`） |
| **无链接** | **不进符号表**，只是编译期给这个块内的名字 | 不能 | **没有符号** |

**三者可以直接在符号表里看出来**：

`实测数据`
`C`

```c
/* kinds.c    编译：gcc -std=c23 -c kinds.c -o kinds.o */
int  ext_var;                   /* 外部链接 */
static int int_var;             /* 内部链接 */

int ext_func(void) { return 1; }        /* 外部链接 */
static int int_func(void) { return 2; } /* 内部链接 */

void has_no_linkage(void) {
    int local = 3;              /* 无链接 */
    static int local_static = 4;/* 无链接，但生存期是静态的 */
    typedef int myint;          /* 无链接 */
    myint x = local;
    (void)x;
label:;                         /* 标签：无链接 */
    goto label;
}
```

`实测数据`
`Bash`

```bash
gcc -std=c23 -c kinds.c -o kinds.o
nm kinds.o
```

`实测数据`
`Text`

```text
0000000000000000 T ext_func        ← 外部链接：大写 T
0000000000000000 B ext_var         ← 外部链接：大写 B
0000000000000016 T has_no_linkage
000000000000000b t int_func        ← 内部链接：小写 t
0000000000000004 b int_var         ← 内部链接：小写 b
0000000000000000 d local_static.0  ← 函数内 static 的存储，名字是编译器造的
```

**`local`、`myint`、`label` 一个都没有出现**——它们是无链接的名字，
**只在编译期有意义，编译完就不存在了**。

**`local_static.0` 那一行值得多看一眼**：函数里的 `static` 变量是**无链接**的，
但它必须有存储，于是编译器给它造了一个内部名字。
**符号表里出现的不是源码里的那个名字**，这正说明它没有链接。

> [!IMPORTANT]
> **无链接不等于没有存储。**
> 它说的是「这个名字不参与跨文件的对接」。
> 局部变量、函数里的 `static` 变量、`typedef` 名、标签都是无链接的，
> **其中前两者的存储照样存在**。

**谁有哪种链接**：

`实测数据`

| 声明在哪 | 名字 | 链接属性 |
|---|---|---|
| 文件作用域 | 普通变量、函数 | **外部** |
| 文件作用域 | 加了 `static` 的变量、函数 | **内部** |
| 文件作用域（C++） | `const` 变量、匿名 `namespace` 里的名字 | **内部**（第 5.1 小节） |
| 块作用域 | 局部变量、函数参数、`typedef` 名、标签 | **无** |
| 块作用域 | **`extern` 声明** | **看它链接到谁**，通常是**外部** |

**最后一行最容易记错**：`extern` 声明写在块里，它仍然有链接。

`实测数据`
`C`

```c
/* block_extern.c    编译：gcc -std=c23 -c block_extern.c -o block_extern.o */
void set_g(void) {
    extern int g;          /* 块作用域，但仍然有外部链接 */
    g = 5;
}

void use_local(void) {
    int g = 1;             /* 块作用域的普通局部变量：无链接 */
    (void)g;
}
```

`实测数据`
`Text`

```text
                 U g        ← extern 那个 g：外部符号，此处还没有定义
0000000000000000 T set_g
0000000000000014 T use_local
```

**`U` 是大写的，说明它是外部符号**；`use_local` 里那个同名的 `g` 没有留下任何符号。

> [!WARNING]
> **不要用「写在函数里就是无链接」来记。**
> 判据是**这个名字要不要与别的文件对接**：
> 要，就有链接（块里的 `extern` 就是这种情况）；不要，才无链接。

## 4.2 `static` 在全局变量上改的是链接

**这一条与 3.2 节的 `static` 不是同一件事。**

`C`

```c
/* a.c    编译：gcc -std=c23 -c a.c -o a.o */
int shared = 1;             /* 外部链接：别的文件能访问 */
static int hidden = 2;      /* 内部链接：只有 a.c 能用 */
```

`C`

```c
/* b.c    编译：gcc -std=c23 -c b.c -o b.o（两个文件一起链接的命令见下） */
extern int shared;          /* 声明：这个符号在别处定义 */
extern int hidden;          /* 试图访问 a.c 里的 hidden */
int main(void) { return shared + hidden; }
```

`实测数据`
`Bash`

```bash
gcc -std=c23 -c a.c -o a.o
gcc -std=c23 -c b.c -o b.o
gcc a.o b.o -o ab            # 链接失败
```

`实测数据`
`Text`

```text
b.o:b.c:(.rdata$.refptr.hidden[.refptr.hidden]+0x0): undefined reference to `hidden'
collect2.exe: error: ld returned 1 exit status
```

**报错里只有 `hidden`，没有 `shared`**：`shared` 是外部链接，链接器找得到；
**`hidden` 是内部链接，别的文件里写 `extern` 也够不着它。**

**`hidden` 有 `static`，因此它是内部链接**——
别的文件里即使写了 `extern int hidden;` 也找不到它。

> [!IMPORTANT]
> **在全局变量前加 `static`，生存期没有变化**（本来就是静态的），
> **变的是「别的文件能不能看到它」。**
> 这与 3.2 节「在局部变量前加 `static` 改的是生存期」完全不同。

## 4.3 `static` 用在函数上

**同样改的是链接。**

`C`

```c
/* e.c    编译：gcc -std=c23 -c e.c -o e.o */
static int helper(void) { return 1; }   /* 只有 e.c 能调用 */
int pub(void) { return helper(); }      /* 对外提供入口 */
```

`C`

```c
/* bad_caller.c    编译：gcc -std=c23 -c bad_caller.c -o bad_caller.o */
int helper(void);               /* 声明一下，试图调用 e.c 里的 static 函数 */
int main(void) { return helper(); }
```

`实测数据`
`Bash`

```bash
gcc -std=c23 -c bad_caller.c -o bad_caller.o
gcc e.o bad_caller.o -o bad     # 链接失败
```

`实测数据`
`Text`

```text
bad_caller.o:bad_caller.c:(.text+0xe): undefined reference to `helper'
collect2.exe: error: ld returned 1 exit status
```

**从另一个文件调用 `helper` 会链接失败**——它只在 `e.c` 内部可见。

> [!TIP]
> **`static` 函数是 C 里「私有函数」的实现方式。**
> C 没有 `private` 关键字，用 `static` 让函数只在本文件可见，
> 既避免命名冲突，也让读者一眼看出「这个函数不对外」。

## 4.4 `extern`：声明而不定义

`C`

```c
/* c.c */
int value = 7;              /* 定义 */

/* d.c */
extern int value;           /* 声明：它在别处定义 */
int main(void) { return value; }
```

`实测数据`

| 编译方式 | 结果 |
|---|---|
| 两个文件一起编 | **通过**，输出 `7` |
| 只编 `d.c` | **失败**：`undefined reference to 'value'` |

**`extern` 不分配空间**，它只是告诉编译器「有这么个东西，在别处」。

**完整讲解见《01-编译器/00-语言的实现.md》第 6 节。**

## 4.5 用 `nm` 看链接属性

**`nm` 会按大小写区分链接属性。**

`C`

```c
/* sym.c    编译：gcc -std=c23 -c sym.c -o sym.o */
int global_var = 1;             /* 外部链接 */
static int file_var = 2;        /* 内部链接 */
extern int ext_var;             /* 外部声明，本文件没定义 */

static int file_func(void) { return file_var; }
int global_func(void) { return file_var + ext_var; }
int main(void) { return global_func() + file_func(); }
```

`Bash`

```bash
gcc -std=c23 -c sym.c -o sym.o
nm sym.o
```

`实测数据`
`Text`

```text
                 U ext_var
0000000000000000 t file_func
0000000000000004 d file_var
000000000000000c T global_func
0000000000000000 D global_var
0000000000000023 T main
```

**读法**：

| 字母 | 含义 |
|---|---|
| **小写 `t` / `d` / `b`** | **内部链接**（local） |
| **大写 `T` / `D` / `B`** | **外部链接**（global） |
| `U` | **未定义**——本文件引用了它，但定义在别处 |

**`file_func` 与 `file_var` 是小写，`global_func` 与 `global_var` 是大写**——
`static` 的效果在符号表里直接可见。

> [!TIP]
> **链接错误排查的第一步就是 `nm`**：
> 报 `undefined reference to 'xxx'` 时，
> 在目标文件里 `nm` 一下，看 `xxx` 是 `U`（没定义）还是根本不存在。
> 做法见《01-编译器/01-编译与链接.md》第 2.4 小节。

# 第 5 节 C 与 C++ 的分歧

## 5.1 `const` 全局变量的链接属性

**这是两种语言在链接层面最实际的一处分歧。**

`C`

```c
/* g.c    编译：gcc -std=c23 -c g.c -o g.o */
const int cval = 5;         /* 定义 */

/* h.c    编译：gcc -std=c23 -c h.c -o h.o */
extern const int cval;      /* 声明 */
int main(void) { return cval; }
```

`实测数据`

| 语言 | 两个文件一起编 |
|---|---|
| **C** | **通过** |
| **C++** | **失败**：`undefined reference to 'cval'` |

**原因**：**C++ 里 `const` 全局变量默认是内部链接**，
相当于自带 `static`。C 里则与普通全局变量一样是外部链接。

> [!WARNING]
> **C++ 里想让 `const` 全局变量被别的文件用到，必须写 `extern`。**
> ```cpp
> extern const int cval = 5;      // 定义，且是外部链接
> ```
> **C 里不用**——同样的代码在 C 下本来就正常工作。
> **这是从 C 转到 C++ 时容易踩空的一处**，
> 因为报错出现在链接阶段，而且只在多文件工程里才暴露。

## 5.2 头文件里的 `const`

**因为上面那条差异，头文件里的 `const` 有两种写法。**

| 场合 | C | C++ |
|---|---|---|
| 头文件里定义常量 | `static const int N = 5;` | `const int N = 5;`（默认内部链接，可以） |
| 需要在 `.c` 里定义、头文件里声明 | `extern const int N;` | `extern const int N;` |

**C++ 里 `const int N = 5;` 写在头文件里是安全的**，
因为它默认内部链接，每个包含它的文件各有一份，不会冲突。

**C 里则要显式写 `static`**，否则每个文件都有一份外部链接的定义，会重复定义。

> [!TIP]
> **C++17 起可以用 `inline constexpr`**，
> 它是「一处定义、处处可用」的现代做法（见 `12-编译期能力`）。

# 第 6 节 回到导读里的问题

**现在可以回答了。**

> `static` 用在函数内部的变量上、用在全局变量上、用在类成员函数上，
> 三者的含义看起来毫不相干。它们为什么共用一个关键字？

**因为 `static` 影响的是三件不同的事，而它恰好能影响每一件。**

| 出现位置 | 影响哪件事 | 效果 |
|---|---|---|
| **函数内部的变量** | **生存期** | 从「自动」变成「静态」，与程序同寿命 |
| **全局变量或函数** | **链接** | 从「外部」变成「内部」，只在本文件可见 |
| **类成员函数**（C++） | **归属** | 不属于某个对象，属于整个类 |

**共同点在哪里**：

> [!IMPORTANT]
> **`static` 的本义是「固定」。**
> **生存期固定**——不随函数进出而变。
> **可见性固定**——不随文件而变。
> **归属固定**——不随对象而变。
>
> **三者都是「把某样东西从『随上下文变化』变成『固定下来』」**，
> 只是被固定的东西不同。

**类成员函数那一条属于 C++ 的面向对象部分**，
见《05-类与面向对象/03-成员与细节.md》第 1 节。**但它的逻辑与上面两条一致**：
普通成员函数跟着对象走，`static` 成员函数跟着类走。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 作用域 | Scope | 名字在源码里可见的范围 |
| 生存期 | Storage duration | 对象存在的时间段 |
| 链接属性 | Linkage | 名字会不会成为符号、成为哪一种；分外部、内部、无链接三种 |
| 外部链接 | External linkage | 成为全局符号，别的文件能用 |
| 内部链接 | Internal linkage | 成为本文件的符号，别的文件看不见 |
| 无链接 | No linkage | **不进符号表**，只在编译期对本块有意义（存储仍可能存在） |
| 遮蔽 | Shadowing | 内层同名名字遮住外层 |
| 可重入 | Reentrant | 同一函数能被并发调用而不互相干扰 |

## A.1 `static` 局部变量只初始化一次

#include <stdio.h>

/* sym.c */

## A.6 三种链接属性在符号表里的样子

`C`

```c
/* kinds.c */
int  ext_var;                   /* 外部链接 */
static int int_var;             /* 内部链接 */

int ext_func(void) { return 1; }        /* 外部链接 */
static int int_func(void) { return 2; } /* 内部链接 */

void has_no_linkage(void) {
    int local = 3;              /* 无链接 */
    static int local_static = 4;/* 无链接，但生存期是静态的 */
    typedef int myint;          /* 无链接 */
    myint x = local;
    (void)x;
label:;                         /* 标签：无链接 */
    goto label;
}
```

`C`

```c
/* block_extern.c */
void set_g(void) {
    extern int g;          /* 块作用域，但仍然有外部链接 */
    g = 5;
}

void use_local(void) {
    int g = 1;             /* 块作用域的普通局部变量：无链接 */
    (void)g;
}
```

`Bash`

```bash
gcc -std=c23 -c kinds.c        -o kinds.o        && nm kinds.o
gcc -std=c23 -c block_extern.c -o block_extern.o && nm block_extern.o
```

`实测数据`
`Text`

```text
# nm kinds.o
0000000000000000 T ext_func        ← 外部链接：大写 T
0000000000000000 B ext_var         ← 外部链接：大写 B
0000000000000016 T has_no_linkage
000000000000000b t int_func        ← 内部链接：小写 t
0000000000000004 b int_var         ← 内部链接：小写 b
0000000000000000 d local_static.0  ← 函数内 static 的存储，名字是编译器造的

# nm block_extern.o
                 U g               ← 块作用域 extern 声明的 g：外部符号
0000000000000000 T set_g
0000000000000014 T use_local
```

**`local`、`myint`、`label` 在符号表里完全不存在**，
`use_local` 里的局部 `g` 同样没有留下符号。
