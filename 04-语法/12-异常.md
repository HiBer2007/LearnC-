**函数出错了怎么办。**

**最直接的做法是返回一个错误码**，让调用方检查。
**但这条路有个问题**：调用方可以**不检查**。

**异常解决的是这件事**：
**它把「出错」变成一条不能忽略的路径**——
只要抛出，就必须有人接住，否则程序直接终止。

# 第 1 节 它解决什么问题

## 1.1 错误码的困境

<small style="color:gray">cpp</small>

```cpp
int divide(int a, int b, int *out);     // 返回 0 表示成功，-1 表示失败
```

**调用方可以这样写**：

<small style="color:gray">cpp</small>

```cpp
int r;
divide(10, 0, &r);          // 忘了检查返回值
printf("%d\n", r);          // r 是未初始化的
```

**编译器不会提醒。** 错误码只是一个普通的返回值。

**如果调用链有五层**，每一层都要检查并向上传递：

<small style="color:gray">text</small>

```
   f1 → f2 → f3 → f4 → f5
   每一层都要写「if (失败) return 失败;」
```

**这就是异常要取代的东西。**

## 1.2 异常的写法

<small style="color:gray">cpp</small>

```cpp
// exception_basic.cpp    编译：g++ -std=c++17 exception_basic.cpp -o exception_basic
#include <cstdio>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0.0) throw std::runtime_error("除数为零");
    return a / b;
}

int main() {
    try {
        std::printf("10 / 2 = %g\n", divide(10, 2));
        std::printf("10 / 0 = %g\n", divide(10, 0));   // 抛异常
        std::printf("这一行不会执行\n");
    } catch (const std::exception &e) {
        std::printf("捕获到: %s\n", e.what());
    }
    std::printf("程序继续\n");
    return 0;
}
```

**实测输出**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
10 / 2 = 5
捕获到: 除数为零
程序继续
```

**三个关键字各司其职**：

| 关键字 | 做什么 |
|---|---|
| `throw` | 抛出，当前函数**立刻结束** |
| `try` | 圈出一段「可能抛出的代码」 |
| `catch` | 接住，处理 |

> [!IMPORTANT]
> **`throw` 之后的代码不会执行，函数立刻结束。**
> 这一点与 `return` 类似，但**它不需要调用方配合**——
> 调用方可以不写 `try`，异常会继续往上传，
> 直到有人接住或程序终止。

## 1.3 C 里没有异常

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
C23 里写 try { } catch (...) { }
→ error: 'try' undeclared (first use in this function)
```

**C 只能用错误码。** 常见的三种做法：

| 做法 | 说明 |
|---|---|
| 返回错误码 | 最常见，但容易被忽略 |
| 返回特殊值 | 如 `NULL`、`-1`，同样容易被忽略 |
| 设置全局错误变量 | 如 `errno`，见《04-语法/02-数据类型与类型系统.md》 |

> [!NOTE]
> **这不是「C 落后」，而是两种语言的取舍不同。**
> 异常需要运行期支持（栈展开、类型信息表），
> 而这些在嵌入式等场景下是额外负担。
> C 选择了「零开销、但需要程序员自律」。

# 第 2 节 栈展开

## 2.1 抛出之后发生了什么

**这是异常最重要的机制。**

<small style="color:gray">cpp</small>

```cpp
// unwind.cpp    编译：g++ -std=c++17 unwind.cpp -o unwind
#include <cstdio>
#include <stdexcept>

struct Guard {
    const char *name;
    Guard(const char *n) : name(n) { std::printf("  构造 %s\n", name); }
    ~Guard() { std::printf("  析构 %s\n", name); }
};

void inner() {
    Guard g("inner 里的对象");
    throw std::runtime_error("出错了");
    // 这一行不会执行
}

void outer() {
    Guard g("outer 里的对象");
    inner();
}

int main() {
    try {
        outer();
    } catch (const std::exception &e) {
        std::printf("捕获到: %s\n", e.what());
    }
    return 0;
}
```

**实测输出**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
  构造 outer 里的对象
  构造 inner 里的对象
  析构 inner 里的对象
  析构 outer 里的对象
捕获到: 出错了
```

**两个析构函数都被调用了，而且顺序是「后构造的先析构」。**

**过程是这样的**：

<small style="color:gray">text</small>

```
   throw
     │
     ├─ 从 inner 开始，逐层退出
     │
     ├─ 每退出一层，就把那一层的局部对象析构掉   ← 栈展开
     │
     ├─ 找不到 catch 就继续往上退
     │
     └─ 找到 catch 就从那里继续执行
```

> [!IMPORTANT]
> **栈展开保证「已经构造好的对象一定会被析构」。**
> 这是异常最核心的价值——
> **它让「出错时释放资源」变成自动的**，
> 而不需要在每个出错分支上手写一遍清理代码。

**没有异常的语言里，同样的代码要这样写**：

<small style="color:gray">c</small>

```c
int f(void) {
    int *p = malloc(100);
    if (!p) return -1;

    if (出错了) {
        free(p);            /* 每个出错分支都要记得清理 */
        return -1;
    }
    /* 分支多了之后，漏掉一处就是内存泄漏 */
    free(p);
    return 0;
}
```

## 2.2 构造函数里抛异常

**这一处比较特殊。**

<small style="color:gray">cpp</small>

```cpp
// ctor_throw.cpp    编译：g++ -std=c++17 ctor_throw.cpp -o ctor_throw
#include <cstdio>
#include <stdexcept>

struct Part {
    const char *name;
    Part(const char *n) : name(n) { std::printf("  构造 %s\n", name); }
    ~Part() { std::printf("  析构 %s\n", name); }
};

struct Whole {
    Part a{"成员 a"};
    Part b{"成员 b"};
    Whole() {
        std::printf("  Whole 的构造函数体\n");
        throw std::runtime_error("构造到一半失败");
    }
    ~Whole() { std::printf("  析构 Whole\n"); }
};

int main() {
    try {
        Whole w;
    } catch (const std::exception &e) {
        std::printf("捕获到: %s\n", e.what());
    }
    return 0;
}
```

**实测输出**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
  构造 成员 a
  构造 成员 b
  Whole 的构造函数体
  析构 成员 b
  析构 成员 a
捕获到: 构造到一半失败
```

**注意没有「析构 Whole」这一行。**

> [!CAUTION]
> **对象自己的构造函数没跑完时，它的析构函数不会被调用。**
> 因为那个对象**从来没有完整地存在过**——
> 析构一个「半成品」是危险的。
>
> **但已经构造好的成员会被析构**（上例里的 `成员 b` 与 `成员 a`），
> 因为它们各自都是完整的对象。

**这条规则的实际含义**：如果构造函数在失败前已经申请了资源
（比如 `new` 了一块内存），**那些资源不会被自动释放**——
因为它们不是「成员对象」，只是构造函数体里的局部状态。

**做法是把资源交给一个成员对象管**，让它的析构函数负责释放
（这叫 RAII，见【待补：05-类与面向对象/】）。

# 第 3 节 接住异常

## 3.1 按引用接，不要按值接

<small style="color:gray">cpp</small>

```cpp
// catch_ref.cpp    编译：g++ -std=c++17 catch_ref.cpp -o catch_ref
#include <cstdio>
#include <stdexcept>

struct MyError : std::runtime_error {
    int code;
    MyError(int c) : std::runtime_error("我的错误"), code(c) {}
};

int main() {
    try {
        throw MyError(42);
    } catch (const std::exception &e) {          // 按基类引用接
        std::printf("当作 exception 接住: %s\n", e.what());
    }

    try {
        throw MyError(42);
    } catch (const MyError &e) {                 // 按派生类引用接
        std::printf("当作 MyError 接住: code=%d\n", e.code);
    }
    return 0;
}
```

**实测输出**：

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
当作 exception 接住: 我的错误
当作 MyError 接住: code=42
```

**两次都接住了，而且都能取到各自需要的信息。**

| 写法 | 效果 |
|---|---|
| `catch (const std::exception &e)` | **按引用接**：`e` 就是抛出的那个对象 |
| `catch (std::exception e)` | **按值接**：会复制一份，**派生类的部分被切掉** |
| `catch (std::exception *e)` | 接的是指针，通常不是你想要的 |

> [!WARNING]
> **按值接会发生「切片」**：
> 抛的是 `MyError`，按 `std::exception` 的值接住时，
> `MyError` 里新增的成员全部丢失。
> **一律按 `const` 引用接**。

## 3.2 `catch` 的顺序

**从派生类到基类，不能颠倒。**

<small style="color:gray">cpp</small>

```cpp
try {
    throw std::runtime_error("x");
} catch (const std::exception &e) {          // 基类在前
    std::printf("被基类接住了\n");
} catch (const std::runtime_error &e) {      // 永远到不了
    std::printf("被派生类接住了\n");
}
```

**实测：编译通过，`-Wall` 下给出警告，运行时输出「被基类接住了」。**

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
warning: exception of type 'std::runtime_error' will be caught
         by earlier handler for 'std::exception'
```

> [!TIP]
> **把最具体的 `catch` 写在最前面。**
> 编译器在 `-Wall` 下会警告「这个处理器永远到不了」，
> 见到这条警告说明顺序写反了。

## 3.3 接住全部

<small style="color:gray">cpp</small>

```cpp
try {
    // ...
} catch (...) {
    // 三个点表示「任何类型」
}
```

**`catch (...)` 接住一切，但拿不到任何信息**——
连异常是什么类型都不知道。

**典型用途**：在程序的最外层兜底，记录日志后退出，
或者在 C 与 C++ 混编的边界上阻止异常穿越 C 代码。

> [!CAUTION]
> **不要让异常穿过 C 代码的边界。**
> C 代码没有栈展开机制，异常穿过去会导致未定义行为。
> **在 C++ 导出给 C 用的函数里，把 `catch (...)` 写在最外层。**

# 第 4 节 `noexcept`

## 4.1 它是什么

**一个承诺：这个函数不会抛异常。**

<small style="color:gray">cpp</small>

```cpp
void safe()   noexcept { }
void unsafe_()         { throw 1; }

// noexcept(表达式) 是一个编译期常量
printf("%d\n", noexcept(safe()));       // 1
printf("%d\n", noexcept(unsafe_()));    // 0
```

**实测输出**：`1` 与 `0`

**`noexcept(表达式)` 的结果是 `bool`**，
它在编译期就能算出来，因此可以用来做 `static_assert`
（见《04-语法/11-编译期能力.md》）。

## 4.2 违背承诺会怎样

<small style="color:gray">cpp</small>

```cpp
// noexcept_throw.cpp    编译：g++ -std=c++17 noexcept_throw.cpp -o noexcept_throw
#include <cstdio>

void bad() noexcept { throw 1; }        /* 承诺了不抛，却抛了 */

int main() {
    try {
        bad();
    } catch (...) {
        std::printf("接住了\n");
    }
    std::printf("继续\n");
    return 0;
}
```

**实测：编译通过，运行时直接终止。**

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
输出: （无）
退出码: 3
```

**注意「接住了」没有打印**——`catch (...)` 根本没机会执行。

> [!CAUTION]
> **在 `noexcept` 函数里抛异常会直接调用 `std::terminate`，
> 连 `catch (...)` 都拦不住。**
> 编译器通常不检查你是否真的不抛，因此这是一个运行期炸弹。

## 4.3 什么时候该写

| 场合 | 写不写 |
|---|---|
| 移动构造函数、移动赋值 | **必须写**（否则容器会退化为复制） |
| `swap` | 写 |
| 析构函数 | 默认就是 `noexcept` |
| 简单的不抛的函数 | 写，让编译器有机会优化 |
| 不确定会不会抛 | **不写** |

> [!IMPORTANT]
> **`noexcept` 不是「性能开关」，而是「接口承诺」。**
> 它的主要作用是让标准库知道「这个操作失败了可以回退」——
> 例如 `std::vector` 扩容时，
> 只有元素的移动构造是 `noexcept`，它才敢用移动而不是复制。

# 第 5 节 异常与错误码

## 5.1 不抛异常时，代价是多少

**看汇编最清楚。**

<small style="color:gray">cpp</small>

```cpp
// cost.cpp    编译：g++ -std=c++17 -O0 -S cost.cpp -o cost.s
int by_error_code(int a, int b, int *out) {
    if (b == 0) return -1;
    *out = a / b;
    return 0;
}
int by_exception(int a, int b) {
    if (b == 0) throw 1;
    return a / b;
}
```

**实测：两个函数的汇编**

<small style="color:gray">asm</small>

```asm
_Z13by_error_codeiiPi:              _Z12by_exceptionii:
    pushq   %rbp                        pushq   %rbp
    movq    %rsp, %rbp                  movq    %rsp, %rbp
    movl    %ecx, 16(%rbp)              subq    $32, %rsp
    movl    %edx, 24(%rbp)              movl    %ecx, 16(%rbp)
    movq    %r8, 32(%rbp)               movl    %edx, 24(%rbp)
    cmpl    $0, 24(%rbp)                cmpl    $0, 24(%rbp)
    jne     .L2                         jne     .L5
    movl    $-1, %eax                   movl    $4, %ecx
    jmp     .L3                         call    __cxa_allocate_exception
.L2:                                    movl    $1, (%rax)
    movl    16(%rbp), %eax              movq    .refptr._ZTIi(%rip), %rdx
    cltd                                movl    $0, %r8d
    idivl   24(%rbp)                    movq    %rax, %rcx
    movl    %eax, %edx                  call    __cxa_throw
    movq    32(%rbp), %rax          .L5:
    movl    %edx, (%rax)                movl    16(%rbp), %eax
    movl    $0, %eax                    cltd
    popq    %rbp                        idivl   24(%rbp)
    ret                                 addq    $32, %rsp
                                        popq    %rbp
                                        ret
```

**对比正常路径**（不抛异常时走的那条）：

| | 错误码版 | 异常版 |
|---|---|---|
| 检查条件 | `cmpl` + `jne` | `cmpl` + `jne` |
| 正常路径上的额外指令 | 0 | **0** |
| 抛异常的分支 | `movl $-1, %eax` | **`call __cxa_allocate_exception` 与 `call __cxa_throw`** |

> [!IMPORTANT]
> **不抛异常时，异常的代价就是一次条件判断。**
> 那些分配异常对象、查找处理器的代码全在**抛出路径**上，
> 正常执行时根本不经过。
>
> **这就是「零开销异常」的含义**：
> 你不用的东西，不用付钱；用了，才付一次较大的代价。

## 5.2 两者的取舍

| | 错误码 | 异常 |
|---|---|---|
| 能否被忽略 | **能**（编译器不提醒） | **不能**（不接就终止） |
| 正常路径开销 | 一次判断 | 一次判断 |
| 出错路径开销 | 小 | **大**（分配 + 栈展开） |
| 跨越函数层数 | 每层都要传递 | **直接跳到处理处** |
| 需要运行期支持 | 不需要 | **需要** |
| C 里能不能用 | 能 | **不能** |

> [!TIP]
> **判断口诀**：
> **「这是异常情况，还是正常流程的一部分？」**
>
> 打不开文件、内存不够、网络断了——**异常**。
> 遍历到末尾、队列为空——**正常流程**，用返回值。
>
> **异常不该用来做控制流。** 每抛一次都要分配对象并展开栈，
> 在循环里用异常做判断会让程序慢几个数量级。

## 5.3 未捕获异常的结果

<small style="color:gray">实测数据</small>
<small style="color:gray">text</small>

```text
抛之前
退出码: 3
```

**程序在 `throw` 处直接终止**，后面的 `printf` 没执行。

**退出码 3 来自 `std::terminate` 默认调用的 `abort()`。**
它与「未初始化的退出码」不同，是一个确定的信号。

> [!WARNING]
> **未捕获异常会让程序立即终止，不做任何清理。**
> 在服务器程序里这意味着正在处理的请求全部丢失。
> **因此程序的最外层应当有一个 `catch (...)`**，
> 至少把「出了什么事」记下来再退出。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 抛出 | Throw | 引发一个异常，当前函数立刻结束 |
| 捕获 | Catch | 接住异常并处理 |
| 栈展开 | Stack unwinding | 逐层退出时析构局部对象 |
| 切片 | Slicing | 按值接住派生类异常时丢失派生部分 |
| 零开销异常 | Zero-cost exception | 不抛时无额外开销的异常实现 |
| `noexcept` | — | 承诺不抛异常；违背会直接终止 |
| RAII | Resource Acquisition Is Initialization | 用对象生命周期管资源 |

# 附录 A 复现本章节实测

**环境**：`g++` 15.2.0（MinGW-w64），Windows x64。

## A.1 基本用法

<small style="color:gray">cpp</small>

```cpp
// basic.cpp
#include <cstdio>
#include <stdexcept>
double divide(double a, double b) {
    if (b == 0.0) throw std::runtime_error("除数为零");
    return a / b;
}
int main() {
    try { std::printf("%g\n", divide(10, 0)); }
```
