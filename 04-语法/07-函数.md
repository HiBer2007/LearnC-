**函数是「一段有名字的代码」。**

**但这只是表面。函数真正做的事是封装**——
**把一段实现包起来，只留一个名字、几个参数、一个返回值作为对外的接口。**
调用方只要知道「给它什么、它给回什么」，不必知道里面怎么算。

**封装划出一条边界**：边界之内是它自己的世界，
边界之外只能通过参数与返回值与它打交道；
**只要接口不变，里面的实现怎么改，调用方都不用动。**
**理解了这条边界，很多「为什么改不动外面的变量」就不用背了。**

**在 C 里，函数是最主要的封装单位**；
`static` 用在函数上时，还能把可见范围再收窄到本文件
（见《04-语法/11-作用域、生存期与链接.md》第 4.3 小节）。

**到了 C++，类把封装又推进了一层**：数据与实现被收进类里，
**而对外露出的接口主要仍由函数承载**——它们成了成员函数
（见《05-类与面向对象/02-类是一种类型.md》第 2 节）。

# 第 1 节 封装与调用

## 1.1 封装：把实现收进一个名字

**封装的意思是：把实现藏起来，只把接口露出来。**

**函数的接口就是三样东西**：

`Text`

```
   名字      调用时写什么
   参数      要给它什么
   返回值    它能给回什么
```

**这三样写在声明里，调用方只看声明。**
函数体里怎么算、用了几个临时变量、先算哪一步，**调用方一律不必知道**。

**封装的价值在于「两边可以分别改」**：
只要接口不变，函数体可以重写、可以换算法，
**所有调用点一行都不用动**；反过来，调用方换个地方调用，函数体也不用改。

> [!IMPORTANT]
> **函数不是「一段可以重复使用的代码」，而是「一份实现加一个承诺」。**
> 承诺就是接口：给它这样的参数，它给回这样的结果。
> **复用它只是封装的副产品**——真正被复用的是那个承诺，不是那几行代码。

**同一个接口可以有几份实现**：`printf`、`malloc` 在不同平台上由不同的代码实现，
调用方的写法完全一样。**这正是封装要达到的效果。**

**C 与 C++ 里还有一层更小的封装**：`static` 函数只在本文件可见，
别的文件连名字都找不到（见《04-语法/11-作用域、生存期与链接.md》第 4.3 小节）。

## 1.2 调用时机器上做了什么

**看一段最简单的函数。**

`C`

```c
/* add.c    编译：gcc -std=c23 add.c -o add */
#include <stdio.h>

int add(int a, int b) {         /* 定义 */
    return a + b;
}

int main(void) {
    int r = add(2, 3);          /* 调用 */
    printf("%d\n", r);
    return 0;
}
```

**输出**：`5`

**调用发生时，机器上做了四件事**：

`Text`

```
   1. 把 2 与 3 放进约定的位置（寄存器或栈）
   2. 把返回地址压栈 —— 记住「回来之后从哪继续」
   3. 跳到 add 的第一条指令
   4. add 执行完，把结果放进约定位置，跳回返回地址
```

**这四步叫「调用约定」**，属于 ABI 的一部分
（见《01-编译器/00-语言的实现.md》第 5.4 小节）。

> [!IMPORTANT]
> **函数调用不是「跳过去再跳回来」这么简单**，
> 它包含一整套参数放哪、返回值放哪、谁负责清理栈的约定。
> **两边的约定不一致时，程序会以难以理解的方式出错**——
> 这是链接不同编译器产物时最常见的坑。

# 第 2 节 声明与定义

## 2.1 两者的区别

`C`

```c
int add(int a, int b);          /* 声明：告诉编译器有这个东西 */
int add(int a, int b) {         /* 定义：给出它的实体 */
    return a + b;
}
```

| | 声明 | 定义 |
|---|---|---|
| 说什么 | 名字、参数类型、返回类型 | 同上，**外加函数体** |
| 可以写几次 | 多次 | **只能一次** |
| 占不占空间 | 不占 | 占 |
| 能不能调用 | 能（但链接时要有定义） | 能 |

**只声明不定义，编译能过，链接会失败**：

`C`

```c
/* nodef.c    编译：gcc -std=c23 nodef.c -o nodef（失败） */
#include <stdio.h>

int add(int a, int b);          /* 只有声明 */

int main(void) {
    printf("%d\n", add(1, 2));
    return 0;
}
```

`实测数据`
`Text`

```text
undefined reference to `add'
collect2.exe: error: ld returned 1 exit status
```

**注意报错出现在链接阶段，不是编译阶段**——
编译器只检查「用法对不对」，链接器才检查「东西在不在」。

## 2.2 为什么要分开写

**因为 C 与 C++ 都是「一次读一个文件」的**。

`Text`

```
   a.c 里调用 add()         编译器读到这时，必须已经知道 add 长什么样
        ↓
   所以 a.c 里要先声明
        ↓
   真正的定义在 b.c 里，链接时才接上
```

**这就是头文件的用途**：把声明集中起来，两边都 `#include`
（详见《04-语法/14-预处理器.md》第 3 节）。

# 第 3 节 参数是按值传递的

**「按值传递」这四个字要先拆开看**：
**什么是「值」，以及「传递」到底传了什么。**

## 3.1 形参是函数自己的局部变量

**形参不是「外面的那个变量」，它是被调用函数里的一个自动变量**——
有自己的名字、自己的地址、自己的生存期。

`实测数据`
`C`

```c
/* 下面这个函数节选自 by_value_what.c，完整文件与输出见附录 A.5 */
#include <stdio.h>

void take_int(int x) {
    printf("  函数里：x 的值 = %d，x 自己的地址 = %p\n", x, (void *)&x);
    x = 99;
    printf("  函数里：改成 %d 之后，x 的地址还是 %p\n", x, (void *)&x);
}

int main(void) {
    int a = 1;
    printf("调用前：a 的值 = %d，a 的地址 = %p\n", a, (void *)&a);
    take_int(a);
    printf("调用后：a 的值 = %d，a 的地址 = %p\n", a, (void *)&a);
    return 0;
}
```

`实测数据`
`Text`

```text
调用前：a 的值 = 1，a 的地址 = 00000070a55ffcbc
  函数里：x 的值 = 1，x 自己的地址 = 00000070a55ffc20
  函数里：改成 99 之后，x 的地址还是 00000070a55ffc20
调用后：a 的值 = 1，a 的地址 = 00000070a55ffcbc
```

**两个地址不同**：`a` 在 `main` 的栈帧里，`x` 在 `take_int` 的栈帧里。
**它们从头到尾就是两个对象**，只是初始值恰好一样。

> [!IMPORTANT]
> **形参是局部变量，实参是调用者的对象。**
> **调用时把实参的值复制进形参，此后两者再无关系。**

## 3.2 「值」是什么，拷贝的是什么

**表达式求值得到一个值；函数调用复制的是那个值，不是那个变量。**
**因此实参可以写任何表达式**：

`实测数据`
`C`

```c
int a = 1;
take_int(a + 100);      /* 没有叫「a + 100」的变量，但它的值是 101 */
```

**拷贝多少内容由类型决定**：

| 实参类型 | 拷贝的是什么 |
|---|---|
| `int` 这类基本类型 | 那几个字节的数据 |
| 指针 | **一个地址**，不是它指向的东西 |
| 结构体 | **整个结构体**（逐成员的拷贝语义） |
| 数组 | **首元素的地址**（数组名退化成指针，见第 3.4 小节） |

**结构体的拷贝最容易看清**：

`实测数据`
`Text`

```text
调用前：big 的地址 = 00000070a55ffc90，big.a[0] = 1
  函数里：b 的地址 = 00000070a55ffc40，b.a[0] = 1
  函数里：改成 99 之后，b 的地址还是 00000070a55ffc40
调用后：big 的地址 = 00000070a55ffc90，big.a[0] = 1
```

**函数里改的是 `b`，也就是那份拷贝；`big` 一点没变。**

> [!WARNING]
> **结构体按值传会整份复制。**
> 一个 1 KB 的结构体，每次调用都要复制 1 KB——
> **这是「大对象不要按值传」的原因**（要传就传指针）。

## 3.3 因此函数里改不动外面的变量

`实测数据`
`C`

```c
/* pass_by_value.c    编译：gcc -std=c23 pass_by_value.c -o pass_by_value */
#include <stdio.h>

void by_value(int x)   { x = 99; }          /* 改的是副本 */
void by_pointer(int *p) { *p = 99; }        /* 改的是外面那块内存 */

int main(void) {
    int a = 1, b = 1;
    by_value(a);
    by_pointer(&b);
    printf("a = %d, b = %d\n", a, b);
    return 0;
}
```

输出是 `a = 1, b = 99`。

**`by_value` 收到的是一份拷贝。** 它把拷贝改成 99，原件没动。

`Text`

```
   调用 by_value(a) 时：
        a 的值  ──拷贝──►  x
                            ↑ 从此两者无关
```

**不是「传变量」，是「传值」。**

## 3.4 三种「看起来不像按值」的写法

**按值传递的规则没有例外，但有三处写法看起来像例外。**

**一、数组参数：传的是首元素的地址。**

`实测数据`
`Text`

```text
调用前：arr 的地址 = 00000070a55ffc70，arr[0] = 1
  函数里：sizeof(arr) = 8（指针大小，不是数组大小）
  函数里：arr 指向 00000070a55ffc70，arr[0] = 1
调用后：arr 的地址 = 00000070a55ffc70，arr[0] = 99
```

**`void take_array(int arr[8])` 里的 `arr` 实际是一个指针**：
`sizeof(arr)` 得到的是指针大小，函数里的 `arr` 与外面的数组指向同一块内存，
**因此改得动它**——**但传进去的仍然是「一个地址」这个值**。

**二、指针参数：传的是一个地址值。**

`实测数据`
`Text`

```text
调用前：c 的地址 = 00000070a55ffc6c，c = 1
  函数里：p 存的值 = 00000070a55ffc6c，p 自己的地址 = 00000070a55ffc20
调用后：c 的地址 = 00000070a55ffc6c，c = 99
```

**`p` 存的值就是 `c` 的地址**（因此 `*p` 能改 `c`），
**而 `p` 自己另有一个地址**——它是函数里的局部变量。
**「按引用传」是错觉，实际是「按值传了一个地址」。**

**三、C++ 的引用参数：语法上看不出传了地址。**
C++ 有真正的引用参数 `T&`，写法和传值一样，底层机制就是指针
（见《04-语法/08-数组、指针与引用.md》第 3.3 小节）。

> [!IMPORTANT]
> **C 与 C++ 的参数一律按值传递。**
> 想让函数改外面的东西，**必须把地址传进去**——
> 传 `&b` 而不是 `b`，函数里用 `*p` 写回。
> **理解「按值」的关键是分清两件事：传过去的是值，形参是另一份对象。**

# 第 4 节 返回值

## 4.1 返回值也是拷贝

**函数返回时，返回值被复制到一个约定的位置。**

**因此返回局部变量的地址是错的**：

`C`

```c
/* dangle.c    编译：gcc -std=c23 dangle.c -o dangle */
#include <stdio.h>

int *bad(void) {
    int local[3] = { 1, 2, 3 };
    return local;               /* 返回局部数组的地址 */
}

int main(void) {
    int *p = bad();
    printf("%d %d %d\n", p[0], p[1], p[2]);
    return 0;
}
```

**编译只有一个警告，运行时直接崩溃。**

`实测数据`
`Text`

```text
编译警告: warning: function returns address of local variable [-Wreturn-local-addr]
运行结果: 程序崩溃，退出码 -1073741819（0xC0000005，访问冲突）
```

**原因**：`local` 是 `bad` 的局部变量，函数一返回它的栈空间就失效了。
`p` 指向的是一块已经不属于自己的内存。

> [!CAUTION]
> **返回局部变量的地址是未定义行为。**
> 它可能崩溃，也可能「看起来能用」——
> 后者更危险，因为问题会在别处爆发。
> **这条警告默认就开着，见到必须处理。**

**正确的做法有三种**：

| 做法 | 说明 |
|---|---|
| 让调用方提供缓冲区 | `void fill(int *out, int n)` |
| 返回 `static` 变量 | 简单但不可重入 |
| 用 `malloc` 分配 | 调用方负责 `free` |

## 4.2 `main` 的返回值

**`main` 的返回值会变成进程的退出码。**

`实测数据`
`C`

```c
int main(void) {
    return 0;       /* 0 表示成功 */
}
```

**`main` 里不写 `return` 也能编过**——
C99 起规定 `main` 执行到末尾等价于 `return 0;`，**C++ 从第一版起就有同一条规定**。

> [!TIP]
> **但显式写 `return 0;` 更好**，因为它让「成功」这件事看得见。
> 非 `main` 的函数**没有这个特权**——不写 `return` 而返回值被用到，
> 是未定义行为。

# 第 5 节 C 与 C++ 的分歧

**这一节集中了函数相关的主要差异。**

## 5.1 `void f()` 的含义：C23 改了

**这是本教材基准里最容易疏忽错误的一处。**

`C`

```c
void f() { }            /* 空参数列表 */
int main(void) {
    f(1, 2, 3);         /* 多传了参数 */
    return 0;
}
```

`实测数据`

| 标准 | `f(1, 2, 3)` 的结果 |
|---|---|
| **C17** | **通过**，运行正常 |
| **C23** | **失败**：`too many arguments to function 'f'; expected 0, have 3` |
| **C++17** | **失败**：`too many arguments to function 'void f()'` |

> [!IMPORTANT]
> **C23 起，`void f()` 与 `void f(void)` 含义相同**——都表示「不接收参数」。
> **C17 及更早，`void f()` 表示「参数表未指定」**，
> 编译器不检查实参个数，因此 `f(1, 2, 3)` 能编过。
>
> **这是一处 C23 的破坏性改动**：
> 老代码里若依赖「空参数列表 = 参数不定」，升级到 C23 后会编译失败。

**同一个变化也影响函数声明**：

`C`

```c
int f();                    /* 空参数列表 */
int main(void) { f(1, 2); } /* C17 通过，C23 失败 */
int f(int a, int b) { return a + b; }
```

**C17 输出 `3`；C23 报 `too many arguments`。**

> [!TIP]
> **写代码时一律写 `void`**：`int f(void)`。
> 这样在 C17 与 C23 下含义一致，也不会有跨版本的意外。

## 5.2 默认参数

**C++ 有，C 没有。**

`实测数据`
`C++`

```cpp
// default_arg.cpp    编译：g++ -std=c++17 default_arg.cpp -o default_arg
#include <cstdio>

int add(int a, int b = 10) { return a + b; }

int main() {
    std::printf("%d %d\n", add(1), add(1, 2));
    return 0;
}
```

输出是 `11 3`——省略第二个参数时用 10。

**C 里同样写法直接失败**：`too few arguments to function 'add'; expected 2, have 1`

## 5.3 函数重载

**C++ 有，C 没有。**

`实测数据`
`C++`

```cpp
// overload.cpp    编译：g++ -std=c++17 overload.cpp -o overload
#include <cstdio>

int    f(int x)    { return x; }
double f(double x) { return x; }

int main() {
    std::printf("%d %.1f\n", f(1), f(2.5));
    return 0;
}
```

输出是 `1 2.5`——编译器按实参类型选了不同的 `f`。

**C 里同样写法失败**：`conflicting types for 'f'; have 'double(double)'`

**原因**：C 的函数名就是符号名，两个 `f` 会撞在一起；
C++ 会把参数类型编进符号名里（叫**名字修饰**），
因此 `_Z1fi` 与 `_Z1fd` 是两个不同的符号
（见《01-编译器/00-语言的实现.md》第 4.2 小节）。

> [!IMPORTANT]
> **重载能成立，靠的是名字修饰，不是「语言更聪明」。**
> 这也解释了为什么 C 与 C++ 混编时必须写 `extern "C"`——
> 它关掉名字修饰，让 C 能找到那个符号。

## 5.4 `main` 的返回类型

`实测数据`

| 写法 | C23 | C++17 |
|---|---|---|
| `int main(void)` | 通过 | 通过 |
| `int main()` | 通过 | 通过 |
| `void main()` | **警告** `return type of 'main' is not 'int'` | **错误** `'::main' must return 'int'` |
| `int main(int argc)` | 警告 `takes only zero or two arguments` | 警告 |
| `int main(int argc, char **argv)` | 通过 | 通过 |

**注意 `void main()` 那一行**：
**C 只给警告（默认还关着，要 `-Wall` 才显示），C++ 直接报错。**

> [!CAUTION]
> **`void main()` 不是合法写法。**
> 它在 C 里可能编过，但退出码会变成随机值——
> 因为运行环境读不到你写的返回值。
> **一律写 `int main(void)` 或 `int main(int argc, char **argv)`。**

# 第 6 节 可变参数函数

**参数个数不固定的函数，C 与 C++ 都有**，`printf` 是其中最常用的一个。
写法上的共同点是参数表末尾的 `...`，取参数时的共同点是 `<stdarg.h>`（C++ 里写 `<cstdarg>`）里的几个宏。

C++ 另有一套**可变参数模板**，类型与个数都在编译期处理，
见《05-类与面向对象/12-模板的高阶使用.md》第 1 节。
`...` 这一套在 C 里是唯一的办法，在 C++ 里同样存在，但新接口通常有更合适的写法（第 6.8 小节）。

**宏那一侧也有一套可变参数**（`__VA_ARGS__` 与 `__VA_OPT__`），那属于文本替换层面，见《04-语法/14-预处理器.md》第 2.4 小节。

## 6.1 写法：`...` 放在参数表最后

**`...` 只能出现在参数表末尾**，前面通常要留一个具名参数——取值用的宏需要它作起点。
**`void f()` 与 `void f(...)` 不是一回事**：C23 起 `void f()` 表示「不接收参数」，
`void f(...)` 表示「参数不定」（`void f()` 的变化见第 5.1 小节）。

`C`

```c
void f_void(void);      /* 不接收参数 */
void f_dots(...);       /* 参数不定：个数与类型都由调用方决定 */
```

`实测数据`

| 写法 | 结果 |
|---|---|
| `f_dots()` | 通过 |
| `f_dots(1, 2.0, "three", (void *)0)` | 通过 |
| 函数体里写 `va_start(ap)`（只有 `...`，没有具名参数） | 失败：`macro 'va_start' requires 2 arguments, but only 1 given` |

**只有 `...` 的函数里取不出实参**：取值要写 `va_start(ap, 最后一个具名参数)`，
本机的宏要求两个参数，没有具名参数就无参可写（完整文件见附录 A.7）。

## 6.2 `<stdarg.h>` 的四件套

`C`

```c
/* va_sum.c    编译：gcc -std=c23 va_sum.c -o va_sum */
#include <stdio.h>
#include <stdarg.h>

/* 第一个参数 n 说明后面有几个 int；... 必须在参数表最后 */
int sum(int n, ...) {
    va_list ap;                 /* 参数表的游标 */
    va_start(ap, n);            /* 从 n 之后开始 */
    int s = 0;
    for (int i = 0; i < n; i++) {
        s += va_arg(ap, int);   /* 取下一个 int，游标前移 */
    }
    va_end(ap);                 /* 收尾 */
    return s;
}

int main(void) {
    printf("%d\n", sum(3, 10, 20, 30));
    printf("%d\n", sum(0));
    return 0;
}
```

`实测数据`
`Text`

```text
60
0
```

| 名字 | 形状 | 做什么 |
|---|---|---|
| `va_list` | 类型 | 游标；**它究竟是什么类型由实现决定** |
| `va_start(ap, last)` | 宏 | 把游标定位到最后一个具名参数之后 |
| `va_arg(ap, T)` | 宏 | 按类型 `T` 取下一个实参，游标前移 |
| `va_end(ap)` | 宏 | 收尾；此后 `ap` 不可再用 |
| `va_copy(dst, src)` | 宏 | 复制游标，两边各走各的 |

**`va_start` 的第二个参数是「最后一个具名参数」的名字**，意思不是「从哪一个参数开始读」——
宏要靠这个名字算出可变部分的起点。`va_arg` 里写的类型要与实参提升之后的类型相同（第 6.4 小节）。

**`va_list` 不是某个标准规定的具体类型**：

`实测数据`

| 平台 | `sizeof(va_list)` |
|---|---|
| Windows x64（MinGW-w64，`gcc` 15.2.0） | 8 |
| Linux x86-64（`gcc` 13.3.0） | 24 |

两边不是同一个东西，第 6.7 小节会看到后果。
**C++ 里写法完全相同**：头文件换成 `<cstdarg>`，四个名字照用；
同一个 `sum` 用 `g++ -std=c++17` 编译，输出同样是 `60`（见附录 A.7）。

## 6.3 个数与类型靠调用方约定

**函数体里拿不到两样东西：有几个实参、每个是什么类型。**
`va_arg` 只是按给出的类型从游标处搬走若干个字节，不知道那里实际放的是什么。
**因此可变参数函数必须带一条「怎么读」的约定**：

`C`

```c
/* 下面三个函数节选自 va_conventions.c，完整文件与输出见附录 A.7 */
#include <stdio.h>
#include <stdarg.h>

/* 约定一：个数参数——第一个实参说清后面有几个 */
int sum_n(int n, ...) {
    va_list ap;
    va_start(ap, n);
    int s = 0;
    for (int i = 0; i < n; i++) s += va_arg(ap, int);
    va_end(ap);
    return s;
}

/* 约定二：格式串——每个 %d、%s 说明下一个实参是什么类型 */
void print_fmt(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    for (const char *p = fmt; *p; p++) {
        if (*p != '%') { putchar(*p); continue; }
        p++;
        if (*p == 'd')      printf("%d", va_arg(ap, int));
        else if (*p == 's') printf("%s", va_arg(ap, const char *));
    }
    putchar('\n');
    va_end(ap);
}

/* 约定三：哨兵值——以 NULL 表示「后面没有了」 */
void print_all(const char *first, ...) {
    va_list ap;
    va_start(ap, first);
    for (const char *s = first; s; s = va_arg(ap, const char *)) printf("%s ", s);
    putchar('\n');
    va_end(ap);
}
```

三种约定的调用与输出：

`实测数据`

| 约定 | 调用 | 输出 |
|---|---|---|
| 个数参数 | `sum_n(3, 10, 20, 30)` | `60` |
| 格式串 | `print_fmt("共 %d 项，第一项是 %s", 3, "abc")` | `共 3 项，第一项是 abc` |
| 哨兵值 | `print_all("a", "b", "c", NULL)` | `a b c` |

三种约定都只是**调用方与函数之间的协议**：编译器不认识它们，写错了也不管
（`printf` 是例外，见第 6.9 小节）。

## 6.4 默认实参提升

**走 `...` 的实参在传进去之前会被统一转换一次**：`float` 提升成 `double`，
`char`、`short`、`bool` 以及它们的无符号版本做整型提升，变成 `int`。

`文档`

> "The ellipsis notation in a function prototype declarator causes argument type
> conversion to stop after the last declared parameter, if present. The integer
> promotions are performed on each trailing argument, and trailing arguments that
> have type float are promoted to double. These are called the default argument
> promotions. No other conversions are performed implicitly."
>
> —— N3220 §6.5.3.3/6

**这条提升解释了 `printf` 上两件看起来不对、实际正确的事**：

`实测数据`
`C`

```c
/* va_promote.c    编译：gcc -std=c23 va_promote.c -o va_promote */
#include <stdio.h>
#include <stdarg.h>

/* 传进来的 float 与 char 已被提升，因此这里按 double 与 int 取 */
static void show(int n, ...) {
    va_list ap;
    va_start(ap, n);
    double d = va_arg(ap, double);
    int    c = va_arg(ap, int);
    va_end(ap);
    printf("按 double 取到 %f，按 int 取到 %d\n", d, c);
}

int main(void) {
    printf("%f\n", 1.0f);       /* %f 要的是 double：1.0f 已被提升成 double */
    printf("%d\n", (char)65);   /* %d 要的是 int：char 被整型提升成 int */
    show(2, 1.5f, 'A');
    return 0;
}
```

`实测数据`
`Text`

```text
1.000000
65
按 double 取到 1.500000，按 int 取到 65
```

**`printf("%f", 1.0f)` 是对的**：`1.0f` 到函数里已经是 `double`，而 `%f` 要的正是 `double`——
`printf` 的参数里没有 `float` 这一档。**`printf("%d", (char)65)` 也是对的**：`char` 先提升成 `int`。
`va_arg` 那一侧同理：标准对类型不匹配写的是「行为未定义」（N3220 §7.16.1.1/2），
**`va_arg(ap, float)` 与 `va_arg(ap, char)` 都是错的**，要写 `va_arg(ap, double)` 与 `va_arg(ap, int)`。

## 6.5 类型写错不会有编译错误

**这是可变参数代价最大的地方。** 下面两个写法都编译通过：

`实测数据`
`C`

```c
/* va_fmt_wrong.c    编译：gcc -std=c23 va_fmt_wrong.c -o va_fmt_wrong */
#include <stdio.h>

int main(void) {
    printf("%d\n", 1.5);    /* 用 %d 去读一个 double */
    printf("%f\n", 1);      /* 用 %f 去读一个 int */
    return 0;
}
```

`实测数据`

| 写法 | 编译 | 运行输出 |
|---|---|---|
| `printf("%d\n", 1.5)` | 通过 | `0` |
| `printf("%f\n", 1)` | 通过 | `0.000000` |

**这两个 0 都不是转换出来的结果**：整型实参与浮点实参按 ABI 放在不同的寄存器里，
格式串去取的那一边从来没有被写过，读到的是那里的原有内容。

**第三个例子直接崩**：

`C`

```c
/* va_fmt_segv.c    编译：gcc -std=c23 va_fmt_segv.c -o va_fmt_segv */
#include <stdio.h>

int main(void) {
    printf("%s\n", 42);     /* 把 42 当成 char * 去解引用 */
    return 0;
}
```

`实测数据`
`Text`

```text
编译：通过
运行：程序直接崩，退出码 -1073741819（0xC0000005，访问冲突）
```

**`42` 被当作一个地址去读**，那个地址不属于本进程，于是访问冲突。
**崩之前一行输出都没有**——`stdout` 是带缓冲的，进程没走到刷新缓冲那一步。

**加上 `-Wall` 之后编译器会说一句**，但仍然只是警告，不是错误：

`实测数据`
`Text`

```text
warning: format '%d' expects argument of type 'int', but argument 2 has type 'double' [-Wformat=]
warning: format '%f' expects argument of type 'double', but argument 2 has type 'int' [-Wformat=]
warning: format '%s' expects argument of type 'char *', but argument 2 has type 'int' [-Wformat=]
```

**这三条警告来自 `printf` 自己的声明**：标准库的头文件把「第一个参数是格式串」告诉了编译器，
编译器才能拿格式串逐个核对实参。**自定义的可变参数函数没有这个待遇**：
把第 6.2 小节的 `sum` 用 `sum(3, 1.0, 2.0, 3.0)` 调用，
`-Wall -Wextra` 一条诊断都没有，运行输出 `0`——三个 `double` 一个也没有读到（见附录 A.7）。

> [!CAUTION]
> **可变参数的类型错配是未定义行为，而且通常没有编译错误。**
> 它可能打印一个错误的数字，可能崩溃，也可能这一次运行恰好正确。
> **编译器只在认识格式串的地方帮得上忙。**

## 6.6 `vprintf` 家族与日志包装

**把可变参数转交给另一个函数，会遇到一个障碍**：`printf` 收的是「格式串加上一串实参」，
而函数体里只有格式串与游标，拼不回调用处的实参序列。
**标准库为此提供了 `v` 开头的一套**：它们把最后那个「一串实参」换成 `va_list`。

`C`

```c
/* 下面这个函数节选自 va_log.c，完整文件与输出见附录 A.7 */
#include <stdio.h>
#include <stdarg.h>

/* 日志包装：自己不解析格式串，把它连同游标交给 vprintf */
void my_log(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    fputs("[log] ", stdout);
    vprintf(fmt, ap);
    va_end(ap);
    putchar('\n');
}
```

`实测数据`
`Text`

```text
[log] 打开了 a.txt，共 1024 字节
```

| 不收 `va_list` | 收 `va_list` |
|---|---|
| `printf` | `vprintf` |
| `fprintf` | `vfprintf` |
| `sprintf` | `vsprintf` |
| `snprintf` | `vsnprintf` |

**规律是：凡是有格式串的接口，都另有一个收 `va_list` 的版本。**
需要把结果写进缓冲区时用 `vsnprintf`，它收的同样是 `va_list`（见附录 A.7）。

## 6.7 把 `va_list` 传给别的函数

**标准对 `va_list` 有一条容易忽略的规定**：

`文档`

> "The object ap may be passed as an argument to another function; if that
> function invokes the va_arg macro with parameter ap, the representation of ap
> in the calling function is indeterminate and shall be passed to the va_end
> macro prior to any further reference to ap."
>
> —— N3220 §7.16/4

**「不确定」的意思是**：对方取走一个实参之后，调用方手里的 `ap` 处于什么状态没有任何保证。

`C`

```c
/* 下面两个函数节选自 va_once.c，完整文件与输出见附录 A.7 */
#include <stdio.h>
#include <stdarg.h>

/* 传值：被调函数拿到的是游标的一份拷贝 */
static void take_value(va_list ap) {
    printf("  被调函数里取到：%d\n", va_arg(ap, int));
}

static void by_value(int n, ...) {
    va_list ap;
    va_start(ap, n);
    printf("  调用方先取到：%d\n", va_arg(ap, int));
    take_value(ap);                     /* 此后 ap 的表示就不确定了 */
    printf("  返回后又取到：%d\n", va_arg(ap, int));
    va_end(ap);
}
```

`实测数据`
`Text`

```text
  调用方先取到：10
  被调函数里取到：20
  返回后又取到：20
```

本该是「调用方读 `10`，帮手读 `20`，调用方接着读 `30`」，
本机的结果是 `20` 被读了两次、`30` 没有人读。**同一份源码换一个 ABI，结果又不同**：

`实测数据`

| 平台 | 直接传 `va_list` 之后再读 |
|---|---|
| Windows x64（MinGW-w64，`gcc` 15.2.0） | `20`（第二个实参被读两次，`30` 丢掉） |
| Linux x86-64（`gcc` 13.3.0） | `30`（对方的推进影响到了调用方） |

**两边都能打印出一个数字，两个数字还不一样**，这正是把它规定为「不确定」的理由：
**跑得出结果不等于行为有定义**。
两个平台上的 `va_list` 大小也不同（第 6.2 小节）：Windows 上它就是一个指针，
传值传的是指针的拷贝；Linux 上是另一种结构，传参时两边指向同一处。

**修法是复制一份再传**：

`C`

```c
va_list ap2;
va_copy(ap2, ap);           /* 复制游标，两边各走各的 */
take_value(ap2);            /* 把副本交给对方 */
va_end(ap2);
```

**修好之后调用方读到的是 `20`**——那是它自己应得的下一个实参，帮手读的是副本，`30` 留在调用方手里。
也可以改成传游标的地址（`void f(va_list *ap)`，调用处写 `f(&ap)`），两边操作的就是同一个游标。
**同一份参数表要从头读两遍时，第二遍同样要从一份复制出来的游标开始**，
`va_arg` 每读一次就把游标往前推。

## 6.8 什么时候用、什么时候别用

**该用的地方**：

| 场合 | 理由 |
|---|---|
| 实现或对接 C 的既有接口 | `printf` 家族、`execl` 这类接口的形态由标准定死了 |
| 包装一个已有的可变参数接口 | 日志、断言、错误上报：包装层只加前缀与转交 |
| 给 C 代码共用的头文件 | C++ 的模板进不了 C 的头文件 |

**新设计的接口需要类型安全时不要用**，问题在第 6.5 小节已经摆出来了。**C++ 里有两个更好的选择**：

| 做法 | 类型 | 个数 | 什么时候查 |
|---|---|---|---|
| `...` 与 `<cstdarg>` | 靠调用方约定 | 靠调用方约定 | 只有格式串能被查（第 6.9 小节） |
| 可变参数模板 | 每个实参各自的类型 | 编译期确定 | **编译期**（《05-类与面向对象/12-模板的高阶使用.md》第 1 节） |
| `std::initializer_list<T>` | 元素类型统一为 `T` | 任意 | **编译期** |

**`...` 在 C++ 里也装不下类类型**：标准对「把非平凡可拷贝或非平凡析构的类对象传给 `...`」
只是有条件支持，语义由实现定义。本机的 `g++` 15.2.0 对这样的写法一条诊断都不给，
取出来的是乱码（见附录 A.7）。

## 6.9 让编译器帮你查格式串

**`printf` 能得到检查，是因为它的声明上带了格式串信息。** 自定义函数可以用 GCC 的扩展把这条信息补上：

`C`

```c
/* va_format_attr.c    编译：gcc -std=c23 -Wall va_format_attr.c -o va_format_attr */
#include <stdio.h>
#include <stdarg.h>

/* 声明上告诉编译器：按 printf 的规则查，格式串是第 1 个参数，可变部分从第 2 个开始 */
void my_log(const char *fmt, ...) __attribute__((format(printf, 1, 2)));

void my_log(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    vprintf(fmt, ap);
    va_end(ap);
}

int main(void) {
    my_log("%d\n", "abc");      /* 类型对不上，编译器按 printf 的规则查出来 */
    return 0;
}
```

`实测数据`
`Text`

```text
warning: format '%d' expects argument of type 'int', but argument 2 has type 'char *' [-Wformat=]
```

**属性里三个信息**：`printf` 表示按 `printf` 的规则检查，
`1` 表示格式串是第 1 个参数，`2` 表示可变部分从第 2 个参数开始。
**不带 `-Wall` 时这条警告不出现**——属性只负责提供信息，检查由 `-Wformat` 做，而它在 `-Wall` 里。
**这是编译器扩展，不属于任何标准**：`gcc` 与 `clang` 支持，别的编译器各有各的写法。

> [!IMPORTANT]
> **可变参数的检查责任在调用方。**
> 函数体拿到的只是一个游标，有几个实参、每个是什么类型全靠约定；
> **编译器只在它认识格式串的地方帮得上忙**——
> 这要么来自标准库的声明，要么来自 `__attribute__((format(...)))` 这类扩展。

# 第 7 节 调用的代价与内联

**第 1.2 小节列过调用的四步**：放参数、压返回地址、跳过去、跳回来。
**这四步与函数体算了什么无关，是调用本身的固定开销。**

## 7.1 一次调用要花多少

`实测数据`
`C`

```c
/* call_cost.c    编译：gcc -std=c23 -O0 -S call_cost.c -o call_cost_O0.s
 * 完整文件见附录 A.6。
 */
int add(int a, int b) {                 /* 函数体只有一次加法 */
    return a + b;
}

int use_add(int x) { return add(x, 1); }
```

`实测数据`
`Assembly`

```asm
use_add:
    pushq    %rbp
    movq     %rsp, %rbp
    subq     $32, %rsp
    movl     %ecx, 16(%rbp)         /* 存下参数 x */
    movl     16(%rbp), %eax
    movl     $1, %edx               /* 第二个参数放进 edx */
    movl     %eax, %ecx             /* 第一个参数放进 ecx */
    call     add                    /* 跳过去 */
    addq     $32, %rsp
    popq     %rbp
    ret
```

**`add` 只做一次加法，`use_add` 为这次调用花了 11 条指令。**

> [!IMPORTANT]
> **函数体越短，调用开销占比越大。**
> **内联就是把这笔开销省掉**：把函数体直接搬进调用点，
> 参数传递与跳转都不再需要。

## 7.2 编译器自己就会内联

**同一份代码换 `-O2` 编译，`call` 消失了**：

`实测数据`

| 函数 | `-O0` 指令数 | `-O0` 的 `call` | `-O2` 指令数 | `-O2` 的 `call` |
|---|---|---|---|---|
| `add` | 9 | 0 | 2 | 0 |
| `use_add` | 11 | **1** | **2** | **0** |
| `big` | 26 | 0 | 17 | 0 |
| `use_big` | 10 | **1** | **17** | **0** |

**`use_add` 从「11 条指令加一次调用」变成两条指令**：

`实测数据`
`Assembly`

```asm
use_add:
    leal    1(%rcx), %eax       /* 内联之后只剩 x + 1 */
    ret
```

**`big` 也被内联进 `use_big`**（26 条加一次调用，变成 17 条、没有调用）。

> [!IMPORTANT]
> **内联是编译器的决定，不是源码里写出来的。**
> 它按自己的成本模型判断：函数体多大、被调用几次、调用点在不在循环里。
> **同一份源码，`-O0` 下每个调用都是真调用，`-O2` 下小函数全部就地展开。**

## 7.3 有四种情形它内联不了

`实测数据`

| 情形 | 例子 | `-O2` 下的结果 |
|---|---|---|
| **递归** | `fib(n - 1) + fib(n - 2)` | 展开了一部分，**仍有 `call fib`** |
| **只有声明，定义在别的文件** | `int ext(int);` | 变成 `jmp ext`（尾调用），跳转仍在 |
| **通过函数指针调用** | `f(x, 2)` | 变成 `jmp *%rax`（间接跳转） |
| **函数取过地址** | `int (*fp)(int, int) = add;` | `add` 的实体必须保留 |

**前三种是「看不到函数体，或者看到了也展不开」**；
**第四种说明「内联」不等于「函数消失」**——
只要有人能拿到它的地址，就必须留一份实体。

## 7.4 什么时候该考虑内联

**先分清三件事**：

| 想做的事 | 该动什么 |
|---|---|
| 让编译器整体优化得更好 | **编译选项**（`-O2`） |
| 让别的文件也能内联某个函数 | **把定义放进头文件** |
| 强行要求内联 | `__attribute__((always_inline))`、`__forceinline` |

**`inline` 关键字不在这张表里**：C 里它管的是「要不要生成函数体」，
C++ 里它管的是「允许多个翻译单元各有一份定义」，
**两者都不是「请内联」**（见《04-语法/15-奇技淫巧与优化.md》第 6.1 小节）。

**值得内联的场合**：

| 场合 | 理由 |
|---|---|
| 函数体只有一两行（取值、包装、转发） | 调用开销比函数体本身还大 |
| 调用点在热点循环里 | 省下的开销被循环次数放大 |
| 定义在头文件里的短函数 | 每个翻译单元都看得见，编译器自己会判断 |

**不值得的场合**：

| 场合 | 理由 |
|---|---|
| 函数体很大 | 每个调用点展开一份，代码膨胀、指令缓存装不下 |
| 需要下断点调试 | 内联之后断点打不进去 |
| 只是「感觉这里慢」 | 没有测量就没有依据 |

> [!TIP]
> **顺序是：先开 `-O2`，再测量，最后才考虑手工内联。**
> 编译器的成本模型看得见调用点上下文与目标 CPU；
> **手工内联的收益要用实测证明**（强制内联的代价见
> 《04-语法/15-奇技淫巧与优化.md》第 6.2、7.4 小节）。

| 声明 | Declaration | 告诉编译器有个东西，不给实体 |

## A.6 调用的代价与内联

`C`

```c
/* call_cost.c */
int add(int a, int b) {                 /* 小函数：编译器愿意内联 */
    return a + b;
}

int big(int x) {                        /* 稍大一点，看编译器还内不内联 */
    int s = 0;
    for (int i = 0; i < 8; i++) {
        s += x * i + (s >> 1) - (x ^ i);
        s ^= (s << 3);
    }
    return s;
}

int fib(int n) {                        /* 双递归：无法化成循环 */
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

int ext(int x);                         /* 只有声明：定义在别的文件里 */

int use_add(int x) { return add(x, 1); }
int use_big(int x) { return big(x); }
int use_fib(int x) { return fib(x); }
int use_ext(int x) { return ext(x); }
int use_indirect(int (*f)(int, int), int x) { return f(x, 2); }

int (*fp)(int, int) = add;              /* 取过地址：add 的实体必须留着 */
```

`Bash`

```bash
gcc -std=c23 -O0 -S call_cost.c -o call_cost_O0.s
gcc -std=c23 -O2 -S call_cost.c -o call_cost_O2.s
```

| `add` | 9 | 0 |

| `fib` | 23 | **2** |
| `use_add` | 11 | **1** |

| `use_ext` | 10 | **1** |

| `use_add` | 2 | **0** |

| `use_ext` | 1 | 0 |

**剩下的那次 `call fib` 去不掉**——递归无法完全内联。

```c
#include <stdio.h>
#include <stdarg.h>

/* 约定一：个数参数——第一个实参说清后面有几个 */
int sum_n(int n, ...) {
    va_list ap;
    va_start(ap, n);
    int s = 0;
    for (int i = 0; i < n; i++) s += va_arg(ap, int);
    va_end(ap);
    return s;
}

/* 约定二：格式串——每个 %d、%s 说明下一个实参是什么类型 */
void print_fmt(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    for (const char *p = fmt; *p; p++) {
        if (*p != '%') { putchar(*p); continue; }
        p++;
        if (*p == 'd')      printf("%d", va_arg(ap, int));
        else if (*p == 's') printf("%s", va_arg(ap, const char *));
    }
    putchar('\n');
    va_end(ap);
}

/* 约定三：哨兵值——以 NULL 表示「后面没有了」 */
void print_all(const char *first, ...) {
    va_list ap;
    va_start(ap, first);
    for (const char *s = first; s; s = va_arg(ap, const char *)) printf("%s ", s);
    putchar('\n');
    va_end(ap);
}

int main(void) {
    printf("%d\n", sum_n(3, 10, 20, 30));
    print_fmt("共 %d 项，第一项是 %s", 3, "abc");
    print_all("a", "b", "c", NULL);
    return 0;
}
```

```c
/* va_wrong_custom.c    编译：gcc -std=c23 -Wall va_wrong_custom.c -o va_wrong_custom */
#include <stdio.h>
#include <stdarg.h>

/* 自定义的可变参数函数：参数个数由 n 说明，类型全是 int */
int sum(int n, ...) {
    va_list ap;
    va_start(ap, n);
    int s = 0;
    for (int i = 0; i < n; i++) {
        s += va_arg(ap, int);
    }
    va_end(ap);
    return s;
}

int main(void) {
    /* 按 double 传进去，函数按 int 取：编译器与函数体都不知道哪里不对 */
    printf("%d\n", sum(3, 1.0, 2.0, 3.0));
    return 0;
}
```

```cpp
// va_cpp_string2.cpp    编译：g++ -std=c++17 va_cpp_string2.cpp -o va_cpp_string2
#include <cstdarg>
#include <cstdio>
#include <string>

// 用 va_arg 按 const char * 取，实际传进来的是 std::string 对象
void log_it(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    const char *s = va_arg(ap, const char *);
    va_end(ap);
    std::printf("[log] %s\n", s);
}

int main() {
    std::string s = "hello";
    log_it("%s", s);
    return 0;
}
```
