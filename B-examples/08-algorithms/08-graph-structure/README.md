# 示例 `08-algorithms/08-graph-structure` · 图上的结构性问题：拓扑排序、强连通分量、割点与桥、最小生成树

一个把图上的四类结构性问题放进同一份报告的命令行程序：有向图上的拓扑排序与强连通分量，
无向图上的割点、桥与最小生成树。三张图都写死在源码里，报告里的每一个数字都由计数器数出来——
访问次数、检查过的边数、`low` 改小的次数、并查集 `find` 的次数与沿父指针走过的步数、
优先队列的入队与出队次数、去掉割点之后连通块数的变化、两版最小生成树的总权值，
重跑逐位相同，一个都不是估的。

程序不打印地址、不读外部文件、不依赖时钟与随机数，因此同一份输出在换一台机器之后仍然一致。
四类问题各配一条独立的核对路子：割点与桥先用 `dfn`／`low` 算一遍，再按定义
「逐个删掉顶点或边，看连通块数有没有变多」算一遍；强连通分量先用 Tarjan 算一遍，
再用「两个顶点互相可达」算一遍；最小生成树用 Kruskal 与 Prim 各算一遍，
两条路的总权值必须相同，选中的边也要逐条相同。

有向图另有一个有环版，是在无环版上加三条回边得到的。同一个 Kahn 算法一行都不用改，
在不加改动的情况下从无环版的「出队九次」变成有环版的「出队一次」，环就是这样被发现的。
报告把「在环上」与「排在环的下游」分开说：Kahn 剩下的八个顶点里只有七个在环上，
分清这两者要交给 Tarjan 的强连通分量。

## 这个项目要解决什么问题

图上的问题有一个共同点：结论落在结构上，而不是落在某个具体数值上。哪几个顶点去掉之后图会散、
哪几条边是唯一的通路、哪些顶点互相可达、把九个顶点连起来最省的那组边是哪几条，
这些都是可以用集合与计数写下来的东西，也都能在不用时钟、不用随机数的前提下重跑核对。
项目把四类问题各做成一段可以逐行对照的输出，并且每一段都带一条独立的核对路子。

拓扑排序那一段把两种写法并排摆出来。Kahn 数一遍入度，入度为 0 的进最小堆，
出队一个就把它出边终点的入度减一，九个顶点各出队一次；DFS 后序按编号挑起点走到底，
回溯时把顶点接到序列尾部，最后整体取逆，入栈出栈各九次。两条序列都是合法拓扑序，
却不是同一条：Kahn 给出 `0 4 7 1 2 8 3 5 6`，DFS 后序给出 `4 0 7 2 1 8 5 3 6`。
报告里有一张位置对照表，同一个顶点在两条序列里差多少一眼就能看到。

环的发现那一段用的是同一个 Kahn，一行都没有改。有环版上只有顶点 4 的入度是 0，
出队一次之后队列就空了，此时进过队的顶点数是一，小于顶点数九。
入度表里剩下的八个顶点中，七个真正在环上，顶点 3 只是排在环的下游——
它的入度被环挡住了。要把这两种情况分开，靠的是第四段的强连通分量。

割点与桥那一段给出完整的 `dfn` 与 `low` 表、DFS 树的父子关系、割点集合与桥集合，
以及「去掉每一个割点之后连通块数从几变成几」的逐行清单：去掉顶点 1 从一块变成三块，
去掉顶点 3、5、6 各从一块变成两块，五个非割点去掉之后仍然是一块。
四条桥各去掉一次，连通块数都是 1 到 2。

最小生成树那一段把 Kruskal 与 Prim 的计数分开列。Kruskal 记排序比较次数、看边条数、
`find` 次数、`union` 次数与 `find` 沿父指针走过的步数；Prim 记优先队列的入队、出队、
过期弹出、堆里剩下的条数与边检查次数。两版选中的八条边逐条相同，总权值都是 44。

## 做完能掌握什么

- 会用邻接表与邻接矩阵两种存法，并说清哪一种能让遍历顺序与加边的先后无关
- 会写 Kahn 与 DFS 后序两版拓扑排序，并说清两版在同一个图上为什么给出不同的合法序列
- 会用「出队次数小于顶点数」发现环，并说清 Kahn 剩下的顶点里哪一些只在环的下游
- 会写 Tarjan 的强连通分量，并说清分量弹出的先后为什么是凝结图的逆拓扑序
- 会写割点与桥的判定条件，并知道根要单独判
- 会用暴力枚举（逐个删掉顶点或边再看连通块数）核对一次 DFS 算出来的割点与桥
- 会写 Kruskal 与 Prim，并说清两者各自把代价花在哪一步上
- 会把结构量做成计数器：数访问、数边检查、数 `low` 改小、数 `find` 走过的步数
- 会区分「与实现有关的数字」与「结构量」：`std::sort` 的比较次数由实现决定，不进报告

## 阶段推进

| 阶段 | 目标 | 做什么 | 怎么验收 |
|---|---|---|---|
| **阶段 1** | 跑通命令行版 | 配置、编译，运行 `build\mingw\bin\app_cli.exe` | 看到六段项目输出与「31 项中 31 项通过，全部通过」 |
| **阶段 2** | 看懂割点与桥 | 读 `conn_dfs`，对照报告第五段的 `dfn`／`low` 表 | 能说清顶点 3 为什么是割点，而顶点 4 为什么不是 |
| **阶段 3** | 换一条回边 | 把 `make_cyclic_digraph` 里的回边 8 -> 7 改成 6 -> 1，再跑一次 | 自测里与分量有关的那几项报出不符，报出的数字就是新的分量与凝结图 |
| **阶段 4** | 换一张图 | 给 `make_undirected_graph` 加一个顶点与一条边 | 报告里的割点、桥、总权值全部跟着变；自测写死集合的那几项会明确指出要改哪一处 |

阶段 2 是重点：把非根判定里对父顶点的检查（`parent[u]` 是否为 `-1`）去掉再跑一次，
自测第 8 项会报出「一次 DFS 得到 0 1 3 5 6」，多出来的顶点 0 就是被误判的那一个——
它的孩子 1 满足 `low[1] == dfn[0]`，而根要按子树个数另判。

## 代码里哪几处是要点

| 位置 | 要点 |
|---|---|
| `graph_lab.cpp` 的 `insert_sorted` | 加边时就把邻接表按编号插好，遍历顺序与加边先后无关，`dfn` 与拓扑序才能重跑逐位相同 |
| `graph_lab.cpp` 的 `topo_sort_kahn` | 最小堆代替普通队列，出队顺序只由入度表决定；剩下的顶点与剩余入度一起留下来 |
| `graph_lab.cpp` 的 `topo_sort_dfs_postorder` | 显式栈里带「下一条要看的出边」下标，回溯时接进后序序列，最后整体取逆 |
| `graph_lab.cpp` 的 `tarjan_dfs` | 指回栈里的顶点才算数：指向已经弹出的分量说明那条路是死路 |
| `graph_lab.cpp` 的 `conn_dfs` | 桥看 `low[v] > dfn[u]`，割点看 `low[v] >= dfn[u]`，根另判子树个数；回边用 `dfn` 而不是 `low` |
| `graph_lab.cpp` 的 `low_by_brute_force` | 按定义重算 `low`：子树里连出去的非树边；树边要排掉，否则父边会把 `low` 拉低 |
| `graph_lab.cpp` 的 `insertion_sort_by_weight` | 自己数比较次数，不用 `std::sort`，这个数才与标准库实现无关 |
| `graph_lab.cpp` 的 `DisjointSet::find` | 一边爬链一边数步数，爬完再把这条链挂到根上 |
| `graph_lab.cpp` 的 `prim_mst` | 候选边里带上「从哪来」，弹出的顶点若已进树就作废（惰性删除） |
| `graph_lab.cpp` 的 `matrix_grid` | 网格每格固定宽，行号与列号都是顶点编号，程序输出与 README 里的网格逐字符相同 |
| `main_cli.cpp` 的 `to_console_encoding` | 全项目唯一的编码转换点：控制台是 65001 就原样输出，是 936 就转 GBK |

## 已知问题

- 三张图都写死在源码里，规模都是九个顶点：报告里的每个集合与计数都只对这三张图成立，
  换一张图就要同步改自测里写死集合与数字的那几项
- 割点与桥的 DFS、Tarjan 都写成递归。顶点数上到十万量级时递归深度会顶穿调用栈，
  那时要改成显式栈，读数的那几个计数器可以照搬
- `Graph::add_edge` 会忽略重边与自环。无向图里出现重边时，「跳过父顶点」的写法会把
  另一条平行边一并跳掉，割点与桥的判定要改成跳过具体的父边
- Kruskal 里的排序是自己写的插入排序，比较次数是 O(n²) 量级；十条边够用，
  上万条边要换成 `std::sort`，代价是那个比较次数不再是结构量，要从报告里去掉
- `find_hops` 依赖并查集的具体写法（按大小合并加路径压缩）；换一种合并策略这个数会变，
  其余计数不受影响
- Prim 的堆里可能留着已经作废的候选边，报告里的「过期弹出」记的就是它们；
  `std::priority_queue` 删不掉堆中间的条目，加上「堆里还剩几条」一起看才不会误读
- 报告里没有任何耗时数字：本示例没有 `--timing`，时间不在它的观察范围内
- 邻接矩阵按 9 × 9 打印，换成几百个顶点的图要改成只打印边表
