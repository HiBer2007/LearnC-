# 示例 `08-algorithms/12-random-sampling` · 随机与采样：偏差、洗牌、蓄水池与加权

一个把随机算法里最容易写错的地方逐个测出来的命令行程序：`rand() % n` 多算了多少、
偏差从哪里来，拒绝采样与 `std::uniform_int_distribution` 怎么把它消掉；
Fisher-Yates 洗牌为什么必须从后往前，错误版把 256 条随机路径摊到 24 个排列上之后
每个排列分到几条；蓄水池抽样为什么每个元素被选中的概率都等于 `k / n`；
加权抽样用前缀和加二分与别名法各要几个随机数、几次比较。

报告里的每个数字都由计数器数出来：每个桶的频次与偏差、每个排列的频次与精确路径数、
每个下标被抽中的次数、随机数调用次数与二分比较次数，固定种子重跑逐位相同，
一个都不是估的。种子写在 `kSeed = 20261002` 一处，`rand()` 与 `std::mt19937`
两条流都从它出发；报告第一段把两条流的前 8 个数并排打出来，并说明两者的可复现范围
不同——`rand()` 的序列标准没有规定，由标准库的实现决定；`std::mt19937` 的序列
由标准规定，换一个标准库也是这 8 个数。

偏差这一类数字分两组规模看。n = 10 与 n = 100 上，取模偏差是 +61 ppm 与 +976 ppm，
而 20 万次试验的抽样噪声约 6700 ppm，观察值里根本看不出偏差；n = 20000 时，
分到两个取值的那些桶平均 12.197 次，分到一个取值的 6.120 次，二比一，
不用统计工具就能看出来。报告因此在三种规模上都给出「取值域计数」这一列：
`rand()` 的 32768 个取值里有几个会落到这个桶上，它是精确值，不随试验次数变化。

## 这个项目要解决什么问题

第一件是取模偏差的来源与它的隐蔽性。`rand() % n` 的偏差不是随机的，它来自一个
整除关系：`RAND_MAX + 1`（本机是 32768）除以 n 之后有余数，余数对应的那部分取值
被摊在前几个桶上。本机 n = 10 时，前 8 个桶各对应 3277 个取值，后 2 个桶各对应
3276 个，理论偏差是 +61 ppm 与 -244 ppm——精确值，再多跑也消不掉。麻烦在于它太小：
20 万次试验下每个桶的频次标准差约 134 次，折合 6700 ppm，是偏差的一百倍，
所以小 n 上靠观察频次判断分布是否均匀这个办法行不通。报告因此给出三列对照——
有偏的 `rand() % n`、拒绝采样、`std::uniform_int_distribution`——并且把 n 推到
20000，让偏差在观察值里露出来：两组桶的平均频次是 12.197 与 6.120。

第二件是洗牌的两种写法差在哪里。正确版从后往前，第 i 步在 i + 1 个位置里挑一个，
路径总数是 n × (n − 1) × … × 2 = n!，一个排列恰好一条路径。错误版每一步都在 n 个
位置里挑，路径总数 n^n；n = 4 时 256 条路径落到 24 个排列上，每个排列分到的条数
从 8 到 15 不等。程序把两个版本的路径数都枚举出来，与 24 万次实际洗牌的频次并排
打印：错误版最多的排列 `1 0 3 2` 有 15 条路径（5.859%），最少的 `3 1 2 0` 有 8 条
（3.125%），相差近一倍；正确版每一行的路径数都是 1，卡方 22.401 落在自由度 23 附近，
错误版的卡方是 7196.380。

第三件是蓄水池抽样的等概率。算法本身只有五行，但「每个元素被选中的概率相同」
这句话需要证明也需要核对。报告给出连乘的推导（`k/(i+1) × (i+1)/(i+2) × … × (n-1)/n = k/n`），
并用两条事实把它钉住：n = 20、k = 5 的两万次试验里每个下标被选中的次数都在
5000 附近（最大偏差 23600 ppm，与 12200 ppm 的噪声标准差同量级）；n = 6、k = 2 时
把全部 360 条随机路径穷举一遍，每个位置恰好被选中 120 次，正是 360 × 2 / 6。

第四件是加权抽样的两种做法各自的账。前缀和加二分每次抽样取一个 `[0, 权重和)` 的
整数，再二分找出落在哪个区间，20 万次抽样用掉 200000 个随机数与 424804 次比较；
别名法建表时把每一列的总权重凑成权重和，抽样时先选列再抛硬币，每次固定两个随机数、
一次比较都不用。两种做法的频次与理论权重对照，偏差都在抽样噪声内；别名法的正确性
另用一条整数恒等式核对：`n × w_i` 等于直接部分加上所有指向 i 的别名部分之和。

## 做完能掌握什么

- 会算出 `rand() % n` 的理论偏差，并能说出它来自 `RAND_MAX + 1` 除以 n 的余数
- 会用取值域计数判断一个抽样做法是否有偏，而不是拿观察频次去猜
- 会写拒绝采样，并能说清「可接受的取值个数是 n 的整数倍」为什么就是无偏
- 会写出正确的 Fisher-Yates 洗牌，并能说清错误版为什么把 n^n 条路径摊不均匀
- 会把一个洗牌算法的全部分布用路径枚举精确算出来，而不是只看几轮试验的结果
- 会写蓄水池抽样，并能用连乘证明每个元素被选中的概率是 `k / n`
- 会用前缀和加二分做加权抽样，也会建别名法的表并核对它的恒等式
- 会用卡方统计量判断一组频次是否偏离理论分布，并知道自由度是多少
- 会分清哪些随机数结果跨实现一致（`std::mt19937`）、哪些只在本机复现（`rand()`）

## 阶段推进

| 阶段 | 目标 | 做什么 | 怎么验收 |
|---|---|---|---|
| **阶段 1** | 跑通命令行版 | 配置、编译，运行 `build\mingw\bin\app_cli.exe` | 看到五段项目输出与「26 项中 26 项通过，全部通过」 |
| **阶段 2** | 看清取模偏差的来源 | 读 `modulo_preimages`，对照报告第二段的「取值域计数」列 | 能说清 n = 20000 时两组桶的平均频次为什么是 2 比 1 |
| **阶段 3** | 把有偏换成无偏 | 把 `modulo_buckets` 里的 `value % buckets` 换成 `uniform_below(engine, buckets)` | 报告里 n = 20000 的两组平均频次回到 10 附近；此刻「取值域计数」与「理论偏差」两列已经不再描述程序实际走的映射，要一并改成拒绝采样的口径 |
| **阶段 4** | 换个试验次数看卡方 | 把 n = 5 的洗牌次数从 120000 提到 1200000 | 错误版卡方随试验次数继续放大，正确版仍在自由度 119 附近 |
| **阶段 5** | 换一组元素个数 | 把加权抽样的 5 个元素换成 20 个等权元素 | 别名法仍是每次 2 个随机数、0 次比较；前缀和版每次的比较次数从 2 到 3 次升到 4 到 5 次 |

阶段 3 是重点：改完之后，第二段里那两组平均频次的差距会消失，而「理论偏差」一列
还在——它算的是取模公式的性质，与程序实际走哪条路无关。要看偏差是否真的被消掉，
看的是「取值域计数」与观察频次两列。

## 已知问题

- **`rand()` 的序列随标准库而变**：报告第一段的前 8 个数、第二段的取模频次、
  拒绝采样频次与调用次数，都只在 MinGW-w64 libstdc++（本机 `g++ 16.2.0`）上
  逐位可复现。标准没有规定 `rand()` 的算法，换一个标准库就是另一串数。
  本机另用 MSVC 19.44 的 STL 编译同一段探测程序对照过：`rand()` 的前 8 个数与
  取模频次与本示例完全相同（两套都落到 Windows CRT 的同一个线性同余发生器上），
  但换到 glibc 上这些数字会变。`std::mt19937` 没有这个问题，它的序列由标准规定，
  自测第 3 项核对的正是这 8 个数
- `std::uniform_int_distribution` 的映射方式标准没有规定，报告里「分布」那一列的
  频次只保证在本机 libstdc++ 上逐位复现。本机用 MSVC 的 STL 跑同一份源码时这一列
  恰好也相同，但这是两套实现碰巧都用了缩放加拒绝这一路的做法，标准并没有要求，
  不能当成跨实现的保证。它的**分布**均匀才是标准的要求，自测第 7、25 项按频次与
  卡方核对，第 6 项核对的是自己写的拒绝采样（取值域被截到 n 的整数倍，
  这是一条精确性质）
- 偏差与平均频次都用整数运算并**向零截断**，不是四舍五入，因此表里的数字与精确值
  可能差一个最小单位，例如 n = 1000 的其余桶理论偏差打印成 -23437，精确值是
  -23437.5 ppm
- **小 n 上的取模偏差在观察值里看不出来**，这是它危险的地方：n = 10 与 n = 100 时，
  20 万次试验下每个桶的相对噪声是 ±6700 ppm 与 ±22300 ppm（桶里期望的频次从
  20000 降到 2000，相对噪声反而变大），而取模偏差只有 +61 ppm 与 +976 ppm，
  差两个数量级；报告用 n = 20000 那一组展示偏差，并且把「取值域计数」与「理论偏差」
  两列作为偏差本身的证据。偏差随 n 线性增长、噪声只随 n 的平方根增长，
  这就是 n 越接近 `RAND_MAX + 1` 越容易看见偏差的原因
- 洗牌的排列统计只做到 n = 5（120 个排列）：n = 6 时排列有 720 个，24 万次试验
  每个排列平均只有 333 次，噪声会盖住错误版的路径差异；错误版的路径枚举本身
  在 n = 6 时仍然可行（6^6 = 46656 条）
- 蓄水池的精确枚举只做了 n = 6、k = 2 与 n = 6、k = 3（360 条与 120 条路径）。
  路径总数是 `n! / k!`，n = 20、k = 5 时是 2.03 × 10^16 条（6 × 7 × … × 20），穷举不可行；
  那个规模只能靠 20000 次抽样看大致均匀，核对靠的是「命中次数之和等于 rounds × k」
  与「最大偏差在 4 倍标准差之内」两条
- 别名法用的是整数权重。权重不是整数时这套写法要先乘一个放大倍数变成整数，
  放大倍数直接决定 `prob_num` 的精度；放大到权重和为 1000 时最小分辨是 0.1%
- 加权抽样只给了 5 个元素，别名法在这里的优势看不出来（多花一个随机数、
  省下两次比较）。它的价值在元素个数大时：每次抽样的比较次数从 log2(n) 降为 0，
  阶段推进的第 5 阶段可以用 20 个元素看到这个趋势
- 报告里**没有任何计时数字**：耗时随机器负载变化，放进来就破坏了逐位可复现。
  本机实测一次完整运行（报告加自测）约 0.3 秒，只跑自测约 0.15 秒，这两个数只在
  这台机器上成立
- 只覆盖单线程使用：`rand()` 的种子是全局状态，`CrandEngine` 每次构造都会
  `srand`，两处在不同线程同时用会互相干扰；`CountingEngine` 的计数器也不带同步
- 未覆盖的范围：连续分布的采样（正态、指数、均匀实数）、`std::shuffle` 内部
  用了几次随机数、`std::random_device` 与操作系统熵源、密码学安全的随机数，
  这些都不在本示例内
