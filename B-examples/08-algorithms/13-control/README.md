# 示例 `08-algorithms/13-control` · 控制：让一个量停在目标上

一个把控制回路里最容易被想当然的几件事逐个测出来的命令行程序：开环给一份标定好的常值力矩，
负载一变位置就跑掉，5 s 内偏出 7.400 个单位；开关控制不加滞回时每个样本都在翻转，加 5 度带宽
把切换次数从 19993 次压到 526 次，代价是温度波动从 0.134 度涨到 5.068 度；P 的稳态误差正好等于
负载除以 kp（0.200 / 0.500 = 0.400），积分项把它压到 0，代价是阶跃超调从 0.164 涨到 0.409；
采样周期从 2 ms 拉到 500 ms，同一组增益从 41% 超调一路走到发散。

报告里的每个数字都由这里的仿真产出：超调、稳态误差、误差绝对值积分（IAE）、控制量总变化
（Σ|Δu|）、开关状态翻转次数、滤波器的输出标准差与阶跃 50% 滞后、测速三种方法在闸门相位上扫出来的
最坏相对误差。被控对象只有一台——位置伺服（转动惯量 J = 0.020、粘性摩擦 b = 0.100、力矩限幅
±4.000），它同时装得下这一章要讲的几件事：P 留下与负载成正比的稳态误差、积分项把误差消掉却带来
超调、微分项加阻尼同时放大噪声、执行器一限幅就出现饱和。仿真用固定步长的显式积分，位置按匀加速
的精确式子推进，参数与噪声种子都写死，重跑逐位相同。

三种量放在一起看最清楚。**超调**是峰值减目标；**稳态误差**只由回路结构决定，噪声与扰动都不改变
它；**控制量总变化**是 Σ|Δu|，量测里那点噪声经过微分项之后会把它顶上去——同一段噪声下 PID 是
PI 的 87.8 倍，给微分项加一个 α = 0.200 的低通又把它压回 0.14 倍。

## 这个项目要解决什么问题

第一件是开环到底缺什么。标定出来的常值力矩只知道「给多少」，不知道「现在在哪儿」：负载从
0.200 阶跃到 0.400 之后，同一个力矩不再是平衡点，位置朝反方向匀速跑掉，5 s 内偏出 7.400，
IAE 14.480；同一份扰动下 PI 闭环把末尾误差压到 0.007，IAE 0.527，2.902 s 回到 ±2%。第二行
把标定值本身打偏 25%（按 0.250 标定、实际负载 0.200），开环 5 s 内偏出 -2.350，闭环是 0.001——
反馈不需要那个标定值。

第二件是滞回的取舍。热模型配开关控制，带宽为 0 时每个样本都在翻转（20000 个样本里切换 19993 次），
温度极差只有 0.134 度；带宽 0.5 度把切换次数压到 3999 次，1 度 2222 次，2 度 1250 次，5 度 526 次，
温度极差分别涨到 0.668、1.202、2.136、5.068 度。切换次数随带宽单调不增、波动单调不减，五个带宽下
后半程均值都在 60 度附近：滞回改的是波动，不是均值。

第三件是 PID 三项各自在改什么。P 的稳态误差是负载除以 kp，实测出来是 0.400，与解析值差不到
一个最低位；PI 把它压到 0.000，代价是阶跃超调从 0.164 涨到 0.409；PID（kd = 0.050）把超调压回
0.278。量测带上 ±0.005 的噪声之后，PI 的控制量总变化是 5.037，PID 跳到 442.406（87.8 倍），
而给微分项加一个 α = 0.200 的低通之后回到 60.031，是未滤波的 0.14 倍。

第四件是离散化与字长各值多少。同一组增益只改采样周期：0.002 s 时超调 0.409，0.200 s 时 0.696，
0.500 s 时发散；相邻样本最大跳变从 0.006 涨到 184.158。字长这一侧，位置与力矩都走 1/1024 的格点，
浮点不量化的末尾最大误差是 0.000000036，12 位量化之后是 0.001（约一个最低位），定点 Q16.16 是
0.001321；定点那一版的积分器一格只有 0.000000015，比传感器细四个数量级，所以瓶颈在量测与执行器
的位数，不在运算用几位。

第五件是饱和之后的积分器怎么收场。参考从 0 跳到 1.000，力矩限幅 ±0.200，开头有 350 个样本贴着
上限：不做抗饱和时积分器在饱和期间涨到 0.206，退出饱和之后超调 0.485、3.226 s 才稳定；钳位把
饱和期的积分器按在 0.000，超调 0.148、2.052 s 稳定；反算（kaw = 5 /s）超调 0.011、2.252 s 稳定。
三者用的限幅一模一样，差别只在饱和期间积分器那一步怎么算。

第六件是滤波的两笔账。同一条噪声（200000 个样本、均匀分布 ±0.020、输入标准差 0.011540）喂给两组
配好对的滤波器：一阶低通 α = 0.250 与滑动平均 N = 7 的输出标准差是 0.004320 与 0.004313，理论值
都是 0.004362，抑制倍数 2.671 与 2.676；阶跃 50% 滞后是 1.444 与 2.500 个样本。第二对（α = 0.100
与 N = 19）是 0.002600 与 0.002595，滞后 5.592 与 8.500 个样本。抑制倍数一样时，一阶低通的滞后
更小，因为它把权重压在当前样本上。

第七件是测速方法跟转速的关系。编码器每转 4096 个计数、时钟 10 MHz、闸门 12 ms，闸门起点在一个
计数周期内扫 211 个相位取最坏值：M 法在 1 rpm 时最坏误差 1000000 ppm（有一批相位一个计数都数不到，
38 / 211 个相位读数是 0），10 rpm 时 98633 ppm，到 3000 rpm 只剩 244 ppm；T 法反过来，1 rpm 时
只有 4 ppm，3000 rpm 时 17253 ppm；M/T 法把闸门两端对齐到计数边沿，用时钟把这段跨度量准，五个
转速都在 6 ppm 以内。一个数脉冲、一个数时钟，各自的短处正好落在另一端。

第八件是前馈什么时候值得加。梯形速度规划（加速到 1.000 单位/s、匀速 0.500 s、再减到 0，总位移
1.000）配一条比标称重 10%、负载大 10% 的真实对象：纯反馈的最大跟踪误差 0.668、RMS 0.414、匀速段
平均误差 0.596；前馈（标称模型）加反馈是 0.012、0.006、0.004；模型完全准确时只剩 0.000000000。
纯反馈要靠误差才能产生力矩，跟一个动着的参考必然落后一拍；前馈把模型里知道的那部分一次给足，
剩下的误差只是模型没算准的残差。

## 做完能掌握什么

- 会说明开环为什么守不住位置，并能用负载阶跃与标定偏差两种扰动把这件事量化
- 会算 P 控制的稳态误差（负载除以 kp），也会说明积分项消掉它的代价是什么
- 会用超调、稳定时间、IAE、控制量总变化四个量评价一条控制回路
- 会说明滞回带宽与切换次数、温度波动之间的取舍，并知道无滞回时抖振从哪里来
- 会判断采样周期够不够：同一组增益下超调怎么随周期上涨，到哪一档直接发散
- 会写定点的 PID，并知道定点位数与传感器位数哪一个才是瓶颈
- 会实现钳位与反算两种抗饱和，并说清它们各自改的是积分器的哪一步
- 会算一阶低通与滑动平均的噪声抑制倍数与阶跃滞后，并知道抑制一样时谁滞后更小
- 会算编码器 M 法、T 法、M/T 法在低速与高速下的量化误差，并知道各自的短处
- 会判断什么时候该加前馈：模型里知道的部分不必等误差出来再补
- 会用固定步长与固定种子把整份报告做成可复现的，并把计时量挡在默认输出之外

## 阶段推进

| 阶段 | 目标 | 做什么 | 怎么验收 |
|---|---|---|---|
| **阶段 1** | 跑通命令行版 | 配置、编译，运行 `build\mingw\bin\app_cli.exe` | 看到八段项目输出与「36 项中 36 项通过，全部通过」 |
| **阶段 2** | 看清 P 与 I 的分工 | 读 `run_pid_row`，对照报告第三段的三个控制器 | 能说清为什么 P 的末尾误差正好是 0.400，而 PI 是 0.000 |
| **阶段 3** | 把滞回加回去 | 把 `probe_hysteresis` 里 `bands` 的第一项从 0.0 改成 5.0 | 第一行切换次数从 19993 落到 500 上下、极差升到 5 度上下；自测第 6 项的判据假定第一档是 0.0，要一并改 |
| **阶段 4** | 换一个反算系数 | 把 `probe_anti_windup` 的 `kaw` 从 5.0 改成 20.0 | 反算那一行的超调与稳定时间都跟着变（这一档的数本示例没有给），钳位那一行不动——它不用这个系数 |
| **阶段 5** | 把采样周期推到更远 | 给 `probe_discretization` 的 `periods` 数组补上 1.0（数组长度同时改成 9） | 报告第四段多出一行（这一档的数本示例没有给），相邻样本最大跳变继续变大 |
| **阶段 6** | 换一台对象 | 把 `kInertia` 从 0.02 改成 0.05 | 第三段的超调、恢复时间与第四段的发散点都跟着变（这一档的数本示例没有给） |

阶段 3 是重点：改完之后第二段第一行的含义就反过来了，从「无滞回有多抖」变成「滞回有多划算」，
而自测第 6 项的判据还按第一档是 0.0 写的，必须同时改，否则那一条会失败。

## 代码里哪几处是要点

| 位置 | 要点 |
|---|---|
| `control_lab.hpp` 的 `PlantParams` | 平衡点：静止时只需 u = load / gain 就能停在任意位置，停在哪儿由历史决定 |
| `control_lab.hpp` 的 `PidController::update` | 微分作用在量测上而不是误差上，目标值跳变时不会有微分冲击 |
| `control_lab.hpp` 的 `AntiWindup` | 三个取值对应积分器的三种处理：照涨、冻结、按超出的部分退回 |
| `control_lab.cpp` 的 `simulate` | 位置按 v·Ts + a·Ts²/2 推进；只写 v·Ts 是一阶格式，周期一粗，数值误差会盖过控制器本身的差别 |
| `control_lab.cpp` 的 `plant_of` | 力矩可正可负；单向限幅时惯性刹不住，超调不是控制器的毛病而是执行器的毛病 |
| `control_lab.cpp` 的 `probe_hysteresis` | 无滞回时温度在目标两侧各差半个步长，于是每个样本都翻转 |
| `control_lab.cpp` 的 `run_pid_row` | 阶跃段与负载段分开统计：一个看超调，一个看稳态误差 |
| `control_lab.cpp` 的 `FixedPointController` | 位置与力矩都按 1/1024 的格点走整数，右移手写成向零取整 |
| `control_lab.cpp` 的 `run_quant_row` | 三条量化路线共用同一条对象，只换控制律的实现方式 |
| `control_lab.cpp` 的 `probe_anti_windup` | 三种做法共用同一个限幅，差别只在饱和期间积分器那一步 |
| `control_lab.cpp` 的 `MovingAverage` | 缓冲先填 0（阶跃之前的值），否则起步那段会把滞后算小 |
| `control_lab.cpp` 的 `step_lag` | 50% 时刻用线性插值取小数，只取整样本会把两组滤波器的滞后差抹平 |
| `control_lab.cpp` 的 `probe_speed_methods` | 闸门相位扫 211 个点取最坏值：量化误差跟相位有关，只看一个相位会低估 |

| `control_lab.cpp` 的 `make_noise` | 取高 24 位再除以 2^24，全程整数与 2 的幂，不依赖标准库的分布实现 |

## 已知问题

- **被控对象是理想化的线性二阶模型**：没有纯滞后、没有齿隙、没有库仑摩擦，参数也不随工况变。
  真实伺服这几样都占，因此报告里的超调与稳定时间是这条理想对象的数，不能直接当成某台设备的指标
- **开环那一列是窗口定义的**：它随时间线性发散（终端速度是 `(load − u) / b`），跑得越久数字越大。
  表里给的是 5 s 窗口里的值，不是「稳态误差」
- 噪声是固定种子的线性同余加均匀分布，不是物理噪声源。滤波那一段的抑制倍数与理论值相符，
  前提是白噪声；有色噪声下这两个滤波器的排序可能变
- 滞回那一段的热模型没有传感器噪声。加上噪声之后无滞回那一档的切换次数只会更高，
  因为噪声会推着温度在目标附近穿来穿去，本示例没有测这一项
- 测速那一段假设计数边沿严格等间隔、时钟严格准确。真实编码器有边沿抖动与占空比误差，
  M/T 法的实际误差会大于这里的 6 ppm；这里量的是量化误差本身
- 定点那一段的格点写在 1/1024（位置盖 [0, 4)、力矩盖 [−4, 4]），报告里「一个最低位」的说法
  只对这个选择成立，换一个量程那一列的数字跟着变
- 反算系数固定 `kaw = 5` /s。换一个值（见「阶段推进」的阶段 4）超调与稳定时间都会变，
  本示例没有给这个系数的扫描
- 微分项的低通只报了 α = 0.200 一档，也没有量相位裕度。想看清滤波与微分的关系，
  看第六段那两组配对滤波器
- **稳定时间与稳态误差都依赖判据**：±2% 的带、末尾 0.2 s 到 1 s 的窗口。改判据这两列就变，
  报告里没有把它们写成绝对的性能指标
- 浮点结果对**同一个可执行文件**逐位可复现，跨编译器、跨优化等级不保证最后几位相同。
  本示例只在本机 `g++ 16.2.0` 的 Debug 构建上跑过，MSVC 未测
- 报告里**没有任何计时数字**。要看耗时用 `--timing`，那个数会随机器负载变
- 位置那一步用的是匀加速的精确式子，报告里没有把「只写 v·Ts」的一阶格式并列打印；
  两者在本示例 2 ms 的周期下差不到 1%，周期粗到第四段最后几档才拉开
- 未覆盖的范围：串级控制、纯滞后对象的 Smith 预估、增益调度、模型预测控制、观测器与状态反馈、
  频域设计（波特图与相位裕度），这些都不在本示例内
