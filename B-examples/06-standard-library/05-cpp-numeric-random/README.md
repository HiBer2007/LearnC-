# 示例 `06-standard-library/05-cpp-numeric-random` · 随机数与统计：`<random>` 抽样、`<numeric>` 统计、直方图（命令行 + Win32 GUI）

这个示例把「造一批数据，再把它算成几个数」这件事做完整：
用 `<random>` 的引擎加分布生成三组样本，用 `<numeric>` 的四个算法把它们变成总和、均值、平方和、方差与前缀和，
再按固定箱宽分箱画成文本条形图；最后拿 `rand()` 做一次同规模的对照，给出两条能观察到的弱证据。

固定种子是整件事的前提。同一个种子必须给出同一批样本，否则「这次跑出来的均值」没有任何意义，
自测也无从写起。因此 `demo::Options` 的 `seed` 有写死的默认值，`--seed` 只是把它换掉。

命令行版出报表并跑自测，Win32 版把同一份报表显示在只读框里，并在下方用 GDI 把直方图真的画出来。
两者都只调用 `core`，界面文件里没有一行抽样或统计的代码。

## 这个项目要解决什么问题

随机数不是「随便取一个数」。要做到可复现，就得固定种子；要让样本的分布可控，
就得把引擎与分布分成两件东西；要把一批样本变成可比较的数字，就得自己把统计算一遍并核对。

`rand()` 常被引用为「弱」，但弱在哪里需要可观察的证据。这个示例给出两条能量出来的：
低位序列的重复周期，以及把取值折叠到非整数倍值域时的分布偏移。
两条都有明确的适用边界，报表里一并写明了边界在哪里。

## 做完能掌握什么

- 会用 `mt19937_64` 配 `uniform_int_distribution`、`normal_distribution`、`discrete_distribution` 造可控样本
- 会用 `<numeric>` 的 `accumulate`、`inner_product`、`iota`、`partial_sum` 把样本算成统计量
- 会按固定箱宽分箱，并检查箱边界首尾相接、计数合计等于样本总数
- 会用两条可观察的证据说明 `rand()` 的弱点，同时说清这两条证据在什么规模下失效
- 会把界面与逻辑分开：`core` 不认识窗口，也不认识 `std::cout`
- 会用 GDI 的 `FillRect` 画直方图，并用无人值守的方式验证柱子确实画出来了

## 代码里哪几处是要点

| 位置 | 要点 |
|---|---|
| `stats_demo.cpp` 的 `uniform_samples` | `mt19937_64` 与分布分开构造：引擎决定序列，分布决定形状；同一个引擎换分布不用重新播种 |
| `stats_demo.cpp` 的 `compute_stats` | `accumulate` 的初值写 `0LL`，避免按 `int` 累加溢出；`inner_product` 拿自己与自己内积就是平方和 |
| `stats_demo.cpp` 的方差计算 | 用「平方和 / n − 均值²」而不是两遍扫描，浮点舍入可能把它压成负数，因此有一句下限归零 |
| `stats_demo.cpp` 的 `make_histogram` | 箱数由最小值与最大值决定，末箱可能超出最大值；相邻箱满足 `high + 1 == next.low` |
| `stats_demo.cpp` 的 `compare_with_rand` | 低位周期按 2 的幂逐级试探；折叠偏差用 20000 这个非整数倍模数，才量得出来 |
| `stats_demo.cpp` 的 `run_self_tests` | 16 项全部在这里，界面只负责把结果摆出来 |
| `main_gui_win32.cpp` 的 `to_wide` | `core` 给的窄字符串是 GBK，按 `CP_ACP` 转宽，界面上的中文才不乱码 |
| `main_gui_win32.cpp` 的 `paint_chart` | 纯 GDI：底色、边框、`FillRect` 画柱子、横轴刻度与纵轴峰值都是 `TextOutW` |

## 已知问题

- `rand()` 的行为由运行库决定，标准只保证 `RAND_MAX` 不小于 32767。自测第 14、15 项断言的是本机实现
  （MinGW 链接的 msvcrt，`RAND_MAX = 32767`）的表现；换到别的运行库时这两项可能变成 `[失败]`，
  这不是代码错误，而是对照结论不适用于那个库
- 固定种子只保证同一实现内可复现。`mt19937_64` 的序列由标准规定，因此跨实现一致；
  `uniform_int_distribution` 等分布的具体取值方式没有规定，换一个标准库实现可能得到不同的样本
- 「折叠偏差」用 `% 20000` 展示。模数远小于 `RAND_MAX` 时（例如 `% 100`）偏差小到在几万个样本里测不出来，
  报表的结论一句已经写明这一点
- 低位周期要取到 2 × 131072 个样本才观察得到；更小的规模下 `rand()` 的低位看不出异常
- Win32 版的窗口是固定大小的（`WS_OVERLAPPED | WS_CAPTION | WS_SYSMENU | WS_MINIMIZEBOX`），
  没有写控件重排
- 直方图只有一种填充色，柱子之间靠间隙区分
- 窄字符串按 GBK 写进 exe。控制台输出编码为 UTF-8 时中文显示成乱码，先 `chcp 936` 再运行
