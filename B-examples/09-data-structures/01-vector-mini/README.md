# 示例 `09-data-structures/01-vector-mini` · 手写动态数组（纯命令行）

一个从零写起的动态数组，配一套能把「增长策略」与「异常安全」测出来的报告。
它把 `std::vector` 的三指针布局、四档增长倍数、搬迁时拷贝与移动的分岔、
扩容搬到一半抛异常之后的收拾工作，都做成了可以逐行对照的输出。

主线是**分配与构造分开**：缓冲区是一块用 `::operator new` 拿来的原始内存，
元素是用定位 new 在这块内存上构造出来的对象。
把这两件事分开之后，增长倍数、异常安全骨架、分配器接口三件事才有地方落脚。
报告里出现的每个数字都来自计数器：容量、扩容次数、搬移元素个数、
分配与释放次数、拷贝与移动次数，重新运行的结果逐位相同。报告不打印任何地址，因为地址不可复现。

核心库另带 19 项自测，其中第 12 与第 13 项专门验「搬到一半抛异常」：
一个拷贝构造会抛的测试类型，在搬迁到第 5 个元素时抛出，
自测随后检查容器内容、占用字节数、分配与释放次数、三条不变式是否全部回到原样。

## 这个项目要解决什么问题

`vector` 的用法已在 `A-01` 中讲完，对应的章节要回答的是「自己写一个的时候，
哪些决定必须提前想清楚」。项目把那些决定各做成一段能看见的输出。

第一件是增长倍数。项目提供四档：2 倍、1.5 倍、每次加一、每次加 10%。
同一份「插入 5000 个 `int`」的活，2 倍策略扩容 14 次、搬走 8191 个元素；
「每次加一」扩容 5000 次、搬走 12497500 个元素。搬移总量与元素个数之比从 1.64
升到 2499.50，这一列正是「倍数必须大于 1 且成倍」的依据。

第二件是搬迁方式。扩容要把旧元素搬到新缓冲区，用移动构造还是拷贝构造，
取决于元素的移动构造有没有标 `noexcept`。项目用三个测试类型验证这条规则：
两个没标 `noexcept` 的类型，搬 8 个元素时拷贝 8 次、移动 0 次；标了的那一个反过来。
`std::move_if_noexcept` 的判据与实测结果在报告里并排出现。

第三件是异常安全。搬迁搬到第 5 个元素时抛出，此时新缓冲区里已经有 4 个构造好的对象、
旧缓冲区一个元素都没动。项目走的是「先备新缓冲区、搬完才动指针」的骨架，
异常路径把已构造的元素析构掉、把新内存还回去，再原样抛出。
自测第 12 项核对的是：容器内容逐位一致、占用字节数回到原值、
这次失败的扩容恰好一进一出、三条不变式仍然成立。

第四件是元素的生命周期。自测第 11 项用另一个只数构造与析构的类型，对
扩容、`pop_back`、`resize` 的放大与缩小各做一次，最后核对「构造次数 == 析构次数、还活着的 0 个」。
漏析构与多析构都会在这一条上暴露。

## 做完能掌握什么

- 会写出三指针布局的动态数组，并能说清 `[data_, data_ + size_)` 与 `[data_ + size_, data_ + cap_)` 的区别
- 会用 `std::move_if_noexcept` 决定搬迁用拷贝还是移动，并能说清它为什么这么判
- 会写强异常安全的扩容骨架：先备新缓冲区、搬完才动指针、抛了把新缓冲区收拾干净
- 能测出四档增长策略的扩容次数与搬移总量，并用数据说明为什么不能用「每次加一」
- 会把分配与构造分开，并把分配次数、释放次数、峰值占用都记下来
- 会解释为什么 `reserve` 之后迭代器仍然可能失效
- 会把核心逻辑与界面分开：`vmini` 命名空间不认识 `std::cout`，也不认识控制台编码

## 代码里哪几处是要点

| 位置 | 要点 |
|---|---|
| `vector_mini.hpp` 的 `invariants_ok()` | 三条不变式写成可调用的检查，每次改完都可以检查一遍 |
| `vector_mini.hpp` 的 `emplace_back()` | 先扩容再构造：扩容抛了容器没变，构造抛了 `size_` 不动 |
| `vector_mini.hpp` 的 `reallocate()` | 全类唯一会抛的地方；新缓冲区、`built` 计数、`catch` 里的两步收拾 |
| `vector_mini.hpp` 的 `std::move_if_noexcept` | 移动构造不抛才敢移动，一行决定搬迁方式 |
| `vector_mini.hpp` 的 `release_all()` | 先逐个析构元素、再还缓冲区，两步不能合成一步 `delete[]` |
| `vector_mini.cpp` 的 `next_capacity()` | 小容量下整数除法会让 1.5 倍退化成原地踏步，届时加一 |
| `vector_mini.cpp` 的 `arm_check()` | 「第 5 次拷贝时抛」的开关；抛出点在拷贝构造里，不在容器里 |
| `vector_mini.cpp` 的 `display_width()` | 表格按显示宽度对齐：CJK 算 2 列，否则中文列会参差 |
| `main_cli.cpp` 的 `to_console_encoding()` | 全项目唯一的编码转换点：控制台是 65001 就原样输出，是 936 就转 GBK |

## 已知问题

- 分档只覆盖 `Growth` 里的四档；`next_capacity` 不做溢出保护，
  往接近 `SIZE_MAX` 的容量上插入会算出回绕后的值
- 元素类型要求可拷贝或可移动，且不支持「只能默认构造」的类型：
  `emplace_back` 走的是定位 new 加完美转发，`resize` 扩大时才用默认构造
- `Vector` 只提供指针迭代器，没有反向迭代器，也没有 `insert`／`erase`；
  中间插入与删除的迭代器失效规则见《09-高阶数据结构/B-01-手写：动态数组.md》第 6 节
- 分配统计是全局的，多线程下不安全；教学示例固定单线程使用
- 报告里的「峰值占用」按字节数记录，不区分是哪一档策略造成的；
  换一个 `T`（例如 `std::string`）之后字节数会跟着变，这是 `sizeof(T)` 的结果
- 报告第三段（异常安全）用 `sizeof(CopyOnly)` 等于 4 这个事实算出 32 与 64 两个字节数；
  把那个类改成带 `double` 成员之后，这两处会跟着变
