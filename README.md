# C/C++ 编译与调试教材

本教材面向**从零开始学 C/C++** 的读者，重点回答两类问题：

- **代码是怎样变成程序的**，以及为什么这个过程不能省略
- **程序出错时怎样查出原因**，而不只是靠打印

全部结论均经过实际验证，并标注了依据。

## 全教材通用的约定

### 结论的依据怎么标

文中每个技术结论都标了依据，**标注是表格或代码块上方的一行灰色小字**：

<small style="color:gray">text</small>

```
实测数据    在编写环境中实际执行并验证过，输出可复现
文档        引自标准或官方资料，原文以引用块给出
待确认      有合理推断但未验证，或依赖外部条件
```

**这三种标注只出现在被标注的对象正上方**，不写在句子中间。

### 提示与注意事项

按后果轻重分五级，靠左侧色线区分：

| 写法 | 颜色 | 表示 |
|---|---|---|
| `> [!IMPORTANT]` | 紫 | **结论**、要点、本质概括 |
| `> [!NOTE]` | 蓝 | **小结**、回顾 |
| `> [!TIP]` | 绿 | **提示**、做法建议 |
| `> [!WARNING]` | 黄 | **警告**、可能出错 |
| `> [!CAUTION]` | 红 | **严重后果**（未定义行为、数据损坏、安全问题） |

### 代码块的语言

**GitHub 与 VS Code 的预览都不在代码块头部显示语言**，
因此每个代码块上方也有一行灰色小字标明：

<small style="color:gray">markdown</small>

````markdown
<small style="color:gray">c</small>

```c
/* width.c    编译：gcc -std=c23 width.c -o width */
#include <stdio.h>
int main(void) { return 0; }
```
````

标签用英文，与围栏名一致：`c`、`cpp`、`powershell`、`bash`、`text`、
`cmake`、`json`、`jsonc`、`asm` 等。

**文中的实测代码一律写成完整单文件**，带 `#include` 与 `int main`，
首行注释写明文件名与编译命令，读者可以直接复制去跑。

### 路径的写法

教材面向任意一台 Windows 计算机，因此**不出现某一台机器的具体安装路径**。
文中一律使用下列占位符：

| 占位符 | 含义 | 常见形式 |
|---|---|---|
| `<MinGW>` | MinGW-w64 的安装目录 | `C:\mingw64` |
| `<CMake>` | CMake 的安装目录 | `C:\Program Files\CMake` |
| `<VS>` | Visual Studio 的安装目录 | `C:\Program Files\Microsoft Visual Studio\2022\Community` |
| `<版本号>` | 带版本号的目录中的那一段数字 | 如 `14.44.35207` |
| `<工作区>` | 你在 VS Code 中打开的文件夹 | 任意位置 |
| `<发行版名>` | WSL 发行版的名字 | `Ubuntu` |
| `<WSL地址>` | WSL 的虚拟网卡地址 | `192.168.x.x` |

**各程序的实际路径怎么找**：见[01-编译器/02-环境配置](01-编译器/02-环境配置.md)第 3 节。

### 引用文档的写法

文中引用其他文档时写作 `《01-编译器/01-编译与链接.md》`，
路径**相对于本教材的根目录**。

**讲清引用的层级**，教材用四个固定的称呼：

| 层级 | 称呼 | 例子 |
|---|---|---|
| 顶层文件夹 | **板块** | `04-语法` |
| 一个 `.md` 文件 | **章节** | `01-一些基础概念.md` |
| 文件内的 `#` 标题 | **节** | `# 第 1 节 语法糖` |
| 文件内的 `##` 标题 | **小节** | `## 1.1 一句话定义` |

因此写「见《03-构建工具链/01-构建工具链.md》第 3.8 小节」。

**已规划但尚未编写的章节**，引用时写成 `【待补：04-语法/07-数组、指针与引用.md】`。

## 本教材的四个立足点

### 一、用真实代码讲，不用玩具代码

教材中的例子取自**实际运行的项目**，而不是为教学编写的片段。
真实代码里有历史包袱、平台差异、为绕开某个问题而写的怪代码——
**这些恰恰构成了实际开发的绝大部分难度**。

源文件收录在 [`A-教学素材/`](A-教学素材/)，可对照阅读。

### 二、说清「为什么」，不只给结论

例如：

- 不只说「要加 `-g`」，而是说明调试信息里存了什么、不加会怎样
- 不只说「任务要这样写」，而是说明为什么另一种写法会失败
- 不只说「用 `volatile`」，而是给出优化前后的汇编对照

**讲一个语法点时，先找出它是不是另一件事的「语法糖」**，
再说明糖纸下面是什么。这样它的性质就是推出来的，不用逐条背。
写法见[04-语法/01-一些基础概念](04-语法/01-一些基础概念.md)第 1 节。

### 三、数据与结论分开摆

**主线只留讲清一件事所必需的数据**，
完整的实测数据、复现命令与源码放到该章节的附录。

数据用灰色小字标注，与正文区分开，读者顺着正文能连续读完。

### 四、区分「实测」与「文档」

教材中的每个技术结论都标明了依据。
凡未实际验证的，一律注明「待确认」，不冒充已验证的事实。

## 实测环境

**本教材中标为「实测数据」的结论，全部在这一套环境下取得。**
换环境后数值可能不同，**结论的方向通常不变，但具体数字不要照搬**。

### 主机

| 项目 | 值 |
|---|---|
| 操作系统 | Windows 11，build 22631 |
| 架构 | x86-64 |
| 内存 | 95.8 GB |
| 逻辑处理器 | 24 |
| ANSI 代码页 | 936 |
| 控制台代码页 | 65001 |
| 工作区路径 | 含中文 |

> [!IMPORTANT]
> 工作区路径含中文这一点很重要：它使 GDB 路线在本工作区不可用，
> 详见《01-编译器/02-环境配置.md》第 1.2 小节。
> 涉及 GDB 的结论若标为「实测数据」，都是在全英文路径下取得的，
> 文中会就近说明。

### 工具链

| 工具 | 版本 |
|---|---|
| gcc / g++ | 15.2.0（MinGW-w64） |
| GDB | 16.3（**只有 mingw32 目标**） |
| CMake | 4.4.3 |
| Ninja | 1.13.2 |
| MSVC cl.exe | 19.51（Visual Studio 生成工具 2026） |
| pwsh | 7.6.3 |

### 编辑器扩展

| 扩展 | 版本 |
|---|---|
| cpptools | 1.34.4 |
| CodeLLDB | 1.12.1 |

### 虚拟机与子系统

| 环境 | 版本 | 工具版本 |
|---|---|---|
| WSL Ubuntu | 24.04.5 | gcc 13.3.0、gdb 15.1、cmake 3.28.3、ninja 1.11.1 |
| Hyper-V 虚拟机 | Ubuntu 24.04.5 | 同上 |

虚拟机用 Ubuntu **云镜像**创建，不经过安装程序；
WSL 与虚拟机共用同一套调试与 SSH 流程，
详见《02-调试器/02-跨系统调试.md》。

### 怎么读这些数字

| 标注 | 含义 |
|---|---|
| 实测数据 | 在上述环境中**真的执行过**，输出可复现；给出的复现步骤能重跑 |
| 文档 | 来自官方文档、组件自身定义或权威资料 |
| 待确认 | 有合理推断但**未验证**，或依赖外部条件 |

**「实测数据」不代表「在所有环境下都成立」。**
例如 `sizeof(long)`，**在 Windows 上测是 4，在 Linux 上测就是 8**——
两个都是实测，差别来自平台而非编译器。
见《04-语法/02-数据类型与类型系统.md》第 2.6 小节。

**遇到与本文数字不符的情况，先核对上表**，
再检查是否有文中已说明的前提没有满足。
