# C/C++ 编译与调试教材

本教材面向**从零开始学 C/C++** 的读者，重点回答两类问题：

- **代码是怎样变成程序的**，以及为什么这个过程不能省略
- **程序出错时怎样查出原因**，而不只是靠打印

全部结论均经过实际验证，并标注了依据。

教材内容分**两条线**，用不同的编号体系区分：

## 全教材通用的约定

### 结论的标注方式

文中出现的结论分三类，均以文字标注：

| 标注 | 含义 |
|---|---|
| **实测** | 在编写环境中实际执行并验证过，输出可复现 |
| **文档** | 来源于官方文档、组件自身定义或权威资料 |
| **待确认** | 文中明确指出不确定之处，使用前需自行验证 |

### 路径的写法

教材面向任意一台 Windows 计算机，因此**不出现某一台机器的具体安装路径**。
文中一律使用下列占位符：

| 占位符 | 含义 | 常见形式 |
|---|---|---|
| `<MinGW>` | MinGW-w64 的安装目录 | `C:\mingw64` |
| `<CMake>` | CMake 的安装目录 | `C:\Program Files\CMake` |
| `<VS>` | Visual Studio 的安装目录 | `C:\Program Files\Microsoft Visual Studio\2022\Community` |
| `<版本号>` | 带版本号的目录中的那一段数字 | 如 `14.44.35207` |
| `<工作区>` | 你在 VS Code 中打开的文件夹 | 任意位置 |
| `<发行版名>` | WSL 发行版的名字 | `Ubuntu` |
| `<WSL地址>` | WSL 的虚拟网卡地址 | `192.168.x.x` |

**各程序的实际路径怎么找**：见[01-编译器/02-环境配置](01-编译器/02-环境配置.md)第 3 章。

### 引用文档的写法

文中引用其他文档时写作 `《01-编译器/01-编译与链接.md》`，
路径**相对于本教材的根目录**。

## 本教材的三个立足点

### 一、用真实代码讲，不用玩具代码

教材中的例子取自**实际运行的项目**，而不是为教学编写的片段。
真实代码里有历史包袱、平台差异、为绕开某个问题而写的怪代码——
**这些恰恰构成了实际开发的绝大部分难度**。

源文件收录在 [`A-教学素材/`](A-教学素材/)，可对照阅读。

### 二、说清「为什么」，不只给结论

例如：

- 不只说「要加 `-g`」，而是说明调试信息里存了什么、不加会怎样
- 不只说「任务要这样写」，而是说明为什么另一种写法会失败
- 不只说「用 `volatile`」，而是给出优化前后的汇编对照

### 三、区分「实测」与「文档」

教材中的每个技术结论都标明了依据。
凡未实际验证的，一律注明「待确认」，不冒充已验证的事实。
