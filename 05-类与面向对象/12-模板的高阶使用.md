# 第 1 节 可变参数模板

## 1.1 参数包

有一类函数的参数个数不确定：把一串值打印出来、把若干个值加起来、
用若干个参数构造一个对象。重载能应付有限几种：

`C++`

```cpp
void print(int a);
void print(int a, int b);
void print(int a, int b, int c);      /* 个数是无限的，代码是有限的 */
```

这条路走不通的原因很直接：**参数个数没有上限，而函数要一个一个写出来**。
C++11 起有了参数包，一个模板就能收下任意多个参数：

`C++`

```cpp
template <class... Ts>                 /* Ts 是模板参数包：装 0 个或更多类型 */
void print_all(const Ts &... args);    /* args 是函数参数包：装 0 个或更多参数 */
```

两处省略号的位置不同，含义也不同：

| 写法 | 名称 | 装什么 |
|---|---|---|
| `class... Ts` | 模板参数包 | 类型，可以是 0 个 |
| `const Ts &... args` | 函数参数包 | 参数，个数与 `Ts` 一致 |

`class... Ts` 与 `typename... Ts` 完全等价，写哪个都可以。

**包不是一个容器**：拿不到 `args[0]`，也没法用下标遍历它。
包里有多少个元素，编译期就知道，取用它们只有一条路——**展开**（pack expansion）。

> [!IMPORTANT]
> **参数包的名字本身用不了，能用的只有它的展开形式。**
> 后面两小节给出两种展开办法：先递归拆，再用折叠表达式一次写完。

`文档`

> "A template parameter pack is a template parameter that accepts zero or more template
> arguments."
>
> —— N4659 §17.5.3/1
>
> "A function parameter pack is a function parameter that accepts zero or more function
> arguments."
>
> —— N4659 §17.5.3/2

## 1.2 先看递归写法：每次拆掉一个

C++17 之前没有折叠表达式，展开只能靠递归：
一次从包里取走第一个参数，把剩下的包再传给自己，直到包空。

`C++`

```cpp
/* variadic_rec.cpp    编译：g++ -std=c++17 variadic_rec.cpp -o variadic_rec */
#include <cstdio>
#include <string>

/* 打印一件东西：按类型选一个重载 */
void show(int v)                { std::printf("%d", v); }
void show(double v)             { std::printf("%.1f", v); }
void show(const char *v)        { std::printf("%s", v); }
void show(const std::string &v) { std::printf("%s", v.c_str()); }

void print_all() { std::printf("\n"); }        /* 递归终点：包里一个参数都不剩 */

template <class T, class... Rest>              /* Rest 是参数包，可以装 0 个参数 */
void print_all(const T &first, const Rest &... rest) {
    show(first);
    if (sizeof...(rest) > 0) std::printf(", ");
    print_all(rest...);                        /* 把剩下的再摊开一次 */
}

int main() {
    print_all(1, 2.5, "三", std::string("四"));
    print_all(42);
    print_all();
    return 0;
}
```

`实测数据`
`Text`

```text
1, 2.5, 三, 四
42

```

（第三行是一次空输出：`print_all()` 一个参数都不给，直接落到那个非模板的重载上。）

这个写法有三个要点：

| 要点 | 说明 |
|---|---|
| **递归终点是一个普通函数** | 包里没有参数时，`print_all()` 只能匹配那个不带模板参数的重载；没有它，模板会一直以空包匹配下去 |
| **`print_all(rest...)` 传下去的是包** | 每一次递归，参数个数少一个，编译器为每个个数生成一份实例 |
| **`sizeof...(rest)` 用来判断要不要分隔符** | 它是编译期常量，不是运行期判断 |

代价是：一个参数的包要实例化两层（带参的模板 + 终点），
参数越多实例化层数越多，报错也会顺着这条实例化链一层层打印出来（《05-类与面向对象/11-模板.md》第 8.3 小节）。

## 1.3 折叠表达式：一次写完

C++17 起，展开可以直接写在一个表达式里：

`C++`

```cpp
/* variadic_fold.cpp    编译：g++ -std=c++17 variadic_fold.cpp -o variadic_fold */
#include <cstdio>
#include <string>

void show(int v)                { std::printf("%d", v); }
void show(double v)             { std::printf("%.1f", v); }
void show(const char *v)        { std::printf("%s", v); }
void show(const std::string &v) { std::printf("%s", v.c_str()); }

template <class... Args>
void print_all(const Args &... args) {
    bool first = true;
    auto sep = [&first] { if (!first) std::printf(", "); first = false; };
    ((sep(), show(args)), ...);                /* 一元左折：对包里每个元素做一遍 */
    std::printf("   （共 %zu 个参数）\n", sizeof...(args));
}

int main() {
    print_all(1, 2.5, "三", std::string("四"));
    print_all(42);
    print_all();
    return 0;
}
```

`实测数据`
`Text`

```text
1, 2.5, 三, 四   （共 4 个参数）
42   （共 1 个参数）
   （共 0 个参数）
```

同一件事、同样的输出（每行末尾多出参数个数），不再需要递归终点，也不再需要为每个参数个数生成一层实例。

`((sep(), show(args)), ...)` 由两部分组成，分清楚它们各自的边界很重要：

| 部分 | 是什么 |
|---|---|
| `(sep(), show(args))` | **模式**：包里每个元素都要套一遍的表达式 |
| `, ...` | **折叠**：把模式在包上展开，元素之间用逗号连起来 |

四个参数时它展开成 `(sep(), show(a1)), (sep(), show(a2)), (sep(), show(a3)), (sep(), show(a4))`，
逗号保证从左到右依次执行。而空包也成立——逗号在空包时有定义（第 2.3 小节）。

`文档`

> "A fold expression performs a fold of a template parameter pack (17.5.3) over a binary
> operator."
>
> —— N4659 §8.1.6/1

> [!TIP]
> **新写的代码用折叠表达式，看到旧代码里的递归写法要能读。**
> C++11/14 的库与工程里递归拆包很常见，读法是「一次取走一个，剩下的再传给自己」；
> 折叠表达式只是把这件事压缩成一行，展开后的语义与递归写法一致。

## 1.4 `sizeof...`：包里有多少个

`sizeof...(args)` 给出包里元素的个数。它与 `sizeof` 不是一回事：
`sizeof` 问「占多少字节」，`sizeof...(args)` 数「有几个」。

`C++`

```cpp
/* sizeof_pack.cpp    编译：g++ -std=c++17 sizeof_pack.cpp -o sizeof_pack */
#include <cstdio>

template <class... T>
void show_count(const T &... v) {
    int arr[sizeof...(v) + 1];                     /* 能当数组长度：它是编译期常量 */
    arr[0] = 0;
    std::printf("%zu 个参数，数组有 %zu 个元素\n",
                sizeof...(v), sizeof(arr) / sizeof(arr[0]));
}

int main() {
    show_count();
    show_count(1);
    show_count(1, 2.5, "三");
    return 0;
}
```

`实测数据`
`Text`

```text
0 个参数，数组有 1 个元素
1 个参数，数组有 2 个元素
3 个参数，数组有 4 个元素
```

第一行是关键：**空包时 `sizeof...` 是 0，而不是编不过**。
能当数组长度说明它是整数常量表达式，编译期就算完了。

`文档`

> "The identifier in a sizeof... expression shall name a parameter pack. The sizeof...
> operator yields the number of arguments provided for the parameter pack identifier."
>
> —— N4659 §8.3.3/5

`sizeof...(args)` 只数个数，不读取任何一个参数的值；
包里的元素是不是能用（比如能不能拷贝），它管不着。

> [!NOTE]
> **第 1 节小结**：参数包收下不定个数的参数；包只能用展开的形式取用；
> C++17 之前靠递归一次拆一个，C++17 起用折叠表达式一次写完；
> `sizeof...(包名)` 给出个数，是编译期常量，空包时为 0。

# 第 2 节 折叠表达式的四种形式

## 2.1 左折与右折

折叠表达式有四种写法，区别在省略号的位置：

| 名称 | 写法 | 展开成 | 有初值吗 |
|---|---|---|---|
| 一元左折 | `(... op e)` | `((e1 op e2) op e3) ...` | 没有 |
| 一元右折 | `(e op ...)` | `e1 op (e2 op (... op eN))` | 没有 |
| 二元左折 | `(e1 op ... op e2)` | `(((E op e1) op e2) ...)` | 有，`E` 在最左边 |
| 二元右折 | `(e1 op ... op e2)` | `e1 op (... op (eN op E))` | 有，`E` 在最右边 |

「一元」指只有包参与，「二元」指除了包还有一个初值。
两种二元写法的形式上完全一样，**哪个是初值由「谁不含参数包」决定**：
`e1` 不含包时它是初值，`e2` 不含包时初值在右边。

`文档`

> "An expression of the form (... op e) where op is a fold-operator is called a unary left
> fold. An expression of the form (e op ...) where op is a fold-operator is called a unary
> right fold. ... In a unary fold, the cast-expression shall contain an unexpanded
> parameter pack (17.5.3)."
>
> —— N4659 §8.1.6/2
>
> "An expression of the form (e1 op1 ... op2 e2) where op1 and op2 are fold-operators is
> called a binary fold. In a binary fold, op1 and op2 shall be the same fold-operator, and
> either e1 shall contain an unexpanded parameter pack or e2 shall contain an unexpanded
> parameter pack, but not both. If e2 contains an unexpanded parameter pack, the
> expression is called a binary left fold. If e1 contains an unexpanded parameter pack,
> the expression is called a binary right fold."
>
> —— N4659 §8.1.6/3

最后一句是一条硬性限制：**两个操作数不能都含参数包**。
`(args + ... + args)` 编不过，标准里给的正是这个反例。

## 2.2 结合方向什么时候看得出来

对加法这类可交换的运算，左折右折结果一样，看不出区别。
换一个不可交换的运算符，区别立刻显出来：

`C++`

```cpp
/* fold_forms.cpp    编译：g++ -std=c++17 fold_forms.cpp -o fold_forms */
#include <cstdio>

/* 运算符用减法：结合方向不同，结果就不同 */
template <class... T> int unary_left(T... v)   { return (... - v); }       /* ( ... op e ) */
template <class... T> int unary_right(T... v)  { return (v - ...); }       /* ( e op ... ) */
template <class... T> int binary_left(T... v)  { return (0 - ... - v); }   /* ( e1 op ... op e2 ) */
template <class... T> int binary_right(T... v) { return (v - ... - 0); }   /* ( e1 op ... op e2 ) */

int main() {
    std::printf("(... - v)     = %d\n", unary_left(10, 3, 2, 1));
    std::printf("(v - ...)     = %d\n", unary_right(10, 3, 2, 1));
    std::printf("(0 - ... - v) = %d\n", binary_left(10, 3, 2, 1));
    std::printf("(v - ... - 0) = %d\n", binary_right(10, 3, 2, 1));
    return 0;
}
```

`实测数据`
`Text`

```text
(... - v)     = 4
(v - ...)     = 8
(0 - ... - v) = -16
(v - ... - 0) = 8
```

四个数字对应四种展开方式，逐个对一遍：

| 写法 | 展开 | 结果 |
|---|---|---|
| `(... - v)` | `((10 - 3) - 2) - 1` | `4` |
| `(v - ...)` | `10 - (3 - (2 - 1))` | `8` |
| `(0 - ... - v)` | `(((0 - 10) - 3) - 2) - 1` | `-16` |
| `(v - ... - 0)` | `10 - (3 - (2 - (1 - 0)))` | `8` |

第三行说明初值不是「补一个元素」那么简单：它在最左边，参与了每一次减法。
**写二元折叠时，初值放在哪一侧、运算是从左还是从右结合，两件事都要想清楚。**

## 2.3 空参数包：一元折叠编不过，二元折叠有初值

包里的元素个数可以是 0，这时一元折叠没有可用的值：

`C++`

```cpp
/* fold_empty_fail.cpp    编译：g++ -std=c++17 fold_empty_fail.cpp -o fold_empty_fail （失败） */
#include <cstdio>

template <class... T>
int sum_all(T... v) { return (... + v); }      /* 一元左折：没有初值 */

int main() {
    std::printf("%d\n", sum_all());            /* 空包：加号不在空展开有定义的运算符表里 */
    return 0;
}
```

`实测数据`
`Text`

```text
fold_empty_fail.cpp: In instantiation of 'int sum_all(T ...) [with T = {}]':
fold_empty_fail.cpp:8:32:   required from here
fold_empty_fail.cpp:5:35: error: fold of empty expansion over operator+
```

改法有两条：给一个初值（二元折叠），或者换一个空包时有定义的运算符。

`C++`

```cpp
/* fold_empty_ok.cpp    编译：g++ -std=c++17 fold_empty_ok.cpp -o fold_empty_ok */
#include <cstdio>

template <class... T>
int sum_all(T... v) { return (0 + ... + v); }   /* 二元左折：0 就是空包时的取值 */

template <class... T>
bool all_true(T... v) { return (... && v); }    /* 一元左折：&& 在空包时有定义 */

int main() {
    std::printf("sum_all()            = %d\n", sum_all());
    std::printf("sum_all(1, 2, 3)     = %d\n", sum_all(1, 2, 3));
    std::printf("all_true()           = %d\n", (int)all_true());
    std::printf("all_true(true, true) = %d\n", (int)all_true(true, true));
    std::printf("all_true(true,false) = %d\n", (int)all_true(true, false));
    return 0;
}
```

`实测数据`
`Text`

```text
sum_all()            = 0
sum_all(1, 2, 3)     = 6
all_true()           = 1
all_true(true, true) = 1
all_true(true,false) = 0
```

标准只给三个运算符定义了空包时的值，其余的一律编不过：

`文档`

> "If N is zero for a unary fold-expression, the value of the expression is shown in
> Table 14; if the operator is not listed in Table 14, the instantiation is ill-formed."
>
> —— N4659 §17.5.3/9

Table 14 只有三行：

| 运算符 | 空参数包时的值 |
|---|---|
| `&&` | `true` |
| `\|\|` | `false` |
| `,` | `void()` |

> [!WARNING]
> **`0 + ... + v` 与 `... + v` 的差别只在空包时暴露出来**：
> 后者一旦被用空包实例化就是编译错误，而前者安静地返回 `0`。
> 一个模板要不要支持空包，写的时候就要定下来，不能让调用方去试。

## 2.4 能用的运算符与两个常用写法

折叠表达式能用的运算符就是二元运算符那一批，包括赋值与复合赋值：

`文档`

> "fold-operator: one of
> + - * / % ^ & \| << >>
> += -= *= /= %= ^= &= \|= <<= >>= =
> == != < > <= >= && \|\| , .* ->*"
>
> —— N4659 §8.1.6/1

两个常见的用法：把一串值拼起来，以及判断「全部都满足」。

`C++`

```cpp
/* fold_ops.cpp    编译：g++ -std=c++17 fold_ops.cpp -o fold_ops */
#include <cstdio>
#include <string>

template <class... T>
std::string join(T... v) { return (std::string() + ... + v); }   /* 二元左折 */

template <class... T>
bool all_positive(T... v) { return (... && (v > 0)); }

int main() {
    std::printf("join：%s\n", join("a", "-", "b", "-", "c").c_str());
    std::printf("all_positive(1,2,3)  = %d\n", (int)all_positive(1, 2, 3));
    std::printf("all_positive(1,-2,3) = %d\n", (int)all_positive(1, -2, 3));
    std::printf("all_positive()       = %d\n", (int)all_positive());
    return 0;
}
```

`实测数据`
`Text`

```text
join：a-b-c
all_positive(1,2,3)  = 1
all_positive(1,-2,3) = 0
all_positive()       = 1
```

`join` 的初值 `std::string()` 不能省：第一个参数是 `const char *`，
几个指针相加不是拼接，而是编译错误。初值把类型定成 `std::string`，
后面的 `+` 才走字符串拼接。

`all_positive()` 返回 `1` 是 Table 14 的直接后果：空包时 `&&` 为 `true`，
「全部都大于 0」在没有元素时成立。这正是它该有的语义。

> [!NOTE]
> **第 2 节小结**：四种形式由省略号的位置区分；一元折叠没有初值，
> 空包时只有 `&&`、`||`、`,` 合法，其余编不过；
> 二元折叠把初值放在包的外侧，`0 + ... + v` 这类写法可以安全接受空包。

# 第 3 节 `if constexpr`

`if constexpr` 这个写法本身在《04-语法/12-编译期能力.md》第 5 节已经出现过，
那里给的是最小例子。本节要说的是它在模板里管什么用。

## 3.1 普通 `if` 为什么不行

按类型给不同的实现，最自然的写法是普通 `if`：

`C++`

```cpp
/* dispatch_if.cpp    编译：g++ -std=c++17 dispatch_if.cpp -o dispatch_if （失败） */
#include <cstdio>
#include <string>
#include <type_traits>

template <class T>
void describe(const T &v) {
    if (std::is_arithmetic<T>::value) {
        std::printf("数字：%s\n", std::to_string(v).c_str());
    } else {
        std::printf("其他：%s\n", v.c_str());
    }
}

int main() {
    describe(42);
    describe(std::string("文本"));
    return 0;
}
```

两处调用分别编不过（下面是节选）：

`实测数据`
`Text`

```text
dispatch_if.cpp: In instantiation of 'void describe(const T&) [with T = int]':
dispatch_if.cpp:16:13:   required from here
dispatch_if.cpp:11:37: error: request for member 'c_str' in 'v', which is of non-class type 'const int'
dispatch_if.cpp: In instantiation of 'void describe(const T&) [with T = std::__cxx11::basic_string<char>]':
dispatch_if.cpp:17:13:   required from here
dispatch_if.cpp:9:49: error: no matching function for call to 'to_string(const std::__cxx11::basic_string<char>&)'
dispatch_if.cpp:9:49: note: there are 9 candidates
```

`T = int` 时，`else` 分支里的 `v.c_str()` 编不过；
`T = std::string` 时，`if` 分支里的 `std::to_string(v)` 编不过。
**两个分支对每一种 `T` 都要合法，而这两件事不可能同时成立。**

这条规则不是模板带来的：一个普通函数里的 `if`，两个分支也都要能编过，
因为类型检查在编译期做，而运行期走哪个分支那时还不知道。
模板让这件事变得致命——**每一份实例化都必须整份合法**。

## 3.2 只编被选中的那个分支

把 `if` 换成 `if constexpr`，条件成立与否在编译期就定下来，只有一个分支会被实例化：

`C++`

```cpp
/* dispatch_constexpr.cpp    编译：g++ -std=c++17 dispatch_constexpr.cpp -o dispatch_constexpr */
#include <cstdio>
#include <string>
#include <type_traits>

template <class T>
void describe(const T &v) {
    if constexpr (std::is_arithmetic<T>::value) {
        std::printf("数字：%s\n", std::to_string(v).c_str());
    } else {
        std::printf("其他：%s\n", v.c_str());
    }
}

int main() {
    describe(42);
    describe(2.5);
    describe(std::string("文本"));
    return 0;
}
```

`实测数据`
`Text`

```text
数字：42
数字：2.500000
其他：文本
```

同一份源码，只改了一个关键字，从两处硬错误变成正常输出。
`T = int` 时 `else` 分支整段被丢弃，`v.c_str()` 根本不会被检查。

`文档`

> "If the if statement is of the form if constexpr, the value of the condition shall be a
> contextually converted constant expression of type bool (8.20); this form is called a
> constexpr if statement. If the value of the converted condition is false, the first
> substatement is a discarded statement, otherwise the second substatement, if present,
> is a discarded statement. During the instantation of an enclosing templated entity
> (Clause 17), if the condition is not value-dependent after its instantiation, the
> discarded substatement (if any) is not instantiated."
>
> —— N4659 §9.4.1/2

（原文里 `instantation` 是草案本身的拼写。）

## 3.3 被丢弃的分支里能写什么

「不实例化」的含义比「不执行」强得多：被丢弃的那一整段，
只要语法上能过、用到的名字能找到，里面的表达式成不成立都不再过问。

`C++`

```cpp
/* discard_branch.cpp    编译：g++ -std=c++17 discard_branch.cpp -o discard_branch */
#include <cstdio>
#include <type_traits>

template <class T>
void check(T v) {
    if constexpr (std::is_integral<T>::value) {
        std::printf("整数：%lld\n", (long long)v);
    } else {
        /* 这一行只对非整数类型实例化；对 int 实例化时整段被丢弃 */
        static_assert(sizeof(T) == 0, "丢弃的分支不会被求值");
        std::printf("不是整数\n");
    }
}

int main() {
    check(42);
    check(7u);
    return 0;
}
```

`实测数据`
`Text`

```text
整数：42
整数：7
```

`sizeof(T) == 0` 对任何类型都不成立，这个 `static_assert` 只要被求值就一定失败。
两次调用都没事，说明它对 `int` 和 `unsigned` 根本没参与实例化。

两条边界要记住：

| 边界 | 说明 |
|---|---|
| **丢弃的分支仍要通得过语法检查** | 括号、分号、明显写错的名字一样会报错；只是模板相关的实例化不再发生 |
| **不依赖模板参数的名字必须能找到** | 模板里非依赖名的查找在定义时进行（《05-类与面向对象/11-模板.md》第 5.4 小节），与分支选哪边无关 |

标准对「不实例化」给的范围是 odr-use：

`文档`

> "[Note: Odr-uses (6.2) in a discarded statement do not require an entity to be defined.
> —end note]"
>
> —— N4659 §9.4.1/2

## 3.4 三条限制

**第一，条件必须是常量表达式。** `if constexpr` 的条件在编译期求值，
拿一个运行期变量当条件，编译直接失败：

`C++`

```cpp
/* if_constexpr_cond_fail.cpp    编译：g++ -std=c++17 if_constexpr_cond_fail.cpp -o if_constexpr_cond_fail （失败） */
int main() {
    int n = 3;
    if constexpr (n > 0) {          /* n 是运行期变量 */
        return 1;
    }
    return 0;
}
```

`实测数据`
`Text`

```text
if_constexpr_cond_fail.cpp:4:19: error: the value of 'n' is not usable in a constant expression
if_constexpr_cond_fail.cpp:3:9: note: 'int n' is not const
```

**第二，丢弃的分支不生成代码，也不代表「运行期两选一」。**
需要按运行期的值分支，仍然用普通 `if`。
两个关键字解决的是两个问题：`if constexpr` 管类型不同带来的实现差异，`if` 管运行期的数据差异。

**第三，它只解决「所有分支都要对同一个类型合法」这一类问题，条件本身仍要写得出来。**
判断用的工具仍然是
`std::is_integral`、`std::is_pointer` 这一族 trait（第 4.5 小节会自己写一个）。

> [!NOTE]
> **第 3 节小结**：普通 `if` 的两个分支对每一种实例化都要合法，
> 按类型分派因此编不过；`if constexpr` 只实例化被选中的分支，
> 被丢弃的分支连 `static_assert` 都不会求值。
> 条件是编译期常量，运行期的分支仍然用普通 `if`。

# 第 4 节 SFINAE 与 `enable_if`

## 4.1 替换失败不是错误

模板参与重载决议（《05-类与面向对象/11-模板.md》第 7 节）时，编译器先做一件事：**把实参类型代进模板参数**（替换，substitution），
得到一份具体的函数签名。如果替换过程中写出了非法的类型或表达式，
这个候选就被丢掉，决议继续在剩下的候选里进行——这就是 SFINAE
（Substitution Failure Is Not An Error，替换失败不是错误）。

关键在于失败的时机：**替换阶段失败是「这个候选不合适」，函数体里失败是「程序错了」**。
前者静默出局，后者是一堵报错墙。

`文档`

> "If a substitution results in an invalid type or expression, type deduction fails. An
> invalid type or expression is one that would be ill-formed, with a diagnostic required,
> if written using the substituted arguments. [Note: If no diagnostic is required, the
> program is still ill-formed. Access checking is done as part of the substitution
> process. —end note] Only invalid types and expressions in the immediate context of the
> function type and its template parameter types can result in a deduction failure. [Note:
> The substitution into types and expressions can result in effects such as the
> instantiation of class template specializations and/or function template
> specializations, the generation of implicitly-defined functions, etc. Such effects are
> not in the "immediate context" and can result in the program being ill-formed. —end
> note]"
>
> —— N4659 §17.8.2/8

「immediate context（直接上下文）」这个词划出了范围：
替换时写坏的类型与表达式算，替换引发的类模板实例化里的错误不算。
所以 SFINAE 要生效，**失败必须发生在签名上，不能发生在函数体里**。

`文档`

> "However, if the template-id is dependent, subsequent template argument substitution
> still applies to the template-id. [Example:
> template<typename...> using void_t = void;
> template<typename T> void_t<typename T::foo> f();
> f<int>(); // error, int does not have a nested type foo
> —end example]"
>
> —— N4659 §17.5.7/3

## 4.2 用 `void_t` 写出「有这个成员才参与重载」

C++17 起，把这件事写成一行有一个现成的工具：`std::void_t`。

它本身什么都不算，只是把这些类型参数原样吞掉、结果固定是 `void`：

`文档`

> "template <class...>
> using void_t = void;"
>
> —— N4659 §23.15.2

用处在于：**要写出 `void_t<X>` 这个实参，必须先把 `X` 算出来**，
而 `X` 里可以放一个「只有类型满足条件时才成立」的表达式。
把它放在模板参数的默认实参上，表达式不成立时，替换就失败，
这个候选自动出局：

`C++`

```cpp
/* sfinae_fallback.cpp    编译：g++ -std=c++17 sfinae_fallback.cpp -o sfinae_fallback */
#include <cstdio>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

/* 只有「能写出 .size()」的类型，这个重载才存在 */
template <class T, class = std::void_t<decltype(std::declval<const T &>().size())>>
std::size_t size_of(const T &c) { return c.size(); }

/* 兜底版本：什么都收，但转换序列最差，只在上面那个不成立时才会被选中 */
std::size_t size_of(...) { return 0; }

int main() {
    std::vector<int> v{1, 2, 3};
    std::string s = "abcd";
    std::printf("vector：%zu\n", size_of(v));
    std::printf("string：%zu\n", size_of(s));
    std::printf("int   ：%zu（走兜底版本）\n", size_of(42));
    return 0;
}
```

`实测数据`
`Text`

```text
vector：3
string：4
int   ：0（走兜底版本）
```

三个调用各走了一条路：

| 调用 | 发生了什么 |
|---|---|
| `size_of(v)` | `std::vector<int>` 有 `size()`，替换成功，模板被选中 |
| `size_of(s)` | `std::string` 有 `size()`，同样走模板 |
| `size_of(42)` | `int` 没有 `size()`，`void_t<...>` 里的表达式非法，替换失败，模板出局；只剩下接受任意参数的兜底版本 |

`std::declval<const T &>()` 是「造一个这种类型的值」的写法，只用在
`decltype` 这类不求值的场合，因此不需要类型可构造。

## 4.3 两种报错的对照

把兜底版本去掉，用 `int` 去调用，报错是**「没有匹配的函数」**（下面是节选）：

`C++`

```cpp
/* sfinae_nomatch.cpp    编译：g++ -std=c++17 sfinae_nomatch.cpp -o sfinae_nomatch （失败） */
#include <cstdio>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

/* 只有「能写出 .size()」的类型，这个重载才存在 */
template <class T, class = std::void_t<decltype(std::declval<const T &>().size())>>
std::size_t size_of(const T &c) { return c.size(); }

int main() {
    return (int)size_of(42);       /* 替换失败：这个重载被移出候选集，于是没有匹配的函数 */
}
```

`实测数据`
`Text`

```text
sfinae_nomatch.cpp:13:24: error: no matching function for call to 'size_of(int)'
sfinae_nomatch.cpp:13:24: note: there is 1 candidate
sfinae_nomatch.cpp:10:13: note: candidate 1: 'template<class T, class> std::size_t size_of(const T&)'
sfinae_nomatch.cpp:10:13: note: template argument deduction/substitution failed:
sfinae_nomatch.cpp:9:75: error: request for member 'size' in 'std::declval<const int&>()', which is of non-class type 'const int'
```

错误落在**签名那一行**（第 9 行，模板参数的默认实参），
并且明确指出「template argument deduction/substitution failed」。

同样的调用，不写 SFINAE、把 `.size()` 直接放进函数体，报错是硬错误（下面是节选）：

`C++`

```cpp
/* sfinae_hard.cpp    编译：g++ -std=c++17 sfinae_hard.cpp -o sfinae_hard （失败） */
#include <cstdio>

/* 没有 SFINAE：.size() 直接写在函数体里，函数体是替换之后才实例化的 */
template <class T>
std::size_t size_of(const T &c) { return c.size(); }

int main() {
    return (int)size_of(42);       /* 硬错误：实例化出来的函数体编不过 */
}
```

`实测数据`
`Text`

```text
sfinae_hard.cpp: In instantiation of 'std::size_t size_of(const T&) [with T = int; std::size_t = long long unsigned int]':
sfinae_hard.cpp:9:24:   required from here
sfinae_hard.cpp:6:44: error: request for member 'size' in 'c', which is of non-class type 'const int'
```

两者的差别不只是措辞：

| | 替换失败（第 4.2 小节） | 函数体里失败（本小节） |
|---|---|---|
| 报错首行 | `no matching function for call to ...` | `In instantiation of ...` |
| 出错的时机 | 挑候选的时候 | 候选已经选定、开始实例化的时候 |
| 其他重载还有机会吗 | **有**，决议继续 | **没有**，程序已经错了 |
| 报错规模 | 12 行 | 7 行（还会随调用层数增长） |

**这是 SFINAE 存在的全部理由**：不是为了报错好看，
而是为了让「这个类型不合适」变成一次安静的落选，把机会留给别的重载。

## 4.4 `enable_if`：按类型性质分流重载

`std::enable_if` 是标准库为这件事准备的另一个工具。
它是一个类模板，一个参数为真时才有成员 `type`：

`文档`

> "template <bool B, class T = void> struct enable_if;
> If B is true, the member typedef type shall equal T; otherwise, there shall be no
> member type."
>
> —— N4659 §23.15.7.6 Table 50

「没有成员 `type`」意味着写 `typename std::enable_if<false, T>::type` 时替换失败。
把这个写法放在返回类型上，两个同名模板就能各管一片类型：

`C++`

```cpp
/* enable_if_dispatch.cpp    编译：g++ -std=c++17 enable_if_dispatch.cpp -o enable_if_dispatch */
#include <cstdio>
#include <string>
#include <type_traits>

template <class T>
typename std::enable_if<std::is_integral<T>::value, std::string>::type
describe(T v) { return "整数 " + std::to_string(v); }

template <class T>
typename std::enable_if<std::is_floating_point<T>::value, std::string>::type
describe(T v) { return "浮点 " + std::to_string(v); }

int main() {
    std::printf("%s\n", describe(42).c_str());
    std::printf("%s\n", describe(2.5).c_str());
    return 0;
}
```

`实测数据`
`Text`

```text
整数 42
浮点 2.500000
```

一个调用只能让其中一个重载的替换成功，二义不会发生。
换成两个都不成立的类型，报错仍然是「没有匹配的函数」：

`C++`

```cpp
/* enable_if_nomatch.cpp    编译：g++ -std=c++17 enable_if_nomatch.cpp -o enable_if_nomatch （失败） */
#include <cstdio>
#include <string>
#include <type_traits>

template <class T>
typename std::enable_if<std::is_integral<T>::value, std::string>::type
describe(T v) { return "整数 " + std::to_string(v); }

template <class T>
typename std::enable_if<std::is_floating_point<T>::value, std::string>::type
describe(T v) { return "浮点 " + std::to_string(v); }

int main() {
    return (int)describe(std::string("文本")).size();   /* 两个重载都不成立 */
}
```

`实测数据`
`Text`

```text
enable_if_nomatch.cpp:15:25: error: no matching function for call to 'describe(std::string)'
enable_if_nomatch.cpp:15:25: note: there are 2 candidates
enable_if_nomatch.cpp:8:1: note: candidate 1: 'template<class T> typename std::enable_if<std::is_integral<_Tp>::value, std::__cxx11::basic_string<char> >::type describe(T)'
enable_if_nomatch.cpp:8:1: note: template argument deduction/substitution failed:
```

`enable_if` 也能写成模板参数的默认实参（`class = typename std::enable_if<...>::type`），
效果一样。两种放法各有各的麻烦：放返回类型上，签名变得很长；
放模板参数上，同一个函数的两份声明容易写得不像同一个函数。

## 4.5 把这件事写成一个 trait

`void_t` 与类模板偏特化（《05-类与面向对象/11-模板.md》第 6.2 小节）配合，可以把「有没有这个成员」
变成一个能当条件用的编译期布尔值：

`C++`

```cpp
/* has_size.cpp    编译：g++ -std=c++17 has_size.cpp -o has_size */
#include <cstdio>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

template <class T, class = void>
struct has_size : std::false_type {};          /* 默认：没有 size() */

template <class T>
struct has_size<T, std::void_t<decltype(std::declval<const T &>().size())>>
    : std::true_type {};                       /* 偏特化：能写出 .size() 才落到这一份 */

struct Empty {};

int main() {
    std::printf("has_size<std::vector<int>> = %d\n", (int)has_size<std::vector<int>>::value);
    std::printf("has_size<std::string>      = %d\n", (int)has_size<std::string>::value);
    std::printf("has_size<int>              = %d\n", (int)has_size<int>::value);
    std::printf("has_size<Empty>            = %d\n", (int)has_size<Empty>::value);
    return 0;
}
```

`实测数据`
`Text`

```text
has_size<std::vector<int>> = 1
has_size<std::string>      = 1
has_size<int>              = 0
has_size<Empty>            = 0
```

写法的关键是两个模板参数的配合：主模板的第二个参数有默认值 `void`，
偏特化只在 `void_t<...>` 能算出来时匹配上。
算不出来就退回主模板，于是得到 `false`。

标准库里 `std::is_integral`、`std::is_pointer` 这一族
（`<type_traits>`，《06-标准库/B-09-工具类（下）：type_traits 与 concepts.md》章节）用的就是这套办法，
只是它们针对的性质由标准规定，不必自己写。

## 4.6 代价

SFINAE 能让重载决议精确到「类型满足什么条件」，代价有三条：

| 代价 | 表现 |
|---|---|
| **写法绕** | 一个条件要写成 `class = std::void_t<decltype(std::declval<const T &>().size())>`，读的人要逐层拆开 |
| **报错长** | 失败信息落在默认实参、返回类型这些不显眼的位置，`enable_if<false, T>` 那行还会把 `_Tp` 之类的内部名字带出来（第 4.4 小节实测） |
| **条件没有名字** | 同一个条件在几处用到就要抄几遍，抄漏一处不会报错，只会让某个重载悄悄不参与 |

第 5 节的做法把这些代价一次性解决：给条件起个名字，写在参数表上。

> [!NOTE]
> **第 4 节小结**：模板实参替换时写坏了类型或表达式，这个候选安静出局，
> 决议继续——这就是 SFINAE，也是「没有匹配的函数」这个报错的来源。
> `void_t` 把「某个表达式成立吗」变成替换是否成功，
> `enable_if` 把「某个条件成立吗」变成有没有成员 `type`；
> 失败必须发生在签名上，写进函数体就是硬错误。

# 第 5 节 概念与约束（C++20）

> [!WARNING]
> **本节内容是 C++20 起才有的，超出本教材的 C++17 基准。**
> 用 `-std=c++20` 编译。本节引用的规则来自 C++20 标准，本教材以 C++17 草案

## 5.1 `requires` 表达式与 `concept`

第 4 节那些条件，在 C++20 里可以写成一句能读的话：

`C++`

```cpp
/* concepts_basic.cpp    编译：g++ -std=c++20 concepts_basic.cpp -o concepts_basic */
#include <concepts>
#include <cstdio>
#include <string>

template <class T>
concept Addable = requires(T a, T b) {          /* 简单要求：a + b 能写出来 */
    { a + b } -> std::convertible_to<T>;        /* 复合要求：结果还要能转回 T */
};

struct NoAdd { int v; };

template <Addable T>
T add_twice(T a, T b) { return a + b; }

void show(Addable auto v) { std::printf("show 收到 %d\n", (int)v); }   /* 简写形式 */

int main() {
    std::printf("Addable<int>         = %d\n", (int)Addable<int>);
    std::printf("Addable<std::string> = %d\n", (int)Addable<std::string>);
    std::printf("Addable<NoAdd>       = %d\n", (int)Addable<NoAdd>);
    std::printf("add_twice(3, 4)      = %d\n", add_twice(3, 4));
    std::printf("add_twice(\"a\", \"b\")  = %s\n",
                add_twice(std::string("a"), std::string("b")).c_str());
    show(9);
    return 0;
}
```

`实测数据`
`Text`

```text
Addable<int>         = 1
Addable<std::string> = 1
Addable<NoAdd>       = 0
add_twice(3, 4)      = 7
add_twice("a", "b")  = ab
show 收到 9
```

三件事在这段代码里各就各位：

| 写法 | 是什么 |
|---|---|
| `requires(T a, T b) { ... }` | **requires 表达式**：一串「这样写成立吗」的要求，结果是一个 `bool` |
| `concept Addable = ...` | **概念**：给这组要求起一个名字 |
| `template <Addable T>` / `Addable auto` | **约束**：把这个名字写在模板参数或参数上 |

要求可以写四种，都可以叠在同一个 requires 表达式里：

`C++`

```cpp
/* concepts_req_forms.cpp    编译：g++ -std=c++20 concepts_req_forms.cpp -o concepts_req_forms */
#include <concepts>
#include <cstdio>
#include <string>
#include <vector>

/* 四种要求写在一个概念里 */
template <class T>
concept Container = requires(T c, const T &cc) {
    typename T::value_type;                        /* 类型要求：有个成员类型 value_type */
    c.size();                                      /* 简单要求：这个表达式能写出来 */
    c.begin();                                     /* 简单要求 */
    { cc.size() } -> std::convertible_to<std::size_t>;   /* 复合要求：结果能转成 size_t */
    requires std::same_as<typename T::value_type, int>;  /* 嵌套要求：另一个概念也成立 */
};

template <Container T>
std::size_t count_of(const T &c) { return c.size(); }

int main() {
    std::printf("Container<std::vector<int>>    = %d\n", (int)Container<std::vector<int>>);
    std::printf("Container<std::vector<double>> = %d\n", (int)Container<std::vector<double>>);
    std::printf("Container<std::string>         = %d\n", (int)Container<std::string>);
    std::printf("Container<int>                 = %d\n", (int)Container<int>);
    std::vector<int> v{1, 2, 3};
    std::printf("count_of(v) = %zu\n", count_of(v));
    return 0;
}
```

`实测数据`
`Text`

```text
Container<std::vector<int>>    = 1
Container<std::vector<double>> = 0
Container<std::string>         = 0
Container<int>                 = 0
count_of(v) = 3
```

`std::vector<double>` 与 `std::string` 都满足前四条要求，
卡住它们的是最后那条嵌套要求：元素类型不是 `int`。
**约束是可以判定的**：`Container<T>` 这个 `bool` 在任何地方都能直接拿出来看。

## 5.2 同一件事用概念重写

把第 4.2 小节那个例子改用概念写，功能一样，条件从模板参数的默认实参挪成了一个有名字的概念：

`C++`

```cpp
/* concept_sized.cpp    编译：g++ -std=c++20 concept_sized.cpp -o concept_sized */
#include <concepts>
#include <cstdio>
#include <string>
#include <vector>

template <class T>
concept Sized = requires(const T &c) { c.size(); };

template <Sized T>
std::size_t size_of(const T &c) { return c.size(); }

int main() {
    std::vector<int> v{1, 2, 3};
    std::string s = "abcd";
    std::printf("vector：%zu，string：%zu\n", size_of(v), size_of(s));
    std::printf("Sized<std::vector<int>> = %d，Sized<int> = %d\n",
                (int)Sized<std::vector<int>>, (int)Sized<int>);
    return 0;
}
```

`实测数据`
`Text`

```text
vector：3，string：4
Sized<std::vector<int>> = 1，Sized<int> = 0
```

再让一个不满足的类型去调用，报错把缺哪一条直接说了出来（下面是节选）：

`C++`

```cpp
/* concept_nomatch.cpp    编译：g++ -std=c++20 concept_nomatch.cpp -o concept_nomatch （失败） */
#include <concepts>
#include <cstdio>

template <class T>
concept Sized = requires(const T &c) { c.size(); };

template <Sized T>
std::size_t size_of(const T &c) { return c.size(); }

int main() {
    return (int)size_of(42);
}
```

`实测数据`
`Text`

```text
concept_nomatch.cpp:12:24: error: no matching function for call to 'size_of(int)'
concept_nomatch.cpp:9:13: note: candidate 1: 'template<class T>  requires  Sized<T> std::size_t size_of(const T&)'
concept_nomatch.cpp:9:13: note: constraints not satisfied
concept_nomatch.cpp:9:13: note: constraints not satisfied
concept_nomatch.cpp:6:9:   required for the satisfaction of 'Sized<T>' [with T = int]
concept_nomatch.cpp:6:17:   in requirements with 'const T& c' [with T = int]
concept_nomatch.cpp:6:46: note: the required expression 'c.size()' is invalid
```

对照第 4.3 小节那份 SFINAE 的报错：两者都是「没有匹配的函数」，
差别在最后一行——SFINAE 那份要读的人自己从
`request for member 'size' in 'std::declval<const int&>()` 里推出「缺少 `size()`」，
概念这份直接写 `the required expression 'c.size()' is invalid`，
并且明确指出是哪一条约束（`Sized<T>`）没有被满足。
**报错行数：SFINAE 那份 12 行，概念这份 20 行——概念并不更短，但把哪一条要求没满足说清楚了。**

## 5.3 概念与 SFINAE 的分工

| | SFINAE（C++17） | 概念与约束（C++20） |
|---|---|---|
| 条件写在哪 | 返回类型或模板参数的默认实参里 | 模板参数上，或者参数类型里（`Addable auto`） |
| 条件有名字吗 | 没有，一处一抄 | 有，`concept` 就是一个名字，可以复用、可以组合 |
| 条件本身能求值吗 | 不能直接问「`T` 满足吗」，只能看替换成不成功 | 能，`Sized<int>` 就是一个 `bool` |
| 报错说什么 | 替换失败发生在哪一行 | 哪一条约束没被满足 |
| 重载决议 | 失败者出局 | 同样出局，另外约束还能参与候选的排序 |

最后一行是概念多出来的一层能力：**约束更强的候选会被优先选中**，
不必再靠 `enable_if` 手工排除二义。那一部分的规则请以 C++20 标准为准，本章不展开。

> [!TIP]
> **新代码用 C++20 时，优先写概念。**
> 条件有了名字，读的人不必逐层拆 `void_t`；
> 编译器也能在调用点直接说清缺什么。
> 需要维护 C++17 的代码时，第 4 节那套写法仍是唯一的选择。

> [!NOTE]
> **第 5 节小结**：`requires` 表达式把「要求」写成可判定的表达式，
> `concept` 给它起名字，约束把名字放到模板参数或参数上。
> 与 SFINAE 相比，功能上覆盖同一片范围，好处是条件可复用、可求值、报错能指出缺哪一条。
> 这是 C++20 的内容，超出本教材基准。

# 第 6 节 模板就是编译期计算

模板实例化的时机是编译期，于是一个模板可以当成一台在编译期运行的计算机：
输入写在模板参数里，输出放在类型里。这一节把它与 `constexpr` 放在一起看。

## 6.1 模板元编程：值算在类型里

同一个阶乘，用模板写是这样：

`C++`

```cpp
/* fact_tmpl.cpp    编译：g++ -std=c++17 fact_tmpl.cpp -o fact_tmpl */
#include <cstdio>
#include <typeinfo>

template <int N>
struct Fact {                                    /* 值算在「类型」里 */
    static const long long value = N * Fact<N - 1>::value;
};

template <>
struct Fact<0> { static const long long value = 1; };    /* 递归终点：全特化 */

int main() {
    std::printf("Fact<10>::value = %lld\n", Fact<10>::value);
    std::printf("Fact<20>::value = %lld\n", Fact<20>::value);
    std::printf("Fact<5> 的类型名：%s\n", typeid(Fact<5>).name());
    std::printf("Fact<5> 与 Fact<6> 是同一个类型吗：%s\n",
                typeid(Fact<5>) == typeid(Fact<6>) ? "是" : "否");
    return 0;
}
```

`实测数据`
`Text`

```text
Fact<10>::value = 3628800
Fact<20>::value = 2432902008176640000
Fact<5> 的类型名：4FactILi5EE
Fact<5> 与 Fact<6> 是同一个类型吗：否
```

四件事从这组输出里读出来：

| 现象 | 说明 |
|---|---|
| 结果是 `static const` 成员 | 算出来的值挂在**类型**上，取用要写 `Fact<10>::value` |
| `Fact<5>` 的类型名是 `4FactILi5EE` | 每个实参组合都对应一个真实存在、有名字的类型 |
| `Fact<5>` 与 `Fact<6>` 不是同一个类型 | 计算过程就是「造类型」，一个值一个类型 |
| 递归靠全特化收尾 | `Fact<0>` 是那个非模板的特化，没有它递归不会停（《05-类与面向对象/11-模板.md》第 6.1 小节） |

这种写法叫**模板元编程**（template metaprogramming，TMP）：
用模板参数当输入，用特化当分支与递归终点，用成员当输出。
它在标准库里的痕迹到处都是——`std::tuple` 的元素类型、
`std::is_integral` 这一族 trait、`std::get<I>` 按下标取元素，
都是同一台计算机算出来的。

## 6.2 `constexpr`：值算在值里

同一个阶乘，用 `constexpr` 函数写是这样：

`C++`

```cpp
/* fact_constexpr.cpp    编译：g++ -std=c++17 fact_constexpr.cpp -o fact_constexpr */
#include <cstdio>
#include <type_traits>
#include <typeinfo>

constexpr long long fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }

static_assert(fact(5) == 120, "5 的阶乘是 120");

int main() {
    std::printf("fact(10) = %lld\n", fact(10));
    std::printf("fact(20) = %lld\n", fact(20));
    constexpr long long v = fact(5);
    std::printf("fact(5) 的结果类型名：%s\n", typeid(v).name());
    using F5 = std::integral_constant<long long, fact(5)>;   /* 值喂给类型层面的模板 */
    std::printf("integral_constant 里的值：%lld\n", F5::value);
    return 0;
}
```

`实测数据`
`Text`

```text
fact(10) = 3628800
fact(20) = 2432902008176640000
fact(5) 的结果类型名：x
integral_constant 里的值：120
```

两边的对照很清楚：

| | 模板版（第 6.1 小节） | `constexpr` 版 |
|---|---|---|
| 输入放在哪 | 模板参数 `Fact<10>` | 函数参数 `fact(10)` |
| 结果是什么 | 类型 `Fact<10>` 的一个静态成员 | 一个普通的值，类型是 `long long` |
| 结果类型名 | `4FactILi5EE`，一个为它造出来的类型 | `x`，就是 `long long` |
| 一个值对应什么 | **一个新类型** | 就是同一个函数的一次求值 |
| 递归怎么收尾 | 全特化 | `if`/`?:` 里的终止条件 |

第四行是全部区别的来源：**模板版的计算过程在造类型，`constexpr` 版的计算过程在算值。**
造出来的类型要进符号表、要有名字、要参与重载决议，因此比算一个值贵得多。

两条路不是互不相干的：`std::integral_constant<long long, fact(5)>` 那一行
把 `constexpr` 算出来的值喂给了类型层面的模板。**值层面与类型层面的接口就是这一类模板**
（`std::integral_constant`、`std::bool_constant`）。

## 6.3 编译时间

同一个任务——求 1 到 N 的平方和——两边各写一份：

`C++`

```cpp
/* tmp_loop.cpp    编译：g++ -std=c++17 -c tmp_loop.cpp -o tmp_loop.o */
template <int N>
struct SumSq { static const long long value = (long long)N * N + SumSq<N - 1>::value; };

template <>
struct SumSq<0> { static const long long value = 0; };

long long total() { return SumSq<500>::value; }
```

`C++`

```cpp
/* const_loop.cpp    编译：g++ -std=c++17 -c const_loop.cpp -o const_loop.o */
constexpr long long sum_sq(long long n) {
    long long s = 0;
    for (long long i = 1; i <= n; ++i) s += i * i;
    return s;
}

constexpr long long total_v = sum_sq(500);

long long total() { return total_v; }
```

模板版要为 1 到 500 的每一个值造一个类型；
`constexpr` 版只有一个函数体，循环写在里面（C++14 起 `constexpr` 函数里可以写循环，
《04-语法/12-编译期能力.md》第 3 节）。把两个程序里的 500 往上调，差距就出来了：

`实测数据`

| 1 到 N 的平方和 | 模板版（每个值一个类型） | `constexpr` 版（一个函数体） |
|---|---|---|
| N = 500（两个程序原样） | 90 毫秒 | 73 毫秒 |
| N = 10000 | **244 毫秒**（10000 个实例化） | **84 毫秒** |
| N = 11000 | **编译器进程被终止**，退出码 1，没有任何诊断输出 | 85 毫秒 |
| N = 20000 | ——（同样过不去） | 86 毫秒 |

（每次编译三次取最快的一次，命令是 `g++ -std=c++17 -c`。
N 超过 900 时模板版会先撞上 `-ftemplate-depth=900`，因此那一列另外加了
`-ftemplate-depth=200000`，`constexpr` 版不需要额外选项。）

三条结论：

| 规模 | 现象 |
|---|---|
| **小规模（500）** | 两边差不多：90 与 73 毫秒。为几百个值造类型，编译器不在乎 |
| **中等规模（10000）** | 模板版是 `constexpr` 版的近三倍：244 与 84 毫秒 |
| **再往上（11000）** | 模板版直接让编译器进程终止；`constexpr` 版到 20000 仍是 86 毫秒 |

第三行不是「慢」，是「过不去」。原因在第 6.5 小节。

## 6.4 报错

同一种错——忘记写递归终点——两边的报错规模差很多。
模板版（下面是节选）：

`C++`

```cpp
/* tmp_no_base.cpp    编译：g++ -std=c++17 tmp_no_base.cpp -o tmp_no_base （失败） */
template <int N>
struct Fact { static const long long value = N * Fact<N - 1>::value; };  /* 忘了写 N == 0 的终点 */

int main() { return (int)Fact<5>::value; }
```

`实测数据`
`Text`


`C++`

```cpp
/* const_no_base.cpp    编译：g++ -std=c++17 const_no_base.cpp -o const_no_base （失败） */
constexpr long long fact(int n) { return n * fact(n - 1); }   /* 忘了写终止条件 */

```

`实测数据`
`Text`

```text

const_no_base.cpp:2:50:   in 'constexpr' expansion of 'fact((n - 1))'
（这两行之后，同样的行一直重复到第 512 层，中间略去）

```

报错总行数 516 行。两边都把「递归没有终点」指了出来，
只是一个由编译器汇总（12 行），另一个逐层打印（516 行）。

**但换一种错法，结论就变了。** 把期望值写错（下面是节选）：

`C++`

```cpp
/* const_wrong_assert.cpp    编译：g++ -std=c++17 const_wrong_assert.cpp -o const_wrong_assert （失败） */
constexpr long long fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }

static_assert(fact(5) == 12, "阶乘算错了");       /* 故意写错期望值 */

int main() { return 0; }
```

`实测数据`
`Text`

```text
const_wrong_assert.cpp:4:23: error: static assertion failed: 阶乘算错了
const_wrong_assert.cpp:4:23: note: the comparison reduces to '(120 == 12)'
```

4 行，直接给出算出来的值。把 `Fact<5>::value == 12` 写成模板版的
`static_assert`，同样是 4 行、同样给出一行 `the comparison reduces to '(120 == 12)'`。

所以报错好坏不是「模板」与「`constexpr`」的分界，而是错的形态的分界：

| 错在哪 | 模板版 | `constexpr` 版 |
|---|---|---|
| 期望值写错 | 4 行，给出算出来的值 | 4 行，给出算出来的值 |
| 递归忘了终点 | 12 行（编译器汇总） | 516 行（逐层打印） |

第三类错是「类型不满足要求」，规模由候选集决定：
第 3.1 小节 71 行，第 4.3 小节 12 行，改用概念（第 5.2 小节）20 行。
真正难读的正是这一类：候选集大、涉及标准库内部的类型不匹配。
模板只是把这种错误的规模放大了。

## 6.5 能算到多大

两边都有上限，而且是同一类限制——编译器前端的递归深度：

| | 模板版 | `constexpr` 版 |
|---|---|---|
| 默认上限 | `-ftemplate-depth=900` | `-fconstexpr-depth=512` |
| 撞上时的报错 | `fatal error: template instantiation depth exceeds maximum of 900` | `error: 'constexpr' evaluation depth exceeds maximum of 512` |
| 能不能调高 | 能，`-ftemplate-depth=` | 能，`-fconstexpr-depth=` |

模板版把上限抬到 20 万会怎样，第 6.3 小节已经测到：
10000 个实例化还能过，11000 个就不行了——

`实测数据`

| 层数 | 模板版的退出码 | 编译器的输出 |
|---|---|---|
| 10000 | 0 | 有产物，249 毫秒 |
| 11000 | **1** | **标准输出与标准错误都是空的** |
| 12000 | **1** | **标准输出与标准错误都是空的** |
| 20000 | **1** | **标准输出与标准错误都是空的** |

表中的毫秒数来自单次运行；第 6.3 小节那组取的是三次里最快的一次，
因此同一个 N = 10000 在那里写作 244 毫秒。

**没有任何诊断输出**：编译器进程直接消失，只留下退出码 1。
按 25 毫秒的间隔采样时，`cc1plus` 的峰值内存是 48 MB
（同一次采样下 10000 层那次是 56 MB），因此不像内存用尽。

`待确认`

更可能的原因是前端递归消耗栈空间，这一点与结论无关。
**这条路有一个实际的上限，撞上去时不会得到有用的报错。**

`constexpr` 版走上限时给的是明确的一句话，
把 `-fconstexpr-depth` 调高就能继续算——第 6.3 小节里 20000 次循环的版本用默认设置就编过了，
因为循环不消耗递归深度。

> [!CAUTION]
> **把编译期计算写成深递归的模板，是在赌编译器的资源。**
> 撞上限时既没有准确的报错，也说不清是哪个实例化的问题；
> 换成 `constexpr` 函数里的循环，同样的计算在默认设置下就能完成。

## 6.6 今天还在哪里用模板元编程

`constexpr` 能算值，但算不了**类型**。下面这些问题只有模板能回答：

| 问题 | 答案是什么 | 例子 |
|---|---|---|
| 这个列表里有没有某个类型 | 一个 `bool`，但依赖类型之间的匹配 | 下面实测的 `contains` |
| 第 I 个元素是什么类型 | 一个**类型** | `std::tuple_element_t<I, Tuple>` |
| 按条件二选一取一个类型 | 一个**类型** | `std::conditional` |
| 这个类型有没有某个成员 | 一个 `bool` | 第 4.5 小节的 `has_size` |

`C++`

```cpp
/* type_list.cpp    编译：g++ -std=c++17 type_list.cpp -o type_list */
#include <cstdio>
#include <tuple>
#include <type_traits>
#include <typeinfo>

template <class... Ts>
struct TypeList { static const std::size_t size = sizeof...(Ts); };

/* 判断某个类型在不在列表里：靠偏特化在「类型」上递归 */
template <class T, class... Rest>
struct contains : std::false_type {};

template <class T, class... Rest>
struct contains<T, T, Rest...> : std::true_type {};          /* 第一个就命中 */

template <class T, class U, class... Rest>
struct contains<T, U, Rest...> : contains<T, Rest...> {};    /* 不是它，往后找 */

/* 把列表里所有类型的大小加起来：在类型上做折叠 */
template <class... Ts>
struct total_size;

template <>
struct total_size<> { static const std::size_t value = 0; };

template <class T, class... Rest>
struct total_size<T, Rest...> {
    static const std::size_t value = sizeof(T) + total_size<Rest...>::value;
};

int main() {
    using L = TypeList<int, double, const char *>;
    std::printf("列表里有 %zu 个类型\n", L::size);
    std::printf("contains<int, int, double>         = %d\n", (int)contains<int, int, double>::value);
    std::printf("contains<double, int, double>      = %d\n", (int)contains<double, int, double>::value);
    std::printf("contains<const char*, int, double> = %d\n", (int)contains<const char *, int, double>::value);
    std::printf("contains<float, int, double>       = %d\n", (int)contains<float, int, double>::value);
    std::printf("total_size<int, double, char>      = %zu\n", total_size<int, double, char>::value);

    std::tuple<int, double, const char *> t{1, 2.5, "三"};
    std::printf("tuple：%d %.1f %s，元素个数 %zu，大小 %zu 字节\n",
                std::get<0>(t), std::get<1>(t), std::get<2>(t),
                std::tuple_size<decltype(t)>::value, sizeof(t));
    std::printf("第 1 个元素的类型名：%s\n",
                typeid(std::tuple_element_t<1, decltype(t)>).name());
    return 0;
}
```

`实测数据`
`Text`

```text
列表里有 3 个类型
contains<int, int, double>         = 1
contains<double, int, double>      = 1
contains<const char*, int, double> = 0
contains<float, int, double>       = 0
total_size<int, double, char>      = 13
tuple：1 2.5 三，元素个数 3，大小 24 字节
第 1 个元素的类型名：d
```

`contains` 的递归不是在算数，而是在**匹配类型**：
两个偏特化分别负责「命中」与「不是它、往后找」，主模板负责「找完了」（偏特化的写法见《05-类与面向对象/11-模板.md》第 6.2 小节）。
这种递归用 `constexpr` 写不出来——`constexpr` 函数收的是值，
它没有语法能遍历一串类型。（`TypeList` 与 `contains` 是教科书式的写法，
标准库里的对应物见《06-标准库/B-08-工具类（上）：pair、tuple、optional、variant、any.md》章节的 `std::tuple`。）

`std::tuple` 那一组数字说明这套机制在日常代码里的样子：
`std::get<0>` 的下标是模板参数，`tuple_size`、`tuple_element_t`
都是模板算出来的，取第 2 个元素时编译器知道那是 `double`（类型名 `d`），
不需要运行期查表。

## 6.7 与 `constexpr` 的分工

把第 6.1 到 6.6 小节合成一条判断标准：

| 要得到的结果 | 用什么 | 理由 |
|---|---|---|
| **一个值**：阶乘、哈希、表格长度、`static_assert` 的比较 | `constexpr` 函数 | 编译期求值，结果是普通的值；循环、局部变量都能用 |
| **一个类型**：按条件选类型、取元组的第 I 个类型、判断类型性质 | 模板 | 类型不是值，`constexpr` 没有语法能算它 |
| 一个值要做成类型 | `std::integral_constant<T, v>` | 它是两类计算的接口 |

写代码时的默认选择是 `constexpr`：

| 场合 | 选择 |
|---|---|
| 要一个编译期常量 | `constexpr` 函数或变量（《04-语法/12-编译期能力.md》第 3 节） |
| 要一个编译期检查 | `static_assert`（同章第 4 节） |
| 要按类型选实现 | `if constexpr`（第 3 节） |
| 要筛选重载 | 概念（C++20）或 `enable_if`（第 4 节） |
| 要在类型上递归、在类型之间做选择 | 模板元编程（第 6.6 小节） |

**模板元编程没有消失，只是退到了它不可替代的位置**：
类型层面的计算。凡是能用 `constexpr` 算出值的，都不必再写成模板——
后者的编译时间更长、上限更低，类型不匹配时报错也更长（第 6.3 到 6.5 小节）。

> [!NOTE]
> **第 6 节小结**：模板实例化是编译期行为，因此模板本身是一台编译期计算机，
> 输入在模板参数里、输出在类型里。`constexpr` 是另一台，输入输出都是值。
> 两者都在编译期跑，但模板要为每个输入造一个新类型，
> 所以规模一大就慢，甚至过不去；能算值的场合一律先用 `constexpr`。

# 第 7 节 检查清单

写代码时逐条对照：

| 检查 | 说明 |
|---|---|
| 展开参数包用的是折叠表达式还是递归 | 新代码用折叠表达式；递归写法要确保有非模板的终点重载（第 1.2 小节） |
| 一元折叠会不会收到空包 | `(... + v)` 空包时编不过，改成 `(0 + ... + v)`（第 2.3 小节） |
| 折叠的结合方向与初值位置对了吗 | 非交换运算上左折右折结果不同（第 2.2 小节） |
| 二元折叠的两个操作数是不是都含参数包 | 都含参数包是非法的（第 2.1 小节） |
| 按类型分派用的是 `if constexpr` 吗 | 普通 `if` 的两个分支对每种实例化都要合法（第 3.1 小节） |
| `if constexpr` 的条件是常量表达式吗 | 运行期变量会直接编不过（第 3.4 小节） |
| 分派的是类型还是运行期的值 | 运行期的值用普通 `if`（第 3.4 小节） |
| 要求某个成员存在，失败发生在签名上吗 | 写进函数体就是硬错误，SFINAE 不生效（第 4.3 小节） |
| 同一个条件是不是抄了好几遍 | 抄多了会漏；C++20 用概念给它起名字（第 4.6、5.3 小节） |
| 编译期算的是值还是类型 | 值用 `constexpr`，类型才用模板（第 6.7 小节） |
| 模板递归的深度会不会失控 | 默认上限 900，撞上去没有有用的报错（第 6.5 小节） |
| 编译选项里的 `-std=` 够不够 | `if constexpr`、`void_t` 要 C++17，概念要 C++20（第 3、4、5 节） |

## A.2 编译时间那组数字是怎么测出来的

第 6.3 小节的四个规模，用的是同一份源码改一个数字：
模板版改 `SumSq<N>` 里的 `N`，`constexpr` 版改 `sum_sq(N)` 的实参。
默认上限下 `SumSq<10000>` 会先撞上 `-ftemplate-depth=900`，
因此那一列一律加 `-ftemplate-depth=200000`。

另外实测过一组「互不相同的实例化」与「互不相同的常量」的对照，
两边各 1000 个：模板版 159 毫秒，`constexpr` 版 155 毫秒，差别在噪声范围内。
小规模上两条路一样快，差距要到几千个以上才出现（第 6.3 小节的表格）。
这一组文件由一段循环生成，形状如下（生成后再编译）：

`Python`

```python
# gen_many.py    生成 tmp_many.cpp 与 const_many.cpp，再用 g++ -std=c++17 -c 编译
n = 1000
with open("tmp_many.cpp", "w", encoding="utf-8") as f:
    f.write("template <int N> struct Sq { static const int value = N * N; };\n")
    f.write("int total() { return " + " + ".join("Sq<%d>::value" % k for k in range(n)) + "; }\n")
with open("const_many.cpp", "w", encoding="utf-8") as f:
    f.write("constexpr int sq(int n) { return n * n; }\n")
    f.write("\n".join("constexpr int v%d = sq(%d);" % (k, k) for k in range(n)) + "\n")
    f.write("int total() { return " + " + ".join("v%d" % k for k in range(n)) + "; }\n")
```
