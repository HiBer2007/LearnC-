**同一段逻辑，换一种类型就要再写一遍**，这是写 C++ 时反复遇到的处境：
给 `int` 数组排序、给 `double` 数组排序、给自定义结构体数组排序，
三份代码除了类型名之外一个字都不差。模板出现之前有两条旧路：宏，以及 `void *` 加函数指针。
两条路都能用，代价都落在同一处——编译器再也帮不上忙。

模板把类型本身也变成参数，让编译器在编译期为每一种用到的类型生成一份代码。
类型检查保留下来，运行期不多一次间接调用；代价转移到编译期，
表现为代码份数变多、编译变慢、报错变长。这三项代价与它们的边界，
和写法本身一样需要说清。

它同时是第 08 章那批「编译期决定」的手段里的第三种
（《05-类与面向对象/08-多态：重载、虚函数与它们的分工.md》第 1.1 小节）：
函数重载按实参挑函数，运算符重载给已有运算符定义新含义，
模板则按类型生成整份代码。

# 第 1 节 为什么需要模板

## 1.1 同一份逻辑按类型抄几遍

`C++`

```cpp
/* before_template.cpp    编译：g++ -std=c++17 before_template.cpp -o before_template */
#include <cstdio>
#include <cstring>

int max_int(int a, int b)             { return a > b ? a : b; }
double max_double(double a, double b) { return a > b ? a : b; }
const char *max_str(const char *a, const char *b) {
    return std::strcmp(a, b) > 0 ? a : b;       /* 字符串另有比法 */
}

int main() {
    std::printf("%d，%.1f，%s\n", max_int(3, 5), max_double(1.5, 0.5), max_str("ab", "cd"));
    return 0;
}
```

`实测数据`
`Text`

```text
5，1.5，cd
```

三个函数做的是同一件事：挑出更大的那个。差别只有类型。
第三个还多了一处：字符串的「大」不是 `>` 能表达的，要换成 `strcmp`。

抄三遍的代价不只是多打几个字：

| 代价 | 说明 |
|---|---|
| 改一处要改多处 | 逻辑要调整时每一份都要同步改，漏掉一份就是一个只在某种类型上出现的错误 |
| 类型组合是乘出来的 | 三个类型三个函数；再加一个「按自定义规则比」的需求，就要再多三份 |
| 类型写在函数名里，调用方必须知道 | 调用方要在 `max_int` 与 `max_double` 之间选，而这个选择本来可以从实参推出来 |

第三点最关键：**类型信息在调用点是多余的**，编译器从实参就能判断该用哪一份。

## 1.2 旧路一：宏

宏是最直接的想法：把类型名留成空位，用文本替换填进去。
《04-语法/14-预处理器.md》第 2.2 小节已经列出函数式宏的三处问题，这里看其中两处落到实处的样子。

`C++`

```cpp
/* macro_twice.cpp    编译：g++ -std=c++17 macro_twice.cpp -o macro_twice */
#include <cstdio>

#define MAX(a, b) ((a) > (b) ? (a) : (b))       /* 文本替换：a 与 b 各出现两次 */

int main() {
    int i = 0;
    int j = 10;
    int r = MAX(i++, j);                        /* i++ 被展开成两次 */
    std::printf("结果 %d，但 i 变成了 %d\n", r, i);
    return 0;
}
```

`实测数据`
`Text`

```text
结果 10，但 i 变成了 1
```

`i` 的初值是 0，调用之后变成 1：展开后的表达式里 `(a)` 出现两遍，
本例中比较不成立，取的是 `(j)`，因此 `i++` 只求值了一次。
比较成立时两处 `(a)` 都会求值，同一个 `i++` 就会自增两次。

第二处代价是**宏没有类型**。同一份 `MAX` 换一组实参，编译器只能事后抱怨：

`C++`

```cpp
/* macro_nocheck.cpp    编译：g++ -std=c++17 macro_nocheck.cpp -o macro_nocheck （失败） */
#include <cstdio>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main() {
    const char *s = "abc";
    int n = 2;
    std::printf("%p\n", (void *)MAX(s, n));     /* 指针与整数比较 */
    return 0;
}
```

`实测数据`
`Text`

```text
macro_nocheck.cpp:4:24: error: ISO C++ forbids comparison between pointer and integer [-fpermissive]
macro_nocheck.cpp:4:30: error: operands to '?:' have different types 'const char*' and 'int'
```

报错指向的是**宏展开之后的第 4 行**，也就是 `#define` 那一行。
写代码的人看到的位置（宏定义）与真正写错的位置（`main` 里的调用）不是同一处；
而且这里等于要求编译器回答「`const char *` 与 `int` 谁大」，这个问题本身就不成立。

> [!WARNING]
> 宏的参数可能被求值多次，宏也不做类型检查。
> 两者叠加之后，一类错误在编译期被漏掉、在运行期变成错数据。
> 需要「对多种类型都成立」时，宏不是可用的工具（《04-语法/14-预处理器.md》第 7.2 小节）。

## 1.3 旧路二：`void *` 加函数指针

第二条路来自 C：把元素的类型信息全部抹掉，换成 `void *` 加两项补充说明——
每个元素多大、怎么比较。C 标准库的 `qsort` 就是这个形状。

`C++`

```cpp
/* void_star.cpp    编译：g++ -std=c++17 void_star.cpp -o void_star */
#include <cstdio>
#include <cstring>

/* 通用排序：元素的类型信息全丢了，只能靠调用方告诉它「每个多大」「怎么比」 */
void sort_any(void *base, int n, int size,
              int (*cmp)(const void *, const void *)) {
    char *p = (char *)base;
    char  tmp[64];
    for (int i = 1; i < n; ++i) {
        std::memcpy(tmp, p + i * size, size);
        int j = i - 1;
        while (j >= 0 && cmp(p + j * size, tmp) > 0) {
            std::memcpy(p + (j + 1) * size, p + j * size, size);
            --j;
        }
        std::memcpy(p + (j + 1) * size, tmp, size);
    }
}

int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;   /* 必须强转回来 */
    return (x > y) - (x < y);
}

int main() {
    int a[5] = {5, 2, 9, 1, 7};
    sort_any(a, 5, sizeof(int), cmp_int);
    for (int x : a) std::printf("%d ", x);
    std::printf("\n");
    return 0;
}
```

`实测数据`
`Text`

```text
1 2 5 7 9
```

排序是对的。代价在三处：

| 代价 | 说明 |
|---|---|
| 函数体里没有类型 | 函数只知道「一块内存 + 元素大小」，`p + j * size` 得到的是 `char *`，每一步都要强转 |
| 调用方要提供三样 | 元素大小、比较函数，还有「传进来的元素类型确实与比较函数一致」这条无法检查的约定 |
| 编译器看不见比较函数 | 比较只能通过函数指针间接调用，无法内联（《04-语法/08-数组、指针与引用.md》第 4.5 小节） |

第二处是真正的危险：**传错了大小，编译器不会有任何提示**。

`C++`

```cpp
/* void_star_wrong.cpp    编译：g++ -std=c++17 void_star_wrong.cpp -o void_star_wrong */
#include <cstdio>

/* 同一份 void * 代码，传错了大小或比法，编译器看不出来 */
void fill(void *base, int n, int size) {
    for (int i = 0; i < n; ++i) *(int *)((char *)base + i * size) = i;
}

int main() {
    long long a[4] = {0};
    fill(a, 4, sizeof(int));            /* 元素其实是 8 字节，却按 4 字节填 */
    for (long long x : a) std::printf("%lld ", x);
    std::printf("\n");
    return 0;
}
```

`实测数据`
`Text`

```text
4294967296 12884901890 0 0
```

程序编译通过、运行正常退出，打印出来的却是错数据：
每个 8 字节的元素被当成两个 4 字节分别写了一半，两个半截拼成了那两个数。
这类错误没有编译期提示，也没有运行期检查，只能靠人盯着输出看。

> [!CAUTION]
> `void *` 把类型信息从接口上抹掉之后，所有依赖类型的前提都成了口头约定：
> 元素大小、对齐、比较函数的适用类型，编译器一项也无法核对。
> 约定被违反时的后果是**静默的错数据**，而不是崩溃。

## 1.4 模板的答案

模板走的是第三条路：**把类型本身写成参数**。

`文档`

> "A template defines a family of classes, functions, or variables, or an alias for a family of types."
>
> —— N4659 §17/1

它不是运行期的一套通用代码，而是编译期的一族代码。
写一份源码，编译器为每一个用到的类型各生成一份函数或类，
与手写多份的效果相同，但源码只有一份，类型检查一项不少。用一个最小的例子对比：

`C++`

```cpp
/* max_template.cpp    编译：g++ -std=c++17 max_template.cpp -o max_template */
#include <cstdio>
#include <cstring>

template <class T>                              /* T 是类型参数 */
T max_of(const T &a, const T &b) {
    return a > b ? a : b;                       /* 只要求 T 支持 > 与拷贝 */
}

class Meter {                                   /* 自定义类型也能用 */
public:
    explicit Meter(int v) : v_(v) {}
    bool operator>(const Meter &o) const { return v_ > o.v_; }
    int value() const { return v_; }
private:
    int v_;
};

int main() {
    std::printf("%d\n", max_of(3, 5));                    /* T 推成 int */
    std::printf("%.1f\n", max_of(1.5, 0.5));              /* T 推成 double */
    std::printf("Meter：%d\n", max_of(Meter(3), Meter(7)).value());
    return 0;
}
```

`实测数据`
`Text`

```text
5
1.5
Meter：7
```

一个函数，三种类型，其中包括一个刚写完的类。与前面两条路对比：

| | 宏 | `void *` 加函数指针 | 模板 |
|---|---|---|---|
| 类型检查 | 没有 | 没有（只剩「多大」这个数） | **完整保留**，错误在编译期报出 |
| 参数求值次数 | 可能多次 | 一次 | 一次 |
| 运行期开销 | 无 | 一次间接调用，通常无法内联 | **无**，调用点可以直接内联 |
| 代码份数 | 一份文本 | 一份机器码 | **每种类型一份机器码** |
| 出错时的表现 | 编译错误指向宏定义 | 静默的错数据 | 编译错误，但很长（第 8.3 小节） |

代价集中在最后两行：模板换来类型安全与速度，付出的是**代码份数**与**编译期的工作量**。

「一份通用代码加运行期查表」是另一种做法，通常叫**类型擦除**：
`std::function`（《05-类与面向对象/10-lambda 与函数对象.md》第 5 节）、
C 标准库的 `qsort`、`void *` 加函数指针，都属于这一类。
它与模板的取舍正好相反——源码一份、机器码一份，但每次调用要多一层转发，
被擦掉的类型信息再也拿不回来。两者的运行期差别在第 8.4 小节实测。

> [!NOTE]
> **模板把类型提升成参数，让编译器在编译期为每一种类型生成一份代码。**
> 类型检查与内联机会都保留下来，代价转移到编译期：
> 代码份数随类型数量增长、编译时间变长、报错信息变长。
> 两条旧路分别败在「没有类型」与「丢掉类型」上，而模板的代价不是正确性，是规模。

# 第 2 节 函数模板

## 2.1 声明与实例化

模板声明以 `template` 开头，尖括号里是**模板参数表**，每一项是一个**模板参数**：

`C++`

```cpp
template <class T>              /* 模板参数表：T 是一个类型参数 */
T max_of(const T &a, const T &b) { return a > b ? a : b; }
//  ↑ 返回类型也用 T
```

`class` 在这里不表示「类」，它只是「一个类型」的占位符（第 2.4 小节）。
调用 `max_of(3, 5)` 时 `T` 被替换成 `int`，编译器生成一份 `int` 版的 `max_of`；
生成出来的那个函数叫**函数模板特化**（function template specialization），
生成它的动作叫**实例化**（instantiation，第 5 节）。

`文档`

> "A function template defines an unbounded set of related functions."
>
> —— N4659 §17.5.6/1

`文档`

> "The act of instantiating a function, a class, a member of a class template or a member template
> is referred to as template instantiation."
>
> —— N4659 §17.7/1

模板参数与模板实参是两个不同的概念，名字接近，含义相反：

| 说法 | 指什么 | 例子里 |
|---|---|---|
| **模板参数**（template parameter） | 模板声明里那个占位符 | `T` |
| **模板实参**（template argument） | 实际填进去的类型或值 | `int` |
| **模板特化**（specialization） | 填好之后生成出来的那个函数或类 | `max_of<int>` |

## 2.2 参数推导与显式指定

多数情况下模板实参不需要写出来，编译器从实参的类型推：

`文档`

> "When a function template specialization is referenced, all of the template arguments shall have
> values. The values can be explicitly specified or, in some cases, be deduced from the use or
> obtained from default template-arguments."
>
> —— N4659 §17.8.2/1

推导的做法是把形参类型与实参类型逐个配对：

`文档`

> "Template argument deduction is done by comparing each function template parameter type (call it
> P) that contains template-parameters that participate in template argument deduction with the type
> of the corresponding argument of the call (call it A) as described below."
>
> —— N4659 §17.8.2.1/1

配对必须得到同一个答案。两个实参推出两个不同的 `T` 时，推导失败：

`C++`

```cpp
/* deduce_fail.cpp    编译：g++ -std=c++17 deduce_fail.cpp -o deduce_fail （失败） */
template <class T>
T max_of(const T &a, const T &b) { return a > b ? a : b; }

int main() {
    return max_of(1, 2.0);          /* 两个实参推出两个不同的 T */
}
```

`实测数据`
`Text`

```text
deduce_fail.cpp: In function 'int main()':
deduce_fail.cpp:6:18: error: no matching function for call to 'max_of(int, double)'
    6 |     return max_of(1, 2.0);          /* 两个实参推出两个不同的 T */
      |            ~~~~~~^~~~~~~~
deduce_fail.cpp:6:18: note: there is 1 candidate
deduce_fail.cpp:3:3: note: candidate 1: 'template<class T> T max_of(const T&, const T&)'
    3 | T max_of(const T &a, const T &b) { return a > b ? a : b; }
      |   ^~~~~~
deduce_fail.cpp:3:3: note: template argument deduction/substitution failed:
deduce_fail.cpp:6:18: note:   deduced conflicting types for parameter 'const T' ('int' and 'double')
```

最后一行给出了原因：`const T` 同时被推成 `int` 与 `double`。
标准把这种失败叫 **type deduction fails**，它的后果是这个候选函数被排除出重载集合，
所有候选都被排除时调用就没有匹配的函数。

两条改法。一条是把两个实参改成同一种类型；
另一条是在函数名后面用尖括号**显式指定**模板实参：

`C++`

```cpp
/* explicit_arg.cpp    编译：g++ -std=c++17 explicit_arg.cpp -o explicit_arg */
#include <cstdio>

template <class T>
T max_of(const T &a, const T &b) { return a > b ? a : b; }

int main() {
    std::printf("%.1f\n", max_of<double>(1, 2.0));       /* 显式指定 T = double */
    std::printf("%d\n", max_of<int>(1.9, 2.9));          /* 显式指定 T = int：两个都转 */
    return 0;
}
```

`实测数据`
`Text`

```text
2.0
2
```

第二行值得留意：指定 `T = int` 之后，`1.9` 与 `2.9` 都被转成 `int`，
比较在整数上完成，结果是 `2`。**显式指定只关掉推导，不关掉转换**，
实参不匹配时会做隐式转换，这一点与普通函数的重载决议一致。

## 2.3 返回类型怎么定

模板的返回类型有两种常见写法。写 `auto` 时按普通函数的 `auto` 规则从 `return` 语句推导；
需要精确控制时用**尾置返回类型**加 `decltype`：

`C++`

```cpp
/* return_types.cpp    编译：g++ -std=c++17 return_types.cpp -o return_types */
#include <cstdio>
#include <typeinfo>

template <class T, class U>
auto add_auto(T a, U b) { return a + b; }               /* 推导出来是什么类型 */

template <class T, class U>
auto add_decl(T a, U b) -> decltype(a + b) { return a + b; }   /* 尾置返回类型 */

int main() {
    std::printf("add_auto(1, 2)    类型 %s\n", typeid(add_auto(1, 2)).name());
    std::printf("add_auto(1, 2.0)  类型 %s\n", typeid(add_auto(1, 2.0)).name());
    std::printf("add_decl(1, 2.0)  类型 %s\n", typeid(add_decl(1, 2.0)).name());
    std::printf("值：%d %.1f %.1f\n", add_auto(1, 2), add_auto(1, 2.0), add_decl(1, 2.0));
    return 0;
}
```

`实测数据`
`Text`

```text
add_auto(1, 2)    类型 i
add_auto(1, 2.0)  类型 d
add_decl(1, 2.0)  类型 d
值：3 3.0 3.0
```

`i` 是 `int`，`d` 是 `double`（`typeid(...).name()` 给出的是编译器内部的类型名）。
两处结论：

| 写法 | 结果 | 说明 |
|---|---|---|
| `auto add_auto(T a, U b)` | `add_auto(1, 2.0)` 得到 `double` | `a + b` 的类型按算术转换规则算出来，就是 `double` |
| `auto add_decl(T a, U b) -> decltype(a + b)` | 同样是 `double` | 尾置返回类型写在参数表之后，此时 `a` 与 `b` 都已在作用域里 |

尾置写法在 C++14 之前是唯一的选择，今天仍然有用：
它把返回类型的表达式直接写出来，读代码的人不必回头推。

## 2.4 `class` 与 `typename` 没有区别

`template <class T>` 与 `template <typename T>` 完全等价：

`文档`

> "There is no semantic difference between class and typename in a type-parameter-key."
>
> —— N4659 §17.1/2

两种写法都常见。惯用法是：模板参数一律写 `class`（历史原因），
而 `typename` 留给另一处必须用它的场合——说明一个依赖名是类型（第 5.5 小节）。

> [!IMPORTANT]
> **`T` 是模板参数，`int` 是模板实参；填好之后生成出来的函数叫模板特化。**
> 实参可以从函数实参推导，也可以在函数名后显式指定；
> 推导要求所有出现同一个 `T` 的位置得到同一个答案，否则该候选被排除。
> 返回类型写 `auto` 或写尾置 `decltype` 都可以。

# 第 3 节 非类型模板参数与成员模板

## 3.1 非类型模板参数

模板参数不一定是类型，也可以是一个**值**。这类参数叫**非类型模板参数**：

`C++`

```cpp
/* nontype.cpp    编译：g++ -std=c++17 nontype.cpp -o nontype */
#include <cstdio>

template <class T, int N>                       /* N 是值参数，不是类型 */
class Array {
public:
    int size() const { return N; }
    T &operator[](int i) { return data_[i]; }
private:
    T data_[N];
};

template <int N>
int sum_array(const int (&a)[N]) {              /* 数组长度由模板参数给出 */
    int s = 0;
    for (int x : a) s += x;
    return s;
}

int main() {
    Array<int, 4> a;                            /* 长度在编译期就定死 */
    for (int i = 0; i < a.size(); ++i) a[i] = i * i;
    std::printf("size = %d，a[3] = %d，sizeof = %zu\n", a.size(), a[3], sizeof(a));

    int arr[5] = {1, 2, 3, 4, 5};
    std::printf("sum_array(arr) = %d\n", sum_array(arr));
    return 0;
}
```

`实测数据`
`Text`

```text
size = 4，a[3] = 9，sizeof = 16
sum_array(arr) = 15
```

`sizeof` 是 `16`：`N` 是编译期常量，`data_` 就是 4 个 `int`，没有任何运行期开销。
`sum_array` 那一份更直接：数组长度通常会在传参时丢掉
（《04-语法/08-数组、指针与引用.md》第 2.2 小节），
写成 `const int (&a)[N]` 之后长度被保留下来，循环范围由编译器算好。

非类型实参必须是**编译期常量**，运行期的值不行：

`C++`

```cpp
/* nontype_fail.cpp    编译：g++ -std=c++17 nontype_fail.cpp -o nontype_fail （失败） */
template <int N>
struct Fixed { int a[N]; };

int main() {
    int n = 4;                      /* 运行期的值 */
    Fixed<n> f;                     /* 模板实参必须是常量表达式 */
    return f.a[0];
}
```

`实测数据`
`Text`

```text
nontype_fail.cpp: In function 'int main()':
nontype_fail.cpp:7:12: error: the value of 'n' is not usable in a constant expression
    7 |     Fixed<n> f;                     /* 模板实参必须是常量表达式 */
      |            ^
nontype_fail.cpp:6:9: note: 'int n' is not const
    6 |     int n = 4;                      /* 运行期的值 */
```

标准对非类型实参的要求是「转换后的常量表达式」：

`文档`

> "A template-argument for a non-type template-parameter shall be a converted constant expression
> (8.20) of the type of the template-parameter."
>
> —— N4659 §17.3.2/2

把 `n` 写成 `const int n = 4;` 或 `constexpr int n = 4;` 就能通过
（两者的区别见《04-语法/12-编译期能力.md》第 2 节）。
C++17 允许的非类型参数类型是一张固定的清单：

`文档`

> "A non-type template-parameter shall have one of the following (optionally cv-qualified) types:
> —(4.1) integral or enumeration type,
> —(4.2) pointer to object or pointer to function,
> —(4.3) lvalue reference to object or lvalue reference to function,
> —(4.4) pointer to member,
> —(4.5) std::nullptr_t, or
> —(4.6) a type that contains a placeholder type (10.1.7.4)."
>
> —— N4659 §17.1/4

## 3.2 成员模板

类里的成员函数自己也可以是模板。这解决的是「同一个类要处理多种类型」的问题：

`C++`

```cpp
/* member_template.cpp    编译：g++ -std=c++17 member_template.cpp -o member_template */
#include <cstdio>

class Printer {
public:
    template <class T>                          /* 成员函数自己是模板 */
    void show(const T &v) { print(v); }

    template <class T>
    void show_all(const T &a, const T &b) { print(a); print(b); }

private:
    void print(int x)         { std::printf("  int：%d\n", x); }
    void print(const char *s) { std::printf("  字符串：%s\n", s); }
    void print(double d)      { std::printf("  double：%.1f\n", d); }
};

int main() {
    Printer p;
    p.show(3);
    p.show("文本");
    p.show(1.25);
    p.show_all(1, 2);
    return 0;
}
```

`实测数据`
`Text`

```text
  int：3
  字符串：文本
  double：1.2
  int：1
  int：2
```

`Printer` 这个类本身不是模板，只有 `show` 与 `show_all` 是。
真正决定打印格式的是三个重载的 `print`——**模板负责把类型传下去，
重载负责按类型挑格式**（第 7 节）。这个组合在标准库里很常见。

## 3.3 模板参数的默认值

模板参数可以带默认值，规则与函数参数的默认值类似：

`文档`

> "A default template-argument is a template-argument (17.3) specified after = in a
> template-parameter. A default template-argument may be specified for any kind of
> template-parameter (type, non-type, template) that is not a template parameter pack (17.5.3)."
>
> —— N4659 §17.1/9

`C++`

```cpp
template <class T, class Alloc = Allocator<T>>    /* 第二个参数有默认值 */
class Vector { /* ... */ };

Vector<int>         a;      /* 等价于 Vector<int, Allocator<int>> */
Vector<int, MyAlloc> b;     /* 显式换掉 */
```

标准库容器正是这样写的：`std::vector<int>` 只需要写一个实参，
分配器那一个平时用不到，默认值把它藏了起来。

> [!NOTE]
> **非类型模板参数把「值」也变成模板参数，它必须是编译期常量。**
> 成员模板让一个类里的个别函数对多种类型成立；
> 模板参数的默认值让不常改的那几个参数在调用处消失。
> 三者的共同点是：所有信息都在编译期确定，生成出来的仍是各自独立的代码。

# 第 4 节 类模板

## 4.1 定义语法

函数模板把函数参数的类型留成参数，类模板把类里用到的某个类型留成参数。写法是在类定义前面加一行 `template` 头：

`文档`

> "A class template defines the layout and operations for an unbounded set of related types."
>
> —— N4659 §17.5.1/1

留出来的那个名字可以用在类里的多个位置：

| `T` 出现的位置 | 例子 |
|---|---|
| 数据成员的类型 | `T data_[N];` |
| 成员函数的参数与返回类型 | `void push(const T &v);`、`T pop();` |
| 成员别名 | `using value_type = T;`（第 4.5 小节） |
| 嵌套类 | `class Cursor { /* ... */ };`（第 4.7 小节） |
| 静态数据成员 | `static int alive_;`（第 4.7 小节） |

> [!IMPORTANT]
> **类模板不是类，是生成类的模板。** `Stack` 是模板名，不能用来定义对象；`Stack<int>` 才是类型。

`template <class T>` 与 `template <typename T>` 在这里没有区别（第 2.4 小节）。下面这个例子把上面几处都占上了，容量由非类型参数给出并带默认值：

`C++`

```cpp
/* stack_full.cpp    编译：g++ -std=c++17 stack_full.cpp -o stack_full */
#include <cstdio>
#include <string>

template <class T, int N = 8>               /* 类型参数 + 非类型参数，后者带默认值 */
class Stack {
public:
    using value_type = T;                   /* 成员别名：把 T 暴露给外面 */
    Stack() : top_(0) { ++alive_; }
    Stack(const Stack &o) : top_(o.top_) {   /* 拷贝构造：逐元素拷 */
        for (int i = 0; i < top_; ++i) data_[i] = o.data_[i];
        ++alive_;
    }
    ~Stack() { --alive_; }
    void push(const T &v) { if (top_ < N) data_[top_++] = v; }
    T   pop();                              /* 类外定义，见第 4.2 小节 */
    int size() const { return top_; }
    static int alive() { return alive_; }   /* 每个实例各有一份 */
private:
    T   data_[N];
    int top_;
    static int alive_;                      /* 静态成员：类外定义 */
};

template <class T, int N> int Stack<T, N>::alive_ = 0;      /* 注意 template 头要写全 */

template <class T, int N>                   /* 类外定义成员函数：template 头 + Stack<T, N>:: */
T Stack<T, N>::pop() {
    return data_[--top_];
}

int main() {
    {
        Stack<int> a;                       /* N 用默认值 8 */
        a.push(1); a.push(2); a.push(3);
        int popped = a.pop();
        std::printf("int 栈：size = %d，pop = %d，alive = %d\n", a.size(), popped, Stack<int>::alive());

        Stack<int> b = a;                   /* 拷贝：两个对象 */
        std::printf("拷贝后 alive = %d，sizeof(Stack<int>) = %zu\n", Stack<int>::alive(), sizeof(Stack<int>));

        Stack<double, 2> d;                 /* 另一个实例：不同的 N */
        d.push(1.5);
        std::printf("double 栈：alive = %d，sizeof = %zu\n", Stack<double, 2>::alive(), sizeof(Stack<double, 2>));

        Stack<std::string> s;               /* 第三个实例：元素换成 std::string */
        s.push("甲");
        std::printf("字符串栈：size = %d，sizeof = %zu\n", s.size(), sizeof(Stack<std::string>));
    }
    std::printf("全部析构后：int alive = %d，double alive = %d\n",
                Stack<int>::alive(), Stack<double, 2>::alive());
    return 0;
}
```

`实测数据`
`Text`

```text
int 栈：size = 2，pop = 3，alive = 1
拷贝后 alive = 2，sizeof(Stack<int>) = 36
double 栈：alive = 1，sizeof = 24
字符串栈：size = 1，sizeof = 264
全部析构后：int alive = 0，double alive = 0
```

三次实例化的大小互不相同，逐项对出来是这样：

| 实例 | 成员 | 合计 |
|---|---|---|
| `Stack<int>` | `int data_[8]`（32 字节）+ `int top_`（4 字节） | 36 |
| `Stack<double, 2>` | `double data_[2]`（16 字节）+ `int top_`（4 字节）+ 4 字节填充 | 24 |
| `Stack<std::string>` | `std::string data_[8]`（8 × 32 = 256 字节）+ `int top_`（4 字节）+ 4 字节填充 | 264 |

静态数据成员不属于对象，不计入 `sizeof`。`std::string` 在 64 位 libstdc++ 里占 32 字节，`Stack<std::string>` 的成员排布要按它的对齐要求走，于是多出 4 字节填充。

## 4.2 成员函数的两种写法

成员的声明留在类里，定义有两种放法。`Stack` 里两种都出现了：`push`、`size`、`alive` 写在类内，`pop` 与静态数据成员 `alive_` 写在类外。类内写法与普通类一样（《05-类与面向对象/02-类是一种类型.md》第 1.4 小节）。

`文档`

> "A member function of a class template may be defined outside of the class template definition in which it is declared."
>
> —— N4659 §17.5.1.1/1

类外定义要写两处，缺一处就报错（第 4.9 小节）：

`C++`

```cpp
template <class T, int N>                   /* 一：模板头重写一遍 */
T Stack<T, N>::pop() {                      /* 二：类名带上完整的实参表 */
    return data_[--top_];
}
```

静态数据成员的定义同样带模板头，类名后的实参表也要写全：写成 `Stack::alive_` 报 `used without template arguments`，表里少写一个参数报 `wrong number of template arguments`。成员模板定义在类外时则要写两个 `template` 头，第一个给类模板的参数，第二个给成员模板自己的参数（第 3.2 小节）。

## 4.3 每个实例是独立的类型

`Stack<int>`、`Stack<double, 2>`、`Stack<std::string>` 是三个不同的类，由同一个模板分别生成。模板实参不同就不是同一个类型；实参相同（包括默认实参补齐之后）才是同一个类型，所以 `Stack<int>` 与 `Stack<int, 8>` 之间可以互相拷贝，而 `Stack<double>` 与 `Stack<int>` 之间没有转换。

独立的类型可以直接体现为重载。同一个函数名对两个实例各写一份：

`C++`

```cpp
/* distinct_type.cpp    编译：g++ -std=c++17 distinct_type.cpp -o distinct_type */
#include <cstdio>

template <class T> class Box { public: T v_{}; };

void take(Box<int> b)  { std::printf("int 版：%d\n", b.v_); }
void take(Box<char> b) { std::printf("char 版：%c\n", b.v_); }

int main() {
    Box<int>  a; a.v_ = 65;
    Box<char> c; c.v_ = 'A';
    take(a);
    take(c);
    std::printf("sizeof(Box<int>) = %zu，sizeof(Box<char>) = %zu\n", sizeof(a), sizeof(c));
    return 0;
}
```

`实测数据`
`Text`

```text
int 版：65
char 版：A
sizeof(Box<int>) = 4，sizeof(Box<char>) = 1
```

两个实例只有成员类型不同，大小就分别是 4 与 1。反过来，把一个实例赋给另一个实例的类型不成立：编译器为 `Box<int>` 与 `Box<double>` 各生成了一份赋值运算符，两份都不接受对方的类型，报 `no match for 'operator=' (operand types are 'Box<int>' and 'Box<double>')`。要让两者互相转换，得自己写一个以对方类型为参数的构造函数或赋值运算符（《05-类与面向对象/05-拷贝与移动.md》第 2.3 小节）。

## 4.4 成员按需实例化

类模板被实例化时，生成的是成员的声明，不是定义。没有用到的成员函数不会生成代码，即使它的函数体对当前的 `T` 根本编不过：

`C++`

```cpp
/* lazy_member_fail.cpp    编译：g++ -std=c++17 lazy_member_fail.cpp -o lazy_member_fail （失败） */
template <class T>
class Box {
public:
    void bad() { v_.no_such_member(); }
    T v_{};
};

int main() {
    Box<int> b;
    b.bad();                            /* 一旦调用，这个成员就被实例化，错误出现 */
    return 0;
}
```

`实测数据`
`Text`

```text
lazy_member_fail.cpp: In instantiation of 'void Box<T>::bad() [with T = int]':
lazy_member_fail.cpp:11:10:   required from here
   11 |     b.bad();                            /* 一旦调用，这个成员就被实例化，错误出现 */
      |     ~~~~~^~
lazy_member_fail.cpp:5:21: error: request for member 'no_such_member' in '((Box<int>*)this)->Box<int>::v_', which is of non-class type 'int'
    5 |     void bad() { v_.no_such_member(); }
      |                  ~~~^~~~~~~~~~~~~~
```

`bad()` 的函数体只在被调用时才生成，把 `b.bad();` 这一行去掉，同一个类模板就能正常编译：`int` 没有 `no_such_member` 这件事，编译器在没有实例化它之前不会追究。第 5.1 小节给出了这类程序的完整例子与标准条文。

> [!WARNING]
> **模板体里的错误会被推迟到调用处。** 没被调用的成员不生成代码，编译期也就不会报错；等到有人调用，报错位置指向模板体内部，而不是调用它的那一行（第 8.3 小节）。

## 4.5 成员别名与 `typename`

成员别名把一个类型从类里引出来，让外面能写出「这个容器装的是什么」：

`C++`

```cpp
/* alias_outside.cpp    编译：g++ -std=c++17 alias_outside.cpp -o alias_outside */
#include <cstdio>

template <class T>
class Stack {
public:
    using value_type = T;               /* 成员别名 */
    value_type v_{};
};

template <class S>
void show(const S &s) {
    typename S::value_type x = s.v_;    /* 依赖名：必须写 typename（第 5.5 小节） */
    std::printf("值：%d\n", (int)x);
}

int main() {
    Stack<int> s;
    s.v_ = 7;
    show(s);
    std::printf("Stack<int>::value_type 就是 int：%zu\n", sizeof(Stack<int>::value_type));
    return 0;
}
```

`实测数据`
`Text`

```text
值：7
Stack<int>::value_type 就是 int：4
```

`show` 是函数模板，写它的时候还不知道 `S` 是什么，只能通过 `S::value_type` 拿到元素类型。`S::` 后面的名字是依赖名，前面要加 `typename`，否则报 `need 'typename' before ...`（第 5.5 小节）。标准库的每个容器都提供 `value_type`，泛型代码靠它取元素类型（容器本身见【待补：08-高阶数据结构/】）。

## 4.6 默认模板实参

模板参数可以带默认值，规则与函数参数的默认值相同（第 3.3 小节）。类模板里多一条：默认实参可以引用排在它前面的参数。

`C++`

```cpp
/* default_arg.cpp    编译：g++ -std=c++17 default_arg.cpp -o default_arg */
#include <cstdio>

template <class T> struct SmallBox { T v[4]; };
template <class T> struct BigBox   { T v[64]; };

template <class T, class Store = SmallBox<T>>   /* 默认实参可以引用前面的参数 */
class Holder {
public:
    Store s;
    int bytes() const { return (int)sizeof(Store); }
};

int main() {
    Holder<int> a;                      /* 用默认的 SmallBox<int> */
    Holder<int, BigBox<int>> b;         /* 显式换掉 */
    std::printf("a.bytes() = %d，b.bytes() = %d\n", a.bytes(), b.bytes());
    return 0;
}
```

`实测数据`
`Text`

```text
a.bytes() = 16，b.bytes() = 256
```

`Holder<int>` 与 `Holder<int, SmallBox<int>>` 是同一个类型，`Holder<int, BigBox<int>>` 是另一个。默认实参只能引用前面的参数，而且顺序不能反过来：

`文档`

> "If a template-parameter of a class template, variable template, or alias template has a default template-argument, each subsequent template-parameter shall either have a default template-argument supplied or be a template parameter pack."
>
> —— N4659 §17.1/11

`template <class T = int, class U>` 不成立：`U` 排在带默认值的 `T` 之后，自己却没有默认值，g++ 报 `no default argument for 'U'`。

## 4.7 嵌套类与静态成员

嵌套类也能用外围的 `T`，每个实例各有一份自己的嵌套类：

`C++`

```cpp
/* nested_in_template.cpp    编译：g++ -std=c++17 nested_in_template.cpp -o nested_in_template */
#include <cstdio>

template <class T>
class Outer {
public:
    class Inner {                       /* 嵌套类：也能用外围的 T */
    public:
        T twice(T v) const { return v + v; }
    };
    Inner make() const { return Inner{}; }
};

int main() {
    Outer<int> o;
    std::printf("Inner.twice(3) = %d\n", o.make().twice(3));
    Outer<double> od;
    std::printf("Inner.twice(1.5) = %.1f\n", od.make().twice(1.5));
    std::printf("sizeof(Outer<int>::Inner) = %zu\n", sizeof(Outer<int>::Inner));
    return 0;
}
```

`实测数据`
`Text`

```text
Inner.twice(3) = 6
Inner.twice(1.5) = 3.0
sizeof(Outer<int>::Inner) = 1
```

`Outer<int>::Inner` 的 `twice` 收 `int`，`Outer<double>::Inner` 的 `twice` 收 `double`，两者是不同的类型；`Inner` 没有数据成员，空类大小是 1 字节。嵌套类也可以定义在类外，规则与成员函数一样（N4659 §17.5.1.2/1）。静态成员则是每个实例各有一份：

`文档`

> "Each class template specialization instantiated from a template has its own copy of any static members."
>
> —— N4659 §17.7/6

第 4.1 小节的 `alive_` 就是这种情况：`Stack<int>` 与 `Stack<double, 2>` 各有一个 `alive_`，一组实例的构造与析构不影响另一组（第 5.6 小节）。

## 4.8 类模板实参推导（C++17 起）

C++17 起，可以从构造函数的实参推出模板实参，变量声明处不必写 `<...>`：

`C++`

```cpp
/* ctad.cpp    编译：g++ -std=c++17 ctad.cpp -o ctad */
#include <cstdio>
#include <typeinfo>

template <class T>
class Pair {
public:
    Pair(T a, T b) : a_(a), b_(b) {}
    T sum() const { return a_ + b_; }
private:
    T a_, b_;
};

template <class T>
class Box {
public:
    Box(T v) : v_(v) {}
    T v_;
};

Box(const char *) -> Box<const char *>;     /* 自定义推导指引（一般用不上） */

int main() {
    Pair p(1, 2);                   /* C++17：从构造函数实参推导出 Pair<int> */
    Box  b("abc");                  /* 推导 + 上面那条指引 */
    std::printf("p.sum() = %d，类型名 %s\n", p.sum(), typeid(p).name());
    std::printf("b.v_ = %s，类型名 %s\n", b.v_, typeid(b).name());
    return 0;
}
```

`实测数据`
`Text`

```text
p.sum() = 3，类型名 4PairIiE
b.v_ = abc，类型名 3BoxIPKcE
```

`Pair p(1, 2)` 推出 `Pair<int>`，`Box b("abc")` 推出 `Box<const char *>`。类型名那一列是 `typeid` 打印的修饰名：`4PairIiE` 里的 `4` 是名字长度，`IiE` 是实参表，整串读作 `Pair<int>`（名字修饰见【待补：07-更底层/】）。其中 `Box` 那一份用到了自定义推导指引，写法是 `Box(const char *) -> Box<const char *>;`，平时用不上。C++17 之前没有实参推导，同样的声明要写成 `Pair<int> p(1, 2);`。

推导的依据是构造函数：形参里出现过 `T` 才能推出来。若某个类模板的构造函数形参里没有 `T`（例如只写了一个默认构造函数），`Box b;` 这样的声明会报 `class template argument deduction failed`，随后是 `couldn't deduce template parameter 'T'`。

## 4.9 常见错误

**漏 `template` 头。** 类外定义成员函数时，第一行要重写模板头：

`C++`

```cpp
/* missing_head_fail.cpp    编译：g++ -std=c++17 missing_head_fail.cpp -o missing_head_fail （失败） */
template <class T>
class Stack {
public:
    const T &top() const;
private:
    T   data_[8];
    int top_ = 0;
};

const T &Stack<T>::top() const { return data_[top_ - 1]; }   /* 漏了 template <class T> */

int main() { return 0; }
```

`实测数据`
`Text`

```text
missing_head_fail.cpp:11:7: error: 'T' does not name a type
   11 | const T &Stack<T>::top() const { return data_[top_ - 1]; }   /* 漏了 template <class T> */
      |       ^
```

**漏 `<T>`。** `Stack` 只是模板名，不是类型，类名后面的实参表不能省：

`C++`

```cpp
/* missing_angle_fail.cpp    编译：g++ -std=c++17 missing_angle_fail.cpp -o missing_angle_fail （失败） */
template <class T>
class Stack {
public:
    const T &top() const;
private:
    T   data_[8];
    int top_ = 0;
};

template <class T>
const T &Stack::top() const { return data_[top_ - 1]; }      /* 漏了 <T>：Stack 只是模板名 */

int main() { return 0; }
```

`实测数据`
`Text`

```text
missing_angle_fail.cpp:12:10: error: 'template<class T> class Stack' used without template arguments
   12 | const T &Stack::top() const { return data_[top_ - 1]; }      /* 漏了 <T>：Stack 只是模板名 */
      |          ^~~~~
missing_angle_fail.cpp:12:23: error: non-member function 'const T& top()' cannot have cv-qualifier
   12 | const T &Stack::top() const { return data_[top_ - 1]; }      /* 漏了 <T>：Stack 只是模板名 */
      |                       ^~~~~
missing_angle_fail.cpp: In function 'const T& top()':
missing_angle_fail.cpp:12:38: error: 'data_' was not declared in this scope [-Wtemplate-body]
（后面还有 6 行，是 `top_` 未声明的同类报错与源码回显）
```

**类外定义的参数表没写全。** 模板头的参数表要与类模板一致：

`C++`

```cpp
/* wrong_arity_fail.cpp    编译：g++ -std=c++17 wrong_arity_fail.cpp -o wrong_arity_fail （失败） */
template <class T, int N>
class Stack {
public:
    T   pop();
private:
    T   data_[N];
    int top_ = 0;
};

template <class T>                          /* 参数表里少了 N */
T Stack<T>::pop() { return data_[--top_]; }

int main() { return 0; }
```

`实测数据`
`Text`

```text
wrong_arity_fail.cpp:12:10: error: wrong number of template arguments (1, should be 2)
   12 | T Stack<T>::pop() { return data_[--top_]; }
      |          ^
wrong_arity_fail.cpp:3:7: note: provided for 'template<class T, int N> class Stack'
    3 | class Stack {
      |       ^~~~~
wrong_arity_fail.cpp: In function 'T pop()':
（后面还有 6 行，是 `data_`、`top_` 未声明的同类报错）
```

三处都出在类外定义的那一行，报错却落在函数体里：

| 写法 | 第一条报错 | 改法 |
|---|---|---|
| 漏 `template <class T>` | `'T' does not name a type` | 类外定义前补上模板头 |
| 漏 `<T>` | `'template<class T> class Stack' used without template arguments` | 类名后写全实参表 |
| 参数表写少 | `wrong number of template arguments (1, should be 2)` | 与类模板的参数表对齐 |

> [!NOTE]
> **类模板把类型参数化：定义时用 `T`，使用时写全 `<...>`，类外定义时模板头与 `类名<T>::` 两处都要写。**
> 成员按需实例化，静态成员与嵌套类各实例一份；成员别名把元素类型暴露给外面，
> 默认实参可以引用前面的参数，C++17 起还能从构造函数实参推出模板实参。

写完一个类模板，逐条对照：

| 检查 | 说明 |
|---|---|
| 类外定义处重写 `template` 头了吗 | 漏写报 `'T' does not name a type`（第 4.9 小节） |
| 类名后写全实参表了吗 | 漏写报 `used without template arguments`（第 4.9 小节） |
| 模板头里的参数表与类模板一致吗 | 数量与种类要对上，名字可以不同（第 4.2 小节） |
| 静态数据成员在类外定义了吗 | 只声明会在链接期报 `undefined reference`（第 4.1 小节） |
| 元素类型要不要用 `value_type` 暴露出去 | 泛型代码靠它取元素类型（第 4.5 小节） |
| 默认实参引用前面的参数了吗 | 后面的参数都要有默认值（第 4.6 小节） |
| 用到 `T` 的哪些成员，每种实参都满足吗 | 不满足的部分等调用时才报错（第 4.4 小节） |
| 两个实例之间需要相互转换吗 | 需要就自己写构造函数或赋值运算符（第 4.3 小节） |
| 变量声明处能省掉 `<...>` 吗 | C++17 起可以，前提是构造函数里有这些参数（第 4.8 小节） |

# 第 5 节 实例化

## 5.1 隐式实例化：什么时候生成代码

编译器不会把模板里所有内容都提前生成出来，它按需要生成：

`文档`

> "Unless a class template specialization has been explicitly instantiated (17.7.2) or explicitly
> specialized (17.7.3), the class template specialization is implicitly instantiated when the
> specialization is referenced in a context that requires a completely-defined object type or when
> the completeness of the class type affects the semantics of the program."
>
> —— N4659 §17.7.1/1
>
> "Unless a function template specialization has been explicitly instantiated or explicitly
> specialized, the function template specialization is implicitly instantiated when the
> specialization is referenced in a context that requires a function definition to exist."
>
> —— N4659 §17.7.1/4

类模板的触发条件是「需要一个完整类型」，函数模板的触发条件是「需要一个函数定义」。
类模板被实例化时，**成员函数的定义并不会跟着生成**：

`文档`

> "The implicit instantiation of a class template specialization causes the implicit instantiation
> of the declarations, but not of the definitions, default arguments, or noexcept-specifiers of the
> class member functions, member classes, scoped member enumerations, static data members, member
> templates, and friends; ..."
>
> —— N4659 §17.7.1/2

这条规则可以直接观察到：下面这个类模板里有一个永远无法通过编译的成员函数，
但只要不调用它，程序照样能通过编译。

`C++`

```cpp
/* lazy_instantiation.cpp    编译：g++ -std=c++17 lazy_instantiation.cpp -o lazy_instantiation */
#include <cstdio>

template <class T>
class Box {
public:
    void ok()  { std::printf("ok() 被调用\n"); }
    void bad() { T x; x.no_such_member(); }     /* T 不支持就编不过，但没用到就不生成 */
};

int main() {
    Box<int> b;                                 /* 类模板实例化：成员函数的声明也实例化 */
    b.ok();                                     /* 只实例化用到的那个成员函数 */
    std::printf("sizeof(Box<int>) = %zu\n", sizeof(b));
    return 0;
}
```

`实测数据`
`Text`

```text
ok() 被调用
sizeof(Box<int>) = 1
```

`bad()` 里的 `x.no_such_member()` 对 `int` 不成立，可是它没有被实例化，
编译器也就不会报错。**代价是错误被推迟**：真正调用 `b.bad()` 时才会报错，
而那时报错的位置会指向模板体内部（第 8.3 小节）。
`sizeof(Box<int>)` 是 1，因为 `Box` 没有任何数据成员——空类的大小是 1 字节。

## 5.2 显式实例化

生成代码的时机也可以由写代码的人指定，这叫**显式实例化**：

`文档`

> "A class, function, variable, or member template specialization can be explicitly instantiated
> from its template. A member function, member class or static data member of a class template can
> be explicitly instantiated from the member definition associated with its class template. An
> explicit instantiation of a function template or member function of a class template shall not
> use the inline or constexpr specifiers."
>
> —— N4659 §17.7.2/1
>
> "The syntax for explicit instantiation is: explicit-instantiation: extern_opt template
> declaration ... There are two forms of explicit instantiation: an explicit instantiation
> definition and an explicit instantiation declaration. An explicit instantiation declaration
> begins with the extern keyword."
>
> —— N4659 §17.7.2/2

写法是在 `template` 后面直接写类型，没有尖括号：

`C++`

```cpp
template class Stack<int>;          /* 显式实例化定义：就在这里生成 Stack<int> 那一份 */
extern template class Stack<int>;   /* 显式实例化声明：这里不生成，别处有 */
```

它最常见的用途，是让模板的定义不必暴露在头文件里。下面三个文件就是这样一组：

`C++`

```cpp
/* tmpl_stack.h    模板的声明（定义故意不放在这里） */
#pragma once

template <class T>
class Stack {
public:
    Stack();
    void push(const T &v);
    T    pop();
    int  size() const;
private:
    T   data_[8];
    int top_;
};
```

`C++`

```cpp
/* tmpl_impl.cpp    编译：g++ -std=c++17 -c tmpl_impl.cpp -o tmpl_impl.o */
#include "tmpl_stack.h"

template <class T> Stack<T>::Stack() : top_(0) {}
template <class T> void Stack<T>::push(const T &v) { if (top_ < 8) data_[top_++] = v; }
template <class T> T Stack<T>::pop() { return data_[--top_]; }
template <class T> int Stack<T>::size() const { return top_; }
```

`C++`

```cpp
/* tmpl_main.cpp    编译：g++ -std=c++17 -c tmpl_main.cpp -o tmpl_main.o（链接见正文） */
#include <cstdio>
#include "tmpl_stack.h"

int main() {
    Stack<int> s;
    s.push(1);
    std::printf("size = %d\n", s.size());
    return 0;
}
```

两个源文件各自编译都通过，链接时才发现问题：

`Bash`

```bash
g++ -std=c++17 -c tmpl_impl.cpp -o tmpl_impl.o
g++ -std=c++17 -c tmpl_main.cpp -o tmpl_main.o
g++ -std=c++17 tmpl_main.o tmpl_impl.o -o tmpl_main
```

`实测数据`
`Text`

```text
tmpl_main.o:tmpl_main.cpp:(.text+0x15): undefined reference to `Stack<int>::Stack()'
tmpl_main.o:tmpl_main.cpp:(.text+0x2c): undefined reference to `Stack<int>::push(int const&)'
tmpl_main.o:tmpl_main.cpp:(.text+0x38): undefined reference to `Stack<int>::size() const'
collect2.exe: error: ld returned 1 exit status
```

`tmpl_main.cpp` 里只有声明，编译器生成不出 `Stack<int>` 的成员函数；
`tmpl_impl.cpp` 里有定义，可它没有被要求生成 `Stack<int>` 那一份，于是谁也没生成。
在 `tmpl_impl.cpp` 末尾加一行显式实例化，问题就消失：

`C++`

```cpp
/* tmpl_impl2.cpp    编译：g++ -std=c++17 tmpl_impl2.cpp -o tmpl_impl2 （加了显式实例化） */
#include <cstdio>
#include "tmpl_stack.h"

template <class T> Stack<T>::Stack() : top_(0) {}
template <class T> void Stack<T>::push(const T &v) { if (top_ < 8) data_[top_++] = v; }
template <class T> T Stack<T>::pop() { return data_[--top_]; }
template <class T> int Stack<T>::size() const { return top_; }

template class Stack<int>;          /* 显式实例化：就在这里把 int 那一份生成出来 */

int main() {
    Stack<int> s;
    s.push(1);
    std::printf("size = %d\n", s.size());
    return 0;
}
```

`实测数据`
`Text`

```text
size = 1
```

这条路线适合「只打算支持少数几种类型」的库：类型清单是已知的，
在实现文件里逐个列出，头文件只留声明。

> [!WARNING]
> **模板的定义放在 `.cpp` 里，编译期不会报错，链接期才报 `undefined reference`。**
> 报错信息里是 `Stack<int>::push(int const&)` 这样的名字，
> 与头文件里的声明写法不同，第一次遇到不容易对上（《01-编译器/01-编译与链接.md》第 2.5 小节）。
> 一个显式实例化定义在一个程序里只能出现一次，否则会出现重复定义。

`文档`

> "For a given template and a given set of template-arguments, —(5.1) an explicit
> instantiation definition shall appear at most once in a program, —(5.2) an explicit
> specialization shall be defined at most once in a program (according to 6.2), and —(5.3)
> both an explicit instantiation and a declaration of an explicit specialization shall not
> appear in a program unless the explicit instantiation follows a declaration of the explicit
> specialization. An implementation is not required to diagnose a violation of this rule."
>
> —— N4659 §17.7/5

## 5.3 为什么模板通常写在头文件里

标准把这件事规定得很直接：

`文档`

> "A function template, member function of a class template, variable template, or static data
> member of a class template shall be defined in every translation unit in which it is implicitly
> instantiated (17.7.1) unless the corresponding specialization is explicitly instantiated (17.7.2)
> in some translation unit; no diagnostic is required."
>
> —— N4659 §17/7

「每个用到它的翻译单元里都要有定义」，加上「编译器按需生成」，
两条合起来就是那句常见的经验：**模板的定义要写在头文件里**。
每个包含这个头文件的源文件都会自己生成一份实例，链接时再把重复的合并掉。

下面两个源文件都包含同一个头文件，都用 `int` 调用同一个模板：

`C++`

```cpp
/* tmpl_shared.h    两个翻译单元共用的头文件（模板定义就在这里） */
#pragma once
#include <cstddef>

template <class T>
T sum_all(const T *p, std::size_t n) {
    T s = 0;
    for (std::size_t i = 0; i < n; ++i) s += p[i];
    return s;
}
```

`C++`

```cpp
/* tu_a.cpp    编译：g++ -std=c++17 -c tu_a.cpp -o tu_a.o */
#include "tmpl_shared.h"

int use_a() { int a[4] = {1, 2, 3, 4}; return (int)sum_all(a, 4); }
```

`C++`

```cpp
/* tu_b.cpp    编译：g++ -std=c++17 -c tu_b.cpp -o tu_b.o */
#include "tmpl_shared.h"

int use_b() { int b[3] = {5, 6, 7}; return (int)sum_all(b, 3); }
```

`C++`

```cpp
/* tu_main.cpp    编译：g++ -std=c++17 -c tu_main.cpp -o tu_main.o（链接见正文） */
#include <cstdio>

int use_a();
int use_b();

int main() {
    std::printf("use_a() = %d，use_b() = %d\n", use_a(), use_b());
    return 0;
}
```

`Bash`

```bash
g++ -std=c++17 -c tu_a.cpp -o tu_a.o
g++ -std=c++17 -c tu_b.cpp -o tu_b.o
g++ -std=c++17 -c tu_main.cpp -o tu_main.o
g++ -std=c++17 tu_main.o tu_a.o tu_b.o -o tu_main
```

`实测数据`
`Text`

```text
tu_a.o 里的 sum_all 符号：
    0000000000000000 T int sum_all<int>(int const*, unsigned long long)
tu_b.o 里的 sum_all 符号：
    0000000000000000 T int sum_all<int>(int const*, unsigned long long)
链接：退出码 0
运行输出：use_a() = 10，use_b() = 18
链接后的可执行文件里，sum_all 的代码只剩一处：
    0000000140008440 T int sum_all<int>(int const*, unsigned long long)
```

两个目标文件里各有一份 `sum_all<int>` 的机器码，链接之后只剩一份。
**重复生成由编译器负责，合并由链接器负责**，写代码的人不必操心，
但要为「每个翻译单元都多编译一遍」付出时间（第 8.2 小节）。

> [!TIP]
> **模板的定义与声明一起放进头文件**，这是默认做法。
> 只有两种情况例外：一是希望把实现藏起来，且类型清单已知（第 5.2 小节的显式实例化）；
> 二是模板只在本文件里用，那就把它放进匿名命名空间或写成 `static`
> （《04-语法/11-作用域、生存期与链接.md》第 4 节）。

## 5.4 两阶段名字查找

模板体里的名字分两类，查找的时机不同：

| 名字 | 什么时候查 | 例子 |
|---|---|---|
| **非依赖名**：与模板参数无关 | 定义模板时 | 函数名、类型名、全局变量 |
| **依赖名**：与模板参数有关 | 实例化时 | `T::value_type`、`x.foo()` |

`文档`

> "Non-dependent names used in a template definition are found using the usual name lookup and
> bound at the point they are used."
>
> —— N4659 §17.6.3/1
>
> "Such names are unbound and are looked up at the point of the template instantiation (17.6.4.1)
> in both the context of the template definition and the context of the point of instantiation."
>
> —— N4659 §17.6.2/1

这条规则有个直接的后果：**在模板定义之后才声明的函数，模板体里看不到**。

`C++`

```cpp
/* two_phase.cpp    编译：g++ -std=c++17 two_phase.cpp -o two_phase （失败） */
#include <cstdio>

template <class T>
void call(T v) {
    helper(v);                  /* 非依赖名：定义时就要求能找到 helper */
}

void helper(int x) { std::printf("%d\n", x); }   /* 声明得太晚了 */

int main() {
    call(1);
    return 0;
}
```

`实测数据`
`Text`

```text
two_phase.cpp: In instantiation of 'void call(T) [with T = int]':
two_phase.cpp:12:9:   required from here
   12 |     call(1);
      |     ~~~~^~~
two_phase.cpp:6:11: error: 'helper' was not declared in this scope, and no declarations were found by argument-dependent lookup at the point of instantiation [-fpermissive]
    6 |     helper(v);                  /* 非依赖名：定义时就要求能找到 helper */
      |     ~~~~~~^~~
two_phase.cpp:9:6: note: 'void helper(int)' declared here, later in the translation unit
```

编译器把话说得很清楚：`helper` 在定义 `call` 时找不到，
而在实例化点通过实参依赖查找（argument-dependent lookup，简称 ADL）也找不到——
`int` 是基本类型，没有关联的命名空间可供查找。

改法有两条：

| 改法 | 说明 |
|---|---|
| 把 `helper` 的声明挪到模板定义之前 | 非依赖名在定义时就能绑上 |
| 让调用变成依赖调用 | 例如把参数换成类类型，ADL 会到那个类所在的命名空间里去找（《05-类与面向对象/01-命名空间与 using.md》第 3 节） |

反过来，依赖名要等到实例化时才查，所以模板体里可以写当时还不存在的成员——
`T::value_type`、`x.foo()` 都是这样。这是模板能对「还没见到的类型」生效的原因。

## 5.5 依赖名与 `typename`

依赖名有一条容易出错的规则：**编译器默认它不是一个类型**。

`文档`

> "A name used in a template declaration or definition and that is dependent on a
> template-parameter is assumed not to name a type unless the applicable name lookup finds a type
> name or the name is qualified by the keyword typename."
>
> —— N4659 §17.6/2

`T::value_type` 里的 `T` 还没定下来，`T::value_type` 可能是类型，
也可能是 `T` 里的一个静态成员。编译器按「不是类型」处理，于是这一行无法通过编译：

`C++`

```cpp
/* typename_fail.cpp    编译：g++ -std=c++17 typename_fail.cpp -o typename_fail （失败） */
class Holder {
public:
    using value_type = int;
    static value_type get() { return 7; }
};

template <class T>
T::value_type read() { return T::get(); }        /* T::value_type 是依赖名 */

int main() {
    return read<Holder>();
}
```

`实测数据`
`Text`

```text
typename_fail.cpp:9:1: error: need 'typename' before 'T::value_type' because 'T' is a dependent scope
    9 | T::value_type read() { return T::get(); }        /* T::value_type 是依赖名 */
      | ^
      | typename
typename_fail.cpp: In function 'int main()':
typename_fail.cpp:12:12: error: 'read' was not declared in this scope
```

编译器甚至把补丁写在了报错里（`| typename`）。加上关键字即可：

`C++`

```cpp
/* typename_ok.cpp    编译：g++ -std=c++17 typename_ok.cpp -o typename_ok */
#include <cstdio>

class Holder {
public:
    using value_type = int;
    static value_type get() { return 7; }
};

template <class T>
typename T::value_type read() { return T::get(); }   /* 加 typename 告诉编译器这是个类型 */

int main() {
    std::printf("read<Holder>() = %d\n", read<Holder>());
    return 0;
}
```

`实测数据`
`Text`

```text
read<Holder>() = 7
```

标准的要求写在 §17.6/3：

`文档`

> "When a qualified-id is intended to refer to a type that is not a member of the current
> instantiation (17.6.2.1) and its nested-name-specifier refers to a dependent type, it shall be
> prefixed by the keyword typename, forming a typename-specifier. If the qualified-id in a
> typename-specifier does not denote a type or a class template, the program is ill-formed."
>
> —— N4659 §17.6/3

> [!WARNING]
> **`T::` 后面跟的名字，只要它是类型就要写 `typename`。**
> 漏写时 g++ 的报错是 `need 'typename' before ... because 'T' is a dependent scope`，
> 照着补上即可；写多了（在不该写的地方写）同样会报错。
> 常见的遗漏位置是返回类型、参数类型、局部变量声明，以及 `using` 别名。

## 5.6 每个实例各有一份

模板生成代码的单位是「一个实例」，函数体、静态变量、成员函数都在内。
函数模板里的局部静态变量可以证明这一点：

`C++`

```cpp
/* one_per_type.cpp    编译：g++ -std=c++17 one_per_type.cpp -o one_per_type */
#include <cstdio>

template <class T>
int &slot() {                                   /* 模板里的局部静态变量 */
    static int v = 0;
    return v;
}

int main() {
    slot<int>()    = 11;
    slot<double>() = 22;

    std::printf("两处地址：%p 和 %p\n", (void *)&slot<int>(), (void *)&slot<double>());
    std::printf("是同一块内存吗：%s\n",
                (void *)&slot<int>() == (void *)&slot<double>() ? "是" : "否");
    std::printf("两个值：%d 和 %d\n", slot<int>(), slot<double>());
    return 0;
}
```

`实测数据`
`Text`

```text
两处地址：00007ff668a79110 和 00007ff668a79100
是同一块内存吗：否
两个值：11 和 22
```

两个地址不同，两个值互不影响。`slot<int>()` 与 `slot<double>()` 是两份独立的函数，
各自的静态变量也是各自的一份——这与普通函数里的静态变量只有一份
（《04-语法/11-作用域、生存期与链接.md》第 3.2 小节）形成对照。

地址的具体数值每次都不同（与加载基址有关），这里看的是「两个地址不相等」这一条。

# 第 6 节 特化

## 6.1 全特化

模板对某个类型有特殊做法时，可以为它单独写一份实现，这叫**全特化**：

`文档`

> "An explicit specialization of any of the following: —(1.1) function template —(1.2) class
> template —(1.3) variable template —(1.4) member function of a class template ... can be declared
> by a declaration introduced by template<>; that is: explicit-specialization: template < >
> declaration"
>
> —— N4659 §17.7.3/1

`C++`

```cpp
/* overload_vs_template.cpp    编译：g++ -std=c++17 overload_vs_template.cpp -o overload_vs_template */
#include <cstdio>
#include <cstring>

template <class T>
const T &max_of(const T &a, const T &b) {
    std::printf("  走模板：");
    return a > b ? a : b;
}

const char *max_of(const char *a, const char *b) {   /* 非模板：优先被选中 */
    std::printf("  走非模板重载：");
    return std::strcmp(a, b) > 0 ? a : b;
}

template <>
const char *const &max_of<const char *>(const char *const &a, const char *const &b) {
    std::printf("  走全特化：");                      /* 全特化 */
    return std::strcmp(a, b) > 0 ? a : b;
}

int main() {
    std::printf("%d\n", max_of(3, 5));                       /* 模板 */
    std::printf("%s\n", max_of("ab", "cd"));                 /* 非模板优先 */
    std::printf("%s\n", max_of<const char *>("ab", "cd"));   /* 显式指定：落到全特化 */
    return 0;
}
```

`实测数据`
`Text`

```text
  走模板：5
  走非模板重载：cd
  走全特化：cd
```

三行输出对应三种选择，第 7 节会说明为什么第二行走的是非模板那一份。
第三行值得注意：**只有显式写出 `<const char *>` 时全特化才被选中**，
因为非模板函数在重载决议里排在模板之前。

写全特化有两个容易错的地方：

| 规则 | 说明 |
|---|---|
| 语法是 `template <>`，尖括号里空的 | 所有模板参数都被填满了，所以没有参数可写 |
| 特化的返回类型必须与主模板**完全一致** | 主模板返回 `const T &`，特化就要返回 `const char *const &`，写 `const char *` 会报「与主模板不匹配」 |

第二条是实践中最容易卡住的地方：特化不是重载，它替换的是同一个函数，
签名必须逐字对上，只是类型已经填好。

## 6.2 类模板偏特化

类模板还可以只固定一部分参数，这叫**偏特化**（partial specialization）：

`文档`

> "A primary class template declaration is one in which the class template name is an identifier.
> A template declaration in which the class template name is a simple-template-id is a partial
> specialization of the class template named in the simple-template-id. A partial specialization of
> a class template provides an alternative definition of the template that is used instead of the
> primary definition when the arguments in a specialization match those given in the partial
> specialization (17.5.5.1)."
>
> —— N4659 §17.5.5/1

`C++`

```cpp
/* partial_class.cpp    编译：g++ -std=c++17 partial_class.cpp -o partial_class */
#include <cstdio>

template <class T>
class Wrapper {
public:
    const char *kind() const { return "通用版本"; }
};

template <class T>
class Wrapper<T *> {                    /* 类模板可以偏特化：只对指针这一族 */
public:
    const char *kind() const { return "指针特化"; }
};

template <class T>
class Wrapper<T &> {                    /* 再来一个：引用这一族 */
public:
    const char *kind() const { return "引用特化"; }
};

int main() {
    Wrapper<int>   a;
    Wrapper<int *> b;
    Wrapper<int &> c;
    std::printf("%s / %s / %s\n", a.kind(), b.kind(), c.kind());
    return 0;
}
```

`实测数据`
`Text`

```text
通用版本 / 指针特化 / 引用特化
```

`Wrapper<T *>` 里的 `T` 仍然是一个参数，只是把「必须是指针」这个条件写进了类名。
偏特化在标准库里用得很多：`std::vector<bool>` 是一份压缩存储的偏特化，
各种 `std::hash<T>`、`std::iterator_traits<T *>` 也是。

## 6.3 函数模板为什么不能偏特化

同样的写法用在函数模板上不成立：

`C++`

```cpp
/* partial_func_fail.cpp    编译：g++ -std=c++17 partial_func_fail.cpp -o partial_func_fail （失败） */
template <class T>
const char *kind_of(T) { return "通用"; }

template <class T>
const char *kind_of<T *>(T *) { return "指针"; }   /* 想写成偏特化：函数模板不允许 */

int main() {
    int x = 0;
    return kind_of(&x)[0];
}
```

`实测数据`
`Text`

```text
partial_func_fail.cpp:6:13: error: non-class, non-variable partial specialization 'kind_of<T*>' is not allowed
    6 | const char *kind_of<T *>(T *) { return "指针"; }   /* 想写成偏特化：函数模板不允许 */
      |             ^~~~~~~~~~~~
```

原因在语法层：函数模板的名字后面不允许再跟尖括号形式的参数表。

`文档`

> "In a function template declaration, the last component of the declarator-id shall not be a
> template-id."
>
> —— N4659 §17/2

函数模板**可以**全特化（`template <> const char *kind_of<char *>(char *)`），
只是不能偏特化。需要「对某一族类型另作处理」时，改用重载：

`C++`

```cpp
/* partial_func_overload.cpp    编译：g++ -std=c++17 partial_func_overload.cpp -o partial_func_overload */
#include <cstdio>

template <class T>
const char *kind_of(T) { return "通用"; }

template <class T>
const char *kind_of(T *) { return "指针"; }      /* 这是重载，不是偏特化 */

int main() {
    int x = 0;
    std::printf("%s / %s\n", kind_of(1), kind_of(&x));
    return 0;
}
```

`实测数据`
`Text`

```text
通用 / 指针
```

两个同名函数模板构成重载，调用时先做重载决议，再做**偏序**：
两个都匹配时，选更特殊的那一个。标准把这件事叫函数模板的偏序：

`文档`

> "Partial ordering selects which of two function templates is more specialized than the other by
> transforming each template in turn (see next paragraph) and performing template argument
> deduction using the function type. The deduction process determines whether one of the templates
> is more specialized than the other. If so, the more specialized template is the one chosen by the
> partial ordering process."
>
> —— N4659 §17.5.6.2/2

`kind_of(T *)` 比 `kind_of(T)` 更特殊，传指针时它胜出。

> [!IMPORTANT]
> **全特化替换同一个模板的一份实现，签名必须与主模板逐字一致；
> 偏特化只能用在类模板上。** 函数模板要对某一族类型另作处理时，
> 写成另一个重载，由偏序决定谁更合适。

# 第 7 节 模板与重载决议

普通函数、模板特化、模板都参与同一次重载决议，排序规则里专门有一条给模板：

`文档`

> "—(1.6) F1 is not a function template specialization and F2 is a function template
> specialization, or, if not that,
> —(1.7) F1 and F2 are function template specializations, and the function template for F1 is more
> specialized than the template for F2 according to the partial ordering rules described in
> 17.5.6.2, or, if not that,"
>
> —— N4659 §16.3.3/1

读法是：**两个候选在所有其他方面一样好时，非模板函数优先**；
两个都是模板时，更特殊的那个优先。这条规则解释了第 6.1 小节的三行输出：

| 调用 | 候选 | 选中 | 依据 |
|---|---|---|---|
| `max_of(3, 5)` | 模板 | 模板 | 只有它匹配 |
| `max_of("ab", "cd")` | 模板、非模板 | **非模板** | (1.6)：非模板优先 |
| `max_of<const char *>("ab", "cd")` | 全特化、非模板 | **全特化** | 显式指定模板实参之后，非模板函数不参与（它没有模板参数可填） |

第三条容易记错成「显式指定也走非模板」。真实情况是：
`max_of<const char *>` 这个写法只能指名模板，非模板函数根本没有模板参数表，
于是候选集合里只剩模板与它的全特化，全特化更特殊，胜出。

重载决议本身的规则（精确匹配优先于提升、提升优先于转换、二义怎么判）
在《05-类与面向对象/08-多态：重载、虚函数与它们的分工.md》第 2 节。
模板只是给这次排序多加了 (1.6) 与 (1.7) 两条，其余部分完全一样。

> [!IMPORTANT]
> **模板不改变重载决议，只是在排序表的末尾多了两条：非模板优先，更特殊的模板优先。**
> 因此写模板时不必担心它会抢走普通函数的调用；
> 反过来，想让自己写的特化被选中，要么显式指定模板实参，要么让它比主模板更特殊。

# 第 8 节 代价与边界

## 8.1 代码膨胀

每个实例一份代码，类型多了代码就多。下面两份源码除了「用了几种类型」以外完全相同：

`C++`

```cpp
/* bloat_one.cpp    编译：g++ -std=c++17 -c bloat_one.cpp -o bloat_one.o */
#include <cstddef>

template <class T>
T sum_all(const T *p, std::size_t n) {          /* 同一个模板 */
    T s = 0;
    for (std::size_t i = 0; i < n; ++i) s += p[i];
    return s;
}

template int sum_all<int>(const int *, std::size_t);   /* 实例化 1 种类型 */

int main() {
    int a[4] = {1, 2, 3, 4};
    return (int)sum_all<int>(a, 4);             /* 只用 int，量的是目标文件 */
}
```

`C++`

```cpp
/* bloat_many.cpp    编译：g++ -std=c++17 -c bloat_many.cpp -o bloat_many.o */
#include <cstddef>

template <class T>
T sum_all(const T *p, std::size_t n) {          /* 同一个模板 */
    T s = 0;
    for (std::size_t i = 0; i < n; ++i) s += p[i];
    return s;
}

template char sum_all<char>(const char *, std::size_t);            /* 实例化 12 种类型 */
template short sum_all<short>(const short *, std::size_t);
template int sum_all<int>(const int *, std::size_t);
template long sum_all<long>(const long *, std::size_t);
template long long sum_all<long long>(const long long *, std::size_t);
template unsigned sum_all<unsigned>(const unsigned *, std::size_t);
template float sum_all<float>(const float *, std::size_t);
template double sum_all<double>(const double *, std::size_t);
template long double sum_all<long double>(const long double *, std::size_t);
template wchar_t sum_all<wchar_t>(const wchar_t *, std::size_t);
template char16_t sum_all<char16_t>(const char16_t *, std::size_t);
template char32_t sum_all<char32_t>(const char32_t *, std::size_t);

int main() {
    int a[4] = {1, 2, 3, 4};
    return (int)sum_all<int>(a, 4);             /* 只用 int，量的是目标文件 */
}
```

`实测数据`

| 程序 | 实例化的类型数 | 目标文件大小 | `sum_all` 相关符号 |
|---|---|---|---|
| `bloat_one.cpp` | 1 | 1434 字节 | 4 个 |
| `bloat_many.cpp` | 12 | 8136 字节 | 48 个 |

模板体只有四行，12 种类型就让目标文件涨到接近 6 倍。
真实项目里的模板体动辄几十行，再加上标准库容器与算法层层嵌套，
同一个模板被实例化成几十份是常态。

| 情况 | 会不会膨胀 |
|---|---|
| 同一份源码，类型越多 | 会，每个实例一份 |
| 同一个实例在多个翻译单元里出现 | 不会，链接时合并（第 5.3 小节） |
| 同一份源码被多个类型用到，但都走同一条分支 | 会，编译器为每个类型各生成一份 |

## 8.2 编译时间

实例化是编译期的工作，实例多了编译就慢。用同一个模板做两组对照，
两份源码的函数个数与行数完全相同，只有类型不同：

`C++`

```cpp
template <int K>
struct Num {                            /* 只为造出 400 个互不相同的类型 */
    int v;
    Num(int x = 0) : v(x) {}
    Num &operator+=(const Num &o) { v += o.v; return *this; }
};

template <class T>
T sum_all(const T *p, std::size_t n) {  /* 被实例化的那个模板 */
    T s = 0;
    for (std::size_t i = 0; i < n; ++i) { /* ... 若干行运算 ... */ }
    return s;
}
```

`C++`

```cpp
/* 第一份（timed_one.cpp）：400 个函数全用同一个类型 */
int use_0() { Num<0> a[4]; return sum_all(a, 4).v; }
int use_1() { Num<0> a[4]; return sum_all(a, 4).v; }
/* ... 共 400 个，全部用 Num<0> */
```

`C++`

```cpp
/* 第二份（timed_many.cpp）：400 个函数各用一个类型 */
int use_0() { Num<0>   a[4]; return sum_all(a, 4).v; }
int use_1() { Num<1>   a[4]; return sum_all(a, 4).v; }
/* ... 共 400 个，分别用 Num<0> 到 Num<399> */
```

`实测数据`

| 源码 | 实例化份数 | 编译时间（三次里最快） |
|---|---|---|
| `timed_one.cpp` | 1 | 229 毫秒 |
| `timed_many.cpp` | 400 | 740 毫秒 |

同样多的代码、同样多的调用点，多出来的时间全部花在实例化上。
这个差距在大项目里会继续放大：头文件里放一个大模板，
每个包含它的源文件都要重新解析并实例化一遍（第 5.3 小节）。

## 8.3 报错为什么难读

模板的报错长，是因为编译器要把「从哪一步开始出错」讲清楚。
下面这个程序里，`NoCompare` 没有 `operator>`：

`C++`

```cpp
/* error_wall.cpp    编译：g++ -std=c++17 error_wall.cpp -o error_wall （失败） */
#include <cstdio>

struct NoCompare { int v; };            /* 没有 operator< 也没有 operator> */

template <class T>
const T &max_of(const T &a, const T &b) {
    return a > b ? a : b;
}

template <class T>
void show_max(const T &a, const T &b) {
    std::printf("%d\n", max_of(a, b).v);
}

int main() {
    NoCompare x{1}, y{2};
    show_max(x, y);
    return 0;
}
```

`实测数据`
`Text`

```text
error_wall.cpp: In instantiation of 'const T& max_of(const T&, const T&) [with T = NoCompare]':
error_wall.cpp:13:31:   required from 'void show_max(const T&, const T&) [with T = NoCompare]'
   13 |     std::printf("%d\n", max_of(a, b).v);
      |                         ~~~~~~^~~~~~
error_wall.cpp:18:13:   required from here
   18 |     show_max(x, y);
      |     ~~~~~~~~^~~~~~
error_wall.cpp:8:14: error: no match for 'operator>' (operand types are 'const NoCompare' and 'const NoCompare')
    8 |     return a > b ? a : b;
      |            ~~^~~
```

十行里只有一行是 `error`，其余是 `required from` 链：
编译器在说「这里要实例化 `max_of`，是因为 `show_max` 的第 13 行；
要实例化 `show_max`，是因为 `main` 的第 18 行」。
**链条越长，真正的错误越靠后**，这是模板报错给人的第一印象。

与普通函数对照，同一类错误短得多：

`C++`

```cpp
/* err_plain.cpp    编译：g++ -std=c++17 err_plain.cpp -o err_plain （失败） */
struct NoCompare { int v; };                    /* 不能转成 int */

int max_plain(int a, int b) { return a > b ? a : b; }

int main() {
    NoCompare x{1}, y{2};
    return max_plain(x, y);                     /* 类型不对 */
}
```

`实测数据`
`Text`

```text
err_plain.cpp: In function 'int main()':
err_plain.cpp:8:22: error: cannot convert 'NoCompare' to 'int'
    8 |     return max_plain(x, y);                     /* 类型不对 */
      |                      ^
      |                      |
      |                      NoCompare
err_plain.cpp:4:19: note: initializing argument 1 of 'int max_plain(int, int)'
    4 | int max_plain(int a, int b) { return a > b ? a : b; }
      |               ~~~~^
```

`9` 行对 `10` 行，差距还不明显。真实场景里的模板会层层嵌套，

## 8.4 与类型擦除的对照

第 1 节说过，模板与类型擦除的取舍相反。同一件事用两种方式写，
运行期的差别有多大，可以直接测出来：

`C++`

```cpp
/* erased_cost.cpp    编译：g++ -std=c++17 -O2 erased_cost.cpp -o erased_cost */
#include <chrono>
#include <cstdio>

template <class T>
long long sum_typed(const T *p, int n) {        /* 类型在编译期已知：可以直接加 */
    long long s = 0;
    for (int i = 0; i < n; ++i) s += p[i];
    return s;
}

/* 类型擦除的写法：元素多大、怎么读，全靠调用方给 */
long long sum_erased(const void *base, int n, int size, long long (*get)(const void *)) {
    long long s = 0;
    for (int i = 0; i < n; ++i)
        s += get((const char *)base + (long long)i * size);
    return s;
}

long long get_a(const void *p) { return *(const int *)p; }
long long get_b(const void *p) { return *(const int *)p; }

static long long (*volatile g_get)(const void *) = get_a;   /* 运行期才知道该调哪个 */

int main(int argc, char **) {
    const int n = 10000000;
    static int data[10000000];
    for (int i = 0; i < n; ++i) data[i] = i & 1023;

    long long (*get)(const void *) = (argc > 100) ? get_a : g_get;
    const int rounds = 10;

    auto t0 = std::chrono::steady_clock::now();
    long long a = 0;
    for (int r = 0; r < rounds; ++r) a += sum_typed(data, n);
    auto t1 = std::chrono::steady_clock::now();
    long long b = 0;
    for (int r = 0; r < rounds; ++r) b += sum_erased(data, n, sizeof(int), get);
    auto t2 = std::chrono::steady_clock::now();

    auto ms = [](auto x, auto y) {
        return std::chrono::duration_cast<std::chrono::milliseconds>(y - x).count();
    };
    std::printf("模板：%lld，用时 %lld 毫秒\n", a, (long long)ms(t0, t1));
    std::printf("类型擦除：%lld，用时 %lld 毫秒\n", b, (long long)ms(t1, t2));
    return 0;
}
```

`实测数据`
`Text`

```text
模板：51148771200，用时 15 毫秒
类型擦除：51148771200，用时 99 毫秒
（三次运行里最快的一次：模板 15 毫秒，类型擦除 99 毫秒）
```

结果相同，时间差六倍多。差别在编译出来的循环里（节选，省去栈帧与收尾）：

`实测数据`
`Assembly`

```asm
# 模板：整段循环被内联进 main，四个一组地加（paddq），没有函数调用
.L13:
        movd    (%rax), %xmm4
        addq    $4, %rax
        cmpq    %r12, %rax
        pshufd  $0, %xmm4, %xmm0
        movdqa  %xmm0, %xmm1
        movdqa  %xmm0, %xmm4
        psrad   $31, %xmm1
        punpckldq %xmm1, %xmm4
        punpckhdq %xmm1, %xmm0
        paddq   %xmm4, %xmm2
        paddq   %xmm0, %xmm3
        jne     .L13

# 类型擦除：每一轮都要问一次「该调哪个函数」
.L5:
        movq    %rbx, %rcx
        addl    $1, %esi
        addq    %r13, %rbx
        call    *%r12
        addq    %rax, %rdi
        cmpl    %esi, %ebp
        jne     .L5
```

模板那一版里 `sum_typed` 连函数体都没有了，整段循环被内联并向量化；
类型擦除那一版每次迭代都有一条 `call *%r12`（间接调用），
编译器无法知道会调到哪个函数，也就无法内联。
代码里的 `volatile` 函数指针与 `argc > 100` 那个判断都是为了让调用目标在编译期不可知：
不这样写，编译器会把目标函数直接内联进来，两组数字就分不开了。这只是测量手段，不是常规写法。
`std::function` 的代价与此同类，第 10 章实测到的是 26 毫秒对 95 毫秒
（《05-类与面向对象/10-lambda 与函数对象.md》第 5.3 小节）。

两边的账要一起算：

| | 模板 | 类型擦除 |
|---|---|---|
| 机器码份数 | 每种类型一份 | 一份 |
| 调用开销 | 无，可内联 | 一次间接调用，通常无法内联 |
| 类型信息 | 编译期完整保留 | 运行期只剩「多大、怎么读」 |
| 换一种类型 | 重新编译 | 不用重新编译，运行期给参数即可 |

最后一行是类型擦除真正的优势：**它能在运行期换类型**。
类型清单在编译期定不下来时（插件、脚本绑定、跨语言接口），
模板帮不上忙，只能擦除。

## 8.5 什么时候不要用模板

模板不是默认选项。下面几种情况，用普通函数或重载更合适。

**只用一种类型时，模板不带来任何收益。** 同一件事写成模板与写成普通函数，
目标文件的大小并不相同，模板那一份更大：

`C++`

```cpp
/* one_type_plain.cpp    编译：g++ -std=c++17 -c one_type_plain.cpp -o one_type_plain.o */
#include <cstddef>

int sum_plain(const int *p, std::size_t n) {    /* 只给 int 写一份 */
    int s = 0;
    for (std::size_t i = 0; i < n; ++i) s += p[i];
    return s;
}

int main() {
    int a[4] = {1, 2, 3, 4};
    return sum_plain(a, 4);
}
```

`C++`

```cpp
/* one_type_template.cpp    编译：g++ -std=c++17 -c one_type_template.cpp -o one_type_template.o */
#include <cstddef>

template <class T>
T sum_all(const T *p, std::size_t n) {          /* 同一件事写成模板 */
    T s = 0;
    for (std::size_t i = 0; i < n; ++i) s += p[i];
    return s;
}

int main() {
    int a[4] = {1, 2, 3, 4};
    return (int)sum_all(a, 4);                  /* 只用 int 这一种类型 */
}
```

`实测数据`

| 程序 | 写法 | 目标文件大小 |
|---|---|---|
| `one_type_plain.cpp` | 普通函数 | 1003 字节 |
| `one_type_template.cpp` | 函数模板 | 1456 字节 |

多出来的部分是实例化相关的段与符号名。**模板让同一份源码覆盖多种类型，
它不负责让代码变小。**

| 情况 | 更合适的选择 |
|---|---|
| 只用一种类型 | 普通函数。模板只增加编译期工作与更长的报错 |
| 类型集合有限且已知，每种处理方式不同 | 重载。报错短，读代码的人一眼看到全部实现 |
| 需要把实现藏进 `.cpp`，且类型清单已知 | 模板加显式实例化（第 5.2 小节） |
| 需要在运行期换类型 | 类型擦除（`std::function`、`void *` 加函数指针、虚函数） |
| 类型集合在编译期确定，且逻辑与类型无关 | 模板。这正是它解决的问题 |

> [!TIP]
> **判断标准是「类型的集合在编译期是否已知，且是否会增长」。**
> 只有一两种类型时，先写普通函数或重载；
> 等到第三种类型出现、而且逻辑确实一样时，再改成模板也不迟。

> [!NOTE]
> **模板的代价是规模：代码份数、编译时间、报错长度，三项都随类型数量增长。**
> 它的收益是同一份源码覆盖多种类型，且不牺牲类型检查与运行期速度。

# 第 9 节 检查清单

写模板时逐条对照：

| 检查 | 说明 |
|---|---|
| 这个逻辑真的会对多种类型用吗 | 只有一种类型时普通函数更简单（第 8.5 小节） |
| 定义是不是和声明一起放在头文件里 | 放 `.cpp` 会在链接期报 `undefined reference`（第 5.2 小节） |
| 依赖名里的类型写 `typename` 了吗 | 漏写报 `need 'typename' before ...`（第 5.5 小节） |
| 模板体里调用的非依赖函数，声明在它前面吗 | 两阶段名字查找：定义时就要求可见（第 5.4 小节） |
| 非类型实参是编译期常量吗 | 运行期的值报 `not usable in a constant expression`（第 3.1 小节） |
| 类外定义成员函数时，`template <class T>` 与 `Stack<T>::` 都写了吗 | 两处都容易漏（第 4.2 小节） |
| 全特化的签名与主模板完全一致吗 | 返回类型差一点就报「与主模板不匹配」（第 6.1 小节） |
| 是不是想给函数模板写偏特化 | 不允许；改写成重载，由偏序选择（第 6.3 小节） |
| 显式实例化定义是不是只出现了一次 | 重复会出现重复定义（第 5.2 小节） |
| 实例化份数会不会太多 | 12 种类型就把目标文件涨到近 6 倍（第 8.1 小节） |
| 编译时间能不能接受 | 400 个实例让编译时间涨到三倍多（第 8.2 小节） |
