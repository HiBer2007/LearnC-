**同一个名字，实参不同就走进了不同的函数；同一个调用点，同一行代码，运行时却可能走进不同的函数。**
这两件事在教材里常被同一个词盖住：多态。

第一件在**编译期**就定死了，靠的是**函数重载**：`print(1)` 与 `print("hi")` 是两个不同的函数，
编译器看一眼实参就知道该调哪一个。

第二件要到**运行期**才知道，靠的是**虚函数**：`shape->area()` 到底调谁的 `area`，
取决于 `shape` 当时指向的是圆还是矩形，而编译期只有一个 `Shape` 可用。

与它们挤在一起的还有三个词：**重载**（overload）、**覆盖**（override）、**隐藏**（hide）。
三个词长得像，含义完全不同，其中「隐藏」还不是设计出来的机制，
而是名字查找规则的副作用（《05-类与面向对象/06-继承.md》第 4 节）。

第 06 章留下了一个未了的问题：**通过基类指针删除派生类对象时，派生类的析构函数没有执行**。
补上它的正是这一章的虚函数（第 3.5 小节）。

# 第 1 节 「多态」是两件事

## 1.1 编译期决定：看一眼实参就能选

调用点上信息足够时，编译器在生成代码的时候就把要调的函数地址填好了，运行期不再做任何选择。
这一类的机制有三种：

| 机制 | 在哪讲 | 依据什么选 |
|---|---|---|
| 函数重载 | 本章第 2 节 | 实参的类型与个数 |
| 运算符重载 | 《05-类与面向对象/08-运算符重载.md》第 1 节 | 操作数的类型 |
| 模板 | 【待补：05-类与面向对象/10-模板.md】 | 模板实参（显式给出或推导出来） |

`C++`

```cpp
void print(int x);              /* 同一个名字，两个函数 */
void print(const char *s);

print(1);                       /* 编译期选定 print(int) */
print("hi");                    /* 编译期选定 print(const char *) */
```

> [!IMPORTANT]
> **选中的函数在编译期就确定，编译出来的是一次普通调用，可以内联，运行期没有额外开销。**
> 这是编译期多态与运行期多态最实在的差别，第 6 节会把代价算清楚。

## 1.2 运行期决定：看到对象才知道选哪个

另一种情况是调用点上信息不够：

`C++`

```cpp
double total = 0;
for (Shape *s : shapes)         /* shapes 里装的是圆、矩形…… */
    total += s->area();         /* 这一行编译期不知道调谁的 area */
```

`shapes` 的元素类型是 `Shape *`，`Shape::area` 是哪一个函数体，编译期无从得知。
要等到运行期，看 `s` 当时指向的对象是哪一种，才决定跳进哪个 `area`。
这个「看对象的实际类型」的动作由编译器生成的**查表**代码完成，表就是虚函数表（第 3.2 小节）。

## 1.3 两件事的区别

`实测数据`

| | 编译期决定 | 运行期决定 |
|---|---|---|
| 依据 | 实参的静态类型、对象的静态类型 | 对象**实际**是哪一种类型 |
| 谁来做决定 | 编译器 | 编译器生成的一段查表代码 |
| 典型机制 | 函数重载、运算符重载、模板 | 虚函数 |
| 代价 | 没有：调用点直接写死，可以内联 | 每个对象一个指针，每次调用一次间接跳转 |
| 适合用在 | 同一个操作面对不同类型的实参 | 一族对象在同一个调用点上各有各的做法 |

`文档`

> "[Note: The interpretation of the call of a virtual function depends on the type of the object
> for which it is called (the dynamic type), whereas the interpretation of a call of a non-virtual
> member function depends only on the type of the pointer or reference denoting that object
> (the static type) (8.2.2). —end note]"
>
> —— N4659 §13.3/9

> [!IMPORTANT]
> **「多态」不是一种机制，而是一类现象：同一个写法在不同的情况下做不同的事。**
> C++ 里实现它的手段分两批，一批在编译期用完，一批留到运行期。
> 后面的章节会看到第三批手段里的模板（【待补：05-类与面向对象/10-模板.md】），
> 它同样属于编译期那一批。

# 第 2 节 函数重载与重载决议

## 2.1 同一个作用域里的同名函数

重载的成立条件只有一个：**在同一个作用域里，几个函数同名而参数表不同**。

`C++`

```cpp
void print(int x);
void print(const char *s);      /* 与上面那个同名，参数表不同：一对重载 */
```

三条边界要记住：

| 说法 | 对不对 |
|---|---|
| 参数表不同就能重载 | 对，参数个数、类型、顺序任一不同都算 |
| 返回类型不同也是重载 | **不对**，返回类型不参与决议（第 2.6 小节） |
| 两个函数写在不同作用域里也算重载 | **不对**，那是名字隐藏（第 5 节）或互不相干的两个名字 |

**C 里没有重载。** C 的函数名就是符号名，两个 `print` 会撞在一起；
C++ 把参数类型编进符号名（名字修饰），`_Z5printi` 与 `_Z5printPKc` 才是两个不同的符号，
重载因此成立（《04-语法/07-函数.md》第 5.3 小节）。

> [!IMPORTANT]
> **重载是编译期的事：编译器按实参从候选里挑一个，把它的地址写进调用点。**
> 挑的过程叫**重载决议**，规则是「哪条路转换得最少、最不丢信息，就走哪条」。

## 2.2 决议怎么排序：精确匹配 → 提升 → 转换

先看一组实测。四个同名函数，形参分别是 `char`、`int`、`long`、`double`，
再拿七种不同类型的实参去调：

`C++`

```cpp
/* overload_pick.cpp    编译：g++ -std=c++17 overload_pick.cpp -o overload_pick */
#include <cstdio>

void f(char)   { std::printf("f(char)\n"); }
void f(int)    { std::printf("f(int)\n"); }
void f(long)   { std::printf("f(long)\n"); }
void f(double) { std::printf("f(double)\n"); }

void g(long)   { std::printf("g(long)\n"); }   /* g 只有一个候选 */

int main() {
    std::printf("%-14s-> ", "f('a')");         f('a');
    std::printf("%-14s-> ", "f(1)");           f(1);
    std::printf("%-14s-> ", "f(1L)");          f(1L);
    std::printf("%-14s-> ", "f(1.0)");         f(1.0);
    std::printf("%-14s-> ", "f(short(1))");    f(static_cast<short>(1));
    std::printf("%-14s-> ", "f(1.0f)");        f(1.0f);
    std::printf("%-14s-> ", "f(true)");        f(true);
    std::printf("%-14s-> ", "g(1)");           g(1);
    return 0;
}
```

`实测数据`
`Text`

```text
f('a')        -> f(char)
f(1)          -> f(int)
f(1L)         -> f(long)
f(1.0)        -> f(double)
f(short(1))   -> f(int)
f(1.0f)       -> f(double)
f(true)       -> f(int)
g(1)          -> g(long)
```

每个实参到形参的转换被分成几等，等级高的候选胜出：

| 等级 | 哪些转换算这一等 | 上面这一组里的例子 |
|---|---|---|
| 精确匹配 | 类型一致；只差顶层 `const`；数组退化成指针、函数退化成函数指针 | `f('a')` 选 `f(char)`，`f(1)` 选 `f(int)` |
| 提升 | 小整型 → `int`、`float` → `double`（不丢信息的那几种） | `f(short(1))` 选 `f(int)`，`f(1.0f)` 选 `f(double)`，`f(true)` 选 `f(int)` |
| 转换 | 其余标准转换：整型之间、浮点与整型之间、指针到 `void *` 等 | `g(1)` 选 `g(long)`（只有一个候选，转换也照走） |
| 用户定义转换 | 要走构造函数或类型转换函数 | 第 2.3 小节 |

整型提升的完整规则见《04-语法/02-数据类型与类型系统.md》第 5.2 小节。

**排序只看「转换得好不好」，不看函数体的长短，也不看谁写在前面。**
`f(short(1))` 之所以落在 `f(int)` 上，是因为 `short → int` 是提升，
而 `short → char`、`short → long`、`short → double` 都是转换，等级更低。

`文档`

> "Standard conversion sequences are ordered by their ranks: an Exact Match is a better
> conversion than a Promotion, which is a better conversion than a Conversion. Two conversion
> sequences with the same rank are indistinguishable unless one of the following rules applies:"
>
> —— N4659 §16.3.3.2/4

## 2.3 隐式转换会把调用引到另一个函数上

构造函数的隐式转换也参与重载决议，而它排在标准转换之后：

`C++`

```cpp
/* overload_user_conv.cpp    编译：g++ -std=c++17 overload_user_conv.cpp -o overload_user_conv */
#include <cstdio>

class Meter {
public:
    Meter(int v) : v_(v) { }        /* 没有 explicit：int 可以隐式转成 Meter */
    int v_;
};

void use(double d) { std::printf("  use(double) 被选中，值 %g\n", d); }    /* 标准转换 */
void use(Meter m)  { std::printf("  use(Meter) 被选中，值 %d\n", m.v_); }  /* 用户定义转换 */

int main() {
    std::printf("use(1)：int 到 double 是标准转换，int 到 Meter 要走构造函数\n");
    use(1);
    std::printf("use(Meter(1))：类型完全对上\n");
    use(Meter(1));
    return 0;
}
```

`实测数据`
`Text`

```text
use(1)：int 到 double 是标准转换，int 到 Meter 要走构造函数
  use(double) 被选中，值 1
use(Meter(1))：类型完全对上
  use(Meter) 被选中，值 1
```

`use(1)` 有两条路：`int → double`（标准转换）与 `int → Meter`（用户定义转换）。
前者等级更高，于是选中 `use(double)`。

> [!TIP]
> **不希望构造函数参与这种隐式转换，就在它前面写 `explicit`。**
> 这也是 `explicit` 最常见的用途：把「可以被隐式当成另一种类型」这件事关掉，
> 重载决议里就少了一条你没想到的路（完整规则见【待补：05-类与面向对象/12-成员、友元与细节.md】）。

## 2.4 两条路一样好：二义

候选的转换等级一样高时，编译器不会替你挑一个，而是直接报错：

`C++`

```cpp
/* overload_ambig.cpp    编译：g++ -std=c++17 overload_ambig.cpp -o overload_ambig （失败） */
void f(long)   { }
void f(double) { }

int main() {
    f(1u);          /* unsigned int 到 long 与到 double 都要一次转换，谁也不比谁好 */
    return 0;
}
```

`实测数据`
`Text`

```text
overload_ambig.cpp:6:6: error: call of overloaded 'f(unsigned int)' is ambiguous
overload_ambig.cpp:6:6: note: there are 2 candidates
overload_ambig.cpp:2:6: note: candidate 1: 'void f(long int)'
```

**二义是编译期的错误，不是运行期的不确定行为。** 编译器列出全部候选让作者自己决定，
常见的收场是加一个参数类型正好对得上的重载，或者把实参显式转成某一种类型。

`文档`

> "If a best viable function exists and is unique, overload resolution succeeds and produces it
> as the result. Otherwise overload resolution fails and the invocation is ill-formed."
>
> —— N4659 §16.3/3

## 2.5 用 `= delete` 堵住不该接受的实参

重载可以用来**增加**能接受的实参类型，也可以反过来，用 `= delete` 明确划掉一种：

`C++`

```cpp
/* overload_deleted_ok.cpp    编译：g++ -std=c++17 overload_deleted_ok.cpp -o overload_deleted_ok */
#include <cstdio>

void f(int x) { std::printf("  f(int) 被调用，值 %d\n", x); }
void f(double) = delete;        /* 明确禁止用浮点参数调用 */

int main() {
    f(1);                       /* 整数可以 */
    return 0;
}
```

`实测数据`
`Text`

```text
  f(int) 被调用，值 1
```

同一个函数用浮点实参去调，就在编译期被拦下：

`C++`

```cpp
/* overload_deleted.cpp    编译：g++ -std=c++17 overload_deleted.cpp -o overload_deleted （失败） */
void f(int) { }
void f(double) = delete;

int main() {
    f(1.5);                     /* 选中了被删除的那一个 */
    return 0;
}
```

`实测数据`
`Text`

```text
overload_deleted.cpp:6:6: error: use of deleted function 'void f(double)'
```

**被删除的函数仍然参与重载决议**，这一点正是它的用处：
先让 `f(double)` 在候选里胜出，再告诉调用者此路不通。
如果不写这一行，`f(1.5)` 会悄悄地把 `1.5` 转成 `1` 调进 `f(int)`，值被截断而没有任何提示。

`文档`

> "[Note: This includes calling the function implicitly or explicitly and forming a pointer or
> pointer-to-member to the function. It applies even for references in expressions that are not
> potentially-evaluated. If a function is overloaded, it is referenced only if the function is
> selected by overload resolution. ... —end note]"
>
> —— N4659 §11.4.3/2

`= delete` 的另一种用法（删掉编译器自动生成的拷贝构造、移动构造）见
《05-类与面向对象/03-构造与析构.md》第 1.4 小节与《05-类与面向对象/04-拷贝与移动.md》第 5 节。

## 2.6 返回类型不参与决议

两个函数只有返回类型不同，不构成重载，而是同一份声明的第二次声明：

`C++`

```cpp
/* overload_return.cpp    编译：g++ -std=c++17 overload_return.cpp -o overload_return （失败） */
int    f(int) { return 1; }
double f(int) { return 2.0; }   /* 参数表一样，只改返回类型 */

int main() {
    return f(1);
}
```

`实测数据`
`Text`

```text
overload_return.cpp:3:8: error: ambiguating new declaration of 'double f(int)'
overload_return.cpp:2:8: note: old declaration 'int f(int)'
```

调用点上只写得出 `f(1)`，返回类型要到选中函数之后才谈得上，
因此它没法作为挑选的依据。

# 第 3 节 虚函数

## 3.1 一个关键字改变决议的时机

第 06 章第 5.3 小节实测过：通过基类的引用或指针调用一个**普通**成员函数，
调到的永远是基类那一份。在基类的声明前面加上 `virtual`，同一行调用就变了：

`C++`

```cpp
/* virtual_basic.cpp    编译：g++ -std=c++17 virtual_basic.cpp -o virtual_basic */
#include <cstdio>

class Base {
public:
    virtual const char *who() const { return "Base"; }
};

class Derived : public Base {
public:
    const char *who() const override { return "Derived"; }
};

void by_ref(const Base &b) { std::printf("  通过基类引用调用：%s\n", b.who()); }
void by_ptr(const Base *b) { std::printf("  通过基类指针调用：%s\n", b->who()); }

int main() {
    Base    b;
    Derived d;

    std::printf("具体对象自己调用（类型是已知的）：\n");
    std::printf("  b.who() = %s\n", b.who());
    std::printf("  d.who() = %s\n", d.who());

    std::printf("交给基类的引用与指针（编译期只知道是 Base）：\n");
    by_ref(d);
    by_ptr(&d);
    return 0;
}
```

`实测数据`
`Text`

```text
具体对象自己调用（类型是已知的）：
  b.who() = Base
  d.who() = Derived
交给基类的引用与指针（编译期只知道是 Base）：
  通过基类引用调用：Derived
  通过基类指针调用：Derived
```

四条规则：

| 规则 | 说明 |
|---|---|
| `virtual` 写在基类的声明里 | 派生类同名同签名的函数**自动**是虚函数，写不写 `virtual` 都行，写上更好读 |
| 只有通过引用或指针调用才有多态 | 通过对象调用时对象类型是已知的，编译器直接调，不必查表 |
| 签名必须一致 | 参数表、`const`、返回类型（有例外，见第 3.5 小节）都要对上，差一点都不构成覆盖 |
| 动了基类，所有派生类跟着变 | 加一个虚函数会影响所有派生类的对象大小与行为，改基类接口的代价在这里 |

**函数的签名由参数表和 `const` 决定，返回值通常不参与**——这一点与重载一致（第 2.6 小节），
与名字修饰的规则也一致。

`文档`

> "If a virtual member function vf is declared in a class Base and in a class Derived, derived
> directly or indirectly from Base, a member function vf with the same name,
> parameter-type-list (11.3.5), cv-qualification, and ref-qualifier (or absence of same) as
> Base::vf is declared, then Derived::vf is also virtual (whether or not it is so declared) and
> it overrides Base::vf."
>
> —— N4659 §13.3/2

## 3.2 虚函数表：对象里多的那个指针

`virtual` 不是一句空话，它要占地方。同一个类，加一个虚函数之后再量：

`C++`

```cpp
/* vtable_size.cpp    编译：g++ -std=c++17 vtable_size.cpp -o vtable_size */
#include <cstdio>

class NoVirtual  { public: int a = 1; };
class OneVirtual { public: int a = 1; virtual void f() { } };
class TwoVirtual { public: int a = 1; virtual void f() { } virtual void g() { } };

class A { public: virtual void f() { } };
class B { public: virtual void g() { } };
class C : public A, public B { public: int c = 3; };   /* 两个多态基类 */

int main() {
    std::printf("sizeof(NoVirtual)  = %zu\n", sizeof(NoVirtual));
    std::printf("sizeof(OneVirtual) = %zu\n", sizeof(OneVirtual));
    std::printf("sizeof(TwoVirtual) = %zu\n", sizeof(TwoVirtual));
    std::printf("sizeof(A) = %zu，sizeof(B) = %zu，sizeof(C) = %zu\n",
                sizeof(A), sizeof(B), sizeof(C));

    OneVirtual ov;
    std::printf("对象首地址 %p，成员 a 的地址 %p，相差 %td 字节\n",
                static_cast<void *>(&ov), static_cast<void *>(&ov.a),
                reinterpret_cast<char *>(&ov.a) - reinterpret_cast<char *>(&ov));
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(NoVirtual)  = 4
sizeof(OneVirtual) = 16
sizeof(TwoVirtual) = 16
sizeof(A) = 8，sizeof(B) = 8，sizeof(C) = 24
对象首地址 0000001fa2dffc60，成员 a 的地址 0000001fa2dffc68，相差 8 字节
```

读出来的三件事：

| 现象 | 原因 |
|---|---|
| `int` 从 4 字节涨到 16 字节 | 对象里多了一个 8 字节的指针，再加对齐填充 |
| 一个虚函数与两个虚函数一样大 | 对象里只放**一个**指针，函数地址放在类共用的表里 |
| `C` 有 24 字节 | 它有两个多态基类，两个基类子对象各带一个指针 |

多出来的那个指针叫**虚指针**（vptr），它指向的只读表叫**虚函数表**（vtable）。
表是每个**类**一张，指针是每个**对象**一个。表的存在可以直接从符号表里看到：

`Bash`

```bash
nm -C virtual_basic.exe | grep -E "vtable|typeinfo"
```

`实测数据`
`Text`

```text
000000014000a9c0 R typeinfo for Base
000000014000a9d0 R typeinfo for Derived
000000014000a9f0 R typeinfo name for Base
000000014000aa00 R typeinfo name for Derived
000000014000aa10 R vtable for Base
000000014000aa30 R vtable for Derived
```

调用 `p->who()` 因此被编译成三步：从对象开头取出虚指针 → 从表里取出第几个槽位 → 间接调用。
第 6.2 小节会把这些指令实际打出来。

> [!IMPORTANT]
> **运行期多态的机制就是「对象里放一个指针，指针指向一张按类共享的函数表」。**
> 代价与它绑在一起：每个对象 8 字节，每次调用一次间接跳转。
> 好处是调用点不必知道对象的类型，只认基类接口。

## 3.3 `override`：让编译器替你检查签名

覆盖要求签名完全一致，而签名差一点时，编译器**不会**报错——
它按名字隐藏处理（第 5 节），于是程序照常编过，行为却与设想的不同。加了 `override` 就会拦下来：

`C++`

```cpp
/* override_typo.cpp    编译：g++ -std=c++17 override_typo.cpp -o override_typo （失败） */
class Base {
public:
    virtual void f(double) { }
};

class Derived : public Base {
public:
    void f(int) override { }        /* 参数表不同：不是覆盖 */
};

int main() {
    Derived d;
    d.f(1);
    return 0;
}
```

`实测数据`
`Text`

```text
override_typo.cpp:9:10: error: 'void Derived::f(int)' marked 'override', but does not override
```

把 `override` 去掉，同一个错误就变成静默的：

`C++`

```cpp
/* override_silent.cpp    编译：g++ -std=c++17 override_silent.cpp -o override_silent */
#include <cstdio>

class Base {
public:
    virtual void f(double x) { std::printf("  Base::f(double %.1f)\n", x); }
};

class Derived : public Base {
public:
    void f(int x) { std::printf("  Derived::f(int %d)\n", x); }    /* 少写了 override */
};

int main() {
    Derived d;
    std::printf("d.f(1.5)：基类的 f(double) 被藏起来，1.5 转成 int\n");
    d.f(1.5);
    std::printf("d.Base::f(1.5)：限定调用才到基类\n");
    d.Base::f(1.5);

    Base *p = &d;
    std::printf("p->f(1.5)：没有覆盖，走的还是 Base::f\n");
    p->f(1.5);
    return 0;
}
```

`实测数据`
`Text`

```text
d.f(1.5)：基类的 f(double) 被藏起来，1.5 转成 int
  Derived::f(int 1)
d.Base::f(1.5)：限定调用才到基类
  Base::f(double 1.5)
p->f(1.5)：没有覆盖，走的还是 Base::f
  Base::f(double 1.5)
```

`1.5` 变成 `1`，而编译器一声不吭。
`d.f(1.5)` 落在派生类的 `f(int)` 上，是因为基类的 `f(double)` 被名字隐藏挡住了；
`p->f(1.5)` 走回基类，是因为派生类的 `f(int)` 没有覆盖任何东西。

`文档`

> "If a virtual function is marked with the virt-specifier override and does not override a
> member function of a base class, the program is ill-formed."
>
> —— N4659 §13.3/5

> [!TIP]
> **打算覆盖基类的虚函数，就在后面写 `override`；不打算覆盖而只是同名，就别写。**
> 这一条把「我以为在覆盖」变成「编译器替我核对」，
> 代价是四个字母，收益是第 3.3 小节这类错误全部现形。

## 3.4 `final`：到此为止

反过来的需求是禁止再覆盖，写 `final`：

`C++`

```cpp
/* final_test.cpp    编译：g++ -std=c++17 final_test.cpp -o final_test （失败） */
class Base {
public:
    virtual void f() final { }      /* 到此为止，不许再覆盖 */
};

class Derived : public Base {
public:
    void f() override { }
};

int main() {
    Derived d;
    return 0;
}
```

`实测数据`
`Text`

```text
final_test.cpp:9:10: error: virtual function 'virtual void Derived::f()' overriding final function
final_test.cpp:4:18: note: overridden function is 'virtual void Base::f()'
```

`final` 也能写在类名后面（`class Derived final { ... };`），意思是这个类不允许再被继承。
它解决的问题是「基类的作者认为这个实现不该被改写」，或者「这个类的继承体系到此为止，别再往下接」。

`文档`

> "If a virtual function f in some class B is marked with the virt-specifier final and in a class
> D derived from B a function D::f overrides B::f, the program is ill-formed."
>
> —— N4659 §13.3/4
>
> "If a class is marked with the class-virt-specifier final and it appears as a class-or-decltype
> in a base-clause (Clause 13), the program is ill-formed."
>
> —— N4659 §12/3

**`final` 不是性能开关。** 它在语义上是禁止扩展，编译器由此得到的信息（这个调用不必查表）
是次要效果；把 `final` 当优化手段到处加，会让类无法再被继承，代价远大于收益。

## 3.5 虚析构函数

第 06 章第 7 节留下的问题在这里收尾：通过基类指针删除派生类对象时，
`~Derived` 没有被执行。基类的析构函数前面加 `virtual` 就补上了：

`C++`

```cpp
/* virtual_dtor.cpp    编译：g++ -std=c++17 virtual_dtor.cpp -o virtual_dtor */
#include <cstdio>

class Base {
public:
    Base() { std::printf("  Base 构造\n"); }
    virtual ~Base() { std::printf("  ~Base\n"); }
};

class Derived : public Base {
public:
    Derived() { std::printf("  Derived 构造\n"); }
    ~Derived() override { std::printf("  ~Derived\n"); }
};

int main() {
    std::printf("通过基类指针删除对象：\n");
    {
        Base *p = new Derived;
        delete p;
    }
    std::printf("sizeof(Base) = %zu，sizeof(Derived) = %zu\n", sizeof(Base), sizeof(Derived));
    return 0;
}
```

`实测数据`
`Text`

```text
通过基类指针删除对象：
  Base 构造
  Derived 构造
  ~Derived
  ~Base
sizeof(Base) = 8，sizeof(Derived) = 8
```

`delete p` 现在从虚函数表里找到真正该调的那个析构函数，派生类的部分先析构，基类的部分随后析构。

标准对这一条的要求是硬性的：

`文档`

> "In the first alternative (delete object), if the static type of the object to be deleted is
> different from its dynamic type, the static type shall be a base class of the dynamic type of
> the object to be deleted and the static type shall have a virtual destructor or the behavior
> is undefined."
>
> —— N4659 §8.3.5/3

> [!CAUTION]
> **只要有可能通过基类指针删除对象，基类的析构函数就必须是虚函数，否则是未定义行为。**
> 判断办法：这个类有虚函数吗；或者，有人可能用基类指针持有派生类对象吗。
> 满足任何一条，就把析构函数写成 `virtual`（或者对纯接口写 `virtual ~Base() = default;`）。

还有一处细节：加了虚函数之后，`Base` 与 `Derived` 都变成了 8 字节，
派生类并没有因为「多了自己的析构」而变大——析构函数的地址放在表里，不占对象。

## 3.6 构造与析构期间不做动态绑定

虚函数在构造函数与析构函数里会失去多态：

`C++`

```cpp
/* ctor_vcall.cpp    编译：g++ -std=c++17 ctor_vcall.cpp -o ctor_vcall */
#include <cstdio>

class Base {
public:
    Base()          { std::printf("  基类构造里调用 who()：%s\n", who()); }
    virtual ~Base() { std::printf("  基类析构里调用 who()：%s\n", who()); }
    virtual const char *who() const { return "Base"; }
};

class Derived : public Base {
public:
    Derived() { std::printf("  派生类构造里调用 who()：%s\n", who()); }
    const char *who() const override { return "Derived"; }
};

int main() {
    {
        Derived d;
        std::printf("  对象建好之后再调用：%s\n", d.who());
    }
    return 0;
}
```

`实测数据`
`Text`

```text
  基类构造里调用 who()：Base
  派生类构造里调用 who()：Derived
  对象建好之后再调用：Derived
  基类析构里调用 who()：Base
```

原因与虚指针的赋值时机有关：对象是一段一段建起来的，
构造基类那一段时，派生类的成员还不存在，虚指针只能指向**当前正在构造的这个类**的表。
析构时反过来，派生类那一段已经拆掉，虚指针先被改回基类的表。

`文档`

> "When a virtual function is called directly or indirectly from a constructor or from a
> destructor, including during the construction or destruction of the class's non-static data
> members, and the object to which the call applies is the object (call it x) under construction
> or destruction, the function called is the final overrider in the constructor's or destructor's
> class and not one overriding it in a more-derived class."
>
> —— N4659 §15.7/3

> [!WARNING]
> **不要在构造函数或析构函数里调用虚函数并指望它调到派生类的版本。**
> 需要「对象完全建好之后再执行一次」的初始化，就另写一个 `init()` 之类的函数，
> 在对象构造完成之后显式调用。

# 第 4 节 纯虚函数与抽象类

## 4.1 只留接口

基类的某个虚函数根本没法给出有意义的实现时，把它写成 `= 0`：

`C++`

```cpp
/* abstract_shape.cpp    编译：g++ -std=c++17 abstract_shape.cpp -o abstract_shape */
#include <cstdio>

class Shape {                                   /* 抽象类：只规定「能做什么」 */
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;            /* 纯虚函数：没有实现 */
    virtual const char *name() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) { }
    double area() const override { return 3.14159265358979 * r_ * r_; }
    const char *name() const override { return "圆"; }
private:
    double r_;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) { }
    double area() const override { return w_ * h_; }
    const char *name() const override { return "矩形"; }
private:
    double w_, h_;
};

int main() {
    Circle c(1.0);
    Rect   r(2.0, 3.0);
    Shape *shapes[2] = { &c, &r };              /* 一个基类指针，装不同的对象 */

    double total = 0;
    for (Shape *s : shapes) {
        std::printf("  %s 的面积 = %.2f\n", s->name(), s->area());
        total += s->area();
    }
    std::printf("总面积 = %.2f\n", total);
    std::printf("sizeof(Shape) = %zu，sizeof(Circle) = %zu，sizeof(Rect) = %zu\n",
                sizeof(Shape), sizeof(Circle), sizeof(Rect));
    return 0;
}
```

`实测数据`
`Text`

```text
  圆 的面积 = 3.14
  矩形 的面积 = 6.00
总面积 = 9.14
sizeof(Shape) = 8，sizeof(Circle) = 16，sizeof(Rect) = 24
```

三条规则：

| 写法 | 含义 |
|---|---|
| `virtual double area() const = 0;` | 这是一条接口要求，派生类**必须**给实现 |
| 含纯虚函数的类是**抽象类** | 不能创建对象，只能作为基类使用 |
| 抽象类可以有数据成员与普通函数 | 它可以是「一部分实现 + 一部分接口」，不是只有接口 |

`文档`

> "An abstract class is a class that can be used only as a base class of some other class;
> no objects of an abstract class can be created except as subobjects of a class derived from it.
> A class is abstract if it has at least one pure virtual function. ... A virtual function is
> specified pure by using a pure-specifier (12.2) in the function declaration in the class
> definition."
>
> —— N4659 §13.4/2
>
> "An abstract class shall not be used as a parameter type, as a function return type, or as the
> type of an explicit conversion. Pointers and references to an abstract class can be declared."
>
> —— N4659 §13.4/3

抽象类不能创建对象，编译器会直接说清楚原因：

`C++`

```cpp
/* abstract_new.cpp    编译：g++ -std=c++17 abstract_new.cpp -o abstract_new （失败） */
class Shape {
public:
    virtual double area() const = 0;
};

int main() {
    Shape s;            /* 抽象类不能创建对象 */
    return 0;
}
```

`实测数据`
`Text`

```text
abstract_new.cpp:8:11: error: cannot declare variable 's' to be of abstract type 'Shape'
abstract_new.cpp:2:7: note:   because the following virtual functions are pure within 'Shape':
abstract_new.cpp:4:20: note:     'virtual double Shape::area() const'
```

## 4.2 一个指针装不同的对象

抽象类真正解决的问题在 `main` 的那几行里：
**调用代码只需要认识 `Shape`，不必认识圆和矩形。**

`C++`

```cpp
for (Shape *s : shapes)         /* 这一行不需要改 */
    total += s->area();
```

以后加一种三角形，只要它继承 `Shape` 并实现 `area` 与 `name`，
这个循环一个字都不用动。反过来，如果没有虚函数，就得在循环里写
`if (s->kind == CIRCLE) ... else if (s->kind == RECT) ...`，
每加一种形状都要回来改这个 `if` 链——这就是第 1 节说的「运行期决定」要买到的东西。

> [!IMPORTANT]
> **纯虚函数解决的是「基类不知道怎么做，但要求派生类必须会做」。**
> 它把接口与实现分开：基类规定调用者能依赖什么，派生类决定怎么做。
> 这是 C++ 里表达「接口」的常规手段（真正只有接口的类，写成不带数据成员的抽象类）。

## 4.3 纯虚析构函数也要有实现

析构函数可以写成纯虚的，但它与别的纯虚函数不同：**必须给一个实现**。

`C++`

```cpp
/* pure_dtor_missing.cpp    编译：g++ -std=c++17 pure_dtor_missing.cpp -o pure_dtor_missing （失败） */
class Base {
public:
    virtual ~Base() = 0;        /* 声明成纯虚，但没有给实现 */
};

class Derived : public Base {
public:
    ~Derived() { }
};

int main() {
    Base *p = new Derived;
    delete p;
    return 0;
}
```

这个程序编译通过，**在链接时才失败**：

`实测数据`
`Text`

```text
undefined reference to `Base::~Base()'
collect2.exe: error: ld returned 1 exit status
```

补上实现就好了：

`C++`

```cpp
/* pure_dtor_ok.cpp    编译：g++ -std=c++17 pure_dtor_ok.cpp -o pure_dtor_ok */
#include <cstdio>

class Base {
public:
    virtual ~Base() = 0;        /* 纯虚：Base 仍然是抽象类 */
};

Base::~Base() { std::printf("  ~Base 的实现\n"); }   /* 但必须给一个实现 */

class Derived : public Base {
public:
    ~Derived() { std::printf("  ~Derived\n"); }
};

int main() {
    Base *p = new Derived;
    delete p;
    return 0;
}
```

`实测数据`
`Text`

```text
  ~Derived
  ~Base 的实现
```

原因是析构的顺序：派生类的析构函数执行完自己的部分之后，**总是要调用基类的析构函数**
（《05-类与面向对象/06-继承.md》第 3.1 小节）。
把基类析构声明成纯虚只是不允许创建 `Base` 对象，并没有取消这次调用，
因此实现必须存在。

`文档`

> "A virtual function declared in a class shall be defined, or declared pure (13.4) in that class,
> or both; no diagnostic is required (6.2)."
>
> —— N4659 §13.3/11
>
> "A pure virtual function need be defined only if called with, or as if with (15.4), the
> qualified-id syntax (8.1)."
>
> —— N4659 §13.4/2

# 第 5 节 重载、覆盖、隐藏的分工

## 5.1 三者的判定条件

三个词长得像，判定的条件各不相同：

| 名字 | 发生在哪两者之间 | 看什么 | 什么时候决定 | 结果 |
|---|---|---|---|---|
| **重载**（overload） | **同一个作用域**里的几个同名函数 | 参数表不同 | 编译期 | 按实参选一个 |
| **覆盖**（override） | 派生类与基类之间 | 名字相同、**签名相同**，且基类那个是虚函数 | 运行期 | 按对象的实际类型选 |
| **隐藏**（hide） | 派生类与基类之间 | **只要名字相同** | 编译期 | 基类那一整组名字在派生类里看不见 |

三者的分界可以这样记：

- **重载**要的是「同名不同参」，它与继承无关，一个类里、一个命名空间里都能发生。
- **覆盖**是「同名同签名 + 虚函数」，先满足虚函数的规则，才有运行期决议。
- **隐藏**只看名字。签名相同但不是虚函数，会隐藏；签名不同，也会隐藏（第 06 章第 4 节）。

> [!IMPORTANT]
> **隐藏是名字查找的规则，不是设计出来的功能。**
> 派生类里出现一个名字，就会把基类里所有同名的东西挡在身后——
> 这是「就近原则」的必然结果（《04-语法/11-作用域、生存期与链接.md》第 2.2 小节），
> 与参数表、与 `virtual` 都没有关系。

## 5.2 同一份代码里的三种情况

把三件事放进一份代码：基类里有一对重载，派生类里覆盖其中一个、又写出另一对重载。

`C++`

```cpp
/* three_ways.cpp    编译：g++ -std=c++17 three_ways.cpp -o three_ways */
#include <cstdio>

class Base {
public:
    virtual void g()             { std::printf("  Base::g()\n"); }
    void         g(int x)        { std::printf("  Base::g(int %d)\n", x); }
};

class Derived : public Base {
public:
    void g() override            { std::printf("  Derived::g()\n"); }            /* 覆盖 */
    void g(double y)             { std::printf("  Derived::g(double %.1f)\n", y); }  /* 隐藏 + 重载 */
};

int main() {
    Derived d;
    std::printf("d.g()        覆盖：调到派生类那个\n");        d.g();
    std::printf("d.g(1)       隐藏：Base::g(int) 看不见了\n");  d.g(1);
    std::printf("d.Base::g(1) 限定调用才到基类\n");            d.Base::g(1);

    Base *p = &d;
    std::printf("p->g()       虚函数：运行期按实际类型选\n");   p->g();
    std::printf("p->g(1)      非虚函数：编译期就定死\n");       p->g(1);
    return 0;
}
```

`实测数据`
`Text`

```text
d.g()        覆盖：调到派生类那个
  Derived::g()
d.g(1)       隐藏：Base::g(int) 看不见了
  Derived::g(double 1.0)
d.Base::g(1) 限定调用才到基类
  Base::g(int 1)
p->g()       虚函数：运行期按实际类型选
  Derived::g()
p->g(1)      非虚函数：编译期就定死
  Base::g(int 1)
```

逐行看：

| 写法 | 发生了什么 |
|---|---|
| `d.g()` | 名字查找在 `Derived` 里找到 `g()`，它就是覆盖基类的那一个，直接调用 |
| `d.g(1)` | 名字查找在 `Derived` 里找到**两个** `g`，`Base::g(int)` 参与不进来；`1` 转成 `double` |
| `d.Base::g(1)` | 限定调用绕开名字查找，直接点名基类那一组（第 06 章第 4.3 小节） |
| `p->g()` | 静态类型是 `Base`，名字查找找到 `Base::g()`；它是虚函数，运行期转到 `Derived::g()` |
| `p->g(1)` | `g(int)` 不是虚函数，编译期就写死了调 `Base::g(int)` |

## 5.3 各自解决什么问题

| | 解决什么问题 | 什么时候用 | 代价 |
|---|---|---|---|
| **重载** | 同一个概念、不同的参数类型，共用一个名字 | 几件事做法相通，只是参数不同（`print(int)`、`print(const char *)`） | 没有：编译期选定，可内联 |
| **覆盖** | 一族对象共享一套接口，各自的行为不同 | 调用点只该认识基类，且行为要按运行期的实际类型变 | 每个对象 8 字节，每次调用一次间接跳转 |
| **隐藏** | 不是功能，是规则的副作用 | 不需要，写代码时要主动避开 | 出错时没有提示（第 3.3 小节） |

**为什么不能互相替代**，各举一个例子就清楚了：

- 只有重载、没有覆盖：`print(shape)` 面对的是同一个类型 `Shape`，
  编译器无从知道里面装的是圆还是矩形，运行期也换不了函数。
- 只有覆盖、没有重载：`area()` 与 `area(int scale)` 就无法共用一个名字，
  得写成两个不同的名字。
- 隐藏既不是好事也不是坏事，它只是要求写代码时把话说清楚：
  想覆盖就写 `override`，想引入基类那一组就写 `using Base::g;`。

# 第 6 节 虚函数的代价

## 6.1 每个对象多一个指针

第 3.2 小节量过一个对象：`int` 从 4 字节变成 16 字节。
对象多起来之后，这笔账会变得明显：

`C++`

```cpp
/* cost_objects.cpp    编译：g++ -std=c++17 cost_objects.cpp -o cost_objects */
#include <cstdio>

class Plain  { public: int a = 1; int b = 2; };
class Virtual { public: int a = 1; int b = 2; virtual int v() const { return a; } };

int main() {
    const size_t n = 1000000;
    std::printf("sizeof(Plain)   = %zu，%zu 个对象占 %zu MB\n",
                sizeof(Plain), n, sizeof(Plain) * n / 1024 / 1024);
    std::printf("sizeof(Virtual) = %zu，%zu 个对象占 %zu MB\n",
                sizeof(Virtual), n, sizeof(Virtual) * n / 1024 / 1024);
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(Plain)   = 8，1000000 个对象占 7 MB
sizeof(Virtual) = 16，1000000 个对象占 15 MB
```

一百万个对象多花 8 MB，对普通程序不算什么；但如果对象本身只有十几个字节，
虚指针会让内存占用接近翻倍（`Plain` 这一组正好翻倍）。
**对象越小、数量越大，这笔开销越显眼。**

## 6.2 调用点：多一次间接跳转

代价还要看调用点。同一个 `v()`，通过基类指针调用与在已知类型的对象上调用，
编译出来的指令不同：

`C++`

```cpp
/* vcall.cpp    只用于看汇编：编译 g++ -std=c++17 -O0 -S vcall.cpp -o vcall_O0.s */
class Base {
public:
    virtual int v() const { return 1; }
};

class Derived : public Base {
public:
    int v() const override { return 2; }
};

int via_ptr(const Base *b)   { return b->v(); }   /* 只知道是 Base：必须查表 */
int via_ref(const Base &b)   { return b.v();  }
int via_local()              { Derived d; return d.v(); }   /* 类型完全确定 */
int via_local_base()         { Base b; return b.v(); }
```

不优化（`-O0`）编译出来，两个调用点是两种样子：

`实测数据`
`Assembly`

```asm
via_ptr:                            # int via_ptr(const Base *b) { return b->v(); }
        movq    16(%rbp), %rax
        movq    (%rax), %rax        # 从对象开头取出虚指针
        movq    (%rax), %rdx        # 取表里第一个槽位，也就是 v
        movq    %rax, %rcx          # this
        call    *%rdx               # 间接调用：调谁由运行期决定

via_local:                          # int via_local() { Derived d; return d.v(); }
        leaq    16+_ZTV7Derived(%rip), %rax
        movq    %rax, -8(%rbp)      # 对象开头写入 Derived 那张表的地址
        leaq    -8(%rbp), %rax
        movq    %rax, %rcx          # this
        call    _ZNK7Derived1vEv    # 类型已知：直接调用，不查表
```

（省去了栈帧建立与销毁的几条指令，其余照抄自 `-S` 生成的汇编。）

`call *%rdx` 与 `call _ZNK7Derived1vEv` 的差别就是这笔开销：
前者要先读两次内存才知道跳去哪，跳转目标不固定，编译器的优化空间小得多。

## 6.3 编译器能确定类型时就不查表

注意上面 `via_local` 那一份：**即使不加优化，编译器也没有查表**。
`d` 的类型在编译期完全确定，`Derived::v` 是唯一可能被调用的函数，
编译器直接把地址填进调用点。这种优化叫**去虚化**（devirtualization）。

开 `-O2` 之后差别更大：

`实测数据`
`Assembly`

```asm
via_ptr:                            # 只知道是 Base：只能查表
        movq    (%rcx), %rax
        rex.W jmp   *(%rax)         # 尾调用：直接跳进表里的函数

via_local:                          # Derived d; return d.v();
        movl    $2, %eax            # 整个函数被内联，结果算成了常量
        ret

via_local_base:                     # Base b; return b.v();
        movl    $1, %eax
        ret
```

> [!TIP]
> **虚函数不等于「一定慢」。** 编译器能证明对象的确切类型时（局部对象、
> 调用点上是具体类型、`final` 类、带 `-flto` 的跨文件分析），
> 间接调用会被换成直接调用，甚至整个函数被内联掉。
> 真正躲不开查表的是「通过基类指针或引用调用、而且实际类型编译期未知」这一类。

## 6.4 什么时候不要用虚函数

| 情形 | 理由 |
|---|---|
| 对象数量极大、每个对象都很小 | 每个对象多 8 字节，占比可能接近翻倍（第 6.1 小节） |
| 调用在极热的内层循环，且实际类型编译期未知 | 一次间接读内存加一次间接跳转，且不能内联 |
| 对象的布局要稳定（与 C 交互、跨编译器传递、直接按字节序列化） | 有虚函数的对象开头多一个指针，布局随实现变 |
| 用一次 `if`/`switch` 就能说清的分支 | 多加一层继承与虚函数，只是把简单的事写复杂 |

反过来，该用的时候也不要因为「有开销」而回避：
需要运行期多态时，手写的 `if` 链或函数指针表同样要花掉这些开销，
而且更难维护。

> [!WARNING]
> **虚函数表长什么样是编译器的实现方式，不要依赖它的布局。**
> 表的槽位顺序、对象里虚指针的位置、表前面的额外数据，
> 都由各平台的 ABI 约定，不同编译器、不同版本可能不同。
> 拿固定偏移去读虚表、或者把表的地址当成稳定的接口，都会在换工具链时出问题。

# 第 7 节 指向成员的指针

## 7.1 指向数据成员的指针

普通指针存的是地址，成员指针存的是「**哪一个成员**」：

`C++`

```cpp
int Base::*pm = &Base::b;       /* 类型是 int Base::*，不是 int * */
Base x;
x.*pm                           /* 在对象 x 上取这个成员 */
Base *p = &x;
p->*pm                          /* 等价于 (*p).*pm */
```

`&Base::b` 单独拿出来没有值可言，它必须配一个对象才能定位到具体内存。
尺寸也与普通指针不同：

`实测数据`

| 表达式 | 本机 `sizeof` |
|---|---|
| `sizeof(int Base::*)` | 8 字节 |
| `sizeof(int (Base::*)())` | 16 字节 |
| `sizeof(int *)` | 8 字节 |
| `sizeof(int (*)())` | 8 字节 |

两者是不同的类型，接不到一起：

`C++`

```cpp
/* member_ptr_null.cpp    编译：g++ -std=c++17 member_ptr_null.cpp -o member_ptr_null （失败） */
class Base { public: int a = 1; };

int main() {
    int *p = &Base::a;          /* 普通指针接不住成员指针 */
    return p != nullptr;
}
```

`实测数据`
`Text`

```text
member_ptr_null.cpp:5:14: error: cannot convert 'int Base::*' to 'int*' in initialization
```

`文档`

> "[Note: ... The type "pointer to member" is distinct from the type "pointer", that is, a pointer
> to member is declared only by the pointer to member declarator syntax, and never by the pointer
> declarator syntax. There is no "reference-to-member" type in C++. —end note]"
>
> —— N4659 §11.3.3/3

## 7.2 指向成员函数的指针

成员函数也能这样取地址，调用时用 `.*` 或 `->*` 把对象补上：

`C++`

```cpp
/* member_ptr.cpp    编译：g++ -std=c++17 member_ptr.cpp -o member_ptr */
#include <cstdio>

class Base {
public:
    int a = 1;
    int b = 2;
    virtual int v() { return 10; }      /* 虚函数 */
    int n()         { return 20; }      /* 非虚函数 */
};

class Derived : public Base {
public:
    int v() override { return 30; }
};

int main() {
    int Base::*pm = &Base::b;                   /* 指向数据成员 */
    Base    x;
    Derived d;
    std::printf("x.*pm = %d，d.*pm = %d\n", x.*pm, d.*pm);

    Base *p = &d;
    std::printf("p->*pm = %d\n", p->*pm);

    int (Base::*pv)() = &Base::v;               /* 指向虚函数 */
    std::printf("(x.*pv)() = %d，(d.*pv)() = %d\n", (x.*pv)(), (d.*pv)());

    int (Base::*pn)() = &Base::n;               /* 指向非虚函数 */
    std::printf("(d.*pn)() = %d\n", (d.*pn)());

    std::printf("sizeof(int Base::*) = %zu，sizeof(int (Base::*)()) = %zu\n",
                sizeof(pm), sizeof(pv));
    return 0;
}
```

`实测数据`
`Text`

```text
x.*pm = 2，d.*pm = 2
p->*pm = 2
(x.*pv)() = 10，(d.*pv)() = 30
(d.*pn)() = 20
sizeof(int Base::*) = 8，sizeof(int (Base::*)()) = 16
```

两点值得注意：

| 现象 | 说明 |
|---|---|
| `(x.*pv)()` 得 10，`(d.*pv)()` 得 30 | 成员指针指向虚函数时，**照样动态绑定**：调谁看对象的实际类型 |
| 成员函数指针 16 字节，比数据成员指针大 | 它要同时表达「哪个函数」与「怎么找到它」；具体布局由实现决定 |

`.*` 与 `->*` 的优先级很低，`(d.*pv)()` 的括号不能省；
完整优先级见《04-语法/04-表达式与运算符.md》第 3.12 小节。

## 7.3 日常为什么少用

| 原因 | 说明 |
|---|---|
| 语法重 | `.*`、`->*` 的优先级低，取地址的写法与普通函数指针不同，读起来费劲 |
| 大多数场合有更直接的写法 | 需要「运行期按类型选行为」就用虚函数；需要「把一段可调用代码传来传去」就用 lambda 或函数对象（【待补：05-类与面向对象/09-lambda 与函数对象.md】） |
| 与普通指针不通用 | 它是另一种类型，不能塞进 `void *` 或函数指针数组 |

它真正的用武之地是**把「成员」本身当成数据**：按名字查表找到某个成员再统一处理、
把一个取值函数传给通用的算法、框架里用成员函数指针做回调注册。

# 第 8 节 `dynamic_cast` 与 `typeid`

## 8.1 基类指针不一定指向你想要的那种对象

有了虚函数，一个 `Base *` 可以指向任何一种派生类对象，这是它的用处，
也是它带来的问题：拿到 `Base *` 的代码想知道「它到底指向什么」时，编译期没有答案。

两种处理办法，优先用第一种：

| 办法 | 做法 | 什么时候用 |
|---|---|---|
| 虚函数 | 把「不同对象该怎么做」交给对象自己，调用点只写一次 | **默认选择**，第 4.2 小节的那种写法 |
| `dynamic_cast` | 在调用点问「你是不是某一种」，是就转过去 | 只有某种派生类才有的操作必须由外部代码调用时 |

**`dynamic_cast` 是补丁，不是设计。** 调用点上一旦出现一串 `dynamic_cast` 加 `if`，
通常说明该被虚函数收进去的行为留在了外面。

## 8.2 `dynamic_cast`：转到指针与转到引用

`C++`

```cpp
/* rtti.cpp    编译：g++ -std=c++17 rtti.cpp -o rtti */
#include <cstdio>
#include <typeinfo>

class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void only_derived() { std::printf("    （只有 Derived 有的操作）\n"); }
};

class Other : public Base { };

void try_ptr(Base *p) {
    if (Derived *d = dynamic_cast<Derived *>(p)) {      /* 指针版：失败得 nullptr */
        std::printf("  转成 Derived 成功，调用它特有的操作\n");
        d->only_derived();
    } else {
        std::printf("  转成 Derived 失败，得到 nullptr\n");
    }
}

int main() {
    Derived d;
    Other   o;

    std::printf("typeid 拿到的名字：\n");
    std::printf("  typeid(d).name()  = %s\n", typeid(d).name());
    std::printf("  typeid(o).name()  = %s\n", typeid(o).name());

    Base *p1 = &d;
    Base *p2 = &o;
    std::printf("通过基类指针看实际类型：\n");
    std::printf("  typeid(*p1).name() = %s\n", typeid(*p1).name());
    std::printf("  typeid(*p2).name() = %s\n", typeid(*p2).name());

    std::printf("dynamic_cast 到指针：\n");
    try_ptr(p1);
    try_ptr(p2);

    std::printf("dynamic_cast 到引用：\n");
    Base &r = o;
    try {
        Derived &dr = dynamic_cast<Derived &>(r);       /* 引用版：失败抛异常 */
        std::printf("  成功，%s\n", typeid(dr).name());
    } catch (const std::bad_cast &e) {
        std::printf("  失败，异常是 %s\n", e.what());
    }
    return 0;
}
```

`实测数据`
`Text`

```text
typeid 拿到的名字：
  typeid(d).name()  = 7Derived
  typeid(o).name()  = 5Other
通过基类指针看实际类型：
  typeid(*p1).name() = 7Derived
  typeid(*p2).name() = 5Other
dynamic_cast 到指针：
  转成 Derived 成功，调用它特有的操作
    （只有 Derived 有的操作）
  转成 Derived 失败，得到 nullptr
dynamic_cast 到引用：
  失败，异常是 std::bad_cast
```

| 转到的目标 | 失败时 |
|---|---|
| 指针（`dynamic_cast<Derived *>`） | 得到空指针，**要判空**，这是推荐写法 |
| 引用（`dynamic_cast<Derived &>`） | 抛 `std::bad_cast`，因此引用版只适合「确定成功」的场合 |

`文档`

> "Otherwise, v shall be a pointer to or a glvalue of a polymorphic type (13.3)."
>
> —— N4659 §8.2.7/6
>
> "The value of a failed cast to pointer type is the null pointer value of the required result
> type. A failed cast to reference type throws an exception (18.1) of a type that would match a
> handler (18.3) of type std::bad_cast (21.7.3)."
>
> —— N4659 §8.2.7/9

`dynamic_cast` 还有一个前置条件：**源类型必须是多态类型**（也就是带虚函数的类）：

`C++`

```cpp
/* rtti_no_poly.cpp    编译：g++ -std=c++17 rtti_no_poly.cpp -o rtti_no_poly （失败） */
class Base { public: void f() { } };
class Derived : public Base { };

int main() {
    Base b;
    Base *p = &b;
    Derived *d = dynamic_cast<Derived *>(p);    /* 基类不是多态类型 */
    return d != nullptr;
}
```

`实测数据`
`Text`

```text
rtti_no_poly.cpp:8:18: error: cannot 'dynamic_cast' 'p' (of type 'class Base*') to type 'class Derived*' (source type is not polymorphic)
```

原因与第 3.2 小节是同一件事：类型信息挂在虚函数表旁边，
没有虚函数的类里没有这个指针，运行期无从查起。

## 8.3 `typeid`：多态类型给动态类型

`typeid` 的结果是一个 `std::type_info` 对象。它有一处特殊规则：
**表达式是多态类型的左值时，它给的是动态类型**（上面的 `7Derived`）；
否则给的是静态类型：

`C++`

```cpp
/* rtti_static.cpp    编译：g++ -std=c++17 rtti_static.cpp -o rtti_static */
#include <cstdio>
#include <typeinfo>

class Base {                        /* 没有虚函数：非多态类型 */
public:
    void f() { }
};

class Derived : public Base { };

int main() {
    Derived d;
    Base *p = &d;                   /* 指向的其实是 Derived */
    std::printf("typeid(*p).name() = %s\n", typeid(*p).name());
    return 0;
}
```

`实测数据`
`Text`

```text
typeid(*p).name() = 4Base
```

`p` 明明指着 `Derived`，`typeid(*p)` 却给出 `Base`——因为 `Base` 没有虚函数，
`*p` 不是多态类型的左值，规则退回静态类型。

`文档`

> "When typeid is applied to a glvalue expression whose type is a polymorphic class type (13.3),
> the result refers to a std::type_info object representing the type of the most derived object
> (4.5) (that is, the dynamic type) to which the glvalue refers."
>
> —— N4659 §8.2.8/2
>
> "When typeid is applied to an expression other than a glvalue of a polymorphic class type,
> the result refers to a std::type_info object representing the static type of the expression."
>
> —— N4659 §8.2.8/3

`name()` 给出的字符串是实现定义的，本机是 `7Derived` 这样的名字修饰结果：

`文档`

> "The class type_info describes type information generated by the implementation. Objects of
> this class effectively store a pointer to a name for the type, and an encoded value suitable
> for comparing two types for equality or collating order. The names, encoding rule, and
> collating sequence for types are all unspecified and may differ between programs."
>
> —— N4659 §21.7.2/1

> [!WARNING]
> **`name()` 返回的字符串只能看，不能用来判断类型。**
> 它的格式由实现决定，各编译器不一样，同一编译器换版本也可能变。
> 要比较两个类型是否相同，写 `typeid(a) == typeid(b)`。

## 8.4 RTTI 的代价与关掉它

上面这些能力合起来叫 **RTTI**（运行期类型信息）。它的成本主要在只读数据段里多出的几张表：

`实测数据`
`Text`

```text
000000014000a9c0 R typeinfo for Base
000000014000a9d0 R typeinfo for Derived
000000014000a9f0 R typeinfo name for Base
000000014000aa00 R typeinfo name for Derived
```

**对象本身不变大**：同一份程序在开着 RTTI 与关掉 RTTI 两种设置下编译，
`sizeof` 的结果完全一样。

`实测数据`

| 编译选项 | `sizeof(Plain)` | `sizeof(Virtual)` |
|---|---|---|
| `g++ -std=c++17` | 8 | 16 |
| `g++ -std=c++17 -fno-rtti` | 8 | 16 |

关掉 RTTI 之后，`dynamic_cast` 与 `typeid` 都不能用了，编译器会直接说：

`实测数据`
`Text`

```text
rtti.cpp:18:22: error: 'dynamic_cast' not permitted with '-fno-rtti'
rtti.cpp:31:54: error: cannot use 'typeid' with '-fno-rtti'
```

| 判断 | 说明 |
|---|---|
| 需要 `dynamic_cast` 或 `typeid` 吗 | 需要就留着 RTTI，它不增加对象大小 |
| 想要的只是「按类型做不同的事」 | 那要的是虚函数，不是 RTTI（第 8.1 小节） |
| 嵌入式等对二进制体积敏感、又确实用不到 | 可以加 `-fno-rtti` 省下类型信息表 |

# 第 9 节 检查清单

写代码时逐条对照：

| 检查 | 说明 |
|---|---|
| 覆盖基类虚函数时写了 `override` | 签名写错时编译器会报错，而不是静默变成隐藏（第 3.3 小节） |
| 基类的析构函数是虚函数 | 只要存在「用基类指针删除对象」的可能就必须是（第 3.5 小节） |
| 没有在构造函数或析构函数里调用虚函数并指望派生类的版本 | 那期间不做动态绑定（第 3.6 小节） |
| 重载之间的区别只在参数表 | 返回类型不同不构成重载（第 2.6 小节） |
| 不希望被隐式转换的构造函数加了 `explicit` | 否则它会参与重载决议（第 2.3 小节） |
| 遇到二义报错时先想清楚想要哪一个重载 | 靠强转压下去，下次换个人调用还会遇到（第 2.4 小节） |
| 不该接受的实参用 `= delete` 明确划掉 | 比留一条隐式转换的路更安全（第 2.5 小节） |
| 需要运行期多态时用虚函数 | 而不是在调用点写一串 `if` 加 `dynamic_cast`（第 8.1 小节） |
| 没有依赖虚函数表的布局 | 那是实现细节，换编译器就变（第 6.4 小节） |
| 对象数量极大且都很小时量过内存 | 每个对象 8 字节的虚指针可能让占用接近翻倍（第 6.1 小节） |

# 术语表

| 词 | 含义 | 在哪一节 |
|---|---|---|
| **多态** | 同一个写法在不同情况下做不同的事；C++ 里分编译期与运行期两批 | 第 1 节 |
| **静态绑定** | 调用哪个函数在编译期就定死 | 第 1.1 节 |
| **动态绑定** | 调用哪个函数在运行期按对象的实际类型决定 | 第 1.2 节 |
| **重载**（overload） | 同一作用域里同名而参数表不同的几个函数 | 第 2.1 小节 |
| **重载决议** | 编译器按实参从重载集合里挑出最佳可行函数的过程 | 第 2.2 小节 |
| **二义** | 有多个一样好的候选，重载决议失败 | 第 2.4 小节 |
| **删除函数** | 用 `= delete` 划掉的函数；它仍参与决议，但被选中就报错 | 第 2.5 小节 |
| **虚函数** | 基类里用 `virtual` 声明的成员函数，调用时按对象实际类型选 | 第 3.1 小节 |
| **覆盖**（override） | 派生类给出同名同签名的虚函数，取代基类那一份 | 第 3.1 小节 |
| **虚函数表**（vtable） | 每个多态类一张的只读函数地址表 | 第 3.2 小节 |
| **虚指针**（vptr） | 每个多态对象里那个指向本类虚函数表的指针 | 第 3.2 小节 |
| **纯虚函数** | 声明为 `= 0` 的虚函数，派生类必须给实现 | 第 4.1 小节 |
| **抽象类** | 含纯虚函数（含继承来的）的类，不能创建对象 | 第 4.1 小节 |
| **隐藏**（hide） | 派生类的同名成员让基类那一组名字在派生类里看不见 | 第 5.1 小节 |
| **去虚化** | 编译器能确定实际类型时，把查表的间接调用换成直接调用 | 第 6.3 小节 |
| **成员指针** | 指向类的某个成员的指针，要配合对象使用 | 第 7 节 |
| **RTTI** | 运行期类型信息，`dynamic_cast` 与 `typeid` 靠它工作 | 第 8 节 |

## A.1 构造期间调用纯虚函数

第 3.6 小节说明了构造期间不做动态绑定。如果基类构造函数调用的那个虚函数**根本没有实现**，
后果会更直接：

`C++`

```cpp
/* pure_call_ctor.cpp    编译：g++ -std=c++17 pure_call_ctor.cpp -o pure_call_ctor */
#include <cstdio>

class Base {
public:
    Base() { std::printf("  基类构造里调用 show()\n"); std::fflush(stdout); show(); }
    void show() const { std::printf("  area() = %g\n", area()); std::fflush(stdout); }
    virtual double area() const = 0;
};

class Derived : public Base {
public:
    double area() const override { return 1.0; }
};

int main() {
    Derived d;
    std::printf("  对象建好之后调用 area()：%g\n", d.area());
    return 0;
}
```

`show()` 不是虚函数，它内部的 `area()` 是一次虚调用。
`Base` 那一段构造时，`area` 在表里的槽位指向的是「未实现」的占位，两侧平台的表现不同：

`实测数据`
`Text`

```text
Windows（g++ 15.2.0，MinGW-w64）：
  基类构造里调用 show()
  进程以 0xC0000005（访问冲突）终止，没有任何提示

Linux（g++ 13.3.0）：
  基类构造里调用 show()
  pure virtual method called
  terminate called without an active exception
  进程以 134（SIGABRT）终止
```

两边都没有走到 `main` 的第二行。**这不是「未定义行为」四个字能带过的边角情况**：
基类构造函数里只要有一条路径会调到纯虚函数，程序就活不到构造完成。
