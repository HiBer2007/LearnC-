# 第 1 节 成员属于对象还是类

## 1.1 `static` 数据成员：全类一份

普通数据成员是对象的一部分：每建一个对象就有一份。
在声明前面写 `static`，这个成员就变成**整个类共有一份**，与对象无关。

`C++`

```cpp
/* static_member.cpp    编译：g++ -std=c++17 static_member.cpp -o static_member */
#include <cstdio>

class Counter {
public:
    Counter()  { ++total_; }
    ~Counter() { --total_; }

    static int total() { return total_; }       /* 没有 this，只能碰静态成员 */
    static void *total_addr() { return &total_; }   /* 取静态成员的地址，供下面打印 */

    int payload = 7;                            /* 普通成员：每个对象一份 */
private:
    static int total_;                          /* 静态成员：全类一份，类外定义 */
};

int Counter::total_ = 0;                        /* 定义（也只能定义一次） */

int main() {
    std::printf("开始：total = %d\n", Counter::total());
    {
        Counter a, b, c;
        std::printf("三个对象：total = %d\n", Counter::total());
        std::printf("sizeof(Counter) = %zu（static 成员不计入对象大小）\n", sizeof(Counter));
        std::printf("a.payload 的地址 %p，total_ 的地址 %p（不同区域）\n",
                    static_cast<void *>(&a.payload), Counter::total_addr());
    }
    std::printf("离开作用域：total = %d\n", Counter::total());
    return 0;
}
```

`实测数据`
`Text`

```text
开始：total = 0
三个对象：total = 3
sizeof(Counter) = 4（static 成员不计入对象大小）
a.payload 的地址 000000fc2d3ffbfc，total_ 的地址 00007ff6f6c0d030（不同区域）
离开作用域：total = 0
```

三个对象加起来还是 4 字节——`sizeof` 只数对象自己的成员，
`total_` 根本不在对象里，它由整个程序共享。

`文档`

> "A static data member is not part of the subobjects of a class. If a static data member is declared
> thread_local there is one copy of the member per thread. If a static data member is not declared
> thread_local there is one copy of the data member that is shared by all the objects of the class."
>
> —— N4659 §12.2.3.2/1

## 1.2 静态成员的声明、定义与初始化

静态成员写起来有个容易踩的地方：**类内那句是声明，不是定义**。
非 `const` 的静态成员不能在类内给初值：

`C++`

```cpp
/* static_init_fail.cpp    编译：g++ -std=c++17 static_init_fail.cpp -o static_init_fail （失败） */
class Config {
    static int count_ = 0;      /* 非 const 的静态成员不能在类内给初值 */
};

int main() {
    return Config::count_;
}
```

`实测数据`
`Text`

```text
static_init_fail.cpp:3:16: error: ISO C++ forbids in-class initialization of non-const static member 'Config::count_'
```

如果只声明、忘了在类外定义，编译照样通过，**要到链接时才报错**：

`C++`

```cpp
/* static_undef.cpp    编译：g++ -std=c++17 static_undef.cpp -o static_undef （失败） */
#include <cstdio>

class Config {
public:
    static int count_;          /* 声明了，但谁也没定义它 */
};

int main() {
    std::printf("%d\n", Config::count_);
    return 0;
}
```

`实测数据`
`Text`

```text
undefined reference to `Config::count_'
collect2.exe: error: ld returned 1 exit status
```

C++17 起有两条捷径，可以不必在类外再写一遍：

`C++`

```cpp
/* static_inline.cpp    编译：g++ -std=c++17 static_inline.cpp -o static_inline */
#include <cstdio>

class Config {
public:
    inline static int count_ = 0;               /* C++17：类内定义，不必再写类外定义 */
    static constexpr int limit = 8;             /* C++17：constexpr 静态成员隐含 inline */
    static const int table[3];                  /* 数组仍要在类外定义 */
};

const int Config::table[3] = {1, 2, 3};

int main() {
    Config::count_ = 5;
    std::printf("count_ = %d，limit = %d，table[1] = %d\n",
                Config::count_, Config::limit, Config::table[1]);
    std::printf("limit 的地址 %p（有地址，说明它真的是一个对象）\n",
                static_cast<const void *>(&Config::limit));
    return 0;
}
```

`实测数据`
`Text`

```text
count_ = 5，limit = 8，table[1] = 2
limit 的地址 00007ff71cbaa950（有地址，说明它真的是一个对象）
```

| 写法 | 类内给初值 | 还要类外定义吗 |
|---|---|---|
| `static int n_;` | 不行 | **要**（`int C::n_ = 0;`），否则链接失败 |
| `static const int n_ = 3;` | 可以 | 只当常量用就不用；**一旦取地址或绑引用就要** |
| `inline static int n_ = 3;` | 可以（C++17） | 不用 |
| `static constexpr int n_ = 3;` | 可以（C++17 起隐含 `inline`） | 不用 |

`文档`

> "An inline static data member may be defined in the class definition and may specify a
> brace-or-equal-initializer."
>
> —— N4659 §12.2.3.2/3
>
> "A function or static data member declared with the constexpr specifier is implicitly an inline
> function or variable (10.1.6)."
>
> —— N4659 §10.1.5/1

## 1.3 静态成员函数：没有 `this`

《05-类与面向对象/02-类是一种类型.md》第 2.4 小节实测过：静态成员函数里没有 `this`，因此它也碰不到非静态成员。
由此可以直接推出它的两条限制：

`C++`

```cpp
/* static_mfct_fail.cpp    编译：g++ -std=c++17 static_mfct_fail.cpp -o static_mfct_fail （失败） */
class Widget {
public:
    static int value() const { return 1; }      /* 静态成员函数没有 this，不能是 const */
    virtual static int other() { return 2; }    /* 也不能是虚函数 */
};

int main() {
    return Widget::value() + Widget::other();
}
```

`实测数据`
`Text`

```text
static_mfct_fail.cpp:4:24: error: static member function 'static int Widget::value()' cannot have cv-qualifier
static_mfct_fail.cpp:5:5: error: member 'other' cannot be declared both 'virtual' and 'static'
```

两条错误的原因是同一条：`const` 修饰的是 `this` 指向的对象，
虚函数要按对象的实际类型查表——**两者都以「有一个对象」为前提**。

`文档`

> "[Note: A static member function does not have a this pointer (12.2.2.1). —end note] A static member
> function shall not be virtual. There shall not be a static and a non-static member function with the
> same name and the same parameter types (16.1). A static member function shall not be declared const,
> volatile, or const volatile."
>
> —— N4659 §12.2.3.1/2

## 1.4 静态成员的用途与代价

静态成员函数不必先有对象就能调，因此适合做「造对象」这件事：

`C++`

```cpp
/* static_factory.cpp    编译：g++ -std=c++17 static_factory.cpp -o static_factory */
#include <cstdio>

class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}

    static Point origin() { return Point(0, 0); }          /* 工厂函数：不必先有对象 */
    static Point scaled(int k) { return Point(k * 2, k * 3); }

    static int manhattan(const Point &p) {                 /* 静态成员函数也是成员：能碰私有 */
        return p.x_ + p.y_;
    }

    int x() const { return x_; }
    int y() const { return y_; }
private:
    int x_, y_;
};

int main() {
    Point o = Point::origin();
    Point s = Point::scaled(2);
    std::printf("origin：(%d, %d)\n", o.x(), o.y());
    std::printf("scaled(2)：(%d, %d)\n", s.x(), s.y());
    std::printf("manhattan(s) = %d\n", Point::manhattan(s));

    std::printf("通过对象调静态成员也合法：(%d, %d)（对象本身不参与）\n",
                s.origin().x(), s.origin().y());
    return 0;
}
```

`实测数据`
`Text`

```text
origin：(0, 0)
scaled(2)：(4, 6)
manhattan(s) = 10
通过对象调静态成员也合法：(0, 0)（对象本身不参与）
```

**但静态数据成员带来一个真实的风险：它们的初始化顺序，跨翻译单元时是不确定的。**
同一份源码，只把两个目标文件的链接顺序换一下，结果就变了：

`C++`

```cpp
/* siof_a.cpp    编译：g++ -std=c++17 -c siof_a.cpp -o siof_a.o */
#include <cstdio>

int value();                    /* 来自 siof_b.cpp */

int a = value();                /* 全局对象：它的初始化要用到另一个翻译单元的全局量 */

int main() {
    std::printf("main 里看到 a = %d\n", a);
    return 0;
}
```

`C++`

```cpp
/* siof_b.cpp    编译：g++ -std=c++17 -c siof_b.cpp -o siof_b.o */
int make_b() { return 7; }

int b = make_b();               /* 函数调用 → 动态初始化，时机不定 */
int value() { return b; }       /* 读的是这个文件里的 b */
```

`实测数据`
`Text`

```text
链接顺序「siof_a.o 在前」：main 里看到 a = 7
链接顺序「siof_b.o 在前」：main 里看到 a = 0
```

`a = 0` 就是问题的样子：`a` 的初始化跑到 `b` 前面去了，读到的是还没赋值的 `0`。
**编译器不会为这件事报警**，而换一个链接顺序、换一个编译器版本，行为都可能变。

> [!CAUTION]
> **不要让一个翻译单元的全局对象，在构造函数里去用另一个翻译单元的全局对象。**
> 需要「用到时才初始化」的全局量，用函数内的局部静态变量：
> 它的初始化由编译器保证「第一次执行到这一行时完成」，而且只做一次。

# 第 2 节 `const` 成员函数与 `mutable`

## 2.1 `const` 成员函数承诺了什么

第 02 章第 2.3 小节讲过：成员函数后面写 `const`，等于把 `this` 的类型从 `T *` 改成 `const T *`。
承诺的内容是**这个函数不会改对象的数据成员**，换来的是「`const` 对象也能调它」。

一对同名函数只差一个 `const` 时，它们是**重载**：编译器按对象的 `const` 与否来选。
第 09 章第 3.3 小节的下标运算符就是这一对（《05-类与面向对象/09-运算符重载.md》）：

`C++`

```cpp
int &operator[](int i)             { return data_[i]; }   /* 非 const 对象：能改 */
const int &operator[](int i) const { return data_[i]; }   /* const 对象：只能读 */
```

**承诺的范围只是「数据成员」**，不包括对象指向的那些外部资源。
一个持有文件句柄的 `const` 对象，它的 `const` 成员函数照样能往文件里写——
被承诺不改的是「句柄存在哪个成员里」，不是「句柄指向的文件内容」。

## 2.2 `mutable`：只读承诺里的例外

有一类成员天生要在 `const` 成员函数里被改：**缓存、计数器、锁**。
它们不改变对象对外的状态，只是内部记账。把这类成员声明成 `mutable`，
`const` 成员函数就能改它们：

`C++`

```cpp
/* mutable_cache.cpp    编译：g++ -std=c++17 mutable_cache.cpp -o mutable_cache */
#include <cstdio>
#include <cstring>

class Report {
public:
    Report(const char *text) : text_(text) {}

    int length() const {                          /* const 成员函数：不修改对象的对外状态 */
        if (cached_ < 0) {                        /* 缓存是内部实现细节 */
            cached_ = (int)std::strlen(text_);    /* 没有 mutable 就改不了 */
            ++calls_;
            std::printf("  （这次真的算了一遍）\n");
        }
        return cached_;
    }
    int calls() const { return calls_; }
private:
    const char *text_;
    mutable int cached_ = -1;                     /* 这两个是 mutable */
    mutable int calls_  = 0;
};

int main() {
    const Report r("hello");
    std::printf("第一次：%d\n", r.length());
    std::printf("第二次：%d\n", r.length());
    std::printf("实际计算次数：%d\n", r.calls());
    return 0;
}
```

`实测数据`
`Text`

```text
  （这次真的算了一遍）
第一次：5
第二次：5
实际计算次数：1
```

`r` 是 `const` 对象，两次 `length()` 都能调；第一次算完存进 `cached_`，
第二次直接返回缓存。**对调用方来说 `r` 没有变化**，变的只是它内部的账。

`文档`

> "The mutable specifier on a class data member nullifies a const specifier applied to the containing
> class object and permits modification of the mutable class member even though the rest of the object
> is const (10.1.7.1)."
>
> —— N4659 §10.1.1/9

## 2.3 `mutable` 的两个禁区

`mutable` 只能用在**非静态数据成员**上，而且不能与 `const` 同用：

`C++`

```cpp
/* mutable_fail.cpp    编译：g++ -std=c++17 mutable_fail.cpp -o mutable_fail （失败） */
class Bad {
    static mutable int count_;      /* mutable 不能用在静态成员上 */
    mutable const int fixed_ = 1;   /* 也不能用在 const 成员上 */
};
int Bad::count_ = 0;

int main() {
    return Bad().fixed_;
}
```

`实测数据`
`Text`

```text
mutable_fail.cpp:3:12: error: 'mutable' specifier conflicts with 'static'
mutable_fail.cpp:4:5: error: 'const' 'fixed_' cannot be declared 'mutable'
```

两条限制都合乎逻辑：静态成员不属于任何对象，「在 `const` 对象里改不了」这件事与它无关；
而 `const` 成员**本来就要求不改**，再声明 `mutable` 是自相矛盾。

`文档`

> "The mutable specifier shall appear only in the declaration of a non-static data member (12.2) whose
> type is neither const-qualified nor a reference type."
>
> —— N4659 §10.1.1/8
>
> "A static data member shall not be mutable (10.1.1)."
>
> —— N4659 §12.2.3.2/7

> [!WARNING]
> **`mutable` 不是「绕过 `const`」的开关。**
> 它该用在「这个改动不影响对象对外的可见状态」的成员上：缓存、统计、同步用的锁。
> 如果一个 `const` 成员函数改的是对象的业务数据，那说明这个函数本来就不该是 `const`，
> 正确的做法是把它后面的 `const` 去掉。

# 第 3 节 `explicit`：挡住隐式转换

## 3.1 隐式转换是什么

**类型转换分两类，来源完全不同。**

| 类别 | 谁定义的 | 例子 |
|---|---|---|
| **标准转换** | 语言规定，编译器直接生成 | `int` → `long`、`float` → `double`、数组 → 指针、派生类指针 → 基类指针 |
| **用户定义转换** | 类作者写的代码 | `const char *` → `Text`、`Handle` → `bool` |

标准转换是「同一个值的不同表示」，编译器按固定的规则做，作者无从干预。
**用户定义转换则完全由类作者决定**，它有且只有两条通道：

| 通道 | 写法 | 方向 |
|---|---|---|
| **转换构造函数** | 一个可以用单个实参调用的构造函数 | 别的类型 → 本类型 |
| **转换运算符** | `operator T()` | 本类型 → 别的类型 |

两条通道都是「作者主动开的门」。门开着的时候，**编译器会在你没有写出转换的地方用上它**：
初始化、赋值、传实参、返回值、条件判断，这五处只要类型对不上，编译器就会去这些通道里找路。

第 08 章第 2.3 小节实测过这件事的后果：用户定义转换在重载决议里排在标准转换之后，
但它**仍然是一条候选路径**。也就是说，只要门开着，
「一个整数悄悄变成一个对象」这种事会在作者完全没打算转换的地方发生。

`C++`

```cpp
long   n = 3;           // 标准转换：int → long，语言规定的
double d = n;           // 标准转换：long → double
```

`explicit` 的作用就是**把其中一条门关上**，让这个转换只在作者明确写出来时才发生。
下面两小节分别看两条通道。

## 3.2 转换构造函数：从一个值到一个对象

单个参数的构造函数（严格说，是「能用一个实参调用」的构造函数）会被编译器当成转换用：
`Implicit(3)` 与 `3` 之间可以自动转换。这带来方便，也带来意外：

`C++`

```cpp
/* explicit_ctor.cpp    编译：g++ -std=c++17 explicit_ctor.cpp -o explicit_ctor */
#include <cstdio>

class Implicit {
public:
    Implicit(int v) : v_(v) {}          /* 转换构造函数 */
    int v_;
};

class Strict {
public:
    explicit Strict(int v) : v_(v) {}   /* 挡住隐式转换 */
    int v_;
};

void take_implicit(Implicit x) { std::printf("  Implicit：%d\n", x.v_); }
void take_strict(Strict x)     { std::printf("  Strict：%d\n", x.v_); }

int main() {
    take_implicit(3);                   /* 3 被隐式转成 Implicit */
    take_strict(Strict(3));             /* 必须显式写出来 */
    Strict s = Strict(3);               /* 直接初始化：可以 */
    std::printf("s.v_ = %d\n", s.v_);
    return 0;
}
```

`实测数据`
`Text`

```text
  Implicit：3
  Strict：3
s.v_ = 3
```

把 `explicit` 加上之后，两种隐式写法都会被拦下：

`C++`

```cpp
/* explicit_ctor_fail.cpp    编译：g++ -std=c++17 explicit_ctor_fail.cpp -o explicit_ctor_fail （失败） */
class Strict {
public:
    explicit Strict(int v) : v_(v) {}
    int v_;
};

void take(Strict x) { (void)x; }

int main() {
    take(3);                    /* 隐式转换被挡住 */
    Strict s = 3;               /* 拷贝初始化也不行 */
    return s.v_;
}
```

`实测数据`
`Text`

```text
explicit_ctor_fail.cpp:11:10: error: could not convert '3' from 'int' to 'Strict'
```

| 写法 | 没有 `explicit` | 加了 `explicit` |
|---|---|---|
| `Strict s(3);` | 可以 | **可以**（直接初始化） |
| `Strict s = 3;` | 可以 | 不行（拷贝初始化） |
| `take(3);` | 可以 | 不行 |
| `take(Strict(3));` | 可以 | **可以** |

`文档`

> "A constructor declared without the function-specifier explicit specifies a conversion from the types
> of its parameters (if any) to the type of its class. Such a constructor is called a converting
> constructor."
>
> —— N4659 §15.3.1/1
>
> "[Note: An explicit constructor constructs objects just like non-explicit constructors, but does so
> only where the direct-initialization syntax (11.6) or where casts (8.2.9, 8.4) are explicitly used;
> ... —end note]"
>
> —— N4659 §15.3.1/2

## 3.3 隐式转换会参与重载决议

门开着的时候，这条转换不只是「能转换」，它还**进到重载决议里去抢候选**。
下面这个程序里，`print` 有两个重载，`Text` 有一个转换构造函数：

`C++`

```cpp
/* explicit_hijack.cpp    编译：g++ -std=c++17 explicit_hijack.cpp -o explicit_hijack */
#include <cstdio>

class Text {
public:
    Text(const char *s) : s_(s) {}          /* 转换构造函数：const char * → Text */
    const char *s_;
};

void print(Text t) { std::printf("print(Text)：%s\n", t.s_); }
void print(bool b) { std::printf("print(bool)：%d\n", b); }

int main() {
    print("abc");                           /* 实参是 const char *：走哪一条路 */
    print(Text("abc"));                     /* 明确写出要哪一种 */
    return 0;
}
```

`实测数据`
`Text`

```text
print(bool)：1
print(Text)：abc
```

**第一行落到了 `print(bool)` 上**，尽管作者写这个类就是为了接收字符串。
原因是第 08 章第 2.2 小节那张排序表：`const char *` → `bool` 是**标准转换**，
`const char *` → `Text` 是**用户定义转换**，前者等级更高。
作者以为开了「字符串进 `Text`」的门，实际却把「指针变真假」这条更便宜的路让给了编译器。

`Text` 的构造函数加上 `explicit` 之后，`print(bool)` 这条路上就没有 `Text` 的影子了，
第一行会直接编不过——**错误出现在调用点，而不是在后面某个莫名其妙的地方**。

## 3.4 直接初始化与拷贝初始化

`explicit` 能挡住哪些写法、挡不住哪些，取决于那处写法是否**要求一次隐式转换**。
标准把初始化分成两类：

| 类别 | 写法 | 要不要隐式转换 |
|---|---|---|
| **直接初始化** | `T x(3);`、`T x{3};`、`static_cast<T>(3)`、`T(3)` | 不要：作者明确写了 `T` |
| **拷贝初始化** | `T x = 3;`、`f(3)`（实参传递）、`return 3;`、`T arr[] = {3};` | **要**：这些位置都要求「把右边的值转换过去」 |
| **上下文转换** | `if (x)`、`!x`、`while (x)` | 要，但规则特殊（第 3.6 小节） |

区分标准只有一条：**`=` 与「把值传进去」都算拷贝初始化，它们要求一次隐式转换。**
所以 `T x(3);` 能用而 `T x = 3;` 不能用，并不是编译器挑剔，
而是后者在语法上就是「把 `3` 拷贝初始化成 `T`」，那一步正是 `explicit` 关掉的东西。

## 3.5 `explicit` 做了什么

`explicit` **不改变构造函数本身**：它照样能用，照样初始化成员，`T x(3);` 照旧。
它做的只有一件事——**把这个构造函数从「可以用于隐式转换」的名单里划掉**。
三个后果：

| 后果 | 说明 |
|---|---|
| 直接初始化不受影响 | `Strict s(3);`、`Strict s{3};`、`static_cast<Strict>(3)` 都可以 |
| 拷贝初始化与实参传递不再考虑它 | `Strict s = 3;`、`take(3);` 变成错误 |
| 重载决议里少一条候选路径 | 第 3.3 小节那种「被别处抢走」的情况不再发生 |

因此 `explicit` 是个**纯粹的表达工具**：它不改变行为，只改变「作者允许编译器自动做什么」。
这也是为什么它几乎没有代价——多写几个字符，换来的是调用点上的错误更早、更贴近原因。

## 3.6 反方向：`explicit` 转换运算符与上下文转换

反过来的方向也能挡住：类自己提供「转成别的类型」的能力时，
在转换运算符前面写 `explicit`，就只允许它在**条件位置**被使用：

`C++`

```cpp
/* explicit_conv.cpp    编译：g++ -std=c++17 explicit_conv.cpp -o explicit_conv */
#include <cstdio>

class Handle {
public:
    explicit operator bool() const { return valid_; }   /* 只在条件里能用 */
    bool valid_ = true;
};

int main() {
    Handle h;
    if (h) std::printf("if (h) 可以：上下文转换\n");      /* 条件位置允许 explicit */
    std::printf("!h = %d\n", !h);
    return 0;
}
```

`实测数据`
`Text`

```text
if (h) 可以：上下文转换
!h = 0
```

想在别处拿它当 `bool` 用就不行了：

`C++`

```cpp
/* explicit_conv_fail.cpp    编译：g++ -std=c++17 explicit_conv_fail.cpp -o explicit_conv_fail （失败） */
class Handle {
public:
    explicit operator bool() const { return true; }
};

int main() {
    Handle h;
    bool b = h;             /* 拷贝初始化：explicit 转换运算符不参与 */
    return b;
}
```

`实测数据`
`Text`

```text
explicit_conv_fail.cpp:9:14: error: cannot convert 'Handle' to 'bool' in initialization
```

`if (h)`、`!h`、`h && x` 这类位置叫**上下文转换**：那里本来就需要一个条件，
编译器允许调用 `explicit` 转换运算符。`bool b = h;` 不是条件位置，因此被挡下。
**这正是 `explicit operator bool()` 想要的**：让 `if (handle)` 写得自然，
又不让 `handle` 到处被当成整数用。

## 3.7 C++20 的 `explicit(bool)`

C++20 起，`explicit` 后面可以跟一个常量表达式，按类型决定要不要 explicit。
下面这段用 `g++ -std=c++20` 实测通过，**属于超出本教材 C++17 基准的内容**：

`C++`

```cpp
/* explicit_bool.cpp    编译：g++ -std=c++20 explicit_bool.cpp -o explicit_bool */
#include <cstdio>
#include <type_traits>

template <class T>
class Maybe {
public:
    Maybe(T v) : has_(true), v_(v) {}
    Maybe() : has_(false), v_(T{}) {}

    explicit(!std::is_pointer<T>::value) operator bool() const { return has_; }  /* C++20 */
    T value() const { return v_; }
private:
    bool has_;
    T    v_;
};

int main() {
    Maybe<int> a(5), b;
    if (a) std::printf("a 有值：%d\n", a.value());
    if (!b) std::printf("b 没有值\n");

    Maybe<int *> p(nullptr);
    bool has_p = p;                     /* T 是指针：转换不是 explicit，可以隐式转 */
    std::printf("指针版能隐式转 bool：%d\n", has_p);
    return 0;
}
```

`实测数据`
`Text`

```text
a 有值：5
b 没有值
指针版能隐式转 bool：1
```

## 3.8 什么时候该加 `explicit`

判断标准是一句话：**这一步转换是「同一个东西换一种表示」，还是「造出一个新东西」。**

| 转换的性质 | 例子 | 该不该隐式 |
|---|---|---|
| 同一个值的不同表示 | `int` → `long`、`float` → `double` | 可以隐式（标准转换，作者管不着） |
| 同一种概念的不同写法 | `std::string` ← `const char *`、`int` ← `long` | 可以不加 |
| **造出一个新对象** | `int` → `Strict`、`const char *` → `Text` | **加 `explicit`** |
| **改变真假语义** | 对象 → `bool` | **加 `explicit`**，否则会参与算术 |

落到具体写法上：

| 情形 | 建议 |
|---|---|
| 单参数构造函数，参数与对象不是同一种概念 | **加** |
| 参数与对象本来就是同一个概念的不同表示 | 可以不加 |
| `operator bool()` | **加**——否则对象会被隐式转成整数参与算术 |
| 拷贝构造、移动构造 | 不要加：`T b = a;` 是语言规定的用法 |

> [!TIP]
> **默认加上 `explicit`，遇到真正需要的场合再拿掉。**
> 从第 3.3 小节的实测可以看清代价：门开着的时候，编译器会拿这条转换去抢重载，
> 抢赢了你还不知道；而报错出现在转换发生的地方，比出现在后面某个重载里好查得多。
> 加上它只是让调用方多写几个字符。

# 第 4 节 成员的初值写在哪里

## 4.1 类内初始化器

数据成员可以在声明的地方直接给初值，这叫**类内初始化器**（标准里的名字是
**默认成员初始化器**）。它写一次，所有构造函数都受益：

`C++`

```cpp
/* member_init.cpp    编译：g++ -std=c++17 member_init.cpp -o member_init */
#include <cstdio>

class Config {
public:
    Config() {}                                     /* 两个成员都用类内默认值 */
    Config(int n) : a_(n) {}                        /* a_ 被初始化列表覆盖，b_ 仍用默认值 */

    int a_ = 1;                                     /* 类内初始化器 */
    int b_ = 2;
    const int c_ = 3;                               /* const 成员也能这样给值 */
};

struct Point { int x = 0; int y = 0; };              /* 聚合也能带默认值（C++14 起） */

int main() {
    Config d, e(10);
    std::printf("默认：a_ = %d，b_ = %d，c_ = %d\n", d.a_, d.b_, d.c_);
    std::printf("带参：a_ = %d，b_ = %d，c_ = %d\n", e.a_, e.b_, e.c_);

    Point p{5};                                      /* 只给 x，y 用默认值 */
    std::printf("Point{5}：x = %d，y = %d\n", p.x, p.y);
    return 0;
}
```

`实测数据`
`Text`

```text
默认：a_ = 1，b_ = 2，c_ = 3
带参：a_ = 10，b_ = 2，c_ = 3
Point{5}：x = 5，y = 0
```

三行输出说明了三件事：

| 观察 | 说明 |
|---|---|
| `Config d;` 里三个成员都有值 | 构造函数体是空的，值来自类内初始化器 |
| `Config e(10);` 里 `a_ = 10`、`b_ = 2` | **初始化列表优先**：写了列表的成员用列表，没写的用类内默认值 |
| `Point{5}` 里 `y = 0` | 聚合也能带类内初始化器（C++14 起），没给的成员用默认值 |

`文档`

> "If a given non-static data member has both a default member initializer and a mem-initializer, the
> initialization specified by the mem-initializer is performed, and the non-static data member's
> default member initializer is ignored."
>
> —— N4659 §15.6.2/10

`文档`

> "A brace-or-equal-initializer shall appear only in the declaration of a data member. (For static data
> members, see 12.2.3.2; for non-static data members, see 15.6.2 and 11.6.1). A brace-or-equal-initializer
> for a non-static data member specifies a default member initializer for the member, and shall not
> directly or indirectly cause the implicit definition of a defaulted default constructor for the
> enclosing class or the exception specification of that constructor."
>
> —— N4659 §12.2/8

## 4.2 与初始化顺序的关系

类内初始化器**不改变初始化顺序**：成员的初始化顺序仍然只由**声明顺序**决定
（《05-类与面向对象/04-构造与析构.md》第 2 节）。
它只是「这个成员如果没人管，就用这个值」的兜底。

| 写法 | 谁说了算 |
|---|---|
| 只在类内给值 | 类内初始化器 |
| 只在初始化列表里给值 | 初始化列表 |
| 两处都有 | **初始化列表**（类内那句被忽略） |
| 都没有 | 默认初始化：内置类型是未定的值（第 04 章第 1.1 小节的坑） |

**因此类内初始化器的价值是消灭第四行**：让每个成员至少有一个明确的值，
构造函数就可以只写「与默认值不同的那些」。

> [!TIP]
> **每个数据成员都给一个类内初值，构造函数里只写需要覆盖的。**
> 这样读一个类时，不必翻遍所有构造函数才能知道成员的初值是什么。

# 第 5 节 嵌套类

## 5.1 为什么把类放进类里

一个类只在另一个类的实现里用到、对外没有意义时，把它定义在外围类里面：
**名字归外围类管**，不会污染外面的作用域。

`C++`

```cpp
/* nested.cpp    编译：g++ -std=c++17 nested.cpp -o nested */
#include <cstdio>

class Outer {
public:
    class Inner {                               /* 嵌套类：名字在 Outer 的作用域里 */
    public:
        int read(const Outer &o) { return o.hidden_; }   /* 嵌套类是成员，能碰外围的私有 */
        int own_ = 2;
    };

    Outer(int v) : hidden_(v) {}

    int outer_read(const Inner &i) { return i.own_; }    /* 反过来：不行，见下一个程序 */
    int hidden_ = 1;
};

int main() {
    Outer o(42);
    Outer::Inner i;                             /* 用 Outer:: 限定 */
    std::printf("嵌套类读到外围私有：%d\n", i.read(o));
    std::printf("sizeof(Outer) = %zu，sizeof(Outer::Inner) = %zu（互不包含）\n",
                sizeof(Outer), sizeof(Outer::Inner));
    return 0;
}
```

`实测数据`
`Text`

```text
嵌套类读到外围私有：42
sizeof(Outer) = 4，sizeof(Outer::Inner) = 4（互不包含）
```

## 5.2 访问权限是单向的

嵌套类是外围类的**成员**，因此享有与其它成员同样的访问权；
反过来，外围类对嵌套类的私有成员没有特权：

`C++`

```cpp
/* nested_fail.cpp    编译：g++ -std=c++17 nested_fail.cpp -o nested_fail （失败） */
class Outer {
public:
    class Inner {
    private:
        int own_ = 2;                   /* 嵌套类的私有成员 */
    };

    int read(const Inner &i) { return i.own_; }   /* 外围类不是嵌套类的特权用户 */
};

int main() {
    Outer o;
    Outer::Inner i;
    return o.read(i);
}
```

`实测数据`
`Text`

```text
nested_fail.cpp:9:41: error: 'int Outer::Inner::own_' is private within this context
```

`文档`

> "A nested class is a member and as such has the same access rights as any other member. The members
> of an enclosing class have no special access to members of a nested class; the usual access rules
> (Clause 14) shall be obeyed."
>
> —— N4659 §14.7/1

## 5.3 互不包含

`sizeof(Outer)` 与 `sizeof(Outer::Inner)` 都是 4——**嵌套关系与「有一个」无关**：
`Inner` 不是 `Outer` 的成员对象，它只是名字写在 `Outer` 的作用域里。
要真的「有一个」，得在外围类里写一个 `Inner` 类型的成员。

| 关系 | 写法 | 含义 |
|---|---|---|
| 嵌套 | `class Inner { ... };` 写在 `Outer` 里面 | 只是名字的归属与访问权，不占对方空间 |
| 成员对象 | `Inner inner_;` 写在 `Outer` 里 | `Outer` 里真的有一份 `Inner`（第 07 章第 1.2 小节的「有一个」） |

## 5.4 什么时候用

| 场合 | 说明 |
|---|---|
| 实现细节 | 某个辅助类型只在 `Outer` 的实现里用得到，放外面只会多一个名字 |
| 强关联的类型 | 两者的名字天然成对（`List::Node`、`Matrix::Row`），嵌套把关系写进名字里 |
| 把实现藏起来 | 只在外围类里留一个指向嵌套实现类的指针，头文件就不必暴露实现的成员（Pimpl，靠前置声明，见《05-类与面向对象/02-类是一种类型.md》第 3.2 小节） |

**不要为了「看起来有层次」而嵌套。** 嵌套类的名字在外面写起来更长
（`Outer::Inner::Detail`），如果它本身是个独立概念，放外面更清楚。

# 第 6 节 友元：把访问权借出去

## 6.1 为什么需要它

《05-类与面向对象/02-类是一种类型.md》第 1.3 小节说过：访问控制的单位是类，
`private` 成员只有本类的成员函数能碰。这条规定挡的是「外面乱改内部数据」，
但它偶尔会挡住本来就该做的事：

`C++`

```cpp
class Counter {
public:
    explicit Counter(int v) : v_(v) { }
    int value() const { return v_; }
private:
    int v_;
};

Counter add(const Counter &a, const Counter &b) {   // 两个计数器相加
    return Counter(a.value() + b.value());          // 只能靠公开接口绕一圈
}
```

`add` 本来就是 `Counter` 这个抽象的一部分，只是它不该写成成员函数——
「两个计数器相加」这个动作不属于其中任何一个对象。
《05-类与面向对象/09-运算符重载.md》第 2 节会给出更硬的理由：
对称的运算符（`a + b` 与 `b + a` 都成立）必须是自由函数。

于是只有两条路：给 `Counter` 加一个只为了给 `add` 用的公开接口，或者把这个函数
**声明为友元**。友元的意思是：**这个函数（或这个类）被允许看我的内部。**

## 6.2 友元的声明与定义

`friend` 写在类定义里面，被声明的函数仍然是一个自由函数：

`C++`

```cpp
// friend_basic.cpp    编译：g++ -std=c++17 friend_basic.cpp -o friend_basic
#include <cstdio>

class Counter {
public:
    explicit Counter(int v) : v_(v) { }
    friend Counter add(const Counter &a, const Counter &b);     // 声明在类里
    friend bool equal(const Counter &a, const Counter &b);
    int value() const { return v_; }
private:
    int v_;
};

Counter add(const Counter &a, const Counter &b) {              // 定义在类外：它是自由函数
    return Counter(a.v_ + b.v_);                               // 友元身份让它读得到 v_
}

bool equal(const Counter &a, const Counter &b) { return a.v_ == b.v_; }

int main() {
    Counter x(1), y(2);
    std::printf("add(x, y).value() = %d\n", add(x, y).value());
    std::printf("equal(x, x) = %d，equal(x, y) = %d\n", equal(x, x), equal(x, y));
    std::printf("sizeof(Counter) = %zu（友元不占对象空间）\n", sizeof(Counter));
    return 0;
}
```

`实测数据`
`Text`

```text
add(x, y).value() = 3
equal(x, x) = 1，equal(x, y) = 0
sizeof(Counter) = 4（友元不占对象空间）
```

| 事实 | 说明 |
|---|---|
| `friend` 是声明，不是定义 | 函数体写在类外，与普通自由函数一样，只是多了一次授权 |
| 友元函数不是成员函数 | 它没有 `this`，调用时写 `add(x, y)`，不写 `x.add(y)` |
| 友元能访问 `private` 与 `protected` 成员 | 效果与成员函数相同 |
| 友元不占对象空间 | `sizeof(Counter)` 仍是 4 字节：授权只在编译期起作用 |
| 声明写在类的哪一段都一样 | 写在 `private` 段里的 `friend` 声明照样有效 |

`文档`

> "A friend of a class is a function or class that is given permission to use the private and
> protected member names from the class. A class specifies its friends, if any, by way of friend
> declarations. Such declarations give special access rights to the friends, but they do not make
> the nominated friends members of the befriending class."
>
> —— N4659 §14.3/1
>
> "The meaning of the friend declaration is the same whether the friend declaration appears in
> the private, protected or public (12.2) portion of the class member-specification."
>
> —— N4659 §14.3/9

反过来，不写 `friend` 就进不去，编译器给的还是那条熟悉的错：

`C++`

```cpp
// friend_missing.cpp    编译：g++ -std=c++17 friend_missing.cpp -o friend_missing （失败）
class Counter {
public:
    explicit Counter(int v) : v_(v) { }
    int value() const { return v_; }
private:
    int v_;
};

Counter add(const Counter &a, const Counter &b) {   // 没有声明为友元
    return Counter(a.v_ + b.v_);
}

int main() {
    Counter x(1), y(2);
    return add(x, y).value();
}
```

`实测数据`
`Text`

```text
friend_missing.cpp:11:22: error: 'int Counter::v_' is private within this context
```

## 6.3 三种友元

| 写法 | 谁得到了访问权 | 常见场合 |
|---|---|---|
| `friend Counter add(const Counter &, const Counter &);` | 一个自由函数 | 对称的运算符、与类同属一个抽象的辅助函数 |
| `friend class Screen;` | 另一个类（它的所有成员函数） | 两个类要配合完成一件事，且拆不开 |
| `friend void Window::draw(const Screen &);` | 另一个类的某一个成员函数 | 只需要放行一个函数，不想把整个类放进来 |

第三种是前两种的折中：**放行的范围越小越好**。
真要用到「友元类」时，通常说明这两个类的耦合已经很强，
值得先想一想它们是不是本来就该是一个类，或者该用公开接口表达。

## 6.4 三条边界

友元关系只落在**被声明的那一个类**上，它有三个「不」：

`C++`

```cpp
// friend_limits.cpp    编译：g++ -std=c++17 friend_limits.cpp -o friend_limits （失败）
class B;                                    // 前置声明

class A {
    friend class B;                         // 只在这里说了「B 是 A 的友元」
    int a_ = 1;
public:
    int peek_b(const B &y);
};

class B {
    int b_ = 2;
public:
    int read_a(const A &x) { return x.a_; } // B 是 A 的友元：可以
};

int A::peek_b(const B &y) { return y.b_; }  // A 不是 B 的友元：不行

class Base {
    friend int peek(const Base &);
    int x_ = 1;
};

class Derived : public Base {
    int y_ = 2;                             // 友元关系不被派生类继承
};

int peek(const Base &) { Derived d; return d.y_; }

class C1 {
    friend class C2;
    int c1_ = 1;
};
class C2 {
    friend class C3;                        // C3 是 C2 的友元，不是 C1 的
};
class C3 {
public:
    int peek(C1 &x) { return x.c1_; }       // 不传递：不行
};

int main() {
    A x; B y;
    Base b;
    C1 c;
    return x.peek_b(y) + y.read_a(x) + peek(b) + C3().peek(c);
}
```

三处违反分别被拦下：

`实测数据`
`Text`

```text
friend_limits.cpp:17:38: error: 'int B::b_' is private within this context
friend_limits.cpp:28:46: error: 'int Derived::y_' is private within this context
friend_limits.cpp:39:32: error: 'int C1::c1_' is private within this context
```

| 边界 | 含义 |
|---|---|
| **单向** | `A` 声明 `B` 是友元，只说明 `B` 能进 `A`；`A` 进不了 `B` |
| **不继承** | 基类的友元不是派生类的友元 |
| **不传递** | 我朋友的朋友不是我的朋友 |

`文档`

> "Friendship is neither inherited nor transitive."
>
> —— N4659 §14.3/10

## 6.5 代价与使用建议

友元是**主动扩大接口**：它把「谁能碰内部」这条线往外挪了一点。
挪得对，读者看到 `friend` 就知道「这个函数是这类型实现的一部分」；
挪得不对，封装就被绕开了，而且绕开的地方不在类的定义里，日后很难查。

| 判断 | 建议 |
|---|---|
| 这个函数/类与当前类型是不是同一个抽象 | 是，才考虑友元 |
| 能不能用公开接口表达同样的意思 | 能，就用公开接口 |
| 放行的范围能不能再小一点 | 从「友元类」缩到「友元成员函数」 |
| 有没有为了图方便把整类设成友元 | 那是把封装直接关掉了 |

> [!TIP]
> **对称的运算符是友元最常见的正当用途。**
> 《05-类与面向对象/09-运算符重载.md》第 2 节会看到 `operator+`、`operator==`
> 这类双目运算符写成非成员函数更合适，而它们要读私有成员时，就声明成友元。
> 写法和本节开头那个 `add` 完全一样。

> [!NOTE]
> **本节小结**：`friend` 把访问权借给一个自由函数、另一个类，或者另一个类的某个成员函数。
> 它只影响编译期的访问检查，不占对象空间，也不是成员函数。
> 友元关系单向、不继承、不传递——判断「能不能访问」时，只看这一步是谁授权的。

# 第 7 节 检查清单

写代码时逐条对照：

| 检查 | 说明 |
|---|---|
| 静态数据成员在类外定义了吗 | 只声明不定义，编译过、链接失败（第 1.2 小节） |
| 能用 `inline static` 就别再写类外定义 | C++17 起可以在类内定义并给初值（第 1.2 小节） |
| 有没有让一个全局对象去用另一个翻译单元的全局对象 | 初始化顺序不确定，换链接顺序结果就变（第 1.4 小节） |
| 需要「用到时才初始化」的全局量写成函数内的局部静态变量了吗 | 它的初始化时机有保证 |
| 静态成员函数里没有 `this`，别写 `const` | 编译期直接报错（第 1.3 小节） |
| `const` 成员函数里真的要改的成员，才用 `mutable` | 缓存、统计、锁可以；业务数据不行（第 2.3 小节） |
| 单参数构造函数默认加 `explicit` 了吗 | 不加就等于给编译器开了一条隐式转换的路，它还会拿这条路去抢重载（第 3.3、3.8 小节） |
| `operator bool()` 加 `explicit` 了吗 | 不加，对象会被当成整数参与算术 |
| 每个数据成员都有类内初值吗 | 构造函数里只写需要覆盖的那些（第 4.2 小节） |
| 嵌套类是不是真的只属于外围类 | 独立的类型放外面，名字更短、更好找（第 5.4 小节） |
| 友元是不是必须的，范围能不能再小 | 能改用公开接口就不用友元；非用不可时优先放行单个函数（第 6.5 小节） |

# 术语表

| 词 | 含义 | 在哪一节 |
|---|---|---|
| **静态数据成员** | 属于类、不属于任何对象的成员，全类共享一份 | 第 1.1 小节 |
| **静态成员函数** | 没有 `this` 的成员函数，不必先有对象就能调 | 第 1.3 小节 |
| **静态初始化顺序问题** | 不同翻译单元的全局对象，初始化顺序不确定 | 第 1.4 小节 |
| **`mutable`** | 让某个数据成员在 `const` 成员函数里也能被修改 | 第 2.2 小节 |
| **隐式转换** | 编译器在类型对不上的地方自动做的转换；用户定义的那部分由类作者开启 | 第 3.1 小节 |
| **转换构造函数** | 不带 `explicit`、可以用一个实参调用的构造函数，是「值 → 对象」的通道 | 第 3.2 小节 |
| **直接初始化 / 拷贝初始化** | `T x(3)` 不要求隐式转换，`T x = 3` 与传实参要求一次 | 第 3.4 小节 |
| **`explicit`** | 把一条用户定义转换从「可隐式使用」的名单里划掉；用在转换运算符上时只允许上下文转换 | 第 3.5 小节 |
| **上下文转换** | `if (x)`、`!x` 这类本来就要求条件的场合，允许用 `explicit` 转换 | 第 3.6 小节 |
| **类内初始化器** | 数据成员在声明处给的初值；标准里叫默认成员初始化器 | 第 4.1 小节 |
| **嵌套类** | 定义在另一个类里面的类，名字归外围类管 | 第 5 节 |
| **友元** | 在类里用 `friend` 授权、可以访问私有与保护成员的自由函数或另一个类 | 第 6 节 |

## A.2 静态初始化顺序那条实测的复现步骤

`Bash`
