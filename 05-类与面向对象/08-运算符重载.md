**`a + b` 里只要有一个操作数是类类型，没有重载时这个表达式就是编译错误。**

《04-语法/04-表达式与运算符.md》第 6 节已经给出结论：
**类类型上的运算符，就是一次函数调用**。这句话的另一半是：
**给一个运算符定义新的含义，让原本非法的表达式成为合法操作，这就是运算符重载。**

**它不改变内建类型上运算符的含义，只是为类类型补充新的用法。**
`std::string` 的 `+`、容器的 `[]`、输出流的 `<<`，全都靠这一个机制。

**C 里没有这个机制。** C 的 `+` 永远只做加法，想给结构体「相加」，
只能写 `vec_add(a, b)`——**调用处看不出这是「加」**。

# 第 1 节 运算符重载：给运算符定义新的含义

## 1.1 `a + b` 与 `operator+(a, b)`

**运算符的适用范围由语言规定**：内建的 `+` 只对算术类型合法
（指针加整数是另一条内建规则）。两个类对象之间写 `a + b`，
在没有重载时是**编译错误**——编译器找不到适用于 `Vec` 的 `+`。

`实测数据`
`C++`

```cpp
/* no_plus.cpp    编译：g++ -std=c++17 no_plus.cpp -o no_plus （失败） */
struct Vec { int x = 0, y = 0; };
int main() { Vec a{1, 2}, b{3, 4}; Vec c = a + b; return c.x; }
```

`实测数据`
`Text`

```text
error: no match for 'operator+' (operand types are 'Vec' and 'Vec')
```

**重载做的事情，是让这个非法表达式变成合法操作**：为 `+` 定义一条针对 `Vec` 的新规则，
运算结果的含义由写代码的人决定。**「写成函数」是它的实现手段**——
编译器把 `a + b` 变成一次函数调用。

**写法本身只有一条规则：把 `+` 换成名字 `operator+`。**

`C++`

```cpp
Vec a{1, 2}, b{3, 4};
Vec c = a + b;                     // 源码里的写法

Vec c = a.operator+(b);            // 编译器看到的样子（成员版）
Vec c = operator+(a, b);           // 或者这样（非成员版）
```

**最后两行通常不必写**，写出来只是为了让这层关系可见：
**`a + b` 会去找一个叫 `operator+` 的函数**，找到了就调用它。

**它和函数重载是同一个机制**：同一个名字（这里是 `+`）配不同的参数表
（`int + int`、`double + double`、`Vec + Vec`），编译器从中选择一个最合适的
（《04-语法/07-函数.md》第 5 节）。

## 1.2 与等价的普通函数编译结果相同

**这一条能消除「运算符重载有额外开销」的疑虑**：

`C++`

```cpp
/* op_vs_fn.cpp    编译：g++ -std=c++17 -O2 -c op_vs_fn.cpp -o op_vs_fn.o */
struct Vec {
    int x = 0, y = 0;
    friend Vec operator+(const Vec &a, const Vec &b) { return Vec{a.x + b.x, a.y + b.y}; }   // 运算符重载
};

Vec plus(const Vec &a, const Vec &b) { return Vec{a.x + b.x, a.y + b.y}; }  // 等价的普通函数

int use_operator() { Vec a{1, 2}, b{3, 4}; return (a + b).x; }
int use_function() { Vec a{1, 2}, b{3, 4}; return plus(a, b).x; }
```

`实测数据`
`Assembly`

```asm
use_operator()     use_function()
  mov $0x4,%eax      mov $0x4,%eax
  ret                ret
```

**两个函数编出来完全相同**——连加法都被优化掉了，只剩下一个常量。
**运算符重载没有任何运行期开销**：它只是一次普通的函数调用，
而普通函数调用能内联，它也能。

## 1.3 哪些能重载、哪些不能

**C++ 里绝大多数运算符都能重载**，下列运算符不能：

`实测数据`

| 不能重载 | 为什么 |
|---|---|
| `.` | 成员访问是语法层面的操作 |
| `::` | 作用域解析是编译期的名字查找（《05-类与面向对象/01-命名空间与 using.md》第 2 节） |
| `.*`、`?:` | 同上，属于语法结构 |
| `sizeof`、`typeid`、`alignof` | 它们问的是类型的信息，不是值 |
| `#`、`##` | 预处理记号，在编译器之前处理（《04-语法/14-预处理器.md》第 7 节） |

**写出来会怎样**：编译器在**语法阶段**直接拒绝。

`实测数据`
`C++`

```cpp
// op_dot.cpp    编译：g++ -std=c++17 op_dot.cpp -o op_dot （失败）
struct T {
    T operator.(const T &) const { return *this; }
};
int main() { T t; return 0; }
```

`实测数据`
`Text`

```text
error: expected type-specifier before '.' token
```

**报错说的是「这里不该出现 `.`」**——编译器并没有把 `operator.` 当成一个名字，
它把 `operator` 当成了类型名，于是要求后面跟一个类型。

**还有一条更基本的限制：至少有一个参数是类类型（或枚举类型）。**

`实测数据`
`C++`

```cpp
// need_class.cpp    编译：g++ -std=c++17 need_class.cpp -o need_class （失败）
int operator+(int a, int b) { return a + b; }    // 两个参数都是内建类型
int main() { return 1 + 2; }
```

`实测数据`
`Text`

```text
error: 'int operator+(int, int)' must have an argument of class or enumerated type
```

> [!IMPORTANT]
> **运算符重载是「给自定义类型配上运算符」，不是「改造语言」。**
> `1 + 2` 永远是 3，无法改动——因为**只能为类类型或枚举类型重载运算符**，
> 内建类型之间的运算不参与重载。

# 第 2 节 写成成员还是非成员函数

**同一个运算符可以写成两种形式**——但它们的**参数表不一样**，
这决定了谁能被隐式转换。

## 2.1 两种写法的对照

`实测数据`

| | 成员版 | 非成员版 |
|---|---|---|
| 写法 | `Vec Vec::operator+(const Vec &) const` | `Vec operator+(const Vec &, const Vec &)` |
| 参数个数 | 比运算对象少一个（左操作数就是 `this`） | 与运算对象个数相同 |
| 左操作数 | **必须是本类（或派生类）的对象** | 任意，只要能转换成参数类型 |
| 能否访问私有成员 | 可以（本身就是成员） | 可以，在类里声明为友元（第 12 章） |
| 对称的双目运算符 | 左操作数被钉死为本类类型 | **首选**——两个操作数地位相同 |

**关键差别在「左操作数能不能被转换」。**
**对称的双目运算符（`+`、`-`、`*`、`/`、`==`、`!=`、`<`、`<=`、`>`、`>=`）
惯例写成非成员函数**：两个操作数地位相同，谁都能参与隐式转换；
写成成员则把左操作数钉死为本类类型。

## 2.2 对称运算符首选非成员

**成员版能编过 `n + 2`，靠的是右操作数被隐式转换**：`2` 转成 `Num`。
方向一换，这条转换就不再适用：

`C++`

```cpp
// member_vs_free.cpp    编译：g++ -std=c++17 member_vs_free.cpp -o member_vs_free （失败）
struct Num {
    int v;
    Num(int x) : v(x) {}                       // 允许由 int 隐式转换
    Num operator+(const Num &o) const { return Num(v + o.v); }   // 成员版
};

int main() {
    Num n(1);
    Num a = n + 2;      // 右边能转换：可以
    Num b = 2 + n;      // 左边要转换：成员版做不到
    return a.v + b.v;
}
```

`实测数据`
`Text`

```text
error: no match for 'operator+' (operand types are 'int' and 'Num')
```

**`2 + n` 找不到可用的 `operator+`**：成员版要求左边是 `Num`，
而 `2` 是 `int`——**编译器不会为了调用成员函数去转换左操作数**。

**换成非成员版，两个方向都能转换**：

`C++`

```cpp
/* free_version.cpp    编译：g++ -std=c++17 free_version.cpp -o free_version */
#include <cstdio>

struct Num {
    int v;
    Num(int x) : v(x) {}
};

Num operator+(const Num &a, const Num &b) { return Num(a.v + b.v); }   // 非成员版

int main() {
    Num n(1);
    Num a = n + 2;
    Num b = 2 + n;      // 两个方向都能转换
    std::printf("n + 2 = %d，2 + n = %d\n", a.v, b.v);
    return 0;
}
```

`实测数据`
`Text`

```text
n + 2 = 3，2 + n = 3
```

> [!TIP]
> **对称的双目运算符（`+`、`-`、`*`、`/`、`==`、`!=`、`<`、`<=`、`>`、`>=`）惯例写成非成员函数。**
> `n + 2` 与 `2 + n` 在数学上没有区别，代码里也不应该出现这种区别；
> 写成成员之后，左操作数需要转换的那一种写法就会失败。

**非成员函数要访问私有成员，就在类里把它声明为友元**：
`friend` 声明写在类里，函数本身**不是成员**（没有 `this`），
却可以像成员函数一样访问私有成员——这正是 `friend` 最典型的用途。

`C++`

```cpp
/* friend_op.cpp    编译：g++ -std=c++17 friend_op.cpp -o friend_op */
#include <cstdio>

class Num {
public:
    Num(int v) : v_(v) {}                                // 允许由 int 隐式转换
    int value() const { return v_; }
    friend Num operator+(const Num &a, const Num &b);     // 友元声明：写在类里
private:
    int v_;
};

Num operator+(const Num &a, const Num &b) {               // 定义写在类外，它不是成员函数
    return Num(a.v_ + b.v_);                              // 友元身份使其可以访问私有成员
}

int main() {
    Num n(4);
    Num a = n + 2;                                       // 2 转成 Num
    Num b = 2 + n;                                       // 两个方向都能转换
    std::printf("n + 2 = %d，2 + n = %d\n", a.value(), b.value());
    return 0;
}
```

`实测数据`
`Text`

```text
n + 2 = 6，2 + n = 6
```

**定义也可以直接写在类里**，形式是
`friend Num operator+(const Num &a, const Num &b) { return Num(a.v_ + b.v_); }`，
效果与写在类外相同：它仍然不是成员函数，只是把函数体一并写在类里。
**友元是什么、能访问到什么、边界在哪里，属于第 12 章。**

## 2.3 标准要求写成成员的运算符

**「标准要求」与「惯例如此」是两件事**：先看标准强制的那一类。
`=`、`[]`、`()`、`->` 这四个只能是**非静态成员函数**，写成非成员函数会被编译器直接拒绝：

`文档`

> "A binary operator shall be implemented either by a non-static member function
> (12.2.1) with one parameter or by a non-member function with two parameters."（§16.5.2）
> "An assignment operator shall be implemented by a non-static member function
> with exactly one parameter."（§16.5.3）
> "operator() shall be a non-static member function with an arbitrary number of parameters."（§16.5.4）
> "operator[] shall be a non-static member function with exactly one parameter."（§16.5.5）
> "operator-> shall be a non-static member function taking no parameters."（§16.5.6）
>
> —— N4659 §16.5.2–§16.5.6

`实测数据`

| 运算符 | 为什么必须是成员 |
|---|---|
| `=`（赋值） | 要处理对象原有的内容，并且要能返回 `*this`（《05-类与面向对象/04-拷贝与移动.md》第 3 节） |
| `[]`（下标） | 要能按对象的状态定位元素 |
| `()`（调用） | 「这个对象可以被调用」是对象自身的性质 |
| `->`（成员访问） | 同上，指向哪个对象由对象自身决定 |

**写成非成员函数会怎样**：

`实测数据`
`C++`

```cpp
// must_member_assign.cpp    编译：g++ -std=c++17 must_member_assign.cpp -o must_member_assign （失败）
struct T { };
T &operator=(const T &) { return *this; }
int main() { T a, b; return 0; }
```

`实测数据`
`Text`

```text
error: 'T& operator=(const T&)' must be a non-static member function
```

**`[]` 也一样**，而且报得更细：

`实测数据`
`Text`

```text
error: non-member function 'int operator[](int)' cannot have cv-qualifier
error: 'int operator[](int)' must be a member function
```

**第一条报错说的是「非成员函数没有 `this`，这个 `const` 修饰的是谁」**——
它同时也说明了成员版里 `const` 修饰的是 `this`（《05-类与面向对象/02-类是一种类型.md》第 2.3 小节）。

**另一类是按惯例写成成员的**，标准并不强制：

| 运算符 | 为什么惯例写成成员 |
|---|---|
| `+=`、`-=`、`*=` 这类复合赋值 | 要修改自身并返回 `*this`，写成成员最直接 |
| `++`、`--`（前置与后置） | 改的是对象自身的状态 |
| `->*`（经指针访问成员） | 第二个操作数是指向成员的指针，实践中总与 `->` 一起写成成员 |

**`->*` 是双目运算符，标准没有对它单独设限**（§16.5.2 允许成员与非成员两种形式），
写成非成员函数同样合法；把它列在惯例一类，是因为它处理的正是对象自身的成员。

## 2.4 选择的标准

`实测数据`

| 情形 | 选哪个 |
|---|---|
| `=`、`[]`、`()`、`->` | **只能成员**（标准要求） |
| `+=`、`-=` 这类复合赋值、`++`、`--` | **惯例成员**（要修改自身，并且要返回 `*this`） |
| `+`、`-`、`*`、`==`、`<` 这类对称运算 | **非成员函数**（必要时声明为友元，两个操作数都能转换） |
| `<<`、`>>` | **非成员函数**（左操作数是流对象，不是自定义类型，见第 3.4 小节） |
| 非成员版需要访问私有成员的 | 在类里**声明为友元**（第 12 章） |

# 第 3 节 常用运算符怎么写

## 3.1 比较：`==` 与 `!=`

**`==` 决定两个对象是否相等**，写法上注意两点：
`==` 与 `!=` 是对称的，两个都写成**非成员函数**（要读私有成员就在类里声明为 `friend`），
两个参数都是 `const` 引用——比较不修改任何一个操作数
（`const` 成员函数见《05-类与面向对象/02-类是一种类型.md》第 2.3 小节）。

`C++`

```cpp
/* point_cmp.cpp    编译：g++ -std=c++17 point_cmp.cpp -o point_cmp */
#include <cstdio>

class Point {
    int x_ = 0, y_ = 0;
public:
    Point(int x, int y) : x_(x), y_(y) {}
    friend bool operator==(const Point &a, const Point &b);   // 友元声明写在类里
    friend bool operator!=(const Point &a, const Point &b);
};

bool operator==(const Point &a, const Point &b) {   // ① 非成员：两个操作数地位相同
    return a.x_ == b.x_ && a.y_ == b.y_;
}

bool operator!=(const Point &a, const Point &b) {   // ② 用 == 实现，只留一处判断
    return !(a == b);
}

int main() {
    Point p(1, 2), q(1, 2), r(3, 4);
    std::printf("p == q：%d，p != q：%d，p != r：%d\n", p == q, p != q, p != r);
    return 0;
}
```

`实测数据`
`Text`

```text
p == q：1，p != q：0，p != r：1
```

**第二条的意义**：C 与 C++ 里 `==` 与 `!=` 是**两个独立的运算符**，
**重载了 `==` 不会自动得到 `!=`**。

> [!TIP]
> **重载 `==` 时把 `!=` 一并写上，而且 `!=` 用 `!(a == b)` 实现。**
> 这样「什么叫相等」只有一处判断，将来修改时不会出现两处不一致。
> （C++20 起有了 `<=>` 与自动生成的比较运算符，能省掉这些样板，超出本书基准。）

## 3.2 算术：`+` 返回新对象，`+=` 返回 `*this`

**这两者的分工与第 04 章讲的「构造 vs 赋值」相同**：
`+` 算出新对象，写成**非成员函数**（要读私有成员就声明为 `friend`）；
`+=` 改的是左操作数自身，写成**成员函数**。
**一对 `+` 与 `+=` 正好演示「非成员 + 成员」的分工。**

`C++`

```cpp
/* vec_arith.cpp    编译：g++ -std=c++17 vec_arith.cpp -o vec_arith */
#include <cstdio>

class Vec {
    int x_ = 0, y_ = 0;
public:
    Vec(int x, int y) : x_(x), y_(y) {}
    int x() const { return x_; }
    int y() const { return y_; }

    Vec &operator+=(const Vec &o) {                     // 成员：修改自身
        x_ += o.x_; y_ += o.y_;
        return *this;                                   // 返回 *this：支持连续运算
    }
    friend Vec operator+(const Vec &a, const Vec &b);   // 非成员：算出新对象
};

Vec operator+(const Vec &a, const Vec &b) {             // 用 += 实现，只写一处逻辑
    Vec r(a);
    r += b;
    return r;
}

int main() {
    Vec a(1, 2), b(3, 4);
    Vec c = a + b;
    std::printf("a + b = (%d, %d)\n", c.x(), c.y());
    a += b;
    std::printf("a += b 之后 a = (%d, %d)\n", a.x(), a.y());
    return 0;
}
```

`实测数据`
`Text`

```text
a + b = (4, 6)
a += b 之后 a = (4, 6)
```

**`+` 返回新对象、`+=` 返回引用**——和 `a = b = c;` 那条链式规则一模一样
（《05-类与面向对象/04-拷贝与移动.md》第 3.2 小节）。

## 3.3 下标 `[]`：两个版本

**`[]` 几乎总是一对**：一个给可修改的对象用，一个给 `const` 对象用。

`C++`

```cpp
/* subscript.cpp    编译：g++ -std=c++17 subscript.cpp -o subscript */
#include <cstdio>

class IntArray {
public:
    IntArray(int n) : data_(new int[n]()), size_(n) {}
    ~IntArray() { delete[] data_; }

    int &operator[](int i)             { std::printf("  非 const 版（能改）\n"); return data_[i]; }
    const int &operator[](int i) const { std::printf("  const 版（只能读）\n"); return data_[i]; }
    int size() const { return size_; }
private:
    int *data_;
    int  size_;
};

void show(const IntArray &a) { std::printf("a[0] = %d\n", a[0]); }   // 传 const 引用

int main() {
    IntArray a(3);
    a[0] = 7;                     // 非 const 版
    show(a);                      // const 版
    return 0;
}
```

`实测数据`
`Text`

```text
  非 const 版（能改）
  const 版（只能读）
a[0] = 7
```

**`[]` 按标准只能写成成员函数**（第 2.3 小节），
两个版本靠成员函数上的 `const` 区分。
**为什么必须写两个**：`const IntArray &` 上的 `[]` 只能调 `const` 版本，
而它返回的必须是 `const int &`，否则就绕过了 `const` 的保护
（《04-语法/03-常量与 const.md》第 2 节）。

**返回引用的意义**：`a[0] = 7;` 能成立，正是因为 `[]` 返回的是**元素的引用**。
如果返回 `int`，这行就只能改一个临时副本。

## 3.4 输出 `<<`：为什么写成非成员

**`out << a` 里的 `out` 不属于本类**，不能充当成员函数的 `this`：

`C++`

```cpp
/* stream_like.cpp    编译：g++ -std=c++17 stream_like.cpp -o stream_like */
#include <cstdio>

class Printer {                                   // 一个自定义的「输出目标」
public:
    Printer &operator<<(int v)      { std::printf("%d", v); return *this; }
    Printer &operator<<(const char *s) { std::printf("%s", s); return *this; }
};

struct Point { int x, y; };

Printer &operator<<(Printer &p, const Point &pt) {   // 只能写成非成员：左边不是 Point
    return p << "(" << pt.x << ", " << pt.y << ")";
}

int main() {
    Point a{1, 2};
    Printer out;
    out << "点 " << a << "\n";
    return 0;
}
```

`实测数据`
`Text`

```text
点 (1, 2)
```

**三个要点**：

| 要点 | 说明 |
|---|---|
| 写成非成员函数 | 左操作数是 `Printer`，右操作数是 `Point` |
| **返回 `Printer &`** | 这样才能连续写 `out << "点 " << a`——每一步都要返回同一个 `out` |
| **不修改 `Point`** | 所以第二个参数是 `const Point &` |

**标准库的 `std::cout` 用的正是这套写法**（`std::ostream` 与 `operator<<`），
它属于【待补：06-标准库/】。

## 3.5 前置与后置 `++`

**两个 `++` 靠一个「没用到的 `int` 参数」区分**：

`C++`

```cpp
/* inc_dec.cpp    编译：g++ -std=c++17 inc_dec.cpp -o inc_dec */
#include <cstdio>

class Counter {
public:
    Counter(int v) : v_(v) {}
    Counter &operator++()    { ++v_; return *this; }          // 前置：返回自己
    Counter  operator++(int) { Counter old(*this); ++v_; return old; }  // 后置：返回旧值
    int value() const { return v_; }
private:
    int v_;
};

int main() {
    Counter c(5);
    std::printf("++c 之后再取值：%d\n", (++c).value());
    std::printf("c++ 的返回值：%d\n", (c++).value());
    std::printf("c 现在的值：%d\n", c.value());
    return 0;
}
```

`实测数据`
`Text`

```text
++c 之后再取值：6
c++ 的返回值：6
c 现在的值：7
```

**这三行输出的含义**：`++c` 先把 `c` 加到 6 再返回它自己，所以取到 6；
`c++` 先把旧值 6 存下来、把 `c` 加到 7，然后返回那个旧值 6——
**所以它打印 6，而 `c` 已经是 7。**

**写法上的三点差别**：

`实测数据`

| | 前置 `++c` | 后置 `c++` |
|---|---|---|
| 签名 | `Counter &operator++()` | `Counter operator++(int)` |
| 参数 | 没有 | 一个占位的 `int`（占位记号，无需命名） |
| 返回 | **引用**（返回自己） | **值**（返回改动前的副本，因此多一次拷贝） |
| 效率 | 高 | 低一些——多出的那一次拷贝无法省略 |

## 3.6 函数调用 `()`：仿函数

**重载 `()` 之后，对象可以像函数一样被调用**——这叫**函数对象**（仿函数）：

`C++`

```cpp
struct Square {
    int operator()(int x) const { return x * x; }
};

Square sq;
int r = sq(5);          // 等价于 sq.operator()(5)
```

**`()` 按标准只能写成成员函数**（第 2.3 小节）。

**它的价值不在写法简短，而在对象可以携带状态参与调用**：
`Square` 可以换成 `Multiply{3}`，把「乘几」这个参数保存在对象里，
然后像函数一样传给别的代码。**第 09 章的 lambda 就是编译器生成的仿函数**
（《04-语法/01-一些基础概念.md》第 1.5 小节）。

# 第 4 节 规矩与代价

## 4.1 不要重载 `&&`、`||` 和 `,`

**重载这三个会改变语言的行为**，C++17 起对 `,` 和 `&&`/`||` 的求值顺序另有规定，
但最直观的问题是**短路求值失效**：

`C++`

```cpp
/* no_shortcut.cpp    编译：g++ -std=c++17 no_shortcut.cpp -o no_shortcut */
#include <cstdio>

struct Flag {
    bool value;
    Flag(bool v) : value(v) {}
};

bool operator&&(const Flag &a, const Flag &b) {     // 重载 &&
    std::printf("  operator&& 被调用\n");
    return a.value && b.value;
}

Flag left()  { std::printf("  求值 left()\n");  return Flag(false); }
Flag right() { std::printf("  求值 right()\n"); return Flag(true); }

int main() {
    std::printf("用重载的 &&：\n");
    bool r = left() && right();          // 短路本应跳过 right()
    std::printf("结果 = %d\n", r);
    return 0;
}
```

`实测数据`
`Text`

```text
用重载的 &&：
  求值 left()
  求值 right()
  operator&& 被调用
结果 = 0
```

> [!CAUTION]
> **`left()` 返回 `false`，`right()` 仍然被求值了——短路失效。**
> 内建的 `&&` 先求值左边，左边为假就**不再求值右边**；
> 一旦写成 `operator&&`，它就成了一次普通函数调用，
> **两个参数都必须先求值**（函数调用要先求值实参）。
> **副作用、判空、越界检查都依赖短路**，重载它等于取消了语言的一条保证。

**规矩**：`&&`、`||`、`,` 这三个不要重载。
确实需要「按名字组合条件」时，写成普通函数名（`both(a, b)`）比写成运算符更清楚。

## 4.2 语义要符合直觉

**运算符重载最大的风险不是写错，而是写出让读者误解的代码。**

`实测数据`

| 写法 | 判断 |
|---|---|
| `Vec + Vec` 表示向量相加 | 好——和数学一致 |
| `String + String` 表示拼接 | 好——虽然数学上不是「加」，但已经是全行业的习惯 |
| `Date - Date` 表示相差天数 | 可以接受——`-` 在这里有「差值」的意思 |
| `Vec * Vec` 表示点积 | **有争议**——读者会以为得到的是向量，建议写成 `dot(a, b)` |
| `Stack + int` 表示压栈 | **坏**——`+` 让人以为得到一个新栈，实际修改的是自身 |
| `operator&` 改成别的含义 | **不能这么做**——`&` 已经有既定含义（取地址），改了会让所有 `&` 都变得可疑 |

**判断标准是**：**读到这个运算符的人，是否会猜错它的行为。**
会猜错，就换成有名字的函数。

> [!TIP]
> **重载之前先确认这个运算符有没有公认的含义。**
> `+`、`==`、`[]`、`<<` 有；`%`、`^`、`>>` 在别的领域也有专有含义，
> 用错地方读者会往那个方向猜。

## 4.3 代价：一次函数调用，能内联

**第 1.2 小节已经量过**：重载的 `+` 与等价的普通函数编出来的指令完全相同，
连加法都被优化掉了。**因此运算符重载本身没有额外开销。**

**真正要付的代价在别处**：

`实测数据`

| 代价 | 说明 |
|---|---|
| `+` 一般返回**新对象** | 一次构造（可能还有一次拷贝／移动）。返回引用可以省掉这一次构造，但语义也随之变成修改自身 |
| 不写 `const` 就不能用在 `const` 对象上 | 比较、算术这类不该改对象的运算符，**都要加 `const`** |
| 隐式转换会带来意外 | 构造函数没加 `explicit` 时，`n + 2` 里的 `2` 会被隐式转换成 `Num`（第 12 章讲 `explicit`） |
| 调试更难 | 断点打在 `a + b` 上，需要先确定它落到哪个 `operator+` |

**运算符重载本身的开销只是一次函数调用，真正的代价来自用错地方的运算符重载。**

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 运算符重载 | Operator overloading | 为类类型定义某个运算符的新含义，使原本非法的表达式成为合法操作；实现手段是写一个名叫 `operator@` 的函数 |
| 运算符函数 | Operator function | `operator+`、`operator[]` 这类函数的名字 |
| 成员版 | Member form | 写成成员函数，左操作数是 `this`，参数少一个 |
| 非成员版 | Non-member form | 两个操作数都在参数表里，**两个操作数都能参与隐式转换**；对称的双目运算符的惯例写法 |
| 友元 | Friend | 在类里用 `friend` 声明的非成员函数，可以访问私有成员；非成员版运算符靠它访问私有成员（第 12 章） |
| 仿函数 | Functor / Function object | 重载了 `operator()` 的类，对象能像函数一样调用 |
| 短路求值 | Short-circuit | 内建 `&&`／`||` 的保证：左边定结果就不算右边；**重载会失去它** |
| `explicit` | — | 禁止构造函数参与隐式转换（第 12 章） |
