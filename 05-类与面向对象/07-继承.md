**第 02 章把数据与操作捆成了一个类型。本章节处理另一种重复：两个类型大部分相同，只差一部分。**

圆和矩形都要算面积、都要打印，代码有八成是一样的。
把这些共同的部分提出来单独写成一个类型，再让圆和矩形**在它的基础上补充**——
这就是继承。

**继承表达的关系是「是一种」**：圆**是一种**形状，矩形**是一种**形状。
它与「有一个」（一个形状**有一个**颜色）不是一回事，混用会写出很别扭的代码（第 1.2 小节）。

继承也是这一板块里**最容易被滥用**的手段。
它看起来能省掉重复的代码，代价却是把两个类型的接口与实现永久绑在一起——
**能用成员表达的关系，不要用继承表达。**

# 第 1 节 继承解决什么问题

## 1.1 共同的部分写两遍

先看不用继承的写法。两种形状各写一个类：

`C++`

```cpp
class Circle {
public:
    double area() const { return 3.141592653589793 * r_ * r_; }
    void   print() const { std::printf("圆，半径 %g\n", r_); }
private:
    double r_;
};

class Rect {
public:
    double area() const { return w_ * h_; }
    void   print() const { std::printf("矩形，%g × %g\n", w_, h_); }
private:
    double w_, h_;
};
```

**两份 `area` 与 `print` 的骨架是一样的**：都是「取自己的数据、算一个数、打印」。
这样的重复在两种形状时还能接受，加到五种、十种时就会变成负担：
**新增一项共同操作，要改多少个地方，取决于有多少个类。**

**C 里没有继承**，常见的替代做法是「一个结构体 + 一个表示种类的字段 + 一串 `switch`」：

`C`

```c
struct Shape {
    int    kind;            /* 0 = 圆，1 = 矩形 */
    double a, b;
};

double area(const struct Shape *s) {
    switch (s->kind) {      /* 每加一种形状，所有 switch 都要加分支 */
    case 0:  return 3.141592653589793 * s->a * s->a;
    default: return s->a * s->b;
    }
}
```

**这串 `switch` 会散落在所有处理形状的函数里**，每加一种形状就要把它们全找出来改一遍，
漏掉一处编译器也不会提醒。

继承换了一种组织方式：**把共同的部分放进一个类型，其余部分各自补充。**

## 1.2 「是一种」与「有一个」

**继承表达的句子是「派生类是一种基类」。** 这个句子必须真的成立，继承才有意义。

| 关系 | 怎么表达 | 例子 |
|---|---|---|
| **是一种**（is-a） | 继承 | 圆是一种形状；学生是一种人 |
| **有一个**（has-a） | 成员 | 形状有一个颜色；汽车有一个发动机 |

**判断办法**：把派生类的名字代进基类出现的位置，读一遍那句话。
「圆是一种形状」读得通；「汽车是一种发动机」读不通，那就该用成员。

**一个典型的反例是让栈继承 `std::vector`**：

`C++`

```cpp
class Stack : public std::vector<int> { };   /* 不该这么写 */
```

读一遍那个句子：「栈是一个向量」。这句话很难说通，但后果是具体的：
**`vector` 的每一个公开成员都成了 `Stack` 的接口**——
调用方可以对一个栈做按下标删除、在中间插入、反转，这些操作都会破坏「后进先出」这个约束。
**栈想要的只是「用向量存数据」，那是「有一个」。**

> [!IMPORTANT]
> **继承把基类的接口全部继承下来。**
> 判断该不该继承，不看两者代码有多像，而看**派生类是不是真的可以被当成基类使用**。
> 只要有一组从基类继承来的操作对派生类没有意义，继承就是错的选择。

## 1.3 派生类对象里有一个基类子对象

派生类的写法只有一句：

`C++`

```cpp
class Derived : public Base {   /* 冒号后面写基类与继承方式 */
    /* 派生类自己新增的成员与函数 */
};
```

**派生类对象里面真的包含一个基类对象**，它叫**基类子对象**，放在对象的最前面。
把两边的成员地址打出来看：

`C++`

```cpp
/* layout.cpp    编译：g++ -std=c++17 layout.cpp -o layout */
#include <cstddef>
#include <cstdio>

class Base {
public:
    int  a;
    char b;
};

class Derived : public Base {          /* 基类子对象是派生类对象的第一部分 */
public:
    int c;
};

int main() {
    std::printf("sizeof(Base)          = %zu\n", sizeof(Base));
    std::printf("sizeof(Derived)       = %zu\n", sizeof(Derived));
    std::printf("Derived 里 Base 的偏移 = %zu\n", offsetof(Derived, a));
    std::printf("Derived 里 c  的偏移   = %zu\n", offsetof(Derived, c));

    Derived d;
    d.a = 1;                            /* 从基类继承来的成员 */
    d.b = 'x';
    d.c = 2;                            /* 派生类自己加的成员 */
    Base *p = &d;                       /* 派生类指针可以隐式转成基类指针 */
    std::printf("通过基类指针看到的 a = %d，b = %c\n", p->a, p->b);
    std::printf("&d = %p，p = %p，两者相同：%s\n",
                static_cast<void *>(&d), static_cast<void *>(p),
                (static_cast<void *>(&d) == static_cast<void *>(p)) ? "是" : "否");
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(Base)          = 8
sizeof(Derived)       = 12
Derived 里 Base 的偏移 = 0
Derived 里 c  的偏移   = 8
通过基类指针看到的 a = 1，b = x
&d = 000000595e9ffe2c，p = 000000595e9ffe2c，两者相同：是
```

程序里用 `offsetof` 取偏移，它作用在 `Derived` 这种**非标准布局类型**上，
标准对此只是「有条件支持」：

`文档`

> "Use of the offsetof macro with a type other than a standard-layout class (Clause 12)
> is conditionally-supported."
>
> —— N4659 §21.2.4/1

g++ 15.2.0 因此给出一条警告：

`实测数据`
`Text`

```text
layout.cpp:19:60: warning: 'offsetof' within non-standard-layout type 'Derived' is conditionally-supported [-Winvalid-offsetof]
```

警告不影响结果，偏移那一行照常打印。不借助 `offsetof` 也能得到同样的结论——
程序最后一行比较的两个地址，就是基类子对象的位置。

三件事从这组数字里可以直接读出来：

| 数字 | 说明 |
|---|---|
| `sizeof(Derived) = 12` | 派生类对象 = 基类子对象（8 字节，含填充）+ 自己新增的成员（4 字节） |
| `Base` 的偏移是 `0` | 基类子对象在对象的最前面 |
| `&d` 与 `p` 相同 | 指向派生类对象的指针转成基类指针时，**地址不变**，因为它本来就指在基类子对象上 |

`文档`

> "Two objects a and b are pointer-interconvertible if: —(4.3) one is a standard-layout
> class object and the other is the first non-static data member of that object, or,
> if the object has no non-static data members, the first base class subobject of that
> object (12.2) ... If two objects are pointer-interconvertible, then they have the same
> address, and it is possible to obtain a pointer to one from a pointer to the other
> via a reinterpret_cast (8.2.10)."
>
> —— N4659 §6.9.2/4

> [!IMPORTANT]
> **派生类对象「是」一个基类对象，而不是「含有」一个基类对象。**
> 这句话解释了后面几乎所有现象：地址相同、可以隐式转换、
> 按值传基类会切掉派生部分（第 5 节）。

# 第 2 节 三种继承方式

## 2.1 三种方式的作用范围

继承方式写的是**基类成员在派生类里的可见性**，它对三种人分别有效：
派生类自己、派生类的派生类、以及类外面的代码。

| 继承方式 | 基类的 `public` 成员变成 | 基类的 `protected` 成员变成 | 外面能否把派生类当基类用 |
|---|---|---|---|
| `public` | `public` | `protected` | **能** |
| `protected` | `protected` | `protected` | 不能 |
| `private` | `private` | `private` | 不能 |

`文档`

> "If a class is declared to be a base class (Clause 13) for another class using the
> public access specifier, the public members of the base class are accessible as public
> members of the derived class and protected members of the base class are accessible as
> protected members of the derived class. If a class is declared to be a base class for
> another class using the protected access specifier, the public and protected members of
> the base class are accessible as protected members of the derived class. If a class is
> declared to be a base class for another class using the private access specifier, the
> public and protected members of the base class are accessible as private members of the
> derived class."
>
> —— N4659 §14.2/1

**基类的 `private` 成员在三种方式下都一样：派生类碰不到**，
只有基类自己（以及它的友元）能访问（《05-类与面向对象/02-类是一种类型.md》第 1.3 小节）。

## 2.2 `public` 与 `protected` 继承

`protected` 继承不挡派生类自己，只挡外面：

`C++`

```cpp
/* inherit_modes.cpp    编译：g++ -std=c++17 inherit_modes.cpp -o inherit_modes */
#include <cstdio>

class Base {
public:
    int open_ = 1;
protected:
    int prot_ = 2;
};

class Pub : public Base { };                        /* public 继承 */
class Pro : protected Base { };                     /* protected 继承 */

class SubPub : public Pub {
public:
    int f() { return open_ + prot_; }               /* 都能用 */
};

class SubPro : public Pro {
public:
    int f() { return open_ + prot_; }               /* 也都能用：protected 继承不挡派生类自己 */
};

int main() {
    Pub a;
    SubPub sa;
    SubPro sb;
    std::printf("a.open_ = %d（public 继承，外部可用）\n", a.open_);
    std::printf("sa.f() = %d，sb.f() = %d\n", sa.f(), sb.f());

    Base *p = &a;                                   /* public 继承：派生类指针可以转成基类指针 */
    std::printf("p->open_ = %d\n", p->open_);
    return 0;
}
```

`实测数据`
`Text`

```text
a.open_ = 1（public 继承，外部可用）
sa.f() = 3，sb.f() = 3
p->open_ = 1
```

外面碰 `protected` 继承来的成员，编译器直接拦下来：

`实测数据`
`Text`

```text
pro_outside.cpp:6:15: error: 'int Base::open_' is inaccessible within this context
```

**`protected` 继承的含义是「只让派生类知道它是从哪来的」**，
外面的代码既不认识这层关系，也拿不到基类的那套接口。

## 2.3 `private` 继承

`private` 继承把基类的一切都收进派生类内部，连派生类的派生类也拿不到：

`C++`

```cpp
/* inherit_private.cpp    编译：g++ -std=c++17 inherit_private.cpp -o inherit_private （失败） */
class Base {
public:
    int open_ = 1;
};

class Pri : private Base { };                       /* private 继承 */

class SubPri : public Pri {
public:
    int f() { return open_; }                       /* 孙类也拿不到：Base 的 public 在 Pri 里成了 private */
};

int main() {
    Pri c;
    int y = c.open_;                                /* 外部同样拿不到 */
    SubPri s;
    return s.f() + y;
}
```

`实测数据`
`Text`

```text
inherit_private.cpp:11:22: error: 'int Base::open_' is private within this context
inherit_private.cpp:16:15: error: 'int Base::open_' is inaccessible within this context
```

外面也做不了「派生类指针转基类指针」这一步：

`实测数据`
`Text`

```text
inherit_conv.cpp:13:16: error: 'Base' is an inaccessible base of 'Pro'
inherit_conv.cpp:14:16: error: 'Base' is an inaccessible base of 'Pri'
```

**`private` 继承的含义是「用基类的实现，但不承认这层关系」。**
外面看到的是一个与 `Base` 毫无关系的类型。

**不写继承方式时，`class` 默认 `private`，`struct` 默认 `public`**——
与第 02 章讲过的默认成员访问权限是同一条规则的延伸：

`实测数据`
`Text`

```text
inherit_default.cpp:11:15: error: 'int CBase::x' is inaccessible within this context
```

## 2.4 该用哪一种

| 想表达 | 用 | 理由 |
|---|---|---|
| 「派生类是一种基类」 | **`public` 继承** | 外面可以把派生类当基类用，这是多态的前提（第 08 章） |
| 「用它的实现，但不暴露这层关系」 | `private` 继承 | 等价于「有一个」，而且可以覆盖基类的实现 |
| 「只想让后代知道」 | `protected` 继承 | 极少用，多数场合它想表达的东西用 `private` + 成员更清楚 |

**「有一个」优先用成员，不要用 `private` 继承。**
`private` 继承在需要覆盖基类实现时才比成员更合适，
其余场合它就是一层多余的耦合：基类改了，派生类跟着受影响。

# 第 3 节 构造与析构的顺序

## 3.1 先是基类，再是成员，最后才是派生类的构造体

一个派生类对象要分三步才能建好，顺序由语言定死：

`C++`

```cpp
/* ctor_order.cpp    编译：g++ -std=c++17 ctor_order.cpp -o ctor_order */
#include <cstdio>

class Member {
public:
    explicit Member(const char *n) : n_(n) { std::printf("  成员 %s 构造\n", n_); }
    ~Member() { std::printf("  成员 %s 析构\n", n_); }
private:
    const char *n_;
};

class Base {
public:
    Base() { std::printf("  基类构造\n"); }
    ~Base() { std::printf("  基类析构\n"); }
};

class Derived : public Base {
public:
    Derived() : m_("m") { std::printf("  派生类构造体\n"); }
    ~Derived() { std::printf("  派生类析构体\n"); }
private:
    Member m_;
};

int main() {
    std::printf("构造一个 Derived：\n");
    {
        Derived d;
        std::printf("  —— 对象已经建好 ——\n");
    }
    std::printf("对象离开作用域之后\n");
    return 0;
}
```

`实测数据`
`Text`

```text
构造一个 Derived：
  基类构造
  成员 m 构造
  派生类构造体
  —— 对象已经建好 ——
  派生类析构体
  成员 m 析构
  基类析构
对象离开作用域之后
```

| 阶段 | 谁在做 | 为什么是这个位置 |
|---|---|---|
| 1 | 基类子对象构造 | 派生类的构造体要用到基类部分，它必须先可用 |
| 2 | 派生类自己的成员构造 | 与《05-类与面向对象/04-构造与析构.md》第 2 节讲的一样，按声明顺序 |
| 3 | 派生类的构造体执行 | 到这里所有成员都已经初始化好了 |

`文档`

> "... initialization proceeds in the following order: ... —(13.2) Then, direct base
> classes are initialized in declaration order as they appear in the base-specifier-list
> (regardless of the order of the mem-initializers). —(13.3) Then, non-static data members
> are initialized in the order they were declared in the class definition (again
> regardless of the order of the mem-initializers). —(13.4) Finally, the compound-statement
> of the constructor body is executed. [Note: The declaration order is mandated to ensure
> that base and member subobjects are destroyed in the reverse order of initialization.—end
> note]"
>
> —— N4659 §15.6.2/13
>
> "Bases and members are destroyed in the reverse order of the completion of their
> constructor (see 15.6.2)."
>
> —— N4659 §15.4/9

**析构严格逆序**：派生类析构体 → 成员 → 基类。
理由与《05-类与面向对象/04-构造与析构.md》第 3 节相同：
**派生类的析构体执行时，基类部分还必须活着**，否则它没法用基类的数据做收尾。

## 3.2 基类的构造要在初始化列表里指定

**基类子对象的构造由派生类负责**，写法是初始化列表里那个冒号：

`C++`

```cpp
class Derived : public Base {
public:
    Derived() : Base(10), w_(20) { }    /* 先给基类传参，再初始化自己的成员 */
private:
    int w_;
};
```

`实测数据`
`Text`

```text
  基类构造，v = 10
d.v() = 10，d.w() = 20
```

**不写就相当于要求基类有默认构造函数**，没有就编不过：

`实测数据`
`Text`

```text
base_no_default.cpp:9:15: error: no matching function for call to 'Base::Base()'
```

> [!IMPORTANT]
> **基类的构造函数不能被继承，只能被调用**（C++11 起可以用 `using Base::Base;` 把基类的构造函数引进来，
> 那属于「继承构造函数」，第 03 章展开）。
> 派生类能做的只有一件事：**在初始化列表里说明调基类的哪一个构造函数**。

## 3.3 析构函数不必手写基类的调用

派生类的析构函数里**不需要写 `~Base()`**，编译器会插入这个调用
（《05-类与面向对象/04-构造与析构.md》第 1.5 小节讲过：构造与析构的调用方是编译器或 CRT）。

反过来说：**析构函数不能重载，也没有返回值**，这两条在派生类里同样成立。

# 第 4 节 名字隐藏

## 4.1 派生类的同名函数挡住基类那一整组

**这条规则与重载决议无关，它发生在更早的一步：名字查找。**
在派生类里写一个与基类同名的函数，基类的所有同名函数都会**被藏起来**，
哪怕参数表完全不同：

`C++`

```cpp
/* hide.cpp    编译：g++ -std=c++17 hide.cpp -o hide */
#include <cstdio>

class Base {
public:
    void f()          { std::printf("  Base::f()\n"); }
    void f(int x)     { std::printf("  Base::f(int %d)\n", x); }
};

class Derived : public Base {
public:
    void f(double y) { std::printf("  Derived::f(double %.1f)\n", y); }
};

int main() {
    Derived d;
    d.f(1.5);           /* 调用派生类自己的 */
    d.f(1);             /* 1 会转成 double：基类那一组被藏起来了 */
    d.Base::f(1);       /* 限定调用才能到基类 */
    d.Base::f();
    return 0;
}
```

`实测数据`
`Text`

```text
  Derived::f(double 1.5)
  Derived::f(double 1.0)
  Base::f(int 1)
  Base::f()
```

**第二行是关键**：实参是 `int`，基类里有一个 `f(int)` 精确匹配，
但调用仍然落到了 `Derived::f(double)`——**因为基类的 `f` 根本没被找到**，
于是 `int` 被隐式转成了 `double`。

`文档`

> "1 A name can be hidden by an explicit declaration of that same name in a nested
> declarative region or derived class (13.2)."
>
> "3 ... The declaration of a member in a derived class (Clause 13) hides the declaration
> of a member of a base class of the same name; see 13.2."
>
> —— N4659 §6.3.10/1、§6.3.10/3

## 4.2 报错长什么样

基类只有 `f()`、派生类写了 `f(int)` 时，调用 `d.f()` 会直接失败：

`实测数据`
`Text`

```text
hide_error.cpp:14:8: error: no matching function for call to 'Derived::f()'
hide_error.cpp:14:8: note: there is 1 candidate
hide_error.cpp:9:10: note: candidate 1: 'void Derived::f(int)'
hide_error.cpp:9:10: note: candidate expects 1 argument, 0 provided
```

**候选只有 1 个**：编译器根本没有把 `Base::f()` 列进候选，
它已经被名字查找挡在外面了。

## 4.3 两种解除方式

| 写法 | 效果 |
|---|---|
| `using Base::f;`（写在派生类里） | 把基类那一组名字引回派生类的作用域，与派生类自己的同名函数**一起参与重载决议** |
| `d.Base::f();` | 本次调用直接指定基类那一组，不影响别处 |

`using` 那种写法见《05-类与面向对象/01-命名空间与 using.md》第 5.3 小节，效果：

`C++`

```cpp
class Derived : public Base {
public:
    using Base::f;                      /* 把基类那一组重新引进来 */
    void f(double y) { ... }
};

int main() {
    Derived d;
    d.f(1.5);       /* Derived::f(double) */
    d.f(1);         /* Base::f(int)：精确匹配，参与重载了 */
    d.f();          /* Base::f() */
}
```

`实测数据`
`Text`

```text
  Derived::f(double 1.5)
  Base::f(int 1)
  Base::f()
```

## 4.4 数据成员同名也会隐藏

函数如此，数据成员也一样：派生类的成员把基类的同名成员藏起来，
**但两份数据都在对象里**。

`实测数据`
`Text`

```text
d.x = 2
d.Base::x = 1
sizeof(Derived) = 8，两份 x 都在对象里
```

**这不是「覆盖」，是两份独立的数据**：一份属于基类子对象，一份属于派生类。
改一个不影响另一个，只是名字撞了。**不要这么写**：
读代码的人看到 `d.x` 必须回去确认说的是哪一份。

## 4.5 隐藏、覆盖、重载不是一回事

| 名字 | 发生在 | 一句话 |
|---|---|---|
| **重载**（overload） | 同一个作用域里 | 同名不同参，编译期按实参选 |
| **隐藏**（hide） | 派生类与基类之间 | 派生类的同名成员把基类那一组挡住，**与参数无关** |
| **覆盖**（override） | 派生类与基类之间，且函数是虚函数 | 运行期按对象的实际类型选（第 08 章） |

**「隐藏」这一条只看名字，不看参数，也不看返回类型。**

# 第 5 节 切片

## 5.1 按值传基类会切掉派生部分

**把一个派生类对象交给基类对象（而不是基类的引用或指针），多出来的部分会被切掉。**
这件事在做参数传递时最容易发生：

`C++`

```cpp
/* slice.cpp    编译：g++ -std=c++17 slice.cpp -o slice */
#include <cstdio>

class Base {
public:
    int a = 1;
    int b = 2;
};

class Derived : public Base {
public:
    int c = 3;
};

void by_value(Base x) {                  /* 按值传基类：这里会新造一个 Base 对象 */
    std::printf("  按值传参：参数地址 %p，sizeof = %zu，a = %d，b = %d\n",
                static_cast<void *>(&x), sizeof(x), x.a, x.b);
}

void by_ref(Base &x) {                   /* 按引用传：不新造对象 */
    std::printf("  按引用传：参数地址 %p，sizeof = %zu，a = %d，b = %d\n",
                static_cast<void *>(&x), sizeof(x), x.a, x.b);
}

int main() {
    Derived d;
    std::printf("原始对象：地址 %p，sizeof(Derived) = %zu，a = %d，c = %d\n",
                static_cast<void *>(&d), sizeof(d), d.a, d.c);
    by_value(d);
    by_ref(d);

    Base copy = d;                       /* 用派生类对象初始化基类对象：同样切开 */
    std::printf("拷成 Base：地址 %p，sizeof = %zu，a = %d，b = %d\n",
                static_cast<void *>(&copy), sizeof(copy), copy.a, copy.b);
    return 0;
}
```

`实测数据`
`Text`

```text
原始对象：地址 0000006603fffbc4，sizeof(Derived) = 12，a = 1，c = 3
  按值传参：参数地址 0000006603fffb80，sizeof = 8，a = 1，b = 2
  按引用传：参数地址 0000006603fffbc4，sizeof = 8，a = 1，b = 2
拷成 Base：地址 0000006603fffbbc，sizeof = 8，a = 1，b = 2
```

| 写法 | 参数地址 | 发生了什么 |
|---|---|---|
| `by_value(d)` | 与 `d` 不同 | **新造了一个 `Base` 对象**，只拷贝基类那一部分，`c` 被丢掉 |
| `by_ref(d)` | 与 `d` 相同 | 没有新对象，引用直接绑在 `d` 上 |
| `Base copy = d;` | 独立地址 | 同样是新对象，同样只有基类部分 |

**原因在拷贝构造身上**：`Base` 的拷贝构造只认识 `Base` 的那几个成员
（《05-类与面向对象/05-拷贝与移动.md》第 2.2 小节的「逐成员拷贝」）。
它没有地方放 `c`，也不知道有 `c`。

> [!CAUTION]
> **按值接收基类对象的函数，拿到的是一个被切过的副本。**
> 派生类新增的成员与它自己的行为全部丢失，而且不会有任何报错或警告。
> 需要保留派生部分时，参数必须是引用或指针。

## 5.2 把派生类对象放进基类的容器

同样的道理适用于容器：`std::vector<Base>` 里存的是 `Base` 对象，
`push_back(derived)` 会把派生部分切掉。
**容器里放的永远是它声明的那个类型的对象**，这条规则在【待补：08-高阶数据结构/】里会再遇到。

## 5.3 通过基类引用调用非虚函数，调的是基类版本

切片的后果还有一种不经过拷贝的版本。对象没被切开，但**调用哪个函数由静态类型决定**：

`C++`

```cpp
/* static_binding.cpp    编译：g++ -std=c++17 static_binding.cpp -o static_binding */
#include <cstdio>

class Base {
public:
    void who() { std::printf("  Base::who\n"); }        /* 非虚函数：看静态类型 */
};

class Derived : public Base {
public:
    void who() { std::printf("  Derived::who\n"); }     /* 同名，把基类的藏起来 */
};

int main() {
    Derived d;
    Base &r = d;            /* 引用绑定到派生类对象，但引用的静态类型是 Base */
    Base *p = &d;

    std::printf("用派生类对象调用：\n");
    d.who();
    std::printf("通过基类引用调用：\n");
    r.who();
    std::printf("通过基类指针调用：\n");
    p->who();
    return 0;
}
```

`实测数据`
`Text`

```text
用派生类对象调用：
  Derived::who
通过基类引用调用：
  Base::who
通过基类指针调用：
  Base::who
```

**引用与指针绑定的确实是派生类对象，但调用的却是 `Base::who`。**
想让它按对象的实际类型选，函数必须声明为 `virtual`——那是第 08 章的内容。

# 第 6 节 多重继承与菱形继承

## 6.1 一个类可以有两个基类

`C++`

```cpp
class C : public A, public B { };       /* 两个基类子对象都在对象里 */
```

`实测数据`
`Text`

```text
sizeof(C) = 12
x.a = 1，x.b = 2，x.c = 3
  A::hello
  B::hello
A 子对象偏移 = 0，B 子对象偏移 = 4
```

**两个基类子对象按声明顺序排列**：`A` 在偏移 0，`B` 跟在它后面。
它们的同名函数必须用 `x.A::hello()` 这样的限定写法区分。

## 6.2 歧义

**两个基类都有同一个名字时，不限定就是错误**：

`实测数据`
`Text`

```text
multi_ambig.cpp:8:7: error: request for member 'hello' is ambiguous
```

## 6.3 菱形继承：同一个基类出现两次

A 被 D 与 E 各继承一次，F 同时继承 D 与 E：

`C++`

```cpp
class A { public: int a = 1; };
class D : public A { };
class E : public A { };
class F : public D, public E { };       /* F 里有两份 A */
```

`实测数据`
`Text`

```text
sizeof(F) = 8，A 有两份子对象
两份 A 的地址：000000e1493ff87c 与 000000e1493ff880，不同
f.D::a = 9，f.E::a = 1
```

**对象里真的有两份 `A`**：地址相差 4 字节，
改 `f.D::a` 不影响 `f.E::a`。不限定地写 `f.a` 就是错误：

`实测数据`
`Text`

```text
diamond_ambig.cpp:9:7: error: request for member 'a' is ambiguous
```

**语义上「F 有两个 A」通常不是想要的**：一份 A 更符合「F 是一种 A」这个说法，
何况两份基类子对象会让每次访问都多一次选择。

## 6.4 虚继承：让共同的基类只留一份

把 D、E 对 A 的继承声明成 `virtual`：

`C++`

```cpp
class D : virtual public A { };         /* 虚继承 */
class E : virtual public A { };
class F : public D, public E { };       /* F 里只有一份 A */
```

`实测数据`
`Text`

```text
sizeof(F) = 24
两份 A 的地址：00000048255ff740 与 00000048255ff740，相同
f.a = 9
```

| 写法 | `sizeof(F)` | `A` 的份数 | 访问 `a` |
|---|---|---|---|
| 普通继承 | **8** | 2 | 必须限定 |
| 虚继承 | **24** | 1 | 直接写 |

**代价是对象变大**：从 8 字节变成 24 字节——虚继承要让「共同的那一份」的位置在
运行期才能确定，于是每个虚继承的派生类里多出指向它的信息。
具体布局属于 ABI 细节，归 `06-更底层` 板块。

> [!TIP]
> **多重继承用在「接口」上比用在「状态」上安全。**
> 两个基类都带来数据成员时，菱形、歧义、对象变大都会跟着来；
> 基类只是几组函数声明（纯虚函数，第 08 章）时，这些问题基本不出现。

# 第 7 节 通过基类指针删除对象的陷阱

**问题出在基类的析构函数不是虚函数，解法见第 08 章。**

`C++`

```cpp
/* no_virtual_dtor.cpp    编译：g++ -std=c++17 no_virtual_dtor.cpp -o no_virtual_dtor */
#include <cstdio>

class Base {
public:
    ~Base() { std::printf("  ~Base\n"); }        /* 没有 virtual */
};

class Derived : public Base {
public:
    ~Derived() { std::printf("  ~Derived\n"); }
};

int main() {
    std::printf("直接删除派生类对象：\n");
    { Derived *d = new Derived; delete d; }
    std::printf("通过基类指针删除：\n");
    { Base *p = new Derived; delete p; }
    return 0;
}
```

`实测数据`
`Text`

```text
直接删除派生类对象：
  ~Derived
  ~Base
通过基类指针删除：
  ~Base
```

**第二种写法里 `~Derived` 没有执行。** 编译器不会为这件事报错，加 `-Wall -Wextra` 也没有警告：

`实测数据`

| 编译选项 | 结果 |
|---|---|
| `g++ -std=c++17` | 编译通过，无警告 |
| `g++ -std=c++17 -Wall -Wextra` | **仍然没有警告** |

派生类析构函数里要释放的资源因此全部泄漏，而这类错误在编译期完全看不见。

`文档`

> "In the first alternative (delete object), if the static type of the object to be deleted is
> different from its dynamic type, the static type shall be a base class of the dynamic type of
> the object to be deleted and the static type shall have a virtual destructor or the behavior
> is undefined."
>
> —— N4659 §8.3.5/3

> [!CAUTION]
> **只要存在「用基类指针删除对象」的可能，基类的析构函数就必须是虚函数。**
> 判断办法很直接：这个类有没有虚函数（第 08 章）、或者有没有人可能通过基类指针持有派生类对象。
> 有一条经验规则：**基类的析构函数要么是虚的，要么是 `protected` 的**
> （`protected` 能挡住「通过基类指针删除」，见《05-类与面向对象/04-构造与析构.md》第 4.3 小节）。

# 第 8 节 检查清单

| 检查 | 为什么 |
|---|---|
| 这个继承关系读成「派生类是一种基类」通顺吗 | 读不通就该改用成员（第 1.2 小节） |
| 基类里有没有对派生类没有意义的接口 | 继承会把基类接口全部继承下来（第 1.2 小节） |
| 继承方式写了吗 | 不写时 `class` 默认 `private`（第 2.3 小节） |
| 基类有默认构造函数吗，没有就在列表里传参 | 否则编不过（第 3.2 小节） |
| 派生类里有没有与基类同名的函数 | 会把基类那一组藏起来（第 4.1 小节） |
| 需要基类那一组参与重载时，写 `using Base::f;` 了吗 | 否则调用会落到派生类版本上（第 4.3 小节） |
| 有没有按值接收基类对象的函数 | 会切片（第 5.1 小节） |
| 有没有用基类指针删除对象的可能 | 没有虚析构就是未定义行为（第 7 节） |

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 继承 | Inheritance | 在一个类型的基础上定义新类型；表达「是一种」 |
| 基类 | Base class | 被继承的那个类；也叫父类 |
| 派生类 | Derived class | 继承出来的类；也叫子类 |
| 基类子对象 | Base class subobject | 派生类对象内部那个基类对象，位于对象最前面 |
| 是一种 | is-a | 继承表达的关系 |
| 有一个 | has-a | 成员表达的关系 |
| 公有继承 | Public inheritance | 基类的 `public` 成员在派生类里仍是 `public`，外面能用 |
| 保护继承 | Protected inheritance | 基类的 `public` / `protected` 成员都变成 `protected` |
| 私有继承 | Private inheritance | 基类成员都变成 `private`，外面不承认这层关系 |
| 名字隐藏 | Name hiding | 派生类的同名成员挡住基类那一整组名字 |
| `using Base::f;` | Using-declaration | 把基类的那组名字引回派生类作用域，解除隐藏 |
| 切片 | Object slicing | 派生类对象被当成基类对象拷贝，派生部分被丢掉 |
| 多重继承 | Multiple inheritance | 一个类有多个基类 |
| 菱形继承 | Diamond inheritance | 同一个基类经由两条路径被继承两次 |
| 虚继承 | Virtual inheritance | 让共同的基类只保留一份子对象；对象会变大 |
| 歧义 | Ambiguity | 多重继承下同一个名字对应多个成员，必须限定 |
| 虚析构函数 | Virtual destructor | 让「通过基类指针删除」也能调用派生类的析构（第 08 章） |

```cpp
public:
    int c = 3;

}

void by_ref(Base &x) {
    std::printf("  按引用传：参数地址 %p，sizeof = %zu，a = %d，b = %d\n",
                static_cast<void *>(&x), sizeof(x), x.a, x.b);
}

int main() {
    Derived d;

    by_ref(d);

    Base copy = d;
    std::printf("拷成 Base：地址 %p，sizeof = %zu，a = %d，b = %d\n",
                static_cast<void *>(&copy), sizeof(copy), copy.a, copy.b);
```

## A.14 多重继承与菱形继承

`C++`

```cpp
/* multi.cpp    编译：g++ -std=c++17 multi.cpp -o multi */
#include <cstdio>

class A {
public:
    int a = 1;
    void hello() { std::printf("  A::hello\n"); }
};

class B {
public:
    int b = 2;
    void hello() { std::printf("  B::hello\n"); }
};

class C : public A, public B {
public:
    int c = 3;
};

class D : public A { };
class E : public A { };
class F : public D, public E { };

int main() {
    C x;
    std::printf("sizeof(C) = %zu\n", sizeof(C));
    std::printf("x.a = %d，x.b = %d，x.c = %d\n", x.a, x.b, x.c);
    x.A::hello();
    x.B::hello();
    std::printf("A 子对象偏移 = %zu，B 子对象偏移 = %zu\n",
                (size_t)(void *)static_cast<A *>(&x) - (size_t)(void *)&x,
                (size_t)(void *)static_cast<B *>(&x) - (size_t)(void *)&x);

    std::printf("菱形继承（不用虚继承）：\n");
    F f;
    std::printf("  sizeof(F) = %zu，A 有两份子对象\n", sizeof(f));
    A *p1 = static_cast<D *>(&f);
    A *p2 = static_cast<E *>(&f);
    std::printf("  两份 A 的地址：%p 与 %p，%s\n",
                static_cast<void *>(p1), static_cast<void *>(p2),
                (static_cast<void *>(p1) == static_cast<void *>(p2)) ? "相同" : "不同");
    f.D::a = 9;
    std::printf("  f.D::a = %d，f.E::a = %d\n", f.D::a, f.E::a);
    return 0;
}
```
