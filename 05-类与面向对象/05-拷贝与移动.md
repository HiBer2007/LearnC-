**先分清一件事：拷贝构造与移动构造，本身也是构造函数。**

前几章说的「构造函数」一直是指「默认构造」那一种；
这一章会一次给出四个新名字：**拷贝构造、移动构造、拷贝赋值、移动赋值**。
它们分成两拨，**分界是这一次调用里对象是诞生还是已经存在**：

| 这一拨是**构造函数**（对象**诞生**时用） | 这一拨不是（给**已有对象**改值） |
|---|---|
| 拷贝构造 `A(const A &)` | 拷贝赋值 `A &operator=(const A &)` |
| 移动构造 `A(A &&)` | 移动赋值 `A &operator=(A &&)` |

**「构造函数有五个」** 说的是：默认构造、带参构造（含转换构造）、**拷贝构造**、**移动构造**、委托／继承构造。

**「五法则」** 说的是另一组五个：拷贝构造、移动构造、拷贝赋值、移动赋值、析构。

**两个「五」不同源**：前者的判定见第 1.1 小节，后者的判定见第 5.4 小节。

**区别可以压成一句话：构造是「从无到有」，赋值是「旧的换新的」。**

# 第 1 节 构造与赋值是两回事

## 1.1 构造函数有五个，其中两个是拷贝与移动

**一个类可以有很多个构造函数**——它们同名，靠参数表区分（就是《04-语法/07-函数.md》第 5.3 小节讲过的重载）。
其中有五个各有专门的名字与用途：

`实测数据`

| # | 名字 | 签名 | 什么时候被调用 |
|---|---|---|---|
| 1 | 默认构造函数 | `A()` | `A a;` |
| 2 | 带参构造函数（含转换构造） | `A(T)` | `A a(x);`、隐式转换 |
| 3 | **拷贝构造函数** | `A(const A &)` | `A b(a);`、按值传参、按值返回 |
| 4 | **移动构造函数** | `A(A &&)` | `A b(std::move(a));`、接管临时对象 |
| 5 | 委托构造／继承构造（C++11 起） | `A() : A(1) {}`、`using Base::Base;` | 复用另一个构造 |

`文档`

> "A constructor declared without the function-specifier explicit specifies a conversion from the
> types of its parameters (if any) to the type of its class. Such a constructor is called a
> converting constructor."
>
> "If a mem-initializer-id designates the constructor's class, it shall be the only mem-initializer;
> the constructor is a delegating constructor, and the constructor selected by the mem-initializer
> is the target constructor."
>
> —— N4659 §15.3.1/1、§15.6.2/6

**第 3、4 条是本章的主角**，它们和默认构造一样，都是「对象诞生时被调用的函数」，
**因此它们的返回类型也一样：不写**（见《05-类与面向对象/04-构造与析构.md》第 1.5 小节）。

## 1.2 拷贝赋值与移动赋值不是构造函数

**它们长得像，但差一个字：多了 `operator=`。**

`C++`

```cpp
A &operator=(const A &);     // 拷贝赋值：把 another 的内容给「已经存在的自己」
A &operator=(A &&);          // 移动赋值：把 another 的资源搬给「已经存在的自己」
```

**判断标准只有一条：这个对象是不是已经存在了。**

| 写法 | 对象是新的还是旧的 | 走哪条路 |
|---|---|---|
| `A b(a);` | `b` 是新的 | **拷贝构造** |
| `A b = a;` | `b` 是新的（这是初始化，不是赋值） | **拷贝构造** |
| `b = a;` | `b` 早就存在 | **拷贝赋值** |

> [!WARNING]
> **`A b = a;` 里虽然有等号，但 `b` 是新造出来的对象——它调用的是拷贝构造，不是拷贝赋值。**
> 等号在这里只是初始化的写法之一（《04-语法/05-初始化.md》第 1 节讲的就是这件事）。
> **判断只看一件事：左边那个对象是这一次新造的吗。**

## 1.3 六个特殊成员与它们被调用的时机

**特殊成员函数**是编译器在需要时会替类生成的那一批函数，共六个：

`实测数据`

| 特殊成员函数 | 签名 | 什么时候被调用 |
|---|---|---|
| 默认构造 | `A()` | `A a;`、`new A`、容器默认造元素 |
| 拷贝构造 | `A(const A &)` | `A b(a);`、按值传参、按值返回 |
| 移动构造 | `A(A &&)` | `A b(std::move(a));`、接管临时对象 |
| 拷贝赋值 | `A &operator=(const A &)` | `b = a;`（`b` 已经存在） |
| 移动赋值 | `A &operator=(A &&)` | `b = std::move(a);`（`b` 已经存在） |
| 析构 | `~A()` | 生存期结束：离开作用域、`delete`、临时对象用完 |

`文档`

> "The default constructor (15.1), copy constructor and copy assignment operator (15.8), move
> constructor and move assignment operator (15.8), and destructor (15.4) are special member
> functions."
>
> —— N4659 §15/1

**前四个是四条路径的主角**：两个构造函数来自第 1.1 小节，两个赋值运算符来自第 1.2 小节。
带参构造与委托构造不在六个之列——它们只在类自己声明时存在，编译器不会生成。

**两处区别把这四个函数分开**：名字里有没有 `operator=` 决定**构造还是赋值**，
参数是 `const A &` 还是 `A &&` 决定**拷贝还是移动**：

`C++`

```cpp
A(const A &);                 // 拷贝构造：照着另一个对象造出新的一个
A(A &&);                      // 移动构造：接过另一个对象的资源，造出新的一个
A &operator=(const A &);      // 拷贝赋值：把另一个对象的内容给已有的一个
A &operator=(A &&);           // 移动赋值：把另一个对象的资源搬给已有的一个
```

`C++`

```cpp
/* which_path.cpp    编译：g++ -std=c++17 which_path.cpp -o which_path */
#include <cstdio>
#include <utility>

class Tracer {
public:
    Tracer()                          { std::printf("  默认构造\n"); }
    Tracer(const Tracer &)            { std::printf("  拷贝构造\n"); }
    Tracer(Tracer &&)                 { std::printf("  移动构造\n"); }
    Tracer &operator=(const Tracer &) { std::printf("  拷贝赋值\n"); return *this; }
    Tracer &operator=(Tracer &&)      { std::printf("  移动赋值\n"); return *this; }
    ~Tracer()                         { std::printf("  析构\n"); }
};

int main() {
    std::printf("Tracer b(a);            —— 新造对象，右边是左值：\n");
    { Tracer a; Tracer b(a); }

    std::printf("Tracer c(std::move(a)); —— 新造对象，右边是右值：\n");
    { Tracer a; Tracer c(std::move(a)); }

    std::printf("b = a;                  —— 给已有对象赋值，右边是左值：\n");
    { Tracer a, b; b = a; }

    std::printf("b = std::move(a);       —— 给已有对象赋值，右边是右值：\n");
    { Tracer a, b; b = std::move(a); }
    return 0;
}
```

`实测数据`
`Text`

```text
Tracer b(a);            —— 新造对象，右边是左值：
  默认构造
  拷贝构造
  析构
  析构
Tracer c(std::move(a)); —— 新造对象，右边是右值：
  默认构造
  移动构造
  析构
  析构
b = a;                  —— 给已有对象赋值，右边是左值：
  默认构造
  默认构造
  拷贝赋值
  析构
  析构
b = std::move(a);       —— 给已有对象赋值，右边是右值：
  默认构造
  默认构造
  移动赋值
  析构
  析构
```

`实测数据`

| 写法 | 对象是新造还是已有 | 右边是左值还是右值 | 调用的函数 | 输出里应当出现哪几行 |
|---|---|---|---|---|
| `Tracer b(a);` | 新造 | 左值 | **拷贝构造** | `默认构造 → 拷贝构造 → 析构 ×2` |
| `Tracer c(std::move(a));` | 新造 | 右值 | **移动构造** | `默认构造 → 移动构造 → 析构 ×2` |
| `b = a;` | 已有 | 左值 | **拷贝赋值** | `默认构造 ×2 → 拷贝赋值 → 析构 ×2` |
| `b = std::move(a);` | 已有 | 右值 | **移动赋值** | `默认构造 ×2 → 移动赋值 → 析构 ×2` |

**每段开头的 `默认构造` 行与操作本身无关**：四个场景都先写了 `Tracer a;`，
第三、第四个场景里还有 `Tracer b;`，每造一个对象就打印一行。
**每段结尾的两行 `析构` 同样与操作本身无关**：它们来自离开作用域时被销毁的两个对象。
**析构顺序与构造顺序相反**——后造的先销毁，
因此第一个场景里先造 `a`、后造 `b`，退出作用域时 `b` 先析构、`a` 后析构
（《05-类与面向对象/04-构造与析构.md》第 3 节）。
**表中的 `×2` 表示该行连续出现两次**；去掉两头这些固定行，
**中间那一行才是四条路径各自的结果**，与表中最后一列逐行对应。

**横向是「新造还是已有」，纵向是「左值还是右值」**：
两个判断的交点就是上面那四个函数。第 4 节会讲清「右值」为什么能触发移动。

> [!IMPORTANT]
> **拷贝与移动各有两副面孔：构造与赋值。**
> 判断走哪一条，看两件事：对象是不是已经存在，右边是左值还是右值。
> **顺序不能反**：`b = a;` 无论右边是什么，都不会调用构造函数。

# 第 2 节 拷贝构造：照着一个对象再造一个

## 2.1 什么时候会被调用

`实测数据`

| 场景 | 例子 |
|---|---|
| 用同类型的对象初始化 | `A b(a);`、`A b = a;` |
| **按值传参** | `void f(A x); f(a);`——`x` 是 `a` 的拷贝 |
| **按值返回**（没有被优化掉时） | `A g(); A b = g();` |
| 放进容器（第 09 章） | `v.push_back(a);`——容器里存的是拷贝 |

`文档`

> "A non-template constructor for class X is a copy constructor if its first parameter is of type X&,
> const X&, volatile X& or const volatile X&, and either there are no other parameters or else all
> other parameters have default arguments (11.3.6)."
>
> —— N4659 §15.8.1/1

> [!WARNING]
> **按值传参与按值返回都会在背后造一个对象**——在类类型上就是调一次拷贝构造
> （《04-语法/07-函数.md》第 3 节讲过：形参就是函数自己的局部变量）。
> 形参看着只是「一个变量」，代价却是一次完整复制。
> **这也是为什么传参习惯写 `const T &`**：引用不造新对象，这一次拷贝就省下来了
> （《04-语法/03-常量与 const.md》第 5 节）。

## 2.2 编译器生成的那一份：逐成员拷贝

**不写拷贝构造时，编译器会生成一个**，做法是**逐个成员拷贝**：

`C++`

```cpp
class Buffer {
    char *data_;        // 生成的拷贝构造会把这个指针照抄一份
    int   size_;        // 这个整数也一样照抄
};
```

**问题就在「指针照抄」上**：两个对象因此指向**同一块内存**。

`实测数据`
`C++`

```cpp
/* shallow.cpp    编译：g++ -std=c++17 -fsanitize=address -g shallow.cpp -o shallow */
#include <cstdio>
#include <cstring>

class Buffer {
public:
    Buffer(int n) : data_(new char[n]), size_(n) { std::memset(data_, 0, n); }
    ~Buffer() { delete[] data_; }          // 没写拷贝构造：编译器生成的是「逐成员拷贝」
    char *data() { return data_; }
private:
    char *data_;
    int   size_;
};

int main() {
    Buffer a(8);
    std::strcpy(a.data(), "hi");
    Buffer b(a);                          // 编译器生成的拷贝构造：把指针照抄一份
    std::printf("a.data() = %p\nb.data() = %p\n",
                static_cast<void *>(a.data()), static_cast<void *>(b.data()));
    return 0;                             // 两个对象各自析构 → 同一块内存被删两次
}
```

**两个指针打印出来是同一个地址，程序在退出时崩掉。**
在 Linux 侧用 AddressSanitizer 运行，得到的报错是：

`实测数据`
`Text`

```text
ERROR: AddressSanitizer: attempting double-free on 0x502000000010 in thread T0
SUMMARY: AddressSanitizer: double-free ... in operator delete[]
```

**这叫浅拷贝（shallow copy）**：只把成员的值抄一遍，
**成员指向的东西不跟着复制一份**。

> [!CAUTION]
> **一个类只要自己管着资源（内存、文件句柄、锁、socket），
> 编译器生成的拷贝构造几乎一定是错的**——它会把「所有权」也复制一份，
> 于是两个对象都认为自己该释放同一份资源。
> **这一类类必须自己写拷贝构造**（或者明确禁止拷贝，见第 5.4 小节）。

## 2.3 深拷贝：自己写拷贝构造

**做法：给自己分配一份新的，再把内容拷过去。**

`C++`

```cpp
/* deep.cpp    编译：g++ -std=c++17 deep.cpp -o deep */
#include <cstdio>
#include <cstring>

class Buffer {
public:
    Buffer(int n) : data_(new char[n]), size_(n) { std::memset(data_, 0, n); }

    Buffer(const Buffer &other)                 // 拷贝构造：自己分配一块、再拷内容
        : data_(new char[other.size_]), size_(other.size_) {
        std::memcpy(data_, other.data_, size_);
        std::printf("  深拷贝了 %d 字节\n", size_);
    }

    Buffer &operator=(const Buffer &other) {    // 拷贝赋值
        if (this == &other) return *this;       // 自赋值
        char *fresh = new char[other.size_];    // 先分配新的，成功了再换
        std::memcpy(fresh, other.data_, other.size_);
        delete[] data_;
        data_ = fresh;
        size_ = other.size_;
        std::printf("  赋值：重新分配并拷了 %d 字节\n", other.size_);
        return *this;
    }

    ~Buffer() { delete[] data_; }
    char *data() { return data_; }
    int   size() const { return size_; }
private:
    char *data_;
    int   size_;
};

int main() {
    Buffer a(8);
    std::strcpy(a.data(), "hi");
    Buffer b(a);                 // 拷贝构造
    Buffer c(8);
    c = a;                       // 拷贝赋值
    std::printf("b = %s，c = %s\n", b.data(), c.data());
    return 0;
}
```

`实测数据`
`Text`

```text
  深拷贝了 8 字节
  赋值：重新分配并拷了 8 字节
b = hi，c = hi
```

> [!IMPORTANT]
> **深拷贝的要点是「各有一份」**：拷贝构造里 `new` 一次，析构里 `delete[]` 一次，
> 两个对象从此互不相干。
> **这对 `new` 与 `delete[]` 必须成对出现**——它就是第 04 章讲的 RAII 在拷贝场景下的样子。

## 2.4 拷贝构造的签名为什么必须是引用

**参数不能按值传递**，否则就是「为了造一个拷贝，先得造一个拷贝」：

`实测数据`
`C++`

```cpp
// ctor_by_value.cpp    编译：g++ -std=c++17 ctor_by_value.cpp -o ctor_by_value （失败）
class A {
public:
    A() {}
    A(A other) { }          // 参数按值传递：要造一个 other 就得再调拷贝构造
};
int main() { A a; A b(a); return 0; }
```

`实测数据`
`Text`

```text
error: invalid constructor; you probably meant 'A (const A&)'
```

> [!IMPORTANT]
> **拷贝构造的签名是 `A(const A &)`，参数必须是引用。**
> 「第一个参数是自己的引用」是它成立的必要条件——
> 写成按值传递的那种，只是一个普通的带参构造。
> **加 `const` 是因为拷贝不该修改源对象**，这样才能拷贝 `const` 对象与临时对象。

# 第 3 节 拷贝赋值：给已有对象换内容

## 3.1 与拷贝构造的区别

**签名里多一个 `operator=`，语义上多一层前提：左边那个对象已经有内容了。**

`实测数据`

| | 拷贝构造 | 拷贝赋值 |
|---|---|---|
| 什么时候调用 | `A b(a);`——`b` 还不存在 | `b = a;`——`b` 已经存在 |
| 要做什么 | 从零造一个 | **先处理掉自己原来的内容**，再接新的 |
| 返回值 | 没有（构造函数） | **通常返回 `*this`** |
| 要不要防自赋值 | 不用 | **要**（`b = b;`） |

`文档`

> "A class object can be copied or moved in two ways: by initialization (15.1, 11.6), including for
> function argument passing (8.2.2) and for function value return (9.6.3); and by assignment (8.18).
> Conceptually, these two operations are implemented by a copy/move constructor (15.1) and
> copy/move assignment operator (16.5.3)."
>
> —— N4659 §15.8/1

**「先处理掉自己原来的内容」是它比拷贝构造复杂的地方**：
`Buffer` 原来的那块内存必须释放，否则就泄漏；但如果先释放、后分配失败，对象就处于坏状态。
第 2.3 小节里那份 `Buffer` 的做法是**先把新的分配好，成功了再释放旧的**：

`C++`

```cpp
Buffer &operator=(const Buffer &other) {
    if (this == &other) return *this;       // ① 自赋值：直接返回
    char *fresh = new char[other.size_];    // ② 先拿新的（这一步可能抛异常）
    std::memcpy(fresh, other.data_, other.size_);
    delete[] data_;                         // ③ 到这一步才动旧的
    data_ = fresh;
    size_ = other.size_;
    return *this;                            // ④ 返回 *this
}
```

> [!TIP]
> **拷贝赋值的四步顺序不要换**：自赋值检查 → 先分配新的 → 再释放旧的 → 返回 `*this`。
> **「先分配、后释放」是关键**：万一分配失败（比如抛异常），
> 对象原来的内容还完好无损，不会被破坏。

## 3.2 为什么要返回 `*this`

**为了能连着写**（与第 02 章讲 `this` 时那条连续调用是同一个道理）：

`C++`

```cpp
a = b = c;      // 等价于 a = (b = c)，因此 b = c 必须返回 b
```

**返回类型写成 `A &` 而不是 `A`**：返回引用不产生新对象，
返回 `A` 会再调一次拷贝构造，多出一次复制。

## 3.3 三法则

**这三件事里写了一样，另外两样通常也必须写**：

`实测数据`

| 三法则 | 为什么连在一起 |
|---|---|
| 析构函数 | 自己写了析构来释放资源 |
| 拷贝构造 | 编译器生成的那个会照抄指针（浅拷贝，第 2.2 小节） |
| 拷贝赋值 | 同上，而且还要处理「自己原有的内容」 |

**三者的联系**：**在析构里释放资源，说明这个类管着资源；
既然管着资源，拷贝就不能是「照抄指针」。**
三者是一件事的三个面——**「这个类的对象拥有什么、怎么复制它、怎么还给系统」**。

> [!IMPORTANT]
> **三法则不是三条规矩，是一条判断**：
> **类里有没有「不能照抄的成员」**（指针、句柄、迭代器）。
> 有，就必须自己写这三个；没有（成员全是 `int`、`std::string` 这类会自己管好自己的类型），
> **一个都不用写**。

# 第 4 节 移动：把资源搬走，而不是复制

## 4.1 复制的代价

**拷贝一份 1 MB 的缓冲区，要分配 1 MB 再拷 1 MB**；
而如果这个缓冲区马上就会被销毁（例如它是一个临时对象），这次复制没有意义。
**移动要做的就是把「所有权」接过来，内容一个字节都不动**：

`实测数据`
`Text`

```text
拷贝一份：
  拷贝了 1048576 字节
移动一份：
  移动（搬走了指针，一个字节都没拷）
移动之后：a.size() = 0，a.data() = 0000000000000000
b.size() = 1048576，c.size() = 1048576
```

**1 MB 对 0 字节**——这就是移动的全部意义。

## 4.2 右值引用 `T&&` 与值类别

**编译器怎么知道该调拷贝还是移动**：看右边是**左值**还是**右值**
（值类别的完整讨论在《04-语法/04-表达式与运算符.md》第 2.4 小节）。

| 值类别 | 什么算 | 意味着 |
|---|---|---|
| **左值** | 有名字、能取地址的东西（`a`、`*p`、`arr[0]`） | 「它还要用」→ 只能**拷贝** |
| **右值** | 临时对象、字面量、被 `std::move` 转过的东西 | 「它马上就没用了」→ 可以**搬走** |

**`T &&` 就是「只接右值的引用」**：它让编译器能够区分
「这个对象还要用」（`const T &`，拷贝）和「这个对象可以拿走」（`T &&`，移动）。

## 4.3 移动构造与移动赋值

**写法与拷贝那两副面孔一一对应，只是参数变成右值引用，做的事变成「搬」**：

`C++`

```cpp
/* move.cpp    编译：g++ -std=c++17 move.cpp -o move */
#include <cstdio>
#include <cstring>
#include <utility>

class Buffer {
public:
    Buffer(int n) : data_(new char[n]), size_(n) { std::memset(data_, 0, n); }

    Buffer(const Buffer &other)                 // 拷贝：分配 + 拷内容
        : data_(new char[other.size_]), size_(other.size_) {
        std::memcpy(data_, other.data_, size_);
        std::printf("  拷贝了 %d 字节\n", size_);
    }

    Buffer(Buffer &&other) noexcept             // 移动：只搬指针，不碰内容
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;                  // 原对象交出去
        other.size_ = 0;
        std::printf("  移动（搬走了指针，一个字节都没拷）\n");
    }

    Buffer &operator=(Buffer &&other) noexcept {
        if (this == &other) return *this;
        delete[] data_;
        data_ = other.data_;
        size_ = other.size_;
        other.data_ = nullptr;
        other.size_ = 0;
        std::printf("  移动赋值（同样没拷内容）\n");
        return *this;
    }

    ~Buffer() { delete[] data_; }
    char *data() { return data_; }
    int   size() const { return size_; }
private:
    char *data_;
    int   size_;
};

int main() {
    Buffer a(1 << 20);                  // 1 MB
    std::strcpy(a.data(), "hi");
    std::printf("拷贝一份：\n");
    Buffer b(a);
    std::printf("移动一份：\n");
    Buffer c(std::move(a));
    std::printf("移动之后：a.size() = %d，a.data() = %p\n", a.size(),
                static_cast<void *>(a.data()));
    std::printf("b.size() = %d，c.size() = %d\n", b.size(), c.size());
    return 0;
}
```

**移动的三步**（缺一不可）：

| 步骤 | 代码 |
|---|---|
| ① 把对方的资源接过来 | `data_(other.data_)` |
| ② **把对方置空** | `other.data_ = nullptr; other.size_ = 0;` |
| ③ 不碰资源本身 | 没有 `new`、没有 `memcpy` |

> [!CAUTION]
> **移动里必须把对方置空**（`other.data_ = nullptr; other.size_ = 0;`）。
> 漏掉这一步，两个对象又都指向同一块内存——
> **移动就退化成了浅拷贝，双重释放照样发生。**

> [!TIP]
> **移动构造与移动赋值都写上 `noexcept`。**
> 移动的承诺本来就是「不会失败」；容器在扩容时**只有看到 `noexcept` 才敢用移动**
> （否则搬到一半失败就没法回退）。容器的细节见《07-标准库/B-02-std-string 与 string_view.md》章节与《09-高阶数据结构/A-01-连续存储：array 与 vector.md》第 3 节。

## 4.4 `std::move` 到底做了什么

**它什么都不搬，只做一次类型转换**——把左值变成右值，好让编译器选中移动那一版：

`实测数据`
`C++`

```cpp
/* move_is_cast.cpp    编译：g++ -std=c++17 move_is_cast.cpp -o move_is_cast */
#include <cstdio>
#include <utility>

int main() {
    int x = 5;
    int y = std::move(x);            // 对 int 来说，move 什么也没做
    std::printf("x = %d，y = %d（int 没有「搬走」这回事）\n", x, y);

    const char *s = "hello";
    const char *t = std::move(s);    // 指针同理
    std::printf("s = %s，t = %s\n", s, t);
    return 0;
}
```

`实测数据`
`Text`

```text
x = 5，y = 5（int 没有「搬走」这回事）
s = hello，t = hello
```

**`int` 搬走之后还是 5，指针也照样有效**——
因为搬不搬、怎么搬，取决于**被搬的那个类型有没有移动构造**。
`std::move` 只负责把「可以拿走」这件事**告诉编译器**。

**反过来，如果那个类型没有移动构造**，`std::move` 之后会退化成拷贝构造：

`实测数据`
`Text`

```text
HasCopyCtor（只写了拷贝构造）：
      HasCopyCtor 的拷贝构造      ← 明明给了右值，走的还是拷贝
```

## 4.5 被搬走的对象处于什么状态

**标准的要求是「有效但未指定」**：可以析构、可以赋值、可以调用不依赖具体值的方法，
**但不要假设它的内容还在**。

上面 `Buffer` 的移动把原对象置成了 `size_ = 0`、`data_ = nullptr`，
`std::string` 被搬走之后通常变成空串（《07-标准库/B-02-std-string 与 string_view.md》章节）。

> [!WARNING]
> **被 `std::move` 过的对象不要再用它的值。**
> 它还在、也还能析构，但内容已经被搬走了。
> **`std::move` 这个名字带有误导性**——它不搬东西，只是一个类型转换，
> **真正搬东西的是被调用的那个移动构造／移动赋值**。

# 第 5 节 编译器什么时候生成这六个特殊成员

## 5.1 生成规则

`实测数据`

| 特殊成员 | 未写时 | 什么情况下**不会**生成 |
|---|---|---|
| 默认构造 | 生成（如果没写任何构造函数） | 写了别的构造函数 |
| 拷贝构造 | 生成（**逐成员拷贝**） | 写了拷贝构造、拷贝赋值、移动构造、移动赋值或析构 |
| 拷贝赋值 | 生成（逐成员赋值） | 同上 |
| **移动构造** | 生成（逐成员移动） | 写了**拷贝构造、拷贝赋值、移动构造、移动赋值或析构**中的任何一个 |
| **移动赋值** | 生成（逐成员移动） | 同上 |
| 析构函数 | 生成 | 写了 |

`文档`

> "If the definition of a class X does not explicitly declare a move constructor, a non-explicit one
> will be implicitly declared as defaulted if and only if
> — X does not have a user-declared copy constructor,
> — X does not have a user-declared copy assignment operator,
> — X does not have a user-declared move assignment operator, and
> — X does not have a user-declared destructor."
>
> —— N4659 §15.8.1/8

> [!IMPORTANT]
> **规律只有一条：一旦自己声明了「对象怎么复制、怎么销毁」，
> 编译器就不再生成移动那一对**——它认为这个类可能有自己的打算。
> **这也是三法则要变成五法则的原因**（见第 5.4 小节）。

## 5.2 写了拷贝构造 → 移动构造消失

`实测数据`
`C++`

```cpp
/* hascopy.cpp    编译：g++ -std=c++17 hascopy.cpp -o hascopy */
#include <cstdio>
#include <utility>

class HasCopyCtor {
public:
    int v = 1;
    HasCopyCtor() = default;
    HasCopyCtor(const HasCopyCtor &) { std::printf("  走了拷贝构造\n"); }
};

int main() {
    HasCopyCtor a;
    HasCopyCtor b(std::move(a));     // 给了右值
    std::printf("b.v = %d\n", b.v);
    return 0;
}
```

`实测数据`
`Text`

```text
  走了拷贝构造
b.v = 1
```

**明明给的是右值，走的却是拷贝构造**——因为移动构造没有被生成。

**这不一定有害**：如果这个类没有可搬的资源（成员都是整数），
拷贝和移动本来就没有区别。**但只写移动构造、不写拷贝构造时，情况会复杂**（见第 5.4 小节）。

## 5.3 写了析构 → 移动也消失

**只写一个析构函数，移动构造与移动赋值就不再生成**：
编译器据此认定这个类管着资源，移动要由类自己决定。

`实测数据`
`C++`

```cpp
// no_move_after_dtor.cpp    编译：g++ -std=c++17 no_move_after_dtor.cpp -o no_move_after_dtor （失败）
#include <utility>

class HasDtor {
public:
    HasDtor() = default;
    ~HasDtor() {}                            // 自己写了析构
    HasDtor(const HasDtor &) = delete;       // 拷贝也删掉，只留移动这一条路
};

int main() {
    HasDtor a;
    HasDtor b(std::move(a));                 // 移动构造没有生成，只能退到拷贝，而拷贝被删了
    return 0;
}
```

`实测数据`
`Text`

```text
error: use of deleted function 'HasDtor::HasDtor(const HasDtor&)'
```

> [!WARNING]
> **自己写了析构函数，移动构造与移动赋值就都不再生成。**
> 这时 `std::move` 也起不到作用——它只是让编译器去找移动构造，而移动构造并不存在，
> 结果只能退回拷贝构造（上面报错点的正是它）。
> **需要移动时，必须自己补上移动那一对。**

## 5.4 零法则、三法则、五法则

`实测数据`

| 法则 | 内容 | 什么时候用 |
|---|---|---|
| **零法则**（Rule of Zero） | **一个都不写** | **首选**：成员都用会自己管好自己的类型 |
| 三法则（Rule of Three） | 析构、拷贝构造、拷贝赋值，写一个就写三个 | 类里自己管着资源 |
| 五法则（Rule of Five） | 再补上移动构造与移动赋值 | 同上，而且希望移动真的能省下拷贝 |

> [!TIP]
> **优先选零法则**：如果成员是 `std::string`、`std::vector`、
> 智能指针（《07-标准库/B-03-智能指针的用法.md》章节）这类**自己会管好自己**的类型，
> 那么「析构、拷贝、移动」这三件事编译器生成的版本就是对的，
> **一个都不用写，也就没有写错的机会**。
> 三法则与五法则的出现，往往意味着「类里有一个需要手工管理的资源」——
> 这时更值得考虑的是**把那个资源本身包成一个类**
> （像《05-类与面向对象/04-构造与析构.md》第 7 节的 `Buffer` 那样），让上层类回到零法则。

**`= default` 与 `= delete` 用来明确声明**：

`C++`

```cpp
class A {
public:
    A(const A &) = delete;              // 明确禁止拷贝（比如锁、文件句柄）
    A &operator=(const A &) = delete;
    A(A &&) = default;                  // 移动照旧
    A &operator=(A &&) = default;
};
```

> [!TIP]
> **「禁止拷贝、允许移动」是管理独占资源时的常见组合**——
> 资源只有一份，可以搬家，不能复制。
> 锁、文件句柄、socket 这类成员都属于这种情形。

# 第 6 节 返回值优化

## 6.1 `return local;` 什么也没调

`C++`

```cpp
/* rvo.cpp    编译：g++ -std=c++17 rvo.cpp -o rvo */
#include <cstdio>
#include <utility>

class Tracer {
public:
    Tracer()             { std::printf("  默认构造\n"); }
    Tracer(const Tracer &) { std::printf("  拷贝构造\n"); }
    Tracer(Tracer &&)      { std::printf("  移动构造\n"); }
    ~Tracer()              { std::printf("  析构\n"); }
};

Tracer make_plain() {
    Tracer local;
    return local;               // 具名返回值：NRVO
}

Tracer make_with_move() {
    Tracer local;
    return std::move(local);    // 手动 move：反而挡住了 NRVO
}

int main() {
    std::printf("return local;（不加 move）：\n");
    { Tracer t = make_plain(); }
    std::printf("return std::move(local);：\n");
    { Tracer t = make_with_move(); }
    return 0;
}
```

`实测数据`
`Text`

```text
return local;（不加 move）：
  默认构造
  析构
return std::move(local);：
  默认构造
  移动构造
  析构
  析构
```

**第一段里只有「默认构造 + 析构」**——没有拷贝，也没有移动。
**对象直接在调用方的位置上造了出来**，这就是**返回值优化**（RVO／具名时叫 NRVO）。
编译器被允许（多数情况下也被要求）省略这次构造。

## 6.2 不要写 `return std::move(x)`

**第二段多了一次移动构造**：`std::move(local)` 让 `local` 变成一个右值表达式，
**编译器因此不能再把它和返回位置当作同一个对象**，NRVO 被挡住了。

> [!IMPORTANT]
> **返回局部对象时写 `return local;`，不要写 `return std::move(local);`。**
> 后者不但没有更「高效」，反而**多一次移动**，还可能更慢。
> **能省略的那一次，只有编译器能省**。

## 6.3 关掉优化再看一次

`实测数据`
`Bash`

```bash
g++ -std=c++17 -fno-elide-constructors rvo.cpp -o rvo_noelide
./rvo_noelide
```

`实测数据`
`Text`

```text
return local;（不加 move）：
  默认构造
  移动构造
  析构
  析构
return std::move(local);：
  默认构造
  移动构造
  析构
  析构
```

> [!IMPORTANT]
> **C++11 起，返回一个局部对象时编译器会先把它当成右值**（隐式移动）——
> 因此即便优化被关掉，走的也是移动而不是拷贝。

**三层优先级**：能省略就省略（NRVO）；省略不了就移动（隐式移动）；
实在没有移动构造，才退到拷贝。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 拷贝构造 | Copy constructor | `A(const A &)`；用同类型对象**造一个新对象** |
| 移动构造 | Move constructor | `A(A &&)`；接过另一个对象的资源**造一个新对象**，通常置空来源 |
| 拷贝赋值 | Copy assignment | `A &operator=(const A &)`；给**已有对象**换内容 |
| 移动赋值 | Move assignment | `A &operator=(A &&)`；把资源搬给**已有对象** |
| 浅拷贝 | Shallow copy | 只抄成员的值；指针成员因此被两个对象共有 |
| 深拷贝 | Deep copy | 自己分配一份新资源再把内容拷过去 |
| 右值引用 | Rvalue reference | `T &&`；只接右值的引用，用来区分「可以搬走」 |
| 值类别 | Value category | 左值／右值；决定走拷贝还是移动（《04-语法/04-表达式与运算符.md》第 2.4 小节） |
| `std::move` | — | **只是一个类型转换**：把左值转成右值，本身不搬任何东西 |
| 有效但未指定 | Valid but unspecified | 被搬走的对象的状态：能析构、能赋值，但内容不可依赖 |
| 三法则 | Rule of three | 析构、拷贝构造、拷贝赋值，写一个就要写三个 |
| 五法则 | Rule of five | 再加上移动构造与移动赋值 |
| 零法则 | Rule of zero | 一个都不写；成员自己会管好自己 |
| 返回值优化 | RVO / NRVO | 省略返回时的拷贝／移动，对象直接在调用方位置上构造 |
| 隐式移动 | Implicit move | 返回局部对象时，编译器先把它当右值 |

# 附录 A 复现本章节实测

## A.1 四条路径各走哪一条

`C++`

```cpp
/* which_path.cpp    编译：g++ -std=c++17 which_path.cpp -o which_path */
#include <cstdio>
#include <utility>

class Tracer {
public:
    Tracer()                          { std::printf("  默认构造\n"); }
    Tracer(const Tracer &)            { std::printf("  拷贝构造\n"); }
    Tracer(Tracer &&)                 { std::printf("  移动构造\n"); }
    Tracer &operator=(const Tracer &) { std::printf("  拷贝赋值\n"); return *this; }
    Tracer &operator=(Tracer &&)      { std::printf("  移动赋值\n"); return *this; }
    ~Tracer()                         { std::printf("  析构\n"); }
};

int main() {
    std::printf("Tracer b(a);            —— 新造对象，右边是左值：\n");
    { Tracer a; Tracer b(a); }

    std::printf("Tracer c(std::move(a)); —— 新造对象，右边是右值：\n");
    { Tracer a; Tracer c(std::move(a)); }

    std::printf("b = a;                  —— 给已有对象赋值，右边是左值：\n");
    { Tracer a, b; b = a; }

    std::printf("b = std::move(a);       —— 给已有对象赋值，右边是右值：\n");
    { Tracer a, b; b = std::move(a); }
    return 0;
}
```

## A.3 深拷贝

`C++`

```cpp
/* deep.cpp */
#include <cstdio>
#include <cstring>

class Buffer {
public:
    Buffer(int n) : data_(new char[n]), size_(n) { std::memset(data_, 0, n); }

    Buffer(const Buffer &other)
        : data_(new char[other.size_]), size_(other.size_) {
        std::memcpy(data_, other.data_, size_);
        std::printf("  深拷贝了 %d 字节\n", size_);
    }

    Buffer &operator=(const Buffer &other) {
        if (this == &other) return *this;
        char *fresh = new char[other.size_];
        std::memcpy(fresh, other.data_, other.size_);
        delete[] data_;
        data_ = fresh;
        size_ = other.size_;
        std::printf("  赋值：重新分配并拷了 %d 字节\n", other.size_);
        return *this;
    }

    ~Buffer() { delete[] data_; }
    char *data() { return data_; }
    int   size() const { return size_; }
private:
    char *data_;
    int   size_;
};

int main() {
    Buffer a(8);
    std::strcpy(a.data(), "hi");
    Buffer b(a);
    Buffer c(8);
    c = a;
    std::printf("b = %s，c = %s\n", b.data(), c.data());
    return 0;
}
```

## A.5 移动构造与移动赋值

`C++`

```cpp
/* move.cpp */
#include <cstdio>
#include <cstring>
#include <utility>

class Buffer {
public:
    Buffer(int n) : data_(new char[n]), size_(n) { std::memset(data_, 0, n); }

    Buffer(const Buffer &other)
        : data_(new char[other.size_]), size_(other.size_) {
        std::memcpy(data_, other.data_, size_);
        std::printf("  拷贝了 %d 字节\n", size_);
    }

    Buffer(Buffer &&other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
        std::printf("  移动（搬走了指针，一个字节都没拷）\n");
    }

    Buffer &operator=(Buffer &&other) noexcept {
        if (this == &other) return *this;
        delete[] data_;
        data_ = other.data_;
        size_ = other.size_;
        other.data_ = nullptr;
        other.size_ = 0;
        std::printf("  移动赋值（同样没拷内容）\n");
        return *this;
    }

    ~Buffer() { delete[] data_; }
    char *data() { return data_; }
    int   size() const { return size_; }
private:
    char *data_;
    int   size_;
};

int main() {
    Buffer a(1 << 20);
    std::strcpy(a.data(), "hi");
    std::printf("拷贝一份：\n");
    Buffer b(a);
    std::printf("移动一份：\n");
    Buffer c(std::move(a));
    std::printf("移动之后：a.size() = %d，a.data() = %p\n", a.size(),
                static_cast<void *>(a.data()));
    std::printf("b.size() = %d，c.size() = %d\n", b.size(), c.size());
    return 0;
}
```
