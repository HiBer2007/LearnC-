**结构体可以有初值，但没有「保证」。**

`struct Stack s;` 之后 `s.top` 是多少，取决于那块内存之前被谁用过；
忘了调用初始化函数，编译器多半只在**事后提醒一句**，程序仍能正常运行。
**类把这件事变成了语言保证**：构造函数在对象出生时一定会执行，
**写不出一个「没构造过」的对象**。

**析构函数是另一半**：对象消失时该做的事（释放内存、关文件、解锁）写在一个地方，
无论对象是正常离开作用域、被 `delete`，还是在异常展开的路上消失，
它都会被调用。**这是后面 RAII 的全部基础**。

# 第 1 节 构造函数：对象一出生就得是合法的

## 1.1 没有构造函数时，忘记初始化没有任何保证

**一个类如果没有写任何构造函数，它不会比结构体多出任何保证**：

`C++`

```cpp
/* uninit_aggregate.cpp    编译：g++ -std=c++17 -O2 uninit_aggregate.cpp -o uninit_aggregate */
#include <cstdio>

struct Stack { int data[4]; int top; };   // 没有构造函数，与结构体一样

int main() {
    Stack s;                              // 忘了初始化
    std::printf("s.top = %d\n", s.top);   // top 是未初始化的值
    return 0;
}
```

**编译器是否给出警告，取决于编译选项**：

`实测数据`

| 编译选项 | 结果 |
|---|---|
| `g++ -std=c++17 -O2` | **0 条警告**，编译通过，运行结果也「正常」 |
| `g++ -std=c++17 -O2 -Wall -Wextra` | 1 条 `warning: 's.Stack::top' is used uninitialized [-Wuninitialized]` |

**加了 `-Wall` 才有提示，而且只是提示**——编译器管不了这件事，
它只能在事后说「这一处可能有问题」。**而线上的构建脚本往往不带 `-Wall`。**

**根本原因是「谁来保证初始化」这件事还没有落到语言上**：
`Stack s;` 只是划出一块内存，没有任何一步保证它进入合法状态。

> [!CAUTION]
> **读一个没有初始化的成员，拿到的是不确定的值**：编译器既不保证它是什么，
> 也不保证给出警告（上面那条实测里，不加 `-Wall` 时是 0 条）。
> **拿它做下标、长度或判断，都属于未定义行为**，出错的位置往往离这一行很远。

## 1.2 构造函数把这件事变成语言保证

**构造函数是一个与类同名的成员函数**，它**在对象创建时自动执行**：

`C++`

```cpp
/* always_ctor.cpp    编译：g++ -std=c++17 always_ctor.cpp -o always_ctor */
#include <cstdio>

class Stack {
public:
    Stack() : top_(0) { std::printf("构造了一次\n"); }   // 只要创建对象就一定执行
    void push(int v) { if (top_ < 4) data_[top_++] = v; }
private:
    int data_[4] = {0};
    int top_;
};

int main() {
    Stack a;                    // 构造
    Stack b;                    // 构造
    a.push(1);
    std::printf("a 与 b 都被构造过\n");
    return 0;
}
```

`实测数据`
`Text`

```text
构造了一次
构造了一次
a 与 b 都被构造过
```

**两条一对比，差别就清楚了**：

| | C 的结构体 | C++ 的类 |
|---|---|---|
| 创建对象 | 划出一块内存 | 划出内存**并调用构造函数** |
| 能不能忘记初始化 | 能，编译器只可能事后警告 | **不能**——没有「不调构造函数」这个选项 |
| 保证从哪来 | 写代码的人 | **语言** |

**构造函数的规则**：与类同名、**没有返回类型**、可以重载、不能手动调用
（它是「对象出生时」这件事的一部分，不是普通函数）。

## 1.3 默认构造函数与它的三个来源

**不带参数就能调用的构造函数叫默认构造函数。** 它有三个来源：

| 来源 | 写法 | 什么时候有 |
|---|---|---|
| 编译器生成 | 不用写 | 未写任何构造函数时 |
| 明确要求编译器生成 | `A() = default;` | 写了别的构造函数，但仍想要默认的 |
| 自己写 | `A() { ... }` | 需要在创建时执行一些操作 |

**最容易出错的一条规则：一旦自己写了任何一个构造函数，编译器就不再生成默认构造函数。**

`实测数据`
`C++`

```cpp
// default_ctor_gone.cpp    编译：g++ -std=c++17 default_ctor_gone.cpp -o default_ctor_gone （失败）
class A {
public:
    A(int) {}               // 一旦自己写了带参构造
};
int main() {
    A a;                    // 编译器就不再生成默认构造
    return 0;
}
```

`实测数据`
`Text`

```text
default_ctor_gone.cpp:7:7: error: no matching function for call to 'A::A()'
```

**为什么这样设计**：既然声明了「`A` 必须带一个参数才能造出来」，
编译器就认为「能凭空造一个 `A`」是不该发生的事。

> [!WARNING]
> **只要自己写了任何一个构造函数，编译器就不再生成默认构造函数**，
> 哪怕写的只是带参的那一个。
> 报错是 `no matching function for call to 'A::A()'`，说的是「找不到」，
> **因此原因要到类的构造函数列表里去找，不在调用处。**

## 1.4 `= default` 与 `= delete`

**`= default` 是「明确要求编译器生成那一份」**：

`C++`

```cpp
class A {
public:
    A() = default;          // 明确要一个默认构造
    A(int) {}
};
```

**`= delete` 是「这一份不许有」**，把某个函数从重载集合里彻底拿掉：

`实测数据`
`C++`

```cpp
// deleted_ctor.cpp    编译：g++ -std=c++17 deleted_ctor.cpp -o deleted_ctor （失败）
class NoCopy {
public:
    NoCopy() = default;
    NoCopy(const NoCopy &) = delete;    // 明确禁止拷贝
};
int main() {
    NoCopy a;
    NoCopy b(a);                        // 用了被删除的函数
    return 0;
}
```

`实测数据`
`Text`

```text
deleted_ctor.cpp:9:15: error: use of deleted function 'NoCopy::NoCopy(const NoCopy&)'
```

**报错用词是 `use of deleted function`**，而不是「没有这个函数」——
**函数在，只是被标成了删除**，因此重载决议会选中它，然后报错。
与「不写」相比，这样写更明确：不写的话，编译器可能自动生成一个。

> [!TIP]
> **该不该有这一份，明确写出来**：要编译器生成的那一份写 `= default`，
> 明确不要的写 `= delete`。
> **不写就等于把决定权交给生成规则**——读代码的人必须自己推导一遍。

## 1.5 为什么没有返回值

**构造函数没有返回值，也不能填返回类型**——连 `void` 都不写。析构函数同理。

**填上返回类型的结果**：

`实测数据`
`C++`

```cpp
// ctor_ret.cpp    编译：g++ -std=c++17 ctor_ret.cpp -o ctor_ret （失败）
class A {
public:
    void A() { }        // 构造函数不能有返回类型
};
int main() { A a; return 0; }
```

`实测数据`
`Text`

```text
ctor_ret.cpp:4:5: error: return type specification for constructor invalid
```

**析构函数一样**：

`实测数据`
`C++`

```cpp
// dtor_ret.cpp    编译：g++ -std=c++17 dtor_ret.cpp -o dtor_ret （失败）
class A {
public:
    int ~A() { return 1; }      // 析构函数也不能有返回类型
};
int main() { A a; return 0; }
```

`实测数据`
`Text`

```text
dtor_ret.cpp:4:5: error: return type specification for destructor invalid
dtor_ret.cpp:4:23: error: returning a value from a destructor
```

**为什么这样规定：因为没有人接收。**

**`Stack s;` 这条语句里没有接收返回值的位置**：
这一行既没有变量可以接住它，也没有表达式需要它——
**这一行执行完，多出来的只有一个已经构造好的 `s`。**

**它们实际由谁调用**：

`实测数据`

| 对象是什么 | 谁插入的调用 |
|---|---|
| 局部对象 | **编译器**——在 `Stack s;` 那一行直接插入调用 |
| 全局／静态对象 | **CRT**——启动时按 `.ctors` 表逐个调用（见《05-类与面向对象/00-导读：类与 OOP 是手段.md》第 5.1 小节） |
| `new` 出来的对象 | **编译器**——在 `new` 分配到的内存上插入构造调用 |

**局部对象这一条可以直接看汇编**：

`实测数据`
`C++`

```cpp
/* local_ctor.cpp    编译：g++ -std=c++17 -O0 -S local_ctor.cpp -o local_ctor.s */
struct Tracer {
    Tracer()  { }
    ~Tracer() { }
};
int main() {
    Tracer t;       // 构造与析构都由编译器在这里插入
    return 0;
}
```

`实测数据`
`Assembly`

```asm
main:
  call   __main              ; 编译器在 main 里插入的启动相关调用
  call   _ZN6TracerC1Ev      ; Tracer::Tracer()
  call   _ZN6TracerD1Ev      ; Tracer::~Tracer()
```

**三方调用者都不是「等着收返回值的表达式」**，而是「在某个时刻自动插入的调用」。
**没有接收方，语言自然不给它返回值。**

> [!IMPORTANT]
> **构造函数的调用方是编译器或 CRT，没有接收方**，因此它没有返回类型，
> **报告失败也只有一条路：抛异常。**
> **构造失败时对象不会诞生**，因此也不会有人去析构它——
> 这正是第 7 节的 `Buffer` 里要写 `if (!data_) throw ...` 的原因。

# 第 2 节 成员怎么初始化：初始化列表

## 2.1 初始化不是赋值

**构造函数有两个操作位置，它们做的事不一样**：

`C++`

```cpp
A(int x, int y)
    : x_(x), y_(y)      // ① 初始化列表：成员在这里「被构造出来」
{
    // ② 函数体：走到这里时，所有成员都已经构造完成了
    //    这里面写的每一句都是「赋值」
}
```

`实测数据`

| 位置 | 名字 | 这里发生的事 |
|---|---|---|
| 冒号到左花括号之间 | **初始化列表** | 成员**被构造**（初始化） |
| 花括号里面 | **函数体** | 成员**已经存在**，写的都是赋值 |

**还有第三个地方会给成员初值——写在成员声明后面**：

`C++`

```cpp
class A {
    int x_ = 1;                 // ③ 类内默认初始化器
};
```

**三处同时出现时，以初始化列表为准；列表里没写，才轮到类内的默认值。**

`实测数据`
`C++`

```cpp
/* two_places.cpp    编译：g++ -std=c++17 two_places.cpp -o two_places */
#include <cstdio>

class A {
public:
    A()        : x_(2) {}        // ① 初始化列表给了值
    A(int)     {}                // ② 没写列表，用类内的默认值
    int value() const { return x_; }
private:
    int x_ = 1;                  // ③ 类内默认初始化器
};

int main() {
    std::printf("A()    的 x_ = %d（列表覆盖了类内的 1）\n", A().value());
    std::printf("A(0)   的 x_ = %d（没写列表，用类内的值）\n", A(0).value());
    return 0;
}
```

`实测数据`
`Text`

```text
A()    的 x_ = 2（列表覆盖了类内的 1）
A(0)   的 x_ = 1（没写列表，用类内的值）
```

**《04-语法/05-初始化.md》第 1 节**已经说过：初始化是「创建时给定值」，赋值是「已有对象改值」。
**在构造函数里，这两者的区别是能看出来的**——因为它们会调用不同的函数。

**同一个成员，两种写法**：

`C++`

```cpp
/* initlist_vs_body.cpp    编译：g++ -std=c++17 initlist_vs_body.cpp -o initlist_vs_body */
#include <cstdio>

class Tracer {
public:
    Tracer()           { std::printf("  Tracer()  默认构造\n"); }
    Tracer(int)        { std::printf("  Tracer(int)  带参构造\n"); }
    Tracer &operator=(const Tracer &) { std::printf("  Tracer::operator=  赋值\n"); return *this; }
    ~Tracer()          { std::printf("  ~Tracer()  析构\n"); }
};

class WithList {                       // 用初始化列表
public:
    WithList() : t_(1) {}
private:
    Tracer t_;
};

class WithBody {                       // 在函数体里赋值
public:
    WithBody() { t_ = Tracer(1); }
private:
    Tracer t_;
};

int main() {
    std::printf("WithList：\n");
    { WithList a; }
    std::printf("WithBody：\n");
    { WithBody b; }
    return 0;
}
```

`实测数据`
`Text`

```text
WithList：
  Tracer(int)  带参构造
  ~Tracer()  析构
WithBody：
  Tracer()  默认构造          ← 先凭空造了一个
  Tracer(int)  带参构造        ← 又造了个临时的
  Tracer::operator=  赋值      ← 再把临时的赋给它
  ~Tracer()  析构             ← 临时对象销毁
  ~Tracer()  析构             ← 成员自己销毁
```

**同样的意图，函数体里那份多了一次默认构造、一次赋值、一次析构。**

> [!IMPORTANT]
> **构造函数体里写 `t_ = ...`，做的不是初始化，而是「先默认构造，再赋值」。**
> **初始化列表里的 `t_(1)` 才是初始化**——成员直接用这个值构造出来，一步到位。
> 这不只是快一点的问题：**有些成员根本没有「先默认构造」这一步可用**（原因见第 2.2 小节）。

**写法上的规则**：初始化列表写在参数表后面，用冒号开始、逗号分隔：

`C++`

```cpp
A(int x, int y) : x_(x), y_(y) { /* 函数体 */ }
```

**列表里也应该尽量按声明顺序写**（原因见第 2.3 小节），
有些编译器会对顺序不一致给出 `-Wreorder` 警告。

## 2.2 三类必须用列表的成员

**这三类成员在函数体里赋值是编不过的**——因为它们没有「先默认构造」这一步：

**一、`const` 成员**：

`实测数据`
`C++`

```cpp
// must_init_const.cpp    编译：g++ -std=c++17 must_init_const.cpp -o must_init_const （失败）
class A {
public:
    A() { n_ = 1; }         // const 成员不能在这里赋值
private:
    const int n_;
};
int main() { A a; return 0; }
```

`实测数据`
`Text`

```text
must_init_const.cpp:4:5: error: uninitialized const member in 'const int' [-fpermissive]
must_init_const.cpp:4:14: error: assignment of read-only member 'A::n_'
```

**二、引用成员**：

`实测数据`
`C++`

```cpp
// must_init_ref.cpp    编译：g++ -std=c++17 must_init_ref.cpp -o must_init_ref （失败）
class A {
public:
    A() { r_ = 1; }         // 引用成员不能在这里赋值
private:
    int &r_;
};
int main() { A a; return 0; }
```

`实测数据`
`Text`

```text
must_init_ref.cpp:4:5: error: uninitialized reference member in 'int&' [-fpermissive]
```

**三、没有默认构造函数的类类型成员**：

`实测数据`
`C++`

```cpp
// must_init_member.cpp    编译：g++ -std=c++17 must_init_member.cpp -o must_init_member （失败）
class NoDefault {
public:
    NoDefault(int) {}       // 只有带参构造，没有默认构造
};

class A {
public:
    A() {}                  // 想默认构造 n_，但 NoDefault 没有默认构造
private:
    NoDefault n_;
};
int main() { A a; return 0; }
```

`实测数据`
`Text`

```text
must_init_member.cpp:9:9: error: no matching function for call to 'NoDefault::NoDefault()'
```

**三处的报错都指向同一个原因**：构造函数体开始执行时，
**所有成员都已经「构造」过了**——`const` 与引用不能被「默认构造」，
没有默认构造的类类型成员也造不出来。
**因此它们只能在初始化列表里给定值**（引用还必须在列表里绑定到某个对象）。

> [!TIP]
> **把初始化列表当成默认写法。**
> 它省掉「先默认构造、再赋值、再析构临时对象」这一串动作，
> 而且是 `const` 成员、引用成员、没有默认构造的类类型成员**唯一**能给定值的地方。

## 2.3 顺序：按声明顺序，不按列表顺序

**成员的初始化顺序由声明顺序决定**，与初始化列表里的排列顺序无关：

`C++`

```cpp
/* order_by_decl.cpp    编译：g++ -std=c++17 order_by_decl.cpp -o order_by_decl */
#include <cstdio>

class Tracer {
public:
    Tracer(const char *name) : name_(name) { std::printf("构造 %s\n", name_); }
    ~Tracer() { std::printf("析构 %s\n", name_); }
private:
    const char *name_;
};

class P {
public:
    P() : b_("b_"), a_("a_") {}   // 列表里 b_ 写在前面
private:
    Tracer a_;                    // 但声明顺序是 a_ 在前
    Tracer b_;
};

int main() {
    P p;
    return 0;
}
```

`实测数据`
`Text`

```text
构造 a_
构造 b_
析构 b_
析构 a_
```

**列表里先写的 `b_`，实际后构造。** 编译器会就这种不一致给出警告：

`实测数据`
`Text`

```text
warning: 'P::y_' will be initialized after [-Wreorder]
warning:   'int P::x_' [-Wreorder]
warning:   when initialized here [-Wreorder]
```

**这条规则的后果很实际**：用前面声明的成员去初始化后面的成员，一切正常；
**反过来写，前面那个成员拿到的是「另一个成员还没初始化时的值」**：

`C++`

```cpp
class P {
public:
    P() : y_(1), x_(y_) {}      // 看起来 y_ 先有值，实际 x_ 先初始化
private:
    int x_;                     // 先初始化 → 拿的是 y_ 的未初始化值
    int y_;
};
```

**避免办法只有一条：列表里按声明顺序写。** 警告能提示，但警告要开 `-Wall` 才会出现。

> [!WARNING]
> **把列表的顺序当成初始化顺序，是一个不会报错的错误。**
> 编译器只会警告（且要开 `-Wall`），运行时也不一定立刻出错——
> 它取决于那个成员恰好拿到了什么值。

## 2.4 聚合初始化仍然可用

**没有用户提供的构造函数、没有私有成员、没有基类的类**（叫聚合）**仍能用花括号一次初始化全部成员**，
这与 C 的写法一致：

`C++`

```cpp
/* aggregate.cpp    编译：g++ -std=c++17 aggregate.cpp -o aggregate */
#include <cstdio>

struct Plain { int x, y; };             // 聚合：没有构造函数
Plain a = {1, 2};                       // 聚合初始化，C 里也是这么写

class WithCtor {                        // 自己写了构造函数 → 不再是聚合
public:
    WithCtor(int x, int y) : x_(x), y_(y) {}
    int sum() const { return x_ + y_; }
private:
    int x_, y_;
};

int main() {
    WithCtor b(1, 2);                   // 走构造函数
    std::printf("a = {%d, %d}，b.sum() = %d\n", a.x, a.y, b.sum());
    return 0;
}
```

`实测数据`
`Text`

```text
a = {1, 2}，b.sum() = 3
```

**两者的分界很清楚**：

| 类型 | 怎么创建 |
|---|---|
| 聚合（没有自己写的构造函数） | `Plain a = {1, 2};` 或 `Plain a{1, 2};` |
| 有构造函数 | `WithCtor b(1, 2);`——编译器会去找匹配的构造函数 |

**因此「给类加一个构造函数」是有代价的**：它会让这个类不再是聚合，
原来那种「一次列全所有字段」的写法就不能用了。

# 第 3 节 析构函数：对象消失时做什么

## 3.1 析构函数的调用时机

**析构函数在对象生存期结束时自动调用**，写法是在类名前面加 `~`：

`C++`

```cpp
/* dtor_order.cpp    编译：g++ -std=c++17 dtor_order.cpp -o dtor_order */
#include <cstdio>

class Tracer {
public:
    Tracer(const char *name) : name_(name) { std::printf("构造 %s\n", name_); }
    ~Tracer() { std::printf("析构 %s\n", name_); }
private:
    const char *name_;
};

Tracer g("全局对象");

int main() {
    std::printf("进入 main\n");
    Tracer a("a");
    {
        Tracer b("b");
        Tracer c("c");
    }
    std::printf("内层块结束\n");
    return 0;
}
```

`实测数据`
`Text`

```text
构造 全局对象
进入 main
构造 a
构造 b
构造 c
析构 c
析构 b
内层块结束
析构 a
析构 全局对象
```

**这段输出里有三条规则**：

| 规则 | 在这段输出里 |
|---|---|
| **局部对象在离开作用域时析构** | `b`、`c` 在 `}` 处消失 |
| **同一作用域内按构造的逆序析构** | 先 `c` 后 `b`（构造时是先 `b` 后 `c`） |
| **全局对象最后析构** | `全局对象` 在 `main` 返回之后才消失 |

**「逆序」的道理与栈一样**：后构造的对象可能用到先构造的对象，
因此必须后销毁。生存期本身的规则见《04-语法/11-作用域、生存期与链接.md》第 3 节。

**析构函数还有三条规定**：不能有参数、**没有返回类型**（理由与构造函数相同，第 1.5 小节）、**一个类只能有一个**——
因为它不带参数，重载也没有意义（没有参数可以区分）。

## 3.2 异常路径上也会析构

**这是析构函数最重要的性质**，也是 RAII 能成立的原因：

`C++`

```cpp
/* dtor_on_throw.cpp    编译：g++ -std=c++17 dtor_on_throw.cpp -o dtor_on_throw */
#include <cstdio>

class Tracer {
public:
    Tracer(const char *name) : name_(name) { std::printf("构造 %s\n", name_); }
    ~Tracer() { std::printf("析构 %s\n", name_); }
private:
    const char *name_;
};

void work() {
    Tracer t("work 里的对象");
    std::printf("work 里抛异常之前\n");
    throw 1;                       // 抛出去之后，t 的析构仍会执行
}

int main() {
    try {
        work();
    } catch (int) {
        std::printf("接住了异常\n");
    }
    return 0;
}
```

`实测数据`
`Text`

```text
构造 work 里的对象
work 里抛异常之前
析构 work 里的对象        ← 异常展开的路上被调用
接住了异常
```

**`throw` 之后 `work` 没有正常返回，但 `t` 仍然被析构了。**
这个「顺着调用栈往回退、把已经构造好的对象逐个析构」的过程叫**栈展开**
（见《04-语法/13-异常.md》第 2 节）。

> [!IMPORTANT]
> **析构函数一定会被调用**——正常离开作用域、`delete`、异常展开，三种情况都算。
> **因此「必须成对做的事」可以交给它**：申请了就在析构里释放，加了锁就在析构里解锁。
> **这是 RAII 的全部机制**；完整讨论见第 05 章。

> [!CAUTION]
> **析构函数里抛异常，程序会直接终止（`std::terminate`）。**
> 异常正在展开时又抛出一个，已经没有第二个异常能承载它，
> 因此这条没有补救的余地。**析构里发现的错误只能记下来，不能往外抛。**

# 第 4 节 构造与析构的访问权限

**前面几节的构造函数与析构函数都写在 `public` 里。**
**把它们挪到 `private` 或 `protected`，改变的不是「这个函数能不能用」，
而是「谁有资格创建这个对象、谁有资格销毁它」。**

`实测数据`

| 写在哪 | 谁能创建、谁能销毁 |
|---|---|
| `public`（前面几节的写法） | 任何人 |
| `private` | **只有这个类自己**（以及它的友元） |
| `protected` | 这个类自己，**以及它的派生类** |

**换一种说法**：构造函数决定「来源」，析构函数决定「去处」。
把它们的权限收紧，就是在给这个类的对象**规定唯一合法的来源与去处**。

## 4.1 私有构造函数：控制「怎么造出来」

**在类外直接定义对象会编译失败**：

`实测数据`
`C++`

```cpp
// private_ctor.cpp    编译：g++ -std=c++17 private_ctor.cpp -o private_ctor （失败）
class A {
public:
    int value() const { return 1; }
private:
    A() {}                  // 构造函数私有
};
int main() {
    A a;                    // 外面造不出来
    return a.value();
}
```

`实测数据`
`Text`

```text
private_ctor.cpp:9:7: error: 'A::A()' is private within this context
```

**但类自己的成员函数可以调用它**——于是「创建」这件事被收进了类里，
**造法由这个类决定**。三种常见用法：

**一、具名构造**：几个静态函数，各说清一种造法。

`C++`

```cpp
/* named_ctor.cpp    编译：g++ -std=c++17 named_ctor.cpp -o named_ctor */
#include <cmath>
#include <cstdio>

class Point {
public:
    // 两个「具名构造」：名字说清了是哪种造法
    static Point fromCartesian(double x, double y) { return Point(x, y); }
    static Point fromPolar(double r, double theta) {
        return Point(r * std::cos(theta), r * std::sin(theta));
    }
    void show() const { std::printf("(%.3f, %.3f)\n", x_, y_); }
private:
    Point(double x, double y) : x_(x), y_(y) {}     // 只允许类自己调用
    double x_, y_;
};

int main() {
    Point::fromCartesian(3, 4).show();
    Point::fromPolar(2, 0).show();
    return 0;
}
```

`实测数据`
`Text`

```text
(3.000, 4.000)
(2.000, 0.000)
```

**在类外写 `Point p(1, 2);` 是编不过的**（与上面同一个错误）；
只能走 `fromCartesian` 或 `fromPolar`——**调用处的名字已经把意图写清楚了**。

**二、单例**：整个程序只允许一个对象。

`C++`

```cpp
/* singleton.cpp    编译：g++ -std=c++17 singleton.cpp -o singleton */
#include <cstdio>

class Config {
public:
    static Config &instance() {
        static Config only;             // 只能在这里诞生一次
        return only;
    }
    int value() const { return v_; }
private:
    Config() = default;                 // 外面造不出来
    int v_ = 42;
};

int main() {
    std::printf("value = %d\n", Config::instance().value());
    return 0;
}
```

`实测数据`
`Text`

```text
value = 42
```

**「只能有一个」这件事靠的不是约定，而是私有构造函数**：
类外没有任何语法能再创建一个对象。

**三、纯静态工具类**：这个类本来就不该有对象，直接禁止构造即可——
写 `A() = delete;`，或把构造函数放进 `private`（见第 4.4 小节的对照）。

## 4.2 私有析构函数：控制「怎么销毁」

**构造函数管来源，析构函数管去处。** 析构私有之后，
**栈上无法创建对象**——离开作用域要析构，而类外没有这个权限：

`实测数据`
`C++`

```cpp
// private_dtor.cpp    编译：g++ -std=c++17 private_dtor.cpp -o private_dtor （失败）
class A {
public:
    A() {}
private:
    ~A() {}                 // 析构函数私有
};
int main() {
    A a;                    // 离开作用域要析构，但没有权限
    return 0;
}
```

`实测数据`
`Text`

```text
private_dtor.cpp:9:7: error: 'A::~A()' is private within this context
```

**这类对象只能由类自己销毁**，因此常见于「引用计数」的对象：
由最后一个持有者负责删除，这件事交给类的成员函数完成（内部 `delete this`），
**类外始终拿不到「删掉它」的权限**。

> [!WARNING]
> **析构私有之后，栈上创建这条路就断了**（编译器必须在这里插入析构调用）。
> 这类对象只能用 `new` 创建，而且必须由类自己提供释放的入口——
> **一旦没有提供，对象就会泄漏**。

## 4.3 protected 构造与析构：只给派生类用

`protected` 的含义是「自己与派生类可以用」，用在构造函数上就是
**「这个类不能被直接创建，只能被继承」**：

`实测数据`
`C++`

```cpp
// protected_ctor.cpp    编译：g++ -std=c++17 protected_ctor.cpp -o protected_ctor （失败）
class Base {
protected:
    Base() {}               // 只有派生类能调用
};
class Derived : public Base {
public:
    Derived() : Base() {}   // 派生类可以
};
int main() {
    Derived d;              // 派生类对象可以
    Base b;                 // 基类对象不行
    return 0;
}
```

`实测数据`
`Text`

```text
protected_ctor.cpp:12:10: error: 'Base::Base()' is protected within this context
```

**两个典型用途**：

| 用途 | 怎么写 |
|---|---|
| **抽象基类**：基类本身不该有对象，只该被继承 | 构造函数放 `protected`（或写成纯虚函数，第 07 章） |
| **禁止通过基类指针 `delete`** | 析构函数放 `protected` 且不写 `virtual` |

**第二条与虚析构正好相反**（对照见第 07 章）：
**基类析构写成 `public virtual` 是为了让「通过基类指针 delete」正确工作；
写成 `protected` 非虚，是为了让这条路根本编不过。**

## 4.4 与 `= delete` 的对照

**C++11 起多了 `= delete`，它比把函数塞进 `private` 更直接。**
两者的差别只有一条，但很关键——**类自己还能不能用**：

`实测数据`

| 写法 | 类外能否创建 | **类自己的成员函数能否创建** | 报错原文 |
|---|---|---|---|
| 构造函数放 `private` | 不能 | **能** | `'A::A()' is private within this context` |
| `A() = delete;` | 不能 | **不能** | `use of deleted function 'A::A()'` |

**后一种写法的实测**：

`实测数据`
`C++`

```cpp
// delete_vs_private.cpp    编译：g++ -std=c++17 delete_vs_private.cpp -o delete_vs_private （失败）
class A {
public:
    A() = delete;                       // 任何调用都不允许，包括类自己
    static A make() { return A(); }     // 想在这里造一个
};
int main() { return 0; }
```

`实测数据`
`Text`

```text
delete_vs_private.cpp:5:32: error: use of deleted function 'A::A()'
```

> [!WARNING]
> **两者的差别只有一条：类自己还能不能调用。**
> 私有构造对类的成员函数仍然开放，工厂与单例正是靠这一点；
> `= delete` 连类自己也被挡住——**上面那条报错就来自 `A::make()` 内部**。
> 想让工厂还能造出对象，却用了 `= delete`，编译会立即失败。

**同一个 `make()`，换成私有构造就正常**：

`实测数据`
`C++`

```cpp
/* private_ok.cpp    编译：g++ -std=c++17 private_ok.cpp -o private_ok */
#include <cstdio>

class A {
public:
    static A make() { return A(); }     // 私有构造：类自己能调用
    int value() const { return 7; }
private:
    A() {}                              // 类外调用是错误，类内调用正常
};

int main() {
    std::printf("value = %d\n", A::make().value());
    return 0;
}
```

`实测数据`
`Text`

```text
value = 7
```

**因此选择规则如下**：

| 想做的事 | 用哪个 |
|---|---|
| **控制造法**（只能从工厂、单例、具名构造出来） | `private` —— 类自己还要用 |
| **彻底禁止**（这个类根本不该有对象） | `= delete` —— 任何地方都不能用 |

> [!IMPORTANT]
> **访问权限写在构造函数与析构函数上时，管的是「谁能创建、谁能销毁」。**
> **这是接口设计的一部分，不是封装之外的装饰**：
> 一个只能由工厂创建的类，类外的代码就没有办法绕过工厂里的检查；
> 一个析构私有的类，任何类外代码都无法在类未许可的位置删除它。

# 第 5 节 动态对象

## 5.1 `new` 与 `delete` 会调用构造与析构

`new` 做两件事：**申请内存 + 调用构造函数**；`delete` 也做两件事：
**调用析构函数 + 释放内存**。而 `malloc`/`free` 只做内存这一半：

`C++`

```cpp
/* new_vs_malloc.cpp    编译：g++ -std=c++17 new_vs_malloc.cpp -o new_vs_malloc */
#include <cstdio>
#include <cstdlib>

class Tracer {
public:
    Tracer()  { std::printf("  构造\n"); }
    ~Tracer() { std::printf("  析构\n"); }
};

int main() {
    std::printf("用 new / delete：\n");
    Tracer *p = new Tracer;
    delete p;

    std::printf("用 malloc / free：\n");
    Tracer *q = static_cast<Tracer *>(std::malloc(sizeof(Tracer)));
    std::free(q);
    std::printf("  （构造与析构都没有发生）\n");
    return 0;
}
```

`实测数据`
`Text`

```text
用 new / delete：
  构造
  析构
用 malloc / free：
  （构造与析构都没有发生）
```

> [!CAUTION]
> **不要用 `malloc` 造 C++ 对象**：内存有了，对象却没有被构造，
> 拿到的指针指向的不是一个合法的对象，**用它的成员就是未定义行为**，
> 析构也不会发生——这与第 1.1 小节所述的问题属于同一类。
> 反过来，`free` 也不能释放 `new` 出来的对象：两套分配与释放不能交叉。

## 5.2 `new[]` 必须配 `delete[]`

**数组形式的 `new` 要用数组形式的 `delete`**，两者形式不匹配是未定义行为。
编译器不会为此报错，程序可能看起来正常——**这正是它危险的地方**：

`实测数据`
`Bash`

```bash
g++ -std=c++17 -fsanitize=address -g mismatch.cpp -o mismatch
./mismatch
```

`实测数据`
`Text`

```text
ERROR: AddressSanitizer: attempting free on address which was not malloc()-ed
SUMMARY: AddressSanitizer: bad-free
```

**AddressSanitizer 能抓到它**（`bad-free`）。
**这套工具在 MinGW 上不可用**，需要在 Linux 侧跑，
理由与《04-语法/08-数组、指针与引用.md》第 5.4 小节所述一致。

> [!CAUTION]
> **`new[]` 与 `delete[]`、`new` 与 `delete`，形式必须一一对应。**
> 形式不匹配是未定义行为：编译器不报错，程序可能看起来完全正常，
> **上面那条 `bad-free` 就是 AddressSanitizer 捕获它时给出的报告。**

## 5.3 忘记 `delete` 会造成泄漏

`new` 出来的对象**不会自己消失**——没有作用域负责它的生存期，只能手动 `delete`：

`实测数据`
`Bash`

```bash
g++ -std=c++17 -fsanitize=address -g leak.cpp -o leak
./leak
```

`实测数据`
`Text`

```text
ERROR: LeakSanitizer: detected memory leaks
Direct leak of 1 byte(s) in 1 object(s) allocated from:
SUMMARY: AddressSanitizer: 1 byte(s) leaked in 1 allocation(s).
```

**析构函数没有被调用**——因此它该释放的资源（内存、文件、锁）全都没释放。
这就是「内存泄漏」的完整含义：**不是内存丢失，而是该做的释放没有执行**。

> [!CAUTION]
> **`new` 与 `delete` 必须成对，而且要在所有路径上成对**——
> 包括提前 `return`、`break`、以及抛异常的路径。
> **依靠人工记住所有这些路径并不现实**，因此有了 RAII（第 05 章）与智能指针。
> 在此之前，凡是能放在栈上的对象都不要用 `new`。

# 第 6 节 编译器自动生成的成员函数

**除了默认构造函数，编译器还会按需生成另外三个**，规则如下：

`实测数据`

| 成员函数 | 什么时候编译器会生成 | 什么时候不生成 |
|---|---|---|
| 默认构造函数 | 未写任何构造函数时 | 已写任何一个构造函数 |
| 析构函数 | 未写时 | 已写时 |
| 拷贝构造函数 | 未写、也未禁止时 | 已写，或用了 `= delete` |
| 拷贝赋值运算符 | 同上 | 同上 |

**这几个函数都是「按成员逐个处理」的**：
默认构造会逐个默认构造成员，析构会逐个析构成员，拷贝会逐个拷贝成员。
**因此成员是什么样，这个类就是什么样**。

> [!IMPORTANT]
> **三法则**：需要自己写析构函数、拷贝构造、拷贝赋值中的任何一个，
> 通常另外两个也要写。**原因与具体写法在第 04 章。**

# 第 7 节 RAII 的雏形

**把「必须成对的事」放进构造与析构，就得到一个 RAII 包装**：

`C++`

```cpp
/* raii_buffer.cpp    编译：g++ -std=c++17 raii_buffer.cpp -o raii_buffer */
#include <cstdio>
#include <cstdlib>
#include <cstring>

class Buffer {
public:
    Buffer(int n) : data_(static_cast<char *>(std::malloc(n))), size_(n) {
        if (!data_) throw "内存不够";        // 构造失败只能抛出去，见第 1.5 小节
        std::memset(data_, 0, size_);
    }
    ~Buffer() { std::free(data_); }          // 无论怎么离开作用域，都会执行

    Buffer(const Buffer &) = delete;         // 先禁止拷贝：理由见第 04 章
    Buffer &operator=(const Buffer &) = delete;

    char *data() { return data_; }
    int   size() const { return size_; }

private:
    char *data_;
    int   size_;
};

int main() {
    Buffer b(16);
    std::strcpy(b.data(), "hello");
    std::printf("b = %s（%d 字节）\n", b.data(), b.size());
    return 0;                                // 离开作用域 → 析构 → free
}
```

`实测数据`
`Text`

```text
b = hello（16 字节）
```

**这个类只有二十行，但它做到了一件 C 做不到的事**：
**调用方不需要记得释放**——没有 `free`，也没有 `delete`。
把 `malloc` 换成文件句柄、锁、socket，写法完全一样。

**RAII 的完整讨论在第 05 章**；`Buffer` 里那两行 `= delete` 的理由在第 04 章。

> [!TIP]
> **资源成对获取与释放**：在构造函数里申请，就在析构函数里释放，
> 两件事写在同一个类里，**调用方不必记住任何事**，异常路径也自动覆盖。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 构造函数 | Constructor | 与类同名、**没有返回类型**的成员函数；对象创建时由编译器或 CRT 自动调用 |
| 默认构造函数 | Default constructor | 不带参数就能调用的构造函数 |
| 成员初始化列表 | Member initializer list | 冒号到左花括号之间那一段；**真正做初始化的地方** |
| 类内默认初始化器 | Default member initializer | 写在成员声明后面的初值（`int x_ = 1;`）；优先级低于初始化列表 |
| 析构函数 | Destructor | 名字前加 `~`；对象生存期结束时自动调用；没有返回类型、不能有参数、不能重载 |
| `= default` | — | 明确要求编译器生成那一份 |
| `= delete` | — | 明确禁止使用那一份；调用时报 `use of deleted function` |
| 聚合 | Aggregate | 没有用户提供的构造函数、没有私有成员、没有基类的类；可用花括号一次初始化 |
| 栈展开 | Stack unwinding | 抛异常时沿调用栈回退并析构已构造对象的过程 |
| 三法则 | Rule of three | 析构、拷贝构造、拷贝赋值，写一个通常就要写三个 |
| 具名构造 | Named constructor | 把构造函数放 `private`，用几个静态函数各表示一种造法 |
| 单例 | Singleton | 只允许存在一个对象；靠私有构造函数保证 |
| RAII | Resource Acquisition Is Initialization | 构造时获取资源、析构时释放 |
| `-Wreorder` | — | 初始化列表顺序与声明顺序不一致时的警告 |
