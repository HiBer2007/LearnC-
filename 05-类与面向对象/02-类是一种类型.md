**第 01 章把名字分好了组，也讲清了 `::` 读作「的」。这一章把这条线索用到数据上：
把数据与操作它的函数捆在一起，就是一个类。**

**导读说清了「类与 OOP 是手段」；本章节说清这个手段在语言里到底是什么。**

答案分为三个层次：

- **类是一种类型**——与 `int`、指针、数组处在同一个位置上；
- **类把数据与操作它的函数写在了一起**——这是它相对结构体唯一的新东西；
- **对象是这种类型的一个实例**——在内存里就是一块数据。

**三层里最容易忽略的是第一层。** 把它当类型看，很多写法就是自然的：
类能有 `const` 对象、能当模板参数、能重载运算符。
**第二层则是这一板块全部内容的出发点**：数据与操作写在一起之后，
才谈得上「谁能访问」「谁构造」「谁清理」「谁派生」。

# 第 1 节 类与结构体只差一条规定

## 1.1 类把数据与操作写在了一起

**以栈为例**：一组数据（元素与栈顶位置），一组操作（入栈、出栈），
**两者必须保持一致**。用类写出来是这样：

`C++`

```cpp
/* stack_cpp.cpp    编译：g++ -std=c++17 stack_cpp.cpp -o stack_cpp */
#include <cstdio>

class Stack {
public:                                 // 谁能用这些
    void push(int v) { if (top_ < CAP) data_[top_++] = v; }
    bool pop(int &out) {
        if (top_ <= 0) return false;
        out = data_[--top_];
        return true;
    }
    int size() const { return top_; }
private:                                // 谁不能用这些
    static constexpr int CAP = 4;       // 类内常量，只在这个类里有意义
    int data_[CAP] = {0};
    int top_ = 0;
};

int main() {
    Stack s;
    s.push(1);
    s.push(2);
    s.push(3);

    int v = 0;
    while (s.pop(v)) std::printf("%d ", v);
    std::printf("| size = %d\n", s.size());
    return 0;
}
```

`实测数据`
`Text`

```text
3 2 1 | size = 0
```

**这份代码与「结构体加一组自由函数」的写法相比，多出来的只有一件事**：
`data_` 与 `top_` 写在 `private` 后面，**只有 `Stack` 自己的成员函数能访问它们**；
外面拿到的入口就是 `push`、`pop`、`size` 三个。

`sizeof(Stack)` 与「装同样数据的结构体」测出来一样
（《05-类与面向对象/00-导读：类与 OOP 是手段.md》第 3.2 小节实测过：类里只有数据成员占空间），成员函数也不在对象里。

> [!IMPORTANT]
> **类没有引入新的运行期机制，它改变的是写法与权限。**
> 数据进 `private`、成员函数写进类里，都不会让程序在运行时多做一件事。

## 1.2 唯一区别：默认访问权限

`class` 与 `struct` 在 C++ 里的**唯一区别**是：

`实测数据`

| 写法 | 成员默认的访问权限 | 继承时的默认权限 |
|---|---|---|
| `struct S { ... };` | `public` | `public` |
| `class  C { ... };` | `private` | `private` |

`文档`

> "Members of a class defined with the keyword class are private by default.
> Members of a class defined with the keywords struct or union are public by default."
>
> "In the absence of an access-specifier for a base class, public is assumed when
> the derived class is defined with the class-key struct and private is assumed
> when the class is defined with the class-key class."
>
> —— N4659 §14/3、§14.2/2

**除了这一条，它们在语言里完全等价**——都能有成员函数、构造析构、继承、模板。
这一点可以直接验证：

`实测数据`
`C++`

```cpp
// default_access.cpp    编译：g++ -std=c++17 default_access.cpp -o default_access （失败）
struct S { int x; };        // struct 的成员默认 public
class  C { int x; };        // class  的成员默认 private

int main() {
    S s;
    s.x = 1;                // 可以
    C c;
    c.x = 1;                // 不行
    return 0;
}
```

`实测数据`
`Text`

```text
default_access.cpp:9:7: error: 'int C::x' is private within this context
```

**报错的行是 `c.x = 1;`，而不是 `class C` 那一行**——
编译器是在**使用成员**的时候才检查访问权限。

**惯例上这样分**：

| 用哪个 | 适用场合 |
|---|---|
| `struct` | 只是把几个数据装在一起，没有要守住的约束（坐标、配置项） |
| `class` | 有内部状态必须保持一致，或者有接口要给外面用 |

**《04-语法/09-结构体、联合体与 enum.md》第 1 节**讲结构体时用的是 C 的视角；
在 C++ 里，该结构体只要把 `struct` 换成 `class`，就立刻有了访问控制。

## 1.3 三种访问权限

`实测数据`

| 关键字 | 谁能访问 | 常见用途 |
|---|---|---|
| `public` | 任何人 | 给外面用的接口 |
| `private` | **只有这个类自己的成员函数**（以及友元） | 数据、内部辅助函数 |
| `protected` | 这个类自己，以及它的派生类 | 留给继承（第 07 章展开） |

`文档`

> "A member of a class can be
> —(1.1) private; that is, its name can be used only by members and friends of the
> class in which it is declared.
> —(1.2) protected; that is, its name can be used only by members and friends of the
> class in which it is declared, by classes derived from that class, and by their
> friends (see 14.4).
> —(1.3) public; that is, its name can be used anywhere without access restriction."
>
> —— N4659 §14/1

**访问控制的作用范围是「类」，不是「对象」。**
同一个类的两个对象之间，可以互相访问私有成员：

`C++`

```cpp
/* same_class_access.cpp    编译：g++ -std=c++17 same_class_access.cpp -o same_class_access */
#include <cstdio>

class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}
    int diff(const Point &other) const {
        return x_ - other.x_;           // 访问的是「另一个对象」的私有成员
    }
private:
    int x_, y_;
};

int main() {
    Point a(5, 1), b(2, 1);
    std::printf("a.diff(b) = %d\n", a.diff(b));
    return 0;
}
```

`实测数据`
`Text`

```text
a.diff(b) = 3
```

> [!IMPORTANT]
> **访问控制的单位是类，不是对象。**
> `private` 的含义是「只有 `Point` 的成员函数能访问 `Point` 的私有成员」，
> 而不是「只有自己才能访问自己的成员」。
> **这一条使拷贝构造、比较、相加这些操作可以直接实现**——
> 它们本来就要访问另一个对象的内部。

## 1.4 成员函数的两种写法

**成员函数可以定义在类里，也可以只声明、把定义放到类外**：
`B::f` 读作「**`B` 的 `f`**」——`::` 是「属于谁」的标记，
完整的用法（命名空间、`using`、开头的 `::`）见《05-类与面向对象/01-命名空间与 using.md》第 2 节。

`C++`

```cpp
/* member_def.cpp    编译：g++ -std=c++17 member_def.cpp -o member_def */
#include <cstdio>

class A {
public:
    int f(int x) { return x + 1; }      // 定义在类里
};

class B {
public:
    int f(int x);                       // 只声明
};

int B::f(int x) { return x + 1; }       // 定义在类外，用 B:: 指明属于谁

int main() {
    A a;
    B b;
    std::printf("%d %d\n", a.f(1), b.f(1));
    return 0;
}
```

**两种写法生成的代码相同**，但这个结论有一个前提。

**类内定义的成员函数隐含 `inline`**，因此**没有调用它时，编译器不会生成这份代码**：

`实测数据`
`C++`

```cpp
// e3a_unused.cpp    编译：g++ -std=c++17 -O0 -S e3a_unused.cpp -o e3a.s
struct InClass  { int f(int x) { return x + 1; } };   // 类内定义
struct OutClass { int f(int x); };                    // 类外定义
int OutClass::f(int x) { return x + 1; }
```

`实测数据`
`Text`

```text
InClass::f  有没有生成代码：没有
OutClass::f 有没有生成代码：有
```

**两个类里写的是同一个函数，类内定义的那个没有被调用，目标文件里就没有它。**
这正是 `inline` 的语义：**允许多处出现同名定义，而用不到就不生成**。

**一旦调用，两者的指令序列相同**：

`实测数据`
`C++`

```cpp
// e3b_used.cpp    编译：g++ -std=c++17 -O0 -S e3b_used.cpp -o e3b.s
struct InClass  { int f(int x) { return x + 1; } };
struct OutClass { int f(int x); };
int OutClass::f(int x) { return x + 1; }

int use_in(int v)  { InClass  a; return a.f(v); }
int use_out(int v) { OutClass b; return b.f(v); }
```

`实测数据`
`Assembly`

```asm
InClass::f(int)                      OutClass::f(int)
  push   %rbp                          push   %rbp
  mov    %rsp,%rbp                     mov    %rsp,%rbp
  mov    %rcx,0x10(%rbp)               mov    %rcx,0x10(%rbp)
  mov    %edx,0x18(%rbp)               mov    %edx,0x18(%rbp)
  mov    0x18(%rbp),%eax               mov    0x18(%rbp),%eax
  add    $0x1,%eax                     add    $0x1,%eax
  pop    %rbp                          pop    %rbp
  ret                                  ret
```

**逐条相同**，类内定义那份后面多出一串 `nop`，
那是编译器为下一个函数做的对齐填充，与函数本身无关。

> [!TIP]
> **写类内还是类外，只看可读性，不看性能**：
> 短函数写在类里（读者一眼看到实现），长函数写在类外（类定义保持清爽）。

# 第 2 节 `this`：隐藏的第一参数

## 2.1 隐藏的第一个参数

`s.push(1)` 里，`push` 收到的实参是 `1`；它还需要知道这个调用发生在**哪个**对象上。

**成员函数有一个隐藏参数，就是对象的地址，这个参数的名字叫 `this`。**

**换一个说法：「成员函数」是一种语法糖**——
糖纸下面是「第一个参数是对象指针的普通函数」，
`this` 就是这个参数的名字。这在《04-语法/01-一些基础概念.md》第 1 节
讲语法糖时已经给出，这里是它的第一个实例。

`实测数据`

| 糖纸（成员函数） | 糖纸下面（自由函数） |
|---|---|
| `void Stack::push(int v)` | `void push(Stack *s, int v)` |
| `int Stack::size() const` | `int size(const Stack *s)` |
| `s.push(1)` | `push(&s, 1)` |
| 函数体里的 `this` | 这个隐藏参数本身 |
| `this->top_` | `s->top_` |

`文档`

> "... a member function is considered to have an extra parameter, called the implicit
> object parameter, which represents the object for which the member function has been
> called."
>
> "... the convention is that the implicit object parameter, if present, is always the
> first parameter and the implied object argument, if present, is always the first
> argument."
>
> —— N4659 §16.3.1/2、§16.3.1/3

**这一对应关系不是比喻**：把成员函数和一个等价的自由函数放在一起编译，
它们的函数体逐条相同：

`C++`

```cpp
/* e4_this.cpp    编译：g++ -std=c++17 -O0 -S e4_this.cpp -o e4.s */
struct S {
    int x;
    int get() const { return x; }          // 成员函数
};
int free_get(const S *s) { return s->x; }  // 等价的自由函数

int call_member(const S *p) { return p->get(); }
int call_free(const S *p)   { return free_get(p); }
```

`实测数据`
`Assembly`

```asm
S::get() const                       free_get(S const*)
  push   %rbp                          push   %rbp
  mov    %rsp,%rbp                     mov    %rsp,%rbp
  mov    %rcx,0x10(%rbp)               mov    %rcx,0x10(%rbp)
  mov    0x10(%rbp),%rax               mov    0x10(%rbp),%rax
  mov    (%rax),%eax                   mov    (%rax),%eax
  pop    %rbp                          pop    %rbp
  ret                                  ret
```

**`%rcx` 就是第一个参数的位置**：在成员函数里它是 `this`，在自由函数里它是 `s`。

**调用处的机器码也相同**：把 `s.push(v)` 与等价的 `push_free(s, v)` 各写一个包装函数，
两份函数的机器码逐条相同：

`C++`

```cpp
/* sugar_call.cpp    编译：g++ -std=c++17 -O2 -c sugar_call.cpp -o sugar_call.o */
struct Stack {
    int top = 0;
    void push(int v) { top += v; }                   // 成员函数
};
void push_free(Stack *s, int v) { s->top += v; }     // 等价的自由函数

void use_member(Stack *s, int v) { s->push(v); }     // 调用成员函数
void use_free(Stack *s, int v)   { push_free(s, v); } // 调用自由函数
```

`实测数据`
`Assembly`

```asm
use_member(Stack*, int)        use_free(Stack*, int)
  add    %edx,(%rcx)             add    %edx,(%rcx)
  ret                            ret
```

**`s.push(v)` 与 `push_free(s, v)` 的编译结果相同**——
编译器只是自动补上了这个参数。

`实测数据`
`Assembly`

```asm
call_member(S const*)                call_free(S const*)
  push   %rbp                          push   %rbp
  mov    %rsp,%rbp                     mov    %rsp,%rbp
  sub    $0x20,%rsp                    sub    $0x20,%rsp
  mov    %rcx,0x10(%rbp)               mov    %rcx,0x10(%rbp)
  mov    0x10(%rbp),%rax               mov    0x10(%rbp),%rax
  mov    %rax,%rcx                     mov    %rax,%rcx
  call   S::get() const                call   free_get(S const*)
  add    $0x20,%rsp                    add    $0x20,%rsp
  pop    %rbp                          pop    %rbp
  ret                                  ret
```

**两条推论**：

| 推论 | 原因 |
|---|---|
| **成员函数不占对象的空间** | 它不在对象里，对象只存数据 |
| **调用成员函数不比调用自由函数慢** | 传 `this` 与传第一个参数是同一件事 |

> [!WARNING]
> **「面向对象有性能代价」这句话对普通成员函数不成立**。
> 传 `this` 与传第一个参数是同一件事，调用不比自由函数慢；
> 真正有代价的是虚函数，因为它需要在对象里存一个指针（第 08 章）。

## 2.2 `this` 的三个用法

**一、返回 `*this`，支持连续调用**：

`C++`

```cpp
/* chain.cpp    编译：g++ -std=c++17 chain.cpp -o chain */
#include <cstdio>

class Builder {
public:
    Builder &add(int v) { sum_ += v; return *this; }   // 返回自己
    int sum() const { return sum_; }
private:
    int sum_ = 0;
};

int main() {
    Builder b;
    b.add(1).add(2).add(3);                            // 连续调用
    std::printf("sum = %d\n", b.sum());
    return 0;
}
```

`实测数据`
`Text`

```text
sum = 6
```

**二、区分同名的形参与成员**：

`C++`

```cpp
/* this_disambiguate.cpp    编译：g++ -std=c++17 this_disambiguate.cpp -o this_disambiguate */
#include <cstdio>

class P {
public:
    void set(int x) {
        this->x = x;        // 左边是成员，右边是形参
    }
    int get() const { return x; }
private:
    int x = 0;
};

int main() {
    P p;
    p.set(7);
    std::printf("p.get() = %d\n", p.get());
    return 0;
}
```

**三、判断是否为同一个对象**（赋值运算符里要用，第 05 章展开）：

`C++`

```cpp
/* self_assign.cpp    编译：g++ -std=c++17 self_assign.cpp -o self_assign */
#include <cstdio>

class Buffer {
public:
    Buffer &operator=(const Buffer &other) {
        if (this == &other) return *this;   // 给自己赋值：直接返回
        n_ = other.n_;
        std::printf("（真的复制了）\n");
        return *this;
    }
    int n_ = 0;
};

int main() {
    Buffer b;
    b = b;                  // 自赋值
    std::printf("n_ = %d\n", b.n_);
    return 0;
}
```

`实测数据`
`Text`

```text
n_ = 0
```

**输出里没有「（真的复制了）」**——自赋值被提前挡掉了。

> [!CAUTION]
> **`operator=` 的第一件事是判自赋值**：`if (this == &other) return *this;`。
> 管理资源的类若「先释放自己的、再从 `other` 拷」，遇到 `b = b` 时
> 释放掉的正是随后要读的那份数据——从已释放的内存里读是未定义行为。

## 2.3 `const` 成员函数：`this` 的类型变了

**在成员函数后面写 `const`，意思是「这个函数不会修改对象」**。
它的实现方式是**把 `this` 的类型从 `T *` 变成 `const T *`**。

因此，`const` 对象只能调用 `const` 成员函数：

`实测数据`
`C++`

```cpp
// const_member.cpp    编译：g++ -std=c++17 const_member.cpp -o const_member （失败）
class Counter {
public:
    int  size() const { return n_; }        // 承诺不改对象
    void push(int v)  { n_ = v; }           // 会改对象，因此它不是 const
private:
    int n_ = 0;
};

int main() {
    const Counter c;
    c.push(1);              // const 对象不能调用非 const 成员函数
    return c.size();
}
```

`实测数据`
`Text`

```text
const_member.cpp:12:11: error: passing 'const Counter' as 'this' argument discards qualifiers
```

**报错说的是「把 `const Counter` 当成 `this` 传进去，丢掉了限定」**——
`push` 要的是 `Counter *`，而 `c` 只能给出 `const Counter *`。

**写 `const` 成员函数的收益**：

| 好处 | 说明 |
|---|---|
| 接口说明了「是否修改对象」 | 读者不必查看实现即可知道 |
| `const` 对象能用 | 传 `const T &` 是常见做法，没有 `const` 成员函数就无法调用 |
| 编译器参与检查 | 写错会直接报错，不会留下一个暗中修改状态的函数 |

**细节在《04-语法/03-常量与 const.md》第 2 节**；
在类里还有 `mutable` 与两个重载版本（`const` / 非 `const`）的配合，
放在第 03 章「成员、友元与细节」展开。

## 2.4 两处例外

**通常可以把 `this` 当成这个参数的名字，但有两处例外。**

**一、`this` 不能被赋值**——它不是变量，只是参数的名字：

`实测数据`
`C++`

```cpp
// this_assign.cpp    编译：g++ -std=c++17 this_assign.cpp -o this_assign （失败）
class A {
public:
    void f(A &other) {
        this = &other;          // this 不是普通变量
    }
};
int main() { A a, b; a.f(b); return 0; }
```

`实测数据`
`Text`

```text
this_assign.cpp:5:9: error: lvalue required as left operand of assignment
```

**报错说的是「赋值号左边必须是可修改的左值」**——`this` 不是左值，不能放在赋值号左边。

**二、静态成员函数里没有 `this`**——它不属于任何对象，因此没有这个隐藏参数：

`实测数据`
`C++`

```cpp
// this_in_static.cpp    编译：g++ -std=c++17 this_in_static.cpp -o this_in_static （失败）
class A {
public:
    static void f() {
        this->x = 1;            // 静态成员函数没有 this
    }
private:
    int x = 0;
};
int main() { A::f(); return 0; }
```

`实测数据`
`Text`

```text
this_in_static.cpp:5:9: error: 'this' is unavailable for static member functions
```

> [!WARNING]
> **静态成员函数没有 `this`**：它不属于任何一个对象。
> 因此它不能访问数据成员——它无法确定要访问的是哪一份数据（第 03 章展开）。

> [!NOTE]
> **本节小结**：普通成员函数与自由函数的差别只有一处——它多一个隐含参数 `this`。
> **成员函数不占对象空间、调用不比自由函数慢，都由这一处推出**；
> `const` 成员函数是把 `this` 的类型改成 `const T *`；
> 例外只有两处——`this` 不能赋值，静态成员函数里没有 `this`。

# 第 4 节 类定义与成员函数的定义分别放在哪里

## 4.1 头文件放类定义，源文件放成员函数

**一个类通常拆成三份**：

`Text`

```text
stack.h      类定义：成员有哪些、哪些公有、哪些私有
stack.cpp    成员函数的定义
main.cpp     用它的程序
```

**头文件**：

`C++`

```cpp
/* stack.h    编译：g++ -std=c++17 -c stack.h -o stack_h.o */
#pragma once

class Stack {
public:
    void push(int v);
    int  size() const;
private:
    int data_[8] = {0};
    int top_ = 0;
};
```

**源文件**：

`C++`

```cpp
/* stack.cpp    编译：g++ -std=c++17 -c stack.cpp -o stack.o */
#include "stack.h"

void Stack::push(int v) { if (top_ < 8) data_[top_++] = v; }
int  Stack::size() const { return top_; }
```

**用它的程序**：

`C++`

```cpp
/* main_stack.cpp    编译：g++ -std=c++17 -c main_stack.cpp -o main_stack.o（与 stack.o 一起链接的命令见下方 Bash 代码块） */
#include <cstdio>
#include "stack.h"

int main() {
    Stack s;
    s.push(1);
    s.push(2);
    std::printf("size = %d\n", s.size());
    return 0;
}
```

`实测数据`
`Bash`

```bash
g++ -std=c++17 -c stack.cpp -o stack.o
g++ -std=c++17 main_stack.cpp stack.o -o main_stack
./main_stack
nm stack.o | grep Stack
```

`实测数据`
`Text`

```text
size = 2
0000000000000000 T _ZN5Stack4pushEi
0000000000000038 T _ZNK5Stack4sizeEv
```

**符号名是修饰过的**（`_ZN5Stack4pushEi` 读作「`Stack` 的 `push(int)`」），
这就是「C++ 支持重载」在目标文件层面的样子——
**同一个类里可以有两个 `push`，因为符号名里带了参数类型**。
名字修饰的规则见《01-编译器/00-语言的实现.md》第 5.6 小节。

**编译器需要知道以下信息**：

| 需要知道的信息 | 从哪知道 |
|---|---|
| 对象多大（`sizeof`） | 类定义里列出的成员 |
| 有哪些成员、谁能访问 | 类定义 |
| 成员函数的签名 | 类定义里的声明（**不需要函数体**） |

> [!IMPORTANT]
> **成员函数的实现可以留给链接器**：调用 `s.push(1)` 时，编译器只需要知道
> 「有个 `push`，收 `int`，返回 `void`」，实现留给链接器去 `stack.o` 里找。
> 类定义因此必须放进头文件，让每个使用它的源文件都看到。

## 4.2 前置声明的适用范围

**只需要「有这么个类」时，不必引入整个定义**：

`C++`

```cpp
/* forward_ok.cpp    编译：g++ -std=c++17 forward_ok.cpp -o forward_ok */
#include <cstdio>

class Stack;                    // 前置声明：只说「有这么个类」
Stack *make();                  // 只用到指针：可以
void  use(Stack &s);            // 只用到引用：可以

class Stack {                   // 真正的定义
public:
    int top = 0;
};

Stack *make() { static Stack s; return &s; }
void  use(Stack &s) { std::printf("s.top = %d\n", s.top); }

int main() {
    use(*make());
    return 0;
}
```

`实测数据`
`Text`

```text
s.top = 0
```

**前置声明的限制同样明确**——一旦要用到对象本身，就必须有完整定义：

`实测数据`
`C++`

```cpp
// forward_decl.cpp    编译：g++ -std=c++17 forward_decl.cpp -o forward_decl （失败）
class Stack;                    // 前置声明：只说「有这么个类」

Stack *make();                  // 可以：指针的大小已知
void  use(Stack &s);            // 可以：引用同理，也不需要完整定义

int main() {
    Stack s;                    // 不行：不知道它多大、怎么构造
    return 0;
}
```

`实测数据`
`Text`

```text
forward_decl.cpp:8:11: error: aggregate 'Stack s' has incomplete type and cannot be defined
```

**「不完整类型」的含义是：知道名字，不知道内容。**
指针与引用的大小与内容无关，所以能用；定义对象需要知道大小与构造方式，所以不能。

> [!TIP]
> **头文件里只需用到指针或引用时，写前置声明，不要 `#include`**：
> 少一层编译依赖，被依赖的头文件改动时，依赖它的源文件不必重编。

## 4.3 头文件里不要放定义

**头文件会被多个源文件包含**，如果在里面写函数定义，就会出现多份同名定义：

`实测数据`
`C++`

```cpp
/* bad.h    编译：g++ -std=c++17 -c bad.h -o bad_h.o */
#pragma once
int add(int a, int b) { return a + b; }     // 定义写在了头文件里
```

`C++`

```cpp
/* tu_a.cpp    编译：g++ -std=c++17 -c tu_a.cpp -o tu_a.o */
#include "bad.h"
int fa() { return add(1, 2); }
```

`C++`

```cpp
/* tu_b.cpp    编译：g++ -std=c++17 -c tu_b.cpp -o tu_b.o */
#include "bad.h"
int main() { return add(3, 4); }
```

`实测数据`
`Bash`

```bash
g++ -std=c++17 -c tu_a.cpp -o tu_a.o
g++ -std=c++17 -c tu_b.cpp -o tu_b.o
g++ tu_a.o tu_b.o -o tu          # 链接失败
```

`实测数据`
`Text`

```text
multiple definition of `add(int, int)'; tu_a.o:tu_a.cpp:(.text+0x0): first defined here
collect2.exe: error: ld returned 1 exit status
```

> [!WARNING]
> **头文件里不要写函数定义**：每个包含它的源文件都会生成一份，
> 两个目标文件一链接就是 multiple definition——错误要到链接阶段才出现。

**有三类定义可以写在头文件里**：

| 写法 | 可以的原因 |
|---|---|
| 类内定义的成员函数 | 隐含 `inline`（第 1.4 小节实测过） |
| 显式加 `inline` 的函数 | 语义就是「允许多处同名定义」 |
| 模板 | 到第 11 章展开 |

**`inline` 在 C 与 C++ 里管的是链接，不是「请内联」**，
这一点在《04-语法/15-奇技淫巧与优化.md》第 7 节与
《04-语法/14-预处理器.md》第 7.3 小节都实测过。

> [!NOTE]
> **本节小结**：类定义放头文件，因为使用者必须知道对象多大、有哪些成员、谁能访问；
> 成员函数的定义放 `.cpp`，调用处只需要签名，分开编译就建立在这条分工上。
> 只需要名字的地方用前置声明，得到的是不完整类型——能用指针与引用，不能定义对象；
> 头文件里只有三类定义是允许的：类内定义的成员函数、显式 `inline` 的函数、模板。

# 第 5 节 写一个类时的检查清单

`实测数据`

| 检查 | 说明 |
|---|---|
| **不变量写进接口了吗** | 「`top_` 与 `data_` 必须一致」这个约束，应当只由成员函数维护 |
| **数据成员是 `private` 吗** | 全 `public` 的类与结构体没有区别，访问控制形同虚设 |
| **接口是最小的吗** | 只暴露外面真正需要的动作，不为「用着方便」额外开放接口 |
| **不改对象的成员函数写 `const` 了吗** | 见第 2.3 小节 |
| **类定义放头文件、实现放源文件了吗** | 见第 4.1 小节 |
| **头文件里有没有定义** | 见第 4.3 小节 |
| **友元是不是必须的，范围能不能再小** | 能改用公开接口就不用友元；非用不可时优先放行单个函数（《05-类与面向对象/03-成员与细节.md》第 6.5 小节） |

**清单只保证不漏项**，一个类真正的形状由第一个问题决定：它有什么必须守住的东西。

**三种常见的退化**：

| 退化 | 症状 | 结果 |
|---|---|---|
| **全公开** | 成员都是 `public` | 与结构体没有区别，不变量照样能被破坏 |
| **成套的 get/set** | 每个私有成员配一个 `getX()` 与 `setX()` | 相当于取消了 `private`，只是多写两行代码 |
| **接口暴露实现** | 返回内部数组的指针、暴露 `Impl` 细节 | 实现一旦要改，调用方就要跟着改（导读第 2.3 小节提到的封装收益随之消失） |

> [!IMPORTANT]
> **类与结构体的分界线不是「有没有成员函数」，而是「有没有需要守住的东西」。**
> 有需要守住的东西，才需要 `private` 与接口；
> 没有，就用 `struct`——**用类包一层只会让读者多一次跳转**。

# 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 类 | Class | 一种类型：把数据与操作它的成员函数写在一起，并规定访问权限 |
| 对象 | Object | 类的一个实例；在内存里是一块数据 |
| 成员 | Member | 类里的数据或函数 |
| 成员函数 | Member function | 属于类的函数；有一个隐藏参数 `this` |
| 数据成员 | Data member | 属于每个对象的变量；决定 `sizeof` |
| 访问控制 | Access control | `public` / `private` / `protected`；作用范围是**类**，不是对象 |
| `this` | — | 成员函数的**隐含第一参数**，指向调用它的对象；是「成员函数」这层语法糖的名字 |
| `const` 成员函数 | const member function | 承诺不修改对象的成员函数；`this` 的类型是 `const T *` |
| 声明与实现分离 | — | 类定义放头文件、成员函数定义放源文件 |
| 前置声明 | Forward declaration | `class Stack;`——只说有这么个类，不知道内容 |
| 不完整类型 | Incomplete type | 只声明未定义的类；能定义指针与引用，不能定义对象 |

## A.13 写类时的检查清单

`Text`

```text
□ 不变量是什么，它落在哪个 private 成员上
□ 数据成员都在 private 里吗
□ 接口是最小的吗（外面真的需要这些动作吗）
□ 不改对象的成员函数都加 const 了吗
□ 类定义在头文件、实现在本文件吗
□ 头文件里有没有函数定义（除类内定义与 inline）
□ 有没有为了「方便」把内部细节返回出去
□ 友元是不是必须的，范围能不能再小
```
