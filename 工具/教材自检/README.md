# 教材自检工具

`verify_measured.py` —— 把教材里的「实测数据」变成**可重复检验**的东西。

## 它解决什么问题

2026-10-02 的两次独立审计用「把正文里的程序抽出来自己跑一遍」的办法，
在 `09-高阶数据结构` 的前十章里抓出 **2 处伪造引文**、**2 处硬编码 printf 冒充实测**，
以及若干「把被优化器删掉的结果当实测结论」的写法。
人工核对一次要几个钟头，而且下一个人不会重做。这个脚本把那套核对固定下来。

## 怎么用

在**仓库根目录**下跑：

`Bash`

```bash
python 工具/教材自检/verify_measured.py             # 默认查 README 与 A-00 到 A-03
python 工具/教材自检/verify_measured.py --all09     # 查 09 板块全部章节
python 工具/教材自检/verify_measured.py --fresh     # 忽略缓存，全部重跑
```

它做三件事：

1. 抽出每个 `.md` 里的 C/C++ 代码块、首部注释里写的编译命令，以及随后带 `实测数据` 标记的输出块（**标了节选的块只登记、不编译**）；
2. 真编译、真运行（注释里有几条命令就跑几个构建；标了「故意编不过」的按预期失败处理，改比对编译错误）；
3. 逐行比对：**结构量必须逐位相同**；**计时量按数量级判**（比值超过 5 倍才报不一致）。

工作目录与报告写在 `临时/ops_lab/`（该目录不入库），控制台只打印末尾摘要。

## 用它之前要知道的四件事（都是实跑换来的）

| # | 事 | 为什么 |
|---|---|---|
| 1 | **先让机器闲下来** | 计时量按比值判（超过 5 倍才算不一致），而这个容差**不只是跨机器的问题，同机负载也能顶穿**。实测教训：一次跑报出 7 处不一致（`trie 有序表 255.9 对 1280.5`、`差分还原 0.334 对 2.968`），当时机器正被编译与跑程序占着；**静置二十秒重跑就回到 0**。跑之前先停掉别的编译与测试 |
| 2 | **计时行必须带单位** | 不带单位的数字（`stack 底层 deque 3.850`）会被当成**结构量**去逐位比对，于是同一个数换一次运行就报不一致。程序输出与正文两边都要写 `ms`／`ns` |
| 3 | **不要跨章引用别章程序的输出块** | 脚本会把那个块配到**最近**的代码块上，于是判成不一致；读者也不知道那是谁跑出来的。改成 markdown 表格 + 《》指路（表格不进比对） |
| 4 | **报错走标准错误的、贴着时钟分辨率的，都别放进 `实测数据` 块** | 调试模式与 ASan 的诊断打到 `stderr`，脚本抓不到（只当 `Text` 块 + 散文引入）；`0.000 ms` 这种贴着分辨率的行重跑就变号，留在块里必然报不一致——改成块外说明「能做稳的是哪一档」 |

一条附带结论：**结构量（字节数、次数、树高、节点大小）是这套自检最可靠的部分**——
逐位相同、可长期复用；计时量只能当参考。写正文时也照这个轻重来。

## 它查不出什么（这一点比它能查什么更重要）

| 查不出 | 原因 |
|---|---|
| **程序里硬编码的 `printf`** | 程序会照打那些字，脚本无法判断那些数到底测没测过 |
| **散文里的数字** | 脚本只比对输出块，不比对句子 |
| **计时数字的跨机器可比性** | 它只报比值，不断言对错 |
| **区间写法的区间宽窄** | 区间不来自程序输出，脚本只能确认「这行不是程序打出来的」，**判不了这个区间是否如实覆盖了实测值**——那要靠写的人 |

因此脚本是**下限**，不是保证：正文里的每一句结论，仍要由写的人自己负责。
第一版判据是 `AGENTS.local.md` 的第 3.12 节。

## 已标节选的块不再报 PROBLEM（2026-10-02 第二轮改）

`AGENTS.local.md` 3.5 要求：凡出现代码的块，要么是**完整单文件**，要么**明确标「（下面是节选）」**。
脚本原先不认这句话，于是 `B-01`…`B-05` 与 `A-10`…`A-12` 里**已经标了节选**的 25 个片段
全被报成 `[PROBLEM]`——看着像 25 处正文缺标注，实际是脚本没读那行字。

现在三种写法都认，认到就**跳过编译**，报告里单列一类 `[SKIP] 已标节选`：

| 写法 | 长什么样 |
|---|---|
| 块**上方**单独一行 | `（下面是节选：只给数据成员与不变式）` |
| 块**下方**单独一行 | `（上面是节选：完整程序在附录 A。）` |
| 块**内首行**（注释里） | `/* （下面是节选）C23 的检查算术 */`、`// 节选自 x.c 第 10 行` |

**判据不是「块短于几行」**——那种判据会把**没标的真碎片**一起漏掉。
没标的碎片照旧报 `[PROBLEM]`；自测脚本 `临时/ops_lab/test_excerpt_skip.py` 里
故意留了一个没标的碎片，它必须仍然被报出来（另有三种标注、一句只是「提到」节选的散文、
一个完整程序四条对照）。汇总因此多了三行：`PROBLEM` 几处、`已标节选` 几个、`需 Linux 侧工具链` 几个。

**同一轮还改了一处**：编译命令写着「（Linux 侧）」或带 `-fsanitize=` 的块
（`A-06` 的 `asan_iter.cpp`），MinGW 缺 `-lasan`／`-lubsan` 运行库，本机编不过。
这种块现在自动送进 WSL 编译运行（默认发行版 `Ubuntu`，用环境变量 `VERIFY_MEASURED_WSL` 可换）；
本机没有 WSL 才跳过并写明原因——**不算 `[PROBLEM]`，也不假装编过**。

## 区间写法不再报 NOT-FOUND（2026-10-02 第三轮改）

`AGENTS.local.md` 3.12 第三节第 2 步规定：计时量漂到 5 倍容差以外时，先停掉并发、
静置复跑；**仍超就把那几行改成区间写法**（「约 2–12」），并写明它会随机器负载浮动。
区间**本来就不该出现在程序输出里**，脚本却按 `NOT-FOUND` 报出来——
**正文没错，是工具不认识区间写法**。全库那 4 处不一致全部来自 `A-04` 的两行正文
与紧跟它们的两句说明，正文一个字都不用改。

现在脚本认两类行，认到就**跳过逐行比对**，报告里单列一类 `[SKIP] 区间写法`
（逐行给出文件与行号），**不计入「不一致」**：

| 认什么 | 判据 |
|---|---|
| **区间行** | 行里有**至少一个**「约 A–B」形式的**数值单元格**（连接号 `–`、`—`、`-` 都认） |
| **它下面那句说明句** | **紧跟在区间行下面**、写着「随机器负载浮动」「按区间给」「不写单次值」的句子 |

### 护栏（这条不许把检查放松）

| 护栏 | 怎么保证 |
|---|---|
| **结构量绝不借这条逃掉** | 判据是「带「约」且形如区间的**数值单元格**」，**不是**「这行有中文」「这行比较长」「带 ms／ns」——后面这几种会把节点大小、次数、字节数一起放过 |
| **写错的具体值仍报 `MISMATCH`** | 把区间单元格**整段挖掉**之后，行里**再没有别的数字**才算区间行；`遍历 11.925 约 1–9` 这种混写的行不算区间行，那个具体值照旧去比对 |
| **没有「约」的单次值仍按原判** | 「约」是硬条件：单次值照旧逐行比对——漂在容差内报漂移，漂超 5 倍照样 `MISMATCH` |
| **说明句不是「提到负载就放过」** | 只有**紧跟在区间行下面**、且**本身不含数字**的句子才算；散文里提一句「随机器负载浮动」照旧报 `NOT-FOUND` |

**它为什么不算不一致**：区间是作者对多次运行的概括，**程序永远不会打印「约 2–12」**，
逐行比对对这类行只有 `NOT-FOUND` 一种结果——那是判据与约定打架，不是正文写错。
代价是脚本**判不了这个区间是否如实覆盖实测值**，所以它进了「它查不出什么」那张表。

自测：`临时/ops_lab/test_interval_skip.py`。六种对照——区间行、紧跟的说明句、
ASCII 连字符、**写错的具体值 → 仍然 `MISMATCH`**、区间与具体值混写、
没有「约」的单次值漂超 5 倍、上面没有区间行的孤立说明句。
上一轮的 `test_excerpt_skip.py` 原样复跑，结论不变（没标的碎片照旧报 `PROBLEM`）。
