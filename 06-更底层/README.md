# 更底层

本板块讲**标准管不到、硬件说了算**的那一层。

写应用的人迟早会遇到这样几个问题：程序链接时报 `undefined reference` 而符号明明写了；
换一台机器结果就变了；加了一行 `printf` 调试，bug 却自己消失了。
写嵌入式的人遇到的问题更直接：程序根本没进 `main`、中断里的变量主循环看不见、
`.data` 里的初值到了 RAM 里不对。这些问题都不是语法问题，翻语言教程也找不到答案——
**它们发生在语言之下：地址空间、寄存器、对齐、调用约定、链接脚本、启动代码。**

本板块的另一条要求是**贴着硬件**。讲 ABI 就讲参数进了哪个寄存器，
讲内存布局就讲进程与裸机的差别，讲 `volatile` 就把 `-O2` 的汇编贴出来看少了它会怎样。
**每条原理都要能回答一句：「在单片机上这件事长什么样」。**

> [!IMPORTANT]
> **本板块的结论都有出处：`实测` 走本机真跑，`文档` 引标准草案原文，没验证过的写明 `待确认`。**
> 嵌入式侧的对象是**一块真板子**：STM32F103C8 最小系统板（Cortex-M3、64 KiB flash、20 KiB RAM、
> CMSIS-DAP 调试器）。**凡这块板能测的都在硅片上测**——启动与内存搬运、各类操作的周期数、
> 中断延迟、数据竞争、少写 `volatile` 的后果。
> **板上只有 MCU 与晶振**，所以**涉及外设时序（USART、SPI、定时器）的结论一律标 `待确认`**，不编造现象。

## 五、怎么实测（本板块的工具链）

嵌入式侧先用 **WSL 里的交叉工具链 + QEMU** 打通，再**烧进真板子复测**；
应用侧走本机的 `gcc`/`g++` 与 MSVC。

| 工具 | 版本 | 用途 |
|---|---|---|
| `arm-none-eabi-gcc` | 13.2.1 | 交叉编译 Cortex-M，产出真实 `.elf` |
| `arm-none-eabi-objdump` | 2.42 | 段布局（`-h`）与反汇编（`-d`） |
| `qemu-system-arm` | 8.2.2 | 先跑一遍裸机镜像 |
| `gdb-multiarch` | 15.1 | 连 QEMU 单步（可选） |
| `openocd` | 0.12.0 | **烧写与调试真板子**（`interface/cmsis-dap.cfg` + `target/stm32f1x.cfg`） |
| 真板子 | STM32F103C8，Cortex-M3，64 KiB flash / 20 KiB RAM | **所有周期数与竞争数据都来自它** |

**两条经验直接写在这里，省得读者自己撞**：

- **程序输出走 semihosting**（`bkpt 0xAB` + `SYS_WRITE0`，QEMU 加 `-semihosting-config enable=on,target=native`）。
  **不要指望串口**：直接写 USART2 寄存器在 QEMU 的 `netduinoplus2` 上打不出字。
- **QEMU 的 `netduinoplus2` 是 Cortex-M4 近似板**，可以配 STM32F103 的链接脚本（flash `0x08000000`、
  RAM `0x20000000` 一致），但**外设行为与真板不同**——只拿它验与机型无关的东西：
  启动、向量表、内存搬运、`volatile` 的汇编、中断与内存序。

## 七、本板块的约定

- **结论必标依据**：`实测`（本机真跑）、`文档`（引草案原文与章节号）、`待确认`（合理推断或依赖外部条件）。
- **汇编只到「认得」这一层**：`mov`/`ldr`/`str`/`bl`/`b`/`bx`/`push`/`pop`。
  逐条讲解只出现在第 7 章（`Reset_Handler`）与第 3 章（`volatile` 对照）。
- **`A-教学素材/01-编译器/嵌入式/` 下的真素材原样引用、不改**：
  链接脚本、启动文件、`gpio.c`、`stm32f1xx_it.c`、`sysmem.c`、CubeMX 的 CMake 链路。
- **涉及真实板子外设行为**（USART、GPIO、定时器的具体时序）**一律标 `待确认`**。
