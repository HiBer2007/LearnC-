`<math.h>` 的函数、`rand` 与 `<stdlib.h>` 的 `abs`、`atoi`；C++ 这边的对应物是
`<limits>`、`<cmath>`、`<random>`、`<numeric>`。名字看起来很接近，用法却不同：
**宏只给出一个数字，`numeric_limits` 给出的是关于这个类型的一整套编译期常量**；
`sqrtf`/`sqrt`/`sqrtl` 三个名字在 C++ 里合并成了一个重载；
**`rand` 被换成了「引擎 + 分布」两台机器**。

# 第 1 节 `<limits>`：类型自己的边界

## 1.1 边界属于类型，不属于宏

C 的 `<limits.h>` 给出 `INT_MAX`、`CHAR_BIT` 这样的宏，`<float.h>` 给出
`DBL_EPSILON`、`FLT_MAX`。这些宏能用，但有两个问题：**它们是宏，
没有类型**；**每加一个类型就要加一批宏**，`long long` 与定宽整数
（《07-标准库/A-03-数值、数学与随机.md》第 3 节）都是后来补上去的。

C++ 换了一个办法：**把边界写成类模板的静态成员**。

`C++`

```cpp
/* （下面是节选）这两个成员的取值 */
std::numeric_limits<int>::max()          // 2147483647，类型是 int
std::numeric_limits<double>::epsilon()   // 2.22044604925031308085e-16
```

**`numeric_limits<T>` 对每个基本类型都有特化**（《05-类与面向对象/11-模板.md》第 6 节），
查不到特化的类型走主模板，所有成员都是「没有意义」的取值：
`is_specialized` 为 `false`，`min()` 与 `max()` 返回 `T{}`。
**因此 `is_specialized` 是判断「这个类型有没有边界」的开关。**

> [!IMPORTANT]
> **`numeric_limits` 的成员全是 `constexpr`，编译期就能用。**
> 于是 `static_assert(std::numeric_limits<int>::max() == 2147483647)` 这样的句子
> 可以写在代码里当断言用（《04-语法/12-编译期能力.md》第 4 节）。

## 1.2 各类型的极值

下面这个程序一次打印出基本类型的边界。**字符类型要先转成整数再打印**，
否则 `std::ostringstream` 输出的是字符本身。

`C++`

```cpp
/* lim_int.cpp    编译：g++ -std=c++17 lim_int.cpp -o lim_int */
#include <cstdio>
#include <limits>
#include <sstream>
#include <string>
#include <type_traits>

// 取值的十进制写法：字符类型必须先转成整数，否则会打印成字符
template <class T>
std::string str(T v) {
    std::ostringstream o;
    if constexpr (std::is_same_v<T, char> || std::is_same_v<T, signed char> ||
                  std::is_same_v<T, unsigned char> || std::is_same_v<T, wchar_t> ||
                  std::is_same_v<T, char16_t> || std::is_same_v<T, char32_t> ||
                  std::is_same_v<T, bool>) {
        o << static_cast<long long>(v);
    } else {
        o.precision(20);
        o << v;
    }
    return o.str();
}

template <class T>
void row(const char *name) {
    using L = std::numeric_limits<T>;
    std::printf("%-18s %2d  %-8s %-7s %6d %6d %6d  %-21s %-21s\n",
                name, (int)sizeof(T),
                L::is_signed ? "signed" : "unsigned",
                L::is_integer ? "integer" : "not-int",
                L::digits, L::digits10, L::radix,
                str(L::min()).c_str(), str(L::max()).c_str());
}

int main() {
    std::printf("%-18s %2s  %-8s %-7s %6s %6s %6s  %-21s %-21s\n",
                "类型", "大小", "符号性", "归类", "digits", "d10", "radix", "min()", "max()");
    std::printf("--------------------------------------------------------------------------------------------------------\n");
    row<bool>("bool");
    row<char>("char");
    row<signed char>("signed char");
    row<unsigned char>("unsigned char");
    row<wchar_t>("wchar_t");
    row<char16_t>("char16_t");
    row<char32_t>("char32_t");
    row<short>("short");
    row<unsigned short>("unsigned short");
    row<int>("int");
    row<unsigned int>("unsigned int");
    row<long>("long");
    row<unsigned long>("unsigned long");
    row<long long>("long long");
    row<unsigned long long>("unsigned long long");
    return 0;
}
```

`Text`

```text

wchar_t             2  unsigned integer     16      4      2  0                     65535
char16_t            2  unsigned integer     16      4      2  0                     65535

unsigned int        4  unsigned integer     32      9      2  0                     4294967295

unsigned long long  8  unsigned integer     64     19      2  0                     18446744073709551615
```

表中有三处需要逐个说明。

**第一，`digits` 与 `digits10` 不是一回事。** `digits` 是**不包括符号位的
进制位数**，`int` 是 31 位；`digits10` 是**十进制下能保证无损往返的位数**，
`int` 是 9 位——所以 `int` 保证能装下 9 位十进制数，第 10 位就可能溢出。
`unsigned long long` 的 `digits10` 是 19，而 `long long` 是 18，
差的正是那个符号位。

**第二，`char` 的符号性在本机是 `signed`，但这不是标准规定的。**
`char`、`signed char`、`unsigned char` 是三个不同的类型，
而 `char` 到底像哪一个由实现决定。本机 `char` 与 `signed char` 的
`min()`/`max()` 完全相同；换到 `char` 默认为无符号的平台上，
这张表的第三行会变成 `0` 与 `255`。

**第三，`bool` 的 `digits` 是 1、`radix` 是 2。**
它不是「1 字节的整数」，而是「只能取 0 与 1 的二进制类型」，
`min()` 是 `false`、`max()` 是 `true`。

## 1.3 浮点的专有成员

浮点类型多出一批整型没有的成员：`epsilon()`、`denorm_min()`、
`has_infinity`、`has_quiet_NaN`、`is_iec559`。

`C++`

```cpp
/* lim_float.cpp    编译：g++ -std=c++17 lim_float.cpp -o lim_float */
#include <cstdio>
#include <limits>
#include <sstream>
#include <string>

template <class T>
std::string num(T v) {
    std::ostringstream o;
    o.precision(21);
    o << v;
    return o.str();
}

template <class T>
void row(const char *name) {
    using L = std::numeric_limits<T>;
    std::printf("%-11s %2d %5d %5d %5d  %-24s %-24s %-24s\n",
                name, (int)sizeof(T), L::digits, L::digits10, L::max_digits10,
                num(L::epsilon()).c_str(), num(L::denorm_min()).c_str(), num(L::max()).c_str());
}

int main() {
    std::printf("%-11s %2s %5s %5s %5s  %-24s %-24s %-24s\n",
                "类型", "大小", "digits", "d10", "maxd10", "epsilon()", "denorm_min()", "max()");
    std::printf("-------------------------------------------------------------------------------------------------------------------------\n");
    row<float>("float");
    row<double>("double");
    row<long double>("long double");

    return 0;
}
```

`实测数据`
`Text`

```text
类型      大小 digits   d10 maxd10  epsilon()                denorm_min()             max()
-------------------------------------------------------------------------------------------------------------------------
float        4    24     6     9  1.1920928955078125e-07   1.40129846432481707092e-45 3.40282346638528859812e+38
double       8    53    15    17  2.22044604925031308085e-16 4.94065645841246544177e-324 1.79769313486231570815e+308
long double 16    64    18    21  1.08420217248550443401e-19 3.64519953188247460253e-4951 1.18973149535723176502e+4932
```

**这三个类型都报告 `has_infinity`、`has_quiet_NaN`、`is_iec559` 为真**，也就是说它们都是 IEEE 754 格式、都有无穷与 NaN。

**`max_digits10` 是这一堆成员里最实用、最少人知道的一个。**
它的含义是「十进制下需要几位才能把一个浮点值原样打印回来」：
`double` 是 17 位。**因此调试时打印 `double` 应该写 `%.17g`**，
写 `%.6f` 或默认的 6 位有效数字都会丢掉信息，`0.1 + 0.2` 与 `0.3`
那点差别（下面第 3 节）就是这样被抹掉的。

**`lowest()` 与 `min()` 在浮点上不是一回事。** 浮点的 `min()` 是
**最小的正数**（`denorm_min()` 之上的规格化最小值），`lowest()` 才是
**最小的负数**。整型上两者相等，浮点上差一个符号，这是最容易写错的一处。

`文档`

> "lowest()    [static] constexpr T lowest() noexcept;
> The lowest finite value representable by the type."
>
> —— N4659 §18.3.2.4/9

## 1.4 `is_signed` 与 `is_integer` 怎么用

这两个成员回答了在 C 里必须查表才能知道的两件事：**这个类型有没有符号位**，
以及**它算不算整数类型**。它们的用途是写泛型代码时按类型分支：

`C++`

```cpp
/* lim_traits.cpp    编译：g++ -std=c++17 lim_traits.cpp -o lim_traits */
#include <cstdio>
#include <limits>
#include <type_traits>

// 按「有没有符号位」决定怎么解释一段二进制：整型与浮点的处理完全不同
template <class T>
void describe(const char *name) {
    constexpr bool is_int = std::numeric_limits<T>::is_integer;
    constexpr bool is_sgn = std::numeric_limits<T>::is_signed;
    std::printf("%-12s is_integer=%-5d is_signed=%-5d is_exact=%-5d is_specialized=%d\n",
                name, (int)is_int, (int)is_sgn,
                (int)std::numeric_limits<T>::is_exact,
                (int)std::numeric_limits<T>::is_specialized);
}

struct Point { int x, y; };           // 没有特化的类型

int main() {
    describe<bool>("bool");
    describe<char>("char");
    describe<unsigned int>("unsigned");
    describe<int>("int");
    describe<float>("float");
    describe<double>("double");
    describe<Point>("Point");

    // 编译期就能判断：这属于类型信息，不是运行期信息
    static_assert(std::numeric_limits<int>::is_integer, "int 是整数类型");
    static_assert(!std::numeric_limits<double>::is_integer, "double 不是整数类型");
    static_assert(std::numeric_limits<unsigned>::is_signed == false, "unsigned 没有符号位");
    return 0;
}
```

`实测数据`
`Text`

```text
bool         is_integer=1     is_signed=0     is_exact=1     is_specialized=1
char         is_integer=1     is_signed=1     is_exact=1     is_specialized=1
unsigned     is_integer=1     is_signed=0     is_exact=1     is_specialized=1
int          is_integer=1     is_signed=1     is_exact=1     is_specialized=1
float        is_integer=0     is_signed=1     is_exact=0     is_specialized=1
double       is_integer=0     is_signed=1     is_exact=0     is_specialized=1
Point        is_integer=0     is_signed=0     is_exact=0     is_specialized=0
```

**`is_exact` 区分「精确类型」与「近似类型」**：整型是精确的
（每一位都表示一个确定的值），浮点不是。**`is_specialized` 区分
「有边界的类型」与「没特化的类型」**：`Point` 那一行全是 0，
说明它没有任何有意义的边界。

> [!TIP]
> **写泛型代码时，用 `is_integer` 而不是「`sizeof(T) <= 8`」这类猜测。**
> 判断「能不能用 `%` 取余」「能不能做位运算」这类问题，
> `is_integer` 是标准给出的答案，`static_assert` 还能把它变成编译期检查。

## 1.5 有符号溢出是未定义行为

**这一小节是全章最需要注意的一处。** 无符号整数溢出有明确定义——
按 2 的 N 次方回绕；**有符号整数溢出是未定义行为**，
编译器可以假设它不会发生，并据此做优化。

`文档`

> "If during the evaluation of an expression, the result is not
> mathematically defined or not in the range of representable values
> for its type, the behavior is undefined."
>
> —— N4659 §8/4

下面这个程序故意制造一次溢出。**关键是让被加的数是运行期才知道的值**，
否则编译器会在编译期直接算出结果，看不出优化等级的差别。

`C++`

```cpp
/* ovf_rt.cpp    编译：g++ -std=c++17 -O0 ovf_rt.cpp -o ovf_rt */
#include <climits>
#include <cstdio>

int plus_one(int x) { return x + 1; }        // 有符号加法，标准规定溢出是未定义行为

int main(int argc, char **) {
    // 值来自运行期（argc），编译器不能把它折成常量
    int m = INT_MAX - (argc - 1);
    int r = plus_one(m);
    std::printf("m                = %d\n", m);
    std::printf("plus_one(m)      = %d\n", r);
    std::printf("plus_one(m) > m  = %d\n", r > m);
    std::printf("m + 1 > m        = %d\n", m + 1 > m);

    // 同一件事在无符号上是有定义的
    unsigned um = UINT_MAX;
    std::printf("UINT_MAX + 1     = %u（回绕，有定义）\n", um + 1);
    return 0;
}
```

同一份源码编两遍，只改优化等级：

`Bash`

```bash
g++ -std=c++17 -O0 ovf_rt.cpp    -o ovf_rt
g++ -std=c++17 -O2 ovf_rt_o2.cpp -o ovf_rt_o2
```

`实测数据`
`Text`

```text
-O0 的输出                      -O2 的输出
m                = 2147483647   m                = 2147483647
plus_one(m)      = -2147483648  plus_one(m)      = -2147483648
plus_one(m) > m  = 0            plus_one(m) > m  = 1
m + 1 > m        = 1            m + 1 > m        = 1
UINT_MAX + 1     = 0（回绕）    UINT_MAX + 1     = 0（回绕）
```

**同一个函数、同一个实参，两次比较得出了相反的结论。**
`-O0` 下 `plus_one(m) > m` 是假的（加完变成负数，确实不大于 `m`）；
`-O2` 下 gcc 依据「有符号加法不会溢出」把 `x + 1 > x` 直接折叠成真，
**于是程序打印的数值是 `-2147483648`，而判断却说是「更大」。**

> [!CAUTION]
> **有符号溢出不是「回绕一下」，而是「编译器可以假设它不发生」。**
> 一旦真的发生，前后两行代码可能互相矛盾，而且换一个优化等级就换一个结果。
> 这是《03-构建工具链/05-优化等级.md》第 5.5 小节讲的同一件事：
> **未定义行为给了优化器「有恃无恐」的依据。**

防范的办法有三条：

| 做法 | 怎么写 |
|---|---|
| 用无符号做「就是要回绕」的运算 | 哈希、校验和一律用 `unsigned`（《04-语法/15-奇技淫巧与优化.md》第 6 节） |
| 加之前先判断是否会越界 | `if (a > std::numeric_limits<int>::max() - b) { /* 处理 */ }` |
| 让编译器代为检查 | `-fsanitize=undefined`（UBSan），把溢出变成一条运行期报告 |

`C++`

```cpp
/* ovf_trap.cpp    编译：g++ -std=c++17 -fsanitize=undefined ovf_trap.cpp -o ovf_trap */
#include <climits>
#include <cstdio>

int plus_one(int x) { return x + 1; }

int main(int argc, char **) {
    int m = INT_MAX - (argc - 1);
    std::printf("m = %d\n", m);
    std::printf("plus_one(m) = %d\n", plus_one(m));
    return 0;
}
```

**UBSan 报的是运行期错误，位置精确到表达式，并且默认不终止程序**——

因此只在调试与测试配置里开（《03-构建工具链/05-优化等级.md》第 6 节）。
`待确认`：MSVC 的对应开关是 `/fsanitize=address`，是否含整数溢出检查未在本机验证。

## 1.6 与 A-03 的对照

| 同一件事 | C（A-03） | C++（本章节） |
|---|---|---|
| 整型上界 | `INT_MAX`、`LLONG_MAX` 宏 | `std::numeric_limits<int>::max()` |
| 浮点精度 | `DBL_EPSILON`、`FLT_DIG` 宏 | `epsilon()`、`digits10`、`max_digits10` |
| 有没有符号位 | 看类型名里有没有 `unsigned` | `is_signed` |
| 不是整数的类型 | 无对应物 | `is_integer` 为 `false` |
| 打印浮点的位数 | `%g` 要自己数 | `max_digits10` 直接给出 |
| 溢出 | 有符号同样未定义 | 同左，可用 `numeric_limits` 提前判断 |

**`<limits.h>` 与 `<float.h>` 并没有被废弃**，C 代码照旧用宏；
但在 C++ 里写模板、写泛型代码时，`numeric_limits` 是唯一能在编译期
按类型取到边界的工具。**本章节的程序一律用后者。**

> [!NOTE]
> **第 1 节小结**：类型的边界在 C++ 里是「类型自带的编译期常量」，
> 而不是一批与类型脱钩的宏。`is_specialized` 说明有没有边界，
> `digits` 与 `digits10` 说精度，`max_digits10` 说打印位数，
> `lowest()` 与 `min()` 在浮点上不是一回事。
> **有符号溢出是未定义行为，`-O0` 与 `-O2` 能给出相反的结果。**

# 第 2 节 `<cmath>`：C 的数学函数加上重载

## 2.1 按实参类型选版本

C 的 `<math.h>` 里每个函数有三份：`sqrt`（`double`）、`sqrtf`（`float`）、
`sqrtl`（`long double`）。C++ 的 `<cmath>` 保留了这三个名字，
**同时把它们做成了一组重载**，于是只写 `std::sqrt` 就够。

`C++`

```cpp
/* cmath_overload.cpp    编译：g++ -std=c++17 cmath_overload.cpp -o cmath_overload */
#include <cmath>
#include <cstdio>

int main() {
    float f = 2.0f;
    double d = 2.0;
    long double ld = 2.0L;

    // 同一个 std::sqrt，参数类型不同，选中的重载就不同
    std::printf("sizeof(sqrt(float))       = %d\n", (int)sizeof(std::sqrt(f)));
    std::printf("sizeof(sqrt(double))      = %d\n", (int)sizeof(std::sqrt(d)));
    std::printf("sizeof(sqrt(long double)) = %d\n", (int)sizeof(std::sqrt(ld)));
    std::printf("sizeof(sqrt(2))（int 实参） = %d\n", (int)sizeof(std::sqrt(2)));
    std::printf("sizeof(fabs(-3))（int 实参） = %d\n", (int)sizeof(std::fabs(-3)));

    std::printf("sqrt(-1.0)  = %f\n", std::sqrt(-1.0));
    std::printf("log(0.0)    = %f\n", std::log(0.0));
    std::printf("pow(2, 10)  = %.1f\n", std::pow(2, 10));
    std::printf("fmod(7.5,2) = %.1f\n", std::fmod(7.5, 2.0));
    std::printf("round(2.5)  = %.1f，round(-2.5) = %.1f\n", std::round(2.5), std::round(-2.5));
    std::printf("floor(-2.5) = %.1f，ceil(-2.5) = %.1f\n", std::floor(-2.5), std::ceil(-2.5));
    std::printf("hypot(3,4)  = %.1f\n", std::hypot(3.0, 4.0));
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(sqrt(float))       = 4
sizeof(sqrt(double))      = 8
sizeof(sqrt(long double)) = 16
sizeof(sqrt(2))（int 实参） = 8
sizeof(fabs(-3))（int 实参） = 8
sqrt(-1.0)  = nan
log(0.0)    = -inf
pow(2, 10)  = 1024.0
fmod(7.5,2) = 1.5
round(2.5)  = 3.0，round(-2.5) = -3.0
floor(-2.5) = -3.0，ceil(-2.5) = -2.0
hypot(3,4)  = 5.0
```

**返回类型跟着实参走**：传 `float` 得到 `float`，传 `long double` 得到
`long double`，传 `int` 则走 `double` 那一份（整型实参先做浮点转换）。
**这就是重载相对三个名字的价值**：写 `std::sqrt(x)` 不会因为 `x` 换了类型
就悄悄走错精度——**C 里写 `sqrt(x)` 时，如果 `x` 是 `float`，
算的是 `double` 版再截断**。

`round` 的一处细节：**它按「远离零」取整**，`2.5` 变 `3.0`、`-2.5` 变 `-3.0`，
而不是「四舍五入到偶数」。

## 2.2 特殊值与出错

`sqrt(-1.0)` 得到 `nan`，`log(0.0)` 得到 `-inf`，**没有异常，也没有错误码**。
这与《07-标准库/A-03-数值、数学与随机.md》第 1.4 小节讲的一致：
C 的数学函数出错时**设置 `errno` 并返回一个特殊值**，返回什么由实现决定。
要抛异常就须自行包一层。

`C++`

```cpp
/* math_err.cpp    编译：g++ -std=c++17 math_err.cpp -o math_err */
#include <cerrno>
#include <cmath>
#include <cstdio>
#include <cstring>

int main() {
    errno = 0;
    double a = std::sqrt(-1.0);
    std::printf("sqrt(-1.0) = %f，errno = %d（%s）\n", a, errno, errno ? std::strerror(errno) : "未设置");

    errno = 0;
    double b = std::log(0.0);
    std::printf("log(0.0)   = %f，errno = %d（%s）\n", b, errno, errno ? std::strerror(errno) : "未设置");

    // 判断要用 isnan / isinf，不能靠比较
    std::printf("isnan(a) = %d，isinf(b) = %d，b < 0 = %d\n",
                (int)std::isnan(a), (int)std::isinf(b), b < 0);
    return 0;
}
```

`实测数据`
`Text`

```text
sqrt(-1.0) = nan，errno = 33（Domain error）
log(0.0)   = -inf，errno = 34（Result too large）
isnan(a) = 1，isinf(b) = 1，b < 0 = 1
```

**`errno` 的两个取值来自本机的运行库**：33 是 `EDOM`（定义域错误），
34 是 `ERANGE`（结果超出范围）。**`b < 0` 对 `-inf` 成立这一点值得注意**，
而 `nan` 与任何值比较都不成立（第 3 节）。

> [!WARNING]
> **不要用 `if (x == std::numeric_limits<double>::quiet_NaN())` 判断 NaN。**
> `nan` 与任何值比较都为假，这个条件永远不成立。
> 判断只有一个正确写法：`std::isnan(x)`。

## 2.3 `abs` 的两个坑

`abs` 是 `<cmath>` 与 `<cstdlib>` 都提供的名字，它有两个容易踩的地方。

**第一个坑：对无符号数用 `abs`，编译都过不去。**
`a - b` 在 `a`、`b` 是无符号时结果也是无符号，而 `abs` 没有无符号版本，
于是所有候选都要做一次整型转换，重载决议无法选择。

`C++`

```cpp
/* abs_unsigned.cpp    编译：g++ -std=c++17 abs_unsigned.cpp -o abs_unsigned （失败） */
#include <cstdio>
#include <cstdlib>

int main() {
    unsigned a = 3, b = 10;
    std::printf("%u\n", std::abs(a - b));       // a - b 的类型是 unsigned
    return 0;
}
```

`实测数据`
`Text`

```text
abs_unsigned.cpp:7:33: error: call of overloaded 'abs(unsigned int)' is ambiguous
    7 |     std::printf("%u\n", std::abs(a - b));       // a - b 的类型是 unsigned
      |                         ~~~~~~~~^~~~~~~
abs_unsigned.cpp:7:33: note: there are 6 candidates
```

**报错说的是「六个候选，无法选择」**：`abs(int)`、`abs(long)`、
`abs(long long)` 与三个浮点版全都在候选里，无符号转成其中任何一个
都是同一种转换，编译器没有依据可选。**正确做法是先把差值转成有符号**：
`std::abs(static_cast<int>(a) - static_cast<int>(b))`，
或者干脆用 `a > b ? a - b : b - a`。

**第二个坑：`abs` 作用于 `INT_MIN` 时结果是负数。**
`int` 的取值范围内，`-INT_MIN` 装不下（`INT_MAX` 比它小 1），
因此这个调用本身就是未定义行为。

`C++`

```cpp
/* abs_intmin.cpp    编译：g++ -std=c++17 abs_intmin.cpp -o abs_intmin */
#include <climits>
#include <cstdio>
#include <cstdlib>

int main() {
    int m = INT_MIN;
    std::printf("INT_MIN        = %d\n", m);
    std::printf("abs(INT_MIN)   = %d\n", std::abs(m));
    std::printf("结果是负数吗   ：%s\n", std::abs(m) < 0 ? "是" : "否");
    return 0;
}
```

`实测数据`
`Text`

```text
INT_MIN        = -2147483648
abs(INT_MIN)   = -2147483648
结果是负数吗   ：否
```

**这里出现了自相矛盾的两行**：`abs(INT_MIN)` 明明是 `-2147483648`（负数），
而下一行判断却说「不是负数」。原因与第 1.5 节的有符号溢出是同一件事：
**编译器依据「`abs` 不返回负数」把比较折叠成了假**。值是真的错了，
判断也是真的错了，只是错的方向相反。

> [!CAUTION]
> **`std::abs` 的实参必须能表示它的相反数。** 处理可能为 `INT_MIN`
> 的输入时，要么换成 `long long` 再取绝对值，要么先把这种情况挡在外面。

# 第 3 节 浮点比较与容差

## 3.1 `==` 什么时候能用

浮点用 `==` 比较是《04-语法/04-表达式与运算符.md》第 3.3 小节就提醒过的事，
原因是 **`0.1`、`0.2`、`0.3` 三个数在二进制里都除不尽**。

`C++`

```cpp
/* float_cmp.cpp    编译：g++ -std=c++17 float_cmp.cpp -o float_cmp */
#include <cmath>
#include <cstdio>
#include <limits>

bool nearly(double a, double b, double eps) {              // 绝对容差
    return std::fabs(a - b) <= eps;
}
bool rel_nearly(double a, double b, double tol) {          // 相对容差
    return std::fabs(a - b) <= tol * std::fmax(std::fabs(a), std::fabs(b));
}

int main() {
    double s = 0.1 + 0.2;
    std::printf("0.1 + 0.2        = %.20f\n", s);
    std::printf("0.3              = %.20f\n", 0.3);
    std::printf("0.1 + 0.2 == 0.3 ：%d\n", s == 0.3);
    std::printf("两者之差         = %.3e\n", std::fabs(s - 0.3));
    std::printf("|差| <= 1e-15    ：%d\n", nearly(s, 0.3, 1e-15));
    std::printf("epsilon          = %.3e\n", std::numeric_limits<double>::epsilon());

    // 绝对容差在大数上失效
    double big = 1e16;
    std::printf("\nbig = 1e16，big + 1 与 big 相等：%d\n", big == big + 1);
    std::printf("绝对容差 1e-9 判定 1e16 与 1e16+1 相等：%d\n", nearly(big, big + 1, 1e-9));
    std::printf("相对容差 1e-15 判定 1e16 与 1e16+1 相等：%d\n", rel_nearly(big, big + 1, 1e-15));

    // NaN 与无穷
    double nan = std::nan("");
    double inf = std::numeric_limits<double>::infinity();
    double zero = 0.0;
    std::printf("\nnan == nan       ：%d\n", nan == nan);
    std::printf("nan != nan       ：%d\n", nan != nan);
    std::printf("isnan(nan)       ：%d\n", (int)std::isnan(nan));
    std::printf("nan > 0 / nan < 0：%d %d\n", nan > 0, nan < 0);
    std::printf("inf - inf        = %f，isnan：%d\n", inf - inf, (int)std::isnan(inf - inf));
    std::printf("zero / zero      = %f\n", zero / zero);
    std::printf("1.0 / zero       = %f\n", 1.0 / zero);
    return 0;
}
```

`实测数据`
`Text`

```text
0.1 + 0.2        = 0.30000000000000004441
0.3              = 0.29999999999999998890
0.1 + 0.2 == 0.3 ：0
两者之差         = 5.551e-17
|差| <= 1e-15    ：1
epsilon          = 2.220e-16

big = 1e16，big + 1 与 big 相等：1
绝对容差 1e-9 判定 1e16 与 1e16+1 相等：1
相对容差 1e-15 判定 1e16 与 1e16+1 相等：1

nan == nan       ：0
nan != nan       ：1
isnan(nan)       ：1
nan > 0 / nan < 0：0 0
inf - inf        = nan，isnan：1
zero / zero      = nan
1.0 / zero       = inf
```

**两组数字值得对照。** `0.1 + 0.2` 与 `0.3` 差 `5.551e-17`，
比 `epsilon`（`2.220e-16`）还小一位，**用绝对容差 `1e-15` 判等是合理的**。
而 `1e16` 与 `1e16 + 1` 在 `double` 里根本就是同一个数
（`double` 只有 53 位有效位，`1e16` 附近的间距已经大于 1），
所以三行判定全都返回真——**最后两行返回真不是容差的功劳，
而是这两个数本来相等**。

> [!IMPORTANT]
> **容差要跟着数值的量级走。** 判断「接近 0 的两个数」用绝对容差，
> 判断「接近 1e16 的两个数」用相对容差；**只写死一个 `1e-9` 是错的**，
> 它在大数上过严（本来相等的数被判为不等），在小数上过松。
> 实用写法是两者取其一并按数量级缩放：
> `|a - b| <= tol * max(|a|, |b|)`。

## 3.2 NaN 的比较规则

`nan == nan` 是假、`nan != nan` 是真、`nan > 0` 与 `nan < 0` 都是假——
**NaN 与任何值（包括它自己）的任何比较都返回假**，只有 `!=` 返回真。
这不是实现问题，是 IEEE 754 规定的。

**这条规则有一个直接后果：排序会失效。** 一个含 NaN 的数组交给
`std::sort`（排序算法本身在 `09-高阶数据结构` 板块），
比较函数既不满足「小于」也不满足「相等」的性质，
**结果可能是未定义行为**。处理办法是把 NaN 先挑出来，或者用
`isnan` 在比较函数里明确排序。

## 3.3 `-ffast-math` 会把 NaN 判定抹掉

如果打开 `-ffast-math`（`-Ofast` 也包含它），编译器会假设
**程序里不会出现 NaN 与无穷，且浮点运算满足结合律**。于是
`std::isnan` 会被直接折叠成假。

`C++`

```cpp
/* isnan_fast.cpp    编译：g++ -std=c++17 -O2 -ffast-math isnan_fast.cpp -o isnan_fast */
#include <cmath>
#include <cstdio>

int main() {
    double zero = 0.0;                  // 不是 const，避免编译器直接折成常量
    double nan = zero / zero;
    std::printf("nan             = %f\n", nan);
    std::printf("std::isnan(nan) = %d\n", (int)std::isnan(nan));
    std::printf("nan != nan      = %d\n", nan != nan);
    return 0;
}
```

`实测数据`
`Text`

```text
nan             = 1.000000
std::isnan(nan) = 0
nan != nan      = 0
```

**连 `0.0 / 0.0` 都被折成了 `1.0`。** 开了 `-ffast-math` 之后，
「`x / x` 等于 1」这条代数规则被无条件使用，分母为零的情形不再特殊对待。
`isnan` 返回 0、`nan != nan` 返回 0，都是同一个假设的后果。

| 写法 | `-O2` | `-O2 -ffast-math` |
|---|---|---|
| `isnan(nan)` | 1 | 0 |
| `nan != nan` | 1 | 0 |
| `zero / zero` | `nan` | `1.0` |

**因此含 `isnan`、`isinf`、`nan` 或依赖浮点结合律的代码不要用 `-ffast-math`。**
它属于《03-构建工具链/05-优化等级.md》第 5.7 小节讲的那一类开关：
**用正确性换速度，而且换掉的正确性不会报错，只会静默改变结果。**

> [!NOTE]
> **第 3 节小结**：浮点判等要么用 `==`（确认两边是同一个计算路径，
> 比如与 `0.0` 比较、判断是否仍未赋值），要么用容差；
> **容差的量级要跟着数值走**。NaN 与任何值比较都为假，
> **判断只能用 `isnan`**；`-ffast-math` 会让 `isnan` 恒为假，
> 因为它假设程序里不会有 NaN。

# 第 4 节 `<random>`：引擎与分布分开

## 4.1 三件东西

`<random>` 把「产生随机数」拆成了三件独立的东西：

`Text`

```text
   ┌───────────────┐      ┌──────────────────────┐      ┌──────────────┐
   │  种子 seed    │─────>│  引擎 engine         │─────>│  分布        │
   │  一个整数     │      │  产生均匀的原始比特  │      │  distribution│
   └───────────────┘      └──────────────────────┘      └──────────────┘
                                 │                            │
                            可复现的部分                  决定取值长什么样
                            （同种子必然同序列）          （整数区间/正态/伯努利…）
```

**这个拆分是 `<random>` 相对 `rand` 的核心区别**：`rand()` 把三件事揉在一起，
既是引擎又是分布，还自带一个全局的、由 `srand` 设置的种子；
`<random>` 里这三件事各有各的类型，可以分别替换。

| 想要 | 做法 |
|---|---|
| 换一个随机数质量更好的引擎 | 换引擎类型，分布代码不动 |
| 把取值从 `[0, 100)` 改成正态分布 | 换分布对象，引擎不动 |
| 让结果可复现 | 固定种子，引擎与分布都不用改 |
| 让两个模块互不干扰 | 各用各的引擎对象，不共享全局状态 |

## 4.2 引擎

常用的引擎有四个：

| 引擎 | 本机 `sizeof` | 说明 |
|---|---|---|
| `std::mt19937` | 2504 字节 | 梅森旋转，周期 2^19937−1，32 位输出 |
| `std::mt19937_64` | 2504 字节 | 同上，64 位输出 |
| `std::minstd_rand` | 4 字节 | 线性同余，周期 2^31−2，快但质量一般 |
| `std::default_random_engine` | 4 字节 | **由实现决定是哪个**，本机是 `minstd_rand0` |

`C++`

```cpp
/* engine_size.cpp    编译：g++ -std=c++17 engine_size.cpp -o engine_size */
#include <cstdio>
#include <random>
#include <type_traits>

int main() {
    std::printf("sizeof(mt19937)               = %d\n", (int)sizeof(std::mt19937));
    std::printf("sizeof(mt19937_64)            = %d\n", (int)sizeof(std::mt19937_64));
    std::printf("sizeof(minstd_rand)           = %d\n", (int)sizeof(std::minstd_rand));
    std::printf("sizeof(default_random_engine) = %d\n", (int)sizeof(std::default_random_engine));
    std::printf("default_random_engine 是 minstd_rand0：%d\n",
                (int)std::is_same_v<std::default_random_engine, std::minstd_rand0>);

    // 引擎的取值上下界也是编译期常量
    std::printf("\nmt19937 的最小/最大值：%u / %u\n",
                (unsigned)std::mt19937::min(), (unsigned)std::mt19937::max());
    std::printf("默认种子（不传实参时）的前 3 个值：");
    std::mt19937 g;
    for (int i = 0; i < 3; i++) std::printf(" %u", (unsigned)g());
    std::printf("\n");
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(mt19937)               = 2504
sizeof(mt19937_64)            = 2504
sizeof(minstd_rand)           = 4
sizeof(default_random_engine) = 4
default_random_engine 是 minstd_rand0：1

mt19937 的最小/最大值：0 / 4294967295
默认种子（不传实参时）的前 3 个值： 3499211612 581869302 3890346734
```

**`mt19937` 有 2504 字节：624 个 32 位状态加一个下标，一个不多。**
`minstd_rand` 只有 4 字节，因为它整个状态就是一个 32 位整数。
**这个大小是实现的自由**——标准规定了算法与输出序列，
没有规定内部怎么存，因此换一个标准库，`sizeof` 就会变
（`待确认`：`<VS>` 的 STL 上这两个数字未在本机验证）。
**结论是不要按值传引擎**：拷贝一次就是 2.5 KB，
而且按值传入函数后，函数内推进的状态不会传回调用方。

**`default_random_engine` 是唯一不保证平台的引擎**：本机是
`minstd_rand0`（4 字节），`<VS>` 上是 `mt19937`。
**要结果跨平台一致，就写明 `mt19937`，不要用这个别名。**

## 4.3 分布

分布负责把引擎输出的均匀整数变成想要的形状。最常用的三个：

| 分布 | 取值 | 说明 |
|---|---|---|
| `std::uniform_int_distribution<int>(a, b)` | `a` 到 `b`，**两端都包含** | 整数均匀 |
| `std::uniform_real_distribution<double>(a, b)` | `[a, b)` | 浮点均匀 |
| `std::normal_distribution<double>(mean, sigma)` | 正态 | 均值与标准差 |

其余分布按「输出是什么形状」分五类，用到时按名字查即可：

| 类别 | 分布 | 输出 |
|---|---|---|
| 均匀 | `uniform_int_distribution`、`uniform_real_distribution` | 区间内等概率 |
| 伯努利 | `bernoulli_distribution`、`binomial_distribution`、`geometric_distribution`、`negative_binomial_distribution` | 是/否、成功次数、等到成功要试几次 |
| 泊松 | `poisson_distribution`、`exponential_distribution`、`gamma_distribution`、`weibull_distribution`、`extreme_value_distribution` | 单位时间内的事件次数与等待时间 |
| 正态 | `normal_distribution`、`lognormal_distribution`、`chi_squared_distribution`、`cauchy_distribution`、`fisher_f_distribution`、`student_t_distribution` | 连续量的分布形状 |
| 离散 | `discrete_distribution`、`piecewise_constant_distribution`、`piecewise_linear_distribution` | 按给定权重取值 |

**引擎一侧同样是「常用的两个、其余备查」**：`mt19937` 与 `mt19937_64` 覆盖绝大多数场合；
`minstd_rand` 与 `minstd_rand0` 状态小、速度快，代价是质量一般；
`ranlux24_base`、`ranlux48_base` 以及由它们派生的 `ranlux24`、`ranlux48`、`knuth_b`
差别只在周期与状态大小上。**换引擎只要改类型名，分布那边的代码一行都不用动**——
这正是第 4.1 小节那个拆分的用处。

`C++`

```cpp
/* dist_demo.cpp    编译：g++ -std=c++17 dist_demo.cpp -o dist_demo */
#include <cstdio>
#include <random>
#include <vector>

int main() {
    std::mt19937 gen(2024);

    // 闭区间的证实：uniform_int_distribution(0, 9) 会取到 9
    std::uniform_int_distribution<int> d10(0, 9);
    int cnt[10] = {0};
    for (int i = 0; i < 20000; i++) cnt[d10(gen)]++;
    std::printf("uniform_int_distribution(0, 9) 计 20000 次：\n  ");
    for (int i = 0; i < 10; i++) std::printf("%5d", cnt[i]);
    std::printf("\n  上界 9 出现了 %d 次，说明两端都包含\n", cnt[9]);

    // 浮点分布是左闭右开：取不到上界
    std::uniform_real_distribution<double> u(0.0, 1.0);
    double mx = -1.0;
    for (int i = 0; i < 100000; i++) { double v = u(gen); if (v > mx) mx = v; }
    std::printf("\nuniform_real_distribution(0.0, 1.0) 十万次的最大值：%.10f（小于 1）\n", mx);

    return 0;
}
```

`uniform_int_distribution<int>(0, 99)` 给出的是 `0..99` 共 100 个值，
写 `(0, 100)` 就成了 101 个值。

## 4.4 为什么不用 `rand`

`rand()` 能用，C 那一半（《07-标准库/A-03-数值、数学与随机.md》第 4 节）
也讲了它的分布直方图。**问题在于直方图看不出它的缺陷。**
下面两个程序先作一次直方图对照，再测出它真正的短处。

`C++`

```cpp
/* rand_vs_mt.cpp    编译：g++ -std=c++17 rand_vs_mt.cpp -o rand_vs_mt */
#include <cstdio>
#include <cstdlib>
#include <random>
#include <vector>

const int N = 100000;

// 0..99 分成 10 个桶，统计频数并算卡方（自由度 9，5% 临界值 16.92）
void hist100(const char *title, const std::vector<int> &v) {
    int bin[10] = {0};
    for (int x : v) bin[x / 10]++;
    std::printf("%s\n", title);
    std::printf("  区间起点  ");
    for (int i = 0; i < 10; i++) std::printf("%7d", i * 10);
    std::printf("\n  频数      ");
    for (int i = 0; i < 10; i++) std::printf("%7d", bin[i]);
    double chi = 0.0;
    const double e = N / 10.0;
    for (int i = 0; i < 10; i++) { double d = bin[i] - e; chi += d * d / e; }
    std::printf("\n  卡方 = %.2f\n", chi);
}

int main() {
    std::printf("RAND_MAX = %d\n\n", RAND_MAX);

    std::srand(12345);
    std::vector<int> r(N);
    for (int i = 0; i < N; i++) r[i] = std::rand() % 100;
    hist100("rand() % 100：", r);

    std::mt19937 gen(12345);
    std::uniform_int_distribution<int> d(0, 99);
    std::vector<int> m(N);
    for (int i = 0; i < N; i++) m[i] = d(gen);
    hist100("mt19937 + uniform_int_distribution(0, 99)：", m);

    return 0;
}
```

一个生成器在粗粒度统计上合格，仍然可能在其他方面不合格。
`rand()` 真正的短处在下面四处，每一处都能直接测出来。

**短处一：位宽。** 本机 `RAND_MAX` 是 32767，**只有 15 位**，
一共 32768 个可能取值。用它造浮点数，值的个数被这个上限卡死。

`C++`

```cpp
/* rand_bias.cpp    编译：g++ -std=c++17 rand_bias.cpp -o rand_bias */
#include <algorithm>
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <random>
#include <vector>

// 穷举 0..RAND_MAX 这 RAND_MAX+1 个取值除以 m 的余数，不是抽样
void residue(const char *title, int m) {
    std::vector<int> cnt(m, 0);
    for (int v = 0; v <= RAND_MAX; v++) cnt[v % m]++;
    int lo = cnt[0], hi = cnt[0];
    for (int c : cnt) { if (c < lo) lo = c; if (c > hi) hi = c; }
    std::printf("%-14s 余数最少的取 %d 次，最多的取 %d 次，相差 %.2f%%\n",
                title, lo, hi, 100.0 * (hi - lo) / lo);
}

int main() {
    std::printf("RAND_MAX = %d，即 rand() 一共只有 %d 个可能取值\n\n", RAND_MAX, RAND_MAX + 1);

    residue("rand() % 100：", 100);
    residue("rand() % 1000：", 1000);

    // 用它造 [0,1) 的浮点数，精度受限于整数取值个数
    const int N = 200000;
    std::vector<bool> seen(RAND_MAX + 1, false);
    std::srand(1);
    for (int i = 0; i < N; i++) seen[std::rand()] = true;
    int n1 = 0;
    for (bool b : seen) if (b) n1++;
    std::printf("\nrand()/(RAND_MAX+1.0) 抽 %d 次，取到的不同值：%d 个（上限 %d）\n",
                N, n1, RAND_MAX + 1);

    // mt19937 + uniform_real_distribution 的取值个数
    std::mt19937 gen(1);
    std::uniform_real_distribution<double> u(0.0, 1.0);
    std::vector<unsigned long long> bits;
    bits.reserve(N);
    for (int i = 0; i < N; i++) {
        double d = u(gen);
        unsigned long long b;
        std::memcpy(&b, &d, sizeof b);          // 按位比较，避免浮点相等
        bits.push_back(b);
    }
    std::sort(bits.begin(), bits.end());        // 排序只为数不同值，容器与算法本身归 08 板块
    bits.erase(std::unique(bits.begin(), bits.end()), bits.end());
    std::printf("uniform_real_distribution 抽 %d 次，取到的不同值：%d 个\n", N, (int)bits.size());
    return 0;
}
```

**短处二：取模偏差，而且它是结构性的，不用抽样就能算出来。**
`32768` 除以 `1000` 除不尽，因此 `rand() % 1000` 的 1000 个余数里，
有一部分比另一部分多算了一次——**相差 3.12%，不是随机波动**。
`uniform_int_distribution` 内部用的是拒绝采样：取到超出范围的值就丢掉重取，
**结果在数学上是均匀的**。

**短处三：精度。** 20 万次抽样里，`rand()` 造出的 `[0,1)` 浮点数
只有 32692 个不同的值（上限 32768，其中有 76 个没被抽到），
而 `uniform_real_distribution` 给出 20 万个互不相同的值——
**后者按 53 位有效位生成，前者只有 15 位。**

**短处四：不可移植。** 同一个 `srand(12345)`，两个平台的 `rand()`
给出完全不同的序列。

## 4.5 可复现性：引擎是标准规定的

`mt19937` 不是「某个库的实现」，**它的算法与输出序列写进了标准**。
同一个种子，在任何符合标准的实现上都给出同一串数字。

`C++`

```cpp
/* seed_repro.cpp    编译：g++ -std=c++17 seed_repro.cpp -o seed_repro */
#include <cstdio>
#include <random>

template <class E>
void first5(const char *name, E e) {
    std::printf("%-18s", name);
    for (int i = 0; i < 5; i++) std::printf(" %10u", (unsigned)e());
    std::printf("\n");
}

int main() {
    std::mt19937 a(42), b(42), c(43);
    first5("mt19937(42) 第1次", a);
    first5("mt19937(42) 第2次", b);
    first5("mt19937(43)", c);

    std::mt19937_64 d(42), e(42);
    first5("mt19937_64(42) 1", d);
    first5("mt19937_64(42) 2", e);

    std::default_random_engine f(1), g(1);
    first5("default_engine(1)", f);
    first5("default_engine(1)", g);
    return 0;
}
```

| 两个模块互不影响 | 各持有自己的引擎对象，不要共用全局状态 |

## 4.6 `random_device` 的用途

`random_device` 不是引擎，是**「向操作系统要一个真随机数」的接口**。
它最常见的用途只有一个：**给引擎取种子**。

`C++`

```cpp
/* rd_seed.cpp    编译：g++ -std=c++17 rd_seed.cpp -o rd_seed */
#include <cstdio>
#include <random>

int main() {
    std::random_device rd;
    std::printf("random_device 的 entropy()：%d\n", (int)rd.entropy());
    std::printf("这一次运行取到的四个值：%u %u %u %u\n", rd(), rd(), rd(), rd());

    // 正确的用法：拿它取种子，再用引擎产生大量随机数
    std::mt19937 gen(rd());
    std::printf("用这个种子建引擎，第一个输出：%u\n", (unsigned)gen());
    return 0;
}
```

`实测数据`
`Text`

```text
第一次运行                                     第二次运行
random_device 的 entropy()：0                  random_device 的 entropy()：0
这一次运行取到的四个值：                        这一次运行取到的四个值：
  748311638 3339546136 3448484452 3761728102     1048558551 148924003 3980895844 1385760356
```

**两次运行的值完全不同，但 `entropy()` 两次都返回 0。**
本机的 libstdc++ 实现里这个函数不反映真实情况，
**因此不要用 `entropy()` 判断「有没有随机源」**——
判断办法只有一个：连跑两次，比较结果是否相同。**这次实测的结果是：值确实是随机的。**
`待确认`：`<VS>` 的 STL 上 `random_device` 的行为与 `entropy()` 的取值未在本机验证。

> [!TIP]
> **不要每次要随机数都新建一个 `random_device`。**
> 它每次调用都要问一次操作系统，比引擎慢几个数量级。
> 正确做法是**建一个引擎、用 `random_device` 喂它一次种子**，
> 之后一直用这个引擎。

## 4.7 写错了会怎样

| 写法 | 后果 |
|---|---|
| `std::uniform_int_distribution<int> d(0, 100)` 想取 `0..99` | 多出一个值 `100`，且概率与其他值相同 |
| 每次循环都 `std::mt19937 gen(rd())` | 循环极快时可能拿到相同的种子，产生重复序列 |
| `gen() % 100` 直接对引擎取模 | 回到 `rand` 的取模偏差，尽管引擎质量更好 |
| 把引擎按值传给函数 | 每次拷贝 2504 字节，而且函数内的推进不影响调用方 |
| 用 `default_random_engine` 却指望跨平台一致 | 它由实现决定，本机是 `minstd_rand0` |
| 用 `rand()` 的种子 `srand(1)` 初始化 `mt19937` | 种子相同不代表序列相同，这是两套算法 |

> [!NOTE]
> **第 4 节小结**：`<random>` 把随机数拆成「种子、引擎、分布」三件，
> 每一件都能单独替换。**引擎选 `mt19937`（或 `mt19937_64`）并写明种子，
> 序列在所有符合标准的实现上一致**；分布负责取值形状，
> **整数分布两端都包含、浮点分布取不到上界**。
> **`rand()` 的问题不是「分布不好看」，而是位宽只有 15 位、
> 取模偏差是结构性的、且跨平台不可复现。**

# 第 5 节 `<numeric>`：一批小算法

## 5.1 这个头文件管什么

`<numeric>` 装的是「对一串数做累计运算」的工具。它和 `09-高阶数据结构`
板块的算法库分工不同：

| 归 `<numeric>`（本章节） | 归 `09-高阶数据结构` |
|---|---|
| 求和、求积、前缀和、差分 | 排序、查找、划分 |
| 内积 | 去重、重排、集合运算 |
| 连续整数填充（`iota`） | 复制、变换、遍历 |
| 最大公约数与最小公倍数 | 堆操作、排列 |

**判断标准**：**这个算法是不是「把一串数合成一个数」或「按位置累计」**——
是就归 `<numeric>`。

## 5.2 常用件

`C++`

```cpp

#include <functional>

template <class T>

    std::printf("accumulate 求积            ：%d\n", std::accumulate(v.begin(), v.end(), 1, std::multiplies<int>()));
    std::printf("reduce 求和（顺序不保证）  ：%d\n", std::reduce(v.begin(), v.end(), 0));
    std::printf("reduce 求积                ：%d\n", std::reduce(v.begin(), v.end(), 1, std::multiplies<int>()));

    dump("partial_sum 前缀和：", p);

    std::vector<int> diff(v.size());

    std::printf("inner_product(v, v, 0)     ：%d\n", std::inner_product(v.begin(), v.end(), v.begin(), 0));

    std::printf("gcd(24, 36) = %d，lcm(4, 6) = %d\n", std::gcd(24, 36), std::lcm(4, 6));
    std::printf("gcd(0, 5) = %d，gcd(-24, 36) = %d，lcm(-4, 6) = %d\n",
                std::gcd(0, 5), std::gcd(-24, 36), std::lcm(-4, 6));
```


几处细节：

**`accumulate` 与 `reduce` 的差别只有一个：顺序。**
`accumulate` 保证从左到右依次累加；`reduce` 允许任意顺序，
**因此它是为并行执行准备的**（C++17 起可以传执行策略）。
浮点求和时这个差别会体现在结果上——**加法不满足结合律**，
换一个累加顺序最后几位就不同。

**`partial_sum` 与 `adjacent_difference` 互为反运算。**
`adjacent_difference` 的第一个输出是第一个输入本身（所以那 6 个 1 前面
还有一个 1，输出是 `1 1 1 1 1 1`——第一个元素与输入的 `1` 相同）。

**`iota` 负责「填充」而不是「合并」**：`std::iota(first, last, 1)` 从 1 开始逐个自增填满整个区间，用来生成下标或给条目编号，**它不能设步长**，要别的步长就须自行写循环。

**`gcd` 与 `lcm` 的结果永远非负，且 `lcm` 的实参不能为零**：
`gcd(0, 5)` 是 5（0 与任何数的最大公约数是那个数本身），
但 `lcm(0, 5)` 是 0，而两者都为零时按标准是未定义行为。

C++17 又给 `<numeric>` 补了几个为并行准备的算法，用法与 `accumulate` 一致，
只是把「顺序不保证」写进了名字里；C++20 再加了一个不会溢出的中点：

| 算法 | 做什么 | 起点 |
|---|---|---|
| `std::reduce` | `accumulate` 的无序版本，可传执行策略 | C++17 |
| `std::transform_reduce` | 先变换再归约，一次写完「先映射、后求和」 | C++17 |
| `std::inclusive_scan` | 前缀和（含当前位置），`partial_sum` 的并行版本 | C++17 |
| `std::exclusive_scan` | 前缀和（**不含**当前位置），要额外给一个初值 | C++17 |
| `std::transform_inclusive_scan` / `transform_exclusive_scan` | 先变换再求前缀和 | C++17 |
| `std::midpoint` | 两个数（或两个指针）的中点，**不会溢出** | C++20 |

`C++`

```cpp
/* numeric_scan.cpp    编译：g++ -std=c++17 numeric_scan.cpp -o numeric_scan */
#include <cstdio>
#include <functional>
#include <numeric>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3, 4, 5, 6};
    std::vector<int> inc(v.size()), exc(v.size());
    std::inclusive_scan(v.begin(), v.end(), inc.begin());
    std::exclusive_scan(v.begin(), v.end(), exc.begin(), 0);   // 初值写在最后

    std::printf("v            :");
    for (int x : v) std::printf(" %d", x);
    std::printf("\ninclusive    :");
    for (int x : inc) std::printf(" %d", x);
    std::printf("\nexclusive    :");
    for (int x : exc) std::printf(" %d", x);

    // 先平方再求和，一次写完
    std::printf("\ntransform_reduce: %d\n",
                std::transform_reduce(v.begin(), v.end(), 0,
                                      std::plus<int>(), [](int x) { return x * x; }));
    return 0;
}
```

`实测数据`
`Text`

```text
v            : 1 2 3 4 5 6
inclusive    : 1 3 6 10 15 21
exclusive    : 0 1 3 6 10 15
transform_reduce: 91
```

**`exclusive_scan` 比 `inclusive_scan` 多一个实参**：那个初值占掉输出的第一个位置，
因此输出比输入「往后错一位」。**两者的长度都与输入相同**，
所以输出容器照样要提前开好同样大小——这一点与 `partial_sum`（第 5.2 小节）一致。

> [!WARNING]
> **`std::lcm` 的结果可能溢出。** `lcm(a, b)` 内部算的是
> `a / gcd(a, b) * b`，两个大数的最小公倍数很容易超出 `int` 的范围，
> 而这种溢出是有符号溢出——**未定义行为**。

## 5.3 `accumulate` 的初值类型

**初值决定了整个累加过程的类型**，这一条是 `<numeric>` 里最容易出错的地方。

`C++`

```cpp
/* accum_wrong.cpp    编译：g++ -std=c++17 -Wconversion accum_wrong.cpp -o accum_wrong */
#include <cstdio>
#include <numeric>
#include <vector>

int main() {
    std::vector<double> v{1.9, 2.9, 3.9};

    double right = std::accumulate(v.begin(), v.end(), 0.0);   // 初值是 double
    double wrong = std::accumulate(v.begin(), v.end(), 0);     // 初值是 int：每一步都被截断

    std::printf("正确（初值 0.0）：%.2f\n", right);
    std::printf("错误（初值 0）  ：%.2f\n", wrong);
    return 0;
}
```

`实测数据`
`Text`

```text
正确（初值 0.0）：8.70
错误（初值 0）  ：6.00
```

**`8.70` 变成 `6.00`，而且没有报错。** 原因在于 `accumulate` 的返回类型
就是初值的类型：初值写 `0`，整个过程就在 `int` 里做，
`1.9 + 0` 得到 `1.9`，赋回 `int` 变成 `1`，下一步再从这个 `1` 开始。

**更麻烦的是编译器不报警告**：

`C++`

```cpp
/* accum_hand.cpp    编译：g++ -std=c++17 -Wconversion accum_hand.cpp -o accum_hand */
#include <cstdio>
#include <numeric>
#include <vector>

int main() {
    std::vector<double> v{1.9, 2.9, 3.9};

    // 手写同样的事：这里有警告
    int hand = 0;
    for (double d : v) hand += d;

    // 交给 accumulate：同一个转换，编译器一声不响
    double acc = std::accumulate(v.begin(), v.end(), 0);

    std::printf("手写循环  ：%d\n", hand);
    std::printf("accumulate：%.2f\n", acc);
    return 0;
}
```

`实测数据`
`Text`

```text
accum_hand.cpp:11:29: warning: conversion from 'double' to 'int' may change value [-Wfloat-conversion]
   11 |     for (double d : v) hand += d;
      |                        ~~~~~^~~~

手写循环  ：6
accumulate：6.00
```

**同一个转换，手写循环有警告，`accumulate` 那行没有。**
原因是那个转换发生在 `<numeric>` 头文件里的模板实例化中，
而 gcc 默认不报系统头文件里的警告。**结果就是一处静默的数值错误。**

> [!IMPORTANT]
> **`accumulate`、`reduce`、`inner_product` 的初值必须写成目标类型。**
> 求 `double` 的和就写 `0.0`，求 `long long` 的和就写 `0LL`。
> 这一个字符决定了整个累加的精度。

> [!NOTE]
> **第 5 节小结**：`<numeric>` 管的是「把一串数合成一个数」或
> 「按位置累计」，与 `09-高阶数据结构` 板块的排序查找分开。
> **`accumulate` 与 `reduce` 的差别是顺序保证**；
> **初值的类型决定整个累加的精度，写错不报错**；
> `gcd`/`lcm` 结果非负，但 `lcm` 可能溢出。

# 第 6 节 `<complex>` 与 `<valarray>`

这两个头文件用得少，但都属于「数值」这一族，列在这里备查。

`<complex>` 提供复数类型，**它的价值在于把 `(a, b)` 这样的成对运算
写成一个数**：加减乘除、模、共轭、指数、对数、三角都有定义。

`<valarray>` 是「逐元素运算」的数组：**运算符直接作用于整个数组**，
不需要写循环。它曾经被期望成为数值计算的主力，
但实践中被专门的数值库取代，标准库里的这个版本功能有限
（没有矩阵、没有切片赋值的高效实现）。

`C++`

```cpp
/* complex_valarray.cpp    编译：g++ -std=c++17 complex_valarray.cpp -o complex_valarray */
#include <complex>
#include <cstdio>
#include <valarray>

int main() {
    const double pi = 3.14159265358979323846;

    std::complex<double> a(1.0, 2.0), b(3.0, -1.0);
    std::printf("a + b       = (%.1f, %.1f)\n", (a + b).real(), (a + b).imag());
    std::printf("a * b       = (%.1f, %.1f)\n", (a * b).real(), (a * b).imag());
    std::printf("|a|         = %.4f\n", std::abs(a));
    std::printf("conj(a)     = (%.1f, %.1f)\n", std::conj(a).real(), std::conj(a).imag());
    std::complex<double> e = std::exp(std::complex<double>(0.0, pi));
    std::printf("exp(i*pi)   = (%.3e, %.3e)\n", e.real(), e.imag());

    std::valarray<double> v = {1.0, 2.0, 3.0, 4.0};
    std::valarray<double> w = v * 2.0 + 1.0;              // 逐元素运算，不需要循环
    std::printf("\nw           = %.1f %.1f %.1f %.1f\n", w[0], w[1], w[2], w[3]);
    std::printf("sum = %.1f，max = %.1f，min = %.1f\n", w.sum(), w.max(), w.min());
    return 0;
}
```

`实测数据`
`Text`

```text
a + b       = (4.0, 1.0)
a * b       = (5.0, 5.0)
|a|         = 2.2361
conj(a)     = (1.0, -2.0)
exp(i*pi)   = (-1.000e+00, 1.225e-16)

w           = 3.0 5.0 7.0 9.0
sum = 24.0，max = 9.0，min = 3.0
```

**`exp(i*pi)` 的实部是 `-1.000`、虚部是 `1.225e-16` 而不是 0。**
这是浮点误差，不是 `complex` 的缺陷：`pi` 本身就是一个近似值，
它的正弦不是精确的 0。**判断复数结果是否为零要用模长与容差**
（第 3 节），不能用 `== 0`。

> [!TIP]
> **这两个头文件不必花时间精通。** 需要复数时用 `<complex>`，
> 需要逐元素数组运算时优先考虑普通容器加算法（`09-高阶数据结构` 板块），
> `<valarray>` 只在维护老代码时遇到。

# 第 7 节 速查表

| 常用件 | 一句话用途 | 典型坑 |
|---|---|---|
| `std::numeric_limits<T>::max()` | 类型的最大值 | 浮点上 `min()` 是最小正数，最小值要用 `lowest()` |
| `...::max_digits10` | 打印浮点要用的位数 | `double` 是 17，写 `%.6f` 会丢信息 |
| `...::is_signed` / `is_integer` | 泛型代码里按类型分支 | 不要用 `sizeof` 猜 |
| `std::sqrt` / `pow` / `fabs` | 数学函数 | 返回类型跟着实参走；出错返回 NaN 并设 `errno` |
| `std::isnan` / `isinf` | 判断特殊值 | `x == NaN` 永远为假；`-ffast-math` 下恒为假 |
| `std::numeric_limits<double>::epsilon()` | 机器精度 | 它是相对误差的基准，不是通用的绝对容差 |
| `std::abs` | 取绝对值 | 无符号实参编译失败；`abs(INT_MIN)` 结果为负 |
| `std::mt19937` | 默认选它当引擎 | 本机 2504 字节，不要按值传 |
| `std::uniform_int_distribution` | 整数均匀分布 | **两端都包含** |
| `std::normal_distribution` | 正态分布 | 参数是均值与标准差 |
| `std::random_device` | 取一个真随机种子 | 用它喂一次引擎就够，不要每次调用 |
| `std::accumulate` | 求和/求积，顺序固定 | **初值类型决定精度**，写错不报错 |
| `std::reduce` | 同上，顺序不保证 | 浮点结果可能与 `accumulate` 差最后几位 |
| `std::partial_sum` | 前缀和 | 输出容器要提前开好大小 |
| `std::inner_product` | 内积 | 初值类型同样决定精度 |
| `std::gcd` / `std::lcm` | 最大公约数/最小公倍数 | `lcm` 可能溢出；两参为零是未定义行为 |
| `std::complex` | 复数 | 结果判零要用容差 |

**配套示例见 [`B-examples/07-standard-library/05-cpp-numeric-random/`](../B-examples/07-standard-library/05-cpp-numeric-random/)，配套练习见 [`C-templates/07-standard-library/05-cpp-numeric-random/`](../C-templates/07-standard-library/05-cpp-numeric-random/)。**
示例把本章节的四件事串成一个程序：用 `mt19937` 造数据、
用 `<numeric>` 统计、用直方图检查分布、用 `steady_clock` 计时。
