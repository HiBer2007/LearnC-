# 第 1 节 `<math.h>`：把数学函数当普通函数用

## 1.1 一个函数三个版本

`<math.h>` 里几乎每个函数都有三份：

| 后缀 | 参数与返回类型 | 例 |
|---|---|---|
| 无后缀 | `double` | `sqrt`、`pow`、`fabs` |
| `f` | `float` | `sqrtf`、`powf`、`fabsf` |
| `l` | `long double` | `sqrtl`、`powl`、`fabsl` |

**它们不是重载。** C 里没有重载，所以只能靠名字区分；
C++ 里 `<cmath>` 提供了重载版本，写 `std::sqrt(2.0f)` 会自动选 `float` 那份
（见《05-类与面向对象/08-多态：重载、虚函数与它们的分工.md》第 2 节）。

**C 里另有一个 `<tgmath.h>`**，它把上面这些名字变成泛型宏：
写 `sqrt(x)` 时按 `x` 的类型自动选 `sqrtf`/`sqrt`/`sqrtl`。
C++ 里不需要它，重载已经解决了同一个问题。

**这一节只讲 `double` 版**，`float` 版与 `long double` 版只是把类型换个位置。

`实测数据`
`C`

```c
/* math_three.c    编译：gcc -std=c23 math_three.c -o math_three */
#include <stdio.h>
#include <math.h>

int main(void) {
    float       xf = 2.0f;
    double      xd = 2.0;
    long double xl = 2.0L;
    printf("sizeof(float)=%zu  sizeof(double)=%zu  sizeof(long double)=%zu\n",
           sizeof xf, sizeof xd, sizeof xl);
    printf("sqrtf(2.0f)  = %.9g\n",  (double)sqrtf(xf));
    printf("sqrt(2.0)    = %.17g\n", sqrt(xd));
    printf("sqrtl(2.0L)  = %.21Lg\n", sqrtl(xl));
    printf("powl(2.0L,10.0L) = %.21Lg\n", powl(2.0L, 10.0L));
    /* 三份函数名字不同，传错类型不报错：double 会先被截成 float */
    printf("sqrtf(2.0)   = %.9g   （实参先转成 float，再算）\n", (double)sqrtf(2.0));
    return 0;
}
```

`实测数据`
`Text`

```text
sizeof(float)=4  sizeof(double)=8  sizeof(long double)=16
sqrtf(2.0f)  = 1.41421354
sqrt(2.0)    = 1.4142135623730951
sqrtl(2.0L)  = 1.41421356237309504876
powl(2.0L,10.0L) = 1024
sqrtf(2.0)   = 1.41421354   （实参先转成 float，再算）
```

**三行有效位数分别是 9 位、17 位、21 位**，对应 `float` 的 24 位尾数、
`double` 的 53 位、`long double` 的 64 位。**最后一行尤其值得注意**：
`sqrtf` 只认 `float`，传一个 `double` 进去不会报错，精度在调用前就丢了。
写 `sqrtf(2.0)` 与写 `sqrtf(2.0f)` 编译结果相同，看不出问题。

## 1.2 常用函数与它们的真实输出

`实测数据`
`C`

```c
/* math_basic.c    编译：gcc -std=c23 math_basic.c -o math_basic */
#include <stdio.h>
#include <math.h>

int main(void) {
    printf("sqrt(2.0)      = %.17g\n", sqrt(2.0));
    printf("sqrtf(2.0f)    = %.9g\n", (double)sqrtf(2.0f));
    printf("pow(2.0, 10.0) = %.17g\n", pow(2.0, 10.0));
    printf("fabs(-3.5)     = %.17g\n", fabs(-3.5));
    printf("fmod(7.5, 2.0) = %.17g\n", fmod(7.5, 2.0));
    printf("floor(-2.5)    = %.17g\n", floor(-2.5));
    printf("ceil(-2.5)     = %.17g\n", ceil(-2.5));
    printf("trunc(-2.5)    = %.17g\n", trunc(-2.5));
    printf("round(-2.5)    = %.17g\n", round(-2.5));
    printf("round(2.5)     = %.17g\n", round(2.5));
    printf("rint(2.5)      = %.17g\n", rint(2.5));
    printf("nearbyint(2.5) = %.17g\n", nearbyint(2.5));
    printf("exp(1.0)       = %.17g\n", exp(1.0));
    printf("log(e)         = %.17g\n", log(2.718281828459045));
    printf("log10(1000.0)  = %.17g\n", log10(1000.0));
    printf("sin(1.0)       = %.17g\n", sin(1.0));
    printf("hypot(3.0,4.0) = %.17g\n", hypot(3.0, 4.0));
    return 0;
}
```

`实测数据`
`Text`

```text
sqrt(2.0)      = 1.4142135623730951
sqrtf(2.0f)    = 1.41421354
pow(2.0, 10.0) = 1024
fabs(-3.5)     = 3.5
fmod(7.5, 2.0) = 1.5
floor(-2.5)    = -3
ceil(-2.5)     = -2
trunc(-2.5)    = -2
round(-2.5)    = -3
round(2.5)     = 3
rint(2.5)      = 2
nearbyint(2.5) = 2
exp(1.0)       = 2.7182818284590451
log(e)         = 1
log10(1000.0)  = 3
sin(1.0)       = 0.8414709848078965
hypot(3.0,4.0) = 5
```

**表中有三处需要单独说明。**

**第一处：`fmod` 不是 `%`。** `%` 只对整数合法，`7.5 % 2.0` 是编译错误。
`fmod` 做的是浮点取余，符号跟着被除数走：`fmod(-7.5, 2.0)` 是 `-1.5`。

**第二处：四个「取整」的函数含义不同。**

| 函数 | 规则 | `-2.5` | `2.5` |
|---|---|---|---|
| `trunc` | 朝零截断 | `-2` | `2` |
| `floor` | 朝负无穷 | `-3` | `2` |
| `ceil` | 朝正无穷 | `-2` | `3` |
| `round` | 远离零，逢五进位 | `-3` | `3` |
| `rint` / `nearbyint` | 按当前舍入模式（默认最近偶数） | `-2` | `2` |

`rint` 与 `nearbyint` 的差别只在「舍入不精确时要不要置 `FE_INEXACT` 标志」，
数值结果相同。

**第三处：`sqrt(2.0)` 打印 17 位是 `1.4142135623730951`，正好是 `double` 能表示的那个数。**
`double` 有 53 位有效二进制位，换算成十进制是 15 到 17 位
（`DBL_DIG` 是 15，`DECIMAL_DIG` 是 17 到 21，见第 2 节）。
**用 `%f` 打印默认只有 6 位小数**，看不出精度差别，要 17 位就得写 `%.17g`。

> [!TIP]
> **打印浮点数时用 `%.17g` 而不是 `%f`。**
> `%f` 固定 6 位小数，`1e300` 会打印出一行 300 多位的数字；
> `%g` 自动在定点与科学计数法之间选，`%.17g` 保证 `double` 不丢信息。

## 1.3 链接时要加 `-lm` 吗

**这个问题被反复转述，结论是：取决于平台，而在多数平台上加不加都一样。**

先看本机（Windows，GCC 15.2.0，MinGW-w64）：

`Bash`

```bash
gcc -std=c23 math_basic.c -o math_basic        # 不加 -lm
gcc -std=c23 -lm math_basic.c -o math_basic    # 加 -lm
```

`实测数据`
`Text`

```text
两条命令都编译链接成功，两个可执行文件的输出完全相同
```

**MinGW-w64 上没有单独的 `libm`。** `gcc -print-file-name=libm.a` 原样返回 `libm`，
意思是找不到这个文件；数学函数在 `msvcrt.dll` 里，随 C 运行库一起进来，
所以本机加不加 `-lm` 完全一样。

**在 Linux 上，这件事的结论容易被传错。**
glibc 的 `libm.so.6` 至今仍是一个独立的库（本机 glibc 2.39 上是 952616 字节），
但不加 `-lm` **也可能**链接成功，取决于编译器有没有把这次调用在编译期算成常量：

`实测数据`
`C`

```c
/* math_link.c    编译：gcc -std=c23 math_link.c -o math_link */
#include <stdio.h>
#include <math.h>

int main(void) {
    /* 实参是编译期常量：前端直接算出结果，不引用 libm 里的符号 */
    printf("sqrt(2.0) = %.17g\n", sqrt(2.0));
    printf("sin(1.0)  = %.17g\n", sin(1.0));
    return 0;
}
```

`实测数据`
`Bash`

```bash
# 实参是常量：GCC 在编译期就算完了，不加 -lm 也能链接
gcc -std=c2x math_link.c -o math_link

# 实参是变量（math_three.c 里的那三个）：真的引用 libm，不加 -lm 就失败
gcc -std=c2x -O0 math_three.c -o math_three
```

`实测数据`
`Text`

```text
/usr/bin/ld: math_three.c:(.text+0x5a): undefined reference to `sqrtf'
/usr/bin/ld: math_three.c:(.text+0x8e): undefined reference to `sqrt'
/usr/bin/ld: math_three.c:(.text+0xb7): undefined reference to `sqrtl'
collect2: error: ld returned 1 exit status
```

**把 `-O0` 换成 `-O2`，同一个 `math_three.c` 不加 `-lm` 又能链接上**：
常量传播把三个变量都算成了常量，目标文件里再没有 `libm` 符号
（`nm -u` 的输出里看不到 `sqrt`）。
**一个随手的 `sqrt(2.0)` 试不出真相，这正是「Linux 不需要 `-lm`」流传开的原因。**

| 情形 | 做法 |
|---|---|
| 只在本机（Windows + MinGW）编译 | 加不加都行 |
| 目标含 Linux 或其它 glibc 平台 | **必须加**，否则可能报 `undefined reference to 'sqrt'` |
| 用 CMake | 写 `target_link_libraries(app PRIVATE m)`，CMake 在 Windows 上会自动忽略它 |

> [!IMPORTANT]
> **加 `-lm` 不会有害，不加可能有害。** 跨平台的构建脚本一律加上，
> 是成本最低的选择。

**还有一个与 `-lm` 有关、但更容易出错的问题：库要放在源文件后面。**

`实测数据`
`Bash`

```bash
# 对的：库排在源码后面，链接器扫到源码时才知道有谁需要它
gcc -std=gnu23 t5_ts.c -o t5_ts -lwinpthread
# 错的：库排在源码前面，链接器扫过它时还不知道有谁需要它
gcc -std=gnu23 -lwinpthread t5_ts.c -o t5_ts
```

`实测数据`
`Text`

```text
ld.exe: t5_ts.c:(.text+0x66): undefined reference to `clock_gettime64'
collect2.exe: error: ld returned 1 exit status
```

**链接器从左到右扫一遍命令行，遇到库就把「当前还未解决的符号」在里面找一遍。**
库排在源码前面时，源码里的符号还没被扫到，后面再出现的符号就没有库可用了
（规则见《01-编译器/01-编译与链接.md》第 2.5 小节）。

> [!WARNING]
> **`-lxxx` 一律写在源文件与 `.o` 文件之后。**
> `gcc -lm a.c` 在本机不报错，是因为本机压根没有需要 `-lm` 解析的符号。

## 1.4 出错了怎么知道：`errno` 与特殊值

**数学函数不用返回值报错。** 原因很直接：返回值可能不够用——
`sqrt` 定义在整个非负实数上，没有一个值适合表示「传入了负数」。

标准规定了两条通道，宏 `math_errhandling` 说明哪一条在起作用：

`文档`

> "The macros MATH_ERRNO MATH_ERREXCEPT expand to the integer constants 1 and 2,
> respectively; the macro math_errhandling expands to an expression that has type
> int and the value MATH_ERRNO, MATH_ERREXCEPT, the bitwise OR of both, or 0; the
> value shall not be 0 in a hosted implementation."
>
> —— N3220 §7.12/20

**本机的 MinGW 没有定义这三个宏**，这一点与实际行为不一致：

`实测数据`
`C`

```c
/* math_err.c    编译：gcc -std=c23 math_err.c -o math_err （失败） */
#include <stdio.h>
#include <math.h>
#include <fenv.h>

int main(void) {
    printf("math_errhandling = %d\n", math_errhandling);
    return 0;
}
```

`实测数据`
`Text`

```text
error: 'math_errhandling' undeclared (first use in this function)
    |            ^~~~~~~~~~~~~~~~
note: each undeclared identifier is reported only once for each function it appears in
error: 'MATH_ERRNO' undeclared (first use in this function)
error: 'MATH_ERREXCEPT' undeclared (first use in this function)
```

**报错并不意味着没有 errno 通道。** 把宏换成条件编译，实际行为就出来了：

`实测数据`
`C`

```c
/* math_errno.c    编译：gcc -std=c23 math_errno.c -o math_errno */
#include <stdio.h>
#include <errno.h>
#include <math.h>
#include <fenv.h>

int main(void) {
#ifdef math_errhandling
    printf("math_errhandling = %d（MATH_ERRNO=%d MATH_ERREXCEPT=%d）\n",
           math_errhandling, MATH_ERRNO, MATH_ERREXCEPT);
#else
    printf("本机 <math.h> 没有定义 math_errhandling\n");
#endif
    errno = 0;
    double a = sqrt(-1.0);
    printf("sqrt(-1.0) = %g, errno = %d (%s)\n", a, errno,
           errno == EDOM ? "EDOM" : errno == 0 ? "没设置" : "其它");
    errno = 0;
    double b = log(0.0);
    printf("log(0.0)   = %g, errno = %d (%s)\n", b, errno,
           errno == ERANGE ? "ERANGE" : errno == 0 ? "没设置" : "其它");
    errno = 0;
    double c = exp(1000.0);
    printf("exp(1000)  = %g, errno = %d\n", c, errno);
    printf("EDOM=%d ERANGE=%d EINVAL=%d\n", EDOM, ERANGE, EINVAL);
    return 0;
}
```

`实测数据`
`Text`

```text
本机 <math.h> 没有定义 math_errhandling
sqrt(-1.0) = nan, errno = 33 (EDOM)
log(0.0)   = -inf, errno = 34 (ERANGE)
exp(1000)  = inf, errno = 34
EDOM=33 ERANGE=34 EINVAL=22
```

**同一个程序在 glibc 上跑，宏是有的：**

`实测数据`
`Text`

```text
math_errhandling = 3 (MATH_ERRNO=1 MATH_ERREXCEPT=2)
sqrt(-1.0) = -nan, errno = 33 (EDOM)
log(0.0)   = -inf, errno = 34 (ERANGE)
```

> [!IMPORTANT]
> **`errno` 只有在清零之后才有意义。**
> 标准没有规定成功的函数要把 `errno` 清成 0，
> 因此「调用之后看 `errno` 是不是 0」这个写法是错的——
> 必须先 `errno = 0`，再调用，再看。
> `errno` 本身的用法见《07-标准库/A-05-工具与其它：stdlib 与杂项.md》第 7 节。

### 1.4.1 特殊值：`NAN`、`INFINITY` 与 `fpclassify`

浮点数里有两个「不是普通数字」的东西：**NaN**（不是一个数）与**无穷**。
`<math.h>` 提供宏 `NAN` 与 `INFINITY`，以及一组判断函数。

`实测数据`
`C`

```c
/* math_special.c    编译：gcc -std=c23 math_special.c -o math_special */
#include <stdio.h>
#include <math.h>

int main(void) {
    double zero = 0.0;
    printf("1.0/0.0      = %g\n", 1.0 / zero);
    printf("NAN          = %g, INFINITY = %g\n", (double)NAN, (double)INFINITY);
    printf("isnan(NAN)=%d isinf(INF)=%d isfinite(1.0)=%d signbit(-0.0)=%d\n",
           isnan(NAN) != 0, isinf(INFINITY) != 0, isfinite(1.0) != 0, signbit(-0.0) != 0);
    printf("NAN == NAN   -> %d\n", NAN == NAN);
    double vals[] = {NAN, INFINITY, 0.0, 5e-324, 1.0};
    for (int i = 0; i < 5; i++)
        printf("fpclassify(%-10g) = %d\n", vals[i], fpclassify(vals[i]));
    printf("FP_NAN=%d FP_INFINITE=%d FP_ZERO=%d FP_SUBNORMAL=%d FP_NORMAL=%d\n",
           FP_NAN, FP_INFINITE, FP_ZERO, FP_SUBNORMAL, FP_NORMAL);
    return 0;
}
```

`实测数据`
`Text`

```text
1.0/0.0      = inf
NAN          = nan, INFINITY = inf
isnan(NAN)=1 isinf(INF)=1 isfinite(1.0)=1 signbit(-0.0)=1
NAN == NAN   -> 0
fpclassify(nan       ) = 256
fpclassify(inf       ) = 1280
fpclassify(0         ) = 16384
fpclassify(4.94066e-324) = 17408
fpclassify(1         ) = 1024
FP_NAN=256 FP_INFINITE=1280 FP_ZERO=16384 FP_SUBNORMAL=17408 FP_NORMAL=1024
```

**`NAN == NAN` 是 0。** 这一条与直觉相反，但它是 IEEE 754 定的：
NaN 与任何值（包括它自己）比较都不相等。
**判断 NaN 只能用 `isnan`，不能用 `==`。**

**`fpclassify` 的返回值是实现定义的。** 同一段代码在 glibc 上给出的是另一组数：

`实测数据`
`Text`

```text
FP_NAN=0 FP_INFINITE=1 FP_ZERO=2 FP_SUBNORMAL=3 FP_NORMAL=4
fpclassify(NAN)=0 fpclassify(INFINITY)=1 fpclassify(0.0)=2
```

> [!WARNING]
> **不要把 `fpclassify` 的返回值当数字比较，也不要写 `1`、`2` 这样的常量。**
> 必须用 `FP_NAN` 这类宏名。MinGW 给的是位标志（`256`、`1280`），
> glibc 给的是序号（`0`、`1`）——**两者都合法，因为它们只承诺互不相同。**

**`isfinite`、`isnormal`、`signbit` 也是宏**，与 `isnan`、`isinf` 一样。
`signbit(-0.0)` 为真，说明它能区分 `+0.0` 与 `-0.0`——
这是 `x == 0` 做不到的。

## 1.5 一个不存在的常量：`M_PI`

**`<math.h>` 里没有 π。** 标准从头到尾没有定义过 `M_PI`。
本机严格模式下两份报错原文：

`实测数据`
`C`


`实测数据`

>

>
> 或者用 `acos(-1.0)` 算一个。**改编译选项让它「能用」不是解决办法**，

> [!NOTE]
> **本节回顾**：`<math.h>` 的函数按类型分成 `f`/`l` 三套；
> 出错通过 `errno`（`EDOM`/`ERANGE`）与特殊值（NaN、无穷）报告；
> 判断特殊值用 `isnan`、`isinf`、`fpclassify`，其中 `fpclassify` 的返回值是实现定义的；
> `M_PI` 不是标准的一部分；本机没有单独的 `libm`，glibc 上 `-lm` 仍然要写，
> 且库必须排在源码之后。

**几个宏的含义如下**：

| 宏 | 含义 |
|---|---|
| `FLT_RADIX` | 浮点的底数，本机是 2 |
| `*_MANT_DIG` | 尾数有多少位（二进制） |
| `*_DIG` | 能round-trip 的十进制位数：`FLT_DIG=6` 表示 `float` 能保证 6 位十进制有效数字 |
| `*_MAX` / `*_MIN` | 最大有限值 / 最小正规格化值 |
| `*_EPSILON` | 1 与「比 1 大的最小可表示数」之差，即机器 epsilon |
| `*_MAX_EXP` | 最大二进制指数 |

**`DBL_EPSILON` 是浮点比较里最常用的一个数。**
两个浮点数不能用 `==` 比较，判等要写成 `fabs(a - b) < DBL_EPSILON * scale`，
理由见《04-语法/04-表达式与运算符.md》第 3.3 小节。

> [!TIP]
> **`DECIMAL_DIG` 是 21，比 `DBL_DIG` 的 15 大得多。**
> 区别在于：`DBL_DIG` 问的是「多少位十进制数转成 `double` 再转回来不变」，
> `DECIMAL_DIG` 问的是「多少位十进制数能把**最宽的浮点类型**（这里是 80 位 `long double`）
> 唯一确定下来」。打印 `long double` 时用 21 位才不丢信息。

## 2.3 `long double` 在本机是 80 位

`sizeof(long double)` 是 **16 字节**，但 `LDBL_MANT_DIG` 是 **64** 位，
而不是 128 位——多出来的 6 个字节是填充。

`实测数据`
`C`

```c
/* long_double.c    编译：gcc -std=c23 long_double.c -o long_double */

#include <float.h>

    printf("LDBL_MAX_EXP   = %d\n", LDBL_MAX_EXP);
    printf("LDBL_MAX_10_EXP= %d\n", LDBL_MAX_10_EXP);
    printf("(double)LDBL_MAX = %g\n", (double)LDBL_MAX);
    printf("sqrtl(2.0L)    = %.21Lg\n", sqrtl(2.0L));
    printf("1.0L/3.0L      = %.21Lg\n", 1.0L / 3.0L);
    printf("1.0/3.0        = %.17g\n", 1.0 / 3.0);

```

`实测数据`

**`(double)LDBL_MAX` 打印出 `inf`**：`long double` 的最大值超出了 `double` 能表示的范围，
转换时上溢成无穷。**打印 `long double` 必须用 `%Lg`**，不能先转成 `double`。

**`1.0L/3.0L` 比 `1.0/3.0` 多出 4 位有效数字**，这就是 64 位尾数对 53 位尾数的差别。
代价是运算慢，且**跨平台不一致**：
MSVC 的 `long double` 与 `double` 完全一样（都是 64 位），
本机 MinGW 用的是 x87 的 80 位扩展精度。

> [!WARNING]
> **`long double` 是所有基本类型里最不可移植的一个。**
> 同样写 `sizeof(long double)`，MSVC 给 8，MinGW 给 16，某些 ARM 平台给 16 但尾数只有 113 位。
> 需要用 `long double` 的场合，先确认目标平台真的给了更多精度。

## 2.4 写错了会怎样：整数溢出

**这是 C 与 C++ 里最常见的一类静默错误：编译通过、程序能跑、结果错了。**

`实测数据`
`C`

```c
/* int_overflow.c    编译：gcc -std=c23 int_overflow.c -o int_overflow */
#include <limits.h>
#include <stdio.h>

int main(void) {
    int x = INT_MAX + 1;              /* 编译期常量，能算出溢出 */
    printf("INT_MAX + 1 = %d\n", x);
    int a = INT_MAX;
    printf("用变量算：   %d\n", a + 1);
    unsigned u = UINT_MAX;
    printf("UINT_MAX + 1 = %u（无符号回绕是定义好的）\n", u + 1);
    return 0;
}
```

`实测数据`
`Text`

```text
int_overflow.c: In function 'main':
int_overflow.c:6:21: warning: integer overflow in expression of type 'int'
    results in '-2147483648' [-Woverflow]
    6 |     int x = INT_MAX + 1;
      |                     ^

（运行输出）
INT_MAX + 1 = -2147483648
用变量算：   -2147483648
UINT_MAX + 1 = 0（无符号回绕是定义好的）
```

**只有一条警告，没有错误。** 而且警告只在编译器**能算出结果**时给：
把 `INT_MAX` 换成一个运行期才知道的变量，警告就消失了，行为照旧是错的。

**两者的区别在这里**：

| 情况 | 标准怎么说 |
|---|---|
| 有符号整数溢出 | **未定义行为**——编译器可以做任何事 |
| 无符号整数回绕 | **定义好的**，按 2 的 N 次方取模 |

> [!CAUTION]
> **有符号溢出是未定义行为，不是一个「会回绕」的操作。**
> 在 `-O2` 下编译器会依据「有符号数不会溢出」这个前提做优化，
> 于是同一段代码在 `-O0` 与 `-O2` 下可能给出不同结果，
> 甚至把整个分支删掉。见《03-构建工具链/05-优化等级.md》第 5.5 小节。
>
> **检查办法**：加法前判 `a > INT_MAX - b`，或用 C23 的 `<stdckdint.h>`：

`C`

```c
/* （下面是节选）C23 的检查算术 */
#include <stdckdint.h>
int r;
if (ckd_add(&r, a, b)) {
    /* 溢出了，r 里的值不可用 */
}
```

`ckd_add`、`ckd_sub`、`ckd_mul` 在溢出时返回非 0，并且**不产生未定义行为**。
这一组函数是 C23 新增的，本机 GCC 15.2.0 的头文件目录里已有 `<stdckdint.h>`。

> [!NOTE]
> **本节回顾**：`<limits.h>` 与 `<float.h>` 全是宏，用来避免对宽度做假设；
> 本机 `long` 是 4 字节、`long double` 是 16 字节装 80 位；
> 有符号溢出是未定义行为，只能靠检查或 `ckd_*` 系列提前发现。

# 第 3 节 定宽整数：`<stdint.h>` 与 `<inttypes.h>`

## 3.1 为什么要「定宽」

`int` 至少 16 位，`long` 至少 32 位——标准只给了下限，实际多宽由实现决定。
**要描述一个外部格式（文件头、网络包、哈希值）时，「至少」是不够的**，
必须有一个宽度确定的类型。

`<stdint.h>` 给的就是这个：

| 类型 | 含义 |
|---|---|
| `int8_t` `int16_t` `int32_t` `int64_t` | **恰好**这么多位的**有符号**整数 |
| `uint8_t` `uint16_t` `uint32_t` `uint64_t` | **恰好**这么多位的**无符号**整数 |
| `int_least8_t` 一族 | 至少有这么多位，实现可以更宽 |
| `int_fast8_t` 一族 | 至少有这么多位，且取该平台上最快的那个 |
| `intptr_t` `uintptr_t` | 能装下一个指针的整数 |
| `intmax_t` `uintmax_t` | 该实现里最宽的整数类型 |

**「恰好」两个字是关键**：如果某个平台没有 8 位的类型，`int8_t` 就不会定义。
`int_least8_t` 则一定有。

`实测数据`
`C`

```c
/* stdint_size.c    编译：gcc -std=c23 stdint_size.c -o stdint_size */
#include <stdio.h>
#include <stdint.h>

int main(void) {
    printf("int8_t   %zu 字节\n", sizeof(int8_t));
    printf("int16_t  %zu 字节\n", sizeof(int16_t));
    printf("int32_t  %zu 字节\n", sizeof(int32_t));
    printf("int64_t  %zu 字节\n", sizeof(int64_t));
    printf("intptr_t %zu 字节\n", sizeof(intptr_t));
    printf("intmax_t %zu 字节\n", sizeof(intmax_t));
    printf("long     %zu 字节（对照）\n", sizeof(long));
    return 0;
}
```

`实测数据`
`Text`

```text
int8_t   1 字节
int16_t  2 字节
int32_t  4 字节
int64_t  8 字节
intptr_t 8 字节
intmax_t 8 字节
long     4 字节（对照）
```

**最后两行的对照最有意义**：`intptr_t` 是 8 字节，`long` 是 4 字节。
**本机的指针装不进 `long`**，只能用 `intptr_t` 或 `long long` 装。

## 3.2 写错了会怎样：`printf("%d", int64_t)`

**这是定宽整数带来的第一个坑，而且它不会崩，只会印出错的数。**

`实测数据`
`C`

```c
/* int64_printf.c    编译：gcc -std=c23 int64_printf.c -o int64_printf */
#include <stdio.h>
#include <stdint.h>

int main(void) {
    int64_t v = 4294967298LL;              /* 2 的 32 次方加 2 */
    printf("正确写法（用 %%lld）: %lld\n", (long long)v);
    printf("用 %%d 输出        : %d\n", v);      /* 故意写错 */
    return 0;
}
```

`实测数据`
`Text`

```text
int64_printf.c:9:35: warning: format '%d' expects argument of type 'int',
    but argument 2 has type 'int64_t' {aka 'long long int'} [-Wformat=]
    9 |     printf("用 %%d 输出        : %d\n", v);
      |                                  ~^     ~
      |                                   |     |
      |                                   int   int64_t {aka 'long long int'}
      |                                  %lld

（运行输出）
正确写法（用 %lld）: 4294967298
用 %d 输出        : 2
```

**值从 `4294967298` 变成了 `2`**：变参函数没有类型信息，
`printf` 完全按格式串去内存（或寄存器）里取值，
`%d` 只取低 32 位，于是 `0x100000002` 被读成了 `0x00000002`。

> [!CAUTION]
> **`printf` 家族的格式串是唯一能告诉它「参数是什么类型」的东西。**
> 类型与格式串不匹配是**未定义行为**：本机是截断成低 32 位，
> 换个平台可能是别的高位垃圾，甚至因为读取了不存在的参数而崩溃。
> `-Wformat` 能抓住大部分常量格式串，但抓不住运行期拼出来的格式串。

## 3.3 `PRIu64` 这一族宏

**问题来了**：`int64_t` 到底是什么底层类型？本机是 `long long`，配 `%lld`；
Linux 上是 `long`，配 `%ld`。写死 `%lld` 在 Linux 上就错了。

`<inttypes.h>` 的答案是把格式串也做成宏：

`实测数据`
`C`

```c
/* inttypes_pri.c    编译：gcc -std=c23 inttypes_pri.c -o inttypes_pri */
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {
    int64_t v = 4294967298LL;              /* 2 的 32 次方加 2 */
    /* %s 会把宏原样打印出来：宏的值里没有 %，那个 % 要自己写 */
    printf("PRId64 的值是 \"%s\"\n", PRId64);
    printf("PRIu64 的值是 \"%s\"\n", PRIu64);
    printf("PRIx64 的值是 \"%s\"\n", PRIx64);
    printf("SCNd64 的值是 \"%s\"\n", SCNd64);
    printf("PRId8/16/32 的值是 \"%s\" \"%s\" \"%s\"\n", PRId8, PRId16, PRId32);
    printf("拼起来用：%" PRId64 "\n", v);
    printf("INT64_MAX = %" PRId64 "\n", INT64_MAX);
    printf("UINT64_MAX = %" PRIu64 "\n", UINT64_MAX);
    printf("十六进制：%#" PRIx64 "\n", (uint64_t)v);
    return 0;
}
```

`实测数据`
`Text`

```text

PRIu64 的值是 "llu"
PRIx64 的值是 "llx"
```

**用法只有一条规则：把宏写在字符串里，两边用 `"` 断开。**

`C`

```c
/* （下面是节选）拼接格式串 */
printf("票号 = %" PRIu64 "，余额 = %" PRId64 "\n", id, balance);
/* 展开之后等于（本机）： */
printf("票号 = %llu，余额 = %lld\n", id, balance);
```

**为什么 `PRId8` 是 `%d` 而不是 `%hhd`？**
因为传给 `printf` 的 `int8_t` 会先经过整型提升变成 `int`
（《04-语法/02-数据类型与类型系统.md》第 5.2 小节），
`%hhd` 也能用，但标准选的是更简单的那个。

`实测数据`

| 宏 | 用途 | 与它配套的类型 |
|---|---|---|
| `PRId8` `PRIi8` | 十进制有符号 | `int8_t` |
| `PRIu8` `PRIo8` `PRIx8` `PRIX8` | 无符号、八进制、小写十六进制、大写十六进制 | `uint8_t` |
| `PRId16` `PRIu16` | 同上，16 位 | `int16_t` `uint16_t` |
| `PRId32` `PRIu32` `PRIx32` | 同上，32 位 | `int32_t` `uint32_t` |
| `PRId64` `PRIu64` `PRIx64` | 同上，64 位 | `int64_t` `uint64_t` |
| `PRIdMAX` `PRIuMAX` | 最宽整数 | `intmax_t` `uintmax_t` |
| `PRIdPTR` `PRIuPTR` | 指针宽的整数 | `intptr_t` `uintptr_t` |
| `SCNd64` `SCNu64` | **`scanf` 侧**的对应物 | `int64_t` `uint64_t` |

> [!TIP]
> **`PRIx64` 打印 `uint64_t` 时建议加 `#`**，写成 `%#" PRIx64`，
> 这样输出带 `0x` 前缀，读日志时不会看错进制。

## 3.4 什么时候用、什么时候不用

| 场合 | 建议 |
|---|---|
| 文件格式、网络协议、哈希值、位掩码 | **用定宽类型**，宽度是格式的一部分 |
| 数组下标、循环计数 | 用 `size_t`（`<stddef.h>`） |
| 两个指针相减 | 用 `ptrdiff_t` |
| 存指针 | 用 `intptr_t` / `uintptr_t`，不要用 `long` |
| 只是想装个大点的数 | 用 `long long`，不必定宽 |

**不要把所有 `int` 都换成 `int32_t`。** 定宽类型表达的是一句话：
「这里的宽度有外部含义」。没有这层含义时，它只是让代码更长。

**该用的三个 typedef 与不该用的 `long`，宽度差别在这里：**

`实测数据`
`C`

```c
/* stdint_choice.c    编译：gcc -std=c23 stdint_choice.c -o stdint_choice */
#include <stdio.h>
#include <stddef.h>
#include <stdint.h>

int main(void) {
    int a[8];
    /* 三个有专门用途的 typedef，宽度随平台走，不要写死 */
    printf("sizeof(size_t)    = %zu   数组下标、循环计数\n", sizeof(size_t));
    printf("sizeof(ptrdiff_t) = %zu   两个指针相减\n", sizeof(ptrdiff_t));
    printf("sizeof(intptr_t)  = %zu   存一个指针\n", sizeof(intptr_t));
    printf("sizeof(long)      = %zu   宽度随平台变，不能拿来存指针\n", sizeof(long));
    printf("&a[7] - &a[0]     = %td\n", &a[7] - &a[0]);
    /* 定宽类型只在宽度本身有外部含义时才该用 */
    printf("sizeof(int64_t)   = %zu   恰好 8 字节，到哪台机器都一样\n", sizeof(int64_t));
    printf("sizeof(long long) = %zu   至少 8 字节，可以更宽\n", sizeof(long long));
    return 0;
}
```

`实测数据`
`Text`

```text
（Windows / MinGW-w64 15.2.0）
sizeof(size_t)    = 8   数组下标、循环计数
sizeof(ptrdiff_t) = 8   两个指针相减
sizeof(intptr_t)  = 8   存一个指针
sizeof(long)      = 4   宽度随平台变，不能拿来存指针
```

**七个量里只有 `sizeof(long)` 一行变了，其余六行两个平台一致。**
`size_t`、`ptrdiff_t`、`intptr_t` 的宽度跟着平台走，所以它们到哪都能用；
`int64_t` 的宽度写死在标准里；**只有 `long` 是「看着通用、实际会变」的那一个。**

> [!NOTE]
> **本节回顾**：`<stdint.h>` 给恰好宽度的类型，`<inttypes.h>` 给与它们配套的格式宏；
> `printf` 的格式串必须与实参类型精确匹配，`int64_t` 配 `%d` 会静默截断；
> 宽度不是外部约定的一部分时，用 `int`、`size_t` 就够。

# 第 4 节 随机数：`rand` 与 `srand`

## 4.1 三个名字

`<stdlib.h>` 里与随机数有关的只有三个名字：

| 名字 | 作用 |
|---|---|
| `rand()` | 返回一个 `[0, RAND_MAX]` 之间的伪随机整数 |
| `srand(unsigned)` | 设置种子，重置序列 |
| `RAND_MAX` | 该实现返回的最大值 |

`文档`

> "The value of the RAND_MAX macro shall be at least 32767."
>
> —— N3220 §7.24.2.1/6

**「at least」这个词是关键：标准只保证不少于 32767，不保证更多。**

`实测数据`
`C`

```c
/* rand_basic.c    编译：gcc -std=c23 rand_basic.c -o rand_basic */
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    printf("RAND_MAX = %d (0x%X)\n", RAND_MAX, RAND_MAX);
    srand(1);
    printf("srand(1) 前 10 个: ");
    for (int i = 0; i < 10; i++) printf("%d ", rand());
    printf("\n");
    srand(1);
    printf("再 srand(1) 前 10 个: ");
    for (int i = 0; i < 10; i++) printf("%d ", rand());
    printf("\n");
    printf("不调用 srand 的前 10 个: ");
    for (int i = 0; i < 10; i++) printf("%d ", rand());
    printf("\n");
    return 0;
}
```

`实测数据`
`Text`

```text
（Windows / MinGW-w64 15.2.0）
RAND_MAX = 32767 (0x7FFF)
srand(1) 前 10 个: 41 18467 6334 26500 19169 15724 11478 29358 26962 24464
再 srand(1) 前 10 个: 41 18467 6334 26500 19169 15724 11478 29358 26962 24464
不调用 srand 的前 10 个: 5705 28145 23281 16827 9961 491 2995 11942 4827 5436

（Linux / glibc 2.39，gcc 13.3.0）
RAND_MAX = 2147483647 (0x7FFFFFFF)
srand(1) 前 10 个: 1804289383 846930886 1681692777 1714636915 1957747793 424238335 719885386 1649760492 596516649 1189641421
```

**表中已经可以读出三个结论。**

**第一，`RAND_MAX` 差了两个数量级。**
本机是 `32767`（15 位），glibc 是 `2147483647`（31 位）。
**同一个 `%` 表达式在两个平台上能取到的值域完全不同。**

**第二，序列完全不同。** 本机的 `41 18467 6334 ...` 是 MSVC 那一套线性同余；
glibc 的是另一套算法。**`srand(1)` 不等于「可复现」，它只等于「在本实现上可复现」。**

**第三，`srand(1)` 是幂等的。** 同一个种子总是给出同一串。
同一段程序运行两遍，输出完全一样——**这正是伪随机数的定义**，
也说明了为什么它不能用于密码学。

**「不调用 `srand` 会怎样」**：标准说等价于 `srand(1)`。
本机的输出与 `srand(1)` 不同（`5705 ...` 对 `41 ...`），
glibc 的输出也与它的 `srand(1)` 不同——**两个实现都没有照这条规定做**。

> [!WARNING]
> **不调用 `srand` 时序列是什么，是实现定义的。**
> 想要可复现就跑一次 `srand(固定值)`；想要每次都不同，才写 `srand(time(NULL))`。
> 不要依赖「不调用 `srand` 会得到种子 1」这个说法。

## 4.2 分布直方图

**伪随机数最容易出问题的地方不是「像不像随机」，而是「取值区间对不对」。**
`rand() % 6` 的直方图如下：

`实测数据`
`C`

```c
/* rand_hist.c    编译：gcc -std=c23 rand_hist.c -o rand_hist */
#include <stdio.h>
#include <stdlib.h>
#define N 60000
#define FACES 6

int main(void) {
    int cnt[FACES] = {0};
    srand(12345);
    for (int i = 0; i < N; i++) cnt[rand() % FACES]++;
    int mx = 0;
    for (int i = 0; i < FACES; i++) if (cnt[i] > mx) mx = cnt[i];
    printf("rand() %% 6，%d 次：\n", N);
    for (int i = 0; i < FACES; i++) {
        printf("  %d: %6d  ", i + 1, cnt[i]);
        for (int k = 0; k < cnt[i] * 50 / mx; k++) putchar('#');
        putchar('\n');
    }
    printf("理论值 %d，最大偏差 %+d\n", N / FACES, mx - N / FACES);
    return 0;
}
```

`实测数据`
`Text`

```text
rand() % 6，60000 次：
  1:   9915  ################################################
  2:  10171  ##################################################
  3:   9994  #################################################
  4:  10017  #################################################
  5:   9939  ################################################
  6:   9964  ################################################
理论值 10000，最大偏差 +171
```

**这一张看起来很正常。** 偏差 `+171` 相当于 1.7%，
而 60000 次投 6 面的标准差约是 91，`+171` 还不到两倍标准差，
属于正常涨落。**所以「`rand() % 6` 分布不匀」这个常见说法，
在这一组参数下测不出来。**

**真正的问题在模数较大或较小时才暴露。** 换成 `rand() % 25000`：

`实测数据`
`C`

```c
/* rand_bias.c    编译：gcc -std=c23 rand_bias.c -o rand_bias */
#include <stdio.h>
#include <stdlib.h>
#define N 200000

int main(void) {
    static int bucket[25];
    int mx = 0;
    srand(12345);
    for (int i = 0; i < N; i++) bucket[(rand() % 25000) / 1000]++;
    printf("rand() %% 25000 分 25 桶，每桶 1000 个值，共 %d 次：\n", N);
    for (int i = 0; i < 25; i++) if (bucket[i] > mx) mx = bucket[i];
    for (int i = 0; i < 25; i++) {
        printf("  [%5d,%5d) %7d ", i * 1000, i * 1000 + 999, bucket[i]);
        for (int k = 0; k < bucket[i] * 40 / mx; k++) putchar('#');
        putchar('\n');
    }
    printf("理论均匀值 %d\n", N / 25);
    int big = 0;
    srand(12345);
    for (int i = 0; i < N; i++) { int r = rand() % 100000; if (r > big) big = r; }
    printf("rand() %% 100000 在 %d 次里取到的最大值 = %d\n", N, big);
    return 0;
}
```

`实测数据`
`Text`

```text
rand() % 25000 分 25 桶，每桶 1000 个值，共 200000 次：
  [    0,  999)   12074 #######################################
  [ 1000, 1999)   12066 #######################################
  [ 2000, 2999)   12287 ########################################
  [ 3000, 3999)   12152 #######################################
  [ 4000, 4999)   12230 #######################################
  [ 5000, 5999)   12198 #######################################
  [ 6000, 6999)   12237 #######################################
  [ 7000, 7999)   10725 ##################################
  [ 8000, 8999)    6130 ###################
  [ 9000, 9999)    6083 ###################
  ...（中间各桶都在 6000 上下）...
  [24000,24999)    6197 ####################
理论均匀值 8000

rand() % 100000 在 200000 次里取到的最大值 = 32767
```

**前 8 个桶是后面各桶的两倍。** 原因可以算出来：

`Text`

```text
RAND_MAX + 1 = 32768 = 25000 + 7768
```

- 落在 `0 … 7767` 的数，有**两种**取模结果都指向它（`x` 和 `x + 25000`）；
- 落在 `7768 … 24999` 的数只有**一种**。

于是前 7768 个值出现的概率是后面那些的两倍，
分成 1000 一桶就是「前 7 桶翻倍、第 8 桶介于中间」。

**而 `rand() % 100000` 更直接：20 万次里取到的最大值就是 `32767`。**
`rand()` 根本产生不了比 `RAND_MAX` 大的数，
所以想要 `0 … 99999` 的随机数，这个写法**永远给不出后三分之二的值域**。

**偏差的定量公式**：用 `rand() % N` 时，
设 `R = RAND_MAX + 1`，那么前 `R % N` 个值出现的概率是后者的
`ceil(R/N) / floor(R/N)` 倍。`N` 远小于 `R` 时偏差可以忽略，
`N` 接近 `R` 时偏差最大。

> [!CAUTION]
> **`rand() % N` 有两个独立的缺陷，别把它们混为一谈。**
> 一个是**取模偏差**（`R % N != 0` 时各值概率不等），
> 另一个是**值域上限**（`N > RAND_MAX` 时一部分值根本取不到）。
> 本机 `RAND_MAX` 只有 32767，第二个缺陷比第一个严重得多。

## 4.3 为什么 `rand` 弱

上面的实测可以归为五条：

| 问题 | 表现 |
|---|---|
| 值域太小 | 本机 `RAND_MAX` 只有 32767，15 位。抽 0…99999 抽不到一半 |
| 取模偏差 | `R % N != 0` 时概率不等，`N` 大时能差出一倍 |
| 不可移植 | 同一份代码在 MinGW 与 glibc 上给出完全不同的数 |
| 质量无保证 | 标准只要求「可重现的伪随机序列」，没有对分布、周期做任何承诺 |
| 不可用于安全 | 知道种子就能推算全部序列，这是设计使然 |

**还有一条容易被忽略的**：`rand()` 的返回值是 `int`，
两个 `rand()` 拼起来（`rand() * (RAND_MAX + 1) + rand()`）看着像能造出更多位数，
但**中间的乘法会溢出**——`RAND_MAX` 是 32767 时还好，
glibc 上是 `2147483647`，一加就溢出成未定义行为。

`实测数据`
`C`

```c
/* rand_weak.c    编译：gcc -std=c23 rand_weak.c -o rand_weak */
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* 最低位：线性同余发生器的最低位周期极短 */
    srand(1);
    printf("最低位连取 24 次：");
    for (int i = 0; i < 24; i++) printf("%d", rand() & 1);
    printf("\n");
    srand(1);
    int even = 0;
    for (int i = 0; i < 10000; i++) even += (rand() & 1) == 0;
    printf("10000 次里最低位为 0 的：%d 次（理想 5000 附近）\n", even);
    /* 想靠拼接扩大值域：这一步在 int 里做会溢出 */
    printf("RAND_MAX = %d\n", RAND_MAX);
    printf("RAND_MAX + 1 用 int 存 = %d\n", (int)(RAND_MAX + 1));
    srand(1);
    long long big = (long long)rand() * ((long long)RAND_MAX + 1) + rand();
    printf("拼一次得到 %lld，最多 %d 位有效\n", big, 15);
    return 0;
}
```

`实测数据`
`Text`

```text

10000 次里最低位为 0 的：4965 次（理想 5000 附近）
```

**两边的数完全不同，这不是随机性，是「不可移植」**：
同一份源码、同一个种子，换一个实现就是另一串数。
**最后两行在 glibc 上是未定义行为**：`RAND_MAX + 1` 在 `int` 里算，
2147483647 加 1 溢出，编译器给了一条警告：

`实测数据`
`Text`

```text

      |                                                            ^
```

**想扩大值域，正确做法是把 `rand()` 的结果先转成更宽的类型再拼接**
（源码里的 `big` 那一行）；**即使这样也只买到 15 位**，
因为每一次 `rand()` 本身只有 15 位有效。

## 4.4 该怎么做

**只要区间不是 `RAND_MAX` 的约数，就该用拒绝采样**：

`实测数据`
`C`

```c
/* rand_range.c    编译：gcc -std=c23 rand_range.c -o rand_range */
#include <stdio.h>
#include <stdlib.h>
/* 返回 [0, n) 上的均匀整数，n 必须大于 0 且不超过 RAND_MAX + 1 */
static int rand_below(int n) {
    if (n <= 0) return 0;
    int limit = (RAND_MAX / n) * n;     /* 能被 n 整除的最大范围 */
    int r;
    do {
        r = rand();
    } while (r >= limit);               /* 落在尾巴上的丢掉重抽 */
    return r % n;
}

int main(void) {
    static int a[25], b[25];
    srand(12345);
    for (int i = 0; i < 200000; i++) a[(rand() % 25000) / 1000]++;
    srand(12345);
    for (int i = 0; i < 200000; i++) b[rand_below(25000) / 1000]++;
    printf("桶              rand()%%25000   rand_below(25000)\n");
    for (int i = 0; i < 8; i++)
        printf("  [%5d,%5d)  %8d      %8d\n", i * 1000, i * 1000 + 999, a[i], b[i]);
    printf("理论均匀值 8000\n");
    return 0;
}
```

`实测数据`
`Text`

```text
桶              rand()%25000   rand_below(25000)
  [    0,  999)     12074          7921
  [ 1000, 1999)     12066          7907
  [ 2000, 2999)     12287          8046
  [ 3000, 3999)     12152          7935
  [ 4000, 4999)     12230          7987
  [ 5000, 5999)     12198          7870
  [ 6000, 6999)     12237          7954
  [ 7000, 7999)     10725          7956
理论均匀值 8000
```

**关键在于 `limit` 那一步**：`(RAND_MAX / n) * n` 是「不超过 `RAND_MAX` 的最大 `n` 的倍数」，
只保留 `[0, limit)` 这一段，每个值被取到的概率就完全相等了。
`n = 25000` 时 `limit` 就是 `25000`，落在 `25000 … 32767` 上的那些数被丢掉重抽，
接受率是 `25000 / 32768`，约 76%。

**两列的对照说明了全部问题**：左列第一桶 12074、第二列 7921，
理论值都是 8000。**拒绝采样把偏差抹平了，代价是多调用了一部分 `rand()`。**

> [!TIP]
> **验证均匀性时，先把「桶数 × 桶宽 × 样本数」三者的关系写清楚。**
> 25 个桶、每桶 1000 个值、200000 个样本，每桶期望 `200000 / 25 = 8000`。
> 数字对不上时先核对这三个量，再怀疑分布——
> 本机实测这一组数据时，最初把桶数组开成了 8 个元素却按 25 个桶计数，
> 结果越界写入把另一列数据改掉了，打印出来的第二列全是 14000 上下。

**拒绝采样解决不了值域上限**：`rand_below(100000)` 在
`RAND_MAX = 32767` 的平台上仍然只能从 32767 个数里挑。
**要更大的值域，只能换随机数源。**

> [!IMPORTANT]
> **`<stdlib.h>` 的 `rand` 适合的场景只有两类**：
> 一是**可复现的测试数据**（要的是「每次一样」，不是「够随机」）；
> 二是对分布没有要求的琐碎用途（随机挪动一个光标位置）。
>
> **正经场合应当用 C++ 的 `<random>`**：引擎与分布分开、
> 值域与分布质量都有明确保证、`uniform_int_distribution` 自带拒绝采样。
> 对照与实测见《07-标准库/B-05-数值.md》第 4 节。

> [!NOTE]
> **本节回顾**：`rand` 的返回值上限由 `RAND_MAX` 决定，本机只有 32767；
> `% N` 在 `N` 不能整除 `RAND_MAX + 1` 时带来偏差，`N` 大于 `RAND_MAX` 时值域不够；
> 修偏差用拒绝采样，修值域只能换实现。

# 第 5 节 C23 的 `<stdbit.h>`

**C23 新增了一个头文件，专门放位操作。** 在这之前，数一个整数里有多少个 1、
有多少个前导零，只能靠编译器内建函数（`__builtin_popcount`）
或者手写位运算（《04-语法/15-奇技淫巧与优化.md》第 6 节）。

`<stdbit.h>` 把这些操作标准化了，一共三组：

| 组 | 名字 | 作用 |
|---|---|---|
| 计数 | `stdc_leading_zeros` `stdc_trailing_zeros` `stdc_leading_ones` `stdc_trailing_ones` | 前导/尾随的 0 或 1 有多少个 |
| 统计 | `stdc_count_ones` `stdc_count_zeros` `stdc_has_single_bit` | 有几个 1、是不是 2 的幂 |
| 定位 | `stdc_bit_width` `stdc_bit_floor` `stdc_bit_ceil` | 表示这个数需要几位、向下/向上取到 2 的幂 |

**它在本机的 C 编译器上不可用**：

`实测数据`
`C`

```c
/* stdbit_probe.c    编译：gcc -std=c23 stdbit_probe.c -o stdbit_probe （失败） */
#include <stdio.h>
#include <stdbit.h>

int main(void) {
    printf("stdc_bit_width(255u) = %u\n", stdc_bit_width(255u));
    return 0;
}
```

`实测数据`
`Text`

```text
stdbit_probe.c:3:10: fatal error: stdbit.h: No such file or directory
    3 | #include <stdbit.h>
      |          ^~~~~~~~~~
compilation terminated.
```

**报错是「找不到文件」而不是「不认识这个名字」**，说明本机的 C 头文件目录里
确实没有这个文件。头文件目录的内容如下：

`实测数据`
`Text`

```text
<MinGW>\lib\gcc\x86_64-w64-mingw32\15.2.0\include\  下的 std*.h：
  stdalign.h  stdarg.h  stdatomic.h  stdbool.h  stdckdint.h
  stddef.h    stdfix.h  stdint-gcc.h stdint.h   stdnoreturn.h
  （没有 stdbit.h）

<MinGW>\lib\gcc\x86_64-w64-mingw32\15.2.0\include\c++\stdbit.h 存在，
  但那是 libstdc++ 给 C++ 用的包装，C 编译器看不到这个目录
```

**Linux 侧的 gcc 13.3.0 有它**，所以这一节的内容可以真跑出来：

`实测数据`
`C`

```c
/* stdbit_demo.c    编译：gcc -std=gnu2x stdbit_demo.c -o stdbit_demo （本机编译失败：缺 stdbit.h） */
#include <stdio.h>
#include <stdbit.h>

int main(void) {
    printf("stdc_leading_zeros(1u)   = %u\n", stdc_leading_zeros(1u));
    printf("stdc_trailing_zeros(8u)  = %u\n", stdc_trailing_zeros(8u));
    printf("stdc_count_ones(0xFFu)   = %u\n", stdc_count_ones(0xFFu));
    printf("stdc_bit_width(255u)     = %u\n", stdc_bit_width(255u));
    printf("stdc_has_single_bit(64u) = %d\n", (int)stdc_has_single_bit(64u));
    printf("stdc_bit_floor(100u)     = %u\n", stdc_bit_floor(100u));
    printf("stdc_bit_ceil(100u)      = %u\n", stdc_bit_ceil(100u));
    return 0;
}
```

`实测数据`
`Text`

```text
stdc_leading_zeros(1u)   = 31
stdc_trailing_zeros(8u)  = 3
stdc_count_ones(0xFFu)   = 8
stdc_bit_width(255u)     = 8
stdc_has_single_bit(64u) = 1
stdc_bit_floor(100u)     = 64
stdc_bit_ceil(100u)      = 128
```

**这一组数可以直接当作定义**：`1u` 有 31 个前导零（32 位一共），
`8u` 有 3 个尾随零，`0xFF` 有 8 个 1，`255` 用 8 位表示，
`100` 向下取到 2 的幂是 `64`，向上是 `128`。

> [!TIP]
> **写可移植代码时的选择顺序**：
> 先看 `<stdbit.h>` 有没有（用 `__has_include`，见《04-语法/14-预处理器.md》第 4.4 小节），
> 没有就退回 `__builtin_*`，再没有才手写位运算循环。
> **手写循环是最慢的一档**，编译器一般认不出它在数 1 的个数。

`实测数据`

| 写法 | 可移植性 | 说明 |
|---|---|---|
| `stdc_count_ones(x)` | C23 起标准 | 首选，但本机 C 编译器还没有 |
| `__builtin_popcount(x)` | GCC / Clang 专有 | 编译成一条指令 |
| `_mm_popcnt_u32(x)` | x86 专有 | 需要 SSE4 支持 |
| 手写 `while (x) { c += x & 1; x >>= 1; }` | 到处都能用 | 慢，且负数是 UB |

> [!NOTE]
> **本节回顾**：`<stdbit.h>` 是 C23 新增的位操作头文件，
> 本机的 MinGW C 编译器没有这个文件（实测报错是「找不到文件」），
> Linux 侧 gcc 13.3 有；用之前先 `__has_include` 探一下。

# 第 6 节 速查表

`实测数据`

| 常用件 | 一句话用途 | 典型坑 |
|---|---|---|
| `sqrt` `pow` `fabs` | 数学函数 | 三个类型各一份，`sqrtf`/`sqrtl` 别混用 |
| `fmod` | 浮点取余 | 不是 `%`；符号跟被除数走 |
| `floor` `ceil` `round` `trunc` | 取整 | `round(-2.5)` 是 `-3`，`rint(-2.5)` 是 `-2` |
| `isnan` `isinf` `isfinite` | 判断特殊值 | `NAN == NAN` 是假，只能用宏判断 |
| `fpclassify` | 更细的分类 | 返回值是实现定义的，必须用 `FP_*` 宏 |
| `errno` + `EDOM`/`ERANGE` | 数学函数的错误通道 | 调用前必须先 `errno = 0` |
| `M_PI` | 圆周率 | **不是标准**，严格模式下不存在 |
| `-lm` | 链接数学库 | 库要写在源文件后面；本机与新版 glibc 不需要 |
| `INT_MAX` `INT_MIN` 等 | 整数极值 | `LONG_MAX` 在 Windows 上是 2147483647 |
| `DBL_EPSILON` | 浮点判等的容差 | 用它判等要乘上量级 |
| `LDBL_MAX` 一族 | 长双精度极值 | 打印用 `%Lg`，转 `double` 会上溢成 `inf` |
| `int64_t` 一族 | 定宽整数 | `intptr_t` 与 `long` 不等宽 |
| `PRId64` 一族 | 与定宽整数配套的格式宏 | 写成 `%" PRId64 "`，两侧引号别丢 |
| `rand` `srand` `RAND_MAX` | 伪随机数 | 本机值域只有 32767；`% N` 有偏差 |
| `stdc_count_ones` 一族 | 位操作 | C23 新增，本机 C 编译器还没有 |
