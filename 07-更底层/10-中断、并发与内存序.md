**一个程序里只要开了中断，就有两条执行流共用同一个核、同一块 RAM。** 主循环在跑，
中断随时可能在任意两条指令之间插进来。语言层面看不到这件事：
C 与 C++ 的抽象机里只有一条执行路径，`x = x + 1` 是一句话；
硬件上它是三条指令，中断可以落在任意两条之间。

《07-更底层/03-寄存器、位与 volatile.md》第 3 节把这件事的入口讲了一半：
`volatile` 保证访问真的发生，却保证不了「读—改—写」是一个整体；
那一节末尾把临界区与原子操作留给了本章。本章接着往下走：
中断上下文里能做什么、共享变量该按什么规则写、三种修法各要付多少周期、
屏障在指令集里长什么样，以及编译器与 CPU 为什么都敢改动手写下的顺序。

本章的数字有两个来源。**周期数与竞争结果来自一块 STM32F103C8 最小系统板**
（Cortex-M3、HSI 8 MHz，1 周期 = 125 ns，flash 64 KiB、RAM 20 KiB、栈顶 `0x20005000`）；
**需要看指令、地址与符号才能说清的部分**走 WSL 里的 `arm-none-eabi-g++` 交叉编译、
QEMU 真跑与 `objdump` 反汇编。真板上没有可观察的外设，凡涉及外设时序与中断嵌套的结论一律标 `待确认`。

接口怎么用（`atomic` 的成员函数、`memory_order` 的取值、锁与条件变量）归
《06-标准库/B-10-内存与并发的基础设施.md》第 5 节；
本章讲的是同一批东西**为什么必须这么用、硬件上发生了什么**。

# 第 1 节 中断上下文

## 1.1 中断进来时硬件做了什么

Cortex-M 的异常进入是硬件完成的一套固定动作，`Reset_Handler` 的第一条指令之前就已经发生过一次。

| 步骤 | 谁做 | 内容 |
|---|---|---|
| 1 | 硬件 | 把 `xPSR`、`PC`、`LR`、`r12`、`r3`、`r2`、`r1`、`r0` 八个寄存器压进**当前栈** |
| 2 | 硬件 | 从向量表取第 N 项，作为 ISR 的入口地址 |
| 3 | 硬件 | 跳进去执行，`LR` 里放一个特殊值（`EXC_RETURN`），返回时用它 |
| 4 | 软件 | ISR 自己的局部变量由编译器再压栈（`push`），退出前 `pop` |
| 5 | 硬件 | 执行到 `bx lr` 且 `LR` 是 `EXC_RETURN` 时，把八个寄存器弹回来，回到被打断的那条指令 |

第 1 步与第 2 步要花时间，这个时间就是**中断延迟**的下界。真板上这两个数如下。

`实测数据`

| 项 | 周期数 | 折合时间（8 MHz） |
|---|---|---|
| 中断延迟（写 `NVIC_ISPR` 到进 ISR 第一条指令） | **21**（触发 64 次，最小 = 最大） | 2.6 µs |
| 一次中断往返（含返回） | **50** | 6.25 µs |

64 次测量的最小值与最大值相同，这个稳定性来自「没有缓存、没有乱序执行」：
Cortex-M3 是顺序核，取向量与压栈的周期数是固定的。
换到有缓存的核上，同样的测量会得到一个分布而不是一个数。

## 1.2 真实工程里的 ISR：`stm32f1xx_it.c`

CubeMX 生成的工程里，所有中断服务函数集中在一个文件。下面三处原样引自
`A-教学素材/01-编译器/嵌入式/内存布局与中断/stm32f1xx_it.c`。

`C`

```c
/* 节选自 stm32f1xx_it.c 第 181 至 193 行 */
/**
  * @brief This function handles System tick timer.
  */
void SysTick_Handler(void)
{
  /* USER CODE BEGIN SysTick_IRQn 0 */

  /* USER CODE END SysTick_IRQn 0 */
  HAL_IncTick();
  /* USER CODE BEGIN SysTick_IRQn 1 */

  /* USER CODE END SysTick_IRQn 1 */
}
```

一个系统节拍中断的全部内容就是一次计数自增。

`C`

```c
/* 节选自 stm32f1xx_it.c 第 202 至 219 行 */
/**
  * @brief This function handles USART1 global interrupt.
  * @note  接收上位机命令：HAL_UART_IRQHandler 内部会调用
  *        HAL_UART_RxCpltCallback（实现于 App/Src/app_link.c），
  *        把字节压入环形缓冲并重新挂上单字节接收。
  *        本函数为强符号，确保向量表指向它而不是 Default_Handler；
  *        Driver.ioc 中已勾选 NVIC.USART1_IRQn，CubeMX 再生成时会保持一致。
  */
void USART1_IRQHandler(void)
{
  /* USER CODE BEGIN USART1_IRQn 0 */

  /* USER CODE END USART1_IRQn 0 */
  HAL_UART_IRQHandler(&huart1);
  /* USER CODE BEGIN USART1_IRQn 1 */

  /* USER CODE END USART1_IRQn 1 */
}
```

这个函数有三处值得看清。**接收的活不在中断里做完**：`HAL_UART_IRQHandler` 只把收到的那个字节
交给回调，回调把它压进环形缓冲，再重新挂上一次单字节接收，然后立刻返回。
**注释自己点出了弱符号这件事**：函数是强符号，向量表才会指向它而不是 `Default_Handler`
（弱符号的机制见《07-更底层/06-符号与链接属性.md》第 4 节）。
**`USER CODE` 区块是给人写的地方**，重新生成代码时只有区块内的内容会被保留。

出错的中断处理函数是另一副样子：

`C`

```c
/* 节选自 stm32f1xx_it.c 第 67 至 95 行 */
/**
  * @brief This function handles Non maskable interrupt.
  */
void NMI_Handler(void)
{
  /* USER CODE BEGIN NonMaskableInt_IRQn 0 */

  /* USER CODE END NonMaskableInt_IRQn 0 */
  /* USER CODE BEGIN NonMaskableInt_IRQn 1 */
   while (1)
  {
  }
  /* USER CODE END NonMaskableInt_IRQn 1 */
}

/**
  * @brief This function handles Hard fault interrupt.
  */
void HardFault_Handler(void)
{
  /* USER CODE BEGIN HardFault_IRQn 0 */

  /* USER CODE END HardFault_IRQn 0 */
  while (1)
  {
    /* USER CODE BEGIN W1_HardFault_IRQn 0 */
    /* USER CODE END W1_HardFault_IRQn 0 */
  }
}
```

`while (1)` 不是偷懒。进了硬件错误之后程序已经不可能继续正确执行，
停在原地至少留给调试器一个完整的现场：`PC` 指向出错的那条指令，压进栈的八个寄存器还在，
用调试器读一次栈就能看出当时在做什么。启动文件里那些弱符号最终指向的 `Default_Handler`
也是同样的形状（第 3.5 小节会看到它被误触发的后果）。

## 1.3 中断里能做什么，不能做什么

中断上下文与主循环的区别只有一条，但这一条决定了其余全部：**中断不会让被它打断的代码继续跑，
它要么跑完，要么返回**。由此推出中断里的纪律。

| 能做 | 为什么 |
|---|---|
| 改一个 `volatile` 标志、加一次计数 | 一两条指令，不依赖别的执行流 |
| 把一字节放进环形缓冲、更新一个索引 | 单写者模式，见第 2.2 小节 |
| 读一个寄存器、清一个中断标志 | 硬件要求的动作必须在中断里完成 |
| 用无锁的原子操作改一个数 | 第 3.3 小节，代价是十几周期 |
| 置一个软件事件，把重活留给主循环 | 中断只负责通知 |

| 不能做 | 后果 |
|---|---|
| `HAL_Delay`、等待某个标志、任何阻塞 | 被等的条件可能正是被自己打断的代码要做的，直接死锁 |
| 长循环、浮点密集计算 | 主循环的时间被整块占掉，第 1.4 小节有实测 |
| `printf`、`malloc`、字符串格式化 | 不可重入、可能阻塞，还会把标准库的内部状态拖进中断 |
| 加锁（`mutex`）等主循环释放 | 中断不会让主循环继续执行，锁永远等不到 |
| 关中断之后忘了恢复 | 从这一刻起所有可屏蔽中断都不再响应 |
| 调用没有标注可重入的库函数 | 主循环可能正在用同一份内部状态 |

> [!IMPORTANT]
> **单核上中断与主循环的互斥不能靠锁。**
> 锁的前提是「持有者迟早会让出 CPU」，而中断打断的正是持有者：
> 主循环拿着锁时中断进来，中断里再去拿同一把锁，就是一次必然的死锁。
> 嵌入式里保护一小段共享数据只用两种手段：**关中断**（第 3.1 小节）与**无锁原子操作**（第 3.3 小节）。

中断优先级决定谁可以打断谁：Cortex-M 的 `NVIC` 支持嵌套，优先级数值小的可以先插进来。
本测试只用了 SysTick 一个中断源，**真实的多源嵌套与优先级分组标 `待确认`**；
`NVIC` 的寄存器与优先级分组的操作细节见《01-编译器/03-嵌入式与交叉编译.md》第 6 节。

## 1.4 中断里的活有多贵

中断与主循环共用同一个核，所以「中断里花了多少时间」等于「主循环少了多少时间」。
下面这份程序用中断次数做基准，数主循环在同样的中断次数里跑了多少圈：

`C++`

```cpp
/* Cortex-M 侧（在 WSL 里交叉编译，QEMU 里跑）：
   isr_long.cpp  —— 中断里的活有多贵
   arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -nostartfiles --specs=nosys.specs \
     -DISR_WORK=0 -T STM32F103XX_FLASH.ld startup_stm32f103xe.s isr_long.cpp -o isr_w0.elf
   qemu-system-arm -M netduinoplus2 -kernel isr_w0.elf -nographic -icount shift=0 \
     -semihosting-config enable=on,target=native */
#include <stdint.h>
#include "semihosting.h"

#define SYST_CSR (*(volatile uint32_t *)0xE000E010u)   /* 控制与状态 */
#define SYST_RVR (*(volatile uint32_t *)0xE000E014u)   /* 重装值 */
#define SYST_CVR (*(volatile uint32_t *)0xE000E018u)   /* 当前值 */

#ifndef ISR_WORK
#define ISR_WORK 0
#endif
#ifndef RVR_VAL
#define RVR_VAL 1000u
#endif

#define TICKS_WANTED 2000u

static volatile uint32_t g_ticks;      /* 中断次数，只在中断里改 */
static volatile uint32_t g_work;       /* 中断里干活的进度，防止循环被优化掉 */

extern "C" void SysTick_Handler(void)
{
    g_ticks = g_ticks + 1u;            /* 一个中断只做最少的事：改一个计数 */
    for (volatile uint32_t i = 0; i < ISR_WORK; ++i) {
        g_work = g_work + i;           /* 中断里的长活：ISR_WORK 次读改写 */
    }
}

int main(void)
{
    SYST_RVR = RVR_VAL;                /* 每 RVR_VAL 节拍中断一次 */
    SYST_CVR = 0u;
    SYST_CSR = 7u;                     /* ENABLE | TICKINT | CLKSOURCE */

    uint32_t loops = 0;
    while (g_ticks < TICKS_WANTED) {
        ++loops;                       /* 主循环的活：数自己转了多少圈 */
    }

    SYST_CSR = 0u;

    sh_puts("中断里的循环次数："); sh_dec32((uint32_t)ISR_WORK);  sh_puts("\r\n");
    sh_puts("中断间隔        ："); sh_dec32((uint32_t)RVR_VAL);   sh_puts(" 节拍\r\n");
    sh_puts("中断次数        ："); sh_dec32(g_ticks);           sh_puts("\r\n");
    sh_puts("主循环转的圈数  ："); sh_dec32(loops);             sh_puts("\r\n");
    sh_puts("中断里的累计活  ："); sh_dec32(g_work);            sh_puts("\r\n");

    for (;;) { }
}

extern "C" void SystemInit(void) { }
extern "C" void _init(void) { }
```

三次运行的差别只有 `-DISR_WORK=` 一个数字，输出照抄如下。

`实测数据`
`Text`

```text
中断里的循环次数：0
中断间隔        ：1000 节拍
中断次数        ：2000
主循环转的圈数  ：2974003
中断里的累计活  ：0
```

`实测数据`
`Text`

```text
中断里的循环次数：20
中断间隔        ：1000 节拍
中断次数        ：2000
主循环转的圈数  ：2873053
中断里的累计活  ：380000
```

`实测数据`
`Text`

```text
中断里的循环次数：60
中断间隔        ：1000 节拍
中断次数        ：2000
主循环转的圈数  ：2673153
中断里的累计活  ：3540000
```

同样的 2000 次中断，中断里的循环从 0 次加到 60 次，主循环少跑了 300850 圈，约 10%。
**中断里的每一圈，都是从主循环的时间里扣的**，这是单核上无法回避的算术。

再加一档就看得更清楚。把中断间隔从 1000 节拍改成 100 节拍、中断里的循环改成 100 次：

`实测数据`
`Text`

```text
--- 中断里的循环 100 次，间隔 100 节拍
（15 秒内没有任何输出：主循环几乎拿不到 CPU）
```

中断里的活超过了中断间隔，CPU 就一直停在「进中断、干活、返回、立刻又进中断」的循环里，
主循环的 `++loops` 再也执行不到。这类现象在示波器上看是主循环停摆，
在代码里看只是一个「多写了几行」的循环。

> [!WARNING]
> **中断里的时间预算要按最坏情况算。** 只要中断里的活可能超过中断间隔，
> 主循环就会饿死，而它饿死时中断看起来一切正常——中断次数照常在涨。
> 中断服务函数里只做必须当场做完的事，其余的交给自己置的标志，让主循环去做。

# 第 2 节 共享变量：`volatile` 不等于原子

## 2.1 一条源码，三条指令

主循环与中断各自都要给同一个计数器加一，源码写起来是两处一样的一句话：

`C`

```c
g_shared = g_shared + 1u;
```

Cortex-M3 上 `-O2` 把主循环里那一句编成五条指令：

`实测数据`
`Assembly`

```asm
; race0.elf 的 main 中段，g_shared 在 [r4, #4]
 8000310:	ldr	r3, [r4, #4]      @ 读
 8000312:	subs	r5, #1            @ 循环计数减一
 8000314:	add.w	r3, r3, #1        @ 加一
 8000318:	str	r3, [r4, #4]      @ 写回
 800031a:	bne.n	8000310           @ 回去再读
```

中断里那一句在同一个程序的 `SysTick_Handler` 里：

`实测数据`
`Assembly`

```asm
08000240 <SysTick_Handler>:
 8000242:	ldr	r2, [r3, #0]      @ 先给中断次数加一
 8000244:	adds	r2, #1
 8000246:	str	r2, [r3, #0]
 8000248:	ldr	r2, [r3, #4]      @ 读 g_shared
 800024a:	adds	r2, #1            @ 加一
 800024c:	str	r2, [r3, #4]      @ 写回
 800024e:	bx	lr
```

`volatile` 让每一次 `ldr` 与 `str` 都真实发生，但它没有让这三条指令变成一个整体。
中断可以落在 `ldr` 与 `str` 之间的任何地方：

`Text`

```text
   主循环                                中断（SysTick）
   ───────────────────────────────       ─────────────────────────────
   ldr  r3, [r4, #4]     读 100
                                         ldr  r2, [r3, #4]   读 100
                                         adds r2, #1         算出 101
                                         str  r2, [r3, #4]   写回 101
   adds r3, #1           算出 101
   str  r3, [r4, #4]     写回 101        ← 中断的这一次增量被抹掉了
```

两次加一，结果是 101 而不是 102。**丢的不是中断本身，是中断那一次更新**：
中断的 `adds` 结果被主循环的 `str` 覆盖。主循环每转一圈都给了中断一次机会，
所以中断越密、循环体越短，丢得越多。

`文档`

> "The semantics of an access through a volatile glvalue are implementation-defined.
> If an attempt is made to access an object defined with a volatile-qualified type
> through the use of a non-volatile glvalue, the behavior is undefined."
>
> "volatile is a hint to the implementation to avoid aggressive optimization involving
> the object because the value of the object might be changed by means
> undetectable by an implementation."
>
> —— N4659 §10.1.7.1/5、§10.1.7.1/6

C 侧有一条更直白的保证：

`文档`

> "Volatile accesses to objects are evaluated strictly according to the rules
> of the abstract machine."
>
> —— N3220 §5.1.2.3/6

两句话合起来是一条边界：**`volatile` 管的是「这次访问有没有真的发生」，
不管「这次访问与别的访问之间是什么关系」**。原子性要另外的手段。

真板上的数字把这条边界画得很清楚：

`实测数据`

| 版本 | 期望值 | 实测值 | 差别 |
|---|---|---|---|
| 普通 `volatile` 计数器（ISR 与主循环都 `++`） | 201459（= 200000 + 1459 次中断） | **200000** | **1459 次中断的增量全部丢失** |
| `__atomic_fetch_add`（`seq_cst`） | 202702（= 200000 + 2702 次中断） | **202702** | **一次没丢** |

这是在 STM32F103C8（Cortex-M3、HSI 8 MHz）上实测的：主循环自增 200000 次，
SysTick 每 1000 周期中断一次，ISR 里也自增同一个计数器。
普通版丢掉的 1459 次恰好等于中断次数——**每一次中断的读—改—写都被主循环撞掉**。

> [!CAUTION]
> **少了原子保护的共享计数器不会报错，只会数得少。**
> 程序照常运行、照常输出，数字看起来也差不多，唯一的线索是它与期望值对不上。
> 靠「程序没崩」判断这类问题，是判断不出来的。

## 2.2 主循环与中断共享数据的正确写法

把上面那类竞争消掉，有两条完全不同的路子：**要么让它只有一个写者，要么让读改写变成原子操作。**
先看第一条，它在真实工程里用得更广——`stm32f1xx_it.c` 的注释里那句
「把字节压入环形缓冲并重新挂上单字节接收」就是这一条。

单写者模式的规则只有一句：**每一个变量只由一边写，另一边只读。**

| 变量 | 谁写 | 谁读 |
|---|---|---|
| `head`（生产者索引） | 只由中断写 | 主循环读 |
| `tail`（消费者索引） | 只由主循环写 | 中断读 |
| 缓冲内容 | 中断写进去的那一格 | 主循环取走 |

`C++`

```cpp
/* Cortex-M 侧（在 WSL 里交叉编译，QEMU 里跑）：
   ring.cpp  —— 单生产者单消费者的环形缓冲：中断只动 head，主循环只动 tail
   arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -nostartfiles --specs=nosys.specs \
     -T STM32F103XX_FLASH.ld startup_stm32f103xe.s ring.cpp -o ring.elf
   qemu-system-arm -M netduinoplus2 -kernel ring.elf -nographic -icount shift=0 \
     -semihosting-config enable=on,target=native */
#include <stdint.h>
#include "semihosting.h"

#define SYST_CSR (*(volatile uint32_t *)0xE000E010u)
#define SYST_RVR (*(volatile uint32_t *)0xE000E014u)
#define SYST_CVR (*(volatile uint32_t *)0xE000E018u)

#define CAP 8u                       /* 容量取 2 的幂，取模变成一条 and */

static volatile uint8_t  g_buf[CAP];
static volatile uint32_t g_head;     /* 只在中断里写，主循环只读 */
static volatile uint32_t g_tail;     /* 只在主循环里写，中断只读 */
static volatile uint32_t g_pushed;   /* 中断压进去多少个 */
static volatile uint32_t g_popped;   /* 主循环取走多少个 */
static volatile uint32_t g_dropped;  /* 缓冲满，丢了多少个 */
static volatile uint32_t g_bad;      /* 取出来的字节不等于它的下标：错位了 */

extern "C" void SysTick_Handler(void)
{
    uint32_t h = g_head;
    uint32_t next = (h + 1u) & (CAP - 1u);
    if (next == g_tail) {            /* 满了：丢最新的一个，不动还没取走的数据 */
        g_dropped = g_dropped + 1u;
        return;
    }
    g_buf[h] = (uint8_t)h;           /* 每个字节就是它自己的下标，取出来可以自检 */
    g_head = next;
    g_pushed = g_pushed + 1u;
}

int main(void)
{
    SYST_RVR = 20u;                  /* 每 20 节拍中断一次，比主循环取的速度快 */
    SYST_CVR = 0u;
    SYST_CSR = 7u;

    while (g_pushed < 1000u) {       /* 主循环只管取 */
        uint32_t t = g_tail;
        if (t != g_head) {
            uint8_t v = g_buf[t];
            if (v != (uint8_t)t) {
                g_bad = g_bad + 1u;
            }
            g_tail = (t + 1u) & (CAP - 1u);
            g_popped = g_popped + 1u;
            for (volatile uint32_t k = 0; k < 300u; ++k) { }   /* 主循环取完还有别的活 */
        }
    }

    SYST_CSR = 0u;

    sh_puts("压入            ："); sh_dec32(g_pushed);    sh_puts("\r\n");
    sh_puts("取走            ："); sh_dec32(g_popped);    sh_puts("\r\n");
    sh_puts("因满丢弃        ："); sh_dec32(g_dropped);   sh_puts("\r\n");
    sh_puts("压入减取走      ："); sh_dec32(g_pushed - g_popped); sh_puts("\r\n");
    sh_puts("取出来对不上的  ："); sh_dec32(g_bad);       sh_puts("\r\n");

    for (;;) { }
}

extern "C" void SystemInit(void) { }
extern "C" void _init(void) { }
```

这份程序是故意让消费者慢的：中断每 20 节拍压一个字节，主循环每取一个还要忙 300 圈。

`实测数据`
`Text`

```text
压入            ：1000
取走            ：993
因满丢弃        ：15065
压入减取走      ：7
取出来对不上的  ：0
```

压进去 1000 个、丢弃 15065 个、取走 993 个，还剩 7 个在缓冲里没来得及取
（`while` 在压入到 1000 个时就结束了）。**丢弃全部发生在缓冲满的时候，而且被记录下来；
已经排队的数据一个都没有错位**（最后一行为 0）。

这一条路子的依据是两件事，缺一不可：

| 依据 | 内容 |
|---|---|
| 每个索引只有一个写者 | 不存在两条执行流同时读—改—写同一个变量，丢更新无从发生 |
| 对齐的单字读写本身是原子的 | `uint32_t` 的 `ldr`/`str` 是一条指令，读到的要么是旧值要么是新值，不会是半个值（依据是 ARMv7-M 架构对单次拷贝原子性的保证，**本章没有单独实测，标 `待确认`**） |

> [!IMPORTANT]
> **单写者模式在硬件上成立，在语言标准里仍然是一次竞争。**
> C 与 C++ 的抽象机里没有「中断」这个概念（唯一接近的模型是信号，见 N3220 §5.1.2.3/5），
> 因此中断与主循环访问同一个非原子对象，按标准的字面定义就是数据竞争。
> 工程上通行不等于标准认可：这份代码的前提是「单核、对齐的单字访问、每个变量单写者」，
> 换成多核、换成 64 位量、换成两个写者，它立刻失效。
> 要一份标准认可的写法，把两个索引换成 `std::atomic<uint32_t>`，
> 用 `memory_order_relaxed` 读写（用法见《06-标准库/B-10-内存与并发的基础设施.md》第 5.1 小节）。

标志位是同一模式的最简形式：中断只写、主循环只读，两边都不做读—改—写，
一个 `volatile uint32_t` 就足够。**容易出错的是「标志加数据」的打包**：
中断先写数据再置标志，主循环看到标志再读数据，这个顺序要靠第 4 节的屏障来保证，
不能靠「我按顺序写的」这句直觉。

# 第 3 节 三种修法与它们的代价

## 3.1 关中断：`cpsid i` 与 `cpsie i`

最直接的办法是把中断整个关掉，做完读—改—写再打开。Cortex-M 上这条指令由 `PRIMASK` 寄存器控制，
CMSIS 里的 `__disable_irq()` 与 `__enable_irq()` 展开就是它们：

`C++`

```cpp
/* Cortex-M 侧（在 WSL 里交叉编译，QEMU 里跑，MODE=1 的分支）：
   irq_race.cpp  —— 主循环与 SysTick 中断抢同一个计数器：四种写法的正确性与代价对照
   arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -nostartfiles --specs=nosys.specs \
     -DMODE=1 -T STM32F103XX_FLASH.ld startup_stm32f103xe.s irq_race.cpp -o race1.elf
   qemu-system-arm -M netduinoplus2 -kernel race1.elf -nographic -icount shift=0 \
     -semihosting-config enable=on,target=native */
/* 只列出与本小节有关的几行，完整程序见第 3.4 小节 */
static inline void irq_disable(void) { __asm__ volatile ("cpsid i" ::: "memory"); }
static inline void irq_enable(void)  { __asm__ volatile ("cpsie i" ::: "memory"); }

static void bump(void) { irq_disable(); g_shared = g_shared + 1u; irq_enable(); }
```

（上面是节选。）它编出来是这样，两条 `cps` 把三条读写指令夹在中间：

`实测数据`
`Assembly`

```asm
 8000314:	b672      	cpsid	i           @ 关中断：PRIMASK 置 1
 8000316:	6863      	ldr	r3, [r4, #4]      @ 读
 8000318:	3301      	adds	r3, #1            @ 加一
 800031a:	6063      	str	r3, [r4, #4]      @ 写回
 800031c:	b662      	cpsie	i           @ 开中断：PRIMASK 清 0
 800031e:	3d01      	subs	r5, #1
 8000320:	d1f8      	bne.n	8000314 <main+0x18>
```

关中断与开中断本身很便宜：

`实测数据`

| 操作 | 周期数（STM32F103C8，8 MHz） | 折合时间 |
|---|---|---|
| `cpsid i` + `cpsie i` | **6** | 0.75 µs |
| 一次空函数调用（`-O2`，`noinline`） | 8 | 1.00 µs |

**它的问题不在速度，在状态。** `cpsie i` 无条件把中断打开，而不管进来之前是开还是关。
如果这段代码被另一个已经关了中断的地方调用（中断里、或者别的临界区里），
内层的 `cpsie i` 会把外层的保护提前拆掉：

`Text`

```
   外层的意图：从这里到那里，中断都别进来
   ┌────────────────────────────────────────────────────────┐
   │  cpsid i                                               │
   │  ...                                                   │
   │      内层 cpsid i                                      │
   │      ...                                               │
   │      内层 cpsie i   ← 中断在这里就开了，外层的窗口破了  │
   │  ...                                                   │
   │  cpsie i                                               │
   └────────────────────────────────────────────────────────┘
```

## 3.2 临界区：保存并恢复 `PRIMASK`

把进入前的 `PRIMASK` 存下来，退出时按原值恢复，嵌套就安全了。CMSIS 里对应
`__get_PRIMASK()` 与 `__set_PRIMASK()`：

`C++`

```cpp
/* Cortex-M 侧（在 WSL 里交叉编译，QEMU 里跑，MODE=2 的分支）：
   节选自 irq_race.cpp 的写法 2 */
static inline uint32_t primask_get(void)
{
    uint32_t v;
    __asm__ volatile ("mrs %0, primask" : "=r"(v));
    return v;
}
static inline void primask_set(uint32_t v) { __asm__ volatile ("msr primask, %0" :: "r"(v) : "memory"); }

static void bump(void)
{
    uint32_t saved = primask_get();    /* 记住进来之前是开还是关 */
    irq_disable();
    g_shared = g_shared + 1u;          /* 临界区：只有这三条指令 */
    primask_set(saved);                /* 按原样恢复，不是无条件打开 */
}
```

（上面是节选。）比关中断版多出两条指令，代价就在这里：

`实测数据`
`Assembly`

```asm
 800031c:	f3ef 8210 	mrs	r2, PRIMASK       @ 读 PRIMASK
 8000320:	b672      	cpsid	i
 8000322:	6863      	ldr	r3, [r4, #4]      @ 读
 8000324:	3301      	adds	r3, #1            @ 加一
 8000326:	6063      	str	r3, [r4, #4]      @ 写回
 8000328:	f382 8810 	msr	PRIMASK, r2       @ 按原值恢复
 800032c:	3d01      	subs	r5, #1
```

临界区里关中断的这段时间，直接加到系统的最坏中断响应时间上。真板上已经测到的是两头：

`实测数据`

| 项 | 周期数（STM32F103C8，8 MHz） |
|---|---|
| 中断延迟（硬件，写 `NVIC_ISPR` 到进 ISR） | 21 |
| 一次中断往返 | 50 |
| `cpsid i` + `cpsie i` | 6 |

中间那段临界区要多少，按上面三个数推算：`mrs` + `cpsid i` + `msr` 三条与 `cpsid`/`cpsie` 两条同量级，
再加快三条读写指令，整段窗口在十几个周期，折合 1.5 µs 上下。
**这三条指令没有在真板上单独计过周期，标 `待确认`**；
量它一次的办法是写 `NVIC_ISPR` 触发中断、读 `SYST_CVR` 前后相减。

结论是两条纪律：**临界区里只放必须保护的几条指令**，不要调用函数、不要放循环、
不要在里面做浮点运算；**关中断的时间就是中断延迟的上界**，它要按最坏情况计入系统的实时性预算。

> [!TIP]
> **只关掉一部分中断：`BASEPRI`。**
> `PRIMASK` 是一位开关，把除 `NMI` 与 `HardFault` 之外的所有中断都关掉。
> 想让高优先级的中断照常响应、只挡住低优先级的，用 `BASEPRI`：写入一个优先级阈值，
> 优先级数值大于等于它的中断被屏蔽。
> 常见做法是给「必须在极短时间内响应」的中断留高优先级，
> 用 `BASEPRI` 挡住其余中断，这样临界区不会推迟关键中断。
> 本测试只有 SysTick 一个中断源，**`BASEPRI` 的实际效果与优先级分组标 `待确认`**。

## 3.3 原子量：不关中断的做法

第三条路既不关中断，也不依赖单写者：把「读—改—写」交给硬件提供的独占访问指令。
Cortex-M3 上是 `LDREX` 与 `STREX` 这一对：`LDREX` 读出一个字并**标记**这个地址，
`STREX` 只在标记仍然有效时写入并返回 0，否则返回 1、什么都不写。

`实测数据`
`Assembly`

```asm
; 真板 STM32F103C8 上，__atomic_fetch_add（seq_cst）的自增
dmb  ish
ldrex r1, [r3]
adds  r1, #1
strex r2, r1, [r3]
cmp   r2, #0
bne.n -8            @ 别人动过这个地址就重来
dmb  ish
```

QEMU 侧用 `std::atomic<uint32_t>` 编出来是同一形状（省掉了两条 `dmb`，原因见第 4.3 小节）：

`实测数据`
`Assembly`

```asm
; race3.elf 的 main 中段，g_shared 在 [r4]
 8000322:	e854 3f00 	ldrex	r3, [r4]          @ 独占读
 8000326:	3301      	adds	r3, #1            @ 加一
 8000328:	e844 3200 	strex	r2, r3, [r4]      @ 独占写，失败返回 1
 800032c:	2a00      	cmp	r2, #0
 800032e:	d1f8      	bne.n	8000322           @ 失败就重来
 8000330:	3d01      	subs	r5, #1
```

重试循环不是给多核准备的。ARMv7-M 的约定是：异常进入与退出会清掉本地独占标记，
因此单核上中断插在 `ldrex` 与 `strex` 之间时，`strex` 照样可能返回 1，
这个 `bne` 就是为这种情况兜底的。
**真板上没有单独统计过重试次数，这条机制与重试频率都标 `待确认`**；
能确认的是结果——真板上 200000 次自增加 2702 次中断，原子版一次没丢。

代价是真板上一组干净的对照：

`实测数据`

| 自增写法 | 周期数（STM32F103C8，8 MHz） | 与普通自增之比 |
|---|---|---|
| 普通 `volatile`（`ldr`/`adds`/`str`） | **7** | 1 |
| `__atomic_fetch_add`（`seq_cst`） | **14** | 2 |

多出来的 7 个周期，对应原子版多出的两条 `dmb ish` 与 `ldrex`/`strex`/`cmp`/`bne` 这一串；
**屏障与独占访问各占多少没有分开测，标 `待确认`**。
**原子操作不是免费的**：它适合用在「一次竞争都丢不起、又不能关中断」的地方，
不适合放进每微秒都要跑一次的路径。

## 3.4 三种写法的实测对照

下面这份程序把四种写法放在同一个源文件里，用 `-DMODE=` 选一种编译。
两个阶段：先让中断真的插进来，验正确性；再关掉中断只留计数器，比每次自增的节拍数。

`C++`

```cpp
/* Cortex-M 侧（在 WSL 里交叉编译，QEMU 里跑）：
   irq_race.cpp  —— 主循环与 SysTick 中断抢同一个计数器：四种写法的正确性与代价对照
   arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -nostartfiles --specs=nosys.specs \
     -DMODE=0 -T STM32F103XX_FLASH.ld startup_stm32f103xe.s irq_race.cpp -o race0.elf
   （把 -DMODE=0 依次换成 1、2、3 得到 race1.elf、race2.elf、race3.elf）
   qemu-system-arm -M netduinoplus2 -kernel race0.elf -nographic -icount shift=0 \
     -semihosting-config enable=on,target=native */
#include <stdint.h>
#if MODE == 3
#include <atomic>
#endif
#include "semihosting.h"

#define SYST_CSR (*(volatile uint32_t *)0xE000E010u)   /* 控制与状态 */
#define SYST_RVR (*(volatile uint32_t *)0xE000E014u)   /* 重装值 */
#define SYST_CVR (*(volatile uint32_t *)0xE000E018u)   /* 当前值，读它顺便清 COUNTFLAG */
#define CSR_ENABLE    1u
#define CSR_TICKINT   2u
#define CSR_CLKSOURCE 4u

#define LOOPS 100000u

/* 关中断与临界区的两条路线：CMSIS 的 __disable_irq/__enable_irq 展开后就是这两条 */
static inline void irq_disable(void) { __asm__ volatile ("cpsid i" ::: "memory"); }
static inline void irq_enable(void)  { __asm__ volatile ("cpsie i" ::: "memory"); }
static inline uint32_t primask_get(void)
{
    uint32_t v;
    __asm__ volatile ("mrs %0, primask" : "=r"(v));
    return v;
}
static inline void primask_set(uint32_t v) { __asm__ volatile ("msr primask, %0" :: "r"(v) : "memory"); }

static volatile uint32_t g_isr;        /* 中断进了多少次，只在中断里改 */

#if MODE == 0
/* 写法 0：只有 volatile。每次访问都真的读写内存，但「读—改—写」不是一体 */
static volatile uint32_t g_shared;
static void bump(void) { g_shared = g_shared + 1u; }
static uint32_t peek(void) { return g_shared; }

#elif MODE == 1
/* 写法 1：关中断。最省事的写法，代价是不保存原来的状态 */
static volatile uint32_t g_shared;
static void bump(void) { irq_disable(); g_shared = g_shared + 1u; irq_enable(); }
static uint32_t peek(void) { return g_shared; }

#elif MODE == 2
/* 写法 2：临界区。把 PRIMASK 存下来，退出时按原值恢复，因此可以嵌套 */
static volatile uint32_t g_shared;
static void bump(void)
{
    uint32_t saved = primask_get();
    irq_disable();
    g_shared = g_shared + 1u;
    primask_set(saved);
}
static uint32_t peek(void) { return g_shared; }

#else
/* 写法 3：原子量。不关中断，靠 LDREX/STREX 把「读—改—写」做成一体 */
static std::atomic<uint32_t> g_shared{0};
static void bump(void) { g_shared.fetch_add(1u, std::memory_order_relaxed); }
static uint32_t peek(void) { return g_shared.load(std::memory_order_relaxed); }
#endif

/* 中断服务函数必须保持 C 链接，否则向量表按名字找不到它（见第 3.5 小节） */
#ifdef NO_C_LINKAGE
void SysTick_Handler(void)
#else
extern "C" void SysTick_Handler(void)
#endif
{
    g_isr = g_isr + 1u;
    bump();                            /* 中断里也加一次 */
}

int main(void)
{
    /* 第一阶段：让中断真的插进来，看总数对不对 */
    SYST_RVR = 100u;
    SYST_CVR = 0u;
    SYST_CSR = CSR_ENABLE | CSR_TICKINT | CSR_CLKSOURCE;

    for (uint32_t i = 0; i < LOOPS; ++i) {
        bump();
    }

    SYST_CSR = 0u;

    uint32_t isr = g_isr;
    uint32_t got = peek();
    uint32_t expect = LOOPS + isr;

    sh_puts("写法            ："); sh_dec32((uint32_t)MODE);  sh_puts("\r\n");
    sh_puts("主循环次数      ："); sh_dec32(LOOPS);          sh_puts("\r\n");
    sh_puts("中断进入次数    ："); sh_dec32(isr);            sh_puts("\r\n");
    sh_puts("应得计数器      ："); sh_dec32(expect);         sh_puts("\r\n");
    sh_puts("实得计数器      ："); sh_dec32(got);            sh_puts("\r\n");
    sh_puts("丢掉的更新      ："); sh_dec32(expect - got);   sh_puts("\r\n");

    /* 第二阶段：关掉中断，只量每次自增本身花多少节拍 */
    g_isr = 0u;
    SYST_RVR = 0x00FFFFFFu;
    SYST_CVR = 0u;
    SYST_CSR = CSR_ENABLE | CSR_CLKSOURCE;        /* 只计数，不产生中断 */

    uint32_t t0 = SYST_CVR;
    for (uint32_t i = 0; i < LOOPS; ++i) {
        bump();
    }
    uint32_t t1 = SYST_CVR;
    SYST_CSR = 0u;

    uint32_t ticks = (t0 - t1) & 0x00FFFFFFu;
    sh_puts("同一条自增      ："); sh_dec32(ticks);         sh_puts(" 节拍/");
    sh_dec32(LOOPS); sh_puts(" 次\r\n");
    sh_puts("每次的节拍数    ："); sh_dec32(ticks / (LOOPS / 1000u)); sh_puts(" 毫节拍/次\r\n");

    for (;;) { }
}

extern "C" void SystemInit(void) { }
extern "C" void _init(void) { }
```

四种写法的输出（QEMU、`-icount shift=0`，每一种都跑两遍，两遍数字完全相同）：

`实测数据`

| 写法 | 循环体指令数 | 中断进入次数 | 应得 | 实得 | 丢掉的更新 | 自增节拍（10 万次） |
|---|---|---|---|---|---|---|
| 0：裸 `volatile` | 5 | 843 | 100843 | **100337** | **506** | 84000 |
| 1：关中断 | 7 | 1184 | 101184 | 101184 | 0 | 117600 |
| 2：临界区（保存/恢复） | 8 | 1355 | 101355 | 101355 | 0 | 134400 |
| 3：`std::atomic`（relaxed） | 7 | 1190 | 101190 | 101190 | 0 | 117600 |

这张表里有三处值得读：

| 现象 | 读法 |
|---|---|
| 写法 0 丢了 506 次，另外三种一次不丢 | 三种修法都解决了原子性，选哪一种看别的约束 |
| 四种写法的中断次数不一样（843 到 1355） | 循环体越长，跑得越慢，同样 10 万圈里中断插进来的次数越多 |
| 节拍数与循环体指令数严格成正比 | 在 `-icount shift=0` 下 QEMU 的节拍与指令数线性相关（这里约 6 条指令一个节拍）。**这张表用来看相对关系，绝对周期数以真板为准** |

同一件事在真板上的两个数字前面已经出现过：普通自增 **7 周期**、原子自增 **14 周期**，
而关中断再开只要 **6 周期**。三种修法怎么选：

| 场合 | 首选 | 理由 |
|---|---|---|
| 保护几条指令的读—改—写，中断里也要用 | **保存/恢复 `PRIMASK` 的临界区** | 6 周期，嵌套安全；临界区短，对中断延迟影响可控 |
| 一个只增不减的计数器、索引 | **`std::atomic` + `relaxed`** | 不关中断，最坏中断延迟不受影响 |
| 一次都不能丢、又要跨核 | **`std::atomic`（`seq_cst` 或 `release`/`acquire`）** | 只有它能跨核，代价是普通自增的两倍 |
| 中断只写、主循环只读的标志或环形缓冲索引 | **`volatile` + 单写者**（第 2.2 小节） | 不需要原子操作，因为根本没有读—改—写竞争 |
| 只在中断里执行的读—改—写 | **什么都不用加** | 同级与低优先级中断本来就进不来 |

## 3.5 写错了会怎样：ISR 忘了 `extern "C"`

写第 3.4 小节那份程序时，我第一版把 `SysTick_Handler` 写成了普通的 C++ 函数。
程序编译链接全部通过，烧进 QEMU 之后**一行输出都没有**——不是输出错了，是根本走不到打印。

# 第 4 节 原子操作与屏障

## 4.1 汇编对照：普通、`volatile`、原子

同一件事——给一个 32 位变量加一——的五种写法，在两边指令集上各编一遍：

`C++`

```cpp
/* atomic_asm.cpp   编译（只看汇编，不链接）：g++ -std=c++17 -O2 -S atomic_asm.cpp -o atomic_asm_host.s
   （Cortex-M 侧换编译器：arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -S atomic_asm.cpp -o atomic_asm_arm.s） */
#include <atomic>
#include <cstdint>

uint32_t g_plain;
volatile uint32_t g_vol;
std::atomic<uint32_t> g_atom{0};

void plain_inc(void) { g_plain = g_plain + 1u; }
void vol_inc(void)   { g_vol = g_vol + 1u; }

void atom_seq(void)  { g_atom.fetch_add(1u); }                            /* 默认 seq_cst */
void atom_rel(void)  { g_atom.fetch_add(1u, std::memory_order_relaxed); }
void atom_acq(void)  { g_atom.fetch_add(1u, std::memory_order_acq_rel); }

bool atom_cas(void)
{
    uint32_t old = g_atom.load(std::memory_order_relaxed);
    return g_atom.compare_exchange_weak(old, old + 1u);
}

uint32_t atom_load_acquire(void) { return g_atom.load(std::memory_order_acquire); }
void     atom_store_release(void) { g_atom.store(1u, std::memory_order_release); }
void     fence_seq(void) { std::atomic_thread_fence(std::memory_order_seq_cst); }

/* 发布：先写数据，再置标志。三种内存序下，编译器的排法不一样 */
int g_data;
std::atomic<int> g_flag{0};
void publish_relaxed(int v) { g_data = v; g_flag.store(1, std::memory_order_relaxed); }
void publish_release(int v) { g_data = v; g_flag.store(1, std::memory_order_release); }
void publish_seq(int v)     { g_data = v; g_flag.store(1, std::memory_order_seq_cst); }
```

两边放在一起，差别集中在三处：

| 问题 | Cortex-M3 | x86-64 |
|---|---|---|
| 普通自增会不会被中断拆开 | **会**：三条指令，中断落在中间就丢更新 | **单核上不会**：一条 `addl $1, mem`，中断只在指令边界上被响应 |
| 原子自增怎么做 | `ldrex` + `strex` + 失败重试 | 一条带 `lock` 前缀的 `addl` |
| `relaxed` 与 `seq_cst` 差多少 | **差两条 `dmb`**（真板上 7 周期与 14 周期） | **不差**：`lock` 前缀同时给了原子性与顺序 |

第一行解释了一个常见现象：同一份有竞争的自增代码，在桌面上跑一年也不出问题，
搬到单片机上一天就丢几千次。桌面上那条指令本身就是不可分割的，
ARM 上要三条，中间那条缝足够进一次中断。

## 4.2 屏障指令：`dmb`、`dsb`、`isb`

Cortex-M3 上与内存顺序有关的三条指令：

| 指令 | 保证什么 | 典型用途 |
|---|---|---|
| `dmb` | 它之前的所有内存访问，在它之后的任何内存访问之前被观察到 | 发布数据前、读标志后 |
| `dsb` | 它之前的所有内存访问**执行完成**才继续 | 改外设配置、跳转前、写控制寄存器后 |
| `isb` | 清空流水线，重新取指 | 改完向量表、改完影响后续指令的寄存器之后 |

`dmb` 只保证「顺序」，不保证「完成」：写缓冲里的数据可能在 `dmb` 之后仍然没有到达外设。
对外设寄存器做完关键配置之后要的是 `dsb`，本测试没有涉及外设时序，**标 `待确认`**。

C++ 层面的屏障有两级，很容易混：

| 写法 | 挡住谁 | 生成什么 |
|---|---|---|
| `std::atomic_thread_fence(std::memory_order_seq_cst)` | 编译器**与** CPU | Cortex-M3：`dmb ish`；x86-64：`lock orq $0, (%rsp)` |
| `asm volatile ("" ::: "memory")` | 只挡编译器 | 没有任何指令，只影响编译器的排布 |

第 3 章讲 `volatile` 时的那份轮询程序，本质上要的就是第二行那个效果：
让编译器每次真的去读。而第 5 节要处理的「标志与数据谁先到」，
是 CPU 层面的顺序，只有第一行那种真屏障才能管住。

真板上屏障的价格可以从这一对数字看个量级：普通自增 7 周期、原子自增 14 周期，
多出的 7 个周期（在 8 MHz 的核上约 0.9 µs）里同时包含两条 `dmb ish` 与独占访问指令。
**两者没有分开计过，标 `待确认`**——这就是「顺序」在这块芯片上的标价量级。

## 4.3 内存序：默认的 `seq_cst` 够用

第 4.1 小节的 `publish` 三个版本，把内存序的差别显示得很清楚（Cortex-M3、`-O2`）：

`实测数据`
`Assembly`

```asm
_Z15publish_relaxedi:                @ relaxed：两条普通存储，没有任何屏障
	movs	r2, #1
	ldr	r3, .L32
	str	r0, [r3, #12]            @ 先写数据
	str	r2, [r3, #16]            @ 再置标志
	bx	lr
_Z15publish_releasei:                @ release：屏障在写标志之前
	movs	r2, #1
	ldr	r3, .L35
	str	r0, [r3, #12]
	dmb	ish                      @ 数据必须先被看到
	str	r2, [r3, #16]
	bx	lr
_Z11publish_seqi:                    @ seq_cst：前后各一条
	ldr	r3, .L38
	movs	r2, #1
	str	r0, [r3, #12]
	dmb	ish
	str	r2, [r3, #16]
	dmb	ish
	bx	lr
```

`release` 与 `seq_cst` 的语义差别是「要不要全局单一顺序」，不是「要不要屏障」。
日常写代码时按下面的口径选，不必一开始就纠结：

| 场合 | 用什么 | 依据 |
|---|---|---|
| 一个计数器、一个索引，只要求「不丢」 | `relaxed` | 要的只是原子性；顺序由别处的同步负责 |
| 中断写数据、主循环读数据，靠一个标志传递 | 标志用 `release` 写、`acquire` 读 | 数据必须先在标志之前可见 |
| 拿不准、或者多处同步交织 | **默认的 `seq_cst`** | 两边都多花一点（Cortex-M3 上多一条 `dmb`），换来不必推理 |
| 单核、中断与主循环之间 | 临界区往往比内存序更简单 | 单核上关中断同时解决了原子性与顺序 |

> [!IMPORTANT]
> **`seq_cst` 是默认值，也是不出错的选择。**
> 它在 x86-64 上几乎不花钱（`lock` 前缀本来就要加），
> 在 Cortex-M3 上一次多两三个周期。
> 把 `relaxed` 留给那些「只需要原子、不需要顺序」的计数器，
> 其余场合用默认值；真正需要 `acquire`/`release` 推理的地方，
> 完整的 happens-before 规则见《06-标准库/B-10-内存与并发的基础设施.md》第 5.2 小节，
> 线程语境下的完整体系见【待补：09-简单算法/】。

# 第 5 节 为什么编译器与 CPU 都会重排

## 5.1 编译器侧：`-O2` 下的真凭实据

编译器优化时依据的是语言抽象机：**只有一条执行路径，没有人会从旁边改内存**。
在这个前提下，把循环里不变的读提到循环外、把两条相邻的写合成一条、调换两条写的先后，
都是合法的变换——它们不改变单线程程序的可观察行为。中断不在这套模型里，
所以编译器不会为它留任何余地。

下面这份程序把四种常见形态写在同一个文件里，只出汇编：

`C++`

```cpp
/* reorder.cpp   编译（只看汇编，不链接）：g++ -std=c++17 -O2 -S reorder.cpp -o reorder_host.s
   （Cortex-M 侧换编译器：arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -S reorder.cpp -o reorder_arm.s） */
#include <cstdint>

/* 1. 循环不变的读：g_cfg 在循环里没被改过，编译器可以只读一次 */
int g_cfg = 1;
long g_acc;
void accumulate(int n)
{
    for (int i = 0; i < n; ++i) {
        g_acc += g_cfg;
    }
}

/* 2. 发布顺序：先写数据，再置标志 */
int g_payload;
int g_ready;
void publish(int v)
{
    g_payload = v;
    g_ready = 1;
}

/* 3. 读的顺序：先看标志，再读数据 */
int consume(void)
{
    if (g_ready == 0) {
        return -1;
    }
    return g_payload;
}

/* 4. 两个写之间夹一个读 */
int g_a, g_b, g_c;
void sandwich(void)
{
    g_a = 1;
    g_c = g_b;
    g_b = 2;
}
```

x86-64 上 `-O2` 编出来是这样的（MinGW-w64 15.2.0）：

`实测数据`
`Assembly`

```asm
_Z7publishi:
	movl	$1, g_ready(%rip)        @ 先置标志
	movl	%ecx, g_payload(%rip)    @ 后写数据 ← 与源码顺序正好相反
	ret
_Z8sandwichv:
	movl	g_b(%rip), %eax          @ 读 g_b 被提到最前
	movl	$1, g_a(%rip)            @ 写 g_a 落到它后面
	movl	$2, g_b(%rip)
	movl	%eax, g_c(%rip)
	ret
_Z10accumulatei:
	testl	%ecx, %ecx
	jle	.L1
	imull	g_cfg(%rip), %ecx        @ 整个循环被一条乘法取代
	addl	%ecx, g_acc(%rip)
	ret
```

同一份源码交给 Cortex-M3，三处的表现各不相同：

`实测数据`
`Assembly`

```asm
_Z7publishi:
	movs	r2, #1
	ldr	r3, .L7
	strd	r0, r2, [r3, #4]         @ 两条写被合并成一条双字存储
	bx	lr
_Z8sandwichv:
	movs	r1, #1
	movs	r2, #2
	ldr	r3, .L15
	ldr	r0, [r3, #20]            @ 读 g_b 被提到写 g_a 之前
	str	r2, [r3, #20]
	strd	r1, r0, [r3, #12]
	bx	lr
_Z10accumulatei:
	cmp	r0, #0
	ble	.L1
	ldr	r2, .L4
	ldr	r1, .L4+4
	ldr	r3, [r2]
	ldr	r1, [r1]
	mla	r3, r0, r1, r3           @ 循环被一条乘加取代，g_cfg 只读一次
	str	r3, [r2]
	bx	lr
```

三处变换分别是：

| 源码 | x86-64 | Cortex-M3 | 后果 |
|---|---|---|---|
| `publish`：先数据后标志 | **两条写的顺序被调换** | 两条写**合并**成一条 `strd` | 读者可能看到「标志已置、数据未到」 |
| `sandwich`：写、读、写 | 读被提到最前 | 读被提到写之前 | 中间状态在别的执行流看来顺序不同 |
| `accumulate`：循环 10 万次累加 | 一条 `imull` | 一条 `mla` | 循环里对 `g_cfg` 的 10 万次读**只剩一次** |

第三条有一个可以直接看到的后果。下面这份程序里，中断会把 `g_cfg` 从 1 改成 2，
主循环累加它 10 万次：

`C++`

```cpp
/* Cortex-M 侧（在 WSL 里交叉编译，QEMU 里跑）：
   hoist.cpp  —— 中断会改的一个配置值：主循环累加它，加不加 volatile 结果不同
   arm-none-eabi-g++ -mcpu=cortex-m3 -mthumb -O2 -nostartfiles --specs=nosys.specs \
     -DUSE_VOLATILE=1 -T STM32F103XX_FLASH.ld startup_stm32f103xe.s hoist.cpp -o hoist1.elf
   （-DUSE_VOLATILE=0 得到 hoist0.elf）
   qemu-system-arm -M netduinoplus2 -kernel hoist1.elf -nographic -icount shift=0 \
     -semihosting-config enable=on,target=native */
#include <stdint.h>
#include "semihosting.h"

#define SYST_CSR (*(volatile uint32_t *)0xE000E010u)
#define SYST_RVR (*(volatile uint32_t *)0xE000E014u)
#define SYST_CVR (*(volatile uint32_t *)0xE000E018u)

#define ITER 100000u

#ifndef USE_VOLATILE
#define USE_VOLATILE 0
#endif

static volatile uint32_t g_ticks;

#if USE_VOLATILE
static volatile uint32_t g_cfg = 1u;   /* 中断会改它，主循环每次都读 */
#else
static uint32_t g_cfg = 1u;            /* 少了 volatile，编译器认为循环里没人改它 */
#endif

static uint32_t g_acc;

extern "C" void SysTick_Handler(void)
{
    g_ticks = g_ticks + 1u;
    g_cfg = 2u;                        /* 中断把配置从 1 改成 2 */
}

int main(void)
{
    SYST_RVR = 1000u;
    SYST_CVR = 0u;
    SYST_CSR = 7u;

    for (uint32_t i = 0; i < ITER; ++i) {
        g_acc += g_cfg;
    }

    SYST_CSR = 0u;

    sh_puts("g_cfg 带 volatile："); sh_dec32((uint32_t)USE_VOLATILE); sh_puts("\r\n");
    sh_puts("中断次数        ："); sh_dec32(g_ticks);               sh_puts("\r\n");
    sh_puts("累加结果 g_acc  ："); sh_dec32(g_acc);                 sh_puts("\r\n");
    sh_puts("每次都读 1 时应为："); sh_dec32(ITER);                  sh_puts("\r\n");
    sh_puts("每次都读 2 时应为："); sh_dec32(ITER * 2u);             sh_puts("\r\n");

    for (;;) { }
}

extern "C" void SystemInit(void) { }
extern "C" void _init(void) { }
```

两种写法的输出：

`实测数据`
`Text`

```text
g_cfg 带 volatile：1
中断次数        ：67
累加结果 g_acc  ：198510
每次都读 1 时应为：100000
每次都读 2 时应为：200000
```

`实测数据`
`Text`

```text
g_cfg 带 volatile：0
中断次数        ：0
累加结果 g_acc  ：100000
每次都读 1 时应为：100000
每次都读 2 时应为：200000
```

带 `volatile` 的版本老老实实循环 10 万次（汇编是 `ldr`/`subs`/`add`/`bne` 四条的循环，
每次真的去读），67 次中断插进来把配置改成 2，累加结果落在 1 与 2 之间：198510。

不带 `volatile` 的版本，循环被一条 `mla` 取代：

`实测数据`
`Assembly`

```asm
 800031a:	481e      	ldr	r0, [pc, #120]	@ 配置值的地址
 800031c:	18cb      	adds	r3, r1, r3
 800031e:	fb00 3301 	mla	r3, r0, r1, r3      @ g_acc += g_cfg * 100000
 8000324:	606b      	str	r3, [r5, #4]
```

程序在中断来得及发生之前就跑完了（**中断次数 0**），结果是 100000——
正好等于「一直读到 1」的答案。中断改的那个 2，主循环从头到尾没有看见。

> [!CAUTION]
> **「一千万次里改一次」的配置值，编译器可以只读一次。**
> 累加循环、求平均、超时计数都容易写成这个样子。
> 判据很简单：**这个变量会不会被中断或别的执行流修改**，会，就必须 `volatile`
> （或者用原子量），没有例外。

## 5.2 CPU 侧：写缓冲与观察顺序

编译器之外还有一层。Cortex-M3 是顺序执行的核：指令按程序顺序发射，没有乱序执行。
但**顺序执行不等于写的顺序立刻被外部看见**：写会先进写缓冲，总线上的完成时间可能晚于指令执行时间，
不同目标的写也可能以不同的先后到达。

这一层在 QEMU 上观察不到：QEMU 按程序顺序执行存储，不模拟写缓冲，
所以凡是「CPU 重排导致的可见顺序问题」在 QEMU 里跑多少遍都是对的。
这类结论只能靠真板或架构手册，**本章真板上没有可观察的外设与第二个总线主设备，
因此 CPU 侧重排在真板上的直接观测标 `待确认`**。

能测的是屏障的价格。真板上同一件事两种写法：

`实测数据`

| 写法 | 周期数 | 说明 |
|---|---|---|
| 普通自增（`ldr`/`adds`/`str`） | 7 | 没有屏障 |
| `__atomic_fetch_add`（`seq_cst`） | 14 | 两条 `dmb ish` 加独占访问 |

**多出来的 7 个周期就是「让别人按我看得见的顺序看到」的价钱。**
在 8 MHz 的核上约 0.9 µs，这个数字决定了屏障该放在哪：
放在每一轮循环里，代价立刻翻倍；放在发布点与消费点，几乎不影响吞吐。

需要屏障的场合可以按「谁需要看到谁」来判断：

| 场合 | 需要什么 |
|---|---|
| 一个计数器，只要求不丢 | 只要原子性（`relaxed`），不需要屏障 |
| 写数据、置标志，另一条执行流按标志取数据 | 写端 `release`、读端 `acquire` |
| 改向量表、改影响后续取指的寄存器 | `dsb` + `isb`，见第 4.2 小节 |
| 改完外设配置马上要用 | `dsb`（**真板外设时序标 `待确认`**） |
| 单核上中断与主循环共享几条指令 | 关中断，比屏障简单 |

## 5.3 写错了会怎样：标志先到、数据后到

第 5.1 小节的 `publish` 给出了现场：源码写的是「先数据后标志」，
x86-64 上编译器把两条写调换了顺序。放进中断的场景就是一次真实故障：

`Text`

```
   主循环                                    中断
   ────────────────────────────────          ────────────────────────────
   g_payload = 新数据
   （编译器可能把这一条挪到后面）
                                              if (g_ready) 读到 1
                                              取 g_payload → 拿到旧数据
   g_ready = 1
```

在单核上这条缝很窄（两条存储指令之间），但中断恰恰喜欢落在窄缝里：
主循环每秒发布几百次、中断每秒进几千次，一天下来这种窗口会被撞上很多次。
**症状是「偶尔读到旧数据」，而且加一句打印就可能消失**——打印会改变编译器的排布。

三种修法，按代价从低到高：

| 修法 | 做什么 | 代价 |
|---|---|---|
| 包进临界区 | 把「写数据 + 置标志」放进保存/恢复 `PRIMASK` 的临界区 | 约 7 周期，中断延迟略微增加 |
| 标志改成原子量 | 数据用 `volatile`，标志用 `std::atomic` 的 `release` 写、`acquire` 读 | Cortex-M3 上每次多一条 `dmb`，不关中断 |
| 换成单写者结构 | 不做「标志 + 数据」，改成环形缓冲 | 结构要重写，但消掉了这类窗口（第 2.2 小节） |

`文档`

> "The execution of a program contains a data race if it contains two potentially
> concurrent conflicting actions, at least one of which is not atomic, and neither
> happens before the other... Any such data race results in undefined behavior."
>
> —— N4659 §4.7.1/20

这条规则在中断语境下的含义值得说清：标准没有「中断」这个模型，
因此中断与主循环之间对同一个非原子变量的访问，按字面就是数据竞争；
`volatile` 不在豁免名单里。**能豁免的只有无锁原子对象**，
这也解释了为什么「关键的那一个变量」要写成 `std::atomic` 而不是「`volatile` 加上小心」。

> [!NOTE]
> 这一节把第 3 章留下的账结清了：`volatile` 保证访问真的发生（第 2.1 小节的文档依据），
> 原子量保证读—改—写不可分割（第 3.3 小节的 `ldrex`/`strex`），
> 屏障保证顺序被别人看见（第 4.2 小节的 `dmb`）。
> 三件事各自解决一个问题，互相代替不了：**用错了工具，代码会编译、会运行、会偶尔出错。**

# 第 6 节 速查表

| 常用件 | 一句话用途 | 典型坑 |
|---|---|---|
| `volatile` | 让每次访问真的读写内存 | **不等于原子**：读—改—写仍可被打断；也不保证跨执行流的顺序 |
| `cpsid i` / `cpsie i` | 关/开所有可屏蔽中断（CMSIS 的 `__disable_irq`/`__enable_irq`） | 无条件打开，嵌套调用会把外层的保护提前拆掉 |
| `mrs`/`msr PRIMASK` | 保存并恢复中断状态（`__get_PRIMASK`/`__set_PRIMASK`） | 临界区里塞进函数调用或循环，中断延迟立刻变长 |
| 临界区 | 保护几条指令的读—改—写 | 关中断的时间就是最坏中断延迟的下界 |
| `BASEPRI` | 只挡住低优先级中断 | 优先级分组配错就挡不住该挡的；本测试**标 `待确认`** |
| `LDREX` / `STREX` | 硬件级的独占读—改—写 | `strex` 会失败，必须写成重试循环 |
| `std::atomic<T>` | 标准认可的无锁读写 | `relaxed` 只给原子性，不给顺序；体积与 `T` 一样大 |
| `memory_order` | 告诉编译器与 CPU 需要多少顺序 | 默认 `seq_cst` 最省心；`relaxed` 用在只求不丢的计数器上 |
| `dmb` / `dsb` / `isb` | 观察顺序 / 执行完成 / 重新取指 | `dmb` 不保证写完，改外设要用 `dsb` |
| `std::atomic_thread_fence` | C++ 层面的屏障 | Cortex-M3 上是 `dmb ish`，x86-64 上是 `lock orq $0, (%rsp)` |
| `asm volatile ("" ::: "memory")` | 只挡编译器，不生成指令 | 挡不住 CPU 的写缓冲 |
| ISR 的签名与名字 | 与启动文件约定好的入口 | **忘了 `extern "C"` 会落到 `Default_Handler` 的 `b .` 上**，链接器不报错 |
| `NVIC_ISPR` | 软件触发一次中断（测试用） | 只能置挂起位，清挂起要用 `NVIC_ICPR` |
| `SYST_RVR` / `SYST_CVR` / `SYST_CSR` | 系统节拍：重装值、当前值、控制 | `CVR` 只有 24 位，相减要 `& 0x00FFFFFF` |
| `-icount shift=0` | 让 QEMU 的节拍与指令数成正比 | 不加它时中断次数随负载变化，数字不可复现 |
| `-semihosting-config enable=on` | 把 `bkpt 0xAB` 的输出接到 stdout | 真板上要 `arm semihosting enable` 才看得到 |
| `nm` | 看 ISR 的符号名对不对 | 名字被修饰过就说明链接没接上向量表 |
| `objdump -d --disassemble=函数名` | 只看一个函数的汇编 | 内联掉的函数不会出现在符号表里 |
| 真板 + `NVIC_ISPR` | 测中断延迟与往返周期 | 与机型无关，但要确认时钟源（本板为 HSI 8 MHz） |
