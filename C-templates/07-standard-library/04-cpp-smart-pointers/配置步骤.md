# 配置步骤 · 07-standard-library/04-cpp-smart-pointers（智能指针与回调注册）

本模板是**分阶段的整体演练**：成品是一个资源管理小系统，
先用智能指针管住对象与文件的生存期，再让弱引用把循环引用断开，
最后用 `std::function` 做一个回调注册表。每个阶段结束时程序都能编译、能运行。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

---

## 成品形态

做完这 4 个阶段之后，`app_cli.exe` 具备下面这些能力：

| 能力 | 由哪一阶段提供 |
|---|---|
| 工厂函数返回 `unique_ptr`，自定义删除器把 `FILE *` 管起来 | 阶段 1 |
| `shared_ptr` 的引用计数变化（复制、按值传参、按引用传参、出作用域） | 阶段 2 |
| 强引用互相指向造成泄漏，弱引用断环后正常释放 | 阶段 3 |
| 事件名到 `std::function` 的注册表，`emit` 按登记顺序调用并回报次数 | 阶段 4 |

`Session` 与 `Node` 各带一个存活计数，验收时靠它判断资源有没有被释放。

## 阶段 1 · `unique_ptr` 与自定义删除器

**要做什么**（都在 `src/resource.cpp`）

- 1-1 `make_session`：用 `std::make_unique<Session>(name)` 返回
- 1-2 `open_file`：`std::fopen` 成功后返回 `FilePtr(f, std::fclose)`；
  失败返回 `FilePtr(nullptr, std::fclose)`

**验收标准**

`Text`

```text
=== Stage 1: unique_ptr and custom deleter ===
make_session    : alpha, alive = 1, created = 1
after move      : from = (null), to = alpha, alive = 1
after reset     : alive = 0
counted payload : 7
deleter calls   : 1
open file       : opened
note            : the FILE is closed by the deleter, not by user code
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `make_session : (null)` | 占位实现还在，或者返回的是默认构造的空指针 |
| `after move : from = not null` | 移动之后源指针仍然非空，说明用的是拷贝而不是移动；`unique_ptr` 不能拷贝，能编译过说明写的是别的东西 |
| `after reset : alive = 1` | `reset()` 之后对象没有析构，检查 `Session` 的析构函数是不是被改动过 |
| `deleter calls : 0` | 自定义删除器的 `operator()` 没被调用；这一行由已给出的代码产生，走到这里说明前面的代码抛了异常 |
| `open file : (not opened)` | 文件真的不存在（不在模板目录下运行），或者阶段 1-2 还没做 |
| 编译报 `use of deleted function` | 对 `unique_ptr` 用了拷贝构造或拷贝赋值，应当 `std::move` |

## 阶段 2 · `shared_ptr` 的引用计数

**要做什么**

- 2-1 `make_shared_session`：用 `std::make_shared<Session>(name)` 返回
- 2-2 `touch`：按值接收一个 `shared_ptr`，返回进入函数时的 `use_count()`

**验收标准**

`Text`

```text
=== Stage 2: shared_ptr and use_count ===
make_shared     : beta, use_count = 1
after copy      : use_count = 2
touch saw count : 3
after touch     : use_count = 2
after peek      : use_count = 2
after scope     : use_count = 1
alive sessions  : 0
```

三个数字的来历：`1` 是调用方自己那一份；`2` 是局部 `copy` 也持有一份；
`3` 是 `touch` 的参数又持有一份（函数返回后回到 `2`）。`peek` 按 `const` 引用接收，
不改变计数。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `use_count = 0` | `make_shared` 的占位实现还在 |
| `touch saw count : 2` | `touch` 的形参写成了 `const std::shared_ptr<Session> &`，引用不增加计数 |
| `touch saw count : 4` | 函数体里又复制了一份，或者返回的是 `s.use_count() + 1` 这类凑出来的值 |
| `after scope : use_count = 2` | 局部 `copy` 的作用域没写对，检查大括号的位置 |
| `alive sessions : 1` | 还有一份 `shared_ptr` 活着。本阶段结束时全部离开作用域，应当回到 0 |

## 阶段 3 · 循环引用与 `weak_ptr`

**要做什么**

- 3-1 `make_node`：用 `std::make_shared<Node>(name)` 返回
- 3-2 `link_strong`：`a->next = b; b->next = a;`（故意造一个环）
- 3-3 `link_weak`：`a->next = b; b->back = a;`（一条强引用、一条弱引用）
- 3-4 `peer_of`：`expired()` 之后 `lock()`，失效时返回空指针

**验收标准**

`Text`

```text
=== Stage 3: weak_ptr breaks the cycle ===
weak link       : a.use_count = 1, b.use_count = 2
peer_of(b->back): c
alive in scope  : 2
alive after scope: 0   (weak link frees both)
strong cycle    : a.use_count = 2, b.use_count = 2
alive in scope  : 2
alive after scope: 2   (the strong cycle leaks these two nodes)
```

`b.use_count = 2` 是因为局部变量 `b` 与 `a->next` 各持一份；
`alive after scope: 2` 就是循环引用留下的泄漏，它不是程序写错了，
而是**共享所有权成环**的必然结果。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `weak link : a.use_count = 2` | `link_weak` 里把 `b->back` 写成了 `b->next`，两条都是强引用，于是和 `link_strong` 一样了 |
| `peer_of(b->back) : (none)` | `peer_of` 的占位实现还在，或者弱引用已经失效 |
| `alive after scope: -2` 一类负数 | 节点的存活计数没有在构造函数里加一，或者加了两处；`Node` 的构造与析构要配平 |
| 第一次演示后 `alive` 不是 0 | 强引用链上还有一份没释放，或者 `peer_of` 返回的 `shared_ptr` 被漏在了作用域外面 |
| `strong cycle` 演示后 `alive` 回到 0 | 两个节点没有真正成环，检查是不是只写了一条强引用 |

> [!WARNING]
> 循环引用不是「写法不对」那么轻：两个对象互相持有强引用时，析构函数永远不会被调用，
> 占用的内存也不会归还。它在小程序里看不出来，在长时间运行的服务里就是持续增长。
> 见《07-标准库/B-03-智能指针的用法.md》第 3 节。

## 阶段 4 · `std::function` 回调注册表

**要做什么**

- 4-1 `Registry::on`：把「事件名 + 回调」存进容器，允许同名多条、按登记顺序
- 4-2 `Registry::emit`：调用该事件名下的每个回调，返回调用次数；没登记过返回 0

**验收标准**

`Text`

```text
=== Stage 4: callback registry ===
handlers        : 4
emit tick(5)    : called = 3
emit tick(7)    : called = 3
emit tock(1)    : called = 1
emit none(1)    : called = 0
captured total  : 12
bound total     : 12
copy  total     : 12   (copy changed its own state)
ref   total     : 112
```

`captured total` 是捕获引用的 lambda 累加的结果（5 + 7），
`bound total` 是 `std::bind` 绑定的成员函数累加的结果（同样是 5 + 7）。
最后两行对照 `std::function` 按值存与用 `std::ref` 存引用的差别。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `handlers : 0` | `on` 的占位实现还在 |
| `emit ... : called = -1` | `emit` 的占位实现还在 |
| `emit tick(5) : called = 1` | 同名多条只保留了一条，`on` 里写成了「按事件名覆盖」 |
| `emit none(1) : called = 0` 但程序崩溃 | 遍历时用了 `handlers_.at(...)` 一类会抛异常的写法，没有登记过的事件应当直接跳过 |
| `captured total : 0` | lambda 按值捕获了，累加的是副本；本模板要的是按引用捕获 |
| 编译报 `no match for call to '(const Accumulator)(int)'` | 遍历时拿到了 `const` 的回调，而可调用物要求非 `const`；用 `const auto &` 或给 `operator()` 加 `const` |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'make_unique' is not a member of 'std'` | 漏了 `#include <memory>`；`make_unique` 是 C++14 起才有的 |
| 编译报 `use of deleted function 'std::unique_ptr<...>::unique_ptr(const ...&)'` | `unique_ptr` 不能拷贝，转移所有权要用 `std::move` |
| 运行时报 `Segmentation fault`，栈里是 `shared_ptr` 的析构 | 同一个裸指针交给了两个 `shared_ptr` 分别管；应当先用 `make_shared` 造好再复制 |
| `use_count` 比预期大 1 | 中间多了一次按值传参或一次 `auto copy = s;`（`auto` 会推导成 `shared_ptr` 而不是引用） |
| 程序结束时 `Session::alive()` 不是 0 | 有对象还挂在某个容器或全局变量里。`g_deleter_calls` 那类全局记账变量不受影响 |
| `Registry::emit` 在回调里又调用 `on` 导致崩溃 | 遍历 `handlers_` 的过程中改了容器，迭代器失效。先把要加的回调收集起来，遍历结束后再登记 |
