# 配置步骤 · 07-standard-library/08-cpp-config-parser（`variant`/`optional`/`tuple` 配置解析器）

本模板是**分阶段的整体演练**：成品是一个配置解析器，
先用 `std::optional` 表达「可能没有值」，再用 `std::variant` 表示配置值的多选一，
然后用 `std::tuple` 与结构化绑定返回一行解析结果，最后用 `<type_traits>` 给取值函数加约束。
每个阶段结束时程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../../README.md`](../../README.md)，本文件不重复。

---

## 成品形态

做完这 4 个阶段之后，`app_cli.exe` 具备下面这些能力：

| 能力 | 由哪一阶段提供 |
|---|---|
| 整数、浮点、布尔的严格解析，失败用 `std::nullopt` 表示 | 阶段 1 |
| 配置表：类型自动判定、按键查找、按键排序、`std::visit` 渲染 | 阶段 2 |
| 按行解析 `key = value`，返回 (键、值、是否合法) 三元组 | 阶段 3 |
| 只接受算术类型的 `get_as<T>`（`enable_if` 约束）与类型名 | 阶段 4 |

## 阶段 1 · `std::optional`：解析失败怎么表达

**要做什么**（都在 `src/config.cpp`）

- 1-1 `parse_int`：整串必须是数字（可带一个符号），否则 `std::nullopt`
- 1-2 `parse_double`：规则同上，允许一个小数点
- 1-3 `parse_bool`：`true/false/1/0/yes/no/on/off`（不区分大小写），其余 `nullopt`

**验收标准**

`Text`

```text
=== Stage 1: optional and parsing ===
parse_int("8080")           : 8080
parse_int("12abc")          : (none)
parse_int(" 42")            : (none)
parse_double("0.75")        : 0.75
parse_bool("true")          : true
parse_bool("ON")            : true
parse_bool("maybe")         : (none)
lookup("name")              : demo
lookup("retries")           : (none)
port value_or(0)            : 8080
```

后两行是 `optional` 的典型用法：`value_or` 在「没有值」时给出默认值。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `parse_int("12abc") : 12` | 直接用了 `std::stoi`，它是前缀解析，多余的字符不会报错。本模板要求整串合法 |
| `parse_int(" 42") : 42` | 没有拒绝两端的空白；解析一个字段与解析一个整数是两件事 |
| `parse_bool("maybe") : false` | 认不出来的写法被当成了 `false`；本模板要求返回 `nullopt` |
| `parse_bool("ON") : (none)` | 没有先转小写 |
| 编译报 `'optional' is not a member of 'std'` | 漏了 `#include <optional>`；C++17 起才有 |
| 程序在 `stoi` 处抛异常退出 | 用 `stoi` 时要捕获 `invalid_argument`，或者干脆自己扫字符 |

## 阶段 2 · `std::variant`：配置值的多选一

**要做什么**

- 2-1 `Config::set`：按 `bool -> int -> double -> 字符串` 的顺序判定类型并存进表
- 2-2 `Config::find`：按键查找，返回 `const Value *`，找不到返回 `nullptr`
- 2-3 `Config::all`：按键升序返回全部条目

**验收标准**

`Text`

```text
=== Stage 2: variant and visit ===
items            : 5
debug            : bool = true
name             : string = demo
paths            : string = src;include
port             : int = 8080
ratio            : double = 0.750000
find("debug")     : bool = true
has("missing")    : no
```

`port` 是 `int` 而不是 `string`，`debug` 是 `bool` 而不是 `int`：
判定顺序决定了 `"1"` 这类写法落到哪个分支。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `items : 0` | 占位实现还在，或者 `set` 里忘了 `push_back` |
| `debug : int = 1` | 判定顺序把 `parse_int` 放在了 `parse_bool` 前面 |
| `ratio : int = 0` | `"0.75"` 被判成了整数；`parse_int` 应当拒绝小数点 |
| `name : string = demo` 但 `items : 4` | 有一个键被覆盖了：`set` 里同名 key 没有正确处理 |
| 顺序与上面不同 | `all()` 没有排序 |
| `find("debug") : (none)` | `find` 返回的是 `nullptr`，或者 `items_` 里存的是别的键 |
| 编译报 `no matching function for call to 'visit'` | lambda 没有覆盖 `variant` 的全部类型；五种（含 `monostate`）都要有 |

## 阶段 3 · `std::tuple` 与结构化绑定

**要做什么**

- 3-1 `parse_lines`：逐行解析，跳过空行与 `#` 注释，
  返回 `vector<tuple<string, Value, bool>>`
- 3-2 `first_item`：第一条合法条目，用结构化绑定取用

**验收标准**

`Text`

```text
=== Stage 3: tuple, structured binding, apply ===
lines parsed     : 5
ok flags         : yes yes yes yes yes
first item       : name / string = demo
apply demo       : timeout / 30 / 1.5
```

`data/app.ini` 里那行 `# demo configuration` 是注释，不计入 5 条。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `lines parsed : 6` | 注释行没有被跳过 |
| `lines parsed : 0` | 占位实现还在，或者 `getline` 的循环条件写错 |
| `ok flags` 里有 `no` | 等号判断或去空白有问题；`app.ini` 的 5 行都应当合法 |
| `first item : / none` | `first_item` 没有跳过 `ok == false` 的条目 |
| 编译报 `'[key, value, ok]' : cannot decompose` | 结构化绑定要求 `#include <tuple>`，且元素个数要对上 |
| `apply demo` 那一行没打印 | `std::apply` 的实参写成了 `sample` 之外的东西；它需要 `#include <tuple>` |

## 阶段 4 · `<type_traits>` 约束

**要做什么**

- 4-1 `get_as<T>`（在 `include/config.hpp` 里）：用
  `std::enable_if_t<std::is_arithmetic_v<T>>` 把 `T` 限制在算术类型上；
  类型相符时返回转换后的值，否则返回 `fallback`
- 4-2 `type_name_of`：用 `visit` 返回类型名

**验收标准**

`Text`

```text
=== Stage 4: type_traits constraints ===
is_arithmetic<int>          : 1
is_arithmetic<std::string>  : 0
get_as<int> available       : yes
get_as<std::string>         : no
get_as<int>("port", -1)     : 8080
get_as<double>("ratio", 0)  : 0.75
get_as<int>("name", -1)     : -1
type_name_of(port)          : int
```

`get_as<std::string>` 那一行的 `no` 是编译期算出来的：`main_cli.cpp` 里那个
`has_numeric_get` 检测模板根本没能实例化出 `get_as<std::string>`，
说明约束确实把它挡住了。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 编译报 `static assertion failed: get_as<std::string> 应当被约束挡住` | 模板参数上的 `enable_if` 没写，或者写成了别的位置 |
| 编译报 `no type named 'type' in 'std::enable_if<false, void>'` | 约束生效了，但主模板的默认实参写法不对：应当写成 `class = std::enable_if_t<...>` |
| `get_as<int>("port", -1) : -1` | 占位实现还在，或者 `find` 返回了 `nullptr` |
| `get_as<int>("name", -1) : 0` | 没有判断类型是否相符，把字符串当成了数字（默认值应当是传入的 `-1`） |
| `get_as<double>("ratio", 0) : 0` | 只处理了 `long long` 分支，`double` 分支漏了 |
| 编译报 `redefinition of 'get_as'` | 实现写在了 `config.cpp` 里；模板必须留在头文件 |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'variant' is not a member of 'std'` | 漏了 `#include <variant>`；C++17 起才有 |
| 编译报 `'monostate' is not a member of 'std'` | `std::monostate` 也在 `<variant>` 里 |
| `std::get<T>(v)` 抛 `bad_variant_access` | `get` 要求类型完全相符；先 `holds_alternative` 或者改用 `get_if` |
| 遍历 `parse_lines` 的返回值时报错 | 结构化绑定要写成 `const auto &[key, value, ok]`，`auto` 会复制 |
| `parse_double("0.75")` 得到 `0.750000` | `std::to_string(double)` 固定六位小数；要改格式就用 `ostringstream` + `setprecision` |
| MSVC 下 `enable_if` 报一大堆模板错误 | 约束失败时的报错本来就长；先看最后一行「没有匹配的函数调用」 |
