# 配置步骤 · 07-standard-library/02-cpp-io-format（C++ 输入输出与格式化）

本模板是**分阶段的整体演练**：成品是一个用 C++ 标准库写成的报表生成器，
读同一份文本，用 `iostream`、`iomanip`、`sstream`、`fstream` 出同一份报表。
每个阶段结束时程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../../README.md`](../../README.md)，本文件不重复。

---

## 阶段 1 · `<fstream>` 读取与流的状态

**要做什么**（都在 `src/report.cpp`）

- 1-1 `read_all`：用 `std::ifstream`（二进制方式）打开，先看 `if (!in)`，
  再一次读全长（`rdbuf()` 或 `seekg`/`tellg` 两条写法都行），
  读完再检查一次流；失败时把路径与 `std::strerror(errno)` 拼进 `err`
- 1-2 `count_lines`：数 `'\n'`；最后一个字节不是 `'\n'` 且文本非空时再加一

**验收标准**

`Text`

```text
=== Stage 1: read file ===
path    : data/sample.txt
bytes   : 913
lines   : 16
```

换成 `data\missing.txt` 运行时应当是同一句失败信息：

`Text`

```text
open failed : data\missing.txt: No such file or directory
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `bytes : 0` | 打开模式写成了文本模式并且用了 `seekg`/`tellg` 的组合，或者读完忘了 `text` 赋值 |
| `bytes : 913` 但 `lines : 15` | `count_lines` 漏了「最后一个字节不是换行也要算一行」 |
| `open failed` 后面没有原因 | `err` 没拼 `std::strerror(errno)`；`errno` 要在打开失败之后立刻取，中间别插入别的库调用 |
| 报错 `no member named 'strerror' in namespace 'std'` | 漏了 `#include <cstring>` |
| 文件确实存在却报打不开 | 不在模板目录下运行，相对路径落到了别处 |

## 阶段 2 · `<sstream>` 分词、计数与排序

**要做什么**

- 2-1 `collect_words`：把整份文本按「连续字母算一个词」切开（`std::isalpha`），
  统一转小写、截断到 63 个字符，在 `entries` 里查一遍并计数，`words` 记总词数
- 2-2 `sort_entries`：`std::sort` + lambda，次数降序、次数相同按字典序升序

**验收标准**

`Text`

```text
=== Stage 2: tokenize and sort ===
words   : 169
unique  : 100
top 5   :
   1  the              16
   2  and               9
   3  a                 8
   4  is                6
   5  word              5
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `words : -1` | 占位实现还在 |
| `unique : 0` | `entries` 一直是空的：查表用了 `=` 比较而不是 `==`，或者忘了 `push_back` |
| `words` 每次调用都变大 | 函数开头没有把 `words` 置 0；它记录的是「本次统计的总词数」，不是累计值 |
| 前几名次序不对 | 次数相同时缺少字典序兜底；`std::sort` 不保证稳定，比较函数必须给出完整的次序 |
| `std::sort` 之后程序崩溃 | 比较函数不满足严格弱序（例如用了 `<=`），排序内部会越界 |
| 编译报 `'isalpha' is not a member of 'std'` | 漏了 `#include <cctype>` |

## 阶段 3 · `<iomanip>` 格式化

**要做什么**

- 3-1 `format_report`：用 `std::ostringstream` 拼报表，名次右对齐宽度 2、
  词左对齐宽度 14、次数右对齐宽度 4，柱状条是 `#` 重复 `min(count, 40)` 次

**验收标准**

`Text`

```text
=== Stage 3: format with iomanip ===
file    : data/sample.txt
bytes   : 913
lines   : 16
words   : 169
unique  : 100
top 10  :
   1  the              16  ################
   2  and               9  #########
   3  a                 8  ########
   4  is                6  ######
   5  word              5  #####
   6  c                 4  ####
   7  be                3  ###
   8  data              3  ###
   9  its               3  ###
  10  library           3  ###
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 整个报表挤成一行 | 拼的是 `'\n'` 还是 `std::endl` 都行，但漏了换行符就会挤成一行 |
| 第 3 名之后全部左对齐 | `std::left` 会一直生效，切回右对齐要显式写 `std::right` |
| 词列宽度不一致，长词把次数列顶开 | 少写了 `std::setw(14)`；`setw` 只对**下一个**输出项生效，每个词都要写一次 |
| 柱状条少一个 `#` 或多一个 | 柱状条长度是 `count` 与 40 的较小值，不是 `count` |
| 报表末尾多一个空行 | 循环里多打了一次换行，或者最后一条之后又拼了一段 |

## 阶段 4 · 写报表文件，并与 `printf` 对照

**要做什么**

- 4-1 `write_file`：`std::ofstream`（二进制方式）写出，打开失败与写入失败都要写 `err`
- 4-2 观察 `main_cli.cpp` 里那段用 `std::snprintf` 拼同一份报表的代码，
  它打印的 `identical` 就是两份报表（流 vs `printf`）逐字节比较的结果

**验收标准**

`Text`

```text
=== Stage 4: write file and compare with printf ===
out file : build/report.txt
written  : 431 bytes
identical: yes
```

`build/report.txt` 出现，内容与阶段 3 打印的报表相同。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `write failed : ...` | 阶段 4-1 的占位实现还在，或者路径不可写 |
| `written  : 0 bytes` | 流打开了但没写：`out << text` 或 `out.write(...)` 漏了 |
| `identical: no` | 格式对不上。把 `report.txt` 与阶段 3 的输出逐行对照；最常见的是宽度或对齐差一位 |
| `report.txt` 里是空白 | 用了 `std::ios::trunc` 之外的模式，或者两次运行之间文件被别的程序占用 |

## 与 01-c-stdlib-toolbox 的对照

两个模板读同一份 `data/sample.txt`（内容逐字节相同），跑出同一份报表。

`实测数据`
`Text`

```text
报表正文：C 版（01 的 ts_write_report）431 字节
          C++ 版（02 的 format_report）431 字节
          两份逐字节相同（PowerShell 的 -ceq 比较结果为 True）

同一件事的核心实现（含注释）：
          C 版 src/textstats.c        282 行
          C++ 版 src/report.cpp       152 行
```

两边的差别集中在三处：读文件（`fopen` 与 `ifstream`）、分词（手写循环与
`istringstream` + 容器）、格式化（`snprintf` 与 `iomanip`）。
字符集与编码的处理方式相同，都只按字节处理，因此计数结果一致。

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| MSVC 下 `std::strerror` 报 `C4996` | MSVC 的弃用检查。工程的 `CMakeLists.txt` 里已经为 `core` 加了 `_CRT_SECURE_NO_WARNINGS` |
| 编译报 `'ifstream' is not a member of 'std'` | 漏了 `#include <fstream>`；`<iostream>` 不带它 |
| 输出里出现 `nan` 或乱码 | 报表字符串没写结尾，或者把 `std::string` 当 C 字符串交给了 `printf`；对照时用 `%s` 要配 `c_str()` |
| `cmake --preset msvc` 找不到生成器 | 若未安装 Visual Studio 生成工具。用 MinGW 路线即可，两条路线只是验收口径不同 |
| `report.txt` 每次运行都在变长 | 打开模式写成了 `std::ios::app`（追加），应当是默认的覆盖写 |
