# 配置步骤 · 07-standard-library/07-cpp-filesystem（`<filesystem>` 目录工具）

本模板是**分阶段的整体演练**：成品是一个目录扫描工具，
先把 `path` 的拆分与拼装理清，再遍历目录树统计文件与字节，
然后对照 `error_code` 与异常两条错误路线，最后走一遍创建、复制、改名、删除。
带 Win32 与 Qt 两份界面，Qt 默认不构建。
每个阶段结束时程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · `path` 的拆分与拼装

**要做什么**（都在 `src/dirscan.cpp`）

- 1-1 `split_path`：`filename()`、`stem()`、`extension()`、`parent_path()`，
  路径统一用 `generic_string()` 输出
- 1-2 `swap_extension`：`replace_extension(new_ext)`，新扩展名要带点

**验收标准**

`Text`

```text
=== Stage 1: path parts ===
input            : data/tree/sub/report.txt
filename         : report.txt
stem             : report
extension        : .txt
parent           : data/tree/sub
generic          : data/tree/sub/report.txt
replace ext      : data/tree/sub/report.md
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 六行全是空的 | 占位实现还在，或者 `input` 为空时提前返回了却没有填 `input` |
| `parent : data\tree\sub` | 用了 `string()` 而不是 `generic_string()`；Windows 上分隔符是反斜杠 |
| `extension : txt` | `extension()` 返回的是带点的 `.txt`；不要自己再去点 |
| `stem : report.txt` | `stem()` 只去掉扩展名；写成 `filename()` 就会连扩展名一起留下 |
| `replace ext : data/tree/sub/report.txt.md` | 用了字符串拼接而不是 `replace_extension`，它会把旧扩展名整段换掉 |
| `replace ext : data/tree/sub/report.md.txt` | 新扩展名写成了 `"md"`（不带点），`replace_extension` 会补一个点再接上去，得到 `.md.txt` 一类结果；按标准写法传 `".md"` |

## 阶段 2 · 遍历与统计

**要做什么**

- 2-1 `scan`：目录不存在时返回全 0；否则用 `directory_iterator` 或
  `recursive_directory_iterator` 遍历，区分文件与目录，累计字节数，
  按扩展名（小写）分类并排序

**验收标准**

`Text`

```text
=== Stage 2: iterate a directory tree ===
root             : data/tree
non-recursive:
  files          : 1
  dirs           : 1
  bytes          : 6
  by extension   :
    .txt : 1
recursive:
  files          : 3
  dirs           : 1
  bytes          : 20
  by extension   :
    .md : 1
    .txt : 2
```

`实测数据`
`Text`

```text
data/tree 里三个文件的字节数：a.txt 6、sub/b.txt 6、sub/c.md 8，合计 20
非递归只看到 a.txt 与 sub 这一层，因此是 1 个文件、1 个目录、6 字节
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 递归与非递归结果一样 | 两处都用了同一个迭代器；`recursive` 参数没有传到构造函数里 |
| `dirs : 0` | 只判断了 `is_regular_file`，目录没数；或者用了 `++it` 而不是范围 for |
| `bytes` 比 20 小 | `file_size` 对目录会失败，要先用 `is_regular_file` 过滤 |
| 扩展名分类里有 `(none) : 3` | `extension()` 的结果没有判断空串 |
| 扩展名分类里有大写（`.TXT`） | 没有转小写 |
| 顺序每次运行都不同 | 没有排序；`directory_iterator` 的顺序由文件系统决定 |

## 阶段 3 · 两条错误处理路线

**要做什么**

- 3-1 `scan_ec`：带 `error_code` 的调用，出错时把错误码交给调用方，自己返回全 0
- 3-2 `scan_throw`：不带 `error_code` 的调用，让 `filesystem_error` 抛给调用方

**验收标准**

`Text`

```text
=== Stage 3: two error paths ===
missing path     : data/no_such_dir
error_code scan  : files = 0, ec = 2 (category generic)
ec nonzero       : yes
exception catch  : threw = yes, code = 2
what() length    : 104 bytes (localized text, not printed)
```

`实测数据`
`Text`

```text
同一个不存在的目录 data/no_such_dir：
  error_code 路线：ec = 2（通用错误「没有这个文件或目录」），函数返回全 0，程序继续跑
  异常路线：抛出 filesystem_error，code = 2，what() 的文本是本地化的一句话（104 字节）
```

`what()` 与 `error_code::message()` 的文本随系统语言变化，因此程序里只打印
数字代码，不打印那句话。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `ec nonzero : no` | `scan_ec` 里用了会抛异常的调用，异常在半路逃走了；或者函数开头 `ec.clear()` 之后没有再置位 |
| 程序在阶段 3 直接退出 | `scan_throw` 抛出的异常没有被 `catch` 捕获；检查 `catch` 的类型是不是 `std::filesystem::filesystem_error` |
| `threw : yes` 但 `code = 0` | 捕获之后没有取 `e.code().value()` |
| 输出里出现乱码 | 打印了 `what()` 或 `message()`。他们的文本是本地化的（本机是中文），脚本与终端编码不一致时会乱码；只打印数字代码 |
| 改成 `catch (const std::exception &)` 之后仍能捕获 | 预期行为：`filesystem_error` 派生自 `std::exception`；但那样就取不到 `code()` 了 |

> [!IMPORTANT]
> 两条路线各有代价：`error_code` 版本不会中断控制流，代价是每一处都要检查；
> 异常版本写起来短，代价是调用方必须知道哪些调用会抛。标准库给同一批操作
> 各留了一个重载，正是为了让调用方自己选。见《07-标准库/B-07-文件系统：filesystem.md》第 5 节。

## 阶段 4 · 创建、复制、改名、删除

**要做什么**

- 4-1 `build_tree`：在 `build/fs_demo` 下建目录、写文件、复制、改名、
  统计文件数与字节数，最后 `remove_all` 清理并把返回值记下来

**验收标准**

`Text`

```text
=== Stage 4: create, copy, rename, remove ===
demo root        : build/fs_demo
created dirs     : 1
copied           : 1
renamed          : 1
files now        : 2
bytes            : 32
remove_all count : 4
left on disk     : no
```

`remove_all` 返回 4：两个文件（`a.txt` 与 `sub/renamed.txt`）加两层目录
（`sub` 与 `fs_demo` 自己）。`left on disk : no` 说明清理干净了。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `copied : 0` 且程序抛异常退出 | `copy_file` 的目标已存在时会失败；用 `fs::copy_options::overwrite_existing` |
| `bytes : 16` | 只数了一个文件；`files now` 应当是 2 |
| `remove_all count : 2` | 只删了文件没删目录，或者 `remove_all` 的返回值没有接收 |
| `left on disk : yes` | 清理那一步没执行，或者路径写错了 |
| 第二次运行时 `created dirs : 0` | `create_directories` 在目录已存在时返回 false。函数开头先 `remove_all` 就有稳定的结果 |
| 运行后 `build/fs_demo` 还在，但里面是空的 | `remove` 与 `remove_all` 的区别：`remove` 不递归 |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'filesystem' is not a member of 'std'` | 漏了 `#include <filesystem>`；GCC 8 及更早还要显式链接 `stdc++fs` |
| `files : 0` 且 `ec` 为 0 | 目录真的不存在时 `is_directory` 返回 false 但不置位 `ec`，本模板在 `scan_ec` 里手动补了一个「没有这个文件或目录」 |
| 输出里出现中文乱码 | 打印了 `what()` 或 `message()`。它们是本地化文本，程序输出统一改成数字代码 |
| 路径里出现乱码 | 非 ASCII 路径要留意编码：Windows 上 `path` 由窄字符串构造时按本地编码解释，见《07-标准库/B-07-文件系统：filesystem.md》第 2 节 |
| `remove_all` 之后文件还在 | 文件被别的程序（编辑器、杀毒软件）占着；关掉占用者再试 |
| `build/fs_demo` 出现在 `git status` 里 | 它落在 `build/` 下，已被 `.gitignore` 覆盖；若自己改了路径，注意不要提交运行期产物 |
