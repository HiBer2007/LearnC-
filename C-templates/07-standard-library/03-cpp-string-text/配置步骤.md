# 配置步骤 · 07-standard-library/03-cpp-string-text（`std::string` 与 `string_view`）

本模板是**分阶段的整体演练**：成品是一个文本处理小工具，
从容量与短串优化看起，再做切分、查找、替换，然后用 `string_view` 做一遍零拷贝的切分，
最后处理数字互转与 UTF-8 字节计数。每个阶段结束时程序都能编译、能运行。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · `std::string` 的构造与容量

**要做什么**（都在 `src/texttool.cpp`）

- 1-1 `probe`：填 `size`、`capacity`，并把 `s.data()` 的地址与对象自身的地址区间
  比一比，判断缓冲区是否就在对象内部

**验收标准**

`Text`

```text
=== Stage 1: string capacity and SSO ===
short         : size =   5   capacity =  15   inside_object = yes
long          : size =  40   capacity =  40   inside_object = no
reserved(64)  : size =  40   capacity =  80   inside_object = no
```

`实测数据`
`Text`

```text
本机 g++ 15.2.0 的 libstdc++：
  "hello"（5 字节）            capacity = 15，缓冲区在对象内部
  std::string(40, 'x')         capacity = 40，缓冲区在堆上
  对 40 字节的串 reserve(64)    capacity = 80（不是 64）
```

容量与增长策略是**实现定义**的，换一套标准库数值可能不同；
验收真正要比的是 `inside_object` 这一列：短的 `yes`、长的 `no`。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `size = 0` 且 `capacity = 0` | 占位实现还在 |
| 三行 `inside_object = no` | 判断区间写成了 `[self, self + s.size())`，短串的缓冲区在对象内部，但长度只有 5，要按 `sizeof(s)` 算区间 |
| 三行 `inside_object = yes` | 区间上界用了 `<=`，或者拿 `s.c_str()` 与 `&s` 之外的地址比较 |
| `reserved(64)` 的 capacity 是 64 而不是 80 | 换了一套标准库。这个数字是实现定义，只要比 40 大就说明 reserve 起作用了 |
| 编译报 `reinterpret_cast` 相关的错 | 把 `const std::string *` 转成 `const char *` 要用 `reinterpret_cast<const char *>(&s)` |

## 阶段 2 · 查找、替换、切分、修剪

**要做什么**

- 2-1 `trim`：`find_first_not_of` 与 `find_last_not_of` 定位，`substr` 取中间
- 2-2 `to_lower`：形参按值传入，原地改；`std::tolower` 的实参先转 `unsigned char`
- 2-3 `split`：`find` + `substr` 循环，最后一段别漏
- 2-4 `count_occurrences`：找到之后 `pos` 要跳过整个 `needle`
- 2-5 `replace_all`：`find` + `replace` 循环，`pos` 要跳过 `to.size()`

**验收标准**

`Text`

```text
=== Stage 2: find, replace, split, trim ===
count "a"      : 6
split count    : 5
tokens         : [alpha] [beta] [gamma] [delta] [epsilon]
trim           : [padded]
lower          : [mixed case]
replace_all    : [AlphA,betA,gAmmA,deltA,epsilon]
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `split count : 6`，最后一段是空的 | 循环在最后一次 `find` 返回 `npos` 时又 push 了一个空串；本模板的输入没有空段 |
| `tokens` 少一段 | 循环条件写成了「找不到就退出」，忘了把最后一段补上 |
| `count "a" : 11` | `pos` 只加了 1，同一个位置上重复计数；应当加 `needle.size()` |
| `replace_all` 输出比预期长很多 | `pos` 没有跳过 `to.size()`；`to` 里含有 `from` 时会一直替换下去 |
| `trim` 结果是 `[  padded  ]` | 只找到位置没有 `substr`，或者边界算成了 `last - first` |
| `lower` 结果是 `[Mixed Case]` | `tolower` 的返回值没有写回；它不会修改实参 |

## 阶段 3 · `string_view` 的零拷贝切分

**要做什么**

- 3-1 `split_view`：与 `split` 同样的切分，但返回 `std::vector<std::string_view>`，
  视图直接指向传进来的那段字符
- 3-2 `trim_view`：视图版的修剪

**验收标准**

`Text`

```text
=== Stage 3: string_view, zero copy ===
split_view count : 5
same as split    : yes
chars copied by split      : 26
chars copied by split_view : 0
trim_view        : [padded]
```

`chars copied by split : 26` 是五个段的字符总数，也就是阶段 2 的 `split`
为切分而复制的字符数；视图版是 0，它只在原串上记位置。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `same as split : no` | 视图的切分边界与阶段 2 不一致，两边的循环写法比一比 |
| `split_view count : 0` | 占位实现还在 |
| 打印结果里有奇怪的字符，或者程序崩溃 | 视图指向的原串已经销毁。本模板里 `text` 是 `main` 的局部变量，活到阶段 3 结束，是安全的；自己写演示时不要把视图指向临时对象 |
| `trim_view` 返回空 | 全部是空白时返回空视图是对的，本模板的输入不是 |

> [!CAUTION]
> `string_view` 不拥有字符。指向临时 `std::string` 的视图、原串被修改或释放之后
> 继续使用的视图，都是悬垂引用，行为未定义。见
> 《07-标准库/B-02-std-string 与 string_view.md》第 6 节。

## 阶段 4 · 数字互转与 UTF-8 计数

**要做什么**

- 4-1 `probe_numbers`：`stoi("42")`、`stod("3.5")`、`to_string(42)`，
  再加 `stoi("7x")` 与 `stoi("hello")` 两种边界
- 4-2 `count_utf8`：数字节数与非续接字节的个数

**验收标准**

`Text`

```text
=== Stage 4: numbers and UTF-8 ===
stoi("42")      : 42
stod("3.5")     : 3.5
to_string(42)   : [42]
stoi("7x")      : 7   (prefix parse, no exception)
stoi("hello")   : caught invalid_argument
utf8 bytes      : 9
utf8 codepoints : 5
```

`stoi("7x")` 返回 7 而不是报错，`stoi("hello")` 抛 `std::invalid_argument`，
这两行的差别是这一段要看清的地方。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `stoi("7x")` 那一行程序直接退出 | 没有 `try`/`catch`，异常逃到了 `main` 外面。`stoi` 只在开头就不是数字时才抛异常 |
| `stoi("hello") : (no exception)` | `catch` 的类型写成了 `std::exception` 之外的派生类，或者 `bad_caught` 没有置位 |
| `utf8 codepoints : 9` | 直接数了字节。续接字节的高两位是 `10`，要排除掉 |
| `utf8 codepoints : 3` | 只数了 ASCII 那三个字母：判断写成了 `c < 0x80`，汉字的首字节也被漏掉 |
| `stod` 的输出位数不是 `3.5` | `std::cout` 的默认精度是 6 位有效数字，`3.5` 正好；换成别的值要显式设 `std::setprecision` |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'string_view' is not a member of 'std'` | 漏了 `#include <string_view>`；C++17 起才有 |
| 编译报 `no matching function for call to 'tolower(char)'` | `std::tolower` 的实参类型是 `int`，且负值行为未定义；先转 `unsigned char` |
| 运行时报 `basic_string::substr: pos > size` | `substr` 的起点超过了长度，常见于 `split` 的最后一段用 `pos` 而不是 `s.size()` 兜底 |
| 编译报 `unused variable 'same'` 一类 | 阶段 3 的判据变量被注释掉了，检查 `main_cli.cpp` 没被改动 |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `core` 与 `app_cli` 加了 `/utf-8` |
| `cmake --preset msvc` 找不到生成器 | 本机没装 Visual Studio 生成工具，用 MinGW 路线即可 |
