# 配置步骤 · 07-lower-level/02-mmio-lab（内存映射 I/O 实验）

本模板是**分阶段的整体演练**：一半在主机上跑，用一块模拟的寄存器区把
「位操作」「一次写完成」「字段读改写」三件事的读写次数数出来；
另一半在 Cortex-M 上跑，用 SysTick 中断与 semihosting 输出把
「少了 `volatile` 会怎样」演一遍。两半合起来回答同一个问题：
**同一句赋值，为什么在单片机上必须写成另一个样子。**
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

---

## 成品形态

做完这 4 个阶段之后：

| 能力 | 由哪一阶段提供 |
|---|---|

## 阶段 1 · 位操作与读-改-写

**要做什么**（都在 `src/gpio_lab.c`）

- 1-1 `gl_set_pin`：`sim_read(REG_ODR)` 读出旧值，或上这一位，`sim_write(REG_ODR, ...)` 写回
- 1-2 `gl_clear_pin`：读出旧值，用 `& ~pin` 清位，写回
- 1-3 `gl_toggle_pin`：读出旧值，用 `^ pin` 翻转，写回
- 1-4 `gl_read_pin`：读 `REG_IDR`，返回第 `pin` 位（0 或 1）

**验收标准**

`Text`

```text
=== Stage 1: read-modify-write (ODR) ===
  reset()                ODR = 0x0000
  set(PIN_OUT_1)         ODR = 0x0002   reads = 1  writes = 1
  set(PIN_OUT_2)         ODR = 0x0006   reads = 1  writes = 1
  toggle(PIN_OUT_1)      ODR = 0x0004   reads = 1  writes = 1
  clear(PIN_OUT_2)       ODR = 0x0000   reads = 1  writes = 1
  read(PIN_READY)        -> 0            IDR reads = 1
  read(PIN_READY)        -> 0            IDR reads = 1
  read(PIN_READY)        -> 1            IDR reads = 1
```

前四条 `reads = 1  writes = 1` 是这一段的关键：**每一次置位都先读了一遍 `ODR`**。
前三次读 `IDR` 的结果依次是 0、0、1，那正是模拟设备「第三步才就绪」的时序。

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `ODR` 一直是 0、计数一直是 0 | 占位实现还在，函数体是空的 | `src/gpio_lab.c` 的 1-1 至 1-4 |
| `set` 之后 `ODR` 是 0x0002 但 `reads = 0` | 没有先读旧值，直接 `sim_write(REG_ODR, pin)`：这样会把别的位一起清掉 | 1-1，必须读-改-写 |
| `toggle` 之后 ODR 变成 0x0002 | 写成了置位而不是异或 | 1-3 |
| `set(PIN_OUT_2)` 之后 ODR 是 0x0002 而不是 0x0006 | 覆盖了上一次的结果：没有读旧值 | 1-1 |
| 三次读 `IDR` 都是 0 | `gl_read_pin` 用了 `REG_ODR` 而不是 `REG_IDR` | 1-4 |
| `reads` 是 2 而不是 1 | 读了两次（例如先判空再读），多出来的一次也是真实开销 | 1-1，一次操作只读一次 |

> [!IMPORTANT]
> **读-改-写是位操作的原罪。** 读和写之间如果来了中断，
> 中断里对同一个寄存器的改动会被这一句覆盖掉。
> 本机上 `reads`/`writes` 那一栏就是在提醒这件事：能只写不读的地方，就不要读。

## 阶段 2 · 一次写完成：`BSRR` 与 `BRR`

**要做什么**

- 2-1 `gl_set_pin_fast`：只写一次 `REG_BSRR`（低 16 位是置位），**不许读 `ODR`**
- 2-2 `gl_clear_pin_fast`：只写一次 `REG_BRR`，同样不许读

**验收标准**

`Text`

```text
=== Stage 2: single write (BSRR / BRR) ===
  set_fast(PIN_OUT_1)    ODR = 0x0002   BSRR: reads = 0  writes = 1
  set_fast(PIN_OUT_2)    ODR = 0x0006   BSRR: reads = 0  writes = 2
  clear_fast(PIN_OUT_1)  ODR = 0x0004   BRR : reads = 0  writes = 1
  clear_fast(PIN_OUT_2)  ODR = 0x0000   BRR : reads = 0  writes = 2
  ODR 的累计计数：reads = 0  writes = 0（一次写完成不碰 ODR）
```

同一个效果，`ODR` 的读次数从 1 变成 0。数字是累计值：
`BSRR` 被写了两次，`BRR` 被写了两次，`ODR` 一次没碰。

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `ODR` 有变化，但 `ODR reads = 1` | 还是读-改-写：写的是 `ODR` 而不是 `BSRR`/`BRR` | 2-1、2-2 |
| `ODR` 有变化，但 `BSRR writes = 0` | 把动作写到了别的寄存器 | 2-1，置位写 `REG_BSRR` |
| `set_fast(PIN_OUT_2)` 之后 `PIN_OUT_1` 掉了 | `BSRR` 的高 16 位是复位：传进去的掩码写到了高 16 位 | 掩码要与 `0xFFFF` 相与，或者直接传低位掩码 |
| `clear_fast` 之后 ODR 反而多了一位 | 用 `BSRR` 传了 `pin << 16` 但又或上了低位的写法 | 清位用 `REG_BRR`，语义最清楚 |
| 设备那边的 ODR 变了，但 `sim_peek` 读出来没变 | `sim_peek` 是调试器视角；`BSRR`/`BRR` 是只写寄存器，回读本来就不可靠 | 看 `sim_device_odr()` 那一栏 |

> [!WARNING]
> **`BSRR` 的语义是「写 1 生效，写 0 不动」**，因此它不需要先读。
> 中断落在这一句前后都不会丢掉自己的那一位改动。
> 这就是《07-更底层/03-寄存器、位与 volatile.md》第 3.3 小节讲的硬件原子位操作。

**去掉之后是 `ldr`、`cbnz`，然后 `b.n` 跳到自己**。那一条 `b.n` 就是死循环。

> **`volatile` 只保证「每次访问都真的去读」，不保证原子。**
> 主循环里 `g_ready = 1` 与中断里 `g_ready = 1` 撞在一起是安全的（单写），
> 换成 `++` 就不安全了：那是一条读-改-写。丢更新的现场与三种修法见
> [`../05-critical-section/配置步骤.md`](../05-critical-section/配置步骤.md)。

## 阶段 4 · 字段的读-改-写

**要做什么**

- 4-1 `gl_write_field(offset, mask, shift, value)`：读出 `offset` 这个寄存器，
  把 `mask` 圈出来的位换成 `value`，再写回
- 4-2 `gl_read_field(offset, mask, shift)`：返回 `(寄存器 & mask) >> shift`

**验收标准**

`Text`

```text
=== Stage 4: field read-modify-write (CRL) ===
  write_field(CRL, 0xF0, 4, 0x3)           CRL = 0x00000030   reads = 1  writes = 1
  read_field(CRL, 0xF0, 4)                 -> 0x00000003
  write_field(CRL, 0xF0, 4, 0xA)           CRL = 0x000000a0   reads = 1  writes = 1
```

写进去的是 `0x3`，落在 bit7..4 上，所以寄存器里是 `0x30`；再写 `0xA`，得到 `0xA0`。

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `CRL` 一直是 `0x00000000` | 占位实现还在 | `src/gpio_lab.c` 的 4-1 |
| `CRL = 0x00000003` | 忘了左移 `shift` | 4-1，写成 `(value << shift) & mask` |
| 第二次写之后 `CRL = 0x0000000A` | 没有保留其他位：少了 `old & ~mask` | 4-1 |
| `read_field` 返回 `0xFFFFFFFF` | 占位值还在 | 4-2 |
| `read_field` 返回 `0x30` 而不是 `0x3` | 忘了右移 `shift` | 4-2 |
| `reads` 是 2、`writes` 是 1 | 多读了一次（例如先 `sim_peek` 再 `sim_read`） | 4-1，一次操作只读一次 |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| `qemu-system-arm: unsupported machine type` | 机型名写错。本模板用的是 `netduinoplus2`（Cortex-M4 近似板，flash 与 RAM 基址与 STM32F103 一致） |
| `qemu: Unsupported SemiHosting SWI 0xdeadbeef` | semihosting 调用的写法问题：`register` 变量绑 `r0`/`r1` 在 `-O2` 下第二次调用会失效，改用 `movs r0, #4` 显式装参数 |
| QEMU 什么都不打印，直接超时 | 向量表没被链接脚本保留（见 [`../03-linker-script-lab/配置步骤.md`](../03-linker-script-lab/配置步骤.md)），或者链接脚本的内存容量与板子不符 |
| `arm-none-eabi-gcc: command not found` | 交叉工具链没装或不在 `PATH` 里；装法见《01-编译器/03-嵌入式与交叉编译.md》章节 |
| MSVC 下 `sim_read` 报 `C4996` 一类弃用警告 | 本工程用的是 ISO C 的写法，与弃用检查无关；模板里没有用到被弃用的函数，若出现请检查是否自己加了 `strcpy` 一类调用 |
| 主机侧 `ODR` 的读数总是 0 | 用的是 `sim_peek` 看结果（不算访问）而不是 `sim_read`；两者用途不同，不要混用 |
