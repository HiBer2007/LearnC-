# 配置步骤 · 06-standard-library/09-stdlib-capstone（毕业练习：日志分析流水线）

本模板是**毕业练习**：把前八个模板练过的东西串成一条完整的流水线——
发现文件、读取、解析成记录、统计与抽样、计时、出报表，外加一套 31 项自测。
每个阶段结束时程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../../README.md`](../../README.md)，本文件不重复。

## 成品形态

做完这 5 个阶段之后，`app_cli.exe` 具备下面这些能力：

| 能力 | 由哪一阶段提供 |
|---|---|
| 用 `<filesystem>` 确认文件存在、用 `<fstream>` 一次读全长并数行 | 阶段 1 |
| 逐行解析成记录，不合法行只计数不中断 | 阶段 2 |

命令行两种用法：

## 阶段 1 · 读取与数行

**要做什么**（都在 `src/pipeline.cpp`）

- 1-1 `read_text_file`：先用 `std::filesystem` 的 `error_code` 版本确认文件存在，
  再用 `std::ifstream` 一次读全长；失败时返回空串并把原因写进 `err`
- 1-2 `count_lines`：数 `'\n'`，最后一个字节不是换行且文本非空时再加一

**验收标准**

`Text`

```text
=== Stage 1: read and count ===
file             : data/app.log
bytes            : 1335
lines            : 24
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `read failed : no such file: ...` | 不在模板目录下运行，或者阶段 1-1 还没做 |
| `bytes : 0` 但文件明明存在 | 读了但没返回：`ss << in.rdbuf()` 之后忘了 `return ss.str()` |
| `lines : 23` | `count_lines` 漏了「最后一个字节不是换行也要算一行」 |
| 路径不存在时抛异常退出 | 用了不带 `error_code` 的 `fs::exists`；本函数约定只通过 `err` 报告失败 |

## 阶段 2 · 解析

**要做什么**

- 2-1 `parse_line`：按空白切 6 段，校验级别（`INFO`/`WARN`/`ERROR`）、
  `worker=`、`task=`、`ms=`、`ok=`（只认 0 与 1），任何一处不合法返回 `std::nullopt`
- 2-2 `parse_log`：逐行解析，空行跳过，不合法行计数并留下前 3 条原文

**验收标准**

`Text`

```text
=== Stage 2: parse ===
total lines      : 24
records          : 20
bad lines        : 4
bad sample 1     : 2026-10-01T08:20:00 INFO  worker=3 task=parse ms=abc ok=1
bad sample 2     : 2026-10-01T08:21:00 DEBUG worker=4 task=flush ms=10 ok=1
bad sample 3     : 2026-10-01T08:22:00 INFO  worker=5 ms=10 ok=1
```

四条不合法行分别是：`ms` 不是数字、级别是 `DEBUG`、缺 `task=`、
以及完全不像日志的一行（它是第 4 条，因为只留前 3 条原文，所以没有打印）。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `records : 24` | 没有校验：只要字段数够就当成合法 |
| `bad lines : 1` | 只认出了最后那一行；前三处的校验漏了（`ms=abc`、`DEBUG`、缺字段） |
| `bad lines : 0` 且 `records : 0` | 占位实现还在 |
| `total lines : 23` | 空行也计进去了，或者反过来把某一行当空行跳过了 |
| `bad sample 4` 也打印了 | `bad_samples` 的前 3 条上限没写 |
| 程序在某一行崩溃 | `parse_line` 里直接取 `f[4]`、`f[5]`，段数不足时越界；先判 `f.size()` |

## 阶段 3 · 统计与抽样

**要做什么**

- 3-1 `summarize`：级别计数、耗时均值（`accumulate`，初值 `0.0`）、
  中位数（排序后取中间）、最大值、按任务分组（按任务名排序）
- 3-2 `sample_ms`：固定种子的 `std::mt19937` 抽 `n` 条耗时

**验收标准**

`Text`

```text
=== Stage 3: summarize and sample ===
INFO/WARN/ERROR  : 14 / 3 / 3
ms mean/median/max : 57.30 / 12.00 / 310
by task          : flush=3 parse=14 write=3
sample seed=2026 : 310 15 10 11 11
```

`实测数据`
`Text`

```text
20 条记录的耗时：最小 6、最大 310、总和 1146，均值 57.30
排序后第 10 与第 11 个都是 12，因此中位数 12.00
任务分组：parse 14 条、flush 3 条、write 3 条
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `mean_ms : 57` 而不是 `57.30` | `accumulate` 的初值写成了 `0`（整数），或者除以了整数个数 |
| `median_ms : 57.30` | 中位数直接用均值顶替了，没有排序取中间 |
| `median_ms : 44` | 取了第 `n/2` 个而奇数/偶数判断写反；20 个元素要取中间两个的平均 |
| `max_ms : 0` | 排序后取了 `front()`（最小值） |
| `by task` 顺序不对 | 分组之后没有排序 |
| `sample_ms` 每次运行都不同 | 种子没有固定成 `2026`，或者用了 `std::random_device` |
| `sample seed=2026` 那一行是空的 | 占位实现还在，或者 `records.empty()` 时提前返回了空表 |

## 阶段 4 · 计时与计数

**要做什么**

- 4-1 `measure_pipeline`：`steady_clock` 量解析、报表、总耗时三段
- 4-2 `count_records_atomic`：`std::atomic<long long>` 数记录条数

**验收标准**

`Text`

```text
=== Stage 4: timings and counting ===
records (atomic) : 20
timings          : parse = 0.075 ms, report = 0.022 ms, total = 0.100 ms
```

`实测数据`
`Text`

```text
同一份可执行文件连跑三次的 total：0.100 ms、0.101 ms、0.100 ms（每次运行都不同）
records (atomic) 是确定值 20
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `records (atomic) : -1` | 占位实现还在 |
| `parse = 0.000` | 计时区间把解析包漏了，或者解析结果被优化掉了（结果要参与输出） |
| `total` 比 `parse` 小 | `total` 的终点取在了解析之前；终点要在报表拼完之后 |
| 三行数字完全相同 | 三段实际上量的是同一段代码 |

## 阶段 5 · 报表与自测

**要做什么**

- 5-1 `format_report`：按固定宽度拼出报表（表头、任务表、最慢 5 条、耗时行）
- 5-2 用 `--selftest` 检查前面四个阶段

**验收标准**

`Text`

```text
=== Stage 5: report ===
file      : data/app.log
lines     : 24
records   : 20
bad lines : 4
INFO/WARN/ERROR : 14 / 3 / 3
ms mean/median/max : 57.30 / 12.00 / 310
by task   :
  flush   : 3
  parse   : 14
  write   : 3
slowest   :
   1  write     310  ERROR
   2  write     280  ERROR
   3  write     265  ERROR
   4  flush      52  WARN
   5  flush      48  WARN
timings   : parse = 0.075 ms, report = 0.022 ms, total = 0.100 ms
```

自测全部通过时：

`Text`

```text
=== selftest ===
  [ok]   read_text_file reads data/app.log
  ...
  [ok]   format_report is not a placeholder

31 项中 31 项通过，全部通过
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 报表是一行 `(TODO stage 5-1: ...)` | 占位实现还在 |
| 数字没有对齐 | `std::setw` 只对下一个输出项生效，每一项都要写一次 |
| `slowest` 打印了最快的 5 条 | 排序方向反了 |
| `ms mean/median/max : 57.3 / 12 / 310` | 没有 `std::fixed` 与 `setprecision(2)` |
| 耗时那一行小数位不对 | 耗时用三位小数，均值用两位；两处的 `setprecision` 要分别设置 |
| 自测里 `format_report is not a placeholder` 失败 | 报表长度不足 100 字节，检查是不是只拼了表头 |
| 自测退出码是 24 | 有 24 项没过，从第一项 `[FAIL]` 开始逐个修 |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'optional' is not a member of 'std'` | 漏了 `#include <optional>`；C++17 起才有 |
| 编译报 `'filesystem' is not a member of 'std'` | 漏了 `#include <filesystem>` |
| 解析 `ms=abc` 时抛 `std::invalid_argument` | 用了 `std::stoi` 而没有捕获异常；本模板的 `to_long` 已经返回 `optional`，直接用它 |
| `parse_line` 在段数不足时崩溃 | 先判 `f.size() != 6` 再取下标 |
| 抽样结果每次运行都不同 | 种子要固定；`std::random_device` 是不确定的 |
| 计时的数字是 0 | 被优化掉了：解析结果与报表长度要参与输出（参考实现里用一个 `volatile` 变量兜底） |
| 自测报 `read_text_file reads data/app.log` 失败 | 不在模板目录下运行；自测也依赖相对路径 |
| MSVC 下 `std::filesystem` 报链接错误 | 用较新的 MSVC（VS 2019 起不需要额外链接）；GCC 8 及更早要链 `stdc++fs` |
