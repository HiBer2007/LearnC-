# 配置步骤 · 06-standard-library/06-cpp-chrono-benchmark（`<chrono>` 基准测试工具）

本模板是**分阶段的整体演练**：成品是一个小基准测试工具，
先把 `duration` 的单位换算理清，再对一段固定工作量做多次测量并给出分位数，
然后处理系统时钟与本地时间，最后用原子量计数并校准 `sleep_for`。
每个阶段结束时程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · `duration` 与单位换算

**要做什么**（都在 `src/bench.cpp`）

- 1-1 `ms_of_seconds`：`duration_cast<milliseconds>(seconds(s))`
- 1-2 `seconds_of_ms`：用 `duration<double>`，不要用 `duration_cast`（那会截断）
- 1-3 `us_of_ms`：`duration_cast<microseconds>`，往小单位换
- 1-4 `add_ms`：两个毫秒数相加

**验收标准**

`Text`

```text
=== Stage 1: durations and conversions ===
1500 ms as seconds   : 1.500
2 s as milliseconds  : 2000
1 s + 500 ms         : 1500 ms
1500 ms as us        : 1500000
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `1500 ms as seconds : 1.000` | 用了 `duration_cast<seconds>`，整数除法把 0.5 秒截掉了。要保留小数就用 `duration<double>` |
| `2 s as milliseconds : 2` | 忘了 `duration_cast`，直接取了秒数的 `count()` |
| `1500 ms as us : 1500` | 换算方向反了，或者两个单位写成了同一个 |
| `1 s + 500 ms : 500` | 加号写成了减号，或者只取了第二个操作数 |
| 编译报 `no matching function for call to 'duration_cast'` | 模板参数写成了单位类型之外的写法；正确写法是 `duration_cast<std::chrono::milliseconds>(...)` |

## 阶段 2 · `steady_clock` 多次测量

**要做什么**

- 2-1 `measure`：把 `workload(n)` 跑 `samples` 次，每次用 `steady_clock` 量一遍，
  把所有耗时排序后取最小、中位、最大；结果要落到一个变量上，避免整段被优化掉

**验收标准**

`Text`

```text
=== Stage 2: steady_clock, repeated measurement ===
workload        : n = 200000
samples         : 9
min / median / max : 0.453 / 0.454 / 0.470 ms
monotonic_ok    : yes
note            : the milliseconds change on every run
```

`实测数据`
`Text`

```text
同一份可执行文件连跑两次：
  min / median / max : 0.453 / 0.454 / 0.470 ms
  min / median / max : 0.453 / 0.454 / 0.454 ms
```

毫秒数每次运行都不同，因此验收比对的是结构与 `monotonic_ok` 这一行，
不是具体数字。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `samples : 0` | 占位实现还在，或者 `samples < 1` 的判断把它挡掉了 |
| 三个数字完全一样，且每次运行也完全一样 | 编译器把整段计算优化掉了：`workload` 的返回值没有被使用。把它累加到一处外部可见的变量上 |
| `monotonic_ok : no` | 排序之后没有按「front / 中间 / back」取值，例如中位数取了 `size()/2 - 1` |
| 数字大了三个数量级（几百毫秒） | 计时区间把整个循环包进去了，而不是每次循环单独量 |
| 数字是 0.000 | 用了 `steady_clock::now().time_since_epoch().count()` 却没有换算单位 |

## 阶段 3 · `system_clock` 与本地时间

**要做什么**

- 3-1 `format_now`：转 `time_t`、转本地 `std::tm`、用 `std::put_time` 输出
  `"YYYY-MM-DD hh:mm:ss"`
- 3-2 `epoch_seconds`：当前的纪元秒数

**验收标准**

`Text`

```text
=== Stage 3: system_clock and calendar ===
now (local)     : 2026-10-01 15:45:28
format_ok       : yes
epoch seconds   : 1790840728
note            : system_clock can be adjusted, use steady_clock to time code
```

具体时间与纪元秒数当然是运行时的那一刻，验收看 `format_ok` 这一行。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `format_ok : no` | 格式串不是 `"%Y-%m-%d %H:%M:%S"`，例如用了 `%D`（那是 `mm/dd/yy`） |
| 年月日是 1900 年附近 | 直接把 `system_clock` 的 `count()` 当秒数用了；要先 `to_time_t` 再 `localtime` |
| 小时数少了 8 小时 | 用了 `gmtime`（UTC）而不是 `localtime`（本地时区） |
| 编译报 `'localtime_s' was not declared` | 非 Windows 平台要换成 `localtime_r`；本模板用宏分了平台 |
| `now` 那一行打印成一片数字 | 把 `time_point` 直接送进了流；要先格式化 |

> [!WARNING]
> `system_clock` 可以被系统对时（NTP）调整，用它测耗时会出现负数或跳变。
> 测代码耗时要用 `steady_clock`。见《06-标准库/B-06-时间：chrono.md》第 2 节。

## 阶段 4 · 原子量计数与 `sleep_for`

**要做什么**

- 4-1 `count_with_atomic`：跑一遍 `workload(n)`，把返回值加进原子计数器并返回
- 4-2 `sleep_ms_measured`：`sleep_for` 之前与之后各取一次 `steady_clock`，返回实测毫秒

**验收标准**

`Text`

```text
=== Stage 4: atomic counter and sleep ===
counter         : 648033198
sleep asked     : 5 ms
sleep measured  : 5.848 ms
at least asked  : yes
```

`sleep measured` 是实测值，与系统定时器分辨率有关；`counter` 是确定值。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `counter : -1` | 占位实现还在 |
| `counter` 每次都是 0 | `Counter::add` 没有真正改到原子量，或者 `workload` 的返回值被丢了 |
| `sleep measured : -1.000` | `sleep_for` 前后的两次取时写反了 |
| `at least asked : no` | 起点取在 `sleep_for` 之后；顺序必须是「取时 → 睡 → 取时」 |
| 编译报 `'std::this_thread' has not been declared` | 漏了 `#include <thread>` |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'std::chrono_literals'` 相关错误 | 用 `100ms` 这类后缀要 `using namespace std::chrono_literals;`，或者写全 `std::chrono::milliseconds(100)` |
| 测量的时间恒定不变，或者快得不像话 | 被优化掉了：测的东西必须有外部可见的结果 |
| 第二次测量的时间比第一次大很多 | 首次运行的缓存与页错误造成的，多测几次取中位数 |
| MinGW 与 MSVC 的 `sleep_for(5ms)` 实测值差很多 | 定时器分辨率不同，这是系统行为不是代码问题；判据只要求「不小于请求值」 |
| `std::put_time` 报未定义 | 漏了 `#include <iomanip>` |
| MSVC 报 `localtime` 不安全（C4996） | 用 `localtime_s`；本模板的头文件里用 `#if defined(_WIN32)` 分了平台 |
