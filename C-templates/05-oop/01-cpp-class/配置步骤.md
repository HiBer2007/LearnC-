# 配置步骤 · 05-oop/01-cpp-class（类与对象）

本模板是**分阶段的整体演练**：成品是一个自己写的字符串类 `MyString`，
外加三个驱动——命令行版 `app_cli.exe`、Win32 界面版 `app_gui_win32.exe` 与 Qt 界面版 `app_gui_qt.exe`（默认不构建）。
每个阶段结束时两个程序都能编译、能运行。怎么复制模板、怎么打开、遇到问题查哪里，
见 [`../../README.md`](../../README.md)，本文件不重复。

---

## 成品形态

做完 4 个阶段之后，`MyString` 是一个能独立使用的字符串类：

| 能力 | 由哪一阶段提供 |
|---|---|
| 从 C 字符串构造、析构时释放内存、查询长度与内容 | 阶段 1 |
| 追加内容（重新分配）、清空、越界访问抛 `std::out_of_range` | 阶段 1 |
| 拷贝构造与拷贝赋值都是深拷贝，自赋值安全 | 阶段 2 |
| 移动构造与移动赋值接管内存，源对象回到空串，且标 `noexcept` | 阶段 3 |
| 能放进 `std::vector`，容器扩容时走移动而不是拷贝 | 阶段 4 |

命令行版按阶段打印验收数据；界面版把同一个对象的状态实时显示在窗口上。

## 阶段 1 · 构造、析构、查询与 `append`

**要做什么**（都在 `src/mystring.cpp`）

- 1-1 `MyString(const char *s)`：量长度、用 `alloc_copy` 拿一块自己的内存
- 1-2 `~MyString()`：`delete[] data_`，并让 `live_count_` 自减
- 1-3 `size()`、`empty()`、`c_str()`（空串返回 `""`，不是 `nullptr`）
- 1-4 `at()`：越界抛 `std::out_of_range`
- 1-5 `append()`：重新分配、复制两段内容、释放旧内存
- 1-6 `clear()`：释放内存并回到空串

**验收标准**

`Text`

```text
=== 阶段 1：构造与析构 ===
  empty : size = 0, empty() = true, c_str = ""
  hello : size = 5, c_str = "hello"
  hello[0] = 'h'
  越界被接住：MyString::at 下标越界
  live = 2, alloc = 1
  作用域结束：live = 0
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `hello : size = 0` | 初始化列表里没填 `size_`，或者忘了调用 `alloc_copy` |
| `hello[0] = ' '` 且没有异常 | `at()` 还没写；注意越界那一行必须抛异常 |
| `作用域结束：live = 2` | 析构函数里没有 `--live_count_` |
| 程序在退出时崩溃，报 `free(): invalid pointer` 一类 | 释放了不是 `new char[]` 得来的指针，检查是否误用了 `delete`（少了 `[]`） |

## 阶段 2 · 拷贝构造与拷贝赋值（深拷贝）

**要做什么**

- 2-1 `MyString(const MyString &other)`：为对方的内容单独分配一块内存
- 2-2 `operator=(const MyString &other)`：先分配新的，再释放旧的，返回 `*this`

**验收标准**

`Text`

```text
=== 阶段 2：拷贝构造与拷贝赋值 ===
  a = "hello" (5)
  b = "hello world" (11)
  c = "hello" (5)
  自赋值后 c = "hello" (5)
  live = 3, alloc = 6
```

其中 `alloc = 6` 是累计值：阶段 1 用掉 1 次，本阶段用掉 5 次
（`a`、`b` 的拷贝、`b.append`、`c` 的构造、`c = a` 各一次）。
自赋值那一行不增加分配，因为 `operator=` 里判断了 `this != &other`。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `b = "" (0)` | 拷贝构造还是占位版本，没有复制内容 |
| `a = "hello world"` | 拷贝成了浅拷贝：两个对象共用一块内存，改一个影响另一个 |
| 程序在阶段 2 结束时崩溃 | 典型现象是同一块内存被 `delete[]` 两次。把拷贝构造暂时改成 `data_ = other.data_; size_ = other.size_;` 跑一次，就能看到这个崩溃，然后改回深拷贝 |
| 自赋值后内容变成空 | `operator=` 里先释放了旧内存再读 `other`，自赋值时读到的就是已经释放的内容 |

## 阶段 3 · 移动构造与移动赋值

**要做什么**

- 3-1 `MyString(MyString &&other)`：接管内存，把源对象置成空串，并给声明与定义都加 `noexcept`
- 3-2 `operator=(MyString &&other)`：处理自赋值、释放自己的旧内存、接管、把源对象置成空串

**验收标准**

`Text`

```text
=== 阶段 3：移动构造与移动赋值 ===
  big   : size = 0, c_str = ""
  taken : size = 10, c_str = "0123456789"
  taken : size = 0
  target: size = 10, c_str = "0123456789"
  新增分配 = 0, 新增移动 = 2
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `big : size = 10` | 移动之后没有把源对象置空，两块内存指向同一个缓冲，析构时会双重释放 |
| `新增分配 = 2` | 移动里又分配了内存，那是拷贝不是移动 |
| `新增移动 = 0` | `move_count_` 没有自增，或移动操作根本没被调用 |

## 阶段 4 · 放进 `std::vector`

**要做什么**

- 确认移动操作已经标了 `noexcept`（头文件与实现都要）
- 把 `src/main_cli.cpp` 里那行 `static_assert(std::is_nothrow_move_constructible<...>)` 取消注释

**验收标准**

`Text`

```text
=== 阶段 4：放进 vector，看容器怎么搬运 ===
  words = "alpha" "beta" "gamma"
  移动次数 = 6
  新增分配 = 3
  live = 3

=== 收尾 ===
  live = 0（构造与析构应当配平，最终为 0）
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `移动次数 = 3, 新增分配 = 6` | 移动构造没标 `noexcept`。标准容器扩容时只在「移动不抛」的前提下才搬元素，否则改用拷贝。这正是本阶段要看的现象，实测对照见下表 |
| `live = 17` 一类的数字 | 析构函数没有配平，回到阶段 1 |
| `static_assert` 报「移动构造必须标 noexcept」 | 同上，去头文件与实现里补 `noexcept` |

`实测数据`
`Text`

```text
标了 noexcept：  移动次数 = 6，新增分配 = 3
漏了 noexcept：  移动次数 = 3，新增分配 = 6
```

## 界面部分怎么用

界面版是同一个核心模块的第二个驱动，有 Win32 与 Qt 两份实现，业务逻辑都只在 `core` 里。

### 两份界面：Win32 与 Qt

同一个窗口有两份实现，业务逻辑都只在 `core` 里，两份界面只负责调用它：

| 文件 | 界面库 | 产物 | 默认是否构建 |
|---|---|---|---|
| `src/main_gui_win32.cpp` | Win32 API + GDI | `app_gui_win32.exe` | 构建（零第三方依赖） |
| `src/main_gui_qt.cpp` | Qt Widgets | `app_gui_qt.exe` | **不构建**，需要显式打开 |

两份界面里的 TODO 是**同一批**，编号也一致（界面连接 1、2a、2b……）。
**做一份即可**，另一份留作对照：同一件事在消息映射里怎么写、在信号槽里怎么写。

**Qt 版怎么打开**

Qt 版用的是**官方安装器的动态版 Qt**，配置时指向那一套 Qt 的**套件目录**：

`PowerShell`

```powershell
# 套件目录要指到编译器那一层，例如 <Qt>/6.11.1/mingw_64
cmake --preset mingw-gdb -DWITH_QT=ON -DQT_ROOT=<Qt 的套件目录>
cmake --build --preset mingw-gdb
build\mingw\bin\app_gui_qt.exe
```

- `WITH_QT` 默认为 `OFF`：没有 Qt 时，`core`、`app_cli` 与 `app_gui_win32` 照常构建；
- Qt 的位置也可以放在环境变量 `QT_ROOT` 里，此时配置命令不必再写 `-DQT_ROOT`；
- 定位 Qt 与工具链匹配检查都交给仓库根目录 `工具/获取依赖/qt-dynamic.cmake`，
  **工程里不写死任何本机路径**；
- 模板若已被复制到仓库之外，Qt 版需要自行 `find_package(Qt6 COMPONENTS Widgets REQUIRED)`。

**运行时怎么部署**

构建完成后会自动调用 `windeployqt`，把 Qt 的 DLL 与 `platforms\qwindows.dll` 拷到 exe 旁边，
随后再把编这个 exe 的那套 MinGW 运行时 DLL 拷过去：

`Text`

```text
Qt6Core.dll  Qt6Gui.dll  Qt6Widgets.dll  platforms\qwindows.dll
libgcc_s_seh-1.dll  libstdc++-6.dll  libwinpthread-1.dll
```

- 后三个是 **MinGW 运行时**。Qt 自己的 DLL 也依赖它们，因此必须与 exe 放在一起，
  而且**必须与编译器同源**——不同 GCC 版本的 `libstdc++-6.dll` 混用会出怪问题；
- 工程同时给 Qt 目标加了 `-static-libgcc -static-libstdc++`：exe 本身不再依赖
  `libgcc_s_seh-1.dll` 与 `libstdc++-6.dll`，但 Qt 的 DLL 仍然需要，所以照拷；
- 目标机器仍需要对应的编译器运行库：MSVC 构建要装 Visual C++ 运行库；
  MinGW 构建的这三个 DLL 已经拷在 exe 旁边；
- **判据：把 exe 连同这些 DLL 拷到一个没有 Qt、`PATH` 里也没有 Qt 与 MinGW 的目录，
  双击能起窗口，才算部署完成。**
- 部署产物全部落在 `build\` 里，已被仓库 `.gitignore` 覆盖，**不要提交 DLL**。

> [!TIP]
> 只练语言部分时保持 `WITH_QT=OFF`，用 Win32 版或命令行版即可，不必装 Qt。

**怎么跑**

`PowerShell`

```powershell
cmake --build --preset mingw-gdb
build\mingw\bin\app_gui_win32.exe
```

也可以直接在 VS Code 里调试它：新建一条 `cppdbg` 或 `cppvsdbg` 配置，
`program` 指向 `build/mingw/bin/app_gui_win32.exe`（MSVC 生成器则是
