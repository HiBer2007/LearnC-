# 配置步骤 · 09-data-structures/02-list（手写链表）

本模板是**分阶段的整体演练**：把 `list` 的哨兵与指针改动自己写一遍。
4 个阶段依次补上「插入接链」「删除摘链与销毁」「清空与析构顺序」「整条链转移」，
每个阶段结束时程序都能构建、能跑出可对照的输出。

本模板的参考答案不给，判据就是本文件里逐字给出的输出与自查表。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · 插入：改哪几个指针

**要做什么**（在 `include/list.hpp` 里，TODO 阶段 1-1）

`insert(pos, value)` 把新节点接在 `pos` 之前，并返回指向新节点的迭代器。

**验收标准**

`Text`

```text
=== Stage 1: insert links the new node ===
size                  : 4
check                 : ok
values                : [2 3 4 5]
nodes alive           : 5
```

四次插入分别是：尾插 3、头插 2、尾插 5、在 5 之前插 4，因此内容是 `[2 3 4 5]`。
`nodes alive = 5` 是 4 个元素加 1 个哨兵——哨兵也占一个节点。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `check : size() differs from the number of nodes on the chain` | 节点建好了、`size_` 也加了，但没有接进链里（占位实现就是这样） |
| `check : node->prev does not match the node before it` | 只改了 `next` 一侧，`prev` 没有成对更新 |
| `values` 顺序反了 | 新节点接在了 `pos` 之后而不是之前 |
| `nodes alive` 是 6 而 `size` 是 4 | 多出来的那个节点没有接进链，也就永远不会被销毁 |
| 头插或尾插崩溃 | 忘了哨兵：`pos` 就是哨兵时，`pos->prev` 是最后一个节点，两者是同一段代码，不需要特例 |

> [!IMPORTANT]
> **插入点之前与之后的迭代器都不会失效。** 链表只改指针，不搬元素——
> 这一点与动态数组相反，也是「位置已经拿到时插入是常数时间」的来路。

## 阶段 2 · 删除：摘链与销毁的顺序

**要做什么**（TODO 阶段 2-1）

`erase(pos)` 把 `pos` 指向的节点从链上摘下来、销毁它，并返回它的后继。

**验收标准**

`Text`

```text
=== Stage 2: erase unlinks and destroys ===
size                  : 2
check                 : ok
values                : [2 4]
nodes destroyed       : 3
nodes alive           : 3
```

原来是 `[1 2 3 4 5]`，删掉头（1）、中间（3）、尾（5）之后剩 `[2 4]`。
销毁了 3 个节点，剩 3 个（2 个元素加 1 个哨兵）。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `check : size() differs from ...` | 只把 `size_` 减了，节点还挂在链上（占位实现就是这样） |
| `nodes destroyed : 0` | 没有调用销毁节点的那个函数，节点内存漏了 |
| `nodes alive` 比 `size + 1` 大 | 有节点摘下来却没销毁，或者销毁了两次的写法把计数弄乱了 |
| 删尾之后 `check` 报错误 | 删的是最后一个节点时，它的后继就是哨兵，不需要特例；检查是不是把哨兵当成了普通节点处理 |
| 程序崩溃或读到乱码 | 顺序反了：先销毁节点（内存已还回去）再去读它的 `next` |

> [!CAUTION]
> **销毁会释放内存，读了再还。** 需要用到被删节点的什么东西，一律在销毁之前取出来。

## 阶段 3 · 清空与析构顺序

**要做什么**（TODO 阶段 3-1、3-2）

- 3-1 `clear()`：把元素全部去掉，哨兵留着，链回到「哨兵自环」的状态；
- 3-2 `~List()`：做一遍 `clear()`，然后连哨兵一起销毁。

**验收标准**

`Text`

```text
=== Stage 3: clear and destructor order ===
after clear, size     : 0
after clear, check    : ok
nodes alive           : 1
push after clear      : 3
alive after scope     : 0
```

- `nodes alive = 1` 是哨兵：`clear()` 不该把哨兵也删掉，否则这个容器就废了；
- `push after clear = 3` 说明清空之后容器还能继续用；
- `alive after scope = 0` 说明析构把哨兵也还回去了。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `after clear, size : 200` | 占位实现还在，`clear()` 什么都没做 |
| `after clear, check` 报不一致 | 元素删了但 `size_` 没归零，或者哨兵的两个指针没有变回自环 |
| `nodes alive : 201` | `clear()` 没有销毁元素，只是把 `size_` 置了 0 |
| `alive after scope : 1` | 哨兵漏了；析构里除了清空元素，还要把哨兵还回去 |
| 清空 200 个节点时崩溃 | 顺序反了：先销毁当前节点，再去取它的 `next`；要先记住下一个 |
| `push after clear` 崩溃 | 哨兵被删掉了，或者哨兵没有变回自环 |

## 阶段 4 · `splice`：整条链的转移

**要做什么**（TODO 阶段 4-1）

把 `other` 的整条链摘下来接到 `pos` 之前。要改的指针只有四个，`other` 的哨兵要变回自环，
两个容器的 `size` 都要改。

**验收标准**

`Text`

```text
=== Stage 4: splice moves the whole chain ===
dst size              : 6
src size              : 0
dst check             : ok
dst values            : [1 2 3 4 5 6]
src values            : []
address kept          : yes
constructed in splice : 0
destroyed in splice   : 0
```

`实测数据`
`Text`

```text
g++ 16.2.0，本机：
  转移 4 个节点，dst 从 2 变成 6、src 从 4 变成 0
  转移过程中构造的元素数 0、析构的元素数 0
  第一个节点的地址与转移前相同
```

最后三行是这一阶段真正的判据：**常数时间与「不构造不析构」是同一件事的两面**。
`address kept = yes` 说明节点没有搬家，因此指向它们的迭代器与引用仍然有效。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `dst size : 2`、`src size : 4` | 占位实现还在，什么都没搬 |
| `address kept : no` 且 `constructed` 大于 0 | 写成了「逐个复制过去再删掉」：这是 `insert` 加 `erase`，不是 `splice` |
| `dst check` 报不一致 | 四根指针漏改了一根，或者 `other` 的哨兵没有变回自环 |
| `dst size` 对而 `src size` 还是 4 | 只改了一个 `size`；两个都要改 |
| `src values` 不是空的 | `other` 的哨兵还指着已经搬走的链 |
| 自己搬给自己时死循环 | `&other == this` 时应当直接返回 |

> [!WARNING]
> **`splice` 之后，两个容器的 `size` 都要改，而且元素不会重新构造。**
> 如果元素的析构里有副作用（计数、写日志），`splice` 不会触发它们——
> 这与「删掉再插入」的语义不同。

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `Node` 是私有类型 | `iterator` 与 `List` 是友元关系，成员函数里直接用 `pos.node_` 即可，不要在类外命名 `Node` |
| 编译报 `size_` 未声明 | 成员函数的定义写在类外时，返回类型要写全（`typename List<T>::iterator`） |
| `check()` 一直报链上有环 | 新节点的 `next` 指回了自己，或者哨兵的 `next` 没有接上 |
| 只用 `--it` 从 `end()` 往回走时崩 | `--end()` 是最后一个节点，这是对的；空链时它是哨兵自己，注意判空 |
| 每次运行节点计数都对不上 | 计数器只在建立与销毁两处增加，只要有一处漏调用就会一直累积 |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `core` 与 `app_cli` 加了 `/utf-8` |
