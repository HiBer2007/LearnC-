# 配置步骤 · 09-data-structures/04-rb-tree（手写红黑树）

本模板是**分阶段的整体演练**：先写一个不变式校验器，再把插入修复的三种情形补上。
4 个阶段结束时程序都能构建、能跑出可对照的输出。

这个模板只做插入，删除用「标记删除」顶着——这是
《09-高阶数据结构/B-04-手写：平衡树.md》第 4.3 小节给的顺序：
先把旋转、颜色、不变式校验这三件事写对，删除那四种情形以后再说。

本模板的参考答案不给，判据就是本文件里逐字给出的输出与自查表。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · 不变式校验器

**要做什么**（在 `include/rb_tree.hpp` 里，TODO 阶段 1-1）

写 `check_subtree(p, height)`：校验「红节点的孩子必须是黑的」与「搜索树顺序」，
递归左右子树，比较两边返回的黑高度。空节点算一个黑（高度 1）；
自己的高度 = 孩子的高度 + （自己是黑节点时加一）。

**验收标准**

`Text`

```text
=== Stage 1: the invariant checker ===
hand-built tree, size             : 7
hand-built tree, check            : ok
hand-built tree, black height     : 3
hand-built tree:
B:40
|-- L B:20
|   |-- L R:10
|   \-- R R:30
\-- R B:60
    |-- L R:50
    \-- R R:70
broken: root is red               : the root is not black
broken: red child of red node     : a red node has a red child
broken: black heights differ      : two paths have different black heights
broken: search order              : the search-tree order is broken (left child)
```

前四行是手工搭的一棵合法树（用已经给出的 `insert_raw` 与 `repaint`，不经过修复），
校验器算出的黑高度是 3：从根到四条空路径各有 2 个黑节点，再加上空节点算的那一个。后四行是把它分别破坏一次：

| 怎么破坏的 | 校验器要报的话 |
|---|---|
| 把根由黑染红 | `the root is not black`（这一条由 `check()` 查） |
| 把一个黑节点染红，它的孩子本来就是红的 | `a red node has a red child` |
| 把一片红叶子染黑 | `two paths have different black heights` |
| 把 10 改成 99，左子树里冒出比父亲大的键 | `the search-tree order is broken (left child)` |

**判据**：这四句话各不相同，而且分别落在四条不变式上。任何一句写成「不合法」，
校验器就没有起到它该起的作用——**报出是哪一条**才是它的价值。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 四行全是 `ok` | 占位实现还在，函数永远返回「没问题」 |
| 黑高度是 1 | 没有把子树的高度算进来；空节点的高度是 1，自己的高度在上面加 |
| 黑高度是 3 但破坏之后仍然 `ok` | 只写了递归，没有比较左右两边的高度 |
| 红孩子那一句报不出来 | 红黑性质查在了错误的一侧：要看的是「自己是红时，孩子是不是红」 |
| 一片叶子染黑之后报的是红孩子 | 遍历顺序问题：先查当前节点、再递归，这样报出的才是最近的一条 |
| 搜索树顺序那一句报不出来 | 比较用了 `<=` 而不是 `<`，或者只在一边查了 |

> [!TIP]
> **随机测加校验器是最省力的组合**：随机插几万个键，每一步都跑校验器。
> 红黑树的分支很多，手写的用例覆盖不全，而随机序列能在几秒内把各种情形都走一遍。

## 阶段 2 · 情形 3：叔叔是黑的，当前节点是外侧孩子

**要做什么**（TODO 阶段 2-1）

父亲染黑、祖父染红，然后对祖父做一次旋转。这一棵子树修好之后不必再往上——
用 `break` 结束循环。

**验收标准**

`Text`

```text
=== Stage 2: case 3, uncle is black and node is the outer child ===
size                              : 3
check                             : ok
black height                      : 2
failed checks while inserting     : 0
after inserting 30, 20, 10:
B:20
|-- L R:10
\-- R R:30
```

依次插入 30、20、10：第三次插入落在「一路往左」的外侧，正好是情形 3。
修完之后根是 20（黑），两个孩子都是红——这是一棵合法的红黑树。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 树还是 `B:30 / R:20 / R:10`，`check` 报红孩子 | 占位实现还在，什么都没做 |
| 旋转方向反了，树变成一条向右的链 | 方向由 `parent_is_left` 决定：父亲在左边就右旋祖父 |
| `check` 报「搜索树顺序」 | 旋转里漏了更新父指针，树的形状与实际链接对不上 |
| 修完之后 `check` 报黑高度不同 | 颜色改错了：是**父亲染黑、祖父染红**，不是反过来 |
| 修完还继续往上走，把别的子树弄坏 | 情形 3 修完就结束，用 `break`；只有情形 1 需要继续 |

## 阶段 3 · 情形 2：叔叔是黑的，当前节点是内侧孩子

**要做什么**（TODO 阶段 3-1）

对**父亲**做一次旋转，把折线拉直，让它落进情形 3；旋转之后父亲与祖父都变了，
要重新取一遍再往下走。落进情形 3 之后不要在这里结束。

**验收标准**

`Text`

```text
=== Stage 3: case 2, uncle is black and node is the inner child ===
size                              : 3
check                             : ok
black height                      : 2
failed checks while inserting     : 0
after inserting 30, 10, 20:
B:20
|-- L R:10
\-- R R:30
```

依次插入 30、10、20：第三次插入落在内侧（折线），先拉直再落进情形 3。
最后得到的树与阶段 2 完全一样——**两条不同的插入顺序得到同一棵红黑树**。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 树还是 `B:30 / R:10 / \ R:20`，`check` 报红孩子 | 占位实现还在，没有拉直 |
| 拉直之后 `check` 报搜索树顺序 | 旋转绕着祖父做了；情形 2 转的是**父亲** |
| 拉直之后程序崩溃或读到坏指针 | 旋转完没有重新取 `parent` 与 `grand`，用的是已经挪位的旧指针 |
| 拉直之后仍然报红孩子 | 拉直之后没有往下走：情形 2 要把当前节点换成旋转前的父亲，好让情形 3 认出「外侧孩子」 |
| 无限循环 | 情形 2 里用了 `continue`：它不是往上推，而是就地转成情形 3 |

> [!IMPORTANT]
> **情形 1 是唯一需要继续往上的情况**，另两种都在本层结束。
> 写循环时把这一点记住，就不会写出「修完还往上跑」的死循环。

## 阶段 4 · 情形 1：叔叔是红的

**要做什么**（TODO 阶段 4-1）

父亲与叔叔染黑、祖父染红，然后把祖父当成新的「当前节点」继续往上修。
一路推到根时，循环会因为「当前节点就是根」而结束，最后把根染黑。

**验收标准**

`Text`

```text
=== Stage 4: case 1, uncle is red ===
size                              : 4
check                             : ok
black height                      : 3
failed checks while inserting     : 0
after inserting 20, 10, 30, 5:
B:20
|-- L B:10
|   |-- L R:5
\-- R B:30
1..64 ascending, failed checks    : 0
1..64 ascending, black height     : 6
random 64 keys, failed checks     : 0
random 64 keys, size              : 64
random 64 keys, black height      : 5
```

依次插入 20、10、30、5：第四次插入时父亲（10）与叔叔（30）都是红的，
于是双红被推给祖父（20），而祖父就是根，循环结束，根染黑。

后面两段是压力测试：一路递增的 64 个键（主要走情形 3）与固定种子的 64 个伪随机键
（三种情形都会走到），每插一个就校验一次。

`实测数据`
`Text`

```text
g++ 16.2.0，本机：
  1..64 递增：64 次插入，校验失败 0 次，最终黑高度 6
  64 个伪随机键（种子 12345 的线性同余）：校验失败 0 次，黑高度 5
```

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `failed checks : 61` 之类的大数 | 情形 1 没做：双红留在树里，后面每一步都带着它 |
| 树里出现连着两个红 | 同上；情形 1 是唯一需要继续往上的情况 |
| 程序在推到根时崩溃 | 循环条件里的 `node != root_` 被去掉了，取 `node->parent` 时越过了根 |
| 一路插入没有报错，但树很高 | 只把颜色改了没有继续往上推（漏了 `node = grand`），双红停在中途 |
| 根偶尔是红的 | 忘了最后那句「根永远染黑」。情形 1 可能一路推到根，它让所有路径的黑节点数一起加一 |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| `check` 报红孩子但看不出哪里红 | 把树打印出来：`print()` 把颜色写在键前面，连着两个 `R:` 就是它 |
| 旋转之后 `check` 报搜索树顺序 | 父指针漏更新：三处链接要成对更新，漏一处就「孩子认父、父不认孩子」 |
| 改一个地方之后别的子树也坏了 | 情形 1 的祖父可能是别人的孩子，改完要接着往上修 |
| 黑高度一直不相等 | 新节点染成了黑；新节点必须是红的，染黑会破坏最难修的那一条 |
| `-Wall` 报变量未使用 | 三段占位里带 `(void)` 的那些行，替换掉整段即可 |
| 编译报 `Node` 是私有类型 | 本模板的 `Node` 是公开的（测试工具要用它），直接用即可 |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `app_cli` 加了 `/utf-8` |
