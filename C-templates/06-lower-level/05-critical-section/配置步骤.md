# 配置步骤 · 06-lower-level/05-critical-section（临界区与原子）

本模板是**分阶段的整体演练**：成品是一个命令行程序，先复现一次「丢更新」，
再用三种办法各修一遍，最后把四种写法的代价放在同一张表里比。
中断不是真硬件中断，而是一个**确定性的模型**：挂起位加一个显式的派发点
（`request_irq()` 与 `poll()`），因此每次跑出来的丢次数都一样，可以逐行核对。
真板上对应的现场与周期数在《06-更底层/10-中断、并发与内存序.md》。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

---

## 成品形态

做完这 4 个阶段之后：

| 能力 | 由哪一阶段提供 |
|---|---|
| 复现丢更新：期望 4500、实际 4000、丢了 500 次 | 阶段 1 |
| 用 RAII 关中断修好，并且**恢复之前的状态**而不是无脑开中断 | 阶段 2 |
| 用可嵌套的临界区修好，进入两层再出来时层数先升后降 | 阶段 3 |
| 用原子读-改-写修好（relaxed 与 seq_cst 各一份），并给出四种写法的代价表 | 阶段 4 |

判定修好的标准不是「程序不崩」，而是**`lost` 那一栏是 0**。

## 阶段 1 · 复现丢更新

**要做什么**（在 `src/counter.cpp`）

- 1-1 `bump_unprotected`：把计数器读进一个局部变量（relaxed）→ 调用 `sim::poll()` →
  把「局部变量 + 1」写回（relaxed）。三步都要写在这个函数体里

**验收标准**

`Text`

```text
=== 阶段 1：无保护的自增（读—改—写，中间给中断留了入口）===
=== unprotected ===
  iterations : 4000
  isr calls  : 500
  expected   : 4500
  actual     : 4000
  lost       : 500
```

`isr calls` 是 500：主循环每 8 次迭代请求一次中断，4000 次迭代就是 500 次。
每一次中断里也把计数器加一，所以期望值是 4500；实际只到 4000，
**500 次中断的增量一次都没留下**。

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `actual = 0`、`lost = 4000` | 函数体还是空的，一次都没加 | 1-1 |
| `actual = 4500`、`lost = 0` | 三步里的 `sim::poll()` 被省掉了：中断没有插进来的机会 | 1-1，三步顺序是「读、poll、写」 |
| `actual` 每次运行都不一样 | 用了自己的计时器或线程当「中断」，而不是模型里的 `request_irq`/`poll` | 回 `include/sim_irq.hpp` 看模型契约 |
| `isr calls` 是 1 | 主循环没有请求中断，只有结尾那次 `poll()` 派发了一次 | 不要改 `main_cli.cpp` |
| `lost` 是 499 或 501 一类的数字 | 中断派发点在某些迭代里没被调用到（例如把 `poll` 放到了 `if` 里面） | 1-1 |

> [!IMPORTANT]
> **丢更新的根因不是「值算错了」，是「读和写之间被打断」。**
> 真板上同一件事的实测是：普通计数器期望 201459、实际 200000，
> 1459 次中断的增量全部丢失；换成原子操作后一次没丢。
> 数据与指令序列见《06-更底层/03-寄存器、位与 volatile.md》第 3.2 小节。

## 阶段 2 · 修法一：关中断

**要做什么**

- 2-1 `IrqGuard::IrqGuard`：把「现在中断是不是开着的」记进 `was_enabled_`，然后关中断
- 2-2 `IrqGuard::~IrqGuard`：只有 `was_enabled_` 为真时才开回去
- 2-3 `bump_irq_guard`：先构造一个 `IrqGuard`，再写阶段 1 那三步

**验收标准**

`Text`

```text
=== 阶段 2：关中断（IrqGuard，恢复之前的状态）===
=== irq guard ===
  iterations : 4000
  isr calls  : 500
  expected   : 4500
  actual     : 4500
  lost       : 0
```

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `lost` 还是 500 | `bump_irq_guard` 里没有构造 `IrqGuard`，或者构造了但没关中断 | 2-1、2-3 |
| 编译报 `was_enabled_ is used uninitialized` | 构造函数没有在初始化列表里给它赋值 | 2-1 |
| 嵌套调用之后中断被提前打开 | 析构里无条件 `sim::enable_irq()`：调用者本来关着中断时，这一下会误开 | 2-2，要按 `was_enabled_` 恢复 |
| `lost = 0` 但 `isr calls` 也变成 0 | 中断被永久关掉了：析构没有开回去 | 2-2 |
| 两次调用之后 `sim::irq_enabled()` 为假 | 关的次数比开的多：`disable_irq` 与 `enable_irq` 没有配对 | 2-1、2-2 |

> [!TIP]
> **RAII 的价值在返回值与异常路径上。** 手工写 `disable(); ...; enable();`
> 时，中间任何一条 `return` 或一次抛出都会把中断永久关掉。
> 析构函数保证配对，与《05-类与面向对象/06-RAII 与资源管理.md》第 4 节讲的是同一件事。

## 阶段 3 · 修法二：临界区（可嵌套）

**要做什么**

- 3-1 `CriticalSection::CriticalSection`：层数加一；**从 0 变 1 时**才真的关中断
- 3-2 `~CriticalSection`：层数减一；**减到 0 时**才真的开中断
- 3-3 `bump_critical`：先构造一个 `CriticalSection`，再写阶段 1 那三步

**验收标准**

`Text`

```text
=== 阶段 3：临界区（CriticalSection，可嵌套）===
=== critical section ===
  iterations : 4000
  isr calls  : 500
  expected   : 4500
  actual     : 4500
  lost       : 0
  nesting depth: 0 -> 1 -> 2 -> 0   (expect 0 -> 1 -> 2 -> 0)
```

`nesting depth` 那一行是本阶段特有的检查：进两层再一层层出来，层数先升后降。

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `nesting depth: 0 -> 0 -> 0 -> 0` | 构造与析构都没有动层数 | 3-1、3-2 |
| `nesting depth: 0 -> 1 -> 1 -> 0` | 内层没有加层数（把判断写成了赋值） | 3-1 |
| `nesting depth: 1 -> 2 -> 3 -> 2` | 初始值算错了，或者析构只减了一层的一半 | 3-1、3-2 |
| `lost` 还是 500 | 每一层都在关中断、但 `bump_critical` 里没用它 | 3-3 |
| 出了临界区中断还是关着 | 层数减到 0 时忘了 `enable_irq` | 3-2 |
| 两次进入之后 `depth()` 变成 1 | 析构里没有减层数，或者 `depth()` 返回的是别的变量 | 3-2 |

> [!IMPORTANT]
> **临界区与关中断用的是同一个原语，区别在「谁负责恢复」。**
> `IrqGuard` 恢复的是**之前的状态**，`CriticalSection` 维护的是**层数**；
> 两者都不能无脑开中断，否则内层一退出就把外层的保护拆了。

## 阶段 4 · 修法三：原子读-改-写

**要做什么**

- 4-1 `bump_atomic_relaxed`：`g_counter.fetch_add(1u, std::memory_order_relaxed)`，
  随后照样调用 `sim::poll()`
- 4-2 `bump_atomic_seq_cst`：同上，内存序换成 `std::memory_order_seq_cst`

**验收标准**

`Text`

```text
=== 阶段 4：原子自增（relaxed 与 seq_cst）===
=== atomic relaxed ===
  iterations : 4000
  isr calls  : 500
  expected   : 4500
  actual     : 4500
  lost       : 0
=== atomic seq_cst ===
  iterations : 4000
  isr calls  : 500
  expected   : 4500
  actual     : 4500
  lost       : 0
```

这一版**没有关中断**：`poll()` 照样在中间被调用，中断照样进来，
只是「加一」这件事不再由读、写两条指令拼成。

**代价对照（Release 构建，`-O3`）**

`Text`

```text
=== 代价对照：2000000 次自增，不请求中断 ===
  unprotected       :   2.12 ns/op
  irq guard         :   3.57 ns/op
  critical section  :   4.23 ns/op
  atomic relaxed    :   4.75 ns/op
  atomic seq_cst    :   4.76 ns/op
```

`实测数据`
`Text`

```text
同一台机器、同一份源码，连跑三次的抖动范围（Release）：
  unprotected        2.12 ~ 2.20 ns
  irq guard          3.57 ~ 4.48 ns
  critical section   3.59 ~ 4.27 ns
  atomic relaxed     4.75 ~ 4.79 ns
  atomic seq_cst     4.73 ~ 4.79 ns

Debug 构建（-O0，不内联）下的这一栏不能用来看保护的开销：
每一栏都多出 2 到 3 ns 的函数调用开销，排序也会反过来（实测）。
```

`实测数据`
`Text`

```text
真板上的同一组对照（STM32F103C8，8 MHz，周期数）：
  普通自增            7 周期
  原子自增（seq_cst） 14 周期（ldrex / strex 加重试，外加两条 dmb 屏障）
  关中断再开          6 周期（cpsid i 与 cpsie i）

数据见《06-更底层/10-中断、并发与内存序.md》第 3.4 小节与第 4.1 小节。
```

**两边的排序为什么相反**：主机上的「关中断」是两个函数调用（进 `sim_irq` 改一个计数），
而真板上它就是两条指令；原子操作在主机上是一条 `lock` 前缀指令（约 5 ns），
在 Cortex-M3 上却要走独占访问的重试循环。**代价要看目标机器**，
这也是《07-标准库/B-10-内存与并发的基础设施.md》第 6.1 小节要对照两种环境的原因。

**怎么自查**

| 你看到的 | 说明 | 改哪里 |
|---|---|---|
| `lost` 还是 500 | 还是读、写两步；`fetch_add` 没有被用上 | 4-1 |
| 编译报 `no member named 'fetch_add'` | 计数器不是 `std::atomic` 类型，或者少了 `#include <atomic>` | `src/counter.cpp` 的包含区与 `g_counter` 声明 |
| `lost = 0` 但 `poll` 被省掉了 | 那只是没让中断插进来，不是真的安全 | 4-1，`fetch_add` 之后照样调用 `sim::poll()` |
| `atomic seq_cst` 比 `relaxed` 便宜 | 主机上 x86-64 的两种内存序编出来的指令差不多，这是正常现象 | 不用改；换 ARM 或换编译器再看 |
| Debug 下 `unprotected` 最慢 | `-O0` 不内联，三步里的每一次原子访问都成了函数调用 | 用 `mingw-rel` 预设再量 |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 四个阶段的 `lost` 全是 4000 | 什么都没做（骨架状态）：`actual` 只有结尾那次 `poll()` 派发的一个中断 |
| `isr calls` 不是 500 | 中断请求的次数被改过：主循环每 8 次迭代请求一次，共 4000 次迭代 |
| 关闭中断之后忘记开，后面的阶段全都不丢也不加 | `IrqGuard` 的析构没有执行（对象被 `new` 出来没有 `delete`，或者用了 `std::move`） |
| 编译报 `use of deleted function` | `IrqGuard` 与 `CriticalSection` 的拷贝构造被删掉了，按值传参会报这个 | 用引用或直接构造 |
| MSVC 下 `-Wall -Wextra` 变成 `/W4` 之后报未使用变量 | 占位实现里的局部变量没有用上：实现补完即可 |
| 代价表里某一栏明显偏大 | Debug 构建下多了一层函数调用；把三步抄进 `bump` 函数体，或改用 Release |
