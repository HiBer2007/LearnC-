# 配置步骤 · 08-algorithms/03-varargs（不定参数：从 printf 到可变模板）

本模板是**分阶段的整体演练**，也是本板块唯一一个 **C 与 C++ 混编**的模板：
阶段 1 与阶段 2 写 C 侧（`<stdarg.h>` 的 `va_list` 家族），
阶段 3 与阶段 4 写 C++ 侧（可变参数模板与折叠表达式）。
两侧合在一个可执行文件里，正是为了把它们摆在一起对照。

本模板的参考答案不给，判据就是本文件里逐字给出的输出与自查表。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · `va_list` 的类型与步进

**要做什么**（在 `src/varargs.c` 里，`va_sum_ints` 上的 TODO 阶段 1-1）

循环的次数已经给定，`va_start` 与 `va_end` 也已经写好。
留空的只有循环体里的那一步：从 `ap` 里取出下一个参数。

**验收标准**

`Text`

```text
=== Stage 1: the C va_list, type and step ===
sum of 5 ints                   : 15
va_arg calls                    : 5
promotions: A, short 7, z, -3   : [65 7 122 -3]
sum of mixed widths             : 191
va_arg calls                    : 4
```

**判据是两列一起看**：和（15、191）与取参次数（5、4）。
取参次数必须正好等于传进来的参数个数——多取一次会读到列表之外，
少取一次会和就不对。第二组的 191 来自 `65 + 7 + 122 - 3`，
四个实参的宽度各不相同，取的时候却都是 `int`。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 和是 0 | 占位实现还在，一次也没取 |
| `va_arg calls` 停在 0 而和是对的 | 取参那一步写了，取参计数没有加 |
| 取参次数多一次 | `va_start` 里的最后一个具名参数也算了一次；它不参与取出 |
| 和是 120 之类的小数 | 类型写成了 `char`：取出来的只有低 8 位，或者步进不对导致参数全错位 |
| 和每次重跑都变 | 累积变量没有初始化，或者 `ap` 用完之后又用了一次（`va_end` 之后再用是未定义行为） |

> [!CAUTION]
> **`va_arg` 的类型必须与实参提升之后的类型一致。**
> 传 `char`、`short` 要用 `int` 取，传 `float` 要用 `double` 取。
> 类型不一致是未定义行为：它可能碰巧给出对的结果，也可能给出完全无关的数，
> 唯一确定的是**结果不可依赖**。

## 阶段 2 · 自己写一个格式化函数

**要做什么**（TODO 阶段 2-1，`va_format`）

格式串的遍历、`%%` 的处理、输出缓冲与长度保护都已经给出。
三个输出工具（放一个字符、放一串字符、放一个十进制整数）也已给出。
留空的是**按格式符决定取什么类型**那一步。

**验收标准**

`Text`

```text
=== Stage 2: a printf subset of our own ===
fmt n=%d s=%s c=%c pct=%%       : [n=42 s=text c=X pct=%]
written                         : 21
va_arg calls                    : 3
same fmt, buffer of 8           : [n=42 s=]
written (buffer of 8)           : 21
va_arg calls                    : 3
unknown specifier %q            : [a=%q b=7]
written (unknown specifier)     : 8
va_arg calls                    : 1
negative int                    : [-1234]
written (negative int)          : 5
va_arg calls                    : 1
```

四段输出各验一件事：

| 段落 | 验什么 |
|---|---|
| 第一段 | 三种格式符都要取对类型；`%%` 不取参数；取参 3 次 |
| 第二段 | 缓冲只有 8 字节时文本截成 7 个字符加一个结尾符，**`written` 仍是 21** |
| 第三段 | 不认识的 `%q` 原样输出，而且**不取参数**（取参只有 1 次） |
| 第四段 | 负数的十进制转换 |

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 输出里 `n=` 后面是空的 | 占位实现还在，格式符被跳过而参数没取 |
| `written` 是 14 而不是 21 | `%d`、`%s`、`%c` 三处一个字符都没写，只有字面部分被写进去 |
| 第二段的 `written` 变成了 7 | 把返回值写成了「实际写进缓冲的字符数」；它必须是**本来需要写多少** |
| 第三段的取参是 2 次 | 不认识的格式符也去取参数了 |
| 字符串打印到一半就断 | `%s` 的字符串没走「一个字符一个字符放」那条路，越过了 `cap` |
| 输出里出现乱码或程序崩溃 | `%s` 用 `va_arg(ap, char *)` 取到了错误的地址；`%c` 取的是提升之后的类型 |
| 一个格式符之后的所有输出都错位 | 某一种格式符忘了取参数，`ap` 的位置与格式串对不上了 |

> [!TIP]
> **`written` 与「实际写入的字符数」是两件事。** 前者是「本来需要多长」，
> 后者的上限由缓冲大小决定。`snprintf` 返回的正是前者，这样调用方可以先问长度再分配。

## 阶段 3 · 可变参数模板：参数包展开

**要做什么**（在 `include/varargs_cpp.hpp` 里，`sum_all` 上的 TODO 阶段 3-1）

一个参数的版本已经给出，它就是展开到底时的落脚点。
留空的是「两个及以上参数」那一版：把第一个与「剩下那一包」的结果加起来。

**验收标准**

`Text`

```text
=== Stage 3: variadic templates, expanding the pack ===
sum_all(1,2,3,4,5)              : 15
sum_all expansions              : 5
count_args(1,2,3,4,5)           : 5
sum_all(2.5, 3.5)               : 5
sum_all expansions              : 2
sum_init_list{1,2,3,4,5}        : 15
init_list_count{1,2,3,4,5}      : 5
```

**判据**：五个 `int` 的和是 15、展开层数是 5（每展开一层加一，五个参数正好五层）；
两个 `double` 的和是 5——`2.5` 与 `3.5` **各自先转成整数**，再相加，
这是 `sum_all` 的算法决定的，后面的折叠表达式必须与它一致。
`count_args`、`sum_init_list` 与 `init_list_count` 都已经给出，用来对照。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 和是 0、展开层数是 1 | 占位实现还在：落的是一参数那个重载 |
| 编译报 `no matching function` | 交手时把整包传成了 `rest` 而不是展开的形式，或者一参数那个重载被删了 |
| 展开层数比参数个数少一 | 落脚的那一层没有计数；一参数版本里也要加一 |
| 展开层数比参数个数多 | 每一层加了两次 |
| 和是 6 而不是 5 | 先把两个 `double` 加成 `6.0` 再转整数；本模板要求与 `sum_all` 一致，是各自先转 |

## 阶段 4 · 折叠表达式

**要做什么**（TODO 阶段 4-1，`sum_fold`）

阶段 3 那条路要写一个基线的重载。C++17 的折叠表达式把同一件事写成一行。

**验收标准**

`Text`

```text
=== Stage 4: fold expressions ===
sum_fold(1,2,3,4,5)             : 15
sum_fold() empty pack           : 0
sum_fold(2.5, 3.5)              : 5
same as sum_all (ints)          : [yes]
same as sum_all (doubles)       : [yes]
```

**判据有四条**：整数包的和是 15；**空参数包是 0**；
两个 `double` 的结果与 `sum_all` 逐位相同；两行 `same` 都是 `yes`。

`sum_all` 至少要一个参数才能调用，空包调不动；`sum_fold` 空包也有值。
这就是阶段 3 的写法与折叠表达式的第一个差别。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 整数包是 0、空包也是 0 | 占位实现还在 |
| 空包编译不过 | 用的是没有初值的一元折叠；加法的一元折叠在空包上不成立 |
| 整数包是 15 但 `doubles` 那一行是 `no` | 折叠时先把整包加起来再转换；要的是**每个元素先各自转**再相加 |
| 编译报 `fold expression` 相关的错 | 括号写少了：折叠表达式的外层括号不能省 |
| 三处结果都对但编不过 MSVC | 折叠表达式是 C++17 的；工程的 `CMakeLists.txt` 已经设了 `CMAKE_CXX_STANDARD 17` |

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 链接报 `undefined reference to va_sum_ints` | `varargs.h` 的 `extern "C"` 守卫被删了，C 侧与 C++ 侧的名字修饰不一致 |
| 编译 `varargs.c` 时报 `static_cast undeclared` | 这个文件按 **C** 编译，不能用 C++ 的转换写法；用 C 的强制转换 |
| 编译报 `'va_list' has not been declared` | 漏了 `#include <stdarg.h>`；`<cstdarg>` 是 C++ 的头，C 文件里用不了 |
| 运行时取出来的数完全无关 | `va_arg` 的类型与实参提升之后的类型不一致，属于未定义行为 |
| `%s` 打印到一半程序崩溃 | 取出来的不是 `const char *`，或者字符串没有结尾符 |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `core` 与 `app_cli` 加了 `/utf-8` |
