# 配置步骤 · 08-algorithms/13-control（控制：让一个量停在目标上）

本模板是**分阶段的整体演练**：把「让一个量停在目标上」这一件事拆成五个阶段，
每个阶段是一个能单独编译的小工程，前一个阶段是后一个阶段的起点。
阶段 1 搭被控对象、看开环差在哪、写带滞回的开关控制；
阶段 2 补上 PID 三项；阶段 3 把同一个控制器写成定点（Q16.16）并补上两种抗饱和；
阶段 4 做滤波与测速；阶段 5 处理「不该用 PID」的三种场合。

五个阶段共 14 处 TODO，全在各自的 `src/control.cpp` 里；
`include/control.hpp` 与 `src/main_cli.cpp` 都是给定的，不需要改。
**所有噪声都来自固定种子的发生器**：同一个可执行文件重跑多少次，验收输出都逐位相同。
判据能成立，靠的正是这一点。

本模板的参考答案不给，判据就是本文件里逐字给出的输出与自查表。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

**判据**

| 看什么 | 应当是 |
|---|---|
| 三行 `settled output` | 1.0000 / 1.2500 / 0.6250，四位小数逐位对上——命令都是 0.5000，变的是对象真正的增益 |
| `error` 一列 | 0.0000 / -0.2500 / 0.3750，符号是「目标减真值」 |
| 命令 5.0000 那一行 | `after the limit` 是 2.0000，`settled output` 是 4.0000，与增益 2.0000 的那一行算得出来 |
| `switches` 一列 | 1945 / 977 / 284 / 113，滞回越宽切换越少 |
| `tail ripple` 一列 | 0.1083 / 0.1540 / 0.2942 / 0.5850，与滞回宽度同量级地往上走 |
| `duty` 一列 | 四行都在 0.24 到 0.26 之间，接近 `r / (K * u_max)` 也就是 0.25 |

**开环为什么不够，三行就说完**：命令按「模型说需要多少」算出来（`u = r / gain`），
模型对得上时真值正好停在 1.0000；对象真正的增益偏大 20% 时停在 1.2500，偏小 37.5% 时停在 0.6250。
开环没有任何办法知道这件事——它不看输出。

**滞回的取舍**：`switches` 从 1945 降到 113（差 17 倍），代价是 `tail ripple` 从 0.1083 涨到 0.5850。
这两个数是同一个旋钮的两端：滞回越宽，噪声越推不过阈值，切换越少，真值摆得越开。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 三行 `settled output` 都是 0.0000 | 占位实现还在，`Plant::step` 没有推进 |
| 命令 5.0000 那一行的 `settled output` 是 10.0000 | 执行器那一刀没切，命令直接进了对象 |
| `switches` 全是 0 而 `duty` 是 1.0000 | 开关控制没写，命令恒为 u_max |
| 无滞回那行的 `switches` 与有滞回的行差不多 | 两个阈值没有分开，滞回没有生效 |
| `tail ripple` 比滞回宽度小很多 | 阈值的方向写反了，成了「到目标就翻」，不是滞回 |
| `duty` 明显偏离 0.25 | 开关控制给出的两个值不是 0 与 u_max，或者真值根本没走到目标附近 |
| 数字与验收标准不同但形状一致 | 一阶惯性写成了精确离散化（`1 - exp(-dt/tau)`）而不是欧拉法，见下面那条提示 |

> [!TIP]
> **一阶惯性有两种写法，验收表按欧拉法给。** 把「剩余距离的一部分」写成
> `dt / tau` 就是欧拉法；写成 `1 - exp(-dt / tau)` 是精确离散化。
> 两者的稳态值一样（本节的 `settled output` 不受影响），但每一步走过的比例差一点，
> 因此开关控制的切换次数会跟着变。**判据里的关系（滞回越宽切换越少、
> 死区宽度与滞回同量级）两种写法都成立**，具体数字不同时以关系为准。

> [!IMPORTANT]
> **占空比是算得出来的，不是凑出来的。** 稳态下执行器的平均出力必须正好抵消对象的衰减，
> 于是 `K * u_max * duty = r`，解出 `duty = r / (K * u_max) = 1 / 4`。
> 四行都在 0.24 到 0.26 之间，正是这个关系；这一列偏离得多，说明对象或者开关控制有问题。


退出码 0。

**判据**

| 看什么 | 应当是 |
|---|---|
| P 与 PD 的 `final error` | 都是 -0.1111，不为 0；`settle time` 是 -1.0000（到结束都没进过 ±2% 带） |
| PI 与 PID 的 `final error` | 都是 0.0000；`settle time` 是 0.4900 与 0.8000 |
| `overshoot %` | 只在带积分的那两组上非零（2.3625 与 3.4236） |
| 噪声打开那张表的 `u ripple` | 0.1380 / 0.1395 / 0.9893 / 0.9915，带微分项的两组大出七倍 |
| `max |u|` 一列 | 4.0000 或 4.0800，说明第一拍没有微分冲击（有冲击会顶到十几） |

**P 为什么留下 0.1111**：比例项给出的命令是 `kp` 乘误差，误差要是 0 命令就是 0，
而维持住输出恰恰需要一个非零命令。解 `y = K * kp * (r - y)` 得 `r - y = r / (1 + K * kp) = 1 / 9`，
正是 0.1111。积分项的作用就是把这一项消掉，因此 PI 与 PID 的 `final error` 是 0.0000。

**微分项放大噪声**：噪声打开之后，`u ripple` 从 0.1380 跳到 0.9893（PD），
`y ripple` 从 0.0041 跳到 0.0218。微分项求的是变化率，采样周期又只有 10 ms，
测量值上一点点噪声除以 0.01 就变成了命令上的大抖。滤波在阶段 4。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 四行 `final error` 都是 -1.0000 | 占位实现还在，命令恒为 0 |
| 四行 `overshoot %` 都是 0 而 P 的 `final error` 也是 0 | 三项写成了同一个东西，或者误差用了真值而不是测量值 |
| PI 的 `final error` 不是 0 | 积分项没有累加，或者忘了乘采样周期 |
| 四行的 `max |u|` 都顶到十几 | 微分项对误差求了变化率，目标一跳就冒出尖峰；改成就测量值 |
| 噪声打开那张表里四行的 `u ripple` 差不多 | 微分项没起作用（`kd` 没乘进去，或者第一拍之后一直没更新上一拍的测量值） |
| P 的 `settle time` 是正数 | ±2% 带的判据被改过，或者对象被改成了别的参数 |

> [!IMPORTANT]
> **微分项对测量值求变化率，不对误差。** 两者在目标不动时完全一样，
> 目标一跳就不一样了：对误差求变化率会在第一拍冒出一个与跳变量成正比的尖峰，
> 命令的峰值会顶到 `kd / dt` 这个量级（本模板是 10），执行器照着这个尖峰动作一下。
> 验收表里的 `max |u|` 一列就是查这一条的。

> [!TIP]
> **积分项先累加还是先算输出，两种都对。** 差别只在第一拍的命令上：
> 先累加会让第一拍多出 `ki * e * dt`（本模板是 0.08），因此 `max |u|` 是 4.0800 而不是 4.0000。
> 两张表里 PI 与 PID 的 `max |u|` 就是这个数。判据不看这一点。

| 定点那一列全是 0.0000 或差出很多 | 占位实现还在；差出很多时先查积分项有没有乘两次（`ki` 与 `dt`） |
| 定点那一列的数只有整数位 | 中间结果没有放宽就移了位，小数位被移掉了 |
| `integral clamps` 很大 | 累加器一直在贴边，多半是积分项忘了乘 `dt`，每拍加得太多 |
| `clamp` 那一行与 `limit only` 一模一样 | 钳位分支没写；条件应当是「顶出去了，而且误差还在往同一边推」 |
| `clamp` 那一行积分回不来、`settle time` 是 -1 | 条件写成了「只要顶出去就不累加」，误差反向时也不累加，积分就卡住了 |
| `back calculation` 那一行与 `limit only` 一样 | 反算分支没写，或者修正量的符号反了（反了会把积分推得更远） |
| 反算那一行 `settle time` 是 -1 | `tt` 放错了位置（该在分母上），或者用了 `dt` 而不是 `tt` |
| 五档采样周期里 `overshoot %` 不涨反降 | 积分项没有乘 `dt`，采样周期变长时反而加得少了 |

> [!IMPORTANT]
> **定点不是「差不多就行」，是「格式要摆对」。** Q16.16 能表示到 ±32768、
> 分辨率是 1 / 65536；两个 Q16.16 相乘是 Q32.32，必须用 64 位放宽再移回来。
> 摆对了，两列数在四位小数上重合；摆错了，误差不是百分之几，是成倍地偏。

> [!WARNING]
> **累加器要留余量，贴边与回绕是两件不同的事。** `int32` 的 Q16.16 累加器一直加下去，
> 越过 32767 会回绕成负数，控制器会突然往反方向猛推。`kQIntegLimit` 是留出的余量（1024.0），
> 越过就贴边并记一次数；`integral clamps` 正常应当是 0，一旦不是 0 就说明余量不够或者积分项写错了。

| `tc` 是负数 | 距离太短时没有退化成三角形，直接用了 `(dist - 2 * d_acc) / v_max` |
| 梯形的 `move time` 是 -1.0000 | 参考轨迹与真值差得太多，检查三段的时长与位置函数对不对得上 |
| 梯形的 `saturated` 不是 0 | 速度上限或加速度上限定得太高，超出了执行器能给的范围 |

> [!IMPORTANT]
> **前馈是「提前算」，不是「提前看」。** 它用的是事先就知道的参考轨迹与一个模型，
> 因此模型差多少，前馈就漏多少：增益偏 20%，剩下两成误差；反馈再把这两成补掉。
> 这也解释了为什么前馈不能替代反馈——它不会发现对象变了。

> [!TIP]
> **查表补偿的意义不是「更准」，是「一组增益全量程能用」。**
> 不补偿时，小信号上环路增益低（响应慢），大信号上增益高（响应快），
> 同一组增益在不同工作点上表现差十几倍；把执行器折成直线之后，
> 控制器的行为才与线性分析对得上。表是测出来的，真机上没有反函数可算。

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| `cmake -S stage1 ...` 报找不到 `g++` | `<MinGW>` 的 `bin` 不在 `PATH` 里 |
| 用 GNU Make 生成器在中文路径下失败 | 本模板的路径含中文时 `mingw32-make` 不可用，一律用 `-G Ninja` |
| `cmake --build` 报 `Compatibility with CMake < 3.5` | 本模板的工程是 3.16 起，CMake 4.x 不再支持更低的写法 |
| 输出里出现乱码 | 程序只打印 ASCII；乱码来自别处，检查是不是往验收输出里加了中文 |
| `-Wall` 报变量未使用 | 占位实现里那几行 `(void)` 没有随 TODO 一起删掉 |
| `-Wall` 报有符号与无符号比较 | 下标用 `std::size_t`，与 `int` 混用时显式转换 |
| 某一阶段的报告打完但 `--selftest` 一堆 `[FAIL]` | 那是正常的骨架状态，看是哪几项，对照该阶段的「怎么自查」表 |
| 改了 `kSeed` 之后数字全变 | 噪声源是固定种子的，改种子等于换了一道题；判据数字要重新对 |
| 重跑一次数字就变 | 有地方用了不设种子的随机源；本模板的噪声只有 `Noise` 一个来源 |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `core` 与 `app_cli` 加了 `/utf-8` |
| 阶段 3 的定点列与浮点列差出很多 | 先查积分项有没有乘两次（`ki` 与 `dt`），再查中间结果有没有放宽 |
| 程序在中途崩掉 | 多半是写出界：查表的下标、环形缓冲的写位置、编码器的下标都要落在范围内 |

## 完成后可做的延伸

| 题目 | 要练的东西 |
|---|---|
| 把执行器的死区从 0.3000 改成 0.0500，再跑一遍查表那两张表 | 非线性越弱，查表的收益越小，什么时候不值得查 |
| 把滑动平均换成中值滤波，量同一对指标 | 中值对脉冲噪声更有效，滞后与窗口的关系也不同 |
| 给 M/T 法加上「一个窗口里一个脉冲都没有」的处理 | 极低速下的边界情形；这也是实机上要单独判的一段 |
| 把 PID 的输出改成增量式（只算这一拍比上一拍多多少） | 增量式与位置式的差别，以及它对积分饱和的天然免疫 |
| 给梯形规划加一段抛物线过渡（S 形曲线） | 加速度不突变之后，跟踪误差与执行器的抖动怎么变 |
| 把前馈也用到梯形那一节，量跟踪误差 | 前馈加轨迹规划是位置控制的常见组合 |
| 用两个被控对象串联（内环速度、外环位置） | 串级控制，以及内环该比外环快多少 |
| 把 `kSeed` 换成五个值各跑一遍阶段 2 的两张表 | 哪些数是结构量（重跑逐位相同），哪些只是这一次抽样 |
