# 配置步骤 · 08-algorithms/07-search-space（搜索：在状态空间里找路）

本模板是**分阶段的整体演练**：把「在状态空间里找路」拆成四个阶段，
从显式栈的深搜写起，再给广搜补上「一层推完怎么进到下一层」，
然后写 Dijkstra 的松弛，最后写 A* 的开放集选择。四个阶段结束时程序都能构建、能跑出可对照的输出。

四个阶段共用同一张写死的网格地图：四邻接（上下左右），`#` 是墙、`.` 是通路、`S` 起点、`G` 终点。
同一张网格另有一份同样写死的代价图，每格进入的代价是 1 到 9 的固定数字。
地图、代价、邻接次序全部写死在源码里，重跑逐位相同，因此四个阶段的展开顺序可以直接并排比较。

深搜是**已经给出**的，它给出的路径不是最短的：46 步，而广搜只要 18 步。
这一点就是后三个阶段的动机——同样一张图，换一种走法，展开的格子与找到的路径都不一样。
广搜找到的路径步数最少，可是它在带权图上付出的代价是 43；Dijkstra 同样 18 步，代价只有 23。
A* 与 Dijkstra 得到同一条路径，展开的格子却从 70 个降到 20 个。

本模板的参考答案不给，判据就是本文件里逐字给出的输出与自查表。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · 深搜：一条路走到底

**要做什么**（`dfs` 是已经给出的，这个阶段没有留空）

`dfs` 用一个 `std::vector` 当栈：压栈时就把标记立起来，弹出时记进展开顺序。
它给出的路径**不是最短的**：46 步，而广搜只要 18 步。
这一步的产出是三条判据：展开顺序、展开节点数、路径步数与代价。

**验收标准**

```text

    #...##.#..#...#
    #.........#..G#
    ###############

dfs path steps                  : 46
dfs path cost                   : 118

    3,7 3,8 3,9 3,10 3,11 3,12 3,13 4,13
    5,13 5,12 5,11 6,11 7,11 7,12 7,13
dfs path on map:
    ###############
    #S*.****......#
```

**判据是三列**：`dfs expanded` 是 47、`dfs path steps` 是 46、`dfs path cost` 是 118。
展开 47 个格子只走了 46 步，说明它一路沿着一条长链绕了大半张图；
`bfs path steps` 的 18 才是这张图上最短的步数。

`Text`

```text
walkable cells                  : 75
```

可走的格子一共 75 个，深搜展开 47 个就撞上了终点。
剩下那 28 个格子它一个都没碰过，而广搜与 Dijkstra 都得把它们翻一遍——
**这正是「走法不同，展开的格子不同」的由来**，
四种走法的展开节点数（47、75、70、20）两两不同，就是照这一点调出来的。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `dfs expanded` 是 75 | 访问标记立在了出栈处，同一个格子被压进栈很多次 |
| `dfs path steps` 是 18 | 栈写成了队列：深搜退化成广搜，路径当然是最短的 |
| `dfs path on map` 里的折线断成几截 | 路径是按前驱串起来的；断掉说明前驱记在了发现处之外的地方 |
| 路径里有格子重复出现 | 前驱被后发现的格子覆盖了；压栈时立标记就不会出现 |
| 程序在 `dfs` 里死循环 | 压栈时没有立标记，两个相邻的格子互相把对方压回去 |

> [!IMPORTANT]
> **深搜没有「最短」这个概念。** 它只保证「有路就一定能走到」，
> 走出来的那条路是什么形状，取决于邻居的压栈次序。
> 本模板把邻居次序写死在 `neighbors_of` 里（上、右、下、左），
> 压栈的次序与执行次序相反，因此第一次走的是「左」——这一段见下面的 `dfs order` 前几项。

## 阶段 2 · 广搜的层推进

**要做什么**（在 `src/pathfind.cpp` 里，TODO 阶段 2-1，`bfs`）

队列、访问标记、前驱数组都已经给出；「当前这一层还剩几个没有出队」与
「下一层已经入队了几个」这两个计数器也已经给出，并在该减、该加的地方减过加过了。
留空的是**一层推完怎么进到下一层**：什么时候把「下一层」的数字交出去当作新一层的规模。

**验收标准**

`Text`

```text

bfs expanded                    : 75
bfs levels                      : 19
bfs level total                 : 75
bfs level sizes                 : 1 1 2 3 4 5 4 7 6 7 6 6 6 5 3 3 3 2 1
bfs path steps                  : 18
bfs path cost                   : 43
bfs order (r,c) (75):
    1,1 1,2 1,3 2,2 1,4 2,3 3,2 1,5
    2,4 3,3 3,1 1,6 2,5 3,4 4,3 4,1
    1,7 3,5 5,3 5,1 1,8 2,7 3,6 4,5
    6,3 5,2 6,1 1,9 3,7 5,5 7,3 6,2
    7,1 1,10 2,9 3,8 4,7 5,6 7,4 7,2
    1,11 2,10 3,9 5,7 6,6 7,5 1,12 2,11
    3,10 4,9 5,8 7,6 1,13 2,12 3,11 5,9
    6,8 7,7 2,13 3,12 5,10 6,9 7,8 3,13
    5,11 7,9 4,13 5,12 6,11 5,13 6,12 7,11
    6,13 7,12 7,13
bfs path (r,c) (18 steps):
    1,1 1,2 1,3 1,4 1,5 1,6 1,7 1,8
    1,9 1,10 1,11 1,12 1,13 2,13 3,13 4,13
    5,13 6,13 7,13
bfs path on map:
    ###############
    #S************#
    ##....#.#....*#
    #............*#
    #.#.#.#.#.###*#
    #...#........*#
    #...##.#..#..*#
    #.........#..G#
    ###############
```

**判据是一串层规模**：`1 1 2 3 4 5 4 7 6 7 6 6 6 5 3 3 3 2 1`，一共 19 层，加起来 75。
第 0 层是起点自己；第 1 层只有 1 个，因为起点的上、下、左三面都是墙，只剩右边一个出口；
最后一层也只有 1 个，就是终点。`bfs level total` 是把这一串加起来得到的数，
它必须等于 `walkable cells`（75）：广搜把整张图翻了一遍。

| 怎么看这一串 | 说明 |
|---|---|
| `bfs levels` 是 1 | 占位实现还在，层推进那一段没写 |
| 和是 74 而不是 75 | 有一格没进过队；终点在最深一层，正常情况应当一格不漏 |
| 某一层是 0 | 计数清零的时机错了：本层最后一个节点的邻居被记到了下一层 |
| 层数比 19 多、每层都偏小 | 层推进写在了扩展之前，邻居被算进了再下一层 |
| `bfs path steps` 不是 18 | 访问标记立在了出队处，同一个格子被更晚的一次发现改了前驱 |

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `bfs levels` 是 1、`bfs level sizes` 是 `1` | 占位实现还在 |
| `bfs level total` 是 75 但层规模对不上 | 数对了个数，分配错了层 |
| `bfs expanded` 比 75 小很多 | 队列按后进先出用了，退化成深搜 |
| `bfs path cost` 不是 43 | 路径不是那条沿着上边界走到右上角再下来的那条，看 `bfs path on map` 即可 |

> [!IMPORTANT]
> **这一层一层的数字就是「步数」这个概念的形状。**
> 广搜在第 `k` 层展开的格子，步数恰好是 `k`；层规模单拿出来看，
> 就是把地图按「离起点几步」切成了一圈一圈。
> 阶段 3 的 Dijkstra 也分层，只不过它切的是**代价**而不是步数——两张图的分层不一样，
> 这就是同样一张图上两种走法展开的格子不同的原因。

## 阶段 3 · Dijkstra 的松弛

**要做什么**（TODO 阶段 3-1，`dijkstra`）

小根堆、距离数组、前驱数组都已经给出：堆里放的是「距离，行优先下标」，
并列时按下标定次序。堆顶那一项就是下一个要展开的格子，
过时的旧条目已经在给出的一段里丢掉了。留空的是**松弛那一步**：
站在当前格子上，把四个邻居各算一遍「绕经这里走过去」的总代价，与记录比一比。

**判据是四列结构量加一段对照**：

| 数 | 值 | 它是什么 |
|---|---|---|
| `dijkstra relax ok` | 72 | 松弛成功的次数：新算出来的总代价比记录小，更新并入堆 |
| `dijkstra relax dropped` | 126 | 抛弃的次数：新算出来的总代价不小于记录，什么都不改 |
| `dijkstra expanded` | 70 | 真正展开的格子数 |
| `dijkstra pops from open` | 70 | 从堆里弹出的总次数，含过时的旧条目 |
| `dijkstra path cost` | 23 | 最小代价 |

弹出的次数与展开的格子数相等，说明这一次运行里堆中没有出现过时的旧条目。
本模板的代价只取决于「进入哪一格」，而 Dijkstra 的弹出是按距离递增的，
因此先给某一格写下的记录就是它最终的最小距离，后来不会再有更小的数把它推翻。

`dijkstra dist grid` 那一块是「各点最短距离」的序列，按行优先读：
起点是 0，右上角那一片是 15 到 22，右下角的终点是 23。
`..` 是始终没有走到的格子，最下面两行各有一格，
它们的代价要绕很远，在终点被取出来之前没轮到。

**并排对照**：广搜与 Dijkstra 走的步数一样，都是 18，
可是广搜那条沿着上边界走的路要付 43 点代价，Dijkstra 只付 23。
广搜看不见代价——它的模型里没有代价这一项，它只知道「多少步」。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `dijkstra expanded` 是 1、`relax ok` 是 0 | 占位实现还在，起点之后再没有格子进堆 |
| `dijkstra path steps` 是 0 | 终点没进过堆，路径是空的 |
| 两个计数器一加不是 198 | 每个邻居都要落到其中一个分支上；总数不对说明有分支没记 |
| 程序在 `dijkstra` 里不结束 | 比较写成了「不大于」：距离相等时也会重新入堆，堆一直长 |
| `relax ok` 大得离谱 | 没有比较，每次检查邻居都入堆 |
| `dijkstra path cost` 是 24 | 起点那一格的代价被算进去了；路径代价不含起点 |
| `dist grid` 里有负号 | `-1` 是「还没到过」的标记，被当成距离打印或参与比较了 |
| 弹出顺序每次都不一样 | 比较器的并列打破方式被改了：本模板是「距离相同按下标」 |

> [!TIP]
> **想看清 Dijkstra 与广搜的差别，看两串展开顺序的前几项最快。**
> 广搜的前几项是 `1,1 1,2 1,3 2,2 1,4`，按离起点的步数一层层来；
> Dijkstra 的前几项是 `1,1 1,2 1,3 2,2 2,3 1,4 2,4`，按已经付出的代价来。
> 两串从第 5 项起就分岔，展开的格子数也就跟着不同（75 与 70）。

**三条判据并排**：

|---|---|---|
| 展开的格子更少 | 20 对 70 | 估价把搜索压向终点，省下 50 个格子 |
| 代价不被破坏 | 23 对 23 | 终点第一次被取出来就是最小代价 |
| 估价取 0 时退化 | 70 对 70，顺序逐项相同 | `astar(h=0)` 与 Dijkstra 完全重合 |

`astar(h=1) order` 只有 20 项，全在上半张图里排成一串向右的折线：
估价让搜索不去翻右下角那些「代价小但离终点远」的格子。
`astar(h=0) vs dijkstra, order` 是 `yes`，这一栏比较的是两串坐标逐项相同——
不是步数相同，也不是代价相同。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `astar(h=1) expanded` 是 0 | 占位实现还在，开放集一次也没取 |
| `astar(h=1) expanded` 与 70 相同 | 估价没算进 `f`，或者 `use_h` 没有传下去 |
| `astar(h=1) path cost` 大于 23 | 估价高估了。本模板的估价是曼哈顿距离，四邻接、每格代价至少是 1，因此不高估 |
| `astar(h=0) vs dijkstra, order` 是 `no` | 关掉估价时应当逐项重合；不重合说明更新条件或并列打破方式与 Dijkstra 不一致 |
| `pops` 比 `expanded` 大 | 堆里有作废的旧账被丢掉了，差值就是丢掉了几条；这是正常的 |
| 程序在 `astar` 里不结束 | 作废的旧账没有丢掉，堆一直长；或者更新条件写成了「不大于」 |

> [!IMPORTANT]
> **可采纳是 A* 最优性的全部依据。**
> 曼哈顿距离数的是「还差几步」，而每走一步至少付 1 点代价，
> 因此它永远不会高估剩下的代价——这就是四邻接加「每格代价至少 1」这两条前提的作用。
> 把地图改成八邻接而估价还留曼哈顿距离，斜走一步的曼哈顿距离是 2、实际只算一步，
> 估价立刻变成高估，最优性不再有保证。

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'bfs' was not declared in this scope` | `pathfind.hpp` 里的 `namespace pf` 没有对上，或者 `main_cli.cpp` 被改动过 |
| `-Wall` 报 `set but not used` | 占位实现里那两行 `(void)` 没有随 TODO 一起删掉 |
| `-Wall` 报 `unused variable 'v'` | 阶段 3 的 `(void)v;` 留在了填好的松弛代码里 |
| 坐标序列每次运行都不一样 | 本模板没有随机数、没有时间种子；出现这种情况说明 `neighbors_of` 里的邻居次序被改了 |
| 地图或代价改过之后判据全不对 | 地图与代价写死在 `src/pathfind.cpp` 顶部；改动它们等于换了一道题，判据要重新跑 |
| `dijkstra dist grid` 与验收标准错位一格 | 下标是按行优先算的（`r * 15 + c`），行列写反了 |
| 程序跑很久不结束 | 见各阶段自查表里「不结束」那一行：多半是把 `<` 写成了 `<=` |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `core` 与 `app_cli` 加了 `/utf-8` |
