# 配置步骤 · 08-algorithms/11-scan-state-machine（扫描与状态机）

本模板是**分阶段的整体演练**：把「一次遍历、边走边记住自己处在哪个状态」
这一件事拆成四个阶段。先在一遍扫描里把行列号算对，再用 `switch` 写一台
玩具状态机，然后把同一台机器改成状态表驱动，最后用状态机剥掉一段 JSONC
里的注释。四个阶段结束时程序都能构建、能跑出可对照的输出。

本模板的参考答案不给，判据就是本文件里逐字给出的输出与自查表。
怎么复制模板、怎么打开、遇到问题查哪里，见 [`../../README.md`](../../README.md)，本文件不重复。

## 阶段 1 · 一遍扫描：行列号怎么累加

**要做什么**（在 `src/scanner.cpp` 里，`scan_lines` 上的 TODO 阶段 1-1，两处分支）

`scan_lines` 只走一遍输入。每到一个字符，先看它是不是偏移表里点名的位置，
是就把当前的 (行, 列) 记下来，然后读掉这个字符。已经给出的部分是遍历、
记录与收尾；缺的两句在 `if (c == '\n')` 的两个分支里：读掉当前字符之后，
光标挪到哪里去。

位置记号记的是「停在这个字符上」时的坐标，因此第 1 个字符是第 1 行第 1 列。
偏移取到 `text.size()` 时，记的是最后一个字符之后的那一个位置——它在输入
之外，但仍然是一个有效的位置。

**验收标准**

`Text`

```text
=== Stage 1: one pass, line and column ===
input lines                     : 9
input chars                     : 235
offset of first newline         : 1
offset of "https"               : 46
offset of the escaped quote     : 82
offset of the block comment     : 91
offset of the last character    : 234
offset one past the last        : 235
scan chars                      : 235
scan lines                      : 9
scan newlines                   : 8
scan tabs                       : 0
scan max col                    : 50
mark 0                          : (1, 1)
mark 1                          : (1, 2)
mark 46                         : (3, 11)
mark 82                         : (4, 15)
mark 91                         : (5, 3)
mark 234                        : (9, 1)
mark 235                        : (9, 2)
```

**判据落在五个结构量与七个位置上**。

| 数 | 值 | 它说明什么 |
|---|---|---|
| `input lines` 与 `scan lines` | 都是 9 | 输入确实是 9 行，扫完停在第 9 行 |
| `input chars` 与 `scan chars` | 都是 235 | 每个字符恰好走过一次 |
| `scan newlines` | 8 | 9 行之间有 8 个换行符，输入末尾没有换行 |
| `scan tabs` | 0 | 这段输入里没有制表符 |
| `scan max col` | 50 | 最长的那一行（第 6 行）有 49 个字符，停在第 50 列 |

七个位置里有两处最能说明问题：

| 位置 | 值 | 为什么单看它 |
|---|---|---|
| `mark 1` | `(1, 2)` | 偏移 1 就是第 1 行末尾那个换行符。它自己还在第 1 行，所以行号不加；如果这一行变成 `(2, 1)`，说明换行符被提前挪到了下一行 |
| `mark 91` | `(5, 3)` | 第 5 行的第 3 列是块注释开头那两个字符的位置。列号从 1 起数，前两个是行首的空格 |
| `mark 235` | `(9, 2)` | 偏移等于输入长度，落在最后一个字符之后。`mark 234` 是 `}`、`(9, 1)`，多走一格正好是 `(9, 2)` |

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| 七行 `mark` 全是 `(1, 1)` | 两个分支一句也没写，光标从头到尾没有动 |
| `scan lines` 是 1 | 行号没有加过 |
| `scan lines` 是 10 | 输入最后一个字符是 `}` 而不是换行；多出来的一行说明把「末尾之后」当成了一整行 |
| `scan max col` 是 235 | 列号一直在加，换行时没有回到 1 |
| `mark 1` 是 `(2, 1)` | 换行符先被挪到了下一行；记号记的是停在这个字符上的位置 |
| `mark 46` 的列号不是 11 | 列号在换行之后没有清零，一路累加到下一行 |
| `mark 235` 取不到值或崩溃 | `offsets` 里最后一个偏移等于输入长度，收尾那一段要负责把它填上 |

> [!TIP]
> 想确认自己的规则是不是自洽，把 `mark 235` 与 `mark 234` 一起看：
> 两个位置的行号相同、列号差一，这条关系在任何一段输入上都成立。

## 阶段 2 · switch 版状态机：十二个格子

**要做什么**（TODO 阶段 2-1，`step_switch`）

这台玩具机器认的是「由减号、数字、小数点拼出来的一个数」，一共三个状态：

| 状态 | 含义 | 能不能在这里收尾 |
|---|---|---|
| `S0` | 什么都还没读到，也在等一个开头的减号 | 不能 |
| `S1` | 整数部分已经读到 | 能 |
| `S2` | 小数点已经读到 | 要等后面再跟一个数字 |

已经给出的是状态的枚举、字符分类、状态的短名字、接受与否的判断，
以及一套驱动程序：它从左往右读，每一步调用一次 `step_switch`，
把 (下标, 字符, 状态) 记下来；某一步走不通就停下。缺的是转移本身——
十二个格子里，每个格子填「下一个状态」，走不通的格子要让函数返回假。

**验收标准**

`Text`

```text
=== Stage 2: the same machine, written with switch ===
--- input: -12.5
accepted                        : yes
consumed                        : 5
accepted prefix length          : 5
states                          : S0 S1 S1 S2 S2
steps:
  [0] '-' -> S0
  [1] '1' -> S1
  [2] '2' -> S1
  [3] '.' -> S2
  [4] '5' -> S2
--- input: 12
accepted                        : yes
consumed                        : 2
accepted prefix length          : 2
states                          : S1 S1
--- input: -
accepted                        : no
consumed                        : 1
accepted prefix length          : 0
states                          : S0
--- input: 1.
accepted                        : no
consumed                        : 2
accepted prefix length          : 1
states                          : S1 S2
--- input: 1.2.3
accepted                        : no
consumed                        : 3
accepted prefix length          : 3
states                          : S1 S2 S2
--- input: 12abc
accepted                        : no
consumed                        : 2
accepted prefix length          : 2
states                          : S1 S1
--- input: .5
accepted                        : no
consumed                        : 0
accepted prefix length          : 0
states                          : (none)
```

**判据是七个输入各自的一整组行**。同一个输入的四行要一起看：
`states` 给出每一步停在哪，`consumed` 给出读进去了几个字符，
`accepted prefix length` 给出最长的那一段「可以在这里收尾」的前缀，
`accepted` 要求整段输入都被读完而且停得住。

| 输入 | 状态序列 | consumed | 最长前缀 | accepted | 这一段说明什么 |
|---|---|---|---|---|---|
| `-12.5` | S0 S1 S1 S2 S2 | 5 | 5 | yes | 减号留在 S0，读到数字进 S1，小数点进 S2，小数位把 S2 继续走下去 |
| `12` | S1 S1 | 2 | 2 | yes | 没有小数点也可以收尾 |
| `-` | S0 | 1 | 0 | no | 只有减号。停在 S0，而 S0 不是能收尾的状态 |
| `1.` | S1 S2 | 2 | 1 | no | 读完了整段，停在 S2，可它后面没有再跟数字，因此不算一个数；最长前缀是开头那个 `1` |
| `1.2.3` | S1 S2 S2 | 3 | 3 | no | 第二个小数点走不通，机器停在那里；手里握着的是 `1.2` |
| `12abc` | S1 S1 | 2 | 2 | no | `a` 走不通，前缀是 `12` |
| `.5` | （没有） | 0 | 0 | no | 第一步就走不通，一个字符也没读进去 |

`states` 那一行是这套判据里最硬的一条：它把每一步都摆出来，
少一步、多一步、停错一个状态都看得见。

> [!WARNING]
> **这台机器只有三个状态，负号与起点合并在 `S0` 里**，`S0` 读到减号仍然回到 `S0`。
> 因此 `--1` 也会被它接受。这是三个状态能表达的语言的边界，不是实现写错了；
> 要拒掉它就得再添一个「负号已读」的状态，见本文件末尾的延伸题。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `states` 全是 `(none)`、`consumed` 全是 0 | 占位实现还在，函数永远返回假 |
| 只有 `12` 一行的 `accepted` 是 `yes` | 小数点的那个格子没填，S1 读到 `.` 时走不通 |
| `1.` 的 `accepted` 是 `yes` | 把 `S2` 整格当成了可收尾的状态；`S2` 还要看后面有没有跟数字 |
| `1.2.3` 的 `accepted prefix length` 是 5 | `S2` 读到小数点时没有返回假，两个小数点被连了起来 |
| `-12.5` 的状态序列是 `S1 S1 S1 S2 S2` | 减号那一格填成了 `S1`；减号只表示「还没读到数字」 |
| `12abc` 的 `consumed` 是 5 | 走不通的格子填了一个状态而不是返回假，机器把走不通的字符也吃掉了 |

> [!TIP]
> 先把七个输入的 `consumed` 对上，再看 `states`。`consumed` 只说明机器在哪里停下，
> 错了容易定位到某一个格子；`states` 全对，十二个格子才算填完。

## 阶段 3 · 表驱动：同一台机器，换一种写法

**要做什么**（TODO 阶段 3-1，状态表 `kTable`）

同一台机器换一种写法：把「当前状态 × 字符类 → 下一个状态」写成一张
3 行 4 列的二维表，查表的那一步由已经给出的 `step_table` 完成。
列的顺序与 `CharClass` 的枚举一致：`Minus`、`Digit`、`Dot`、`Other`。
格子里填状态的编号，走不通的格子填 `kDead`。

**表是数据，`step_table` 是驱动**：驱动只做一次查表，怎么走全看表里填了什么。
因此这一阶段的产物是一张表，不是一段分支；`step_table` 一个字也不用改。

**验收标准**

`Text`

```text
=== Stage 3: the same machine, driven by a table ===
table states                    : 3
table classes                   : 4
table cells                     : 12
table dead cells                : 7
--- input: -12.5
accepted                        : yes
consumed                        : 5
accepted prefix length          : 5
states                          : S0 S1 S1 S2 S2
same as the switch version      : yes
--- input: 12
accepted                        : yes
consumed                        : 2
accepted prefix length          : 2
states                          : S1 S1
same as the switch version      : yes
--- input: -
accepted                        : no
consumed                        : 1
accepted prefix length          : 0
states                          : S0
same as the switch version      : yes
--- input: 1.
accepted                        : no
consumed                        : 2
accepted prefix length          : 1
states                          : S1 S2
same as the switch version      : yes
--- input: 1.2.3
accepted                        : no
consumed                        : 3
accepted prefix length          : 3
states                          : S1 S2 S2
same as the switch version      : yes
--- input: 12abc
accepted                        : no
consumed                        : 2
accepted prefix length          : 2
states                          : S1 S1
same as the switch version      : yes
--- input: .5
accepted                        : no
consumed                        : 0
accepted prefix length          : 0
states                          : (none)
same as the switch version      : yes
all inputs identical            : yes
```

**判据分两层**。

第一层是表的形状，四个数：

| 数 | 值 | 它说明什么 |
|---|---|---|
| `table states` | 3 | 三个状态 |
| `table classes` | 4 | 四类字符 |
| `table cells` | 12 | 一共十二个格子 |
| `table dead cells` | 7 | 其中走不通的有七个，走得通的五个 |

第二层是逐位相同的比对：每个输入后面那一行 `same as the switch version`，
以及最后一行 `all inputs identical`。`same_states` 是已经给出的，
它连长度带每一步的 (下标, 字符, 状态) 都比较，不只看结论：

| 对不上的地方 | `same as the switch version` |
|---|---|
| 状态序列某一步不同 | `no` |
| 停下的位置不同（`consumed` 不一样） | `no` |
| 最长前缀不同 | `no` |
| 只有某一行的 `accepted` 不同 | `no` |

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `table dead cells` 是 0 | 一个 `kDead` 也没填，每个字符都走得通 |
| 所有 `states` 都是 `S0 S0 ...` | 表整表还是 0（占位实现），每个字符都留在起点 |
| 某一个输入是 `no`，别的都是 `yes` | 表里至少有一个格子与阶段 2 的分支不一样；按这个输入的状态序列定位是哪一格 |
| `table cells` 不是 12 | 表的行列数写错了，应当是 3 行 4 列 |
| 编译报 `kTable` 未定义 | 表的名字被改了，`step_table` 与两个结构量函数都按这个名字找它 |
| `all inputs identical` 是 `yes` 但 `table dead cells` 不是 7 | 表能走通的路与阶段 2 相同，但多填了几个永远不会走到的格子；走不到的格子也算表的一部分，照样要对上 |

## 阶段 4 · 剥掉 JSONC 的注释

**要做什么**（TODO 阶段 4-1，`strip_json_comments`）

朴素做法已经给出：见到两个斜杠就删到行尾，见到块注释的开头就删到结尾，
完全不看自己站在哪儿。它会把 `"https://example.com"` 截成 `"https:`。
阶段 4 把它换成状态机，循环体整段要自己写。这一阶段的规则取自一份真实工程里的
写法，素材副本见《A-教学素材/04-语法/递归与状态机/parser_json.cpp》
（GPL-3.0，原样保留版权头）；本模板按它的做法另写了一段保长替换的版本，
没有把它的源码复制过来。

规则的要点是三条：

| 处境 | 怎么走 |
|---|---|
| 在字符串里 | 字符照抄；反斜杠把紧跟其后的那一个字符一起吃掉（它可能是结束引号，也可能是另一个反斜杠）；此外只有那个开头的引号能结束字符串 |
| 在块注释里 | 字符换成空格，换行符原样留下；遇到 `*` 与 `/` 连着出现时，这两个字符也换成空格并退出注释 |
| 两处都不在 | 引号打开字符串；斜杠要往后多看一个字符才能定下来；行注释到行尾为止，块注释可以跨行 |

**注释里的每个字符都在输出里占掉同样多的位置**，因此输出与输入一样长，
行列号不会因为剥注释而错位。已经给出的 `out.reserve(in.size())` 正是按这条
写的：长度上界已知，一次分配就够。

**验收标准**

`Text`

```text
=== Stage 4: stripping JSON comments ===
input lines                     : 9
input chars                     : 235
output chars                    : 235
lengths equal                   : yes
chars that differ from input    : 89
occurrences of "//" in output   : 1
same as expected text           : yes
output (' *' marks a line that differs from the expected one):
  1|{|
  2|                                 |
  3|  "url": "https://example.com",|
  4|  "escaped": "a\"b",|
  5|                                    |
  6|                                                 |
  7|  "path": "C:\\tmp\\log",|
  8|  "note": "/* not a comment */"|
  9|}|
naive chars                     : 88
occurrences of "//" in naive    : 0
naive same as expected text     : no
naive output (' *' marks a line that differs from the expected one):
  1|{|
  2|  | *
  3|  "url": "https:| *
  4|  "escaped": "a\"b",|
  5|   | *
  6|  "path": "C:\\tmp\\log",| *
  7|  "note": " "| *
  8|}| *
--- tail input: one backslash at the very end ---
tail input chars                : 3
tail input escaped              : \"a\\
tail output chars               : 3
tail output escaped             : \"a\\
tail lengths equal              : yes
tail output same as input       : yes
```

**判据有六条，逐条都能独立对**。

| 数 | 值 | 它说明什么 |
|---|---|---|
| `same as expected text` | `yes` | 输出与参考文本逐字节相同。参考文本写在 `src/main_cli.cpp` 的 `kExpectedLines` 里，与输入一行对一行 |
| `input chars` 与 `output chars` | 都是 235 | 等长替换：注释换空格，长度不变 |
| `lengths equal` | `yes` | 同上，单独成行以便一眼看到 |
| `chars that differ from input` | 89 | 只有注释所在的位置变了，其余 146 个位置原样不动 |
| `occurrences of "//" in output` | 1 | 剩下的那一处正是网址里的两个斜杠；注释里的两处已经被换成空格 |
| `naive same as expected text` | `no` | 朴素做法给出的东西不是这个结果 |

三条边界的验法：

| 边界 | 怎么验 |
|---|---|
| `"a\"b"` 里的引号不结束字符串 | 输出第 4 行整行与输入第 4 行逐字节相同；反斜杠没有被当成转义之外的东西 |
| 字符串里的 `/* ... */` 不算注释 | 输出第 8 行原样保留；上面那张表里 `chars that differ from input` 是 89，第 8 行不在变化之列 |
| 跨行的块注释不破坏行结构 | 输出第 5、6 行各自是一行空格，行数与输入一样是 9 行；`naive` 那边只剩 8 行 |

朴素做法的输出单独打印出来作对照，三处差别都看得见：

| 行 | 朴素做法的输出 | 原因 |
|---|---|---|
| 第 3 行 | `  "url": "https:` | 它把网址里的两个斜杠当成了注释的开头，一路删到行尾 |
| 第 5 行 | 只剩一个空格 | 块注释跨了两行，被整段压成了一个空格，行结构随之破坏 |
| 第 8 行 | `  "note": " "` | 写在字符串里的注释开头它也照删 |

**越界保护怎么验**（这一段单独打印）

| 数 | 值 |
|---|---|
| `tail input chars` | 3 |
| `tail input escaped` | `\"a\\` |
| `tail output chars` | 3 |
| `tail output same as input` | `yes` |

这段输入是三个字符：一个引号、一个 `a`、一个反斜杠。走到最后一个字符时
`i + 1` 已经等于输入长度，后面没有字符可取。保护写在条件里——`i` 已经是
最后一个下标时就不进「把后一个字符一起吃掉」的那一支。少了这一句，
`in[i + 1]`（或者先自增再取）读到的是 `size()` 那一格：对 `std::string` 来说
这一格是可读的，返回的是末尾的空字符，见
《07-标准库/B-02-std-string 与 string_view.md》第 5.1 小节。

因此少写这一句不会让程序崩掉，而是**静悄悄地多出一个字节**：
`tail output chars` 会从 3 变成 4，`tail output escaped` 会多出一个 `\x00`，
`tail output same as input` 变成 `no`。这个模板只用普通构建，
不依赖任何检查工具，判断依据就是这三行。

**怎么自查**

| 你看到的 | 说明 |
|---|---|
| `same as expected text` 是 `no`，带 ` *` 的行停在三处注释上 | 循环体还是占位实现，注释一个也没剥 |
| 带 ` *` 的行停在第 3 行 | 字符串判断写在注释判断之后，网址里的 `//` 被当成了注释 |
| 输出第 5、6 行合成了一行 | 块注释里的换行符被一起换成了空格；换行符要原样留下 |
| `output chars` 比 `input chars` 小 | 注释被删掉了而不是换成了空格；等长替换是这一阶段的硬约束 |
| `occurrences of "//" in output` 是 0 | 连网址里的那两个斜杠也被吃掉了 |
| `output chars` 比 `input chars` 大 1 | 转义处理读了结尾之后那一格，多出一个字节 |
| 输出第 8 行变成 `  "note": " "` | 只按字符判断，没有看自己在不在字符串里 |

> [!CAUTION]
> **`out[i + 1]` 在 `i + 1` 等于长度时读到的是结尾那一格，不是数据。**
> 对 `std::string` 来说这一格恰好可读（是末尾的空字符），程序不会崩，
> 因此这类错误不会被运行时报出来，只会让输出悄悄多一个字节。
> 判断「后面还有没有字符」的那一句不能省。

## 常见错误与排查

| 现象 | 原因与做法 |
|---|---|
| 编译报 `'scan_lines' was not declared in this scope` | `scanner.hpp` 里的 `namespace scan` 没有对上，或者 `main_cli.cpp` 被改动过 |
| 阶段 1 的七个 `mark` 全是 `(1, 1)` | 阶段 1-1 的两处分支还空着 |
| 阶段 3 的 `states` 全是 `S0` | `kTable` 整表还是 0，占位实现没有替换 |
| 阶段 4 的 `same as expected text` 是 `no` 而 `lengths equal` 是 `yes` | 长度对不代表内容对：带 ` *` 的行会指出差在哪一行 |
| 输出某一行比预期短一大截 | 字符串判断写在了注释判断之后，字符串里的斜杠被当成了注释开头 |
| 输出的行数比输入少 | 块注释里的换行符被一起吃掉了；换行符要原样留下 |
| `tail output chars` 是 4 | 转义处理没有问「后面还有没有字符」 |
| 同一份源码重跑数字不同 | 本模板四个阶段全是确定性的，输入写死在源码里，出现这种情况说明 `main_cli.cpp` 被改动过 |
| `-Wall` 报 `unused parameter` | 占位实现里带 `(void)` 的那几行没有随 TODO 一起删掉 |
| MSVC 下中文注释导致 `C4819` | 工程的 `CMakeLists.txt` 已经给 `core` 与 `app_cli` 加了 `/utf-8` |
