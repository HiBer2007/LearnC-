# 搜索算法交互演示

48×32 的方格地图上，把广度优先、深度优先、Dijkstra、A*、贪心最佳优先五种搜索
一步一步跑出来看：谁先展开、谁展开得多、代价算得对不对、路径长什么样。

界面进程只管画，算法在另一个进程里跑；每一步的状态通过共享内存交给界面，
因此「不限速」这一档能真的把算法跑到每秒几十万步，而界面仍按约 60 帧每秒刷新。

框架部分（两个进程怎么分工、共享内存怎么排、主题与署名怎么做）见
《演示工具/README.md》。本章节只讲搜索演示自己的东西。

## 怎么跑

`PowerShell`

```powershell
.\SearchDemo.exe                    # 打开窗口（界面进程会自己拉起运算进程）
.\SearchDemo.exe --theme dark       # 指定主题：light / dark / auto
.\SearchDemo.exe --selftest         # 无窗口自测，输出固定格式的结果
.\SearchDemo.exe --palettecheck     # 无窗口查配色：逐控件算对比度，低于 4.5:1 非零退出
.\SearchDemo.exe --trace            # 诊断日志写到 %TEMP%\visualcore_trace.log
.\SearchDemo.exe --worker --port=…  # 运算进程身份，由界面进程拉起，不必手敲
```

`--selftest` 不开窗口、不起子进程、不读注册表，输出与界面无关，可以直接对比。
`--palettecheck` 只创建窗体对象、不显示窗口，两种主题各遍历一遍控件，
按对比度判配色是否合格，详见《演示工具/README.md》的「主题与配色」一节。

## 界面怎么用

### 画布

| 元素 | 含义 |
|---|---|
| 白色（浅色）/ 深灰（深色） | 空地，代价 1 |
| 米黄（浅色）/ 深褐（深色） | 地形，代价 2 到 9，格子上写着代价数字 |
| 近黑的纯色块 | 墙，不可通行，也不写数字（**没有纹理，也没有边框**） |
| 绿色 | 起点 |
| 红色 | 终点 |
| 浅黄 | 待访问，在 open 表里 |
| 蓝色 | 已访问，展开过了 |
| 亮橙色 | 当前正在展开的节点 |
| 紫色 + 折线 | 最终路径 |

**状态只用填充色区分**（作者 2026-10-02 的决定）：不加叉、角点、三角、圆、
加粗边框、斜纹这些形状或纹理线索；**只有最终路径用折线画出来**。
色值、折线与各底色的对比度见《演示工具/README.md》的「主题与配色」一节。

格子边长 **20 像素**；格上的数字用 **11 像素 Consolas 粗体**写。
**字号只有这一个**，不为塞下长数字换小号字；空间从标注内容里省：
代价以千分之一为单位，显示时四舍五入到整数（`123.4` 写成 `123`），
一千以上写成 `1k+`，因此**任何标注都不超过三个字符**。

`实测数据`
`Text`

```text
格子边长：最初 20 像素 → 放大过一版 26 像素 → 现在退回 20 像素
格上字号：最初 7 像素（四位数时）与 8 像素 → 放大到 9 与 10 → 现在统一 11 像素粗体
字符宽度：11 像素 Consolas 每字符 6 像素，三个字符 18 像素，格子 20 像素放得下
```

### 路径连线

最终路径按**搜索走的次序**连成折线，而且**每一段只许横或只许竖**：
八方向模式下相邻两格落在斜方向上时，拆成「先横后竖」两段，拐点在两格之间。
折线画两遍（先描边色、再主色），画出来总宽 3 像素，压在任何一种填充色上都看得清；
主色与路径块的填充色相同，压在路径块上时只剩两道细描边，格上的数字不会被拦腰截断。
`--layoutcheck` 断言正交性（四方向 74 段、八方向 76 段，斜段 0 条）。
折线与各填充色的对比度、以及数字压在折线上怎么保证读得动，见《演示工具/README.md》。

### 工具与刷子

| 工具 | 左键 | 右键 |
|---|---|---|
| 墙壁 | 把格子变成墙 | 擦掉墙 |
| 擦除 | 恢复成代价 1 的空地 | 同左键 |
| 地形代价 | 把格子设成「刷子值」（1 到 9） | 把该格代价循环加一（9 之后回到 1） |
| 起点 | 把起点放到这里 | 同左键 |
| 终点 | 把终点放到这里 | 同左键 |

刷子有 **1x1、3x3、5x5** 三档，按住左键拖动会连续生效。
起点或终点落到墙上时，**自动清掉那一格的墙**，不需要先擦墙。

**编辑地图会自动暂停运算，并清空上一次的搜索状态**，不留上一次的颜色。

### 键盘

| 按键 | 作用 |
|---|---|
| 空格 | 开始或暂停 |
| 右方向键 | 单步推进 |
| `R` | 重置到初始状态 |
| `Ctrl+Z` | 撤销上一次落笔（至少一步，实测可连续撤销多步） |

### 速率

单位是 **sps**（每秒推进多少步）。滑块是对数刻度，从 0.5 到不限速，
另有 `0.5`、`1`、`10`、`100`、`1k`、`10k`、`不限速` 七个预设按钮。

| 档位 | 谁在控制 | 说明 |
|---|---|---|
| 有限 sps | 运算进程按目标速率发步数配额 | 配额不足一步的余量留到下一片，因此长时间平均值贴近目标 |
| 不限速 | 运算进程全力跑 | 每一片推进到用掉约 12 毫秒预算为止；界面按 60 帧每秒独立刷新 |

**统计里的「实测推进速率」是运算进程用真实经过的时间与步数算出来的**，
不是界面帧率，也不是滑块上的目标值。

### 时间线

暂停、继续、单步推进、重置到初始状态、**回放到第 N 步**。
回放靠引擎的确定性：重置之后连续推进 N 步，得到的状态与当初第 N 步时相同。

### 主题

浅色、深色、跟随系统三态，命令行 `--theme light|dark|auto` 也能指定。
色表、对比度实测值与形状线索见《演示工具/README.md》的「主题与配色」一节。

## 五种算法

| 算法 | 按什么排序 | 用不用代价 | 最优性 |
|---|---|---|---|
| BFS | 先进先出，按步数分层 | **不用**，一律按无权图 | 步数最少，但不是代价最小 |
| DFS | 后进先出，沿一条路走到底 | **不用** | 不保证最优 |
| Dijkstra | `g`（从起点到这里的实际代价） | **用** | 代价最小 |
| A* | `f = g + h` | **用** | 启发函数可采纳时最优 |
| 贪心最佳优先 | `h`（到终点的估计） | 只看估计 | 不保证最优 |

**BFS 与 DFS 把地形代价当作不存在**，这是它们的定义决定的：
两者按「边的条数」分层，代价信息在它们的模型里没有位置。
要看代价说话，用 Dijkstra 或 A*。

### 代价怎么算

地图上每格有一个 1 到 9 的代价，走一格要付这一格的代价。
为了避免浮点误差，内部一律用**千分之一**为单位的整数：
直走一步算 1000，斜走一步算 1415（略高于 1000√2 ≈ 1414.214）。

斜走取 1415 是有意的：取 1414 会让「齐次」的启发函数偶尔高估千分之一，
取 1415 则保证不高估，可采纳性不被破坏。

### 启发函数

三种距离，乘「齐次」或「非齐次」两种尺度：

| 名称 | 4 方向 | 8 方向 |
|---|---|---|
| 曼哈顿 | `dx + dy` | 不适用（会高估） |
| 欧几里得 | `√(dx²+dy²)` | `√(dx²+dy²)` |
| 八分（Octile） | 退化为曼哈顿 | `(dx+dy) + (√2-2)·min(dx,dy)` |

| 尺度 | 做法 | 可采纳吗 |
|---|---|---|
| 齐次 | 用**全图最小代价**乘距离 | 可采纳，因此 A* 最优 |
| 非齐次 | 用**这一格的代价**乘距离 | 允许斜走时会高估，A* 不再保证最优 |

**这一条可以在界面上直接看出来**：选「A*」+「曼哈顿（非齐次）」，
跑完看统计里的路径代价，再换成 Dijkstra 比一比，非齐次那一档会更大。
`--selftest` 里也把这两个数打出来了，见下面的实测数据。

### 斜走与拐角

8 方向模式下允许斜走，**只检查目标格能不能走**，不检查两个正交邻居，
因此可以从两堵墙的夹缝里斜穿过去。这是有意的简化，README 与界面上都写明。

## 两个进程怎么分工

| 谁 | 干什么 | 节奏 |
|---|---|---|
| 界面进程（不带参数启动） | 画元素、收鼠标与按钮、发命令 | 固定约 60 帧每秒 |
| 运算进程（`--worker`） | 推进算法、按 sps 限速、写共享内存 | 自己按时钟推进 |

每元素的状态与数值走共享内存（48×32 = 1536 格，整块约 41 KB），
命令与统计走环回 TCP。完整的布局表与取舍理由见《演示工具/README.md》。

`实测数据`
`Text`

```text
界面进程：  "...\SearchDemo.exe"
运算进程：  "...\SearchDemo.exe" --worker --port=3134 --shm=VisualCoreShm.b4a46f... --parent=13268
关掉窗口之后：Get-Process SearchDemo 查不到残留进程
```

**同进程模式**（面板上「运算 / 同进程」）把算法放回界面进程，用于对照：
同一台机器、同一次不限速运行，两种模式的实测 sps 会并排列在统计面板的
「两种模式对照」一行里。
