# 数据结构演示

十个结构场景装在一个程序里：动态数组的增长、链表、哈希表、搜索树与平衡、堆、B 树、
trie、图、并查集、排序过程。下拉框里切换场景，画布上切换画法，右边切换选项，其余交给运算进程。

界面进程只管绘制，算法在另一个进程中推进；每一步的状态通过共享内存交给界面，
因此「不限速」这一档能把排序一次性推进到底，而界面仍按约 60 帧每秒刷新。
框架部分（两个进程的分工、共享内存的布局、主题与署名的做法）见《演示工具/README.md》，
本文件只讲数据结构演示自己的部分。

十个场景**共用同一份元素数组**（256 个），每个场景各用自己那一段下标，
因此换场景不必重建共享内存，也就不必重启运算进程。

## 怎么跑

`PowerShell`

```powershell
.\DsDemo.exe                       # 打开窗口（界面进程会自己拉起运算进程）
.\DsDemo.exe --mode=6              # 开局停在某个场景（0 到 9），这里停在第 7 个
.\DsDemo.exe --seed=12345          # 换一批场景数据
.\DsDemo.exe --theme dark          # 指定主题：light / dark / auto
.\DsDemo.exe --selftest            # 无窗口自测，输出格式固定
.\DsDemo.exe --palettecheck        # 无窗口查配色：逐控件算对比度，低于 4.5:1 非零退出
.\DsDemo.exe --layoutcheck         # 无窗口查排版与连线：文字放不下、出现斜段都非零退出
.\DsDemo.exe --worker --port=…     # 运算进程身份，由界面进程拉起，不必手敲
```

`--mode` 与 `--seed` 是本演示自己认的两个开关（核心不认识它们，原样透传），
写在这里是为了让截图与复现有个统一的入口。`--theme`、`--selftest`、`--palettecheck`、
`--layoutcheck`、`--worker`、`--trace` 都由共享核心处理。

窗口客户区 **1336×870**（整个窗口 1342×899），**最小尺寸就等于内容尺寸**：
窗口缩小时会停在这个尺寸上，因此不存在「缩到把面板或画布切掉」的状态。

### 画布

| 元素 | 含义 |
|---|---|
| 画布顶上一行 | 场景名、种子、以及本场景最该看的几个数 |
| 画布最下一行 | **场景数据本身**（要插入的键、词表、边表、待排序的数），按钮改的就是它 |

### 工具与直接操作

右边「工具」分组里有五个工具，落笔之后**命令发给运算进程执行**，界面这一侧不自己改结构。

| 工具 | 左键 | 用到的参数 |
|---|---|---|
| 插入 | 把「刷子值」当键值插进去（按下标落的场景插在点中的位置上） | 刷子值、点中的元素 |
| 删除 | 删掉点中的那个／最后那个 | 点中的元素 |
| 查找 | 高亮「刷子值」这个键的路径（trie 里是词表里的第几个键） | 刷子值 |
| 选中 | 标记点中的元素（图上当起点、trie 里高亮它的前缀路径） | 点中的元素 |
| 清空 | 清空这一轮所用的场景数据 | — |

**「刷子值」就是键值**：本演示的刷子不带尺寸，`刷子` 那一行的单选钮因此是空的，
它下面那个数字框就是插入／删除／查找用的参数，范围 1 到 99。

一次点击只作用在第一个元素上，按住拖动不会连发（指针事件的第二个元素起就忽略了）。
**改动会清空运行状态，运算进程从头重新运行一遍**，因此看到的始终是「这一份数据上算法走的全过程」。

右上的三个按钮改的是**场景数据**（不是运行状态）：

| 按钮 | 做什么 |
|---|---|
| 重新生成数据 | 按当前种子重新生成一批（等价于 `--seed` 换一个数） |
| 追加 5 个随机键 | 按种子推进出 5 个键，接到场景数据后面，可复现 |
| 清空结构 | 清空场景数据，画面上只剩空结构 |
| 种子 + 生成 | 换种子并重新生成；种子写在画布顶行，也写进自检输出 |

### 键盘

| 右方向键 | 单步推进 |

### 速率与时间线

单位是 **sps**（每秒推进多少步）。滑块是对数刻度，从 0.5 到不限速，
另有 `0.5`、`1`、`10`、`100`、`1k`、`10k`、`不限速` 七个预设按钮。

暂停、继续、单步推进、重置到初始状态、**回放到第 N 步**都在右边。
回放靠引擎的确定性：重置之后连续推进 N 步，得到的状态与当初第 N 步时相同。
排序场景用它最合适——把滑块拉到不限速运行到底，再回到第 300 步查看那一次交换。

### 主题与署名

浅色、深色、跟随系统三态，命令行 `--theme light|dark|auto` 也能指定。
主窗口左下角常驻 `Written By HiBer2007`，随窗口缩放贴在底部，不压画布也不压面板。

### 1 动态数组的增长

容量从 0 起按 `1、2、4、8…` 跳，每跳一次就把旧块整个搬到新块，旧地址随即失效。
画面上一行是新块的两排 64 个槽，下面一行是旧块：**旧块里已经搬走的槽变成「已失效」，
还没搬的还是「待处理」，搬的那一个有一条连线从旧块指到新块**。
「选项一」换成 `先 reserve(32)`，扩容次数直接变成 0——这就是 `reserve` 省下的开销。

### 2 链表

下标 0 是头哨兵。每个节点盒子里写着键值与 `next` 指向谁，两者之间连着一条正交折线。
插入分两步写指针（先 `new->next`，再 `prev->next`），每一步在画面上都能看到改了哪个；
删除只改一个指针，被摘掉的节点标成失效留在原地，看得出「摘链」与「释放」是两件事。
「选项一」里还有尾部接上（每次都要走到尾）与头部插入（不必找位置）两种对照。

### 3 哈希表

桶画成一列（桶多了自动分两列），每个桶右边挂着它的冲突链。
一次插入走四步：算哈希、走到桶、沿链比较、挂上；键数越过负载因子上限 0.75 就再哈希，
**桶数翻倍的那一刻整个表重排一次**，键一个一个搬过去，搬过的节点换色，状态行写着进度。
「选项一」换哈希函数（取模与乘法散列），「选项二」换初始桶数（8 与 16）。

### 4 搜索树 → 平衡

节点按**中序排名**定 x 坐标、按层数定 y 坐标，因此**旋转一次，屏幕上整棵树的坐标就重排一次**。
「选项一」在朴素 BST、AVL、红黑树之间切；「选项二」换成升序插入，
朴素 BST 会一路挂到最右边，长成一条高 16 的链（键数就是 16），AVL 只有 5 层。
红黑树的颜色写在键值后面（`R`／`B`），旋转时颜色跟着变。

### 5 堆

**同一份数组画两次**：上面按完全二叉树排成树形，下面按存储顺序排成数组行，
两边用的是同一批元素，因此下沉与上浮时两边同时换色。
一轮包含自底向上建堆（下沉）、push 两个（上浮）、pop 两个（下沉）；
弹出去的格子留在数组行里标成失效，看得出堆大小在缩。

### 6 B 树

阶 4，每个节点最多 3 个键槽（画成三个格子，格线是装饰性的，不参与连线自检）。
插满就先分裂，中位键升到父节点；删除时一路走最右的孩子，碰到「将空」的节点
先从左右兄弟借一个，借不到就与兄弟合并（父节点的分隔键沉下来）。
一轮删除最多删三个键，删出一次合并就停。

### 7 trie

一层一个单位，兄弟节点连成一条链。「选项一」在**按码点**与**按字节**之间切：
同一个两字中文词，按码点占 2 层，按 UTF-8 字节占 6 层（一个汉字三字节）。
「选项二」换词集（英文、中文、中英混合）。用「查找」工具输入词表里的第几个键，
或者用「选中」点一个节点，就能高亮一条前缀路径，状态行报出这个前缀命中了几个键。

### 8 图

八个顶点排成两行，边一律走两行之间的通道，**每条边有自己的通道**，因此不会叠成一条长横线。
「选项一」在邻接矩阵、邻接表、边表之间切：矩阵带行列字母，邻接表一行一个顶点，
边表把边原样列出来。遍历每一步只走一条边，**图上那条边、矩阵里两格、邻接表里那一项同时高亮**。
「选项二」换 BFS 与 DFS。

### 9 并查集

父指针画成正交折线，自己指向自己的是根（锚点色）。「选项一」是四种组合：
什么都不加、只按秩合并、只路径压缩、两者都加。
所有合并做完之后，从**最深的那个节点**做一次 find：先数压缩前走了几跳，
再逐个把路径上的节点接到根上（换成「已压缩」色），最后再数一次。
这一组数字就是「路径压缩省下了什么」的直接回答。

### 10 排序过程

四十根柱子，柱高就是键值。比较中的两根、刚换过的两根、已就位的分开上色。
「选项一」是冒泡、插入、选择、快速（Lomuto）四种，「选项二」是初始次序（随机、近乎有序、逆序）。
逆序数据下插入排序的比较次数与交换次数最多，近乎有序时它最快——这两个极端在画面上就是
「柱子几乎不动」与「每根柱子都在移动」。

## 三条自检

三条都在同一个进程中运行，不开窗口，也不启动子进程；任何一条不通过都以非零退出码结束。

### `--selftest`：每个场景一组可复现的结构量

`PowerShell`

```powershell
.\DsDemo.exe --selftest
```

## 与共享核心的两条约定

### 一、十个场景共用同一份元素数组

核心的 `Snapshot` 与共享内存按 `Scene.ElementCount` **一次定长**（见
`VisualFormBase` 的构造函数），换场景也换不来长度。因此本演示让 `ElementCount` 恒为 256，
每个场景各用自己那一段下标：

`Text`

```text
[0,128)    结构单元区：节点、槽、桶、格
[128,255)  输入区：场景数据（要插入的键、编码后的词表、边表、合并的对）
[255]      命令邮箱
```

用得最多的场景是图（到下标 101），最小的场景是 trie（到下标 11），
每一个都留在 128 以内——`--selftest` 里逐场景打印并断言这一条。

### 二、界面进程的改动只能走命令邮箱

核心给渲染侧到运算侧只有一条路：`WriteScene` 写的是 Marker／Tag／Attr0..5／Seed／CustomA／CustomB，
再由 `SYNC` 让运算进程 `ImportScene`。因此本演示留出最后一个元素当**命令邮箱**：
Marker 是命令序号，Attr0 到 Attr2 是命令码与两个参数。

**引擎的数据是权威**：运算进程那一侧的 `ImportScene` 只读邮箱，其余字段一律不读——
界面进程那一份只是上一帧的回声，一次迟到的回写就会把结构顶回几步之前。
邮箱按序号去重，因此同一条命令重发几次也只生效一次。

## 画图纪律怎么落地的

### 连线只有横段与竖段

所有连线都由 `DsPath` 产出，它只提供三种加法：横段、竖段，以及把一个任意方向的连接
**拆成「先横后竖」两段**。产出斜段的唯一可能是有人直接加一条斜的，
自检里专门造了这样一条当反例。

树、堆、B 树、trie 的父子连线走「竖 → 横 → 竖」三段，图的边走两行之间的通道，
链表与哈希的指针是横段或「竖横竖」，并查集的父指针是「竖横竖」。十个场景合计 230 段线，
斜段 0 条。

### 线宽按像素量

线画两遍：先描边色 3.0 像素，再压主色 1.6 像素。**实画宽度是从截图里逐像素数出来的**：

`实测数据`
`Text`

```text
浅色（画布 #F4F4F4，一段竖线横切）：#C0C0C0 #3A1A00 #C0C0C0，共 3 像素
深色（画布 #1B1B1B，同一位置）  ：#0B0E12 #ECEFF1 #0B0E12，共 3 像素
```

深色的描边色**没有用核心给的那个值**：核心的 `PathHalo` 在深色下是 `#1B1B1B`，
正好等于画布底色，测出来整条线只剩 1 像素，描边也就失去了作用。
本演示改成比画布更暗的那一档填充色（`#0B0E12`），于是两套主题画出来都是 3 像素。
浅色仍用核心给的中灰 `#C0C0C0`——**描边不用近白色**，否则浅色主题下整条线会看着像白线。

### 线在字的位置让开

线与字重叠时，只调绘制顺序不够：GDI 画字带抗锯齿，十来像素的字笔画只有一两像素宽，
压在线的描边上时笔画芯部会被混成描边色，看上去就是「数字糊成影子」。
本演示的做法是：**先用所在块的填充色把字位（上下左右各 1 像素）盖一遍，再画字**，
只对真正与连线相交的字位做，因此连线在字的两侧照常连着；**字一律用粗体**
（13 像素 Consolas 粗体，小一号的地方用 12 像素粗体，见「字号」一节）。

### 装饰性的格子线不算连线

B 树的键槽分隔线、堆的数组行格子用的都是网格线的颜色，也不进 `DsPath`，
因此不参与「连线只许横或竖」那条断言——它们是格子，不是结构里的连线。

## 主题与配色

颜色由共享核心的 `ThemePalette` 给，两套都是手工配的。
本演示只声明语义色槽，不写死色值；连线与文字的颜色也从色槽取，
只有「高亮连线」那一支按主题在两支候选里挑（见下）。

### 对比度

块上文字与块底色的对比度**两套主题下都不低于 4.5:1**；连线（主色与描边里较高的那一个）
与十二种填充色的对比度**都不低于 3:1**（图形元素的标准低于文字）。
这两个数由 `--selftest` 现算现打印并断言，不是抄来的。

`实测数据`

| 项 | 浅色最低 | 深色最低 | 出现在哪一对 |
|---|---|---|---|
| 块上文字 / 块底色 | 5.60:1 | 5.46:1 | 浅色「当前」、深色「路径／前缀」 |
| 连线 / 填充色 | 3.33:1 | 3.08:1 | 浅色「当前」、深色「待处理」 |
| 控件前景 / 背景 | 12.51:1 | 12.51:1 | 署名条（`--palettecheck` 逐控件算） |

### 高亮连线取哪一支

| 主题 | 主色（普通连线） | 描边（两遍描） | 高亮（当前边、当前指针） |
|---|---|---|---|
| 浅色 | `#6A1B9A`（最终结果槽的填充色） | `#C0C0C0` | `#3A1A00`（当前槽的字色） |
| 深色 | `#CE93D8`（最终结果槽的填充色） | `#0B0E12` | `#ECEFF1`（参照槽的字色） |

两支都是「该主题下与画布底色对比度更高的那一支」：浅色下高亮是近黑（15.82:1），
深色下高亮是近白（16.75:1），普通连线分别是 9.39:1 与 5.52:1。
换的是颜色，不是粗细——每一段仍然是横段或竖段。

## 看图时先发现的问题

截图是逐张看过的（两套主题的全窗、画布 2 倍放大、最小尺寸、十个场景各一张），
下面这些问题都是看图时先看出来、再去改代码的：

| 现象 | 原因 | 改法 |
|---|---|---|
| 第 6 个场景的子树是一片空框，连线一直伸到画布外 | B 树节点的父指针存的是**节点号**，画布按元素下标数层数，越走越偏 | 父指针统一存元素下标（＝节点号 × 2），树、并查集、B 树三处一致 |
| 第 8 个场景的邻接表叠在邻接矩阵上 | 布局给三种存法都发了矩形，三种一起画 | 只给「选项一」选中的那一种发矩形，边表改用画布上的说明文字列出来 |
| 图的十来条边叠成一条长横线 | 所有边共用一个通道 | 每条边一条通道 |
| 第 1 个场景的旧块写了一整排空槽 | 旧块行固定 32 个槽，没内容的也画 | 旧块里没有内容的槽不画，只留当时真正装着的那些 |
| 深色主题下连线看着只有 1 像素 | 描边色等于画布底色 | 描边改用比画布更暗的那一档填充色 |
| 堆的数组行下标与格子对不齐 | 下标是一整串写死的文字 | 一格一个下标，居中画 |
| 「元素上标」下拉换了没有反应 | 绘制没有用到它 | 四档都实现：键值、元素下标、结构编号、不写 |
| 键值后面的 `R`／`B` 看不出是什么 | 只有画布上没说明 | 画布说明行里补一句 |

## 已知限制

- **结构区只有 128 个元素**。数据规模因此是固定的（键 12 到 24 个、排序 40 个），
  改大要动 `DsConst.StructCount`，也要跟着改各场景的布局。
- **B 树只删最大键**。它一定在最右边的叶子里，因此不必处理「从内部节点删」那种情形；
  借用与合并这两种修法都能看到，但删除的一般情形没有覆盖。
- **图的边表视图只列出边**，没有做成可点的元素；要加删边请切到矩阵或邻接表视图再用工具。
- **trie 的场景数据是编码后的词表**（长度 + 单位，按码点或按字节），
  因此「插入」加的是词库里下一个词，不能任意输入字符串。
- **排序的四种算法都是就地排序**，没有归并排序（它需要额外的数组，
  而本演示的元素数组是给结构用的，不好再切一块出来当辅助空间）。
- **两个进程共用一块共享内存**，`--mode` 只影响开局停在哪个场景，
  换场景不会重建共享内存，因此十个场景的元素总数必须一致。
