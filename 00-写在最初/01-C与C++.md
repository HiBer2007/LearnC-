# 第 1 节 C 与 C++ 是什么

## 1.1 它们都是「编译型语言」

**这一条决定了后面的一切。**

| | 编译型（C、C++） | 解释型（Python、JavaScript） |
|---|---|---|
| 代码怎么被执行 | 先整体翻译成机器码，再运行 | 运行时逐句翻译 |
| 能不能直接双击运行 | **不能**，必须先编译 | 能，只要有解释器 |
| 错误什么时候暴露 | **大部分在编译期** | 多数在运行到那一行时 |
| 运行速度 | 快 | 相对慢 |

**「为什么写完的代码不能直接点一下运行」的完整回答，
见《01-编译器/01-编译与链接.md》第 5 节。**

## 1.2 C 语言

**C 诞生于 1972 年，最初是为了写操作系统。**

它的设计取向可以概括成一句话：**贴近硬件，但比汇编好写。**

| 特点 | 含义 |
|---|---|
| **过程式** | 程序是一串函数调用，没有「对象」的概念 |
| **静态类型** | 每个变量在编译期就有确定的类型 |
| **手动内存管理** | `malloc` / `free` 由程序员负责 |
| **极小的运行时** | 几乎没有语言自带的运行时支持 |
| **可移植的汇编** | 同一份代码可在不同架构上重新编译 |

**最后两条是 C 至今不可替代的原因**：
它足够底层，能直接操作内存与寄存器；
又足够高级，不必手写汇编。

**C 的典型用途**：操作系统内核、嵌入式固件、驱动程序、运行时库。

## 1.3 C++ 语言

**C++ 诞生于 1983 年，最初的名字就叫「C with Classes」。**

它的设计取向是：**在保留 C 的性能与底层能力的同时，
提供更高层的抽象手段。**

| 特点 | 含义 |
|---|---|
| **多范式** | 既能写过程式代码，也能写面向对象与泛型代码 |
| **零开销抽象** | 不用的特性不付出代价，用了的与手写等价 |
| **RAII** | 用对象的生命周期管理资源 |
| **模板** | 编译期的泛型编程 |
| **标准库** | 容器、算法、字符串、智能指针等 |

**「零开销抽象」是理解 C++ 的关键**：
它不是「比 C 慢的高级语言」，
而是「可以写得和 C 一样快，也可以写得更抽象」的语言。

**C++ 的典型用途**：游戏引擎、浏览器、数据库、图形软件、
高频交易、需要性能又需要复杂结构的场合。

## 1.4 一句话概括两者的关系

<small style="color:gray">text</small>

```text
   C  ──诞生──→  1972
                  │
                  │ 语法与语义被大量继承
                  ▼
   C++ ──诞生──→  1983（原名 C with Classes）
```

**C 是 C++ 的直接来源。**
C++ 保留了 C 的绝大部分语法、类型系统与内存模型，
在上面加了一整套抽象机制。

**这个关系带来的后果，是第 2 节的主题。**

## 1.5 关于「语言的实现」

**标准与实现是两回事**：标准只规定语言应当怎样，
具体落实由编译器完成，而编译器不止一种。
分工的细节、标准留的三类「自由度」以及它们在实际中的表现，
见《01-编译器/00-语言的实现.md》第 1 节至第 3 节。

**归结为一句话**：

<small style="color:gray">text</small>

```text
   你写的是源码，编译器才是把它变成程序的那个东西。
   而编译器不止一种，它们遵循同一份标准，但不必处处相同。
```

# 第 2 节 C++ 是 C 的超集

## 2.1 这个说法的来源

**「超集」是集合论的说法**：

<small style="color:gray">text</small>

```text
   如果把「所有合法的 C 程序」看作集合 A，
   把「所有合法的 C++ 程序」看作集合 B，

   那么「C++ 是 C 的超集」意味着：  A ⊆ B
   即：每一个合法的 C 程序，同时也是合法的 C++ 程序。
```

**这个说法有很强的历史根据**：
C++ 的设计目标之一就是**兼容 C**，
让已有的 C 代码可以平滑迁移过来。

**它大致成立，但不是严格成立的。**
下面两小节分别说这两面。

## 2.2 它在哪些地方成立

**绝大部分 C 代码可以直接当 C++ 编译。** 具体包括：

| C 的构造 | 在 C++ 中 |
|---|---|
| 基本类型与运算符 | 完全一致 |
| `if` / `for` / `while` / `switch` | 完全一致 |
| 函数定义与调用 | 基本一致 |
| 结构体 `struct` | 一致，且升级为类 |
| 指针与数组 | 基本一致 |
| 预处理器（`#include` / `#define`） | 完全一致 |
| 标准库函数（`printf` / `malloc`） | 可用（需包含对应头文件） |

**一个具体例子**：

<small style="color:gray">实测数据</small>
<small style="color:gray">c</small>

```c
/* c_compat.c    编译：gcc -std=c23 c_compat.c -o c_compat（用 g++ -std=c++17 编译同一文件也通过） */
#include <stdio.h>

struct Point { int x; int y; };

int add(int a, int b) { return a + b; }

int main(void) {
    struct Point p = { 3, 4 };      /* C 与 C++ 都允许这样初始化 */
    printf("%d\n", add(p.x, p.y));
    return 0;
}
```

**这一段 C 与 C++ 写法相同，两个编译器都能编过。**

**这种兼容性带来一个实用的能力**：
**存量 C 代码可以逐个文件地迁移到 C++**，
不必一次重写。

## 2.3 它在哪些地方不成立

**这是更需要记住的一面**：有四类 C 代码不能原样搬到 C++ 里。

### 2.3.1 C++ 新增了关键字

**C 里可以用的标识符，在 C++ 里可能是保留字。**

<small style="color:gray">实测数据</small>
<small style="color:gray">c</small>

```c
/* keyword_clash.c    编译：gcc -std=c23 keyword_clash.c -o keyword_clash（换 g++ -std=c++17 编同一文件会报错） */
#include <stdio.h>

int main(void) {
    int class = 3;      /* 合法的 C。C++ 中 class 是关键字，这一行编不过 */
    int new = 5;        /* 同上：new 在 C++ 中是关键字 */
    printf("%d %d\n", class, new);
    return 0;
}
```

**同一份源码，`gcc` 编得过，`g++` 报错。**
老 C 代码里用这些词做变量名或函数名的，迁移时要改名。
**C++ 新增的关键字清单见附录 A。**

### 2.3.2 类型转换规则更严

**C 允许 `void*` 隐式转换成任何指针类型，C++ 不允许。**

<small style="color:gray">c</small>

```c
/* void_cast.c    编译：gcc -std=c23 -c void_cast.c -o void_cast.o */
#include <stdlib.h>

int *alloc_ints(int n) {
    return malloc(sizeof(int) * n);         /* 合法的 C：void* 隐式转成 int* */
}
```

<small style="color:gray">cpp</small>

```cpp
// void_cast.cpp   编译：g++ -std=c++17 -c void_cast.cpp -o void_cast.o
#include <stdlib.h>

int *alloc_ints(int n) {
    return (int *)malloc(sizeof(int) * n);  // 必须显式转换
}
```

**这是 C 代码迁移到 C++ 时最常见的编译错误之一。**

> [!TIP]
> C++ 里通常用 `new` 或容器代替 `malloc`。
> `unique_ptr` 是 C++ 的智能指针：它独占对象的所有权，
> 自身被销毁时自动释放所指对象，因此不需要手写 `delete`。
> 完整讲解见【待补：01-编译器/05-语法.md】。

### 2.3.3 C 的部分特性 C++ 不支持

**变长数组（VLA）是最常遇到的一个**：C 标准允许，C++ 标准不支持，
只在 GCC 中作为扩展可用。旧式函数定义、隐式 `int`、
指定初始化器的部分写法、复合字面量也各有各的限制。

**用了这些特性的 C 代码，换个 C++ 编译器可能编不过。
完整清单见附录 A。**

### 2.3.4 同一段代码，行为可能不同

**这一类最隐蔽，因为代码能编过，但行为变了。**

| 写法 | 在 C 中 | 在 C++ 中 |
|---|---|---|
| `sizeof('a')` | 等于 `sizeof(int)` | 等于 `sizeof(char)` |
| `const` 变量 | 默认外部链接 | **默认内部链接** |
| 空参数列表 `f()` | 表示参数不限 | 表示**没有参数** |
| 结构体标签 | 需要 `struct Point p` | 可以直接 `Point p` |

**空参数列表这一条值得单独说明**：

<small style="color:gray">c</small>

```c
/* C：表示「参数个数与类型不限」—— 不推荐，但合法 */
int f();

/* C++：表示「没有参数」—— 与 f(void) 等价 */
int f();
```

**如果有 C 代码用了 `f()` 这种旧式写法，
换成 C++ 编译器后调用检查会变严，可能报错。**

### 2.3.5 准确的表述

**综合上面四类，更严谨的说法是**：

> [!IMPORTANT]
> **C++ 以 C 为基础，语法上高度兼容，绝大部分 C 代码可以直接编译。
> 但它不是数学意义上的严格超集。**

**或者用集合的方式表达**：

<small style="color:gray">text</small>

```text
   A（合法 C 程序）  ⊄  B（合法 C++ 程序）
   A ∩ B 覆盖了 A 的绝大部分，但不是 A 全部
```

**为什么要强调这一点**：
因为「超集」这个说法容易让人以为
「C 代码放到 C++ 里一定没问题」，
而 2.3.4 那一类问题恰恰是**能编过但行为不同**的，
比编不过更危险。

## 2.4 这个关系对我们编程的深刻影响

「C++ 兼容 C」不只是一条语言史知识，
它直接决定了实际工程里的很多做法。

### 2.4.1 影响一：可以混用两种语言

**同一个工程里可以同时有 `.c` 与 `.cpp` 文件。**

<small style="color:gray">text</small>

```text
   project/
   ├── legacy/           编译成 C
   │   ├── parser.c
   │   └── parser.h
   └── app/              编译成 C++
       └── main.cpp
```

**CMake 会自动按扩展名选择编译器**：
`.c` 用 C 编译器，`.cpp` 用 C++ 编译器。

**这是渐进迁移的基础**：不必一次重写整个项目。

### 2.4.2 影响二：`extern "C"` 必须存在

**C++ 支持函数重载，因此会把参数类型编码进符号名**（这叫名字修饰）。
**C 不做修饰**，函数名就是符号名。

结果是一个具体问题：

| 写法 | 符号名 |
|---|---|
| `int add(int, int)` 用 C++ 编译 | `_Z3addii` |
| 同上，用 C 编译 | `add` |

**C 代码按 `add` 去找符号，而实际符号叫 `_Z3addii`，于是链接失败。**

**`extern "C"` 的作用就是关掉名字修饰**，让符号名回到 `add`。

**完整说明见《01-编译器/00-语言的实现.md》第 6.5 小节**，
那里给出了三种写法的符号名实测对照。

### 2.4.3 影响三：头文件要写成两种语言都能用

**这是上一条的必然结果**：给 C 写的库，头文件要用 `#ifdef __cplusplus`
把 `extern "C"` 包起来，让两种编译器各取所需。

**写法、逐行解释与常见误用**
见《01-编译器/00-语言的实现.md》第 6.6 小节。

**本教材 `A-教学素材/10-寄存器与位运算/gpio.h` 就是这种结构**，
可以打开对照。

### 2.4.4 影响四：学习路径变得连续

**学过 C 之后学 C++，绝大部分语法不需要重新学。**

<small style="color:gray">text</small>

```text
   已掌握的（C 与 C++ 通用）
   ├── 基本类型与运算符
   ├── 流程控制
   ├── 函数
   ├── 指针与数组
   ├── 结构体
   └── 预处理器
              │
              ▼  在此基础上新增
   C++ 特有
   ├── 类与对象
   ├── 引用
   ├── 模板
   ├── 异常
   ├── 标准库容器与算法
   └── 智能指针
```

**这是本教材把 C 与 C++ 放在一起讲的原因**：
两者共用的部分占多数，分开讲会大量重复。

### 2.4.5 影响五：但不能反过来

**C 编译器编译不了 C++ 代码。**

<small style="color:gray">text</small>

```text
   C   ──→  C++      可以（大部分）
   C++ ──→  C        不行
```

**这一条决定了方向性**：

| 场景 | 可行 |
|---|---|
| 老 C 项目逐步改用 C++ | 可行 |
| 老 C++ 项目改用 C | **不可行**，除非重写 |
| C 库被 C++ 项目使用 | 可行，加 `extern "C"` |
| C++ 库被 C 项目使用 | **需另做一层 C 接口** |

**最后一条是常见需求**：很多 C++ 库会额外提供一个纯 C 的 API，
就是为了让 C 程序也能用。

### 2.4.6 影响六：把 C 代码当 C++ 编译要小心

**「能编过」不等于「行为一样」**：第 2.3 小节列的情况里，
标识符撞上关键字、`void*` 的隐式转换会在编译期直接报错；
`sizeof('a')` 的结果、`const` 全局变量的链接属性、
空参数列表的含义则是**编得过、结果却不同**。

> [!WARNING]
> 不要假设「把 C 代码改个扩展名就行」。
> 后一类问题不会报错，只能靠**逐个文件编译并测试**发现。

# 第 3 节 大方向上的区别

## 3.1 抽象手段

| | C | C++ |
|---|---|---|
| 组织代码的方式 | 函数 + 结构体 | 类、命名空间、模板 |
| 数据与操作的关系 | 分离（函数操作数据） | 结合（对象带有方法） |
| 复用方式 | 函数指针、宏 | 继承、模板、组合 |

**C 的结构体只能装数据，不能带函数。**
C++ 的类把数据与操作放在一起，并能控制访问权限。

## 3.2 资源管理

**这是两者最实质的差异。**

| | C | C++ |
|---|---|---|
| 内存分配 | `malloc` / `free` | `new` / `delete`，或容器与智能指针 |
| 谁来释放 | **程序员手工** | **由对象的生命周期自动完成** |
| 忘记释放 | 内存泄漏 | 不适用（RAII） |
| 异常安全 | 需要手工保证 | 由析构函数保证 |

**C++ 的核心机制叫 RAII**（Resource Acquisition Is Initialization）：
**把资源的获取放在构造函数里，释放放在析构函数里。**
对象离开作用域时析构函数自动执行，于是资源必定被释放。

**这条机制的影响超出内存**：文件句柄、锁、网络连接，
都可以用同一套办法管理。

**手工 `new` / `delete` 与 `unique_ptr` 的写法对照
见【待补：01-编译器/05-语法.md】。**

## 3.3 运行时开销

| | C | C++ |
|---|---|---|
| 语言自带的运行时 | 极少 | 有，但**只在你使用对应特性时才有** |
| 虚函数 | 无 | 一次间接调用 |
| 异常 | 无 | 有表驱动的实现开销 |
| 模板 | 无 | **零运行时开销**（全在编译期完成） |

**「零开销抽象」的具体含义**：
一个用模板写的 `max(a, b)`，编译后与手写 `a > b ? a : b` 的机器码相同。
**抽象在源码里，不在产物里。**

## 3.4 编译期能力

| | C | C++ |
|---|---|---|
| 泛型 | 靠宏（不安全） | **模板**（类型安全） |
| 编译期计算 | 很有限 | `constexpr`、模板元编程 |
| 函数重载 | 不支持 | 支持 |
| 命名空间 | 靠命名前缀 | `namespace` |

**C 用宏做泛型的代价是明显的**：

<small style="color:gray">c</small>

```c
/* max_macro.c    编译：gcc -std=c23 -c max_macro.c -o max_macro.o */
#define MAX(a, b) ((a) > (b) ? (a) : (b))      /* 宏展开，没有类型检查 */

int max_int(int a, int b) { return MAX(a, b); }
```

<small style="color:gray">cpp</small>

```cpp
// max_template.cpp   编译：g++ -std=c++17 -c max_template.cpp -o max_template.o
template <typename T>
T max(T a, T b) { return a > b ? a : b; }      // 模板，有类型检查

int max_int(int a, int b) { return max(a, b); }
```

## 3.5 一句话对照

| 维度 | C | C++ |
|---|---|---|
| 定位 | 可移植的汇编 | 带抽象的系统级语言 |
| 规模 | 语言本身很小 | 语言本身很大 |
| 学习曲线 | 平缓但要懂底层 | 前期陡，后期宽 |
| 适合 | 内核、固件、驱动 | 引擎、应用、框架 |
| 代码风格 | 一种主流写法 | 多种范式并存 |

# 第 4 节 关键特性速览

## 4.1 C 的关键特性

| 特性 | 作用 | 在哪讲 |
|---|---|---|

# 第 5 节 学习指南

## 5.1 应该先学哪个

**这取决于你的目标。**

| 你的情况 | 建议 |
|---|---|
| 完全零基础，想理解计算机 | **从 C 开始** |
| 要做嵌入式、单片机 | **从 C 开始**，之后按需学 C++ |
| 要做应用、游戏、桌面软件 | C 的基础 + **尽早进入 C++** |
| 要读懂现有 C 项目 | C |
| 要读懂的现有项目是 C++ | C 的基础 + C++ |

**共同点是：无论目标是什么，C 的基础都要先打。**

**原因**：C++ 的语法建立在 C 之上（第 2 节），
跳过 C 直接学 C++，会不知道哪些是 C++ 特有的、哪些是继承来的，
遇到问题时也难以判断该往哪个方向查。

## 5.3 常见误区

| 误区 | 实际 |
|---|---|
| 「学 C++ 就不用学 C 了」 | C++ 的很多知识建立在 C 之上，跳不过去 |
| 「C 是 C++ 的子集，所以 C 代码直接改扩展名就行」 | 见第 2.3 小节，有四类不成立的情况 |
| 「C++ 比 C 慢」 | 不用的特性不付代价；用了的与手写等价 |
| 「C++ 就是 C 加类」 | 模板、RAII、标准库都是独立的重要部分 |
| 「先把语法学完再写代码」 | 语法要在写的过程中掌握 |
| 「能编过就没问题」 | 未定义行为能编过，但结果是不可预测的 |

**最后一条最值得记住**：
本教材反复强调「未定义行为」「实现定义行为」，
就是因为**它们能通过编译**，因而比编译错误更危险。

## 5.4 学习建议

| 建议 | 理由 |
|---|---|
| **动手编译每一段示例** | 编译报错是最好的老师 |
| **看反汇编** | 理解「源码到机器码」的最直接方式 |
| **用调试器看变量** | 比 `printf` 快得多，见《02-调试器/01-原理与使用.md》 |
| **看编译警告** | 打开 `-Wall -Wextra`，警告多半是真问题 |
| **不要跳过报错信息** | 编译错误按阶段分类的解读见《01-编译器/01-编译与链接.md》第 7 节 |

**本教材的示例都放在 `B-examples/` 下，可以直接构建**，
配置方法见各示例目录的 `README.md`。

# 第 6 节 术语表

| 术语 | 英文 | 含义 |
|---|---|---|
| 标准 | Standard | 规定语言语法与语义的规范性文件 |
| 实现 | Implementation | 标准的具体落实者，即编译器 |
| 未定义行为 | Undefined behavior | 标准不作要求，任何结果都可能 |
| 实现定义行为 | Implementation-defined behavior | 由具体实现选定，但必须一致 |
| 未指定行为 | Unspecified behavior | 标准给出若干可能，不规定用哪个 |
| 超集 | Superset | 集合论概念，第 2 节讨论其适用性 |
| 名字修饰 | Name mangling | C++ 把参数类型编码进符号名的机制 |
| `extern "C"` | — | 关闭名字修饰，使 C 与 C++ 能互相链接 |
| RAII | Resource Acquisition Is Initialization | 用对象生命周期管理资源 |
| 零开销抽象 | Zero-overhead abstraction | 不用的不付代价，用了的与手写等价 |
| 过程式 | Procedural | 以函数为组织单位的编程范式 |
| 泛型 | Generic | 一套代码适配多种类型 |
| 多范式 | Multi-paradigm | 同时支持多种编程风格 |

## A.3 复现本章节的实测

**环境**：`gcc` / `g++` 15.2.0，Windows x64（MinGW-w64）。

第 2.2 小节的例子，同一份源码两种编译器都通过：

<small style="color:gray">bash</small>

```bash
gcc -std=c23 c_compat.c -o c_compat
g++ -std=c++17 c_compat.c -o c_compat_cpp
```

第 2.3.1 小节的例子，C 通过，C++ 报错：

<small style="color:gray">bash</small>

```bash
gcc -std=c23 keyword_clash.c -o keyword_clash            # 通过
g++ -std=c++17 keyword_clash.c -o keyword_clash_cpp      # 报错：class、new 是关键字
```
